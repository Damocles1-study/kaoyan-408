其之壹四层软件

术式
每层干什么

用户层：库函数、假脱机。
设备独立性：逻辑设备名映射、权限检查、缓冲、错误报告、分配回收。
驱动程序：计算柱面、磁头、扇区，启动设备。每种设备一个。
中断处理：保存状态，处理完唤醒进程。

2012實戰I/O 软件层次结构
操作系统的 I/O 子系统通常由 4 个层次组成，每层明确定义了与邻近层次的接口，其合理的层次组织排列顺序是（　）。

考查内容同上题。设备管理软件一般分为 4 个层次：用户层、与设备无关的系统调用处理层、设备驱动程序及中断处理程序。
再深一层
选 A。与 2011 那道是同一个考点连考两年——2011 问"处理流程"，2012 问"层次顺序"，答案结构完全一样。
图 5.5 自上而下四层（一个字都不要记错）

  ① 用户层软件       ← 离用户最近
  ② 设备独立性软件   （＝设备无关软件＝系统调用处理层）
  ③ 设备驱动程序
  ④ 中断处理程序     ← 离硬件最近
  ─────────── 硬件 ───────────

记忆口诀：用户 → 无关 → 驱动 → 中断
  「越往下越依赖具体硬件」
⚠️ 唯一的争议点在③④谁在下：直觉上"中断处理"像是发生在驱动之前（先中断才处理），但分层看的是"抽象程度"不是"时间先后"——中断处理程序直接与硬件打交道、最不通用，所以排在最底层。
⭐ 连做提示：做完 2011 + 2012，再做 5.2-31（哪些活归设备独立性软件）与 5.2-34（驱动程序五步的顺序），四题构成"I/O 软件层次"的完整闭环。
2011實戰I/O 软件层次的处理流程
用户程序发出磁盘 I/O 请求后，系统的正确处理流程是（　）。

输入/输出软件一般从上到下分为 4 个层次：用户层、与设备无关的软件层、设备驱动程序及中断处理程序。与设备无关的软件层也就是系统调用的处理程序。当用户使用设备时，首先在用户程序中发起一次系统调用，操作系统的内核接到该调用请求后，请求调用处理程序进行处理，再转到相应的设备驱动程序，当设备准备好或者所需数据到达后，设备硬件发出中断，将数据按上述调用顺序逆向回传到用户程序中。
再深一层
选 B。本题与下一题（2012）是连考两年的同一个考点，必须并排记。
四层的两个方向

请求向下（本题问的是这个方向）
  用户程序 → 系统调用处理程序（＝设备无关层）
         → 设备驱动程序 → 启动硬件

应答向上（数据回传）
  硬件发中断 → 中断处理程序 → 驱动 → 设备无关层
          → 用户程序

⚠️ 中断处理程序永远在"最后"出现——
  因为它是被硬件触发的，不在请求路径上
⭐ 一个关键等式："系统调用处理程序" ≡ "与设备无关的软件层"。王道在解析里明说了这一点。记住这个等式，2011 与 2012 两道题就是同一道。
⚠️ A 项把中断放在驱动前面：这等于说"设备还没启动就先中断了"，因果颠倒 ⟹ 一眼可排。

选 B。题眼是"首先"两个字——问的是数据最先落到谁手里，不是"谁最终用它"。
一个键盘字符的旅程（2010/2024/2023 三年都在考这条链）

  用户按键
   ↓ 字符进入键盘控制器的数据寄存器
   ↓ 控制器发中断

   ↓ 搬到内核缓冲区   ← 2024 问这里：中断返回时数据在哪

⚠️ A 项"命令解释程序"是最像的错项：它确实要处理你敲的命令，但它是用户层程序，拿到的是已经过三次搬运的数据。
2013實戰柱面号/磁头号/扇区号由驱动程序计算
用户程序发出磁盘 I/O 请求后，系统的处理流程是：用户程序→系统调用处理程序→设备驱动程序→中断处理程序。其中，计算数据所在磁盘的柱面号、磁头号、扇区号的程序是（　）。

计算柱面号、磁头号和扇区号的工作是由设备驱动程序完成的。题中的功能因设备硬件的不同而不同，因此应由厂家提供的设备驱动程序实现。
物理地址的计算要懂设备，所以是驱动程序。
再深一层
选 C。判据只有一句：这件事随设备型号而变吗？变 ⟹ 驱动程序。
同一个请求在四层里各被加工成什么

用户程序      「读文件 a.txt 的第 100 字节」
      ↓ 文件系统（ch4）
系统调用处理  「读逻辑块号 3」（设备无关的抽象块号）

2009實戰逻辑设备名
程序员利用系统调用打开 I/O 设备时，通常使用的设备标识是（　）。

用户程序对 I/O 设备的请求采用逻辑设备名，而程序实际执行时使用物理设备名，它们之间的转换是由设备无关软件层完成的。主设备和从设备是总线仲裁中的概念。
用户用逻辑设备名，设备独立性软件负责映射。
再深一层
选 A。一句话链条：程序员写逻辑名 → 设备无关层查 LUT → 得到物理名与驱动入口。
逻辑设备表 LUT 的两种设置方式

(a) 全系统一张
  逻辑设备名     物理设备名   驱动入口
  /dev/printer      3          2014
  /dev/tty          5          2046
  ⚠️ 要求所有用户不能用相同的逻辑名 ⟹ 只适合单用户系统

(b) 每个用户一张
  逻辑设备名 → 系统设备表指针
  ⟹ 不同用户可以用相同的逻辑名 ⟹ 适合多用户系统
⚠️ C、D 项是跨科干扰："主设备/从设备"是组原总线仲裁里的概念（谁发起传输谁是主设备），与 OS 的设备标识毫无关系。⟹ 组原 ch6 学过的词被搬来当错项，本章多处如此（还有"通道""周期窃取"等）。
⭐ Linux 里确实有"主设备号/次设备号"：但那是内核标识驱动的编号，与本题说的"总线仲裁的主/从设备"不是一回事，也不是程序员 open() 时用的东西——open() 用的永远是路径名（逻辑名）。

其之參缓冲

为什么要缓冲：匹配速度差、减少中断次数、提高并行性。

比方

流程图

T：设备→缓冲区的时间。M：缓冲区→用户区的时间。C：用户处理时间。

术式
块设备的时间

单缓冲，稳态每块：max(T, C) + M。
单缓冲，n 块总时间：n(T+M) + C。
双缓冲，稳态每块：max(T, C+M)。
双缓冲，n 块总时间：nT + M + C。

咒灵
n 块总时间不等于稳态 × n

2011 真题的干扰项 1000 和 1500 就是照稳态乘出来的。问 n 块就用下面两行的公式，把第一块的启动代价算对。

2011實戰单缓冲与双缓冲的 n 块总时间
某文件占 10 个磁盘块，现要把该文件的磁盘块逐个读入主存缓冲区，并且送到用户区进行分析，假设一个缓冲区与一个磁盘块大小相同，把一个磁盘块读入缓冲区的时间为 100 μs，将缓冲区的数据传送到用户区的时间是 50 μs，CPU 对一块数据进行分析的时间为 50 μs。在单缓冲区和双缓冲区结构下，读入并分析完该文件的时间分别是（　）。

在单缓冲区中，当上一个磁盘块从缓冲区读入用户区完成时，下一磁盘块才能开始读入，也就是当最后一个磁盘块读入用户区完毕时所用的时间为 150×10 = 1500 μs，加上处理最后一个磁盘块的时间 50 μs，得 1550 μs。双缓冲区中，不存在等待磁盘块从缓冲区读入用户区的问题，10 个磁盘块可以连续从外存读入主存缓冲区，加上将最后一个磁盘块从缓冲区送到用户区的传输时间 50 μs 及处理时间 50 μs，也就是 100×10 + 50 + 50 = 1100 μs。
单 10×150+50 = 1550；双 1000+50+50 = 1100。
再深一层
选 B（1550, 1100）。⚠️⚠️ 本题是全章最大的坑：n 块总时间不能用单块稳态公式直接乘 n。
两套公式必须分开记（T=100, M=50, C=50, n=10）

单块稳态（问"平均每块多久"时用）
  单缓冲 Max(T,C)+M = Max(100,50)+50 = 150
  双缓冲 Max(T,C+M) = Max(100,100)  = 100

n 块总时间（问"读完并分析完要多久"时用）
  单缓冲 n×(T+M) + C = 10×150 + 50 = 1550 ✓
  双缓冲 n×T + M + C = 10×100 + 50+50 = 1100 ✓

⚠️ 若照搬稳态乘 10：单缓冲得 1500、双缓冲得 1000
  ⟹ 正好是错误选项 A，出题人专门为此设了这个选项
⭐ 为什么要"+C"这个尾巴：因为最后一块的 CPU 分析没有下一块的读入可以与之并行，只能裸露地加在末尾。凡"读完并处理完 n 块"的题，末尾必有一个孤零零的 C。
⭐ 单缓冲为什么是 n×(T+M)：单缓冲下 T 与 M 必须串行（同一个缓冲区，搬走之前不能再写），所以每块的"占用缓冲区时间"是 T+M=150；而 C 可以与下一块的 T 并行 ⟹ C 不进循环体，只在末尾露一次。
2013實戰单缓冲读入并分析 2 块的最短时间
设系统缓冲区和用户工作区均采用单缓冲，从外设读入一块数据到系统缓冲区的时间为 100，从系统缓冲区读入一块数据到用户工作区的时间为 5，对用户工作区中的一块数据进行分析的时间为 90。进程从外设读入并分析 2 个数据块的最短时间是（　）。

数据块 1 从外设到用户工作区的总时间为 105，在这段时间中，数据块 2 未进行操作。在数据块 1 进行分析处理时，数据块 2 从外设到用户工作区的总时间为 105，这段时间是并行的。再加上数据块 2 进行处理的时间 90，总共是 300。
2 块：2×105 + 90 = 300。
再深一层
选 C（300）。本题与 2011 那道同型，但因为 n 只有 2，直接画时间轴反而最快。
时间轴（T=100, M=5, C=90）

  0 ─────100────105────────195───────210
  块1： T(100) │ M(5) │ C(90) ────────┐
  块2：        │ 等   │ T(100) │ M(5)  │ C(90)
                        105→205  205→210  210→300

  块1 到用户区：105
  块1 分析(90) 与 块2 的 T+M(105) 并行 ⟹ 取 105
  块2 分析：90
  合计 105 + 105 + 90 = 300 ✓
⭐ 用 2011 的公式验算：n×(T+M)+C = 2×105+90 = 300 ✓ 完全吻合。⟹ 2011 与 2013 是同一个公式的两次考查，2013 只是把 n 减到 2、让你能手画。
⚠️ 错误选项的来源都能还原：200 = 只算两次 T（忘了 M 和 C）；295 = 105+100+90（漏了块 2 的 M）；390 = 195×2（把两块完全串行，忘了并行）。390 是"什么都不并行"的答案，200 是"什么都并行"的答案，正确答案在中间。
2015實戰磁盘缓冲区的目的
在系统内存中设置磁盘缓冲区的主要目的是（　）。

磁盘和内存的速度差异，决定了可以将内存经常访问的文件调入磁盘缓冲区，从高速缓存中复制的访问比磁盘 I/O 的机械操作要快很多。
再深一层
选 A。注意区分"减少 I/O 次数"与"让每次 I/O 更快"——缓冲区做的是前者。
四个选项各归各家

A 减少磁盘 I/O 次数 ⟹ 磁盘缓冲区/高速缓存 ✓
  命中缓存就不必访盘；延迟写还能合并多次写
B 减少平均寻道时间 ⟹ 磁盘调度算法（5.3.3）
C 提高数据可靠性   ⟹ RAID / 坏块管理 / 校验
  ⚠️ 缓冲区反而降低可靠性（延迟写时断电就丢数据）
D 实现设备无关性   ⟹ 逻辑设备名 + LUT
⭐ C 项的反向思考很有价值：内核缓冲区的延迟写意味着"你以为写完了，其实还在内存里"——突然断电就全丢了。这正是数据库要用 fsync、文件系统要有日志的原因。缓冲提高的是性能，代价是可靠性。
🔵 与 5.3.3「提高磁盘 I/O 速度的方法」串：七条方法里①磁盘高速缓存 ③提前读 ④延迟写都是本题这一类，共同目标就是把访盘次数压下去。

循环缓冲：多个缓冲区连成一圈，生产者消费者（第28话）的翻版。缓冲池：统一管理的公共缓冲区。

其之肆设备分配

术式
分配用到的数据结构

SDT（系统设备表）→ DCT（设备控制表）→ COCT（控制器）→ CHCT（通道）。
逻辑设备表 LUT：逻辑名 → 物理设备。
方式：独占、分时共享、虚拟（SPOOLing）。安全分配 vs 不安全分配。

其之伍SPOOLing

比方

打印机

打印机是独占设备。用一块磁盘做输出井，把所有人的打印任务先放在磁盘，再由守护进程一件件打印。每个人都感觉自己独占了打印机。

术式
SPOOLing 的结论

把独占设备改造成共享设备：虚拟设备。
组成：输入井、输出井（磁盘）；输入缓冲、输出缓冲（内存）；输入进程、输出进程（守护进程）。
不需要用户作业控制。它破坏死锁的「互斥」条件。

2016實戰SPOOLing 技术的特点
下列关于 SPOOLing 技术的叙述中，错误的是（　）。

SPOOLing 利用专门的外围控制机，将低速 I/O 设备上的数据传送到高速磁盘上，或者相反。SPOOLing 的意思是外部设备同时联机操作，也称假脱机输入/输出操作，是操作系统中采用的一项将独占设备改造成共享设备的技术。高速磁盘即外存，选项 A 正确。SPOOLing 技术建立在多道程序设计技术的基础上，在一个时间段内，输入进程、输出进程是可以和运行的作业进程并发执行的，选项 B 正确。SPOOLing 技术实现了将独占设备改造成共享设备的技术，选项 C 正确。设备与输入井/输出井之间数据的传送是由系统实现的，选项 D 错误。
再深一层
选 D（错误项）。D 项偷换的是主语：搬数据的是系统的输入/输出进程，不是用户作业。
谁在搬数据（SPOOLing 的分工）

  设备 ⇄ 井  ：输入进程 SPᵢ / 输出进程 SPₒ（系统的进程）
  作业 ⇄ 井  ：由井管理程序控制

  用户作业全程只和"井"打交道，碰不到设备
  ⟹ D 说"由用户作业控制设备与井之间的传送" ✗

这正是"假脱机"的实质：用系统进程模拟当年的外围控制机
⭐ SPOOLing 题的通用识别法：看主语有没有被换：常见的偷换有——"用户作业控制数据传送"（应为系统进程）、"把物理设备分配给进程"（应为分配井空间）、"需要外围计算机"（应为 0 台）。三处主语一换，正确句就变成错误句。
⚠️ B 项为什么必需多道程序：输入进程、输出进程要与用户作业并发执行，没有多道程序技术，这三者只能一个一个来，SPOOLing 就退化成了普通的串行 I/O。
2009實戰单处理机系统中的并行
单处理机系统中，可并行的是（　）。
Ⅰ. 进程与进程　Ⅱ. 处理机与设备　Ⅲ. 处理机与通道　Ⅳ. 设备与设备

在单 CPU 系统中，同一时刻只能有一个进程占用 CPU，因此进程之间不能并行执行。通道是独立于 CPU、控制输入/输出的设备，两者可以并行。显然，处理器与设备是可以并行的。设备与设备也是可以并行的，比如显示屏与打印机可以并行工作。
单核下 CPU 只有一个，进程只能并发；CPU、设备、通道相互可并行。
再深一层
选 D（Ⅱ、Ⅲ、Ⅳ）。唯一被排除的是 Ⅰ——单 CPU 上进程只能并发，不能并行。
并发 vs 并行（本题的全部考点）

并发 concurrent：宏观同时、微观交替
  单 CPU 上的多个进程 ⟹ 只能并发 ⟹ Ⅰ ✗
并行 parallel：同一时刻真的一起动
  需要多个独立的执行部件

Ⅱ 处理机 ‖ 设备：设备有自己的控制器 ✓
Ⅲ 处理机 ‖ 通道：通道是独立的专用处理机 ✓
Ⅳ 设备 ‖ 设备  ：如显示屏与打印机各干各的 ✓
⭐ 为什么后三项都能并行：因为它们各有各的硬件。并行的充要条件就是"有几套独立的执行部件"——单 CPU 只有一套指令执行部件，所以进程之间无论如何也并行不起来。
⚠️ 与 5.1-14 的 B 项别混：那道说"对于同一组 I/O 命令，控制器、通道、设备可以并行工作"是错的——因为它们对同一条命令是串行的上下级关系。本题问的是"不同的活儿能不能同时干"，那道问的是"同一件活儿能不能同时干"。
2012實戰read 系统调用的三个说法
若一个用户进程通过 read 系统调用读取一个磁盘文件中的数据，则下列关于此过程的叙述中，正确的是（　）。
Ⅰ. 若该文件的数据不在内存，则该进程进入睡眠等待状态
Ⅱ. 请求 read 系统调用会导致 CPU 从用户态切换到核心态
Ⅲ. read 系统调用的参数应包含文件的名称

对于说法 Ⅰ，当所读文件的数据不在内存时，产生中断（缺页中断），原进程进入阻塞态，直到所需数据从外存调入内存后，才将该进程唤醒。对于说法 Ⅱ，read 系统调用通过陷入将 CPU 从用户态切换到核心态，从而获取操作系统提供的服务。对于说法 Ⅲ，要读一个文件，首先要用系统调用打开该文件。open 中的参数包含文件的路径名与文件名，而 read 只需使用 open 返回的文件描述符，并不使用文件名作为参数。read 要求用户提供三个输入参数：① 文件描述符 fd；② buf 缓冲区首址；③ 传送的字节数 n。read 的功能是试图从 fd 所指示的文件中读入 n 字节的数据，并将它们送至由指针 buf 所指示的缓冲区中。
read 在用户进程请求之后，进程进入内核，数据未到就睡眠。
再深一层
选 A（仅 Ⅰ、Ⅱ）。三个说法各考一个模块，Ⅲ 是本章最高频的送分/送命点：
说法判定理由属于
Ⅰ✅数据不在内存 ⟹ 启动 I/O ⟹ 进程阻塞（睡眠等待），I/O 完成后被唤醒ch2 进程状态
Ⅱ✅系统调用靠陷入（trap）指令主动从用户态进内核态ch1 运行环境
Ⅲ❌read 的三个参数是 <fd, buf, n>，没有文件名ch4 文件操作
⭐⭐ read 的函数原型直接背下来，一劳永逸：
ssize_t read(int fd, void *buf, size_t n);
             ↑        ↑           ↑
      文件描述符  缓冲区首址  要读的字节数

⟹ 三个参数里没有一个是文件名
   文件名只出现在 open(路径名, mode) 里
📌 Ⅰ 的一个细节值得注意：书上把它写成「产生缺页中断」。严格说读文件数据不在内存导致的是普通的 I/O 阻塞，缺页中断特指虚拟内存中访问未调入的页。但两者在"进程转阻塞态、等 I/O 完成再唤醒"这一点上完全一样，王道用缺页中断作类比不影响本题结论。
🔵 Ⅲ 这个考点在本节被考了整整三次，是全章复现率最高的点：2012（本题 Ⅲ）：read 参数不含文件名 · 选 42：打开后用文件描述符访问 · 2024（选 68）：含按名查找的系统调用是 open()。⟹ 三题一句话：「文件名只在 open 出现一次，此后一律用 fd」。
🔵 Ⅱ 承接 OS ch1 那把刀：系统调用 = 陷入指令（访管指令） ⟹ 陷入指令本身在用户态执行，执行后 CPU 才切到内核态。这是 ch1「四条分界线」之一，2015/2020/2022 反复考。
领域展开

层次：用户 → 设备独立 → 驱动 → 中断。算柱面在驱动。
缓冲：单 n(T+M)+C；双 nT+M+C。
