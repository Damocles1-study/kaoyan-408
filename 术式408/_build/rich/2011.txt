#1
@ans A
@tpl T循环次数
::rev
- **该花** 20 秒。x 每次乘 2，到 n/2 为止 ⟹ 对数。
- **卡点** 看到条件里的 n/2 以为要「再除以 2」而犹豫；或没看循环体就凭一层循环选 B。
- **错了说明** 没先看循环变量是加还是乘。
- **带走** 单层循环先看循环变量怎么变：每次乘 2 就是 $O(\log_2n)$；条件里的常数倍（n/2、2n）不改变量级。
::read
「while(x＜n/2)　{{圈|x=2*x}}」 >> 循环变量每次翻倍 ⟹ 执行次数是对数级；条件里的 n/2 只让次数少 1，不影响量级
::fast
{{秒|循环变量乘 2 ⟹ 对数}}，选 A。
::steps
设循环体执行了 $k$ 次。x 的初值是 2，每次乘 2 ⟹ 执行 $k$ 次后 $x=2^{k+1}$（做法见 [[T循环次数]]）。
循环停下来的条件是 $x\ge n/2$，即 $2^{k+1}\ge n/2$ ⟹ $k\ge\log_2n-2$。
所以执行次数约为 $\log_2n-2$，时间复杂度 $O(\log_2n)$，选 **A**。
~验算：$n=64$ 时 x 依次为 2、4、8、16、32，到 32 时不再小于 32，循环体执行 4 次＝$\log_264-2$。
::note
- {{扣|把 n/2 当成会让复杂度变化的东西}}：常数倍、加减常数都不改变量级。
- 提速：这类题不用解方程，只看循环变量的变化方式——加常数是线性，乘常数是对数。
::vary
把循环体改成 `x=x+2;`，时间复杂度 >> x 每次加 2，从 2 加到 n/2 约 $n/4$ 次 ⟹ $O(n)$
在这个循环外面再套一层 `for(i=0;i＜n;i++)`（每次进入内层前 x 重新赋 2），时间复杂度 >> 外层 n 次，每次内层 $\log_2n$ 次 ⟹ $O(n\log_2n)$

@ans B
@tpl T出栈序列
::rev
- **该花** 1 分钟。d 先出 ⟹ 栈里压着 a、b、c，只能按 c、b、a 出；剩一个 e，数它能插在哪。
- **卡点** 把 e 的位置漏数一个（e 紧跟在 d 后面，或 e 排在最后），选 A；或想去套卡特兰数公式。
- **错了说明** 没把「谁的相对次序已经定死」和「谁还能自由插入」分开。
- **带走** 「以某元素开头的出栈序列有几个」：它出栈时在它前面入栈的元素全压在栈里，出栈次序已定死；只需数后面的元素能插进几个空档。
::read
「以元素 {{圈|d 开头}}的序列个数」 >> d 第一个出栈 ⟹ 此前 a、b、c 都已入栈且一个都没出 ⟹ 栈里从底到顶是 a、b、c，它们以后只能按 c、b、a 的次序出
::sk 330 96 列 | 先画栈：底 a、中 b、顶 c（d 已出）；再写一行 d □ c □ b □ a □，四个方框是 e 可以出现的位置

s.text(96,86,'e 落在哪个方框都行 ⟹ 4 种',11,'r')
::fast
{{秒|骨架 d、c、b、a 固定，e 可以放在 d 后、c 后、b 后、a 后}} ⟹ 4 个，选 B。
::steps
d 要第一个出栈 ⟹ 必须先把 a、b、c、d 依次压入，再弹出 d。此时栈内从底到顶为 a、b、c（规则见 [[T出栈序列]]）。
栈里的三个元素以后只能按 c、b、a 的顺序出来，相对次序固定。
还没入栈的只有 e。e 入栈后立刻在栈顶，可以马上出栈；它可以选在任何时刻入栈并立即出栈。
e 的出栈时刻有 4 种：在 c 之前、在 c 与 b 之间、在 b 与 a 之间、在 a 之后 ⟹ decba、dceba、dcbea、dcbae。
~为什么 e 入栈后不立即出也只得到这 4 种：e 压在栈顶，下面的元素要出必须先弹 e，所以 e 一定比它入栈时栈里剩下的元素先出，结果仍在这 4 种之内。
共 4 个，选 **B**。

同样的入栈次序，以 c 开头的出栈序列有几个 >> c 出时栈里是 a、b（只能 b 先 a 后），d、e 还没入栈。d、e 自己有 2 种出栈次序（d e 或 e d），再与 b、a 穿插：穷举得 9 个
以 e 开头的出栈序列有几个 >> a、b、c、d 全压在栈里，只能 d、c、b、a ⟹ 1 个（edcba）

@ans B
@tpl T队列指针约定
::rev
- **该花** 40 秒。写出入队两行代码，把「第一个元素存到 A[0]」代进去倒推 rear。
- **卡点** 按背熟的「初始 front＝rear＝0」直接选 A；没注意本题 rear 指向的是队尾元素本身。
- **错了说明** 没读题干对指针的约定就套了另一种约定的结论。
- **带走** 循环队列题先圈出 front、rear 各指向谁；rear 指向队尾元素时，入队是「先加 1 再存」，第一个元素要落在 A[0]，rear 的初值就得是 n−1。
::read
「队列非空时 front 和 rear 分别指向{{圈|队首元素和队尾元素}}」 >> rear 指的是队尾元素本身（不是它后面的空位）⟹ 入队：先 rear 后移一格，再把元素放进 A[rear]
「第一个进入队列的元素存储在 {{圈|A[0]}} 处」 >> 第一次入队后 rear 必须等于 0，同时这个元素也是队首 ⟹ front 也必须等于 0
::fast
{{秒|rear 加 1 取模后要等于 0 ⟹ rear 初值 n−1；入队不改 front，而队首在 A[0] ⟹ front 初值 0}}，选 B。
::steps
按题干的约定写出入队操作（见 [[T队列指针约定]]）：`rear=(rear+1)%n; A[rear]=x;`。入队不改变 front。
第一个元素入队后存在 A[0] ⟹ $(\text{rear}_0+1)\bmod n=0$ ⟹ rear 初值为 $n-1$。
第一个元素入队后队列非空，它既是队尾也是队首 ⟹ front 必须指向 A[0]；入队没有动过 front ⟹ front 初值就是 0。
front＝0、rear＝n−1，选 **B**。
~逐项代入：A（0,0）入队后元素存到 A[1]；C（n−1,0）存到 A[1]；D（n−1,n−1）存到 A[0]，但 front 还指着 A[n−1]，不是队首。
::note
- {{扣|套「front＝rear＝0」}}：那是「rear 指向队尾的下一个位置」约定下的初值（见 [[循环队列]]）。约定换了，初值、判空条件都跟着换。
- 本题约定下队空的条件是 `(rear+1)%n==front`。
- 对照 2014 第 3 题：那题的 rear 指向队尾的下一个位置，问的是判空判满的条件，同样先看指针约定。
::vary
若改成「rear 指向队尾元素的下一个位置」，其余不变，初值是多少 >> 入队是先存 A[rear] 再后移 ⟹ rear 初值 0，front 初值 0
本题约定下，某时刻 front＝3、rear＝1、n＝8，队列里有几个元素 >> 两端都指向元素：$(\text{rear}-\text{front}+1+n)\bmod n=(1-3+1+8)\bmod8=7$ 个

#4
@ans C
@tpl T完全二叉树叶子
::rev
- **该花** 15 秒。$768\div2=384$。
- **卡点** 想先求树高、再数最后一层，绕远还容易把倒数第二层的叶子漏掉；或选 D，多算一个。
- **错了说明** 不知道「最后一个分支结点是 $\lfloor n/2\rfloor$ 号」这条编号性质。
- **带走** 完全二叉树 n 个结点：叶子数＝$\lceil n/2\rceil$；n 为偶数时恰有一个度为 1 的结点。
::read
「一棵{{圈|完全二叉树}}有 768 个结点」 >> 按层序编号 1～768；有孩子的结点是 1～$\lfloor768/2\rfloor$，其余全是叶子
::fast
{{秒|叶子数＝⌈n/2⌉＝384}}，选 C。
::steps
按层序给结点编号 1～768（性质见 [[完全二叉树]]）。结点 $i$ 有孩子 ⟺ $2i\le768$ ⟺ $i\le384$。
所以 1～384 号是分支结点，385～768 号是叶子，叶子数＝$768-384=384$，选 **C**。
~另一种算法：$n=n_0+n_1+n_2$ 且 $n_0=n_2+1$ ⟹ $768=2n_0-1+n_1$。$n_1$ 只能是 0 或 1，等式左边是偶数 ⟹ $n_1=1$，$n_0=384$。
::note
- {{扣|选 385}}：把那个只有左孩子的结点（384 号）也当成了叶子。
- 提速：偶数个结点 ⟹ 叶子正好一半；奇数个结点 ⟹ 叶子比一半多半个，取上整。
::vary
完全二叉树有 767 个结点，叶子数是多少、有没有度为 1 的结点 >> $\lceil767/2\rceil=384$；奇数个结点，没有度为 1 的结点
完全二叉树有 384 个叶子，结点数最多、最少各是多少 >> 最多 $2\times384=768$，最少 $2\times384-1=767$

#5
@ans C
@tpl T遍历建树
::rev
- **该花** 1 分钟。先序与后序正好相反 ⟹ 每个结点只有一个孩子；中序里每个结点都在它那棵子树序列的最左或最右。
- **卡点** 想把 8 棵树都画出来；或只检查了根 1 在两端就以为四个选项都行。
- **错了说明** 没把「单支」这个条件一层层往下用：2、3 也各是一棵单支子树的根。
- **带走** 先序与后序正好相反 ⟺ 每个结点至多一个孩子（单支树）；判中序时从根起一层层看：每个根都必须在剩余序列的最左或最右。
::read
「先序 1,2,3,4 和后序 {{圈|4,3,2,1}}」 >> 两个序列正好相反 ⟹ 树是一条链：1 的孩子是 2，2 的孩子是 3，3 的孩子是 4；每一层的孩子挂左挂右不确定
「中序遍历序列{{圈|不会是}}」 >> 链上每个结点只有一侧有子树 ⟹ 中序里它排在自己子树所有结点的最前或最后
::fast
{{秒|去掉 1 后看 2 在不在剩余序列的两端}}：A 剩 2,3,4（2 在头）、B 剩 2,3,4（2 在头）、D 剩 4,3,2（2 在尾）、C 剩 3,2,4（2 在中间）⟹ 选 C。
::steps
先序＝根、左、右，后序＝左、右、根。若某结点同时有左右孩子 x、y，则先序里 x 的子树在 y 之前，后序里 x 的子树也在 y 之前，两个序列不可能完全相反 ⟹ 每个结点至多一个孩子。
所以树是一条链 1→2→3→4（每个箭头可以是左孩子，也可以是右孩子，共 $2^3=8$ 棵）。
中序＝左、根、右。结点只有左子树时，它排在子树所有结点之后；只有右子树时，排在之前。
检查 C（3,2,4,1）：1 在最后，说明 2、3、4 都在 1 的左子树。看以 2 为根的子树的中序 3,2,4：2 在中间，说明 2 既有左子树（3）又有右子树（4），与「至多一个孩子」矛盾 ⟹ C 不可能。
其余三项都能画出来：A 是全向右的链；D 是全向左的链；B（2,3,4,1）是 1 的左孩子 2，2 的右孩子 3，3 的右孩子 4。
选 **C**。
::note
- {{扣|只看根在不在两端}}：四个选项里 1 都在两端，必须再往下看一层。
- 这样的二叉树高度等于结点数（4 层）；8 棵树对应 8 个不同的中序序列。
- 对照 2012 第 3 题：也是只给先序和后序，靠「去掉根后首尾是否相同」判断根有几个孩子。
::vary
先序 1,2,3,4、后序 4,3,2,1 的二叉树共有几棵 >> 三条边各有左右两种挂法：$2^3=8$ 棵
若先序 1,2,3,4 与中序 1,2,3,4 相同，树是什么形状 >> 每个结点都没有左孩子，只向右的单链（见 [[T两序相同]]），唯一一棵

@ans D

::rev

#7
@ans A
@tpl TBST查找路径
::rev
- **该花** 1 分钟。每个选项从左到右走一遍，每一步收紧上界或下界，看后面的数出不出界。
- **卡点** 只比较相邻两个数的大小，看不出毛病；A 里 94 比 24 大没问题，但它超过了更早锁定的上界 91。
- **错了说明** 没意识到查找路径上每一次转向都会留下一个永久有效的界。
- **带走** 判查找路径：往左走一次，当前值成为以后所有数的上界；往右走一次，成为下界；后面任何一个数出界就不合法。
::read
「{{圈|不可能}}构成某二叉排序树中一条{{圈|查找路径}}」 >> 查找路径是从根一路向下，每到一个结点就往左（找更小）或往右（找更大）；一旦在某结点往左，之后经过的结点全在它的左子树里，都比它小
::fast
{{秒|A：91 之后是 24（往左）⟹ 此后都要小于 91，却出现了 94}}，选 A。
::steps
用 [[TBST查找路径]] 的区间法检查 A：95, 22, 91, 24, 94, 71。
| 当前结点 | 下一个 | 方向 | 之后的数必须落在 |
| 95 | 22 | 左 | (−∞, 95) |
| 22 | 91 | 右 | (22, 95) |
| 91 | 24 | 左 | (22, 91) |
| 24 | 94 | 右 | (24, 91) |
94 不在 (24, 91) 内 ⟹ A 不可能，选 **A**。
~B：92→20→91→34→88→35，区间依次 (−∞,92)、(20,92)、(20,91)、(34,91)、(34,88)，35 在内。C：21→89→77→29→36→38，区间 (21,+∞)、(21,89)、(21,77)、(29,77)、(36,77)，38 在内。D：12→25→71→68→33→34，区间 (12,+∞)、(25,+∞)、(25,71)、(25,68)、(33,68)，34 在内。三个都合法。
::note
- {{扣|只看相邻两项}}：查找路径可以忽大忽小，合法与否看的是有没有越过更早留下的界。
- 提速：找「先变小、后来又出现更大的数」的位置，只核对那个数有没有超过转向点。
- 对照 2015 第 7 题：折半查找的比较序列用同一个判法（那年的卡叫「区间夹逼」），因为折半查找的判定树就是一棵二叉排序树。
::vary
把 A 中的 94 改成 90，序列 95, 22, 91, 24, 90, 71 合法吗 >> 90 在 (24, 91) 内；之后区间 (24, 90)，71 在内 ⟹ 合法
序列 50, 30, 40, 35, 45, 33 可能是查找路径吗 >> 50 左 (−∞,50)；30 右 (30,50)；40 左 (30,40)；35 右 (35,40)；45 不在 (35,40) 内 ⟹ 不可能

@ans C
@tpl T罗马数字组合

「bgt（{{圈|无符号}}整数比较大于时转移）」 >> 无符号数的大小关系由 CF（借位）和 ZF 反映；SF、OF 是给有符号数用的 ⟹ 含 SF 或 OF 的选项先划掉

::vary

P2 写入的值＝它 load 到的值 −1。它 load 时 x 是 1 或 2（P1 已经 store）⟹ P2 写入 0 或 1。
| 执行次序 | 结果 |
| P1 三条全做完，P2 再做（或反过来） | 1 |
| 两个都先 load（都读到 1），P2 先 store 0，P1 后 store 2 | 2 |
| 两个都先 load（都读到 1），P1 先 store 2，P2 后 store 0 | 0 |
可能的结果是 0、1、2，选 **C**。
~为什么没有 −1 和 3：要得到 −1，P2 必须 load 到 0，但只有 P2 自己能把 x 变成 0，而它只做一次；3 同理。
::note
- {{扣|按「加一次减一次」推}}：只有两个操作各自不被打断时才是 1。
- 这就是[[竞争条件]]：结果取决于指令穿插的次序；把三条指令放进临界区就只剩 1。
- 对照 2018 第 25 题：也是并发指令交错求可能的结果，同样先确定「最后写入的是谁」。
::vary
若 P1 和 P2 都是对 x 加 1（各自三条指令），x 初值 1，最终可能的值有哪些 >> 都读到 1 ⟹ 2；一先一后 ⟹ 3。可能为 2 或 3

**解法一（保底，时间 $O(n)$，空间 $O(1)$）**
**1）基本设计思想** ⛳3
两个序列共 2n 个元素，中位数是合并后的第 n 个元素。不必真的合并：设两个指针分别指向 A、B 的第一个元素，每次比较两个指针所指元素，取较小者并将其指针后移，如此取 n 次，第 n 次取到的元素即为所求中位数。
**2）算法描述** ⛳6
```
int MedianMerge(int A[], int B[], int n){
    int i = 0, j = 0, k, x = 0;
    for(k = 1; k <= n; k++){            // 只取前 n 个，不真的合并
        if(A[i] <= B[j]) x = A[i++];    // 谁小取谁，取走后指针后移
        else x = B[j++];
    }
    return x;                           // 第 n 个被取走的就是中位数
}
```
**3）复杂度** ⛳1　时间复杂度 $O(n)$，空间复杂度 $O(1)$。
**解法二（最优，时间 $O(\log_2n)$，空间 $O(1)$）**
**1）基本设计思想** ⛳4
分别求两个升序序列 A、B 的中位数，设为 a 和 b：
① 若 a＝b，则 a（或 b）即为所求中位数，算法结束；
② 若 a ＜ b，则舍弃序列 A 中较小的一半，同时舍弃序列 B 中较大的一半，要求两次舍弃的长度相等；
③ 若 a ＞ b，则舍弃序列 A 中较大的一半，同时舍弃序列 B 中较小的一半，要求两次舍弃的长度相等。
在保留的两个升序序列中重复上述过程，直到两个序列中均只含一个元素为止，较小者即为所求的中位数。
**2）算法描述** ⛳9
```
int MedianBest(int A[], int B[], int n){
    int s1 = 0, d1 = n - 1, s2 = 0, d2 = n - 1, m1, m2;
    while(s1 != d1 || s2 != d2){        // 两段都只剩 1 个元素时停
        m1 = (s1 + d1) / 2;             // A 当前段的中位数下标
        m2 = (s2 + d2) / 2;             // B 当前段的中位数下标
        if(A[m1] == B[m2]) return A[m1];
        if(A[m1] < B[m2]){              // 舍 A 的前半、B 的后半
            if((s1 + d1) % 2 == 0) s1 = m1;   // 段长为奇数：保留中间点
            else s1 = m1 + 1;                 // 段长为偶数：中间点也舍去
            d2 = m2;
        }else{                          // 舍 A 的后半、B 的前半
            d1 = m1;
            if((s2 + d2) % 2 == 0) s2 = m2;
            else s2 = m2 + 1;
        }
    }
    return A[s1] < B[s2] ? A[s1] : B[s2];     // 各剩 1 个，取较小者
}
```
**3）复杂度** ⛳2　每轮两个序列的长度都减半，时间复杂度 $O(\log_2n)$；只用了几个整型变量，空间复杂度 $O(1)$。
::note
- {{扣|先合并到新数组再取第 n 个}}：时间 $O(n)$ 没问题，但空间 $O(n)$，「空间尽可能高效」这一条要扣分。
- {{扣|偶数段不舍中间点}}：比如两段各剩 2 个时，「留后半」的一边若只写 s1＝m1，s1 不动，循环停不下来。
- 评分按效率分档：$O(n)$ 时间、$O(1)$ 空间的正确解法能拿到大部分分数，所以保底解一定先写完整；最优解背过就写，没背过不要在考场上现推奇偶。
- 两段代码已用 gcc 编译，在 30 万组随机数据（含 n＝1、大量重复元素）上与「合并后排序取第 n 个」对拍一致。对照 2020 第 41 题（多个升序数组上移指针）、2016 第 43 题（无序数组找中位数用划分）。
::vary
