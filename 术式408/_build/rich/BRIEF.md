## 统一规定（2026-11-12 起，所有年份都照此写；与上文冲突的以这里为准）

用户原话：「我现在不是无限时间」「图是要我确实能在草稿纸上想到和能画出的」。距初试不到 40 天，一张卷的复盘只有卷首给的限时（60–150 分钟）。精解是给他在这段时间里读完并记住的，不是越多越好。

### 一、篇幅预算（超了就删重复话，不删步骤）

| 题型 | 每题正文上限（不含草图代码） |
|---|---|
| 选择 | 900 字 |
| 综合 | 2400 字 |

- `::steps` 照旧不许跳步，这是用户要的；可省的步骤照旧标 `~`。省的是别处：
- `::read` 只写「不写就会漏掉」的句子，一题最多 3 行。「求极限」「设函数可导」这类看了等于没看的不写。
- `::think` 最多 4 条，只写怎么选路，不预演计算。
- `::note` 最多 3 条：一个扣分点、一个边界或易错、一个提速。没有就少写。
- `::vary` 普通题 2 条，精研卡点名「必吃透」的题 3 条。每条必须改了条件后做法真的变了。
- 同一句话只说一次：read 里说过的，think、steps、note 里不再重复。
- 旧精研卡的「本质」那一行（`_build/deep/<年份>.txt`）是交卷后做对的题唯一显示的东西，写精解时顺手核一遍：≤ 50 字，一句话说清「看到什么 → 做什么 → 答案」。

### 二、草图：只画考场上真会画的（`::sk 宽 高 画|列|看 | 图注`，不标用途构建报错）

- **画**＝考场草稿纸上 1 分钟内徒手画得出、并且画了能帮着得出答案。只用默画得出的形状：直线、圆、抛物线、钟形、指数衰减、折线、数轴、韦恩图、小规模的树 / 图 / 链表、栈和队列的状态、逐轮表、地址切分条、甘特图、时空图、三态图、磁头折线、cwnd 台阶、握手 / 挥手时序。图上要标的点不超过 4 个，坐标都能口算。图注第一句写画法：「先画……，再标……」。
- **列**＝草稿上列的式子或表（抵消账本、逐轮表、地址切分）。纯表格优先直接用 `| 表 | 格 |` 写进 `::steps`，不必做成图。
- **看**＝只为看懂、考场不会画的示意图。页面上标着「看懂就行 · 考场不画」，用户点「精简」就整类隐藏。**一张卷最多 8 张**，只在「不看图就讲不清」时用。
- **不许再画的**：概念对照表做成的图、部件关系示意（CPU＝数据通路＋控制器 这类）、层次结构示意、比喻图。概念题本来就不用画图，用一句口诀或一张 `| 表 |` 代替。这些改成一句话。
- **不再要求每题一张图**。没有值得画的就不画，别凑数。
- 画完自问一句：合上页面，用户能不能在草稿纸上照着图注自己画出来？不能就改成「看」或删掉。

### 三、知识点卡要写全（页面会把它们汇到每题顶上「这题要用到的」）

- 本题用到的每个公式、定理、常用结论都要有 `[[id]]` 或 `@tpl` 指到一张卡，用户靠它重复记忆。
- 卡的内容写全：是什么、公式全文、什么时候用、一个最小例子。不许写「见教材」「略」。
- 先在 `kp.txt` 里搜，能复用就复用。

### 四、样式与写法

- 不写 emoji（块标题的图标页面已不显示；正文里也别加）。采分点照旧写 `⛳N`，页面会画成红笔圈的「+N 分」。
- 页面现在是手写笔记样式（引擎 v5，见 README「套卷引擎」）：解析是一页带红页边线的纸，交卷后只有失分、标记过、看过提示、必吃透的题默认摊开。写的时候按「用户只读摊开的这些题」来安排详略。

### 六、精修已完成年份（2026-11-12 用户点名：删废话、删无用图、每题写「复盘」）

样板：数学 `_build/rich/2021.txt` 第 1–12 题（已精修）。其余年份、其余题照此做，一年一个会话：

1. **每题第一块加 `::rev`**，固定四行，必须具体到这道题，不许写套话：
   `- **该花** 几分钟；超时说明走了哪条弯路` / `- **卡点** 具体错在哪一步、会错成哪个选项或哪个数` / `- **错了说明** 哪个知识点或习惯没到位` / `- **带走** 一句下次能直接用的做法`。
2. **删**：`::think` 若只是把 read 和 steps 再说一遍，整块删；note 里的「跨章：第 N 期……」泛泛指路、与 read 重复的话、讲故事的话；vary 里只换数字或答案是「做法一样」的条目（留 2 条，必吃透题 3 条）；steps 里「这一步其实可省，写它只是为了……」这类元话。
3. **不删**：steps 的推导步骤、扣分点、反例、秒杀。
4. **图**：标「看」的已逐张筛过；标「画」的若对解题没帮助（比如直接能算的积分配一条被积函数曲线）也删。删图后搜本题正文里的「草图 / 见图 / 图上」并改掉。
5. 改完 `python3 _build/rich_build.py <年份>` 通过，再跑 `_build/rich/chk/<年份>.py`。

### 七、分档 · 限时 · 三条线（2026-11-12 起，每个年份必写）

用户要知道一张卷「保底多少、正常多少、尽力多少」，以及每题考场上给几分钟、哪些分不值得硬啃。

- 每年多写一个 `_build/tier/<年份>.txt`（语法见 `_build/tier_build.py` 开头，样板看已有年份）：每题一行「题号 档 分钟 | 说明」。档＝必 / 常 / 冲 / 弃；解答题按问拆成 `a/b/c/x` 四个数。写完跑 `python3 _build/tier_build.py`（校验题号齐全、拆分之和＝满分、总限时 ≤ 180）。
- 判据：必＝定义、背过的结论、一步套公式、标准手算；常＝两三步推理或中等计算；冲＝要绕弯、计算量大、考得偏；弃＝按分值算时间不划算（证明题的第二问、算法题的最优解这类），必须在说明里写「卡在哪就走、时间挪给谁」。
- 限时按「基础一般的考生」给，不按高手用时：全卷限时合计留 15–25 分钟检查。`::rev` 的「该花」写的是熟练后的用时，可以比限时短。
- 说明里**不要泄露做法**的只有一种情况：做题前页面只显示通用的取舍提示，完整说明对完答案才显示，所以说明可以写具体。
- 写精解时，`::rev` 的「带走」和 `::read` 的第一句会被自动汇到这题所标 `@tpl` 的套路卡上（「真题里的字眼」），所以：**第一句 read 要写题干里最该敏感的那句原话**，「带走」要写成离开这道题也成立的一句做法。写新年份前先翻一遍要用的套路卡下已有的字眼，发现同一个字眼在别的年份有不同的坑，就在本题 `::note` 里点一句「对照某年第几题」。
