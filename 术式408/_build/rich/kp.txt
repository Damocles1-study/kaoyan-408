@tpl T遍历建树 | 给两种遍历序列建树：先序/后序定根，中序分左右
1. 先序的第一个、后序的最后一个是根。
2. 在中序里找到根：左边全是左子树，右边全是右子树；按个数把先序/后序也切成两段，递归。
3. 只有先序＋后序 ⟹ 不能唯一确定（单孩子分不清左右）。
4. 森林、树的序列先翻译：森林先根＝二叉树先序，森林后根＝二叉树中序；树的先根＝二叉树先序，树的后根＝二叉树中序。

@tpl TB树插入 | m 阶 B 树插入：只往叶子插，满了取第 ⌈m/2⌉ 个上提
1. 每结点关键字数 ∈ [⌈m/2⌉−1, m−1]（根至少 1 个）。
2. 永远插在叶子；插后超过 m−1 个 ⟹ 分裂：第 ⌈m/2⌉ 个关键字上提到父结点，左右各成一个结点。
3. 父结点也可能连锁分裂；根分裂时树长高一层（B 树只从根长高）。
4. 草稿上每次分裂画一行，盯住「谁被挤上去」。

@kp 孩子兄弟 | 孩子兄弟表示法（树、森林 ⟷ 二叉树）
每个结点两个指针：左＝第一个孩子，右＝下一个兄弟。森林的各棵树的根互为兄弟。
- 森林先根 ＝ 二叉树先序；森林后根 ＝ 二叉树中序。
- 森林的叶子数 ＝ 二叉树中左指针为空的结点数。
- 森林的树棵数 ＝ 从二叉树根沿右链走过的结点数。

@tpl T压缩矩阵下标 | 特殊矩阵压缩存储求下标：只数「它前面有几个元素」
1. 先看给的元素在不在被存的那一半：对称矩阵给了下三角元素却存上三角 ⟹ 先换成 $m_{ji}$。
2. 再看按行还是按列：按列 ⟹ 先数前面整列有几个，再数本列里它排第几。
3. 最后看数组从 0 还是 1 起：前面有 $k$ 个 ⟹ 0 起下标 $k$，1 起下标 $k+1$。
4. 四个选项通常就是「行/列 × 0 起/1 起」四种组合，算完对一下哪种口径。

@tpl T出栈序列 | 给操作序列求出栈 / 判断出栈序列是否可能：草稿上画栈，一步一行
1. 给了 Push/Pop 序列 ⟹ 照做，每行写「栈底→栈顶」和已出栈的元素。
2. 判断某出栈序列可不可能 ⟹ 对每个要出的元素：在栈顶就弹；还没入栈就一直压到它；已入栈却不在栈顶 ⟹ 不可能。
3. $n$ 个元素合法出栈序列共 $\frac{1}{n+1}C_{2n}^{n}$ 个（卡特兰数）。

@tpl T顺序存储二叉树 | 二叉树顺序存储要多少单元：看最大编号，不看结点数
1. 顺序存储＝按满二叉树层序编号对号入座（根 1、左 $2i$、右 $2i+1$），空位也占坑。
2. 需要的单元数＝实际出现的最大编号。高度 $h$ 的最大编号最坏是 $2^h-1$（一路向右）。
3. 题干说「任意一棵」⟹ 按最坏 $2^h-1$；说「某一棵 / 至少」且形态可选 ⟹ 让最深的结点尽量靠左。

@tpl TBST序列 | 判断一个序列能否生成给定的二叉排序树：祖先必须先到
1. 序列能生成这棵 BST ⟺ 树中每个结点都排在它所有子孙之前。
2. 只需看每个结点和它的孩子：父亲晚到 ⟹ 孩子先占了父亲的位置 ⟹ 树形变了。
3. 兄弟之间、不同子树之间先后随意；合法序列个数＝拓扑序个数。

@tpl TDFS输出位置 | DFS 递归里「输出语句放在哪」决定得到什么序列
1. 进入递归时输出 ⟹ DFS 序列。
2. 退出递归前输出 ⟹ 每条弧 $u\to v$ 都是 $v$ 先出 ⟹ 逆拓扑序列（有向无环图）。
3. 退出前压栈、最后全部弹出 ⟹ 拓扑序列。
4. 先画一张 3 个点的小 DAG（1→2，1→3，2→3）手跑一遍，比背结论稳。

@tpl TMST过程 | 问 Kruskal / Prim 的加边顺序：列边表，一条条试
1. Kruskal：所有边按权从小到大排好，依次试，两端已连通（成环）就跳过，选够 $n-1$ 条停。
2. Prim：从指定起点出发，每次在「一端在树里、一端不在」的边里挑最小的。
3. 自检：Kruskal 的选边权值必须非递减；边数必须 $n-1$。选项里常有一个是另一种算法的顺序。

@tpl T关键路径判断 | 关键路径的概念判断：长度看权值和；延长必延期，缩短不一定
1. 关键路径＝源点到汇点权值和最大的路径，长度＝最短工期（不是边数最多）。
2. 延长任一关键活动 ⟹ 工期一定延长。
3. 缩短关键活动不一定缩短工期：有多条关键路径时要缩所有关键路径共有的活动；压过头关键路径会转移。

@tpl T堆性质 | 堆的判断题：堆只管纵向（父子），不管横向（兄弟）
1. 堆＝完全二叉树＋父 ≥ 子（大根堆），所以顺序存储、不是二叉排序树。
2. 每棵子树也是堆 ⟹ 次大值在下标 2 或 3；第 $k$ 大只能确定在前 $k$ 层内。
3. 最小值（大根堆）在叶子里，即下标 $\lfloor n/2\rfloor+1\sim n$。

@tpl T排序特性对比 | 比较几种排序「谁的比较/移动更少、与初态有没有关」：拿极端输入试
1. 拿「已有序」「逆序」两种输入各算一遍比较次数和移动次数。
2. 简单选择：比较恒 $n(n-1)/2$，与初态无关；移动 $\le 3(n-1)$，是最少的一类。
3. 直接插入：有序时比较 $n-1$、移动 0；一般情况移动次数＝逆序对数，可达 $O(n^2)$。
4. 空间：除快排 $O(\log n)$、归并 $O(n)$、基数 $O(r)$ 外都是 $O(1)$。

@kp 压缩存储 | 对称矩阵的压缩存储
$n$ 阶对称矩阵 $m_{ij}=m_{ji}$，只存一个三角（含对角线）共 $\frac{n(n+1)}{2}$ 个元素到一维数组。
- 上三角按列优先存，第 $j$ 列有 $j$ 个元素；$m_{ij}$（$i\le j$）前面有 $\frac{(j-1)j}{2}+(i-1)$ 个。
- 上三角按列优先 ≡ 下三角按行优先（转置一下就是同一个顺序）。
- 例：$n=10$，$m_{2,7}$ 前面有 $21+1=22$ 个 ⟹ 0 起下标 22。

@kp 卡特兰数 | 出栈序列个数（卡特兰数）
$n$ 个不同元素依次入栈，可能的出栈序列共 $\frac{1}{n+1}C_{2n}^{n}$ 个。
- $n=3$ 时 5 个，$n=4$ 时 14 个，$n=5$ 时 42 个。
- 同一个数也是 $n$ 个结点二叉树的形态数。

@kp 拓扑序 | 拓扑序列与逆拓扑序列
有向无环图（DAG）里，把顶点排成一列，使每条弧 $u\to v$ 都满足 $u$ 在 $v$ 前面，就是拓扑序列；倒过来（$v$ 在 $u$ 前）是逆拓扑序列。
- 有环 ⟺ 不存在拓扑序。
- 求法：反复删入度为 0 的点（Kahn）；或 DFS 按退出时间从大到小排。
- 例：1→2、1→3、2→3 的拓扑序只有 1,2,3。

@kp Kruskal | Kruskal 与 Prim
两个求最小生成树的贪心算法。
- Kruskal：边按权升序逐条加，成环则跳过；用并查集判环；$O(e\log e)$，适合稀疏图。
- Prim：从一个顶点长树，每次加「树内到树外」最轻的边；$O(n^2)$，适合稠密图。
- 边权互不相同 ⟹ MST 唯一（但两种算法的加边顺序一般不同）。

@kp 关键路径 | AOE 网与关键路径
AOE 网：顶点是事件、边是活动、边权是活动时间。
- 关键路径＝源点到汇点权值和最长的路径；它的长度＝完成工程的最短时间。
- 关键活动：最早开始 $e$＝最迟开始 $l$ 的活动（余量 0）。
- 延长关键活动必延长工期；缩短不一定缩短（多条关键路径、或缩过头关键路径转移）。

@kp 堆 | 堆（大根堆 / 小根堆）
完全二叉树，且每个结点 ≥（大根堆）它的孩子。顺序存储在数组 $A[1..n]$ 里，$A[i]$ 的孩子是 $A[2i]$、$A[2i+1]$。
- 只约束父子，不约束兄弟 ⟹ 不是二叉排序树。
- 建堆 $O(n)$，插入、删堆顶 $O(\log n)$；堆排序不稳定。
- 例：9(8(5,6),7) 是合法大根堆，中序 5,8,6,9,7 无序。

@tpl T部件位数 | 问「某部件的位数一定等于什么」：先问它装的是什么
1. 装整数数据、直连 ALU（ALU、通用寄存器）⟹ 机器字长。
2. 装指令（IR）⟹ 指令字长；装存储单元内容（MDR）⟹ 存储字长。
3. 装地址（MAR、PC）⟹ 地址位数；浮点寄存器 ⟹ 浮点格式宽度（常 64、80 位）。

@tpl T位模式多解 | 给一串机器数问「它的值可能是」：每种类型各读一遍
1. 先写成二进制，按题目允许的类型（int 补码 / unsigned / float / short…）各算一个值。
2. 补码负数快算：机器数 − $2^{n}$；看到连续 $k$ 个 1 想到 $2^k-1$。
3. float：符号 1 位、阶码 8 位减 127、尾数前补隐藏位 1。
4. 选项通常只给其中一种解释的值，算出一个不在选项里就换另一种。

@tpl T对齐小端 | 结构体成员的某个字节在哪个地址：先对齐算起点，再按小端拆字节
1. 对齐：每个成员的偏移是自身大小的整数倍，不够就填充；结构体总长补到最大成员的整数倍。
2. 小端：最低有效字节放最低地址。把机器数按「高→低」写一行，整行倒过来，从成员起点逐格对。
3. 大端（网络字节序）就不倒。四个选项常是「对齐/不对齐 × 大端/小端」。

@tpl T指令格式位数 | 定长指令字的字段位数：⌈log₂ 个数⌉ 后做减法，再看问的是哪种寻址
1. 操作码 $\lceil\log_2(\text{指令条数})\rceil$，寻址特征 $\lceil\log_2(\text{寻址方式数})\rceil$，剩下的是地址码。
2. 直接寻址给的是主存地址 ⟹ 无符号 $0\sim2^n-1$。
3. 相对寻址给的是偏移量、立即数常为补码 ⟹ $-2^{n-1}\sim2^{n-1}-1$。
4. 题干说「扩展操作码」时不能直接做减法，要逐级算编码空间。

@tpl TCPI对照 | 比较几种 CPU 结构的 CPI / 性能：数「一个时钟周期完成几条指令」，再乘时钟周期
1. 单周期 CPI＝1（周期最长）；多周期 CPI＞1；基本流水线理想 CPI＝1；超标量 CPI＜1；超流水线 CPI＝1 但周期更短。
2. 「理想情况」才成立；有冒险、阻塞、Cache 缺失时实际 CPI 变大。
3. 比性能一律回到 CPU 时间＝指令数 × CPI × 时钟周期，三个因子缺一不可。

@tpl T中断三分 | 判断一个事件是外中断、故障还是自陷：看谁触发、回到哪条
1. 和正在执行的指令无关、来自 CPU 外部（定时器、I/O 完成、网卡）⟹ 外中断，回下一条。
2. 指令执行中出错（缺页、除零、越界）⟹ 故障，回本条重新执行。
3. 执行一条陷阱指令主动进入（系统调用、断点 int3、单步 TF）⟹ 自陷，回下一条。
4. 可屏蔽中断要「请求 ＋ 开中断且未屏蔽 ＋ 指令执行完」三关全过才响应。

@tpl T带宽口径 | 总线带宽：每秒传几次 × 每次几字节有效数据 × 几个方向
1. 每秒传送次数＝时钟频率 × 每周期传几次；题干直接给 MT/s（工作频率）就不能再乘。
2. 每次的字节数只算有效数据（校验位不算），除非题干另说。
3. 全双工两个方向同时传 ⟹ 再 ×2。
4. 带宽不看事务时序；「有效数据传输率」才用数据量 ÷ 事务总时间。

@tpl TDMA方式 | DMA 题：先分清是哪种访存冲突方式，再数总线请求次数
1. 停止 CPU 访存：整块期间 CPU 不能访存。
2. 周期挪用：每传一个字挪一个存储周期、传完立即还总线，CPU 在字与字之间照样访存。
3. 交替访存：CPU 周期劈成两半，CPU 完全不受影响。
4. 总线请求次数＝数据块大小 ÷ 缓冲寄存器宽度；整块传完只发 1 次「DMA 结束」中断。

@tpl T存储层次对照 | Cache / TLB / 主存 / 磁盘的判断题：列「存什么、用什么做、缺失找谁、谁来处理」四行
1. Cache 存主存数据块；TLB 存页表项；两者都用 SRAM、都靠局部性。
2. 缺失去哪：Cache、TLB 缺失都去主存；缺页才去磁盘。
3. 谁处理：Cache 缺失只能硬件；TLB 缺失硬件或软件；缺页只能 OS。
4. 命中组合：TLB 命中则页一定在内存；TLB 缺失、页命中、Cache 缺失都可能。

@kp 机器字长 | 机器字长
CPU 内部用于**整数运算**的数据通路宽度＝ALU 位数＝通用寄存器位数。
- 指令字长（IR 的位数）、存储字长（MDR 的位数）可以与它不同。
- 浮点寄存器走浮点通路，宽度由浮点格式决定（32 位机的双精度寄存器是 64 位）。

@kp IEEE754 | IEEE 754 单精度浮点数
32 位＝符号 1 位 ＋ 阶码 8 位（移码，偏置 127）＋ 尾数 23 位（前面隐含一个 1）。
- 值 $=(-1)^s\times1.f\times2^{e-127}$（$e$ 为 1～254 时）。
- 例：C800 0000H：$s=1$，$e=1001\,0000_2=144$，$f=0$ ⟹ $-1.0\times2^{17}$。

@kp 补码真值 | 补码机器数的真值
$n$ 位补码，最高位为 1 时是负数，真值＝机器数（当无符号读）$-2^n$。
- 例：32 位 C800 0000H ＝ 3355443200，减 $2^{32}$ 得 $-939524096=-7\times2^{27}$。
- 也可「数值位取反加 1 再加负号」，两种方法互相验算。

@kp 边界对齐 | 边界对齐
每个基本类型的数据，地址必须是自身长度的整数倍（short 2、int 4、double 8）。
- 结构体成员按声明顺序放，前一个成员末尾到下一个成员的对齐位置之间填充空字节。
- 结构体总长补到最大成员长度的整数倍（数组里下一个元素也能对齐）。

@kp 小端 | 大端与小端
一个多字节数在内存里的字节顺序。
- 小端：最低有效字节（LSB）放在最低地址（x86）。
- 大端：最高有效字节（MSB）放在最低地址（网络字节序）。
- 例：1234 0000H 小端存于 FE04H 起：00 00 34 12。

@kp TLB | TLB（快表）
存放最近用过的页表项的高速缓存，用 SRAM 做，通常全相联或组相联。
- 命中：直接得到物理页框号；缺失：去主存的页表取页表项（硬件或软件处理均可）。
- 它缓存的是「地址映射」，Cache 缓存的是「数据块」；两者都靠局部性起效。

@kp 寻址方式 | 直接、间接、立即、相对寻址
- 直接：$EA=A$（形式地址就是主存地址，无符号）。
- 间接：$EA=(A)$，再访存一次取地址。
- 立即：操作数就是 $A$ 本身（常为补码）。
- 相对：$EA=(PC)+A$，$A$ 是补码偏移，可前可后。

@kp CPI | CPI
执行一条指令平均需要的时钟周期数。CPU 时间＝指令条数 × CPI × 时钟周期。
- 单周期 CPU：CPI＝1，但时钟周期按最慢的指令定，很长。
- 多周期：CPI＞1；基本流水线（理想）：CPI＝1；超标量：CPI＜1。

@kp 自陷 | 自陷（陷阱，Trap）
执行陷阱指令时主动触发的**内部异常**，属于事先安排好的「有意」异常。
- 用途：系统调用、程序调试的断点（int3）与单步（TF＝1）。
- 处理完回到陷阱指令的**下一条**；对比故障（如缺页）回到本条重新执行。

@kp NMI | 不可屏蔽中断 NMI 与可屏蔽中断 INTR
外中断经两根线进 CPU：INTR（可屏蔽）、NMI（不可屏蔽）。
- NMI：关中断（IF＝0）也响应，优先级最高，用于掉电、硬件故障等紧急事件。
- INTR：要开中断、未被屏蔽字屏蔽、当前指令执行完才响应。
- 屏蔽字能改变的是**处理**优先级，**响应**优先级由硬件排队线路固定。

@kp 周期挪用 | DMA 的周期挪用
DMA 控制器每传送一个数据字，向 CPU 申请（挪用）一个存储周期，传完立即释放总线。
- 一个数据块被拆成很多次单字传送，每次都要发总线请求。
- CPU 在两次挪用之间照样访存；DMA 的总线优先级高于 CPU（I/O 数据不等人）。

@tpl T打开文件表 | 多进程打开同一文件：系统表一份（带计数），用户表各一份
1. 系统打开文件表全系统一张，一个文件只占一项，含打开计数和文件属性（FCB/inode 副本）。
2. 每个进程有自己的用户打开文件表：读写指针、打开方式、权限各自不同，表项指向系统表项。
3. open 已打开的文件 ⟹ 计数 +1；close ⟹ 计数 −1，减到 0 才删系统表项。
4. OS 不保证多个写者互斥，要互斥得进程自己加锁（读者-写者）。

@tpl T文件分配方式 | 选磁盘分配方式：随机访问 + 可变长 ⟹ 索引
1. 连续：随机访问快，但难扩展、有外部碎片。
2. 隐式链接：易扩展，只能顺序访问；显式链接（FAT）：可随机访问，但 FAT 要常驻内存。
3. 索引：随机访问 ✓、可变长 ✓、无外部碎片，代价是索引块。
4. 选项里混进内存管理术语（动态分区、分页）直接划掉。

@tpl T中断分工 | 中断处理里「谁做的」：硬件三件事，其余都是 OS
1. 硬件（中断隐指令）：关中断、保存断点（PC、PSW）、取中断向量跳到服务程序。
2. OS（服务程序）：保存屏蔽字和通用寄存器、提供服务、恢复现场、开中断、中断返回。
3. OS（开机引导时）：建立并初始化中断向量表——不在中断发生时做。

@tpl T调度算法要素 | 问某调度算法「要考虑 / 会不会饥饿 / 是否抢占」：先把它的规则用一句话说全
1. 多级反馈队列四个参数：队列数、各队列优先级、各队列内算法、迁移条件。
2. 会饥饿的：短作业优先、静态优先级（非老化）、多级反馈队列；不会饥饿的：FCFS、RR、高响应比优先。
3. 是否抢占看规则里有没有「来了更高优先级就打断」。

@tpl T银行家安全性 | 银行家算法表格题：先算 Need 和 Available，再用 Work 推进
1. 表头若给「最大需求 / 需求总量」，先算 Need＝Max − Allocation。
2. Available＝资源总数 − 各进程已分配之和；先看哪一列已被分光（Available 为 0），起手只能推 Need 那一列为 0 的进程。
3. 推进：找 Need ≤ Work 的进程，完成后 Work += 它的 **Allocation**（不是 Max），直到全部完成或卡住。
4. 选项给了几个序列时，逐个代入验证即可；问「是否安全」只要找到一个序列。

@tpl TEAT公式 | 有效访存时间：按「命中 / 缺失」加权平均，缺失那一支把处理全过程写出来
1. EAT＝(1−p)×访存时间＋p×(缺页处理时间＋访存时间)。
2. 缺页处理时间＝CPU 处理缺页中断的时间＋（换出脏页）＋读入新页的磁盘时间。
3. 有 TLB 时再套一层：TLB 命中 / TLB 缺失页表命中 / 缺页三支。

@tpl T父子进程线程 | 谁和谁共享什么：同一进程的线程共享地址空间；父子是两个进程
1. 父子进程：各有 PCB、各有虚拟地址空间（fork 复制一份）、可并发；可共享已打开文件等部分资源。
2. 同一进程的线程：共享地址空间、全局变量、打开文件；不共享栈、寄存器、PC。
3. 临界资源对任何两个进程都要互斥使用，父子没有特权。

@tpl T设备层次 | I/O 软件题：先把四层画出来，再问「这件事归哪层」
1. 用户层 I/O 软件 → 设备独立性软件 → 设备驱动程序 → 中断处理程序 → 硬件。
2. 逻辑名到物理名的映射（LUT）、缓冲、设备分配、出错处理：设备独立性软件。
3. 把抽象命令翻译成设备操作、直接操作控制器寄存器：驱动程序（换设备就换它）。
4. 换物理设备：改映射、换驱动，应用程序不改。

@tpl T文件数上限 | 文件系统「最多多少个文件 / 单个文件最大多长」：先分清问的是数量还是大小
1. 文件数量上限 ⟹ 看全局唯一的编号：inode 号（或 FCB 号）有几位，或 inode 区能放多少个 inode。
2. 文件名在不同目录下可以重名，不构成上限。
3. 单个文件最大长度 ⟹ 看 inode 里直接、间接地址项的个数和块大小。

@tpl T互斥四准则 | 互斥机制的四条准则：前三条管正确性（必须），让权等待管效率（可不满足）
1. 空闲让进、忙则等待、有限等待：必须满足。
2. 让权等待：进不去时放弃 CPU，只影响效率；Peterson、TSL、Swap 都不满足它，但仍是正确的互斥方法。
3. 判断某个软件算法违反哪条：单标志违反空闲让进；双标志先检查违反忙则等待；双标志后检查违反空闲让进与有限等待。

@kp 打开文件表 | 系统打开文件表与用户打开文件表
- 系统打开文件表：整个系统一张，每个被打开的文件一项，含文件属性和打开计数。
- 用户（进程）打开文件表：每个进程一张，每项含读写指针、打开方式，并指向系统表项；open 返回的文件描述符就是它的下标。
- close：用户表项删除，系统表项计数减 1，减到 0 才删除。

@kp 索引分配 | 索引分配
每个文件一个索引块，按逻辑块号顺序存放各物理块号；FCB 里只记索引块的位置。
- 随机访问：第 $i$ 块直接查索引第 $i$ 项。
- 文件变长：往索引里加项即可；大文件用多级索引或混合索引。
- 无外部碎片；代价是索引块本身占空间。

@kp 中断向量表 | 中断向量表
存放各中断服务程序入口地址的表（数组），下标就是中断类型号。
- 由操作系统在初始化（开机引导）时建立并填写。
- 中断发生时，硬件按中断类型号查表、取入口地址并跳转。

@kp 多级反馈队列 | 多级反馈队列调度
设多个就绪队列，优先级逐级降低、时间片逐级加长；新进程进第一级，时间片用完未完成就降到下一级；上一级空了才调度下一级。
- 设计时要定：队列个数、各队列优先级、各队列的调度算法、进程在队列间迁移的条件。
- 兼顾短进程（响应快）与长进程（不会一直轮不到——除非一直有新进程进来，可能饥饿）。

@kp 银行家算法 | 银行家算法与安全性算法
- 数据结构：Available、Max、Allocation、Need＝Max−Allocation。
- 安全性算法：Work＝Available；反复找 Need ≤ Work 的未完成进程，令它完成并 Work += Allocation；全部能完成 ⟹ 安全，得到的顺序是安全序列。
- 请求算法：Request ≤ Need、Request ≤ Available 后试分配，再跑安全性算法，不安全就撤销、让进程等待。
- 不安全 ≠ 死锁。

@kp EAT | 请求分页的有效访存时间
EAT＝(1−p)·t＋p·(缺页处理时间＋t)，$p$ 是缺页率，$t$ 是一次访存时间。
- 缺页处理时间包括：缺页中断的 CPU 处理时间、换出与读入页面的磁盘时间等，通常是毫秒级，比 $t$（纳秒级）大 $10^5$ 倍以上。
- 例：$t=100$ns、处理 8ms、$p=10^{-5}$ ⟹ EAT≈100ns＋80ns＝180ns。

@kp fork | 父进程与子进程
父进程用 fork 创建子进程：子进程获得父进程地址空间的一份副本、自己的 PCB 和 PID。
- 两者是独立的进程，可以并发执行，虚拟地址空间不共享（写时复制只是物理层面的优化）。
- 子进程继承父进程已打开的文件，可以共享这些文件。

@kp 设备独立性 | 设备独立性
应用程序使用逻辑设备名，与实际使用的物理设备无关；系统通过逻辑设备表（LUT）把逻辑设备映射到物理设备及其驱动。
- 换物理设备：只改映射关系、换驱动程序，应用程序不用改。
- UNIX 把设备当作特殊文件（/dev 下），用文件名就能访问设备。

@kp inode | 索引节点（inode）与目录项
UNIX 类文件系统把文件说明分成两部分：目录项只存「文件名 ＋ inode 号」，其余属性和地址信息放在 inode 里。
- inode 号全系统唯一，每个文件一个 inode；文件名在不同目录下可以相同。
- 好处：目录项变短，查目录时读盘次数少；硬链接＝多个目录项指向同一 inode。

@kp 互斥准则 | 临界区互斥的四条准则
- 空闲让进：临界区空闲时，允许一个请求进入的进程立即进入。
- 忙则等待：已有进程在临界区时，其他进程必须等待。
- 有限等待：请求进入的进程要在有限时间内进入（不饥饿）。
- 让权等待：进不去时立即释放处理器（不忙等）——不是必须的。

@tpl T协议三要素 | 看图/看描述判协议要素：只认实际画出来的东西
1. 字段、位数、格式框 ⟹ 语法。
2. 「收到 X 就做 Y」、字段的含义、出错怎么办 ⟹ 语义。
3. 时间轴、往返箭头、先后顺序 ⟹ 时序（同步）。

@tpl T交换方式对比 | 电路交换 / 虚电路 / 数据报：先问「建的是物理通路还是逻辑连接」
1. 电路交换：建立物理通路，预留带宽、独占，无存储转发、无排队。
2. 虚电路：建立逻辑连接，只在建立时选一次路由，之后按 VC 号转发、按序到达；链路统计复用，不预留带宽、有存储转发。
3. 数据报：不建连接，每个分组独立选路、可能乱序（IP）。

@tpl T冲突域广播域 | 数冲突域与广播域：从每台设备的端口往下看
1. 广播域：只有路由器（三层）能隔开 ⟹ 广播域数＝路由器接口所连的网段数。
2. 冲突域：交换机、路由器的每个端口各隔开一个；端口下若挂集线器，集线器连同它下面的主机合成一个冲突域。
3. 集线器、中继器什么都不隔。

@tpl T停等利用率 | 停等 / 滑动窗口利用率：先画一个发送周期，再看分子
1. 一个周期 $T$＝数据帧发送 $T_D$＋传播 $\tau$＋确认帧发送 $T_A$＋传播 $\tau$；题目说「忽略确认帧」才令 $T_A=0$。
2. 停等 $U=T_D/T$；窗口为 $W$ 时 $U=\min(1, W\cdot T_D/T)$。
3. 选项常是漏掉某一项的口径，算出四种分母对一下。

@tpl TIFS判定 | 802.11 帧间间隔：新的接入用 DIFS，同一次对话里的后续帧用 SIFS
1. 站点想发起一次新的传输（RTS，或不用 RTS 时的 DATA）：先等 DIFS（最长）。
2. CTS、跟在 CTS 后的 DATA、ACK：都只等 SIFS（最短），别人插不进来。
3. 长短只看紧跟其后的帧类型，与是谁发的无关。

@tpl T拥塞窗口 | 拥塞窗口变化题：逐 RTT 列 cwnd，问「最短/最长」时自己挑 ssthresh
1. 慢开始：cwnd < ssthresh 时每 RTT 翻倍（不超过 ssthresh）；拥塞避免：每 RTT +1 MSS。
2. 超时：ssthresh＝cwnd/2，cwnd＝1；3 个冗余 ACK：ssthresh＝cwnd/2，cwnd＝ssthresh 后线性。
3. 问「最短时间」⟹ 让它一直指数增长；问「最长时间」⟹ 把 ssthresh 设成 ≤ 起点，全程线性。
4. 最后别忘了乘 RTT 的具体时间。

@tpl TTCP序号 | TCP 序号计数：SYN、FIN 各占一个序号，纯 ACK 不占
1. 数据从 SYN 的 seq＋1 开始编号。
2. FIN 的 seq＝最后一个数据字节的序号＋1。
3. 数据字节数＝FIN.seq − SYN.seq − 1；确认号＝期望收到的下一个序号。
4. 先圈出题目给的 seq 属于哪个报文段（SYN？FIN？第几次挥手？）。

@tpl TRTT账本 | 「从点击到收到页面」这类时间题：DNS 几个 RTT ＋ TCP 握手 ＋ 取对象
1. 圈出时延可忽略的那一跳（如主机到本地域名服务器在同一局域网）。
2. DNS：有缓存 0；本地域名服务器迭代查询根、顶级、权限服务器各 1 RTT。
3. 取一个对象：握手 1 RTT（第三次握手捎带请求）＋请求响应 1 RTT＝2 RTT。
4. 多个对象按持续/非持续、流水线/非流水线再记账；「最短/最长」分别对应全命中缓存与全迭代。

@kp 协议三要素 | 网络协议三要素
- 语法：数据与控制信息的格式（字段、长度、编码）。
- 语义：各控制信息的含义、要做出的动作和响应。
- 同步（时序）：事件发生的先后顺序、速度匹配。
例：TCP 首部格式图是语法；「收到 SYN 回 SYN+ACK」是语义；三次握手的时间顺序图是时序。

@kp 虚电路 | 虚电路
分组交换的一种连接方式：通信前建立一条逻辑连接（虚电路），建立时做一次路由选择，各结点记下「入 VC 号 → 出端口、出 VC 号」。
- 之后的分组只带短的虚电路号，沿同一路径按序到达。
- 「虚」：链路不是专用的，多条虚电路统计复用同一链路，不预留带宽。
- 某结点故障 ⟹ 经过它的虚电路全部断开。

@kp 冲突域 | 冲突域与广播域
- 冲突域：同一时刻只能有一台设备发送、否则会冲突的范围；集线器连起来的都在一个冲突域里。
- 广播域：一个广播帧能到达的范围；交换机转发广播，只有路由器（或 VLAN）隔离广播。
- 例：路由器两个接口各接一台交换机 ⟹ 2 个广播域。

@kp 停等协议 | 停止-等待协议的信道利用率
发送一帧后等确认，收到确认才发下一帧。一个发送周期 $T=T_D+\tau+T_A+\tau$。
- 利用率 $U=T_D/T$（只有发数据帧那段时间信道在「有效」工作）。
- 例：$T_D=800$ms、$\tau=200$ms、$T_A=800$ms ⟹ $U=800/2000=40\%$。

@kp IFS | 802.11 的帧间间隔
- SIFS（短帧间间隔）：最短，用于 CTS、ACK 以及收到 CTS 后发的数据帧——同一次对话里的后续帧。
- DIFS（分布协调功能帧间间隔）：最长，站点要发起新的传输前等待。
- 时长 SIFS < PIFS < DIFS，越短优先级越高。

@kp 拥塞控制 | TCP 拥塞控制四算法
- 慢开始：cwnd 从 1 起每 RTT 翻倍，到 ssthresh 为止。
- 拥塞避免：cwnd ≥ ssthresh 后每 RTT 加 1 MSS。
- 超时：ssthresh＝cwnd/2，cwnd＝1，重新慢开始。
- 快重传＋快恢复：收到 3 个冗余 ACK 立即重传，ssthresh＝cwnd/2，cwnd＝ssthresh，进入拥塞避免。
- 发送窗口＝min(rwnd, cwnd)。

@kp TCP序号 | TCP 序号与确认号
- 序号（seq）：本报文段数据第一个字节的编号。确认号（ack）：期望收到对方下一个字节的编号。
- SYN、FIN 虽不带数据，各消耗一个序号；纯 ACK 不消耗。
- 例：SYN seq＝1000，数据从 1001 开始；发了 4000B 后 FIN 的 seq＝5001，对方确认 FIN 的 ack＝5002。

@kp DNS查询 | DNS 递归查询与迭代查询
- 递归查询：被问的服务器替你把答案查到再返回（主机 → 本地域名服务器通常是递归）。
- 迭代查询：被问的服务器只告诉你「下一个去问谁」，由你再去问（本地域名服务器 → 根、顶级、权限服务器通常是迭代）。
- 本地域名服务器完整迭代一次：根 → 顶级域 → 权限域名服务器，各 1 个 RTT。

@tpl T多指针有序 | 几个升序数组里各取一个、求某个「最优组合」：每个数组一个指针，每轮只动最小的那个
1. 先把目标写成「最大值 − 最小值」之类的形式，看清动哪个指针才可能变好。
2. 每轮算一次当前组合、更新答案，然后把最小元素所在数组的指针后移（谁小谁走）。
3. 任一指针走到头就停：时间 $O(n_1+n_2+\dots)$，空间 $O(1)$。
4. 卷面：基本设计思想 → C 代码（带注释）→ 时空复杂度；暴力三重循环只能拿一部分分。

@tpl T前缀码树 | 前缀码 / 编码判定 / 译码：都用一棵 0 左 1 右的二叉树
1. 存：每个字符是一个叶子，编码是根到叶子的路径。前缀特性 ⟺ 字符全在叶子上。
2. 译：从根出发读一位走一步，到叶子输出字符、回到根。
3. 判：边插边查——途经已有的叶子（别人是我的前缀）或一个新结点都没建（我是别人的前缀）⟹ 不是前缀码。

@tpl T乘法溢出 | n 位乘法取低 n 位：无符号看高 n 位全 0，有符号看高 n+1 位全同
1. 先用真值算出 2n 位乘积，写成十六进制，分出高 n 位、低 n 位。
2. 无符号：高 n 位全 0 ⟹ 不溢出。
3. 有符号：高 n 位与低 n 位的最高位，共 n+1 位全 0 或全 1 ⟹ 不溢出。
4. 也可直接比真值是否落在类型范围内，两种判法互相验算。

@tpl TCache地址划分 | Cache 题第一步：把主存地址切成「标记 | 组号（行号）| 块内地址」
1. 块内地址位数＝$\log_2$ 块大小；组数＝Cache 容量 ÷（块大小 × 路数），组号位数＝$\log_2$ 组数。
2. 标记位数＝地址位数 − 组号 − 块内地址。
3. 每行附加位：有效位 1；LRU 位 $\log_2$ 路数（2 路 1 位、4 路 2 位、8 路 3 位）；回写才有修改位，直写没有。
4. 给具体地址就把十六进制写成二进制，按位数切三段。

@tpl T数组遍历局部性 | 数组遍历的缺失 / 缺页次数：先算「一块（一页）装几个元素」
1. 一块装 $k$ 个元素；顺序访问时每块只第一次缺失。
2. 先查首地址是否块（页）对齐：不对齐会多跨一块。
3. 每个元素访问几次（读 1 次＋写 1 次？）决定访问总数，但缺失次数仍按块数算。
4. 按列遍历行优先数组：步长 ＝ 一行的字节数，常常每次都换块（页）。

@tpl T前驱图PV | 前驱关系用信号量实现：一条边一个信号量，初值 0；边的起点做完 V，终点开始前 P
1. 先把文字画成前驱图，数边。
2. 每条边 $X\to Y$ 设信号量 $S_{XY}=0$：$X$ 末尾 V($S_{XY}$)，$Y$ 开头 P($S_{XY}$)。
3. 校验：几条边就有几个信号量、几个 P、几个 V。
4. 同一线程内部的先后由程序顺序保证，不用信号量（2022 年那题只用 2 个）。

@tpl T多级页表地址 | 二级页表求各种地址：拆位 + 「表项地址＝表起址＋序号×表项长」
1. 先求虚拟地址（数组元素：首地址＋偏移；能整行整页地数更好）。
2. 写成二进制按位数切：页目录号 | 页号 | 页内偏移。
3. 页目录项地址＝页目录起址＋页目录号 × 项长；页表项地址＝页表起址（页框号 × 页大小）＋页号 × 项长。
4. 页框号不是地址：页框号后面补上页内偏移的位数（4KB 页就是十六进制补三个 0）。

@tpl TNAT改址 | NAT 题：出站改源、入站改目的；外面要主动访问里面，就得配静态映射
1. 分组从内网出去经过 NAT：源地址（和源端口）改成 NAT 的外网地址。
2. 分组从外网进来经过 NAT：目的地址（和端口）按 NAT 表改成内网主机的地址。
3. 内网服务器要被外部主动访问 ⟹ 事先在它那侧的 NAT 上配静态映射（外网 IP:端口 ↔ 内网 IP:端口）；客户端那侧由出站分组自动建表。
4. 两个私网可能用同一网段，草稿上标清「哪一边的」。

@kp 前缀码 | 前缀码
任何一个字符的编码都不是另一个字符编码的前缀。这样的 0/1 串可以从左到右唯一译码，不需要分隔符。
- 用二叉树表示：左分支 0、右分支 1，字符放在叶子上 ⟺ 前缀码。
- 哈夫曼编码就是带权路径长度最小的前缀码。
- 例：{0, 10, 110, 111} 是前缀码；{0, 01} 不是（0 是 01 的前缀）。

@kp 组相联 | 组相联映射
Cache 分成若干组，每组 $r$ 行（$r$ 路组相联）；主存块按「块号 mod 组数」映射到某一组，可放在组内任意一行。
- 地址划分：标记 | 组号 | 块内地址。
- 查找：用组号选组，组内 $r$ 个比较器并行比较标记（且有效位为 1）。
- 1 路即直接映射，路数＝总行数即全相联。

@kp 直写回写 | 直写法与回写法
- 直写（全写）：写命中时同时写 Cache 和主存，Cache 与主存始终一致 ⟹ 不需要修改位（脏位）。
- 回写：只写 Cache，块被替换时才写回主存 ⟹ 每行要一个修改位，标记它是否被改过。

@kp 二级页表 | 二级页表
32 位虚拟地址＝页目录号（10 位）| 页号（10 位）| 页内偏移（12 位），页大小 4KB，每张页表 1024 项正好占一页。
- 页目录项给出某张二级页表所在的页框号；页表项给出数据页的页框号。
- 只为用到的虚拟区域建二级页表，省内存；代价是多一次访存。

@kp NAT | 网络地址转换 NAT
让使用私有地址（如 192.168.0.0/16）的内网主机共用路由器的公网地址访问外网。
- NAPT 同时转换 IP 地址和端口号，转换表项形如「外网 IP:端口 ↔ 内网 IP:端口」。
- 出站分组改源地址，入站分组改目的地址；外部要主动访问内网服务器，须预先配置静态映射。

@kp 信号量同步 | 用信号量实现同步（前驱关系）
同步信号量初值 0，表示「前一件事还没做完」：
- 前驱操作做完后 V(S)；后继操作开始前 P(S)。
- P 在前驱完成之前会阻塞，于是后继一定晚于前驱。
- 互斥信号量初值 1，P、V 在同一进程里成对出现；同步信号量的 P、V 分在两个进程里。

@tpl T受限双端队列 | 受限双端队列判出队序列：画出「队里的排列」，再看能否按出口依次取
1. 先找第一个出队的元素 $x$：它出队时，入队序列里排在它前面的元素全都已经在队里。
2. 输出受限（两端进、一端出）：每个元素进来时只能贴在队的左端或右端 ⟹ 队里是「从第一个元素向两边长」的形状；出口只有一个，后面只能按这个排列依次出。
3. 输入受限（一端进、两端出）：队里的顺序就是入队顺序，只看能不能每次从两头之一取到下一个要的元素。
4. 4 个元素的经典结论：输出受限得不到 4,1,3,2 与 4,2,3,1；输入受限得不到 4,2,1,3 与 4,2,3,1。

@tpl T数组地址 | 数组元素地址：前面隔了几个元素 × 元素长度；给两个地址就反推维数
1. 行优先 $A[i][j]$（下标从 0）：地址 ＝ 首地址 ＋（$i\times$列数 ＋ $j$）× 元素长度；列优先把「行、列」对调。
2. 下标从 1 开始：先把 $i$、$j$ 各减 1 再套。
3. 给两个元素地址：地址差 ÷ 元素长度 ＝ 它们之间隔的元素个数，列出一次方程解出列数（行数）。

@tpl T哈夫曼 | 「最小 WPL / 最优编码」：构造哈夫曼树；WPL＝所有非叶结点权值之和
1. 每次从集合里取最小的两个合并，新权值放回集合，直到剩一个。
2. WPL 两种算法互相验算：叶子权 × 深度求和；或把每次合并得到的新权值全加起来。
3. 根的权值＝权值总和，不是 WPL。$n$ 个叶子 ⟹ 合并 $n-1$ 次、结点 $2n-1$ 个、没有度为 1 的结点。

@kp 哈夫曼树 | 哈夫曼树（最优二叉树）
给定 $n$ 个带权叶子，带权路径长度 $\mathrm{WPL}=\sum w_i\,l_i$ 最小的二叉树。
- 构造：反复合并权值最小的两棵树。结果不唯一（左右可换、权值相等时可选），但 WPL 唯一。
- 每次合并产生一个非叶结点，它的权值恰好被下面每个叶子各「算」一次 ⟹ WPL＝非叶结点权值之和。
- 例：{1,2,3} ⟹ 先合 1、2 得 3，再合 3、3 得 6 ⟹ WPL＝3＋6＝9＝1×2＋2×2＋3×1。

@tpl TAVL旋转 | AVL 插入后调平：找最低失衡点 A，看新结点在 A 的哪个孩子的哪棵子树
1. 从新结点往上逐个算平衡因子，第一个 |bf|＝2 的是 A（最小不平衡子树的根）。
2. 新结点在 A 的左孩子的左子树 ⟹ LL；右孩子的右子树 ⟹ RR；左孩子的右子树 ⟹ LR；右孩子的左子树 ⟹ RL。
3. 单旋（LL、RR）：A 的那个孩子 B 上位；双旋（LR、RL）：B 的那个孩子 C（「孙子」）上位，A、B 分站两边。
4. 选择题只问根是谁 ⟹ 判型后直接说出谁上位，不必真画旋转。

@kp AVL | 平衡二叉树（AVL）
二叉排序树，且每个结点左右子树高度差（平衡因子）的绝对值 ≤ 1。
- 插入后只需调整最低的那个失衡结点，调完整棵树就平衡了。
- 高度为 $h$ 的 AVL 至少有 $n_h$ 个结点：$n_1=1,n_2=2,n_h=n_{h-1}+n_{h-2}+1$（1、2、4、7、12、20…）。
- 例：依次插 1、2、3 ⟹ 1 失衡（RR）⟹ 2 上位，得 2(1,3)。

@tpl T拓扑计数 | 拓扑序列有几个：逐步删入度为 0 的点，盯住「每一步有几个候选」
1. 先列入度表。每一步只看此刻入度为 0 的顶点有几个。
2. 每一步都恰好 1 个 ⟺ 拓扑序列唯一。
3. 某一步出现 2 个候选：不能直接答 2，要沿每个分支继续数（后面的候选会受影响），点少时直接把序列写全。

@tpl TDijkstra表 | Dijkstra 按轮列 dist 表：每轮选未确定的最小值，再用它松弛邻居
1. 第 0 行写源点的直接出边（其余 ∞）。
2. 每一轮：圈出未确定顶点里 dist 最小的那个（它的最短路就此确定），再用它更新它的邻居：$d[v]=\min(d[v],d[u]+w)$。
3. 「求出第 $k$ 条最短路径后」＝第 $k$ 轮做完（含松弛）的那一行；问终值才做完所有轮。
4. 选项经常就是不同轮次的快照，数清轮数。

@kp Dijkstra | Dijkstra 算法
求单源最短路径（边权非负）。集合 S 放已确定最短路的顶点，每轮把 S 外 dist 最小的顶点加入 S，并用它松弛其余顶点。
- 时间 $O(n^2)$（邻接矩阵）；有负权边时可能出错（用 Bellman-Ford）。
- 加入 S 的次序就是最短路径长度从小到大的次序。
- 例：1→2 权 5、1→3 权 2、3→2 权 1 ⟹ 先定 3（2），再用 3 把 dist(2) 改成 3。

@tpl TB树结点数 | B 树结点数 / 关键字数的最多最少：一层一层数，「关键字数＋1＝孩子数」
1. $m$ 阶：每结点关键字 $[\lceil m/2\rceil-1,m-1]$（根 $[1,m-1]$），孩子数＝关键字数＋1。
2. 下一层的结点数＝上一层各结点的孩子数之和＝上一层关键字数＋上一层结点数。
3. 求结点最多：每层关键字摊成尽量多的结点（每个结点装得少）；求结点最少：装满。上一层的容量会限制这一层能有几个结点，要两头同时检查。

@kp B树 | B 树（多路平衡查找树）
$m$ 阶 B 树：每个结点最多 $m$ 棵子树、$m-1$ 个关键字；非根非叶结点至少 $\lceil m/2\rceil$ 棵子树；所有叶子在同一层。
- 结点内关键字有序，$k$ 个关键字把子树分成 $k+1$ 棵。
- 3 阶 B 树（2-3 树）：每结点 1～2 个关键字、2～3 个孩子。
- 例：3 阶、根有 2 个关键字 ⟹ 第 2 层恰有 3 个结点。

@tpl T基数排序一趟 | LSD 基数排序问某一趟的结果：只看相关的桶，桶内保持原来顺序
1. 第 1 趟按个位、第 2 趟按十位……；不足位数的高位补 0（9 的十位是 0）。
2. 分配：按原序列从左到右把元素放进对应桶的队尾（稳定）；收集：0 号桶到 9 号桶依次首尾相接。
3. 问某元素的前后邻居：先找它的桶，看桶内左右；在桶头/桶尾就去看相邻的非空桶的尾/头。

@kp 基数排序 | 基数排序（LSD）
不比较关键字，按位「分配 ＋ 收集」：从最低位到最高位各做一趟，每趟必须稳定。
- $d$ 位、基数 $r$：时间 $O(d(n+r))$，空间 $O(r)$（队列），稳定。
- 例：{21,12,11}：个位趟得 21,11,12；十位趟得 11,12,21。

@tpl T建堆两法 | 题目说「依次插入」还是「建堆」：前者 n 次向上调整，后者从 ⌊n/2⌋ 倒着向下筛
1. 依次插入：新元素放在末尾，和父亲比，大（大根堆）就交换，一直上浮；草稿上每插一个画一次。
2. 整体建堆（筛选法）：序列先原样放成完全二叉树，$i=\lfloor n/2\rfloor,\dots,1$ 逐个向下筛。
3. 两种方法结果通常不同，而且都是合法的堆 ⟹ 不能用「是不是堆」排除，必须按题目指定的方法走一遍。
4. 删堆顶：末尾元素放到根，向下筛。

// ───── 本年新建：组成原理 ─────

@kp 量级前缀 | 数量级前缀与中文数词
速率、频率、FLOPS 用 10 的幂：K $10^3$、M $10^6$、G $10^9$、T $10^{12}$、P $10^{15}$、E $10^{18}$，每级 ×1000。
- 中文：万 $10^4$、亿 $10^8$、万亿 $10^{12}$、千万亿 $10^{15}$、亿亿 $10^{16}$。
- 存储容量用 2 的幂：K $2^{10}$、M $2^{20}$、G $2^{30}$。
- 例：$93\ \mathrm{PFLOPS}=9.3\times10^{16}$ 次/秒 ＝ 9.3 亿亿次/秒。

@tpl T精确表示 | 十进制小数能否用二进制（IEEE 754）精确表示：化成最简分数，看分母是不是 2 的幂
1. 能写成 $k/2^n$ ⟺ 有限位二进制小数 ⟺（位数够时）能精确表示。
2. 小数部分出现 .1 .2 .3 .4 .6 .7 .8 .9 这类（分母含 5）一律不能；.5 .25 .75 .125 … 能。
3. 反过来，有限位二进制小数转十进制永远精确。

@tpl T芯片数 | 存储器扩展要几片芯片：总位数 ÷ 单片位数，先看清编址单位
1. 地址个数＝末地址 − 首地址 ＋ 1（十六进制直接算）。
2. 总位数＝地址个数 × 每个地址的位数（按字节编址乘 8，按字编址乘字长）。
3. 片数＝总位数 ÷（芯片字数 × 芯片位宽）；位扩展片数＝所需位宽 ÷ 芯片位宽，字扩展片数＝所需字数 ÷ 芯片字数。

@tpl T程序员可见 | 某寄存器对（汇编）程序员可见吗：汇编指令里能不能写出它、能不能用它
1. 可见：通用寄存器、PC、PSW/标志寄存器、基址/变址寄存器、栈指针 SP。
2. 不可见（透明）：IR、MAR、MDR、暂存寄存器、微程序控制器里的 μPC、μIR、CMAR、CMDR。
3. 「数据会经过它」≠「程序员能用它」。

@kp 数据通路 | 数据通路
指令执行过程中数据所经过的路径及路径上的部件：ALU、通用寄存器、状态寄存器、Cache、MMU、浮点运算逻辑、异常和中断处理逻辑等。
- 它由控制部件发出的控制信号控制；CPU＝数据通路 ＋ 控制器。
- 判据：数据（或地址、断点）是否从它身上流过。控制器输出的是控制信号，不是数据通路本身。

@kp 异步总线 | 同步总线与异步总线
- 同步：双方用同一时钟定时；一次总线事务可以占多个时钟周期（时钟频率 ≠ 工作频率）。
- 异步：用握手信号（请求 / 回答）定时，不需要统一时钟；一次握手完成一次数据交换，传的是一个总线宽度的数据。
- 突发传送：发一次地址后连续传多个数据。

@kp I/O接口 | I/O 接口（I/O 控制器）
主机和外设之间的部件：接收主机的 I/O 控制信号，完成数据缓冲、格式转换、状态登记、中断请求等。
- 名称里带「适配器、控制器、接口」的多半是它；可编程中断控制器、DMA 控制器、网卡控制逻辑都算。
- 磁盘驱动器、打印机本体是外设，不是接口。

@kp 中断响应条件 | CPU 响应中断的条件
① 有中断请求；② 该请求没被屏蔽（屏蔽位取反后与请求相「与」，被屏蔽的进不了判优电路）；③ CPU 处于开中断状态；④ 一条指令执行完毕（且没有更紧急的事）。
- 「CPU 检测到中断请求」本身就意味着请求未被屏蔽。
- 中断服务程序在内核态执行；多重中断就是在内核态里再响应新中断。

// ───── 本年新建：操作系统 ─────

@tpl T特权指令 | 判断哪条指令「只能在内核态执行」：它会不会影响别的进程或整个系统
1. 特权指令：I/O 指令、开/关中断、改 PSW、置时钟、改页表基址/存储保护寄存器、停机、切换执行状态。
2. 非特权：数据传送、算术逻辑、Trap（访管）指令、设置断点（int3）——它们在用户态执行，只是可能引发进入内核态。
3. 分界线：「会导致进内核」≠「只能在内核里执行」。

@kp 进程创建 | 进程创建原语
① 分配 PID、申请空白 PCB；② 分配除 CPU 以外的资源；③ 初始化 PCB（标识、CPU 状态、优先级等）；④ 插入就绪队列。
- 新进程是就绪态，「运行」要等调度程序。
- 引起创建的事件：用户登录、作业调度、系统提供服务、应用请求（fork）。

@kp 时钟中断 | 时钟中断与时间片轮转
定时器按固定频率发中断。时钟中断处理程序更新系统时间、扣减当前进程的剩余时间片；时间片用完 ⟹ 当前进程（改 PCB 状态）挂到就绪队列尾，调度程序取就绪队列队首。
- 没有时钟中断，OS 就无法从不肯让出 CPU 的进程手里夺回 CPU。
- 阻塞队列里的进程不参加调度。

@tpl T磁盘调度 | 磁盘调度算总移动距离：一步一行写「当前位置 → 选谁 → 走多远」
1. FCFS 按请求顺序；SSTF 每次选离当前磁头最近的（含与当前位置相同的请求，距离 0）；SCAN/LOOK 按方向走到头（或最远请求）再折返；C-SCAN/C-LOOK 单向，返程是否计入看题。
2. 单向到底再折返的轨迹可用「两段距离」快算；SSTF 来回跳时只能逐步算。
3. 距离很接近的两个候选（差 1）要多核一遍。

@kp SSTF | 最短寻找时间优先（SSTF）
每次选与当前磁头位置距离最近的请求。
- 平均寻道短，但可能饥饿（远处请求一直被插队）。
- 与 SCAN 的区别：SSTF 只看距离不看方向，轨迹会来回跳。
- 例：磁头 50，请求 45、60、40 ⟹ 45(5)→40(5)→60(20)，共 30。

@tpl T调度时机 | 「能否 / 可能 / 必然引起调度」：先钉死题干的口径
1. 必然引起：当前进程终止、阻塞、时间片用完、主动让出 ⟹ CPU 空出来了。
2. 可能引起：中断处理结束、系统调用返回用户态前（有更高优先级的就绪了才抢占）、新进程就绪（抢占式）。
3. 不能调度：处理中断的过程中、进程在操作系统内核临界区中、原子操作中。

@tpl T改进CLOCK | 改进型 CLOCK 选淘汰页：按 (访问位 A, 修改位 M) 找 (0,0) → (0,1)（清 A）→ 重来
1. 第 1 轮：从指针处扫一圈找 (0,0)，不改任何位。
2. 第 2 轮：找 (0,1)，经过的页把 A 清 0。
3. 还没找到：此时所有 A 都是 0，回到第 1 轮再找 (0,0)（原来的 (1,0)），再不行第 2 轮找 (0,1)（原来的 (1,1)）。
4. 结果上等价于优先级 (0,0) ＞ (0,1) ＞ (1,0) ＞ (1,1)，同级看指针位置。
5. 存在位为 0 的页表项，页框号字段无效，不能拿来拼地址。

@kp 改进型CLOCK | 改进型 CLOCK 置换算法
每页两位：访问位 A（最近用过）、修改位 M（被写过，换出要写回磁盘）。
- 优先淘汰「最近没用、也没改过」的页 (0,0)，其次 (0,1)，因为换出脏页要多一次写磁盘。
- 简单 CLOCK 只看 A：A＝1 清 0 跳过，遇到 A＝0 就淘汰。

@kp 页表基址寄存器 | 页表基址寄存器（PTBR）
存当前进程**顶级（一级）页表**的起始**物理**地址。
- 物理：查页表本身不能再经过地址变换，否则无限递归。
- 一级：二级页表有很多张，位置要从一级页表项里查出来；一级页表每进程只有一张。
- 进程不运行时，这个值保存在 PCB 里，切换时装入。

@kp 软链接 | 软链接（符号链接、快捷方式）与硬链接
- 硬链接：多个目录项指向同一个 inode，inode 里有链接计数；删除时计数减 1，减到 0 才回收 inode 和磁盘块。
- 软链接：一个独立的文件，内容是目标的路径名；目标被删后它变成悬空链接，内核不会去找它、也找不到它。
- 删除文件的标准动作：删目录项、（计数为 0 时）回收 FCB/inode、回收磁盘块。

@tpl T死锁资源数 | 「不会死锁至少要几个资源 / 最多几个进程」：每人先给 k−1 个，再多 1 个
1. $n$ 个进程各最多要 $k$ 个：最坏情况每人拿 $k-1$ 个都卡住，再多 1 个就有人能完成。
2. 不死锁 ⟺ $m\ge n(k-1)+1$，即 $m>n(k-1)$。
3. 需求不等时：$m\ge\sum(k_i-1)+1$。反问「最多几个进程」：解 $n(k-1)<m$。

@kp 系统调用 | 系统调用
用户进程主动请求操作系统内核提供服务的接口（如 fork、open、read、write）：执行陷入指令进入内核态，服务完返回用户态。
- 页置换、进程调度是 OS 自己发起的管理动作，不是系统调用。
- 纯计算的库函数（sin、random）在用户态完成，不进内核；库函数也可能内部调用系统调用（printf → write）。

// ───── 本年新建：计算机网络 ─────

@kp TCP/IP四层 | TCP/IP 体系结构
应用层 → 传输层（TCP、UDP，端到端）→ 网际层（IP 及 ARP、ICMP、IGMP，路由选择与转发，无连接尽力而为）→ 网络接口层。
- 会话管理并进应用层；网际层不做流量控制、不保证有序。
- 对比 OSI：OSI 网络层可面向连接、可有流量控制。

@tpl T读编码波形 | 读编码波形：先按虚线把每个码元切开，确认每格中间都跳，再按规则逐位读
1. 曼彻斯特：只看每个码元**中间**跳变的方向（常用约定：高→低为 1 或题目给出），一位一读、互不相关。
2. 差分曼彻斯特：中间必跳（只管同步）；看码元**起始处**相对前一位末尾有没有跳变：有 ⟹ 0，无 ⟹ 1。
3. 第一位与波形开头的电平比；读完把串和选项对，四个选项常是「读反、错一位」。

@kp 曼彻斯特 | 曼彻斯特编码与差分曼彻斯特编码
- 曼彻斯特：每位中间都跳变，跳变方向表示 0/1；自带时钟，但带宽是原来的 2 倍。以太网用它。
- 差分曼彻斯特：每位中间也都跳变；位开始处有跳变表示 0、无跳变表示 1。抗干扰更好。

@tpl T子网二叉树 | 子网划分能否互不重叠又不遗漏：把网络前缀画成二叉树，看叶子能否恰好铺满
1. 只看网络号里比公共前缀多出的那几位，例如 /24 里的 .128/26 写成「10」。
2. 互不重叠 ⟺ 任何一个的位串都不是另一个的前缀。
3. 不遗漏 ⟺ 各块大小之和等于父块（/25 占 1/2，/26 占 1/4，/27 占 1/8）。
4. 再看块数：凑满父块需要的最少块数要等于题目给的个数。

@tpl TIP分片 | IP 分片三步：每片最大数据要 8 的倍数，再列分片表
1. 每片最大数据＝$\lfloor(\text{MTU}-\text{首部})/8\rfloor\times8$。
2. 数据总量＝总长度 − 首部；片数＝$\lceil$数据总量 ÷ 每片最大数据$\rceil$。
3. 逐片写：数据长度、总长度（＋首部）、片偏移（已发数据 ÷ 8）、MF（最后一片为 0，其余为 1）、DF＝0。

@kp IP分片 | IP 分片
数据报大于下一跳 MTU 时，在路由器上分片，到目的主机再重组。
- 片偏移以 8 字节为单位 ⟹ 除最后一片外，每片的数据长度必须是 8 的倍数。
- 总长度字段是本片的首部 ＋ 数据；MF＝1 表示后面还有分片；DF＝1 不允许分片（超长就丢弃并发 ICMP）。

@tpl T距离向量 | 距离向量更新：对每个目的网络，算「到邻居的代价 ＋ 邻居报的距离」取最小
1. 把每个邻居的链路代价写在它那一列的表头上。
2. 一行一个目的网络，横着算每列的和，取最小值并记下下一跳。
3. 只能经过邻居 ⟹ 不能把链路代价本身当成到目的网络的距离。

@kp 距离向量 | 距离向量算法（RIP）
每个路由器周期性地把自己的距离向量发给邻居；收到后对每个目的 $N$：$d_E(N)=\min_v\{c(E,v)+d_v(N)\}$。
- RIP 用跳数，16 表示不可达；坏消息传得慢（计数到无穷）。
- 例：到邻居 A 代价 2，A 报到 N 距离 3 ⟹ 经 A 到 N 为 5。

@kp TCP四次挥手 | TCP 连接释放的状态
主动关闭方：ESTABLISHED → 发 FIN → FIN_WAIT_1 → 收到 ACK → FIN_WAIT_2 → 收到对方 FIN、回 ACK → TIME_WAIT → 等 2MSL → CLOSED。
被动关闭方：收到 FIN、回 ACK → CLOSE_WAIT → 发 FIN → LAST_ACK → 收到 ACK → CLOSED。
- TIME_WAIT 等 2MSL：保证最后的 ACK 能到达（丢了还能重发），让旧报文段在网络中消失。

@tpl T发送窗口 | TCP 还能发哪些序号：窗口从 ack 起算，长度 min(rwnd, cwnd)，再扣掉已发未确认
1. 可发区间上界＝ack ＋ 窗口 − 1（窗口＝min(rwnd, cwnd)，只给 rwnd 就用 rwnd）。
2. 已发出但没被确认的序号仍占着窗口 ⟹ 可继续发的从「已发到的下一个」开始。
3. 对方报文里的 seq 是对方方向的序号，和本方能发什么无关。

// ───── 本年新建：综合题套路 ─────

@tpl T矩阵数度 | 邻接矩阵上求度：第 i 行（无向）非零元素个数；有向图出度看行、入度看列
1. 0/1 矩阵直接把一行加起来；带权矩阵要数「非 0 且非 ∞」的元素。
2. 两重循环扫整张矩阵 ⟹ 时间 $O(n^2)$，只用计数器 ⟹ 空间 $O(1)$。
3. 2021（奇度顶点数）、2023（出度＞入度的 K 顶点）、2024（拓扑序唯一）都是这个模子。

@tpl T稳定性判断 | 读代码判稳定性：只看「两个相等元素」走哪条分支，谁被放到后面
1. 构造一个最小例子：两个相等的元素 $a_i=a_j$（$i$ 在前），手跑一遍看最后谁在前。
2. 比较语句里有没有等号是关键：相等时让靠后的那个「往后挪」就稳定，让靠前的往后挪就不稳定。
3. 修改时只改那一个比较符号，并把改后的那一行写出来。

@kp 符号扩展 | 符号扩展与零扩展
把短的数扩成长的数：
- 符号扩展：高位全部补符号位，补码真值不变。用于有符号数（访存偏移量、条件转移的相对位移）。
- 零扩展：高位全部补 0，无符号真值不变。用于无符号数、逻辑运算的立即数。
- 例：6 位 111110（−2）符号扩展成 16 位：FFFEH；零扩展：003EH（62）。

@tpl TTLB当Cache | TLB 组相联的标记、组号、替换：把虚页号当成 Cache 的「主存块号」
1. 虚页号＝虚拟地址 − 页内地址位数；组号位数＝$\log_2$ 组数，取虚页号的低位；其余高位是标记。
2. 组号＝虚页号 mod 组数，先把整串访问的组号算出来，只模拟「访问的不同页数 ＞ 路数」的那几组。
3. LRU：命中也要把它移到「最近」；FIFO 命中不变。
4. 地址变宽时只有标记变宽（页框号取决于物理地址，组号取决于组数）。

@tpl T引导顺序 | 开机引导与磁盘初始化的先后：先有物理结构，才有逻辑结构；先跑固定的，再跑可变的
1. 引导：ROM 中的引导程序（自举）→ 磁盘引导程序（MBR，选分区）→ 分区引导程序 → 操作系统初始化程序。
2. 制盘：物理（低级）格式化（划扇区）→ 分区（写分区表）→ 逻辑（高级）格式化（建文件系统、根目录）→ 安装 OS。
3. 每一步都写一句「为什么必须在它前面」，那是理由分。

@kp 磁盘格式化 | 物理格式化、分区与逻辑格式化
- 物理（低级）格式化：把磁道划分成扇区（头、数据区、尾部校验码），标坏扇区，通常出厂已完成。
- 分区：把磁盘分成若干相互独立的逻辑盘，分区表放在第 0 号扇区的主引导记录（MBR）里。
- 逻辑（高级）格式化：在分区上建立文件系统——分区引导块、空闲空间管理结构（位示图/FAT）、根目录等。

@tpl T关中断互斥 | 用开/关中断实现互斥：关中断期间不会切换进程，所以「关着中断忙等」必死循环
1. 单处理机上关中断 ⟹ 时钟中断进不来 ⟹ 不会发生进程切换 ⟹ 关中断到开中断之间的代码对其他进程是原子的。
2. 关着中断等一个只有别的进程才能改变的条件 ⟹ 永远等不到。等待循环里必须「开中断—关中断」放一次风。
3. 开/关中断是特权指令：只能给内核用（实现 wait、signal 这类原语），用户程序不能用；多处理机上关中断只关本 CPU，不够用。

@tpl T全栈帧序列 | 「访问网页时网络上出现了哪些帧」：按时间把要发的报文排成一列，每个报文前先问「下一跳的 MAC 知道吗」
1. 用域名访问 ⟹ 先 DNS（DNS → UDP → IP → 以太网帧）。
2. 每发一个 IP 分组：目的在本网段 ⟹ 下一跳是目的主机本身；不在 ⟹ 下一跳是默认网关。下一跳 MAC 不在 ARP 表里 ⟹ 先发 ARP 请求（广播）、等 ARP 响应（单播）。
3. 交换机：收到帧先记「源 MAC → 进入端口」，再查目的 MAC：查到就单播转发，查不到或广播就从其余端口泛洪。
4. 某主机收到哪些帧：广播帧和交换机还没学到目的地址时的泛洪帧。

@kp 交换机自学习 | 以太网交换机的自学习与转发
- 学习：每收到一帧，把（源 MAC，进入端口）记入交换表。没发过帧的主机不会被记住。
- 转发：目的 MAC 在表中 ⟹ 只从对应端口转出（同端口则丢弃）；不在表中或是广播地址 FF-FF-FF-FF-FF-FF ⟹ 从除进入端口外的所有端口转出。

@kp ARP | 地址解析协议 ARP
已知下一跳的 IP 地址，求它的 MAC 地址。
- ARP 请求：广播（目的 MAC 全 F），问「谁是这个 IP」；ARP 响应：单播回给请求方。
- 目的主机在本网段 ⟹ 问目的主机；在别的网段 ⟹ 问默认网关（路由器接口）的 MAC。
- 结果缓存在 ARP 表里，有就不再问。

// ── 由 2022 年精解提上来 ──

@tpl T循环求和 | 内层循环次数依赖外层变量：先列表求和，不许直接相乘
1. 写出外层变量依次取哪些值（1,2,4,… 还是 1,2,3,…）。
2. 对每个值写出内层执行几次，列成一张两列小表。
3. 把内层次数加起来：等比 ⟹ 被最后一项主导（约等于末项的 2 倍）；等差 ⟹ 平方级。
4. 只有内层次数与外层变量无关时，才能「外层次数 × 内层次数」。

@tpl T反例排除 | 选项里有「一定 / 不可能 / 都」：先造最小反例
1. 「一定 X」：造一个满足条件但不 X 的小例子就能排除。
2. 「不可能 X」：能画出一个 X 的例子就排除；画不出的再说出它为什么不可能（往往是结构上被某个东西隔开）。
3. 反例越小越好：2～4 个结点的树、3～5 个点的图、3～4 个字符的编码。

@tpl T满树定高 | 给结点数问 m 叉树最少几层：写满树的累计结点数
1. 第 h 层最多 $m^{h-1}$ 个结点，前 h 层最多 $\frac{m^h-1}{m-1}$ 个。
2. 把累计数列写出来（三叉：1, 4, 13, 40, 121, 364），看 n 落在哪一段。
3. 题干说「叶结点高度为 1」或「根高度为 1」是层数口径；边数口径要再减 1。

@tpl TAOE余量 | AOE 网求活动余量：正推 ve 取 max，逆推 vl 取 min
1. 按拓扑序正推事件最早时间：$ve(j)=\max\{ve(i)+w\}$。
2. 汇点 vl＝ve，逆推事件最迟时间：$vl(i)=\min\{vl(j)-w\}$；逆推到源点必须得 0，可自查。
3. 活动 $i\to j$ 的余量 $d=vl(j)-ve(i)-w$；余量 0 的是关键活动。
4. 草图上把 ve/vl 写在每个结点旁边，候选活动直接读。

@tpl TB树删除 | m 阶 B 树删除：非终端先换成前驱/后继，亏空先借后并
1. 被删关键字不在终端结点 ⟹ 用前驱（左子树最右下）或后继（右子树最左下）顶替，转成删终端结点。
2. 删后关键字数 ≥ $\lceil m/2\rceil-1$ ⟹ 结束。
3. 不够：兄弟有多余就借（兄弟的关键字上到父结点，父结点夹在中间的关键字下来）；左右兄弟都不够才合并（亏空结点＋兄弟＋父结点中间那个关键字并成一个，父结点少一个）。
4. 问「可能 / 不可能」⟹ 前驱、后继两条路都走，合并时左右兄弟都试，列出全部结局。
5. 秒判：候选根里相邻两个关键字之间的子树，必须装得下 ≥ $\lceil m/2\rceil-1$ 个关键字。

@kp 连通边数 | 无向图连通与边数的两条临界线
- 下界：n 个顶点连通至少 $n-1$ 条边（一棵树）。边数 $<n-1$ ⟹ 一定不连通。
- 上界：边数 $\ge C_{n-1}^{2}+1$ ⟹ 一定连通（前 $n-1$ 个点连成完全图也只有 $C_{n-1}^2$ 条，再多一条必然连到最后那个点）。
- 介于两者之间：可能连通也可能不连通。例：5 个点 6 条边，可以是 $K_4$ 加一个孤立点。

@kp 装填因子 | 装填因子 α 与散列查找效率
$\alpha=\frac{\text{表中记录数 } n}{\text{散列表长度 } m}$。散列表的平均查找长度取决于三件事：散列函数、处理冲突的方法、装填因子；不直接取决于 n 或 m 本身。
例：线性探测成功 $ASL\approx\frac12\left(1+\frac{1}{1-\alpha}\right)$，α＝0.5 时 1.5，α＝0.9 时 5.5。

@tpl T主频周期 | CPU 时间题：先把主频换成周期，再乘「条数 × CPI」
1. 平均 CPI＝各类指令 CPI 按比例加权；结果必在最小与最大 CPI 之间，可用来自查。
2. 主频 ⇄ 周期：1GHz ↔ 1ns，2GHz ↔ 0.5ns，500MHz ↔ 2ns，1MHz ↔ 1μs。
3. CPU 时间＝指令条数 × CPI × 时钟周期；在纳秒下算完再换 μs、ms。

@tpl T转IEEE754 | 十进制数写成 IEEE 754 单精度：规格化 → 填三段 → 四位一组
1. 小数部分化成分母是 2 的幂的分数（或乘 2 取整），写成二进制。
2. 规格化成 $\pm1.f\times2^e$：符号 1 位，阶码 $e+127$ 写 8 位，尾数只写 f 补足 23 位。
3. 32 位四位一组读十六进制；选项往往只差在阶码上，先核对前 3 个十六进制位。

@tpl T页式地址转换 | 页式虚实转换：切地址 → 统一进制查表 → 看存在位 → 拼接
1. 页内偏移位数＝$\log_2$ 页大小；页大小是 4KB 时偏移就是十六进制末 3 位。
2. 查表前统一进制：页表里的页号带不带 H 要看清。
3. 存在位 0 ⟹ 缺页异常；1 ⟹ 页框号与偏移拼接（不是相加）。

@tpl T扩展操作码 | 扩展操作码数条数：每级「共有 → 用掉 → 剩下当前缀」
1. 地址最多的一级：操作码位数＝字长 − 地址个数 × 地址码位数。
2. 下一级共有＝上一级剩余编码数 × $2^{\text{本级多出的操作码位数}}$。
3. 「最多」⟹ 前面各级只用题给条数；也可按最低级的编码空间整体相减验算。

@kp 扩展操作码 | 扩展操作码
定长指令字里，地址码少的指令把省下的地址位挪给操作码。规则：短操作码不能是长操作码的前缀——长操作码只能以短操作码里没用掉的编码开头。
例：16 位指令、地址码 4 位，三地址用 15 条（剩 1 个前缀 1111），二地址可有 $1\times2^4=16$ 种编码。

@kp DRAM复用 | DRAM 的地址复用与行缓冲
DRAM 存储阵列按行、列组织，行地址和列地址分两次经同一组引脚送入（先 RAS 后 CAS）⟹ 地址引脚数是地址位数的一半。
- 读出时一整行进入行缓冲；刷新也按行进行。
- SRAM 不复用，引脚数＝地址位数。
例：$2^{26}$ 个单元、行列各 $2^{13}$ ⟹ 13 根地址引脚。

@kp ISA | 指令集体系结构（ISA）
软件和硬件之间的界面，规定机器语言程序员看得见的一切：指令格式与类型、操作数类型、寻址方式、寄存器个数和位数、存储空间与编址方式、I/O 方式。
时钟频率、加法器结构、流水线、Cache 等属于实现（微架构），同一 ISA 可以有多种实现。

@kp 中断IO | 程序中断 I/O 方式
外设准备好数据后向 CPU 发中断请求，CPU 暂停当前程序，执行中断服务程序完成一次数据传送。
- 适合慢速字符设备；外设准备期间 CPU 可运行别的进程。
- 要求外设准备一个数据的时间大于中断处理时间，否则数据丢失。
- CPU 占用率＝每次中断处理时间 ÷ 两次中断间隔。

@kp Flynn | Flynn 分类与并行结构
按指令流、数据流的个数分四类：SISD（传统单核）、SIMD（向量处理器、GPU）、MISD（几乎没有实例）、MIMD（多核、多处理器、多计算机）。
- SMP：共享单一物理地址空间的多处理器；多计算机：各有地址空间、靠消息通信。
- 硬件多线程：一个核里保存多套线程上下文，硬件切换，单核即可使用。

@tpl T调度次数 | 数调度次数 / 求周转时间：画甘特图，每次「换人」画一条竖线
1. 先按优先权（或到达、剩余时间）把进程排好序，写在甘特图旁边。
2. 在每个「到达时刻」和「结束时刻」检查：抢占式下新到的更优才换人；有进程结束一定换人。
3. 0 时刻第一次把进程放上 CPU 也算一次调度；新到的进程不比当前优，不算。
4. 周转＝完成 − 到达，等待＝周转 − 运行时间，直接从甘特图读。

@kp 三态转换 | 进程的三种基本状态及转换
- 就绪 → 运行：被调度。运行 → 就绪：时间片用完或被抢占。
- 运行 → 阻塞：进程请求的东西暂时得不到（I/O、资源、信号量 wait），是进程自己主动的。
- 阻塞 → 就绪：等待的事件发生（I/O 完成、别人 signal），是被动的。
- 没有就绪 → 阻塞，也没有阻塞 → 运行。

@kp 缺页处理 | 缺页异常的处理过程
1. 找空闲页框；没有才用置换算法淘汰一页（被修改过的先写回外存）。
2. 把所缺的页从外存读入该页框（进程此时阻塞）。
3. 修改页表：填页框号、存在位置 1（有 TLB 的还要更新 TLB）。
4. 返回并重新执行引起缺页的指令。
「一定有」的是 2、3、4；「不一定」的是淘汰和写回。

@kp 工作集 | 工作集
进程在最近一段时间窗口 Δ 内访问过的页面集合。分配给进程的页框数小于工作集大小就会频繁缺页（抖动）。
影响缺页率的因素：分配的页框数（受进程数、工作集影响）、页面大小、置换算法、程序局部性；页缓冲只减少 I/O 开销，不改变缺页次数。

@tpl T奈氏香农 | 求信道最大速率：给状态数用奈氏，给信噪比用香农，都给取小
1. 无噪声、给了码元状态数 V ⟹ 奈氏：$2W\log_2V$。
2. 给了信噪比（dB 要先换成 $10^{dB/10}$）⟹ 香农：$W\log_2(1+S/N)$。
3. 两个都给 ⟹ 各算一个，取较小值。

@kp 奈氏香农 | 奈氏准则与香农定理
- 奈氏准则：理想低通无噪声信道，码元速率最高 $2W$ 波特；每码元 $\log_2V$ bit ⟹ 最大数据率 $2W\log_2V$。
- 香农定理：有噪声信道的极限数据率 $W\log_2(1+S/N)$，与编码方式无关；$S/N$ 由分贝换算：$10\lg(S/N)$ dB。
例：W＝3kHz、V＝4 ⟹ 12 kb/s；30dB ⟹ $3\text{k}\times\log_2 1001\approx30$ kb/s。

@tpl T网络地址 | 求网络地址 / 网关 / 同网段：只把「掩码不是 0 也不是 255」的那个字节写成二进制
1. 掩码为 255 的字节照抄，为 0 的字节变 0。
2. 中间那个字节：步长＝256 − 掩码值，网络号取不超过 IP 该字节的步长倍数。
3. 默认网关必须与主机同网段，掩码与网关接口一致；广播地址＝主机位全 1。

@kp SDN | 软件定义网络 SDN
把控制平面从交换设备中分离出来，集中到 SDN 控制器；数据平面的 SDN 交换机按流表（匹配＋动作）转发。

- 南向接口：控制器 ↔ SDN 交换机（向下，下发流表，如 OpenFlow）。
- 东西向接口：控制器之间。

@tpl T挥手计时 | TCP 释放连接的时间：画时序图，主动方多等 2MSL

@tpl T溢出判别 | 用符号位写溢出逻辑式：加法「同号相加变号」，减法「把 B 的符号取反再套」

@tpl T双链表插入 | 双链表插入 / 删除写指针：先画三个结点，每句话执行完就改图，后面的语句只认「改过的图」
1. 在 p 后插 s 要改 4 个指针：s→next、s→prev、原后继→prev、p→next；删除只改 2 个。
2. 关键约束：p→next 一旦被改成 s，原后继就只能经 s→next 找到——所以「p→next＝s」通常放最后，或改之前先把原后继存下来。
3. 选项题：把每个选项逐句在图上执行，最后检查 4 个指针是否全对。

@kp 双链表 | 双链表
每个结点有 prev、data、next 三个域，可以 O(1) 找到前驱和后继。
- 在 p 之后插入 s（原后继 r＝p→next）：`s->next=r; r->prev=s; s->prev=p; p->next=s;`，顺序可调，但用到 r 时 r 必须还能被找到。
- 删除 p 的后继 q：`p->next=q->next; q->next->prev=p;` 只改 2 个指针。

@kp 三元组 | 稀疏矩阵的三元组表
只存非零元，每个非零元记成（行号, 列号, 值）一条，按行优先排好。
- 光有三元组还原不出矩阵大小：最后几行几列全是 0 时，表里根本不出现 ⟹ 必须另存 **行数、列数**（通常也存非零元个数）。
- 例：3×3 与 100×100 的矩阵，若都只有 $a_{12}=5$，三元组表都是 (1,2,5)。
- 三元组表、十字链表都失去随机存取特性。

@tpl T树形填序列 | 给定树形（只有圈和边）＋ 一种遍历序列：先给空结点按该遍历编号，再按号填字母

2. 把序列的第 k 个字母填进 ⓚ 号圈。

@kp 后序遍历 | 后序遍历（左 → 右 → 根）
先后序遍历左子树、再后序遍历右子树、最后访问根。
- 序列最后一个一定是整棵树的根；任一子树的结点在序列里连成一段，段尾是该子树的根。
- 先序（根左右）第一个是根；中序（左根右）根把序列切成左右两段。

@kp BFS最短路 | BFS 求单源最短路径
广度优先搜索一层层往外扩：第 k 层恰好是「离源点 k 条边」的顶点，BFS 生成树上的路径就是边数最少的路径。
- 只适用于**无权图或各边权相等**的图；权值不等时要用 Dijkstra。
- 例：边权全为 1 的三角形 a–b–c，从 a 出发第 1 层就是 {b, c}，到 c 的最短距离 1。
- 对比：MST 只保证总权最小，树上两点间的路径不一定最短。

@kp 折半判定树 | 折半查找的判定树与比较次数
把折半查找每次比较的 mid 画成二叉树：根是第一次比较的元素，左右子树是左右半区。$n$ 个元素的判定树高 $h=\lceil\log_2(n+1)\rceil$（与 $n$ 个结点的完全二叉树同高）。
- 查找成功最多比较 $h$ 次；查找失败也最多 $h$ 次（最少 $h-1$ 次）。
- 心算：找「刚好装得下 $n+1$ 的 2 的幂」，$2^9=512\lt601\le1024=2^{10}$ ⟹ $h=10$。

@tpl T散列ASL | 散列表求 ASL：先把表填出来，再逐个地址（失败）或逐个关键字（成功）数比较次数
1. 按散列函数和冲突处理把每个关键字放进表里，草稿上画一排格子。
2. 成功 ASL：每个关键字的比较次数（第几次探测找到它）相加 ÷ 关键字个数。
3. 失败 ASL：对散列函数的每个可能值（$H(k)$ 的值域，**不是表长**）从那里开始探，一直探到空位，空位也算一次比较；相加 ÷ 值域个数。
4. 有删除标记的位置：查找时当作「有东西」继续往后探，不能停。

@kp 开放定址删除 | 开放定址法的删除：只能做删除标记（逻辑删除）
线性探测等开放定址法中，一个关键字可能是别人探测路径上的「中转站」。若把它物理清空，后面经过它才放进去的关键字就再也找不到了。
- 所以删除时只打标记：**查找**遇到标记要继续往后探；**插入**遇到标记可以直接占用。
- 例：表长 5，2022、12 都散列到 1，12 放在 2；若清空地址 1，再查 12 会在 1 处撞空而失败。
- 链地址法可以直接把结点从链表里摘掉（物理删除）。

@tpl T稳定性口诀 | 问哪些排序稳定 / 不稳定：先在草稿上写「稳 / 不稳」两栏，再回头看题干问哪栏
1. 不稳定：快（快速）、些（希尔）、选（简单选择）、堆（堆排序）——「快些选堆」。

@kp 排序稳定性 | 排序算法的稳定性
关键字相等的两个元素，排序后相对次序保持不变，就叫稳定。
- 不稳定的根源是**跨越式交换**：一次把元素甩过中间一段，相等元素的先后就可能颠倒（希尔按增量跳、快排两头交换、堆把根换到末尾、选择把最小值换到前面）。
- 只做相邻移动或按序搬运的（插入、冒泡、归并、基数）稳定。
- 归并靠 Merge 里「相等时先取前一段」保住稳定；把 `<=` 改成 `<` 就不稳定了。

@tpl T反推枢轴 | 给快排某趟结果问枢轴 / 能否是某趟结果：与最终有序序列逐位对齐，再验「左小右大」
1. 写出排好序的序列，与给的序列逐位对齐，同位置的元素才可能是枢轴（必要条件）。
2. 对候选逐个验：左边全比它小、右边全比它大（充分条件）。
3. 问「第 k 趟后」：第 1 趟至少 1 个这样的元素；第 2 趟至少 2 个，或 1 个在端点（另一段为空）——只能用来否定。

@kp 快排划分 | 快速排序的一次划分
取枢轴（常取第一个元素），一趟交替从两头扫描，结束时枢轴落到最终位置：左边全 ≤ 它，右边全 ≥ 它。
- 一次划分后**恰好**保证一个元素归位；其他元素碰巧也满足「左小右大」的，同样在最终位置上。
- 例：对 46, 79, 56, 38, 40, 84 以 46 划分，得 40, 38, 46, 56, 79, 84。

@tpl T负数补码 | 求负数的 n 位补码：直接算 $2^n-|x|$，再写成十六进制；取反加 1 只用来验算
1. $n$ 位补码：负数 $x$ 的机器数（当无符号数读）＝$2^n+x=2^n-|x|$。
2. 十六进制心算：先把 $|x|$ 写成十六进制（如 8190＝2000H−2＝1FFEH），再用 10000H 减。
3. 自查：机器数（无符号）＋$|x|$ 必须正好等于 $2^n$；差 1 的是反码。
4. 选项里常把原码、反码、补码摆一桌：算完问自己「我算的是哪个码」。

@tpl T浮点先看阶码 | IEEE 754 读值：先看阶码是不是全 0 或全 1，再决定用哪套公式
1. 按 1 / 8 / 23（单精度）切开，十六进制先展成二进制。
2. 阶码 1～254：规格化，$(-1)^s\times1.f\times2^{e-127}$。
3. 阶码全 0：尾数 0 是 ±0；尾数非 0 是非规格化数 $(-1)^s\times0.f\times2^{-126}$（没有隐藏 1，指数固定 −126）。
4. 阶码全 1：尾数 0 是 ±∞；尾数非 0 是 NaN。

@kp 非规格化数 | IEEE 754 非规格化数
阶码全 0、尾数不全 0 的浮点数。单精度值 $=(-1)^s\times0.f\times2^{-126}$：**没有隐藏位 1，指数固定按 −126**（不是 0−127）。
- 作用：填补 0 与最小规格化数 $1.0\times2^{-126}$ 之间的空隙，让数轴「逐渐下溢」。
- 最小正非规格化数 $2^{-23}\times2^{-126}=2^{-149}$；最大的 $(1-2^{-23})\times2^{-126}$。
- 例：0020 0000H：$f=0.01_2$ ⟹ $0.01_2\times2^{-126}=2^{-128}$。

@tpl T地址区间 | 存储器地址空间按比例 / 按容量划分：先写总范围，再算每区大小，最后从指定端往回数
1. $n$ 根地址线 ⟹ 范围 $0\sim2^n-1$；十六进制每 4 根线 1 位（30 根线顶地址是 3FFF FFFFH，不是 FFFF FFFFH）。
2. 各区大小＝总空间 × 比例，写成十六进制（$2^{28}$＝1000 0000H）。
3. 区间：起址＝末址 − 大小 ＋ 1，末址＝起址 ＋ 大小 − 1；相邻两区「前一区末址＋1＝后一区起址」。

@tpl T标志位双线 | 加减法的 OF、CF：同一串位按两种眼镜各算一遍——OF 看有符号，CF 看无符号
1. OF：把两个操作数当补码（有符号）真值做运算，结果超出 $[-2^{n-1},2^{n-1}-1]$ ⟹ OF＝1。
2. CF：把同样的位当无符号数做运算；加法有进位、减法不够减（借位）⟹ CF＝1（x86 口径，减法 CF＝借位）。
3. 速判：无符号减法 $x-y$ 中 $x\lt y$ 就借位；有符号「正−负得负」或「负−正得正」才溢出。
4. 题干若先给一组「x、y → OF、CF」，那是在告诉你 CF 的口径，先用它验证自己的口径。

@kp 标志位 | 运算标志 OF、SF、ZF、CF
ALU 只按位做加法，同时产生四个标志，不管操作数是有符号还是无符号：
- OF（溢出）：作为有符号数是否溢出；加法 $OF=C_n\oplus C_{n-1}$（最高位进位与次高位进位异或）。
- CF（进位 / 借位）：作为无符号数是否越界；减法时 CF＝借位＝（最高位进位取反）。
- SF：结果最高位；ZF：结果全 0。
- 例：8 位 $50-(-80)$：有符号得 130 超 127，OF＝1；无符号 $50-176$ 不够减，CF＝1。

@kp 操作元件 | 组合逻辑元件（操作元件）与时序逻辑元件（状态元件）
- 操作元件：没有记忆，输出只由当前输入决定——加法器、ALU、译码器、多路选择器 MUX、三态门。
- 状态元件：能存信号、跨时钟周期保持——PC、通用寄存器组、IR、MAR/MDR、各种暂存寄存器、存储器。
- 判据：时钟停一拍，它的值还需要留着吗？要留 ⟹ 状态元件。PC 自增用的是旁边的加法器，PC 自己只负责存。

@tpl T流水线冒险 | 判流水线冒险 / 阻塞：先写每条指令「写谁、读谁」，再按相邻对逐对判三种冒险
1. 数据冒险（RAW）：后一条读前一条写的寄存器。有转发时：运算类结果 EX 末就有 ⟹ 不阻塞；**load 的结果 MEM 末才有，紧跟着用 ⟹ load-use，转发也要阻塞 1 拍**。
2. 控制冒险：分支 / 跳转后面的指令要等转移地址确定；「硬件阻塞」口径下后继指令要停到分支写 PC 之后才取指。
3. 结构冒险：同一部件同一拍被两条指令用（统一存储器的取指与访存）。
4. 题问「阻塞」不是问「有冒险」：有冒险但被转发解决的不算阻塞。画时空图核对。

@kp 数据冒险 | 数据冒险、转发与 load-use
后一条指令要读前一条还没写回的寄存器（写后读，RAW）。
- 转发（旁路）：把 EX/MEM、MEM/WB 流水段寄存器里的新值直接送到 ALU 输入端，运算类指令相邻相关可以不停。
- load-use：load 的数据在 MEM 段末才取到，下一条的 EX 段已经要用 ⟹ 转发也赶不上，必须阻塞 1 个周期（或编译器插一条无关指令）。
- 不转发时：要等前一条 WB 之后才能读，相邻相关通常停 2～3 拍。

@kp 控制冒险 | 控制冒险
转移指令（beq、jmp 等）在确定「下一条取哪里」之前，后继指令无法正确取指。
- 王道五段流水线中 beq 在 EX 段比较、在 MEM 段把转移目标写入 PC，硬件阻塞时后继指令要等它写完 PC 才能取指（典型损失 3 个周期）。
- 缓解办法：分支预测、延迟转移（延迟槽）、提前在 ID 段算转移地址。

@tpl T总线读块 | 总线读一个主存块的时间：先算「一次传送」的拍数，再乘传送次数；问的是不是突发决定乘在哪
1. 传送次数＝块大小 ÷ 总线宽度（字节）。
2. 不支持突发：每次都要「送地址 ＋ 主存准备 ＋ 传数据」⟹ 总时间＝次数 ×（地址＋准备＋数据）。
3. 支持突发：地址只送一次，之后每个数据「准备＋传送」（准备可重叠时还能更快）。
4. 问「带宽」就别数这些拍子：带宽＝宽度 × 工作频率（见 [[T带宽口径]]）。

@kp 突发传送 | 突发（猝发）传送方式
一次总线事务中只送一次首地址，随后连续传送多个地址连续的数据（主存块），地址由从设备自己递增。
- 不支持突发：每个数据都要单独发起一次「地址 → 准备 → 数据」的事务。
- 例：64 位总线读 32B 块、地址 1 拍、准备 6 拍、数据 1 拍：不突发 $4\times8=32$ 拍；突发且准备不重叠 $1+4\times(6+1)=29$ 拍。

@kp DMA三阶段 | DMA 方式的三个阶段
- 预处理：CPU 执行 I/O 指令，给 DMA 控制器设主存起始地址、传送字数、方向，启动设备。
- 数据传送：由 DMA 控制器（硬件）占用总线直接在设备与主存之间搬数据，**CPU 不执行任何传送程序**，可以继续干别的。
- 后处理：传完后 DMAC 发中断请求，CPU 执行中断服务程序做校验、善后。
- 对比：程序查询、程序中断方式的数据都是 CPU 执行程序搬的。

// ───── 本年新建：操作系统 ─────

@kp 微内核 | 微内核与宏内核
- 宏内核（单内核）：进程管理、内存管理、文件系统、设备驱动全部在内核态，模块之间直接函数调用 ⟹ 性能好，但一个模块崩溃可能拖垮整个系统。
- 微内核：内核态只留最基本的功能（中断与异常处理、进程/线程管理与调度、低级存储管理、进程通信），文件系统、驱动等作为服务进程放在用户态，通过消息传递协作。
- 微内核的优点：可靠性、安全性、可扩展性、可移植性都较高；缺点：频繁的用户态 ⇄ 内核态切换和消息传递 ⟹ **性能较差**。

@tpl T位图大小 | 位图管理空闲空间占多大：先数被管理的对象有几个，一个对象 1 位，最后 ÷ 8 换成字节
1. 对象个数＝总容量 ÷ 单位大小（页框、盘块、簇），全部写成 2 的幂。
2. 位图位数＝对象个数；字节数＝位数 ÷ 8（即再减 3 个幂次）。
3. 算完问一句「单位是位还是字节」：忘了 ÷ 8 的结果常被做成错误选项。
4. 位图大小只与对象总数有关，与当前空闲多少无关。

@kp 位图 | 位示图（位图）
用一串二进制位记录每个单位（页框 / 盘块）是否空闲：1 位对应 1 个单位，0 / 1 表示空闲或已分配。
- 大小＝单位总数 ÷ 8 字节；例：16 GB 内存、4 KB 页框 ⟹ $2^{22}$ 位 ＝ 512 KB。
- 已知字号 $i$、位号 $j$（字长 $n$，都从 0 起）⟹ 块号 $b=n\times i+j$。

@kp 虚拟地址空间 | 进程的虚拟地址空间
每个进程看到一个从 0 开始、连续的地址空间，大小由虚拟地址的位数决定（32 位 ⟹ 4 GB），与物理内存、磁盘容量无关。
- 每个进程有自己的页表，同一个虚拟地址在不同进程中可以映射到不同页框 ⟹ 进程隔离。
- 程序里看到的一切地址（含 malloc 返回值、指针值）都是虚拟地址。
- 内存 ＋ 外存的大小只限制「实际能用多少」（虚拟存储器的实际容量），不决定地址空间有多大。

@tpl T逻辑物理 | 共享 / 映射类判断题：问「物理的」就一定相同，问「逻辑的」就不一定
1. 共享＝物理上只有一份 ⟹ 页框号、物理地址、物理块号必然相同。
2. 逻辑编号（页号、段号、虚拟地址、文件描述符）是各进程自家的门牌号，可以相同也可以不同。
3. 选项是 2×2 的组合时，两个维度分开判。

@kp 页面共享 | 页面（段）共享
让多个进程页表中的表项指向同一个物理页框，这一页在内存里只有一份。
- 共享的页在各进程中的页号可以不同（各自的虚拟地址空间独立），页框号一定相同。
- 典型用途：共享代码（多个进程运行同一程序）、共享库、进程通信的共享内存、fork 后的写时复制。
- 分段系统共享更自然：共享段在各进程段表中各占一项，段号也可以不同。

@kp 设备分配 | 设备分配要考虑的因素
- 设备的固有属性（类型）：独占设备、共享设备、虚拟设备分配方式不同。
- 设备分配算法：先来先服务、优先级高者优先。
- 设备分配的安全性：会不会造成死锁（安全分配 / 不安全分配）。
- 此外还有访问权限、设备当前状态（DCT 中的忙 / 闲）、逻辑设备到物理设备的映射（LUT，实现设备独立性）。

// ───── 本年新建：计算机网络 ─────

@tpl T分组交换时延 | 分组交换「发完一个文件要多久」：最后一个分组什么时候出发，再走完全程
1. 先拆包装：给「时延带宽积」⟹ 传播时延＝时延带宽积 ÷ 带宽；给距离和速度 ⟹ 距离 ÷ 速度。
2. 每段发送时延 $r$＝分组长 ÷ 带宽；$m$ 个分组、$k$ 段链路（$k-1$ 个路由器）。
3. 总时间 $T=(m-1)r+k(r+p)$：前 $m-1$ 个分组占住源端 $(m-1)r$，最后一个分组再走完 $k$ 段的发送＋传播。
4. 报文交换（不分组）：每段都要发完整个报文，$T=k(L/C+p)$。

@kp 时延带宽积 | 时延带宽积
时延带宽积 ＝ 传播时延 × 带宽，表示链路上「正在路上」最多能容纳多少比特（以比特为单位的链路长度）。
- 反求传播时延：传播时延 ＝ 时延带宽积 ÷ 带宽。
- 例：时延带宽积 1000 b、带宽 100 Mb/s ⟹ 传播时延 $1000/10^8$ s ＝ 0.01 ms。

@tpl T窗口上限 | 滑动窗口协议的窗口上限：序号 k 位，停等 1、GBN $2^k-1$、SR $2^{k-1}$
1. 停等：发送窗口 ＝ 接收窗口 ＝ 1（序号 1 位就够）。
2. GBN：接收窗口 1，发送窗口最大 $2^k-1$（不能等于 $2^k$，否则全部确认丢失时分不清新旧帧）。
3. SR：$W_T+W_R\le2^k$；题说收发窗口相等 ⟹ 各 $2^{k-1}$。
4. 理想利用率与发送窗口成正比 ⟹ 停等 ≤ SR ≤ GBN（反直觉：SR 并不比 GBN 高）。

@kp 滑动窗口 | 停止-等待、GBN 与 SR
- 停止-等待：发一帧等一个确认，窗口 1。
- 后退 N 帧（GBN）：发送窗口 $W_T\le2^k-1$，接收窗口 1，累积确认；某帧出错，它及其后已发的帧全部重传。
- 选择重传（SR）：$W_R\gt1$，接收方缓存失序的正确帧、逐帧确认，只重传出错的帧；要求 $W_T+W_R\le2^k$，通常 $W_T=W_R=2^{k-1}$。
- 信道利用率 $U=\min(1,W_T\cdot T_D/T)$，$T$ 是一个发送周期。

@tpl T指数退避 | 二进制指数退避：第 n 次冲突后 $k=\min(n,10)$，从 $[0,2^k-1]$ 里取 r，等 r 个争用期
1. 最长等待 ＝ $(2^k-1)\times$ 争用期；最短 0。
2. $n\gt10$ 时 $k$ 封顶 10；冲突 16 次放弃发送、报告上层。
3. 选项常把 $r$ 取成 $2^k$（忘了减 1）、取成 $k$ 或 1。

@kp 指数退避 | 截断二进制指数退避（CSMA/CD）
发生冲突后不立即重发，而是推迟一段随机时间：基本退避时间取争用期 $2\tau$（10 Mb/s 以太网为 51.2 μs）；第 $n$ 次冲突后取 $k=\min(n,10)$，从 $\{0,1,\dots,2^k-1\}$ 中随机选 $r$，等待 $r\times2\tau$。
- 冲突越多，随机范围越大，再次冲突的概率越小。
- 重传 16 次仍不成功就丢弃该帧。

@tpl TCRC | CRC 校验：生成多项式写成位串（缺项补 0），r＝最高次幂；发送端补 r 个 0 做模 2 除，接收端整串除余数为 0 才对
1. $G(x)$ 从最高次往下逐项写系数：$x^4+x+1$ ⟹ 10011，$r=4$。
2. 发送：数据后补 $r$ 个 0，模 2 除（异或、不借位），余数（$r$ 位）就是 FCS。
3. 判断收到的串对不对：直接整串除以 $G$，余数全 0 ⟹ 未检出错误。
4. 选项只差最后几位时：先算正确的 FCS，与选项比；比整串验四次快。

@kp CRC | 循环冗余校验 CRC
发送端把 $k$ 位数据左移 $r$ 位（补 $r$ 个 0）后用生成多项式（$r+1$ 位）做模 2 除法，余数作为 $r$ 位冗余码（FCS）附在数据后面发送；接收端用同一个 $G$ 去除收到的整串，余数为 0 就认为无差错。
- 模 2 运算：加减都是异或，不进位不借位。
- 例：数据 10111、$G=10011$ ⟹ FCS ＝ 1100，发送 101111100。
- CRC 只能检错，不能纠错；数据链路层用它做无比特差错的帧接收。

@tpl T斜30对端 | 点对点链路 /30：写出 4 个地址，网络号、广播各占一个，剩下两个分给两端
1. /30 的块大小 4：最后一个字节取不超过它的 4 的倍数作网络地址。
2. 4 个地址：网络地址、可用 1、可用 2、广播地址。
3. 已知一端的接口地址 ⟹ 另一端就是剩下那个可用地址。
4. 配合 NAT：出站分组的源地址被换成 NAT 路由器**外侧**接口的地址。

@kp IPv6 | IPv6 的要点
- 地址 128 位，地址空间是 IPv4 的 $2^{128}/2^{32}=2^{96}$ 倍（不是 96 倍）。
- 基本首部固定 40 B，选项放进扩展首部；取消了首部校验和；分片只在源主机进行（路由器不分片）。
- 跳数限制（Hop Limit）对应 IPv4 的 TTL；流标签用于标识同一数据流。
- IPv4 → IPv6 过渡：双协议栈、隧道技术（把 IPv6 数据报封装在 IPv4 数据报里）。

// ───── 本年新建：综合题 ─────

@tpl T置换选择 | 置换-选择排序手推：三列表「输出 / 工作区 / 待输入」，时刻记住「上一个输出值」
1. 工作区装满 $m$ 个；每步从工作区里选「不小于上一个输出值」的最小者（MINIMAX）输出，再从输入补一个进来。
2. 补进来的若比刚输出的值小，就给它加括号（冻结），留给下一段。
3. 工作区全被冻结 ⟹ 本段封口，解冻、重新开始下一段；输入读空后只出不进。
4. 每写完一段数一下长度，全部段长相加必须等于记录总数。

@kp 置换选择 | 置换-选择排序（生成初始归并段）
外部排序的第一步，用大小为 $m$ 的工作区 WA 从输入文件 FI 逐个读记录，生成比 $m$ 更长的有序初始归并段。
- 每次输出工作区里「≥ 当前段最后输出值」的最小记录（MINIMAX），再读入一个记录补位；新读入的若小于 MINIMAX 就只能留给下一段。
- 段长：输入有序时一段吃完全部 $n$ 个；最坏（初始 $m$ 个都大于后面所有记录）第一段只有 $m$ 个；随机输入平均约 $2m$。
- 段数少了，后面多路归并的趟数和 I/O 次数就少。各段长度不等时用最佳归并树（哈夫曼思想）安排归并顺序。

@kp 局部性 | 时间局部性与空间局部性
- 时间局部性：刚访问过的单元不久会再被访问（循环变量、循环体指令、反复使用的数组元素）。
- 空间局部性：刚访问过的单元附近的单元不久会被访问（顺序执行的指令、按存放顺序遍历的数组）。
- 判断数据访问有没有时间局部性，问「同一个元素会不会被访问不止一次」；有没有空间局部性，问「访问顺序和存放顺序是否一致」。
- 例：`for(i)for(j) a[i][j]=10;` 每个元素只写一次 ⟹ 无时间局部性；按行顺序访问行优先数组 ⟹ 有空间局部性。

@tpl T机器码地址 | 读机器级代码：下一条地址＝本条地址＋本条字节数；相对寻址目标＝下一条地址＋偏移；多字节常数按小端倒读
1. 数机器码字节数（两个十六进制数字一个字节），本条地址 ＋ 字节数 ＝ 下一条地址。
2. 转移指令判寻址方式：用「目标 − 下一条地址」算偏移，若正好等于机器码里的那个字段 ⟹ 相对寻址；偏移是补码，可负。
3. 机器码里出现的地址 / 立即数，若是低字节在前（如 00 20 42 00 表示 0042 2000H）⟹ 小端。
4. 比例变址寻址 `[base+index*scale+disp]`：scale 只能是 1、2、4、8，更大的行宽要由软件先乘好放进寄存器。
5. 判取指缺页：看指令所在页号（高 20 位）和此前执行过的指令是否同页。

@kp 比例变址 | 基址＋比例变址寻址（x86）
有效地址 EA ＝ 基址寄存器 ＋ 变址寄存器 × 比例因子 ＋ 位移量，比例因子只能取 1、2、4、8（对应 char、short、int、double 的元素大小）。
- 访问 `int a[24][64]` 的 `a[i][j]`：EA＝首址 ＋ $i\times256$ ＋ $j\times4$。行宽 256 超出比例因子范围，编译器先把 $i\times256$ 算到一个寄存器里，再用 `[ecx+edx*4+首址]`，其中 edx＝j。
- 适合按下标访问数组元素，下标变量放变址寄存器，循环时只改它。

@tpl T硬件互斥改错 | 硬件指令（TSL / Swap）实现互斥的改错题：先默写标准写法，再逐行比对
1. 标准 Swap：`key=TRUE; while(key==TRUE) Swap(&lock,&key); 临界区; lock=FALSE;`
2. 标准 TSL：`while(TestAndSet(&lock)); 临界区; lock=FALSE;`
3. 常见错法：进入区用 if（只试一次）、退出区不开锁或把锁置反、锁的初值写反。
4. 「能否用函数代替硬件指令」：不能——函数由几条普通语句组成，中间可被切换，读 lock 与写 lock 之间被插入另一线程 ⟹ 举出具体交错序列说明两个线程同时进入。
5. 这类方法满足空闲让进、忙则等待，不满足让权等待（忙等），可能不满足有限等待。

@kp Swap指令 | Swap（Exchange）指令实现互斥
硬件提供的原子指令：一条指令内完成两个变量的交换，执行期间不会被中断。
- 用法：共享 `lock` 初值 FALSE；每个进程有局部变量 `key`。进入区 `key=TRUE; while(key==TRUE) Swap(&lock,&key);`——换回来的 key 是 lock 的旧值，旧值为 FALSE 说明原来没人，自己已把 lock 置成 TRUE，可以进入；退出区 `lock=FALSE;`。
- 原子性是正确的根源：若交换被拆成「读 lock、写 lock」两步，两个进程可能都读到 FALSE。
- 缺点：进不去时一直循环交换（忙等），不让权。

@tpl TIO全程时序 | 一次 I/O 的全过程排序：两条线并排写——进程这条线（运行 → 阻塞 → 就绪 → 运行），设备这条线（启动 → 工作 → 中断）
1. 进程发系统调用 → 设备独立性软件 → 驱动程序启动设备 → 进程阻塞，CPU 去跑别人。
2. 设备完成（用户敲键、磁盘读完）→ 发中断 → 中断处理程序 → 唤醒驱动 / 搬数据到系统缓冲区 → 唤醒进程（进就绪队列）。
3. 进程被调度上 CPU 后，才从系统调用返回（把数据从系统缓冲区复制到用户区）。
4. 「一定切换」在阻塞之后；「才能被选中」在进就绪队列之后；中断处理期间进程仍是阻塞态、CPU 在内核态。

@kp FTP | 文件传送协议 FTP
FTP 使用两条 TCP 连接：
- 控制连接（服务器端口 21）：整个会话期间一直保持（持久），传登录、命令、应答等控制信息。
- 数据连接（主动模式服务器端口 20）：每传一个文件临时建立一条，传完就关闭（非持久）。
- 控制信息「带外」传送：命令走控制连接，文件内容走数据连接。
- 登录（用户名、口令）在控制连接上完成；上传 / 下载文件时再建数据连接。

@tpl T循环次数 | 单层循环的时间复杂度：设执行 $k$ 次，写出第 $k$ 次后循环变量的值，代入「停下来」的条件解出 $k$
1. 先看循环变量怎么变：每次 $+1$（线性）、$\times2$（对数）、还是条件里藏着平方（开方）。
2. 设循环体执行了 $k$ 次，写出此时变量的值（$x=k$、$i=2^k$ …）。
3. 把它代入循环条件「刚好不成立」的那一刻，解出 $k$ 关于 $n$ 的式子，取最高阶。
4. 条件写成 $n\ge(x+1)^2$ 这种：先把平方挪到 $x$ 一侧，就是 $x\approx\sqrt n$。

@tpl T度数方程 | 给结点总数 / 叶子数 / 各度结点数，求另一个：列两条方程「结点数＝各度结点数之和」「结点数＝分支数＋1」
1. $n=n_0+n_1+\dots+n_k$（按度分类数结点）。
2. $n=0\cdot n_0+1\cdot n_1+\dots+k\cdot n_k+1$（每个结点除根外头上都有一条分支）。
3. 两式相减消掉 $n$：二叉树得 $n_0=n_2+1$；严格 $k$ 叉树（只有度 0 和度 $k$）得 $n_0=(k-1)n_k+1$。
4. 哈夫曼树、最佳归并树、满二叉树都只有度 0 和最大度两种结点，直接套第 3 条。

@kp 严格k叉树 | 只有度 0 和度 $k$ 结点的树（哈夫曼树、最佳归并树）
- 叶子数 $n_0$ 与分支结点数 $n_k$ 满足 $n_0=(k-1)n_k+1$，总结点 $n=n_0+n_k$。
- $k=2$：$n=2n_0-1$（哈夫曼树 $n$ 个叶子共 $2n-1$ 个结点）。
- $(n_0-1)$ 必须能被 $(k-1)$ 整除，否则构不成严格 $k$ 叉树——这就是最佳归并要补虚段的原因。
- 例：3 叉，叶子 7 个 ⟹ $(7-1)/2=3$ 个分支结点，共 10 个结点。

@tpl T表达式DAG | 用有向无环图表示表达式求最少顶点：先画表达式树，再把相同的叶子、相同的子树各合成一个
1. 按运算顺序画出表达式二叉树，数出结点数（这是没共享时的上限，常是一个干扰项）。
2. 操作数去重：同一个变量不管出现几次只留一个顶点。
3. 子表达式去重：**整棵子树完全相同**才能合并（运算符相同、两个操作数也相同）；$x+y$ 与 $x+z$ 不能合。
4. 从下往上合并，每合并一次减去被删掉的结点数，最后数顶点。

@tpl TKMP比较次数 | 数 KMP 的比较次数：先写 next，再一趟一趟比；失配那次也算，失配后主串指针不动、模式串跳到 next
1. 求 next（0 起：next[0]＝−1，next[j]＝前 $j$ 个字符最长相等真前后缀的长度）。
2. 每趟从当前 $j$ 开始和主串第 $i$ 个字符比，相等就都后移；**失配的那一次也计 1 次**。
3. 失配：$i$ 不动，$j\leftarrow$ next[$j$]，在同一个 $i$ 上继续比（这是新的一次比较）；$j$ 退到 −1 时 $i$、$j$ 都后移、不计比较。
4. 匹配成功时停，把各趟次数加起来。草稿上把模式串在主串下面错位写几行，最直观。

@kp KMP | KMP 算法与 next 数组
主串指针 $i$ 永不回退；模式串在 $j$ 处失配时，跳到 next[$j$] 继续比，跳过的部分已知相等。
- next[$j$]（0 起）＝模式串前 $j$ 个字符中「最长的相等真前缀与真后缀」的长度，next[0]＝−1。
- 时间 $O(n+m)$；nextval 在 $p_j=p_{\text{next}[j]}$ 时继续往回跳，省掉必然失败的比较。
- 例：abaabc 的 next＝(−1,0,0,1,1,2)。

@tpl T虚段 | $k$ 路最佳归并树要补几个虚段：算 $u=(n_0-1)\bmod(k-1)$，$u=0$ 不补，否则补 $k-1-u$ 个
1. 最佳归并树是严格 $k$ 叉的哈夫曼树（[[严格k叉树]]）：要求 $(n_0-1)$ 被 $(k-1)$ 整除。
2. 算 $u=(n_0-1)\bmod(k-1)$；$u\ne0$ ⟹ 补 $k-1-u$ 个长度为 0 的虚段。
3. 验算：补完后 $(n_0+\text{补}-1)$ 能被 $k-1$ 整除；分支结点（归并次数）＝商。
4. 两个「减 1」别丢：模的是 $n_0-1$，模数是 $k-1$。

@kp 最佳归并树 | 最佳归并树（外部排序）
把初始归并段的长度当权值，做 $k$ 叉哈夫曼树，使总读写次数（＝WPL × 2，读一次写一次）最小。
- 叶子数不满足 $(n_0-1)\bmod(k-1)=0$ 时，补若干个长度为 0 的虚段，让它们在最底层先参与归并。
- 例：8 个段 3 路归并，$(8-1)\bmod2=1$ ⟹ 补 $3-1-1=1$ 个虚段。

@tpl T链表三板斧 | 单链表重排 / 回文 / 交替合并类算法题：拆成「快慢指针找中点 → 头插法逆置一段 → 两链交替合并」三个基本操作，每步 $O(n)$、空间 $O(1)$
1. 找中点：p、q 从头结点出发，p 走一步、q 走两步；q 到尾时 p 在前半段末尾（前半段 $\lceil n/2\rceil$ 个）。
2. 逆置：从 p 之后断开，后半段逐个摘下头插到 p 后面。
3. 合并：两个指针分别扫前后两段，把后段结点插到前段结点之后；插之前先用临时指针记住后继。
4. 题目要「空间 O(1)」就是在禁止复制到数组；要「尽可能高效」就是在禁止每次从头找尾的 $O(n^2)$。

@tpl T大小端字节 | 多字节数里某个字节在哪个地址：先求起始地址，再按大/小端数到那个字节
1. 起始地址＝有效地址 EA（算 EA 时负的偏移量要先[[符号扩展]]）。

3. 大端：从左往右依次放在 EA、EA＋1…，LSB 在 EA＋（字节数−1）；小端：整行倒过来，LSB 在 EA。

@tpl T中断占用率 | 中断方式下 CPU 用于 I/O 的时间占比：每秒中断次数 × 每次开销周期 ÷ 主频
1. 每次中断传多少：缓冲寄存器满一次中断一次 ⟹ 一次传「寄存器宽度」那么多（32 位＝4B）。
2. 每秒中断次数＝设备速率 ÷ 每次传的量。
3. 占比＝每秒中断次数 × 每次中断开销（周期）÷ 主频（周期/秒）。
4. 换成 DMA：每次传「一块」才中断一次，次数要除以块大小；再加上预处理开销（若题给）。

@tpl T置换表 | 页面置换手算：画「访问串 × 页框」表，每列写一次访问后的页框内容，缺页打 √

@kp 用户级线程 | 用户级线程（ULT）与内核级线程（KLT）
- ULT：线程库在用户空间管理，线程控制块放在用户空间；**内核只看见进程**，不为它们建 TCB。切换不进内核、快，能在不支持线程的 OS 上实现；但一个线程阻塞（系统调用）整个进程阻塞，多个线程也不能在多核上并行。
- KLT：内核建 TCB、内核调度；切换要进内核、慢，但能并行、一个阻塞不连累别人。
- 组合（多对多）方式兼得两者。

@kp 动态分区 | 动态分区分配的四种算法
- 首次适应：空闲区按地址递增排，找第一个够大的。综合表现最好，低地址碎片多。
- 循环首次（邻近）适应：从上次找到的位置往后找。大空闲区被均匀切碎。
- 最佳适应：按容量递增排，找最小的够大的。剩下的边角最小 ⟹ **外部碎片最多**。
- 最坏适应：找最大的空闲区切。大空闲区最快用光。

@tpl TPV限流器 | 「既要不死锁、又要尽可能多并发」的 PV 题：加一个计数信号量当门票，初值取上限，并且**先 P 门票、再 P 资源**
1. 先找出会死锁的环（人人拿一只筷子等另一只）：只要同时抢资源的人数 ≤ 资源数能保证至少一人凑齐，就不会死锁。
2. 门票信号量初值＝「题目天然的上限」与「不死锁的上限」取 min（哲学家：$\min(m,n-1)$）。
3. P(门票) 必须写在所有 P(资源) 之前；V 的顺序无所谓。

@kp 哲学家进餐 | 哲学家进餐问题与三种防死锁办法
$n$ 人围坐、$n$ 根筷子，每人要左右两根才能吃。人人先拿左边 ⟹ 可能人人拿一根、互相等 ⟹ 死锁。
- 法一：最多允许 $n-1$ 人同时拿筷子（加一个初值 $n-1$ 的信号量）。
- 法二：奇数号先拿左边、偶数号先拿右边（打破环路）。
- 法三：两根筷子要么一起拿到、要么都不拿（用互斥量把「拿两根」包成原子操作）。

@tpl T簇号换算 | 簇号 / 块号 → （柱面，磁头，扇区）：先算「每磁道几簇、每柱面几簇」，再逐级整除、取余

@kp P2P | C/S 模型与 P2P 模型

3. 找选项里「第一个跳着出的元素」，看被它压在底下的几个，后面是不是逆序出现。

@tpl TBST祖先约束 | 抽象结点的二叉排序树比大小 → 写中序或看「在谁的哪一侧」
1. BST 的中序遍历严格递增：把中序写出来，从左到右就是从小到大。
2. 更快：在某结点的==右子树里==（不只是右孩子）就一定比它大，左子树里一定比它小。
3. 选项里的三元不等式，逐对用第 2 条核对。

@tpl T拓扑入度筛 | 「哪个不是拓扑序列」→ 先看入度为 0 的点占没占前几位
1. 列每个顶点的入度；入度为 0 的点才能当第一个。
2. 删掉第一个点及其出边，再看谁的入度变成 0，才能当第二个……
3. 选项多时先用第 1 条筛前两位；还分不出就挑「前驱多的顶点」检查它的前驱是否都在它前面。

@tpl T希尔反推增量 | 给出希尔排序某趟结果问增量 → 用「换了位置的元素」反推间隔，再整趟验证
1. 找一个从下标 $i$ 换到下标 $j$ 的元素：它俩同组 ⟹ 增量 $d$ 整除 $|i-j|$。
2. 用候选 $d$ 把序列按下标模 $d$ 分组，组内排序放回，看是否和题给结果一模一样。
3. 第二趟必须在第一趟的==结果==上做，不是在原序列上做。

@tpl T罗马数字组合 | Ⅰ/Ⅱ/Ⅲ 组合选择题 → 先判最有把握的一条，用选项结构砍
1. 每条单独判对错，不要互相牵连（一条对不代表另一条对）。
2. 先判最确定的那条，立刻排除含它/不含它的选项；常常只判两条就能定。
3. 三条都像「好话」时，先怀疑「全选」；有「必须」「一定」「立即」的那条先怀疑是错的。

@tpl T移位补什么 | 逻辑/算术移位 → 只有右移分家：逻辑补 0，算术补符号位
1. 左移：两种都补 0（算术左移可能溢出）。
2. 右移：逻辑补 0（无符号数）；算术补符号位（补码，保持正负）。
3. 做完回头对一下题干问的先后顺序，别把两个结果对调。

@tpl TDRAM行列 | DRAM 阵列问行数列数 → 引脚＝max(行位数,列位数) 先定，再按「行少刷新快」
1. 行列地址复用同一组引脚分两次送 ⟹ 引脚数 ＝ $\max(\log_2 r,\log_2 c)$ ⟹ $r$、$c$ 尽量接近。
2. DRAM 按行刷新 ⟹ 行数越少刷新开销越小 ⟹ 二者不能相等时取 $r<c$。
3. 容量 $r\times c$ ＝ 单元数，位数加起来等于地址位数。

@tpl T变址反求下标 | 给元素地址求变址寄存器的值 → (地址差) ÷ 元素大小
1. 地址差先换成十进制（100H ＝ 256）。
2. 变址寄存器存下标还是字节偏移看题干：「偏移地址 ＝ 变址值 × sizeof」⟹ 存的是下标，要除元素大小。
3. 常用大小：char 1、short 2、int/float 4、double 8。

@tpl T流水线周期 | 问流水线时钟周期 → 最慢段 ＋ 段间寄存器延时（题干给了才加）
1. 时钟周期 ＝ max(各段时间) ＋ 流水段寄存器（锁存器）延时。
2. 题干写「忽略段间缓存时间」或没给 ⟹ 不加；给了数值 ⟹ 一定要加。
3. 吞吐、加速比都建立在这个周期上，算错一步全错。

@tpl T总线提速 | 问哪些措施能提高总线传输率/带宽 → 按公式因子判，复用只省线
1. 带宽 ＝ 总线宽度 × 工作频率（× 每周期传送次数）：加宽、提频都能提高。
2. 突发（猝发）传输：一次地址传多个连续数据，省掉重复的地址时间 ⟹ 有效传输率提高（带宽不变）。
3. 地址/数据线复用：只省引脚和成本，地址和数据要分时用线，不提速。

@tpl T交错穷举反推 | 并发指令交错问结果/序列个数 → 从结果反推约束，不要正着枚举
1. 把 `x++` 拆成「读 → 加 → 写」三条机器指令。
2. 要某个结果，先想「后写的线程必须读到什么值」，推出两段指令的先后约束。
3. 总交错数 ＝ $\binom{a+b}{a}$（两线程各 $a$、$b$ 条指令），用来核对答案的量级。

@tpl T三态转换判据 | 问哪些事件导致阻塞/就绪/唤醒 → 「缺 CPU」落就绪，「缺别的」落阻塞
1. 等 I/O、等资源、等信号 ⟹ 阻塞态。
2. 只是 CPU 被拿走（时间片到、被抢占）⟹ 就绪态。
3. 阻塞 → 就绪是被别人唤醒，不能自己醒；就绪 → 运行只能由调度程序完成。

@tpl T磁盘调度辨析 | 问饥饿/黏着/公平 → 想「同一磁道上请求源源不断」会怎样
1. 饥饿（远处请求永远等）：只有 SSTF。
2. 磁头臂黏着（被一个磁道拖住不走）：SSTF、SCAN、C-SCAN 都会；FCFS 不会。
3. 治黏着：N-Step-SCAN、FSCAN（新请求不插进正在处理的队列）。

@tpl T端口协议表 | 应用层协议问传输层/端口 → 背一张表：20 21 23 25 53 69 80 110 161
1. FTP 数据 20 / 控制 21、TELNET 23、SMTP 25、DNS 53、TFTP 69、HTTP 80、POP3 110、SNMP 161（递增）。
2. 用 UDP 的只有 ==DNS、TFTP、SNMP==（再加 DHCP 67/68），其余全 TCP。
3. 每层「交给上一层」看本层首部的一个字段：帧的类型 → IP 的协议 → TCP/UDP 的==目的端口==。

@tpl T层次归属 | 问某概念属于哪一层 → 看它解决什么问题，别看名字
1. 物理层四特性：机械（形状尺寸）、电气（电平）、功能（引脚含义）、过程（时序）。
2. 物理地址＝MAC 地址，属于==数据链路层==；IP 地址网络层；端口传输层。
3. 名字里带「物理」的不一定是物理层，名字里带「传输」的也不一定是传输层。

@tpl TMAC逐跳 | 问某一段链路上帧的源/目的地址 → 两段表：MAC 逐跳换，IP 端到端不变
1. 每经过一台路由器，帧头重写：源 MAC ＝ 路由器出口、目的 MAC ＝ 下一跳。
2. IP 源、目的地址全程不变（经过 NAT 才变）。
3. 交换机是二层设备，不改任何地址，也不出现在 MAC 地址里。

@tpl T路由聚合 | 几条路由求聚合 → 展开不同的那一字节，数公共前缀位数
1. 前面完全相同的字节直接算进前缀（每字节 8 位）。
2. 把不同的那一字节写成二进制，从高位数到第一个不同为止 ⟹ 公共位数 $k$。
3. 聚合 ＝ 公共位保留、其余清 0，前缀长度 ＝ 相同字节数×8 ＋ $k$；最后把原路由逐条代回检查都被覆盖。

@tpl T标记数组 | 数组题要求「时间尽可能高效」且值域有界 → 开一个标记/计数数组，空间换时间
1. 先找答案的范围（本题：缺失的最小正整数一定在 $1\sim n+1$）。
2. 开大小为范围的数组 B，扫一遍原数组做标记/计数，再扫一遍 B 找答案：$O(n)$ 时间、$O(n)$ 空间。
3. 卷面三段：基本设计思想 → 代码（关键处注释） → 时间、空间复杂度。

@tpl TMST多解 | 「给出所有最小生成树」→ Kruskal 按权分批加边，同权边处分岔
1. 按权从小到大把边分批；每一批里先删掉会成环的边。
2. 若某一批里剩下的边比「还需要的边数」多，或者能互相替代，就产生多棵 MST。
3. 每棵都要画出来（带权图）并写总费用；总费用一定相同。

@kp 满二叉树 | 满二叉树
每层都排满的二叉树：高 $h$ 时结点 $2^h-1$ 个、叶子 $2^{h-1}$ 个，全部在最底层。
- 等价说法：「所有叶子在同一层且每个非叶结点都有 2 个孩子」。
- 用法：结点数 ＝ $2\times$叶子数 − 1。最小例子：高 3，叶 4，共 7 个。

@kp 线性探测 | 线性探测再散列
冲突时依次试下一个地址：$H_i=(H(k)+i)\bmod m$，$i=1,2,\dots$
- 查找成功的比较次数 ＝ 插入时试到第几个位置。
- 查找失败（王道口径）：从散列地址起一直比到空位为止，空位也算一次比较。
- 副作用：堆积（同义词和非同义词挤在一起）。

@kp 希尔排序 | 希尔排序
按增量 $d$ 把下标相差 $d$ 的元素分成一组，组内直接插入排序；$d$ 逐步缩小，最后一趟 $d=1$。
- 每趟结果：每组（下标模 $d$ 相同的元素）各自有序。
- 不稳定；时间约 $O(n^{1.3})$，最坏 $O(n^2)$；增量序列没有统一标准，题给什么用什么。

@kp 变址寻址 | 变址寻址
有效地址 EA ＝ (IX) ＋ A：形式地址 A 放数组首地址，变址寄存器 IX 放下标（或字节偏移），循环里 IX 自增。
- 题干若说「偏移地址 ＝ 变址值 × sizeof(元素)」，硬件自动乘比例因子，IX 存的就是下标。

@kp 流水段寄存器 | 流水段寄存器（锁存器）延时
每个流水段末尾有一个寄存器，把本段结果锁住给下一段用。一个时钟周期要够「本段组合逻辑做完 ＋ 写进寄存器」，所以周期 ＝ 最慢段 ＋ 寄存器延时。题目没给就忽略。

@kp 并发并行 | 并发与并行
- 并发：同一时间段内交替执行，宏观同时、微观轮流（单 CPU 就有）。
- 并行：同一时刻真正同时执行，需要多个执行部件——多 CPU，或者 CPU 与 I/O 设备同时工作。

@kp 周转时间 | 周转时间
周转时间 ＝ 完成时刻 − 提交（进入系统/就绪队列）时刻 ＝ 等待时间 ＋ 运行时间（＋调度开销）。平均周转时间 ＝ 总和 ÷ 进程数；带权周转时间 ＝ 周转时间 ÷ 运行时间。

@kp 竞争条件 | 竞争条件（race condition）
多个线程不加同步地读写同一共享变量，结果取决于指令交错的先后。`x++` 不是原子操作：读到寄存器、加 1、写回三步，两个线程交错时后写的会覆盖先写的。解决：把读写包进临界区（信号量、锁、原子指令）。

@kp 条件变量 | 管程的条件变量
管程里为「等某个条件」设的变量，只有一个等待队列，没有数值。
- `x.wait()`：调用者阻塞，挂到 x 的队列上，==同时释放管程==。
- `x.signal()`：唤醒 x 队列上的一个进程；队列空则什么也不做。

@kp 磁头臂黏着 | 磁头臂黏着
有进程反复访问同一磁道（或一小片磁道），磁头一直停在那里服务，其他磁道的请求得不到响应。SSTF、SCAN、C-SCAN 都会被拖住（新请求总比远处的「更近」或「在当前扫描路径上」）；FCFS 按到达顺序，不会。

@kp 让权等待 | 让权等待
同步机制四准则之一：进程进不了临界区时应立即释放 CPU（阻塞自己），不要忙等。做到它的是记录型信号量（block/wakeup）和管程；软件方法和 TS、Swap 指令都是忙等。

@kp RTSCTS | RTS/CTS 信道预约
802.11 的 CSMA/CA 可选机制：发送方先发短的 RTS（请求发送），接收方（AP）回 CTS（允许发送），两帧都带「本次通信要占多久」，听到的站据此设置 NAV（网络分配向量），在这段时间内不发送。主要缓解隐蔽站问题。

@kp 两种时延 | 传输时延与传播时延
- 传输时延（＝发送时延）＝ 数据长度 ÷ 发送速率，与距离无关。
- 传播时延 ＝ 信道长度 ÷ 信号传播速度，与数据长度无关。
- 「忽略确认帧的传输时延」只去掉确认帧的发送时间，它回程的传播时延照算。

@kp TTL | IP 首部的 TTL（生存时间）
每经过一台路由器减 1，减到 0 就丢弃并（通常）回 ICMP 超时报文。所以 TTL ＝ 分组最多能被转发的路由器个数：路径上有 $r$ 台路由器，要求 $\text{TTL}-r\ge1$ 才能送到目的主机。

@kp VIPT | 用虚拟地址的低位定 Cache 组号（VIPT）
若「组号位数 ＋ 块内地址位数 ≤ 页内偏移位数」，组号完全落在页内偏移里，而页内偏移虚实相同 ⟹ 可以直接用虚拟地址定组，查 TLB 和查 Cache 组同时进行，等物理地址出来再比标记。

@kp MIME | MIME
SMTP 只能传 7 位 ASCII 文本。MIME 在邮件首部增加说明内容类型和编码方式的字段（如 base64），把图片、音视频、可执行文件等二进制内容编码成 ASCII 再交给 SMTP 传送。

@kp 分用 | 复用与分用
复用：发送方多个进程共用同一个传输层协议发出去；分用：接收方传输层根据==目的端口号==把报文交给对应的进程。UDP 的源端口可以全 0（不需要回信时），所以分用不可能依赖它。

@tpl T两序相同 | 两种遍历序列相同的条件：把两种顺序都写成 N、L、R 三个字母，相同就得让「位置不同的那个」消失
1. 先序 NLR、中序 LNR、后序 LRN。两两比较，找出位置不一样的字母。
2. 先序＝中序：N 与 L 换了位置 ⟹ L 必须为空 ⟹ 每个结点都没有左孩子（向右的单链）。
3. 中序＝后序：N 与 R 换了位置 ⟹ R 必须为空 ⟹ 都没有右孩子（向左的单链）。
4. 先序＝后序：N 一头一尾 ⟹ L、R 都为空 ⟹ 只有一个根结点。
5. 选项里的「度均为 1」是陷阱：单链可以左右拐，拐一次就不相同了。

@tpl T握手定理 | 无向图顶点数 / 边数：度数之和＝2×边数；问「至少几个顶点」就让其余顶点的度取到最大
1. 列式：$\sum \deg(v)=2e$（每条边给两端各贡献 1 度）。
2. 已知度数的顶点先算出贡献，剩下的度数交给「其他顶点」。
3. 求顶点「至少」⟹ 其他顶点每个尽量多分担 ⟹ 度取允许的最大值；求「至多」⟹ 取最小值（一般是 1）。
4. 有向图：入度和＝出度和＝弧数。

@tpl T判定树判据 | 判断一棵树能否是折半查找判定树：逐个结点数左右子树大小，全树只许一边倒
1. mid 向下取整：每个结点都有 左子树结点数＝右子树 或 少 1；向上取整：等于或多 1。
2. 同一棵树只能用一种取整：不许这里左多、那里右多。
3. 考场快法：只盯「只有一个孩子」的结点——它们挂的孩子必须全在左边或全在右边；再往上查一层。
4. 「是平衡二叉树」「高度对」都只是必要条件，不够。

@tpl T链式存储排序 | 换成链表会不会变慢：看算法取下一个元素时下标是 ±1 还是跳着走
1. ±1（顺着走、相邻比较）⟹ 链表照样 $O(1)$ 一步：直接插入、冒泡、简单选择、归并、基数。
2. 跳着走（±d、mid、2i、两头夹）⟹ 链表每跳一次要从头数 ⟹ 变慢：折半插入、希尔、快排（双向）、堆排序。
3. 链表还能省东西：直接插入不用移动元素，归并不用辅助数组——但时间复杂度不变。

@tpl T跨字周期数 | 多字节数据要几个存取周期：起址除以「一次能取的字节数」看余数，再加上数据长度，数跨了几个对齐字
1. 先定一次能取几个字节 $w$（同时启动的交叉存储器：模块数 × 每模块字节数；或总线宽度）。
2. 起址 $\bmod w$＝$r$；数据长 $L$ 字节 ⟹ 涉及的对齐字个数＝$\lceil (r+L)/w\rceil$。
3. 对齐（$r=0$）时就是 $L/w$；不对齐至少多一个周期——这正是要求边界对齐的理由。

@tpl T调度先圈候选 | 调度题「某时刻选谁」：先圈出此刻已到达、还没做完的作业，再在圈内按算法比
1. 列表时把到达时刻写在最前一列，对着题给时刻画一条竖线，竖线右边（还没来）的划掉。
2. FCFS 比到达先后，SJF 比运行时间，HRRN 算 $1+$等待/运行，优先级比优先数。
3. 选项里总有一个「最短但还没到」的作业专坑没圈候选的人。

@tpl T回收合并 | 动态分区回收：先按始址把空闲区排好，验「首＋长＝下一个首」，再按算法重排空闲链
1. 空闲区表常按大小或乱序给出，先按地址重写一遍。
2. 回收区 [b, b+len)：前一块末尾＝b ⟹ 前邻；b+len＝后一块始址 ⟹ 后邻。四种情形：都不邻 +1、单邻 0、双邻 −1（个数变化）。
3. 合并后按算法重排：首次适应按地址、最佳适应按大小递增、最坏适应按大小递减。

@tpl T权限位串 | 权限用二进制位串表示要几位：可以同时拥有的权限一种一位，位串属于文件就要存下所有用户类别
1. 权限能叠加（读＋写＋执行）⟹ 不能编号，只能「一种权限一个标志位」。
2. 位串写在 FCB 里 ⟹ 要覆盖所有用户类别 ⟹ 位数＝类别数 × 权限种数（访问控制矩阵的一列）。
3. 用户来访问时系统先判断他属于哪一类、再查那一行——「哪一类」不用存。

@tpl T封装效率 | 封装开销求传输效率：先数清哪几层加首部，效率＝原始数据 ÷（数据＋全部首部）
1. 写出模型的层：OSI 七层或 TCP/IP 四（五）层，逐层打勾。
2. 物理层不封装；最上层要发的数据本身是基准，不算开销；题目另说「某层不加」照划。
3. 选项常是「多数一层 / 少数一层」的等差链，数层数时用手指一层层点。

@tpl T等分子网 | 网络等分成 N 个子网：子网位＝$\log_2N$，主机位＝原主机位−子网位，可分配地址＝$2^h-2$
1. $N$ 不是 2 的幂就向上取到 2 的幂。
2. 新前缀＝原前缀＋子网位；可分配主机数要减 2（网络地址、广播地址）。
3. 选项里成对出现的「$2^h$ 与 $2^h-2$」，答案几乎总是减 2 的那个。

@tpl T带括号中序 | 表达式树转中缀：中序递归，叶子直接输出，分支结点（根除外）外面包一层括号
1. 递归带一个深度参数 deep，根的 deep＝1。
2. 叶子：输出操作数，不加括号。
3. 分支结点：deep＞1 时先输出「(」，递归左子树、输出运算符、递归右子树，再输出「)」。
4. 一元运算（如取负）左子树为空，递归空树直接返回，照样得到 (-d)。

@tpl T无符号回绕 | unsigned 参与减法和比较：$0-1$ 回绕成 $2^{32}-1$，$\le$ 永真就是死循环
1. 表达式里只要有一个 unsigned 操作数，int 会被转成 unsigned 再算（C 的寻常算术转换）。
2. unsigned 的 $0-1$＝全 1＝$2^{32}-1$；`i<=n-1` 在 $n=0$ 时永真。
3. 机器层面：减法的 CF＝借位，无符号「小减大」就借位 ⟹ CF＝1。
4. 改法：把条件写成 `i<n`，或把变量改成 int。

@tpl T读写定互斥 | 「互斥且最大限度并发」的 PV：列「线程 × 共享变量」读写表，每一对有读写冲突的「线程—线程—变量」才设一个信号量
1. 局部变量、只被一个线程碰的全局变量都不用管。
2. 读读不互斥，读写、写写才互斥（读者—写者原则）。
3. 一对冲突一个信号量：若用一个信号量把整片锁住，互斥满足了，但让本可同时读的线程也互斥了 ⟹ 扣并发度的分。
4. 一个线程要同时拿几把锁时，各线程按同一顺序申请；能拆开的临界区先做完一个、放掉锁再拿下一个。

@tpl T捎带确认号 | 帧写成 $S_{x,y}$（x＝发送序号，y＝捎带确认号）：y 是「希望收到的下一帧」，已收到的是 y−1 及以前
1. 读对方帧 $R_{x,y}$：对方已正确收到我方 $0\sim y-1$ 号；我方发送窗口左沿移到 $y$。
2. 我方帧的 y：等于我方期望对方的下一帧号；GBN 只按序接收，中间丢了一帧，后面的帧数据被丢弃，y 停在丢的那一号。
3. 重发旧数据时，序号沿用原来的，确认号要填==当前最新==的期望值。
4. 窗口内序号按 $2^k$ 取模回绕：$k=3$ 时 …6、7、0、1…

@kp 两序相同 | 三种遍历序列两两相同的条件
- 先序＝中序 ⟺ 所有结点都没有左孩子（右单链，或只有一个结点）。
- 中序＝后序 ⟺ 所有结点都没有右孩子（左单链）。
- 先序＝后序 ⟺ 只有一个根结点（空树另说）。
- 先序与后序恰好相反 ⟺ 每个结点至多一个孩子（树高＝结点数），左右都行。
- 例：A 的右孩子 B，B 的右孩子 C：先序 ABC，中序 ABC。

@kp 握手定理 | 握手定理（度数之和＝2×边数）
无向图中所有顶点的度数之和等于边数的 2 倍：$\sum\deg(v)=2e$。
- 推论：度为奇数的顶点有偶数个。
- 有向图：所有顶点入度之和＝出度之和＝弧数。
- 例：4 个顶点度为 3、3、2、2 ⟹ 边数 $(3+3+2+2)/2=5$。

@kp B+树 | B+ 树
m 阶 B+ 树是 B 树的变形，为数据库和文件系统的磁盘索引而生。
- 关键字都出现在叶结点里，非叶结点只放索引（每个子树的最大或最小关键字），不放记录 ⟹ 一个盘块能塞更多索引 ⟹ 树更矮 ⟹ 读盘次数更少。
- 叶结点按关键字顺序链成单链表 ⟹ 支持顺序查找和范围查询。
- 每次查找都要走到叶结点 ⟹ 查找时间稳定。
- B 树的非叶结点也存记录，可能在半路就找到；B+ 树结点里 n 个关键字对应 n 棵子树，B 树是 n+1 棵。
- 典型应用：关系数据库索引（如 MySQL InnoDB）、文件系统索引。

@kp 交叉编址 | 多模块交叉编址（低位交叉）与两种启动方式
相邻地址落在相邻模块：模块号＝地址 mod 模块数。
- 轮流启动：每隔 1/m 个存取周期启动下一个模块，单个模块宽度＝总线宽度；连续读 m 个字只需 $T+(m-1)\cdot T/m$。
- 同时启动：所有模块同时读同一行，m 个模块的位数拼起来＝总线宽度，一个存取周期读出 m 个连续字节（一个对齐的字）。
- 判别：模块位数 × 模块数＝总线宽度 ⟹ 同时启动；单模块位数＝总线宽度 ⟹ 轮流启动。
- 例：4 片 ×8 位接 32 位总线 ⟹ 同时启动，一次取 4 字节，地址必须 4 字节对齐地取。

@kp 超标量 | 超标量与超流水线
- 超标量：CPU 里放多条流水线（多套功能部件），一个时钟周期同时发射多条指令 ⟹ CPI＜1；功能段的处理时间、时钟周期都不变。常配合动态调度（乱序执行、分支预测）。本质是空间并行。
- 超流水线：把每个功能段再切细，段数更多 ⟹ 时钟周期变短、主频升高；CPI 仍为 1。本质是时间并行。
- 对照性能公式 $T=IC\times CPI\times T_{clk}$：超标量压 CPI，超流水线压 $T_{clk}$。

@kp 控制存储器 | 控制存储器 CS（微程序控制器）
存放全部微程序（微指令）的存储器，在 CPU 的控制器内部，用 ROM 实现，运行时只读不写。
- 按微地址访问：地址寄存器 μPC（CMAR），数据寄存器 μIR（CMDR）。
- 入口微地址由操作码经微地址形成部件得到，后继微地址由 μPC＋1 或下址字段给出。
- 对照主存 MM：在 CPU 外，存指令和数据，RAM（大部分）＋ROM（BIOS），也按地址访问。

@kp 相联存储器 | 相联存储器（按内容访问）
不按地址、而是拿一个关键字同时与所有单元的标记比较，命中的单元输出内容，又叫 CAM。
- 408 里用到它的地方：全相联 / 组相联 Cache 的标记比较、快表 TLB。
- 控制存储器、主存、寄存器堆都是按地址访问，不是相联存储器。

@kp PCIe | PCI-Express 总线
高速串行、点对点连接的 I/O 总线，支持全双工。
- 由若干条通道（lane）组成：×1、×4、×16 指 1、4、16 条通道；每条通道内部是一对发、一对收的差分串行线。
- 通道数越多带宽越大，但每条通道的传输方式仍是串行，所以「×16 采用并行传输」是错的。
- 对照 PCI：32/64 位并行共享总线。

@kp 多重中断 | 多重中断与单重中断
- 单重中断：执行中断服务程序时不响应新的中断 ⟹ 整个处理期间关中断。
- 多重中断（中断嵌套）：保存现场和屏蔽字后先开中断，再执行服务程序主体，期间可被更高优先级的中断打断；恢复现场前再关中断。
- 流程：关中断 → 保存断点 → 识别中断源 → 保存现场和屏蔽字 → ==开中断== → 执行服务程序 → 关中断 → 恢复现场和屏蔽字 → 开中断、返回。
- 例：「中断处理期间 CPU 处于关中断状态」对单重中断对、对多重中断错。

@kp I/O端口 | I/O 端口与 I/O 指令
I/O 端口是 I/O 接口里可被 CPU 访问的寄存器：数据端口、状态端口、控制端口。
- I/O 指令（IN / OUT）在 CPU 的通用寄存器和 I/O 端口之间传送数据；端口与外设之间的传送由接口的控制逻辑完成，CPU 碰不到设备本身。
- 端口编址：独立编址（专用 I/O 指令）或统一编址（用访存指令访问端口）。

@kp FCFS与SJF | 先来先服务与短作业优先
- FCFS：按到达先后选；对长作业有利、对短作业不利；不会饥饿。
- SJF：在已到达的作业中选估计运行时间最短的；平均等待 / 周转时间最短（所有作业同时到达时），长作业可能饥饿。
- 作业调度只能在已到达的作业里选：某时刻还没到的作业不参加比较。

@kp 多道程序 | 多道程序设计
内存中同时放多道程序，一道等 I/O 时 CPU 去运行另一道。
- 好处：CPU 利用率高、I/O 设备利用率高、系统吞吐量大。
- 代价：要管理多个进程（PCB、调度、切换、内存分配与保护），系统开销增大；单个作业的周转时间可能变长、无交互性（批处理）。

@kp 簇 | 簇（文件分配单位）
把若干个连续扇区（盘块）组成一簇，文件系统以簇为单位分配空间。
- 文件占用空间＝$\lceil$文件大小 / 簇大小$\rceil$ × 簇大小；最后一簇没用满的部分是内部碎片。
- 簇越大：FAT / 位图越小、指针越少，但内部碎片越多。
- 例：簇 4KB，文件 5600B ⟹ 2 簇＝8KB。

@kp 访问控制矩阵 | 访问控制矩阵与权限位串
行＝用户（或用户类别），列＝文件（对象），格子里是该用户对该文件的权限集合。
- 按列存（每个文件一张）＝访问控制表 ACL，记在文件的 FCB 里；按行存＝权限表（能力表），记在用户那里。
- 权限能叠加 ⟹ 每种权限一个标志位；一个文件的权限位串＝用户类别数 × 权限种数。
- UNIX 的 rwxrwxrwx：3 类用户 × 3 种权限＝9 位。

@kp OSI七层 | OSI 参考模型与封装
自上而下：应用层、表示层、会话层、传输层、网络层、数据链路层、物理层。
- 封装：发送时每层给上层交下来的数据加上本层首部（数据链路层还加尾部），形成本层 PDU；接收时逐层剥去。
- 物理层只传比特，不再封装；数据链路层的 PDU 叫帧，网络层叫分组（数据报），传输层叫报文段（TCP）/ 用户数据报（UDP）。
- TCP/IP 只有四层：应用、传输、网际、网络接口。

@kp 特殊IP地址 | 特殊 IP 地址的用途与方向
| 地址 | 含义 | 作源 | 作目的 |
| 0.0.0.0 | 本网络上的本主机（还没有 IP，如 DHCP 发现阶段） | 可 | 不可 |
| 255.255.255.255 | 受限广播（本网络所有主机，路由器不转发） | 不可 | 可 |
| 主机号全 1 | 直接广播（某个网络的所有主机） | 不可 | 可 |
| 127.x.x.x | 环回测试，数据不出本机 | 可 | 可 |
| 网络号全 0 的主机地址 | 本网络上的某台主机 | 可 | 不可 |
- 路由表里的 0.0.0.0/0 是默认路由，与「作源地址的 0.0.0.0」是两回事。

@kp 路由协议封装 | RIP、OSPF、BGP 的封装与特点
| 协议 | 类型 | 直接封装在 | 理由 |
| RIP | 内部网关、距离向量 | UDP（端口 520） | 信息量小、周期性全量重发，不需要可靠传输 |
| OSPF | 内部网关、链路状态 | IP（协议号 89） | 报文尽量短，可靠性自己用确认实现 |
| BGP | 外部网关、路径向量 | TCP（端口 179） | 跨自治系统、环境复杂，要可靠传输 |
- 「直接封装」＝紧挨着的下一层；BGP 报文最终也在 IP 数据报里，但直接封装它的是 TCP。

@kp 表达式树 | 表达式树
叶结点是操作数，分支结点是运算符；左右子树是运算符的两个操作数（一元运算只有右子树）。
- 后序遍历＝后缀表达式，先序遍历＝前缀表达式，中序遍历＝去掉括号的中缀表达式。
- 中序要加括号才等价：分支结点（除根）外包一层括号；后序、先序不需要括号。
- 求值：后序递归，先算左右子树，再用根的运算符合并。

@kp MST唯一性 | 最小生成树的唯一性
- 充分条件：全图各边权值互不相同；更弱也够用：任意一个环上的边权互不相同。
- 都不是必要条件：有等权边的图，MST 也可能唯一（等权边替换会成环就换不了）。
- 判断某图的 MST 是否唯一：求出一棵 MST 后，看树外的每条边能否替换环上一条同权的树边——能换就不唯一。

@kp 无符号比较 | C 语言中有符号数与无符号数的比较和转换
- 同长度的 int 与 unsigned 一起运算或比较时，int 先按位不变转成 unsigned。
- 例：`-1 < 0u` 为假（$-1$ 变成 $2^{32}-1$）；unsigned 的 `0-1` 得 $2^{32}-1$。
- 机器层面比较靠减法置标志：无符号看 CF（借位），有符号看 SF⊕OF。

@kp CISC与RISC | CISC 与 RISC
| 特点 | CISC（如 x86） | RISC（如 MIPS、ARM、RISC-V） |
| 指令长度 | 不固定（x86 为 1～15 字节） | 固定（通常 4 字节） |
| 指令条数 / 寻址方式 | 多、复杂 | 少、简单 |
| 访存 | 多数指令可访存 | 只有 load/store 访存 |
| 控制器 | 多用微程序 | 多用硬布线，适合流水线 |
| 通用寄存器 | 较少 | 较多 |
- 判 CISC/RISC 最直接的证据是指令长短是否一致。

@kp 就近舍入 | IEEE 754 的就近舍入（舍入到偶数）
尾数只能保留 23 位（加隐藏位共 24 位有效位），多出来的位按「最近」舍入：
- 被舍部分＞一半 ⟹ 进 1；＜一半 ⟹ 舍去；恰好一半 ⟹ 舍入到使末位为 0 的那个（偶数）。
- 进 1 可能让尾数全 1 变成 10.0…0，要右规、阶码加 1；阶码因此到 255 就上溢成 ∞。
- 例：$2^{25}-1$（25 个 1）存成 float，第 25 位的 1 是被舍部分且后面全 0 ⟹ 恰好一半，24 位全 1 是奇数 ⟹ 进位 ⟹ 结果 $2^{25}$。

@kp 读者写者 | 读者—写者问题
多个进程共享一个数据：读读可以同时，读写、写写必须互斥。
- 读者优先写法：`count` 记读者数，`mutex` 保护 count，`rw` 保证读写互斥；第一个读者 P(rw)、最后一个读者 V(rw)。
- 写进 PV 题的判据：只有「至少一方要写」的两个进程之间，才对该变量需要互斥。

@kp 捎带确认 | 捎带确认
双向通信时，一方在发给对方的数据帧里顺便带上对已收到帧的确认号，不单独发确认帧。
- 确认号＝希望收到的下一帧序号（累积确认）：确认号 y 表示 $y$ 号以前的帧都已正确收到。
- 算信道利用率时，「确认帧」就是对方的数据帧，长度与数据帧相同 ⟹ $T_A=T_D$，不能当 0。
