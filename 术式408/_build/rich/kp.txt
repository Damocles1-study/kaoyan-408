@tpl T遍历建树 | 给两种遍历序列建树：先序/后序定根，中序分左右
1. 先序的第一个、后序的最后一个是根。
2. 在中序里找到根：左边全是左子树，右边全是右子树；按个数把先序/后序也切成两段，递归。
3. 只有先序＋后序 ⟹ 不能唯一确定（单孩子分不清左右）。
4. 森林、树的序列先翻译：森林先根＝二叉树先序，森林后根＝二叉树中序；树的先根＝二叉树先序，树的后根＝二叉树中序。

@tpl TB树插入 | m 阶 B 树插入：只往叶子插，满了取第 ⌈m/2⌉ 个上提
1. 每结点关键字数 ∈ [⌈m/2⌉−1, m−1]（根至少 1 个）。
2. 永远插在叶子；插后超过 m−1 个 ⟹ 分裂：第 ⌈m/2⌉ 个关键字上提到父结点，左右各成一个结点。
3. 父结点也可能连锁分裂；根分裂时树长高一层（B 树只从根长高）。
4. 草稿上每次分裂画一行，盯住「谁被挤上去」。

@kp 孩子兄弟 | 孩子兄弟表示法（树、森林 ⟷ 二叉树）
每个结点两个指针：左＝第一个孩子，右＝下一个兄弟。森林的各棵树的根互为兄弟。
- 森林先根 ＝ 二叉树先序；森林后根 ＝ 二叉树中序。
- 森林的叶子数 ＝ 二叉树中左指针为空的结点数。
- 森林的树棵数 ＝ 从二叉树根沿右链走过的结点数。

@tpl T压缩矩阵下标 | 特殊矩阵压缩存储求下标：只数「它前面有几个元素」
1. 先看给的元素在不在被存的那一半：对称矩阵给了下三角元素却存上三角 ⟹ 先换成 $m_{ji}$。
2. 再看按行还是按列：按列 ⟹ 先数前面整列有几个，再数本列里它排第几。
3. 最后看数组从 0 还是 1 起：前面有 $k$ 个 ⟹ 0 起下标 $k$，1 起下标 $k+1$。
4. 四个选项通常就是「行/列 × 0 起/1 起」四种组合，算完对一下哪种口径。

@tpl T出栈序列 | 给操作序列求出栈 / 判断出栈序列是否可能：草稿上画栈，一步一行
1. 给了 Push/Pop 序列 ⟹ 照做，每行写「栈底→栈顶」和已出栈的元素。
2. 判断某出栈序列可不可能 ⟹ 对每个要出的元素：在栈顶就弹；还没入栈就一直压到它；已入栈却不在栈顶 ⟹ 不可能。
3. $n$ 个元素合法出栈序列共 $\frac{1}{n+1}C_{2n}^{n}$ 个（卡特兰数）。

@tpl T顺序存储二叉树 | 二叉树顺序存储要多少单元：看最大编号，不看结点数
1. 顺序存储＝按满二叉树层序编号对号入座（根 1、左 $2i$、右 $2i+1$），空位也占坑。
2. 需要的单元数＝实际出现的最大编号。高度 $h$ 的最大编号最坏是 $2^h-1$（一路向右）。
3. 题干说「任意一棵」⟹ 按最坏 $2^h-1$；说「某一棵 / 至少」且形态可选 ⟹ 让最深的结点尽量靠左。

@tpl TBST序列 | 判断一个序列能否生成给定的二叉排序树：祖先必须先到
1. 序列能生成这棵 BST ⟺ 树中每个结点都排在它所有子孙之前。
2. 只需看每个结点和它的孩子：父亲晚到 ⟹ 孩子先占了父亲的位置 ⟹ 树形变了。
3. 兄弟之间、不同子树之间先后随意；合法序列个数＝拓扑序个数。

@tpl TDFS输出位置 | DFS 递归里「输出语句放在哪」决定得到什么序列
1. 进入递归时输出 ⟹ DFS 序列。
2. 退出递归前输出 ⟹ 每条弧 $u\to v$ 都是 $v$ 先出 ⟹ 逆拓扑序列（有向无环图）。
3. 退出前压栈、最后全部弹出 ⟹ 拓扑序列。
4. 先画一张 3 个点的小 DAG（1→2，1→3，2→3）手跑一遍，比背结论稳。

@tpl TMST过程 | 问 Kruskal / Prim 的加边顺序：列边表，一条条试
1. Kruskal：所有边按权从小到大排好，依次试，两端已连通（成环）就跳过，选够 $n-1$ 条停。
2. Prim：从指定起点出发，每次在「一端在树里、一端不在」的边里挑最小的。
3. 自检：Kruskal 的选边权值必须非递减；边数必须 $n-1$。选项里常有一个是另一种算法的顺序。

@tpl T关键路径判断 | 关键路径的概念判断：长度看权值和；延长必延期，缩短不一定
1. 关键路径＝源点到汇点权值和最大的路径，长度＝最短工期（不是边数最多）。
2. 延长任一关键活动 ⟹ 工期一定延长。
3. 缩短关键活动不一定缩短工期：有多条关键路径时要缩所有关键路径共有的活动；压过头关键路径会转移。

@tpl T堆性质 | 堆的判断题：堆只管纵向（父子），不管横向（兄弟）
1. 堆＝完全二叉树＋父 ≥ 子（大根堆），所以顺序存储、不是二叉排序树。
2. 每棵子树也是堆 ⟹ 次大值在下标 2 或 3；第 $k$ 大只能确定在前 $k$ 层内。
3. 最小值（大根堆）在叶子里，即下标 $\lfloor n/2\rfloor+1\sim n$。

@tpl T排序特性对比 | 比较几种排序「谁的比较/移动更少、与初态有没有关」：拿极端输入试
1. 拿「已有序」「逆序」两种输入各算一遍比较次数和移动次数。
2. 简单选择：比较恒 $n(n-1)/2$，与初态无关；移动 $\le 3(n-1)$，是最少的一类。
3. 直接插入：有序时比较 $n-1$、移动 0；一般情况移动次数＝逆序对数，可达 $O(n^2)$。
4. 空间：除快排 $O(\log n)$、归并 $O(n)$、基数 $O(r)$ 外都是 $O(1)$。

@kp 压缩存储 | 对称矩阵的压缩存储
$n$ 阶对称矩阵 $m_{ij}=m_{ji}$，只存一个三角（含对角线）共 $\frac{n(n+1)}{2}$ 个元素到一维数组。
- 上三角按列优先存，第 $j$ 列有 $j$ 个元素；$m_{ij}$（$i\le j$）前面有 $\frac{(j-1)j}{2}+(i-1)$ 个。
- 上三角按列优先 ≡ 下三角按行优先（转置一下就是同一个顺序）。
- 例：$n=10$，$m_{2,7}$ 前面有 $21+1=22$ 个 ⟹ 0 起下标 22。

@kp 卡特兰数 | 出栈序列个数（卡特兰数）
$n$ 个不同元素依次入栈，可能的出栈序列共 $\frac{1}{n+1}C_{2n}^{n}$ 个。
- $n=3$ 时 5 个，$n=4$ 时 14 个，$n=5$ 时 42 个。
- 同一个数也是 $n$ 个结点二叉树的形态数。

@kp 拓扑序 | 拓扑序列与逆拓扑序列
有向无环图（DAG）里，把顶点排成一列，使每条弧 $u\to v$ 都满足 $u$ 在 $v$ 前面，就是拓扑序列；倒过来（$v$ 在 $u$ 前）是逆拓扑序列。
- 有环 ⟺ 不存在拓扑序。
- 求法：反复删入度为 0 的点（Kahn）；或 DFS 按退出时间从大到小排。
- 例：1→2、1→3、2→3 的拓扑序只有 1,2,3。

@kp Kruskal | Kruskal 与 Prim
两个求最小生成树的贪心算法。
- Kruskal：边按权升序逐条加，成环则跳过；用并查集判环；$O(e\log e)$，适合稀疏图。
- Prim：从一个顶点长树，每次加「树内到树外」最轻的边；$O(n^2)$，适合稠密图。
- 边权互不相同 ⟹ MST 唯一（但两种算法的加边顺序一般不同）。

@kp 关键路径 | AOE 网与关键路径
AOE 网：顶点是事件、边是活动、边权是活动时间。
- 关键路径＝源点到汇点权值和最长的路径；它的长度＝完成工程的最短时间。
- 关键活动：最早开始 $e$＝最迟开始 $l$ 的活动（余量 0）。
- 延长关键活动必延长工期；缩短不一定缩短（多条关键路径、或缩过头关键路径转移）。

@kp 堆 | 堆（大根堆 / 小根堆）
完全二叉树，且每个结点 ≥（大根堆）它的孩子。顺序存储在数组 $A[1..n]$ 里，$A[i]$ 的孩子是 $A[2i]$、$A[2i+1]$。
- 只约束父子，不约束兄弟 ⟹ 不是二叉排序树。
- 建堆 $O(n)$，插入、删堆顶 $O(\log n)$；堆排序不稳定。
- 例：9(8(5,6),7) 是合法大根堆，中序 5,8,6,9,7 无序。

@tpl T部件位数 | 问「某部件的位数一定等于什么」：先问它装的是什么
1. 装整数数据、直连 ALU（ALU、通用寄存器）⟹ 机器字长。
2. 装指令（IR）⟹ 指令字长；装存储单元内容（MDR）⟹ 存储字长。
3. 装地址（MAR、PC）⟹ 地址位数；浮点寄存器 ⟹ 浮点格式宽度（常 64、80 位）。

@tpl T位模式多解 | 给一串机器数问「它的值可能是」：每种类型各读一遍
1. 先写成二进制，按题目允许的类型（int 补码 / unsigned / float / short…）各算一个值。
2. 补码负数快算：机器数 − $2^{n}$；看到连续 $k$ 个 1 想到 $2^k-1$。
3. float：符号 1 位、阶码 8 位减 127、尾数前补隐藏位 1。
4. 选项通常只给其中一种解释的值，算出一个不在选项里就换另一种。

@tpl T对齐小端 | 结构体成员的某个字节在哪个地址：先对齐算起点，再按小端拆字节
1. 对齐：每个成员的偏移是自身大小的整数倍，不够就填充；结构体总长补到最大成员的整数倍。
2. 小端：最低有效字节放最低地址。把机器数按「高→低」写一行，整行倒过来，从成员起点逐格对。
3. 大端（网络字节序）就不倒。四个选项常是「对齐/不对齐 × 大端/小端」。

@tpl T指令格式位数 | 定长指令字的字段位数：⌈log₂ 个数⌉ 后做减法，再看问的是哪种寻址
1. 操作码 $\lceil\log_2(\text{指令条数})\rceil$，寻址特征 $\lceil\log_2(\text{寻址方式数})\rceil$，剩下的是地址码。
2. 直接寻址给的是主存地址 ⟹ 无符号 $0\sim2^n-1$。
3. 相对寻址给的是偏移量、立即数常为补码 ⟹ $-2^{n-1}\sim2^{n-1}-1$。
4. 题干说「扩展操作码」时不能直接做减法，要逐级算编码空间。

@tpl TCPI对照 | 比较几种 CPU 结构的 CPI / 性能：数「一个时钟周期完成几条指令」，再乘时钟周期
1. 单周期 CPI＝1（周期最长）；多周期 CPI＞1；基本流水线理想 CPI＝1；超标量 CPI＜1；超流水线 CPI＝1 但周期更短。
2. 「理想情况」才成立；有冒险、阻塞、Cache 缺失时实际 CPI 变大。
3. 比性能一律回到 CPU 时间＝指令数 × CPI × 时钟周期，三个因子缺一不可。

@tpl T中断三分 | 判断一个事件是外中断、故障还是自陷：看谁触发、回到哪条
1. 和正在执行的指令无关、来自 CPU 外部（定时器、I/O 完成、网卡）⟹ 外中断，回下一条。
2. 指令执行中出错（缺页、除零、越界）⟹ 故障，回本条重新执行。
3. 执行一条陷阱指令主动进入（系统调用、断点 int3、单步 TF）⟹ 自陷，回下一条。
4. 可屏蔽中断要「请求 ＋ 开中断且未屏蔽 ＋ 指令执行完」三关全过才响应。

@tpl T带宽口径 | 总线带宽：每秒传几次 × 每次几字节有效数据 × 几个方向
1. 每秒传送次数＝时钟频率 × 每周期传几次；题干直接给 MT/s（工作频率）就不能再乘。
2. 每次的字节数只算有效数据（校验位不算），除非题干另说。
3. 全双工两个方向同时传 ⟹ 再 ×2。
4. 带宽不看事务时序；「有效数据传输率」才用数据量 ÷ 事务总时间。

@tpl TDMA方式 | DMA 题：先分清是哪种访存冲突方式，再数总线请求次数
1. 停止 CPU 访存：整块期间 CPU 不能访存。
2. 周期挪用：每传一个字挪一个存储周期、传完立即还总线，CPU 在字与字之间照样访存。
3. 交替访存：CPU 周期劈成两半，CPU 完全不受影响。
4. 总线请求次数＝数据块大小 ÷ 缓冲寄存器宽度；整块传完只发 1 次「DMA 结束」中断。

@tpl T存储层次对照 | Cache / TLB / 主存 / 磁盘的判断题：列「存什么、用什么做、缺失找谁、谁来处理」四行
1. Cache 存主存数据块；TLB 存页表项；两者都用 SRAM、都靠局部性。
2. 缺失去哪：Cache、TLB 缺失都去主存；缺页才去磁盘。
3. 谁处理：Cache 缺失只能硬件；TLB 缺失硬件或软件；缺页只能 OS。
4. 命中组合：TLB 命中则页一定在内存；TLB 缺失、页命中、Cache 缺失都可能。

@kp 机器字长 | 机器字长
CPU 内部用于**整数运算**的数据通路宽度＝ALU 位数＝通用寄存器位数。
- 指令字长（IR 的位数）、存储字长（MDR 的位数）可以与它不同。
- 浮点寄存器走浮点通路，宽度由浮点格式决定（32 位机的双精度寄存器是 64 位）。

@kp IEEE754 | IEEE 754 单精度浮点数
32 位＝符号 1 位 ＋ 阶码 8 位（移码，偏置 127）＋ 尾数 23 位（前面隐含一个 1）。
- 值 $=(-1)^s\times1.f\times2^{e-127}$（$e$ 为 1～254 时）。
- 例：C800 0000H：$s=1$，$e=1001\,0000_2=144$，$f=0$ ⟹ $-1.0\times2^{17}$。

@kp 补码真值 | 补码机器数的真值
$n$ 位补码，最高位为 1 时是负数，真值＝机器数（当无符号读）$-2^n$。
- 例：32 位 C800 0000H ＝ 3355443200，减 $2^{32}$ 得 $-939524096=-7\times2^{27}$。
- 也可「数值位取反加 1 再加负号」，两种方法互相验算。

@kp 边界对齐 | 边界对齐
每个基本类型的数据，地址必须是自身长度的整数倍（short 2、int 4、double 8）。
- 结构体成员按声明顺序放，前一个成员末尾到下一个成员的对齐位置之间填充空字节。
- 结构体总长补到最大成员长度的整数倍（数组里下一个元素也能对齐）。

@kp 小端 | 大端与小端
一个多字节数在内存里的字节顺序。
- 小端：最低有效字节（LSB）放在最低地址（x86）。
- 大端：最高有效字节（MSB）放在最低地址（网络字节序）。
- 例：1234 0000H 小端存于 FE04H 起：00 00 34 12。

@kp TLB | TLB（快表）
存放最近用过的页表项的高速缓存，用 SRAM 做，通常全相联或组相联。
- 命中：直接得到物理页框号；缺失：去主存的页表取页表项（硬件或软件处理均可）。
- 它缓存的是「地址映射」，Cache 缓存的是「数据块」；两者都靠局部性起效。

@kp 寻址方式 | 直接、间接、立即、相对寻址
- 直接：$EA=A$（形式地址就是主存地址，无符号）。
- 间接：$EA=(A)$，再访存一次取地址。
- 立即：操作数就是 $A$ 本身（常为补码）。
- 相对：$EA=(PC)+A$，$A$ 是补码偏移，可前可后。

@kp CPI | CPI
执行一条指令平均需要的时钟周期数。CPU 时间＝指令条数 × CPI × 时钟周期。
- 单周期 CPU：CPI＝1，但时钟周期按最慢的指令定，很长。
- 多周期：CPI＞1；基本流水线（理想）：CPI＝1；超标量：CPI＜1。

@kp 自陷 | 自陷（陷阱，Trap）
执行陷阱指令时主动触发的**内部异常**，属于事先安排好的「有意」异常。
- 用途：系统调用、程序调试的断点（int3）与单步（TF＝1）。
- 处理完回到陷阱指令的**下一条**；对比故障（如缺页）回到本条重新执行。

@kp NMI | 不可屏蔽中断 NMI 与可屏蔽中断 INTR
外中断经两根线进 CPU：INTR（可屏蔽）、NMI（不可屏蔽）。
- NMI：关中断（IF＝0）也响应，优先级最高，用于掉电、硬件故障等紧急事件。
- INTR：要开中断、未被屏蔽字屏蔽、当前指令执行完才响应。
- 屏蔽字能改变的是**处理**优先级，**响应**优先级由硬件排队线路固定。

@kp 周期挪用 | DMA 的周期挪用
DMA 控制器每传送一个数据字，向 CPU 申请（挪用）一个存储周期，传完立即释放总线。
- 一个数据块被拆成很多次单字传送，每次都要发总线请求。
- CPU 在两次挪用之间照样访存；DMA 的总线优先级高于 CPU（I/O 数据不等人）。

@tpl T打开文件表 | 多进程打开同一文件：系统表一份（带计数），用户表各一份
1. 系统打开文件表全系统一张，一个文件只占一项，含打开计数和文件属性（FCB/inode 副本）。
2. 每个进程有自己的用户打开文件表：读写指针、打开方式、权限各自不同，表项指向系统表项。
3. open 已打开的文件 ⟹ 计数 +1；close ⟹ 计数 −1，减到 0 才删系统表项。
4. OS 不保证多个写者互斥，要互斥得进程自己加锁（读者-写者）。

@tpl T文件分配方式 | 选磁盘分配方式：随机访问 + 可变长 ⟹ 索引
1. 连续：随机访问快，但难扩展、有外部碎片。
2. 隐式链接：易扩展，只能顺序访问；显式链接（FAT）：可随机访问，但 FAT 要常驻内存。
3. 索引：随机访问 ✓、可变长 ✓、无外部碎片，代价是索引块。
4. 选项里混进内存管理术语（动态分区、分页）直接划掉。

@tpl T中断分工 | 中断处理里「谁做的」：硬件三件事，其余都是 OS
1. 硬件（中断隐指令）：关中断、保存断点（PC、PSW）、取中断向量跳到服务程序。
2. OS（服务程序）：保存屏蔽字和通用寄存器、提供服务、恢复现场、开中断、中断返回。
3. OS（开机引导时）：建立并初始化中断向量表——不在中断发生时做。

@tpl T调度算法要素 | 问某调度算法「要考虑 / 会不会饥饿 / 是否抢占」：先把它的规则用一句话说全
1. 多级反馈队列四个参数：队列数、各队列优先级、各队列内算法、迁移条件。
2. 会饥饿的：短作业优先、静态优先级（非老化）、多级反馈队列；不会饥饿的：FCFS、RR、高响应比优先。
3. 是否抢占看规则里有没有「来了更高优先级就打断」。

@tpl T银行家安全性 | 银行家算法表格题：先算 Need 和 Available，再用 Work 推进
1. 表头若给「最大需求 / 需求总量」，先算 Need＝Max − Allocation。
2. Available＝资源总数 − 各进程已分配之和；先看哪一列已被分光（Available 为 0），起手只能推 Need 那一列为 0 的进程。
3. 推进：找 Need ≤ Work 的进程，完成后 Work += 它的 **Allocation**（不是 Max），直到全部完成或卡住。
4. 选项给了几个序列时，逐个代入验证即可；问「是否安全」只要找到一个序列。

@tpl TEAT公式 | 有效访存时间：按「命中 / 缺失」加权平均，缺失那一支把处理全过程写出来
1. EAT＝(1−p)×访存时间＋p×(缺页处理时间＋访存时间)。
2. 缺页处理时间＝CPU 处理缺页中断的时间＋（换出脏页）＋读入新页的磁盘时间。
3. 有 TLB 时再套一层：TLB 命中 / TLB 缺失页表命中 / 缺页三支。

@tpl T父子进程线程 | 谁和谁共享什么：同一进程的线程共享地址空间；父子是两个进程
1. 父子进程：各有 PCB、各有虚拟地址空间（fork 复制一份）、可并发；可共享已打开文件等部分资源。
2. 同一进程的线程：共享地址空间、全局变量、打开文件；不共享栈、寄存器、PC。
3. 临界资源对任何两个进程都要互斥使用，父子没有特权。

@tpl T设备层次 | I/O 软件题：先把四层画出来，再问「这件事归哪层」
1. 用户层 I/O 软件 → 设备独立性软件 → 设备驱动程序 → 中断处理程序 → 硬件。
2. 逻辑名到物理名的映射（LUT）、缓冲、设备分配、出错处理：设备独立性软件。
3. 把抽象命令翻译成设备操作、直接操作控制器寄存器：驱动程序（换设备就换它）。
4. 换物理设备：改映射、换驱动，应用程序不改。

@tpl T文件数上限 | 文件系统「最多多少个文件 / 单个文件最大多长」：先分清问的是数量还是大小
1. 文件数量上限 ⟹ 看全局唯一的编号：inode 号（或 FCB 号）有几位，或 inode 区能放多少个 inode。
2. 文件名在不同目录下可以重名，不构成上限。
3. 单个文件最大长度 ⟹ 看 inode 里直接、间接地址项的个数和块大小。

@tpl T互斥四准则 | 互斥机制的四条准则：前三条管正确性（必须），让权等待管效率（可不满足）
1. 空闲让进、忙则等待、有限等待：必须满足。
2. 让权等待：进不去时放弃 CPU，只影响效率；Peterson、TSL、Swap 都不满足它，但仍是正确的互斥方法。
3. 判断某个软件算法违反哪条：单标志违反空闲让进；双标志先检查违反忙则等待；双标志后检查违反空闲让进与有限等待。

@kp 打开文件表 | 系统打开文件表与用户打开文件表
- 系统打开文件表：整个系统一张，每个被打开的文件一项，含文件属性和打开计数。
- 用户（进程）打开文件表：每个进程一张，每项含读写指针、打开方式，并指向系统表项；open 返回的文件描述符就是它的下标。
- close：用户表项删除，系统表项计数减 1，减到 0 才删除。

@kp 索引分配 | 索引分配
每个文件一个索引块，按逻辑块号顺序存放各物理块号；FCB 里只记索引块的位置。
- 随机访问：第 $i$ 块直接查索引第 $i$ 项。
- 文件变长：往索引里加项即可；大文件用多级索引或混合索引。
- 无外部碎片；代价是索引块本身占空间。

@kp 中断向量表 | 中断向量表
存放各中断服务程序入口地址的表（数组），下标就是中断类型号。
- 由操作系统在初始化（开机引导）时建立并填写。
- 中断发生时，硬件按中断类型号查表、取入口地址并跳转。

@kp 多级反馈队列 | 多级反馈队列调度
设多个就绪队列，优先级逐级降低、时间片逐级加长；新进程进第一级，时间片用完未完成就降到下一级；上一级空了才调度下一级。
- 设计时要定：队列个数、各队列优先级、各队列的调度算法、进程在队列间迁移的条件。
- 兼顾短进程（响应快）与长进程（不会一直轮不到——除非一直有新进程进来，可能饥饿）。

@kp 银行家算法 | 银行家算法与安全性算法
- 数据结构：Available、Max、Allocation、Need＝Max−Allocation。
- 安全性算法：Work＝Available；反复找 Need ≤ Work 的未完成进程，令它完成并 Work += Allocation；全部能完成 ⟹ 安全，得到的顺序是安全序列。
- 请求算法：Request ≤ Need、Request ≤ Available 后试分配，再跑安全性算法，不安全就撤销、让进程等待。
- 不安全 ≠ 死锁。

@kp EAT | 请求分页的有效访存时间
EAT＝(1−p)·t＋p·(缺页处理时间＋t)，$p$ 是缺页率，$t$ 是一次访存时间。
- 缺页处理时间包括：缺页中断的 CPU 处理时间、换出与读入页面的磁盘时间等，通常是毫秒级，比 $t$（纳秒级）大 $10^5$ 倍以上。
- 例：$t=100$ns、处理 8ms、$p=10^{-5}$ ⟹ EAT≈100ns＋80ns＝180ns。

@kp fork | 父进程与子进程
父进程用 fork 创建子进程：子进程获得父进程地址空间的一份副本、自己的 PCB 和 PID。
- 两者是独立的进程，可以并发执行，虚拟地址空间不共享（写时复制只是物理层面的优化）。
- 子进程继承父进程已打开的文件，可以共享这些文件。

@kp 设备独立性 | 设备独立性
应用程序使用逻辑设备名，与实际使用的物理设备无关；系统通过逻辑设备表（LUT）把逻辑设备映射到物理设备及其驱动。
- 换物理设备：只改映射关系、换驱动程序，应用程序不用改。
- UNIX 把设备当作特殊文件（/dev 下），用文件名就能访问设备。

@kp inode | 索引节点（inode）与目录项
UNIX 类文件系统把文件说明分成两部分：目录项只存「文件名 ＋ inode 号」，其余属性和地址信息放在 inode 里。
- inode 号全系统唯一，每个文件一个 inode；文件名在不同目录下可以相同。
- 好处：目录项变短，查目录时读盘次数少；硬链接＝多个目录项指向同一 inode。

@kp 互斥准则 | 临界区互斥的四条准则
- 空闲让进：临界区空闲时，允许一个请求进入的进程立即进入。
- 忙则等待：已有进程在临界区时，其他进程必须等待。
- 有限等待：请求进入的进程要在有限时间内进入（不饥饿）。
- 让权等待：进不去时立即释放处理器（不忙等）——不是必须的。

@tpl T协议三要素 | 看图/看描述判协议要素：只认实际画出来的东西
1. 字段、位数、格式框 ⟹ 语法。
2. 「收到 X 就做 Y」、字段的含义、出错怎么办 ⟹ 语义。
3. 时间轴、往返箭头、先后顺序 ⟹ 时序（同步）。

@tpl T交换方式对比 | 电路交换 / 虚电路 / 数据报：先问「建的是物理通路还是逻辑连接」
1. 电路交换：建立物理通路，预留带宽、独占，无存储转发、无排队。
2. 虚电路：建立逻辑连接，只在建立时选一次路由，之后按 VC 号转发、按序到达；链路统计复用，不预留带宽、有存储转发。
3. 数据报：不建连接，每个分组独立选路、可能乱序（IP）。

@tpl T冲突域广播域 | 数冲突域与广播域：从每台设备的端口往下看
1. 广播域：只有路由器（三层）能隔开 ⟹ 广播域数＝路由器接口所连的网段数。
2. 冲突域：交换机、路由器的每个端口各隔开一个；端口下若挂集线器，集线器连同它下面的主机合成一个冲突域。
3. 集线器、中继器什么都不隔。

@tpl T停等利用率 | 停等 / 滑动窗口利用率：先画一个发送周期，再看分子
1. 一个周期 $T$＝数据帧发送 $T_D$＋传播 $\tau$＋确认帧发送 $T_A$＋传播 $\tau$；题目说「忽略确认帧」才令 $T_A=0$。
2. 停等 $U=T_D/T$；窗口为 $W$ 时 $U=\min(1, W\cdot T_D/T)$。
3. 选项常是漏掉某一项的口径，算出四种分母对一下。

@tpl TIFS判定 | 802.11 帧间间隔：新的接入用 DIFS，同一次对话里的后续帧用 SIFS
1. 站点想发起一次新的传输（RTS，或不用 RTS 时的 DATA）：先等 DIFS（最长）。
2. CTS、跟在 CTS 后的 DATA、ACK：都只等 SIFS（最短），别人插不进来。
3. 长短只看紧跟其后的帧类型，与是谁发的无关。

@tpl T拥塞窗口 | 拥塞窗口变化题：逐 RTT 列 cwnd，问「最短/最长」时自己挑 ssthresh
1. 慢开始：cwnd < ssthresh 时每 RTT 翻倍（不超过 ssthresh）；拥塞避免：每 RTT +1 MSS。
2. 超时：ssthresh＝cwnd/2，cwnd＝1；3 个冗余 ACK：ssthresh＝cwnd/2，cwnd＝ssthresh 后线性。
3. 问「最短时间」⟹ 让它一直指数增长；问「最长时间」⟹ 把 ssthresh 设成 ≤ 起点，全程线性。
4. 最后别忘了乘 RTT 的具体时间。

@tpl TTCP序号 | TCP 序号计数：SYN、FIN 各占一个序号，纯 ACK 不占
1. 数据从 SYN 的 seq＋1 开始编号。
2. FIN 的 seq＝最后一个数据字节的序号＋1。
3. 数据字节数＝FIN.seq − SYN.seq − 1；确认号＝期望收到的下一个序号。
4. 先圈出题目给的 seq 属于哪个报文段（SYN？FIN？第几次挥手？）。

@tpl TRTT账本 | 「从点击到收到页面」这类时间题：DNS 几个 RTT ＋ TCP 握手 ＋ 取对象
1. 圈出时延可忽略的那一跳（如主机到本地域名服务器在同一局域网）。
2. DNS：有缓存 0；本地域名服务器迭代查询根、顶级、权限服务器各 1 RTT。
3. 取一个对象：握手 1 RTT（第三次握手捎带请求）＋请求响应 1 RTT＝2 RTT。
4. 多个对象按持续/非持续、流水线/非流水线再记账；「最短/最长」分别对应全命中缓存与全迭代。

@kp 协议三要素 | 网络协议三要素
- 语法：数据与控制信息的格式（字段、长度、编码）。
- 语义：各控制信息的含义、要做出的动作和响应。
- 同步（时序）：事件发生的先后顺序、速度匹配。
例：TCP 首部格式图是语法；「收到 SYN 回 SYN+ACK」是语义；三次握手的时间顺序图是时序。

@kp 虚电路 | 虚电路
分组交换的一种连接方式：通信前建立一条逻辑连接（虚电路），建立时做一次路由选择，各结点记下「入 VC 号 → 出端口、出 VC 号」。
- 之后的分组只带短的虚电路号，沿同一路径按序到达。
- 「虚」：链路不是专用的，多条虚电路统计复用同一链路，不预留带宽。
- 某结点故障 ⟹ 经过它的虚电路全部断开。

@kp 冲突域 | 冲突域与广播域
- 冲突域：同一时刻只能有一台设备发送、否则会冲突的范围；集线器连起来的都在一个冲突域里。
- 广播域：一个广播帧能到达的范围；交换机转发广播，只有路由器（或 VLAN）隔离广播。
- 例：路由器两个接口各接一台交换机 ⟹ 2 个广播域。

@kp 停等协议 | 停止-等待协议的信道利用率
发送一帧后等确认，收到确认才发下一帧。一个发送周期 $T=T_D+\tau+T_A+\tau$。
- 利用率 $U=T_D/T$（只有发数据帧那段时间信道在「有效」工作）。
- 例：$T_D=800$ms、$\tau=200$ms、$T_A=800$ms ⟹ $U=800/2000=40\%$。

@kp IFS | 802.11 的帧间间隔
- SIFS（短帧间间隔）：最短，用于 CTS、ACK 以及收到 CTS 后发的数据帧——同一次对话里的后续帧。
- DIFS（分布协调功能帧间间隔）：最长，站点要发起新的传输前等待。
- 时长 SIFS < PIFS < DIFS，越短优先级越高。

@kp 拥塞控制 | TCP 拥塞控制四算法
- 慢开始：cwnd 从 1 起每 RTT 翻倍，到 ssthresh 为止。
- 拥塞避免：cwnd ≥ ssthresh 后每 RTT 加 1 MSS。
- 超时：ssthresh＝cwnd/2，cwnd＝1，重新慢开始。
- 快重传＋快恢复：收到 3 个冗余 ACK 立即重传，ssthresh＝cwnd/2，cwnd＝ssthresh，进入拥塞避免。
- 发送窗口＝min(rwnd, cwnd)。

@kp TCP序号 | TCP 序号与确认号
- 序号（seq）：本报文段数据第一个字节的编号。确认号（ack）：期望收到对方下一个字节的编号。
- SYN、FIN 虽不带数据，各消耗一个序号；纯 ACK 不消耗。
- 例：SYN seq＝1000，数据从 1001 开始；发了 4000B 后 FIN 的 seq＝5001，对方确认 FIN 的 ack＝5002。

@kp DNS查询 | DNS 递归查询与迭代查询
- 递归查询：被问的服务器替你把答案查到再返回（主机 → 本地域名服务器通常是递归）。
- 迭代查询：被问的服务器只告诉你「下一个去问谁」，由你再去问（本地域名服务器 → 根、顶级、权限服务器通常是迭代）。
- 本地域名服务器完整迭代一次：根 → 顶级域 → 权限域名服务器，各 1 个 RTT。

@tpl T多指针有序 | 几个升序数组里各取一个、求某个「最优组合」：每个数组一个指针，每轮只动最小的那个
1. 先把目标写成「最大值 − 最小值」之类的形式，看清动哪个指针才可能变好。
2. 每轮算一次当前组合、更新答案，然后把最小元素所在数组的指针后移（谁小谁走）。
3. 任一指针走到头就停：时间 $O(n_1+n_2+\dots)$，空间 $O(1)$。
4. 卷面：基本设计思想 → C 代码（带注释）→ 时空复杂度；暴力三重循环只能拿一部分分。

@tpl T前缀码树 | 前缀码 / 编码判定 / 译码：都用一棵 0 左 1 右的二叉树
1. 存：每个字符是一个叶子，编码是根到叶子的路径。前缀特性 ⟺ 字符全在叶子上。
2. 译：从根出发读一位走一步，到叶子输出字符、回到根。
3. 判：边插边查——途经已有的叶子（别人是我的前缀）或一个新结点都没建（我是别人的前缀）⟹ 不是前缀码。

@tpl T乘法溢出 | n 位乘法取低 n 位：无符号看高 n 位全 0，有符号看高 n+1 位全同
1. 先用真值算出 2n 位乘积，写成十六进制，分出高 n 位、低 n 位。
2. 无符号：高 n 位全 0 ⟹ 不溢出。
3. 有符号：高 n 位与低 n 位的最高位，共 n+1 位全 0 或全 1 ⟹ 不溢出。
4. 也可直接比真值是否落在类型范围内，两种判法互相验算。

@tpl TCache地址划分 | Cache 题第一步：把主存地址切成「标记 | 组号（行号）| 块内地址」
1. 块内地址位数＝$\log_2$ 块大小；组数＝Cache 容量 ÷（块大小 × 路数），组号位数＝$\log_2$ 组数。
2. 标记位数＝地址位数 − 组号 − 块内地址。
3. 每行附加位：有效位 1；LRU 位 $\log_2$ 路数（2 路 1 位、4 路 2 位、8 路 3 位）；回写才有修改位，直写没有。
4. 给具体地址就把十六进制写成二进制，按位数切三段。

@tpl T数组遍历局部性 | 数组遍历的缺失 / 缺页次数：先算「一块（一页）装几个元素」
1. 一块装 $k$ 个元素；顺序访问时每块只第一次缺失。
2. 先查首地址是否块（页）对齐：不对齐会多跨一块。
3. 每个元素访问几次（读 1 次＋写 1 次？）决定访问总数，但缺失次数仍按块数算。
4. 按列遍历行优先数组：步长 ＝ 一行的字节数，常常每次都换块（页）。

@tpl T前驱图PV | 前驱关系用信号量实现：一条边一个信号量，初值 0；边的起点做完 V，终点开始前 P
1. 先把文字画成前驱图，数边。
2. 每条边 $X\to Y$ 设信号量 $S_{XY}=0$：$X$ 末尾 V($S_{XY}$)，$Y$ 开头 P($S_{XY}$)。
3. 校验：几条边就有几个信号量、几个 P、几个 V。
4. 同一线程内部的先后由程序顺序保证，不用信号量（2022 年那题只用 2 个）。

@tpl T多级页表地址 | 二级页表求各种地址：拆位 + 「表项地址＝表起址＋序号×表项长」
1. 先求虚拟地址（数组元素：首地址＋偏移；能整行整页地数更好）。
2. 写成二进制按位数切：页目录号 | 页号 | 页内偏移。
3. 页目录项地址＝页目录起址＋页目录号 × 项长；页表项地址＝页表起址（页框号 × 页大小）＋页号 × 项长。
4. 页框号不是地址：页框号后面补上页内偏移的位数（4KB 页就是十六进制补三个 0）。

@tpl TNAT改址 | NAT 题：出站改源、入站改目的；外面要主动访问里面，就得配静态映射
1. 分组从内网出去经过 NAT：源地址（和源端口）改成 NAT 的外网地址。
2. 分组从外网进来经过 NAT：目的地址（和端口）按 NAT 表改成内网主机的地址。
3. 内网服务器要被外部主动访问 ⟹ 事先在它那侧的 NAT 上配静态映射（外网 IP:端口 ↔ 内网 IP:端口）；客户端那侧由出站分组自动建表。
4. 两个私网可能用同一网段，草稿上标清「哪一边的」。

@kp 前缀码 | 前缀码
任何一个字符的编码都不是另一个字符编码的前缀。这样的 0/1 串可以从左到右唯一译码，不需要分隔符。
- 用二叉树表示：左分支 0、右分支 1，字符放在叶子上 ⟺ 前缀码。
- 哈夫曼编码就是带权路径长度最小的前缀码。
- 例：{0, 10, 110, 111} 是前缀码；{0, 01} 不是（0 是 01 的前缀）。

@kp 组相联 | 组相联映射
Cache 分成若干组，每组 $r$ 行（$r$ 路组相联）；主存块按「块号 mod 组数」映射到某一组，可放在组内任意一行。
- 地址划分：标记 | 组号 | 块内地址。
- 查找：用组号选组，组内 $r$ 个比较器并行比较标记（且有效位为 1）。
- 1 路即直接映射，路数＝总行数即全相联。

@kp 直写回写 | 直写法与回写法
- 直写（全写）：写命中时同时写 Cache 和主存，Cache 与主存始终一致 ⟹ 不需要修改位（脏位）。
- 回写：只写 Cache，块被替换时才写回主存 ⟹ 每行要一个修改位，标记它是否被改过。

@kp 二级页表 | 二级页表
32 位虚拟地址＝页目录号（10 位）| 页号（10 位）| 页内偏移（12 位），页大小 4KB，每张页表 1024 项正好占一页。
- 页目录项给出某张二级页表所在的页框号；页表项给出数据页的页框号。
- 只为用到的虚拟区域建二级页表，省内存；代价是多一次访存。

@kp NAT | 网络地址转换 NAT
让使用私有地址（如 192.168.0.0/16）的内网主机共用路由器的公网地址访问外网。
- NAPT 同时转换 IP 地址和端口号，转换表项形如「外网 IP:端口 ↔ 内网 IP:端口」。
- 出站分组改源地址，入站分组改目的地址；外部要主动访问内网服务器，须预先配置静态映射。

@kp 信号量同步 | 用信号量实现同步（前驱关系）
同步信号量初值 0，表示「前一件事还没做完」：
- 前驱操作做完后 V(S)；后继操作开始前 P(S)。
- P 在前驱完成之前会阻塞，于是后继一定晚于前驱。
- 互斥信号量初值 1，P、V 在同一进程里成对出现；同步信号量的 P、V 分在两个进程里。

@tpl T受限双端队列 | 受限双端队列判出队序列：画出「队里的排列」，再看能否按出口依次取
1. 先找第一个出队的元素 $x$：它出队时，入队序列里排在它前面的元素全都已经在队里。
2. 输出受限（两端进、一端出）：每个元素进来时只能贴在队的左端或右端 ⟹ 队里是「从第一个元素向两边长」的形状；出口只有一个，后面只能按这个排列依次出。
3. 输入受限（一端进、两端出）：队里的顺序就是入队顺序，只看能不能每次从两头之一取到下一个要的元素。
4. 4 个元素的经典结论：输出受限得不到 4,1,3,2 与 4,2,3,1；输入受限得不到 4,2,1,3 与 4,2,3,1。

@tpl T数组地址 | 数组元素地址：前面隔了几个元素 × 元素长度；给两个地址就反推维数
1. 行优先 $A[i][j]$（下标从 0）：地址 ＝ 首地址 ＋（$i\times$列数 ＋ $j$）× 元素长度；列优先把「行、列」对调。
2. 下标从 1 开始：先把 $i$、$j$ 各减 1 再套。
3. 给两个元素地址：地址差 ÷ 元素长度 ＝ 它们之间隔的元素个数，列出一次方程解出列数（行数）。

@tpl T哈夫曼 | 「最小 WPL / 最优编码」：构造哈夫曼树；WPL＝所有非叶结点权值之和
1. 每次从集合里取最小的两个合并，新权值放回集合，直到剩一个。
2. WPL 两种算法互相验算：叶子权 × 深度求和；或把每次合并得到的新权值全加起来。
3. 根的权值＝权值总和，不是 WPL。$n$ 个叶子 ⟹ 合并 $n-1$ 次、结点 $2n-1$ 个、没有度为 1 的结点。

@kp 哈夫曼树 | 哈夫曼树（最优二叉树）
给定 $n$ 个带权叶子，带权路径长度 $\mathrm{WPL}=\sum w_i\,l_i$ 最小的二叉树。
- 构造：反复合并权值最小的两棵树。结果不唯一（左右可换、权值相等时可选），但 WPL 唯一。
- 每次合并产生一个非叶结点，它的权值恰好被下面每个叶子各「算」一次 ⟹ WPL＝非叶结点权值之和。
- 例：{1,2,3} ⟹ 先合 1、2 得 3，再合 3、3 得 6 ⟹ WPL＝3＋6＝9＝1×2＋2×2＋3×1。

@tpl TAVL旋转 | AVL 插入后调平：找最低失衡点 A，看新结点在 A 的哪个孩子的哪棵子树
1. 从新结点往上逐个算平衡因子，第一个 |bf|＝2 的是 A（最小不平衡子树的根）。
2. 新结点在 A 的左孩子的左子树 ⟹ LL；右孩子的右子树 ⟹ RR；左孩子的右子树 ⟹ LR；右孩子的左子树 ⟹ RL。
3. 单旋（LL、RR）：A 的那个孩子 B 上位；双旋（LR、RL）：B 的那个孩子 C（「孙子」）上位，A、B 分站两边。
4. 选择题只问根是谁 ⟹ 判型后直接说出谁上位，不必真画旋转。

@kp AVL | 平衡二叉树（AVL）
二叉排序树，且每个结点左右子树高度差（平衡因子）的绝对值 ≤ 1。
- 插入后只需调整最低的那个失衡结点，调完整棵树就平衡了。
- 高度为 $h$ 的 AVL 至少有 $n_h$ 个结点：$n_1=1,n_2=2,n_h=n_{h-1}+n_{h-2}+1$（1、2、4、7、12、20…）。
- 例：依次插 1、2、3 ⟹ 1 失衡（RR）⟹ 2 上位，得 2(1,3)。

@tpl T拓扑计数 | 拓扑序列有几个：逐步删入度为 0 的点，盯住「每一步有几个候选」
1. 先列入度表。每一步只看此刻入度为 0 的顶点有几个。
2. 每一步都恰好 1 个 ⟺ 拓扑序列唯一。
3. 某一步出现 2 个候选：不能直接答 2，要沿每个分支继续数（后面的候选会受影响），点少时直接把序列写全。

@tpl TDijkstra表 | Dijkstra 按轮列 dist 表：每轮选未确定的最小值，再用它松弛邻居
1. 第 0 行写源点的直接出边（其余 ∞）。
2. 每一轮：圈出未确定顶点里 dist 最小的那个（它的最短路就此确定），再用它更新它的邻居：$d[v]=\min(d[v],d[u]+w)$。
3. 「求出第 $k$ 条最短路径后」＝第 $k$ 轮做完（含松弛）的那一行；问终值才做完所有轮。
4. 选项经常就是不同轮次的快照，数清轮数。

@kp Dijkstra | Dijkstra 算法
求单源最短路径（边权非负）。集合 S 放已确定最短路的顶点，每轮把 S 外 dist 最小的顶点加入 S，并用它松弛其余顶点。
- 时间 $O(n^2)$（邻接矩阵）；有负权边时可能出错（用 Bellman-Ford）。
- 加入 S 的次序就是最短路径长度从小到大的次序。
- 例：1→2 权 5、1→3 权 2、3→2 权 1 ⟹ 先定 3（2），再用 3 把 dist(2) 改成 3。

@tpl TB树结点数 | B 树结点数 / 关键字数的最多最少：一层一层数，「关键字数＋1＝孩子数」
1. $m$ 阶：每结点关键字 $[\lceil m/2\rceil-1,m-1]$（根 $[1,m-1]$），孩子数＝关键字数＋1。
2. 下一层的结点数＝上一层各结点的孩子数之和＝上一层关键字数＋上一层结点数。
3. 求结点最多：每层关键字摊成尽量多的结点（每个结点装得少）；求结点最少：装满。上一层的容量会限制这一层能有几个结点，要两头同时检查。

@kp B树 | B 树（多路平衡查找树）
$m$ 阶 B 树：每个结点最多 $m$ 棵子树、$m-1$ 个关键字；非根非叶结点至少 $\lceil m/2\rceil$ 棵子树；所有叶子在同一层。
- 结点内关键字有序，$k$ 个关键字把子树分成 $k+1$ 棵。
- 3 阶 B 树（2-3 树）：每结点 1～2 个关键字、2～3 个孩子。
- 例：3 阶、根有 2 个关键字 ⟹ 第 2 层恰有 3 个结点。

@tpl T基数排序一趟 | LSD 基数排序问某一趟的结果：只看相关的桶，桶内保持原来顺序
1. 第 1 趟按个位、第 2 趟按十位……；不足位数的高位补 0（9 的十位是 0）。
2. 分配：按原序列从左到右把元素放进对应桶的队尾（稳定）；收集：0 号桶到 9 号桶依次首尾相接。
3. 问某元素的前后邻居：先找它的桶，看桶内左右；在桶头/桶尾就去看相邻的非空桶的尾/头。

@kp 基数排序 | 基数排序（LSD）
不比较关键字，按位「分配 ＋ 收集」：从最低位到最高位各做一趟，每趟必须稳定。
- $d$ 位、基数 $r$：时间 $O(d(n+r))$，空间 $O(r)$（队列），稳定。
- 例：{21,12,11}：个位趟得 21,11,12；十位趟得 11,12,21。

@tpl T建堆两法 | 题目说「依次插入」还是「建堆」：前者 n 次向上调整，后者从 ⌊n/2⌋ 倒着向下筛
1. 依次插入：新元素放在末尾，和父亲比，大（大根堆）就交换，一直上浮；草稿上每插一个画一次。
2. 整体建堆（筛选法）：序列先原样放成完全二叉树，$i=\lfloor n/2\rfloor,\dots,1$ 逐个向下筛。
3. 两种方法结果通常不同，而且都是合法的堆 ⟹ 不能用「是不是堆」排除，必须按题目指定的方法走一遍。
4. 删堆顶：末尾元素放到根，向下筛。

// ───── 本年新建：组成原理 ─────

@kp 量级前缀 | 数量级前缀与中文数词
速率、频率、FLOPS 用 10 的幂：K $10^3$、M $10^6$、G $10^9$、T $10^{12}$、P $10^{15}$、E $10^{18}$，每级 ×1000。
- 中文：万 $10^4$、亿 $10^8$、万亿 $10^{12}$、千万亿 $10^{15}$、亿亿 $10^{16}$。
- 存储容量用 2 的幂：K $2^{10}$、M $2^{20}$、G $2^{30}$。
- 例：$93\ \mathrm{PFLOPS}=9.3\times10^{16}$ 次/秒 ＝ 9.3 亿亿次/秒。

@tpl T精确表示 | 十进制小数能否用二进制（IEEE 754）精确表示：化成最简分数，看分母是不是 2 的幂
1. 能写成 $k/2^n$ ⟺ 有限位二进制小数 ⟺（位数够时）能精确表示。
2. 小数部分出现 .1 .2 .3 .4 .6 .7 .8 .9 这类（分母含 5）一律不能；.5 .25 .75 .125 … 能。
3. 反过来，有限位二进制小数转十进制永远精确。

@tpl T芯片数 | 存储器扩展要几片芯片：总位数 ÷ 单片位数，先看清编址单位
1. 地址个数＝末地址 − 首地址 ＋ 1（十六进制直接算）。
2. 总位数＝地址个数 × 每个地址的位数（按字节编址乘 8，按字编址乘字长）。
3. 片数＝总位数 ÷（芯片字数 × 芯片位宽）；位扩展片数＝所需位宽 ÷ 芯片位宽，字扩展片数＝所需字数 ÷ 芯片字数。

@tpl T程序员可见 | 某寄存器对（汇编）程序员可见吗：汇编指令里能不能写出它、能不能用它
1. 可见：通用寄存器、PC、PSW/标志寄存器、基址/变址寄存器、栈指针 SP。
2. 不可见（透明）：IR、MAR、MDR、暂存寄存器、微程序控制器里的 μPC、μIR、CMAR、CMDR。
3. 「数据会经过它」≠「程序员能用它」。

@kp 数据通路 | 数据通路
指令执行过程中数据所经过的路径及路径上的部件：ALU、通用寄存器、状态寄存器、Cache、MMU、浮点运算逻辑、异常和中断处理逻辑等。
- 它由控制部件发出的控制信号控制；CPU＝数据通路 ＋ 控制器。
- 判据：数据（或地址、断点）是否从它身上流过。控制器输出的是控制信号，不是数据通路本身。

@kp 异步总线 | 同步总线与异步总线
- 同步：双方用同一时钟定时；一次总线事务可以占多个时钟周期（时钟频率 ≠ 工作频率）。
- 异步：用握手信号（请求 / 回答）定时，不需要统一时钟；一次握手完成一次数据交换，传的是一个总线宽度的数据。
- 突发传送：发一次地址后连续传多个数据。

@kp I/O接口 | I/O 接口（I/O 控制器）
主机和外设之间的部件：接收主机的 I/O 控制信号，完成数据缓冲、格式转换、状态登记、中断请求等。
- 名称里带「适配器、控制器、接口」的多半是它；可编程中断控制器、DMA 控制器、网卡控制逻辑都算。
- 磁盘驱动器、打印机本体是外设，不是接口。

@kp 中断响应条件 | CPU 响应中断的条件
① 有中断请求；② 该请求没被屏蔽（屏蔽位取反后与请求相「与」，被屏蔽的进不了判优电路）；③ CPU 处于开中断状态；④ 一条指令执行完毕（且没有更紧急的事）。
- 「CPU 检测到中断请求」本身就意味着请求未被屏蔽。
- 中断服务程序在内核态执行；多重中断就是在内核态里再响应新中断。

// ───── 本年新建：操作系统 ─────

@tpl T特权指令 | 判断哪条指令「只能在内核态执行」：它会不会影响别的进程或整个系统
1. 特权指令：I/O 指令、开/关中断、改 PSW、置时钟、改页表基址/存储保护寄存器、停机、切换执行状态。
2. 非特权：数据传送、算术逻辑、Trap（访管）指令、设置断点（int3）——它们在用户态执行，只是可能引发进入内核态。
3. 分界线：「会导致进内核」≠「只能在内核里执行」。

@kp 进程创建 | 进程创建原语
① 分配 PID、申请空白 PCB；② 分配除 CPU 以外的资源；③ 初始化 PCB（标识、CPU 状态、优先级等）；④ 插入就绪队列。
- 新进程是就绪态，「运行」要等调度程序。
- 引起创建的事件：用户登录、作业调度、系统提供服务、应用请求（fork）。

@kp 时钟中断 | 时钟中断与时间片轮转
定时器按固定频率发中断。时钟中断处理程序更新系统时间、扣减当前进程的剩余时间片；时间片用完 ⟹ 当前进程（改 PCB 状态）挂到就绪队列尾，调度程序取就绪队列队首。
- 没有时钟中断，OS 就无法从不肯让出 CPU 的进程手里夺回 CPU。
- 阻塞队列里的进程不参加调度。

@tpl T磁盘调度 | 磁盘调度算总移动距离：一步一行写「当前位置 → 选谁 → 走多远」
1. FCFS 按请求顺序；SSTF 每次选离当前磁头最近的（含与当前位置相同的请求，距离 0）；SCAN/LOOK 按方向走到头（或最远请求）再折返；C-SCAN/C-LOOK 单向，返程是否计入看题。
2. 单向到底再折返的轨迹可用「两段距离」快算；SSTF 来回跳时只能逐步算。
3. 距离很接近的两个候选（差 1）要多核一遍。

@kp SSTF | 最短寻找时间优先（SSTF）
每次选与当前磁头位置距离最近的请求。
- 平均寻道短，但可能饥饿（远处请求一直被插队）。
- 与 SCAN 的区别：SSTF 只看距离不看方向，轨迹会来回跳。
- 例：磁头 50，请求 45、60、40 ⟹ 45(5)→40(5)→60(20)，共 30。

@tpl T调度时机 | 「能否 / 可能 / 必然引起调度」：先钉死题干的口径
1. 必然引起：当前进程终止、阻塞、时间片用完、主动让出 ⟹ CPU 空出来了。
2. 可能引起：中断处理结束、系统调用返回用户态前（有更高优先级的就绪了才抢占）、新进程就绪（抢占式）。
3. 不能调度：处理中断的过程中、进程在操作系统内核临界区中、原子操作中。

@tpl T改进CLOCK | 改进型 CLOCK 选淘汰页：按 (访问位 A, 修改位 M) 找 (0,0) → (0,1)（清 A）→ 重来
1. 第 1 轮：从指针处扫一圈找 (0,0)，不改任何位。
2. 第 2 轮：找 (0,1)，经过的页把 A 清 0。
3. 还没找到：此时所有 A 都是 0，回到第 1 轮再找 (0,0)（原来的 (1,0)），再不行第 2 轮找 (0,1)（原来的 (1,1)）。
4. 结果上等价于优先级 (0,0) ＞ (0,1) ＞ (1,0) ＞ (1,1)，同级看指针位置。
5. 存在位为 0 的页表项，页框号字段无效，不能拿来拼地址。

@kp 改进型CLOCK | 改进型 CLOCK 置换算法
每页两位：访问位 A（最近用过）、修改位 M（被写过，换出要写回磁盘）。
- 优先淘汰「最近没用、也没改过」的页 (0,0)，其次 (0,1)，因为换出脏页要多一次写磁盘。
- 简单 CLOCK 只看 A：A＝1 清 0 跳过，遇到 A＝0 就淘汰。

@kp 页表基址寄存器 | 页表基址寄存器（PTBR）
存当前进程**顶级（一级）页表**的起始**物理**地址。
- 物理：查页表本身不能再经过地址变换，否则无限递归。
- 一级：二级页表有很多张，位置要从一级页表项里查出来；一级页表每进程只有一张。
- 进程不运行时，这个值保存在 PCB 里，切换时装入。

@kp 软链接 | 软链接（符号链接、快捷方式）与硬链接
- 硬链接：多个目录项指向同一个 inode，inode 里有链接计数；删除时计数减 1，减到 0 才回收 inode 和磁盘块。
- 软链接：一个独立的文件，内容是目标的路径名；目标被删后它变成悬空链接，内核不会去找它、也找不到它。
- 删除文件的标准动作：删目录项、（计数为 0 时）回收 FCB/inode、回收磁盘块。

@tpl T死锁资源数 | 「不会死锁至少要几个资源 / 最多几个进程」：每人先给 k−1 个，再多 1 个
1. $n$ 个进程各最多要 $k$ 个：最坏情况每人拿 $k-1$ 个都卡住，再多 1 个就有人能完成。
2. 不死锁 ⟺ $m\ge n(k-1)+1$，即 $m>n(k-1)$。
3. 需求不等时：$m\ge\sum(k_i-1)+1$。反问「最多几个进程」：解 $n(k-1)<m$。

@kp 系统调用 | 系统调用
用户进程主动请求操作系统内核提供服务的接口（如 fork、open、read、write）：执行陷入指令进入内核态，服务完返回用户态。
- 页置换、进程调度是 OS 自己发起的管理动作，不是系统调用。
- 纯计算的库函数（sin、random）在用户态完成，不进内核；库函数也可能内部调用系统调用（printf → write）。

// ───── 本年新建：计算机网络 ─────

@kp TCP/IP四层 | TCP/IP 体系结构
应用层 → 传输层（TCP、UDP，端到端）→ 网际层（IP 及 ARP、ICMP、IGMP，路由选择与转发，无连接尽力而为）→ 网络接口层。
- 会话管理并进应用层；网际层不做流量控制、不保证有序。
- 对比 OSI：OSI 网络层可面向连接、可有流量控制。

@tpl T读编码波形 | 读编码波形：先按虚线把每个码元切开，确认每格中间都跳，再按规则逐位读
1. 曼彻斯特：只看每个码元**中间**跳变的方向（常用约定：高→低为 1 或题目给出），一位一读、互不相关。
2. 差分曼彻斯特：中间必跳（只管同步）；看码元**起始处**相对前一位末尾有没有跳变：有 ⟹ 0，无 ⟹ 1。
3. 第一位与波形开头的电平比；读完把串和选项对，四个选项常是「读反、错一位」。

@kp 曼彻斯特 | 曼彻斯特编码与差分曼彻斯特编码
- 曼彻斯特：每位中间都跳变，跳变方向表示 0/1；自带时钟，但带宽是原来的 2 倍。以太网用它。
- 差分曼彻斯特：每位中间也都跳变；位开始处有跳变表示 0、无跳变表示 1。抗干扰更好。

@tpl T子网二叉树 | 子网划分能否互不重叠又不遗漏：把网络前缀画成二叉树，看叶子能否恰好铺满
1. 只看网络号里比公共前缀多出的那几位，例如 /24 里的 .128/26 写成「10」。
2. 互不重叠 ⟺ 任何一个的位串都不是另一个的前缀。
3. 不遗漏 ⟺ 各块大小之和等于父块（/25 占 1/2，/26 占 1/4，/27 占 1/8）。
4. 再看块数：凑满父块需要的最少块数要等于题目给的个数。

@tpl TIP分片 | IP 分片三步：每片最大数据要 8 的倍数，再列分片表
1. 每片最大数据＝$\lfloor(\text{MTU}-\text{首部})/8\rfloor\times8$。
2. 数据总量＝总长度 − 首部；片数＝$\lceil$数据总量 ÷ 每片最大数据$\rceil$。
3. 逐片写：数据长度、总长度（＋首部）、片偏移（已发数据 ÷ 8）、MF（最后一片为 0，其余为 1）、DF＝0。

@kp IP分片 | IP 分片
数据报大于下一跳 MTU 时，在路由器上分片，到目的主机再重组。
- 片偏移以 8 字节为单位 ⟹ 除最后一片外，每片的数据长度必须是 8 的倍数。
- 总长度字段是本片的首部 ＋ 数据；MF＝1 表示后面还有分片；DF＝1 不允许分片（超长就丢弃并发 ICMP）。

@tpl T距离向量 | 距离向量更新：对每个目的网络，算「到邻居的代价 ＋ 邻居报的距离」取最小
1. 把每个邻居的链路代价写在它那一列的表头上。
2. 一行一个目的网络，横着算每列的和，取最小值并记下下一跳。
3. 只能经过邻居 ⟹ 不能把链路代价本身当成到目的网络的距离。

@kp 距离向量 | 距离向量算法（RIP）
每个路由器周期性地把自己的距离向量发给邻居；收到后对每个目的 $N$：$d_E(N)=\min_v\{c(E,v)+d_v(N)\}$。
- RIP 用跳数，16 表示不可达；坏消息传得慢（计数到无穷）。
- 例：到邻居 A 代价 2，A 报到 N 距离 3 ⟹ 经 A 到 N 为 5。

@kp TCP四次挥手 | TCP 连接释放的状态
主动关闭方：ESTABLISHED → 发 FIN → FIN_WAIT_1 → 收到 ACK → FIN_WAIT_2 → 收到对方 FIN、回 ACK → TIME_WAIT → 等 2MSL → CLOSED。
被动关闭方：收到 FIN、回 ACK → CLOSE_WAIT → 发 FIN → LAST_ACK → 收到 ACK → CLOSED。
- TIME_WAIT 等 2MSL：保证最后的 ACK 能到达（丢了还能重发），让旧报文段在网络中消失。

@tpl T发送窗口 | TCP 还能发哪些序号：窗口从 ack 起算，长度 min(rwnd, cwnd)，再扣掉已发未确认
1. 可发区间上界＝ack ＋ 窗口 − 1（窗口＝min(rwnd, cwnd)，只给 rwnd 就用 rwnd）。
2. 已发出但没被确认的序号仍占着窗口 ⟹ 可继续发的从「已发到的下一个」开始。
3. 对方报文里的 seq 是对方方向的序号，和本方能发什么无关。

// ───── 本年新建：综合题套路 ─────

@tpl T矩阵数度 | 邻接矩阵上求度：第 i 行（无向）非零元素个数；有向图出度看行、入度看列
1. 0/1 矩阵直接把一行加起来；带权矩阵要数「非 0 且非 ∞」的元素。
2. 两重循环扫整张矩阵 ⟹ 时间 $O(n^2)$，只用计数器 ⟹ 空间 $O(1)$。
3. 2021（奇度顶点数）、2023（出度＞入度的 K 顶点）、2024（拓扑序唯一）都是这个模子。

@tpl T稳定性判断 | 读代码判稳定性：只看「两个相等元素」走哪条分支，谁被放到后面
1. 构造一个最小例子：两个相等的元素 $a_i=a_j$（$i$ 在前），手跑一遍看最后谁在前。
2. 比较语句里有没有等号是关键：相等时让靠后的那个「往后挪」就稳定，让靠前的往后挪就不稳定。
3. 修改时只改那一个比较符号，并把改后的那一行写出来。

@kp 符号扩展 | 符号扩展与零扩展
把短的数扩成长的数：
- 符号扩展：高位全部补符号位，补码真值不变。用于有符号数（访存偏移量、条件转移的相对位移）。
- 零扩展：高位全部补 0，无符号真值不变。用于无符号数、逻辑运算的立即数。
- 例：6 位 111110（−2）符号扩展成 16 位：FFFEH；零扩展：003EH（62）。

@tpl TTLB当Cache | TLB 组相联的标记、组号、替换：把虚页号当成 Cache 的「主存块号」
1. 虚页号＝虚拟地址 − 页内地址位数；组号位数＝$\log_2$ 组数，取虚页号的低位；其余高位是标记。
2. 组号＝虚页号 mod 组数，先把整串访问的组号算出来，只模拟「访问的不同页数 ＞ 路数」的那几组。
3. LRU：命中也要把它移到「最近」；FIFO 命中不变。
4. 地址变宽时只有标记变宽（页框号取决于物理地址，组号取决于组数）。

@tpl T引导顺序 | 开机引导与磁盘初始化的先后：先有物理结构，才有逻辑结构；先跑固定的，再跑可变的
1. 引导：ROM 中的引导程序（自举）→ 磁盘引导程序（MBR，选分区）→ 分区引导程序 → 操作系统初始化程序。
2. 制盘：物理（低级）格式化（划扇区）→ 分区（写分区表）→ 逻辑（高级）格式化（建文件系统、根目录）→ 安装 OS。
3. 每一步都写一句「为什么必须在它前面」，那是理由分。

@kp 磁盘格式化 | 物理格式化、分区与逻辑格式化
- 物理（低级）格式化：把磁道划分成扇区（头、数据区、尾部校验码），标坏扇区，通常出厂已完成。
- 分区：把磁盘分成若干相互独立的逻辑盘，分区表放在第 0 号扇区的主引导记录（MBR）里。
- 逻辑（高级）格式化：在分区上建立文件系统——分区引导块、空闲空间管理结构（位示图/FAT）、根目录等。

@tpl T关中断互斥 | 用开/关中断实现互斥：关中断期间不会切换进程，所以「关着中断忙等」必死循环
1. 单处理机上关中断 ⟹ 时钟中断进不来 ⟹ 不会发生进程切换 ⟹ 关中断到开中断之间的代码对其他进程是原子的。
2. 关着中断等一个只有别的进程才能改变的条件 ⟹ 永远等不到。等待循环里必须「开中断—关中断」放一次风。
3. 开/关中断是特权指令：只能给内核用（实现 wait、signal 这类原语），用户程序不能用；多处理机上关中断只关本 CPU，不够用。

@tpl T全栈帧序列 | 「访问网页时网络上出现了哪些帧」：按时间把要发的报文排成一列，每个报文前先问「下一跳的 MAC 知道吗」
1. 用域名访问 ⟹ 先 DNS（DNS → UDP → IP → 以太网帧）。
2. 每发一个 IP 分组：目的在本网段 ⟹ 下一跳是目的主机本身；不在 ⟹ 下一跳是默认网关。下一跳 MAC 不在 ARP 表里 ⟹ 先发 ARP 请求（广播）、等 ARP 响应（单播）。
3. 交换机：收到帧先记「源 MAC → 进入端口」，再查目的 MAC：查到就单播转发，查不到或广播就从其余端口泛洪。
4. 某主机收到哪些帧：广播帧和交换机还没学到目的地址时的泛洪帧。

@kp 交换机自学习 | 以太网交换机的自学习与转发
- 学习：每收到一帧，把（源 MAC，进入端口）记入交换表。没发过帧的主机不会被记住。
- 转发：目的 MAC 在表中 ⟹ 只从对应端口转出（同端口则丢弃）；不在表中或是广播地址 FF-FF-FF-FF-FF-FF ⟹ 从除进入端口外的所有端口转出。

@kp ARP | 地址解析协议 ARP
已知下一跳的 IP 地址，求它的 MAC 地址。
- ARP 请求：广播（目的 MAC 全 F），问「谁是这个 IP」；ARP 响应：单播回给请求方。
- 目的主机在本网段 ⟹ 问目的主机；在别的网段 ⟹ 问默认网关（路由器接口）的 MAC。
- 结果缓存在 ARP 表里，有就不再问。
