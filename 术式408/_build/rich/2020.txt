@tpl T出栈序列
::rev
- **该花** 40 秒。一步一列模拟：弹出 b、c、e。
- **卡点** 第二个 Pop 前忘了先 Push c，弹成 a，错选 A。
- **错了说明** Push、Pop 交替时没有逐步记栈内容。
- **带走** 栈操作序列题画横栈，一步一列写栈里剩什么、弹出什么。
::read
「对空栈 S」 >> 起点是空栈；画一个开口朝右的横栈：左边是栈底、右边是栈顶
「入栈序列为 a,b,c,d,e」 >> Push 只能按这个顺序拿下一个，不能跳
「Push、Push、Pop、Push、Pop、Push、Push、Pop」 >> 8 个操作，{{圈|3 个 Pop}} ⟹ 出栈序列只有 3 个元素；草稿上一步一行
::sk 420 128 列 | 草稿：一列一步，记下栈里剩什么、弹出了什么
ops=['Push','Push','Pop','Push','Pop','Push','Push','Pop']
stk=['a','a b','a','a c','a','a d','a d e','a d']
out=['','','b','','c','','','e']
s.cells(10,10,[['操作']+ops,['栈底→顶']+stk,['弹出']+['!'+o if o else '' for o in out]],cw=[54]+[44]*8,ch=26,size=11)
s.text(10,112,'弹出依次是 b、c、e；栈里还剩 a、d',12,'r')
::fast
{{秒|第一个 Pop 前只压了 a、b ⟹ 第一个弹出的必是 b}}，四个选项都满足；第二个 Pop 前又压了 c ⟹ 弹 c，排除 A、B；第三个 Pop 前压了 d、e ⟹ 弹 e，选 D。
::steps
Push a：栈 [a]；Push b：栈 [a, b]。
Pop：弹出栈顶 b，栈 [a]。
Push c：栈 [a, c]；Pop：弹出 c，栈 [a]。
Push d：栈 [a, d]；Push e：栈 [a, d, e]；Pop：弹出 e，栈 [a, d]。
出栈序列 b, c, e，选 **D**。
::note
- 选项 A（b,a,c）是把第二个 Pop 当成弹 a 的——忘了 Pop 之前先 Push 了 c。凡是 Push、Pop 交替的题，**先 Push 再看栈顶**。
- 题目问的是「得到的出栈序列」，栈里剩下的 a、d 不算。
::vary
问 d, b, a, c, e 是否可能 >> 不可能：d 出栈时 a、b、c 都在栈里且 c 在顶，下一个只能是 c 或新压的 e，b 出不来
把栈换成队列，同样 8 个操作（入/出），出队序列 >> 队列先进先出：a, b, c

@tpl T顺序存储二叉树
::rev
- **该花** 30 秒。「任意」⟹ 按最坏形态：高 5 一路向右，最大编号 $2^5-1=31$。
- **卡点** 只数结点答 10，或让第 5 层结点靠左答 16（B）。
- **错了说明** 「任意一棵」要求数组装得下所有形态，没读出来。
- **带走** 顺序存储所需单元＝最大编号；高 $h$ 的二叉树最坏要 $2^h-1$ 个。
::read
「对于{{圈|任意}}一棵高度为 5 且有 10 个结点的二叉树」 >> 「任意」＝数组得装得下**所有**这样的树 ⟹ 要按最坏形态准备
「采用{{圈|顺序存储}}结构」 >> 按满二叉树的层序编号对号入座：根 1、左孩子 $2i$、右孩子 $2i+1$，{{波|空位也占坑}}
「每个结点占 1 个存储单元」 >> 单元数＝数组长度＝出现的最大编号
「{{圈|至少}}」 >> 能保证装下任何一棵这样的树的最小数组长度
::sk 420 200 画 | 草稿：高 5 的最坏形态是一路向右，第 5 层的结点编号是 31；10 个结点只是凑数
for i,(lab) in enumerate(['1','3','7','15','31']):
    x=40+i*48;y=24+i*36
    s.node(x,y,lab,13,c='r' if i==4 else 'k',size=11)
    if i<4: s.edge(x,y,x+48,y+36,13,13)
s.text(250,40,'编号：右孩子 = 2i+1',12)
s.text(250,64,'1→3→7→15→31',12,'b')
s.text(250,88,'第 5 层最右 = 2^{5}−1 = 31',12,'r')
s.text(250,124,'其余 5 个结点随便挂在',12)
s.text(250,144,'前 4 层，编号都 < 31',12)
s.text(250,180,'数组至少 31 个单元',13,'r',bold=True)
::fast
{{秒|顺序存储看最大编号，高 $h$ 最坏 $2^h-1$}} ⟹ 31。10 是只数了结点、16 是 $2^4$、15 是高 4 的满二叉树，三个都是少算。
::steps
顺序存储把结点放在它在满二叉树中的层序编号处：根编号 1，结点 $i$ 的左孩子 $2i$、右孩子 $2i+1$，不存在的结点位置空着。
所以数组至少要开到「树里出现的最大编号」那么长。
高度为 5 ⟹ 第 5 层至少有一个结点。第 5 层的编号范围是 $2^4=16$ 到 $2^5-1=31$。
「任意一棵」⟹ 必须对每一棵都够用。取一条一路向右的单支（编号 1, 3, 7, 15, 31），再把剩下 5 个结点挂在前 4 层，高度是 5、结点是 10，最大编号 31。
于是至少需要 31 个单元，选 **A**。
~程序穷举：10 个结点、高 5 的所有二叉树形态里，最大编号的最大值是 31、最小值是 16。
::note
- 「任意」「至少」两个词决定答案：去掉「任意」改问「某一棵至少需要多少单元」，就是让第 5 层那个结点尽量靠左（编号 16）⟹ 答 16（选项 B）。
- 顺序存储只适合完全二叉树：完全二叉树零浪费，一般二叉树可能浪费到指数级（本题 10 个结点占 31 个单元）。
::vary
高度为 $h$ 的二叉树顺序存储，最坏要多少单元、最多存多少结点 >> 都是 $2^h-1$（最坏单支要 $2^h-1$ 个单元却只存 $h$ 个结点）
1 起编号时结点 $i$ 的父亲 >> $\lfloor i/2\rfloor$；判断 $i$ 是不是叶子（完全二叉树、$n$ 个结点）：$2i>n$

#4
@tpl T遍历建树
::rev
- **该花** 2 分钟。森林先根＝T 的先序，森林后根＝T 的中序，建出 T 再写后序。
- **卡点** 把森林后根当成 T 的后序，直接选 A。
- **错了说明** 对应关系「先根—先序、后根—中序」没背。
- **带走** 森林与二叉树：先根对先序、后根对中序；T 的后序必须建树后自己读。
::read
「森林 F 及与之对应的二叉树 T」 >> 对应＝[[孩子兄弟|孩子兄弟表示法]]：左指针＝第一个孩子，右指针＝下一个兄弟
「F 的先根 a,b,c,d,e,f」 >> 森林先根 ＝ {{圈|T 的先序}}
「F 的后根 b,a,d,f,e,c」 >> 森林后根 ＝ {{圈|T 的中序}}（不是后序！）——先序＋中序 ⟹ T 唯一确定
「问 T 的后序」 >> 要真把 T 建出来；选项 A 原样抄了题干的后根序列，是诱饵
::sk 420 190 画 | 草稿：右边按「先序定根、中序分左右」建出 T；左边把 T 还原成森林，顺手核对题干两个序列

::steps
森林先根 ＝ 二叉树先序 ⟹ T 的先序 $a,b,c,d,e,f$；森林后根 ＝ 二叉树中序 ⟹ T 的中序 $b,a,d,f,e,c$。
  为什么：先根遍历「根 → 子树们 → 下一棵树」，对应二叉树「根 → 左子树（孩子们） → 右子树（兄弟们）」；后根「子树们 → 根 → 下一棵树」对应「左 → 根 → 右」即中序。
先序第一个 $a$ 是根；中序里 $a$ 左边只有 $b$ ⟹ 左子树 $\{b\}$，右子树 $\{d,f,e,c\}$。
右子树的先序是 $c,d,e,f$ ⟹ 根 $c$；中序 $d,f,e,c$ 里 $c$ 在最右 ⟹ $c$ 只有左子树 $\{d,f,e\}$。
$\{d,f,e\}$ 先序 $d,e,f$ ⟹ 根 $d$；中序 $d,f,e$ 里 $d$ 在最左 ⟹ 只有右子树 $\{f,e\}$。
$\{f,e\}$ 先序 $e,f$ ⟹ 根 $e$；中序 $f,e$ ⟹ $f$ 是 $e$ 的左孩子。
后序（左 → 右 → 根）：$b$，然后右子树 $c$ 的后序 $f,e,d,c$，最后 $a$ ⟹ $b,f,e,d,c,a$，选 **C**。
~核对：还原成森林（草图左下），先根 a b c d e f、后根 b a d f e c，与题干一致。
::fast
{{秒|T 的后序最后一个一定是根 $a$}} ⟹ 排除 A（以 c 结尾）和 D（以 a 结尾但第一个是 f——左子树只有 b，后序第一个必是 b）。剩 B、C：右子树的根 $c$ 必须紧挨着 $a$ 前面，两者都满足；再看 $d$ 是 $e$ 的父亲，后序里 $e$ 要在 $d$ 之前 ⟹ C。
::note
- 记住这张对应表就够：==森林先根＝二叉树先序；森林后根＝二叉树中序==。森林没有「中根」遍历。
- {{扣|把森林后根当成二叉树后序}}：那样直接选 A，是本题最大的坑。
::vary
F 的先根同上，若 T 的后序是 $b,f,e,d,c,a$，问 F 有几棵树 >> 从 T 的根沿右链走：$a\to c$，2 棵
问 F 中叶子结点个数 >> 森林的叶子＝没有孩子＝T 中左指针为空的结点：$b$、$d$、$f$ 的左指针为空（$a,c,e$ 都有左孩子）⟹ 3 个

@tpl TBST序列
::rev
- **该花** 40 秒。只查三条约束：4 最先，2 在 1 和 3 之前。
- **卡点** 把四个序列各建一棵树，费时且易手滑。
- **错了说明** 「父结点必须先于子孙插入」这条判据没用。
- **带走** 判插入序列能否生成给定 BST：把树抄成「祖先先于子孙」的约束，逐个选项查先后。
::read
「{{圈|不能}}生成下图所示二叉排序树的是」 >> 选「不能」的；四个序列可能只有一个错
「下图：4 的左孩子 2、右孩子 5；2 的左孩子 1、右孩子 3」 >> 草稿上把父子关系抄成三条约束：4 最先；2 在 1、3 之前；5 只要在 4 之后

::fast
{{秒|看 1、2、3 谁先出现}}：A 中 2 先于 1、3 ✓；B 中 1 排在 2 前面 ✗；C、D 都是 2 先 ✓ ⟹ 选 B。
::steps
插入序列的第一个元素是根。四个选项都以 4 开头，根都是 4。
目标树里 2 是 1 和 3 的父亲。插入时若 1 比 2 先到，1 会直接成为 4 的左孩子，占住 2 的位置，后来的 2 只能挂到 1 的右子树里。
所以一个序列能生成目标树，必须让 2 出现在 1、3 之前；5 是 4 的右孩子，只需在 4 之后，与左子树谁先无所谓。
逐个检查：A（4,5,2,1,3）2 先于 1、3 ✓；B（4,5,1,2,3）1 先于 2 ✗；C（4,2,5,3,1）✓；D（4,2,1,3,5）✓。
~验证 B：插 4、5（右）、1（4 的左）、2（比 4 小走左，比 1 大挂 1 的右）、3（挂 2 的右）⟹ 4 的左边是一条 1→2→3 的右斜链，确实不同。
不能生成目标树的是 **B**。
::note
- 合法序列**不必**是层次序：C 的 4,2,5,3,1 不是层次序，照样合法。只要求祖先先于子孙。
- {{扣|逐个画四棵树}}：考场上能做但费时间，而且容易在挂左还是挂右上手滑。
::vary
能生成这棵树的序列一共有多少个 >> 4 第一；剩下 4 个数里 2 要先于 1、3，5 随意：$4!\div 3=8$ 个
从这棵 BST 中删除根 4，用中序后继顶替，新根是 >> 中序后继是右子树最小的 5 ⟹ 新根 5，5 原来位置空出

@tpl TDFS输出位置
::rev
- **该花** 1 分钟。拿 1→2、1→3、2→3 手跑：退出顺序 3,2,1，是逆拓扑序。
- **卡点** 选「深度优先搜索序列」（那是进入时输出）或选「拓扑有序」（方向反了）。

- **带走** DFS 三种输出位置：进入时是 DFS 序列，退出时是逆拓扑，退出时压栈再弹是拓扑序。
::read
「将输出顶点信息的语句{{圈|移到退出递归前}}」 >> 先把所有邻居都递归完，自己最后才打印——和「进入时打印」的 DFS 序列不是一回事

::vary

{{秒|Ⅱ 两者都 O(1)，一定错}} ⟹ 排除 C、D；剩 A（仅Ⅰ）、B（仅Ⅲ）：有序时两者移动都是 0，Ⅲ不成立 ⟹ 选 A。
::steps
已有序时，直接插入每个元素只和前一个比较 1 次就停，共 $n-1$ 次比较、0 次移动。
简单选择每趟都要在剩余元素里找最小值，第 $i$ 趟比较 $n-i$ 次，共 $\frac{n(n-1)}{2}$ 次比较，与初始顺序无关；已有序时每趟最小值就在原位，0 次移动。
Ⅰ：比较次数 $n-1$ 对 $\frac{n(n-1)}{2}$，插入少一个数量级——这正是效率高的原因。对。
Ⅱ：两者都只用一个临时变量，辅助空间都是 $O(1)$。错。
Ⅲ：已有序时都是 0；一般情况直接插入的移动次数等于逆序对数，可达 $O(n^2)$，简单选择每趟最多交换一次（3 次移动），总共不超过 $3(n-1)$。插入并不更少。错。
只有Ⅰ，选 **A**。
~程序核对：$n=100$ 已有序时插入比较 99、选择比较 4950，移动都是 0；随机输入时插入移动 2774 次、选择 288 次。
::note
- 简单选择是「比较多、移动少」的典型：记录很大（移动代价高）时反而该选简单选择。
- {{扣|觉得插入「更快」就以为它什么都更少}}：Ⅲ 就是给这种直觉设的坑。
::vary
比较次数与初始序列无关的排序 >> 简单选择排序（恒 $n(n-1)/2$）；另外折半插入的比较次数也与初态无关（约 $n\log_2 n$），但移动有关
最坏情况下移动次数最少的是 >> 简单选择排序，最多 $3(n-1)$ 次（2025 年考过）

单周期 CPU：每条指令在一个时钟周期内完成（时钟周期按最慢的指令定），CPI＝1。Ⅰ对。

超标量流水线 CPU：每个时钟周期可同时发射、流出多条指令，CPI＜1。Ⅳ错。

::note
- CPI 相同不等于性能相同：CPU 时间＝指令条数 × CPI × 时钟周期。单周期与流水线 CPI 都是 1，但单周期的时钟周期要装下整条指令（如 800ps），流水线只装最长的一段（如 200ps）。

::vary

@tpl TEAT公式
::rev
- **该花** 15 秒。写出 EAT 公式，四项都在里面。
- **卡点** 漏掉 Ⅳ（缺页处理程序占的 CPU 时间）。
- **错了说明** 缺页处理时间＝磁盘读写＋处理程序的 CPU 时间，只记了前者。
- **带走** EAT＝$(1-p)\times$访存时间＋$p\times$（缺页处理时间＋访存时间）。
::read
「影响请求分页系统{{圈|有效（平均）访存时间}}的」 >> 把 [[EAT]] 公式写出来，看四个因素各站在哪一项
「Ⅰ 缺页率」 >> 加权的权重 $p$
「Ⅱ 磁盘读/写时间　Ⅳ 执行缺页处理程序的 CPU 时间」 >> 都在「缺页处理时间」里
「Ⅲ 内存访问时间」 >> 不缺页那一支、以及缺页处理完重新访存，都要它
::fast
{{秒|写出 EAT 公式，四项各有位置}} ⟹ 全选 D。
::steps
请求分页的有效访存时间 $EAT=(1-p)\cdot t+p\cdot(T_{缺页}+t)$，$p$ 是缺页率、$t$ 是一次访存时间。
Ⅰ 缺页率 $p$ 是加权的权重，直接影响 EAT。
Ⅲ 内存访问时间 $t$：不缺页时要访存，缺页处理完还要重新访存（访问页表和目标单元），影响 EAT。
缺页处理时间 $T_{缺页}$ 包括：CPU 执行缺页中断处理程序的时间（Ⅳ），以及换出、调入页面的磁盘读写时间（Ⅱ）。两者都影响 EAT。
四项都影响，选 **D**。
::note
- Ⅳ 最容易漏：只记得磁盘慢，忘了 OS 处理中断本身也耗 CPU 时间。题目给「缺页中断处理需要 xx μs」就是Ⅳ。
- 缺页处理是毫秒级、访存是纳秒级，差 $10^5$ 倍以上：缺页率是 EAT 里杠杆最长的变量。
::vary
访存 100ns，缺页处理（含磁盘）10ms，缺页率 0.1%，EAT >> $0.999\times100+0.001\times(10^7+100)\approx10100$ns，约 10.1μs，比不缺页慢 100 倍
加上快表（命中率 $\alpha$、查快表 $\varepsilon$），不缺页时的访存时间 >> $\alpha(\varepsilon+t)+(1-\alpha)(\varepsilon+2t)$

::rev
- **该花** 13 分钟。看出 $D=2(\max-\min)$ 3 分钟，写代码 7 分钟，复杂度和检查 3 分钟。

「D＝|a−b|＋|b−c|＋|c−a|」 >> 三个数在数轴上：两两距离之和＝{{圈|2×（最大 − 最小）}}，中间那个数不影响

化简：不妨设 $a\le b\le c$，则 $|a-b|+|b-c|+|c-a|=(b-a)+(c-b)+(c-a)=2(c-a)$，即 $D=2(\max-\min)$。
用 i、j、k 分别指向 $S_1,S_2,S_3$ 的当前元素，初值都为 0；D_min 初值取一个很大的数（INT_MAX）。
每一轮：计算当前三元组 $(S_1[i],S_2[j],S_3[k])$ 的距离 D，若 D ＜ D_min 就更新 D_min。
然后找出三个当前元素中最小的那个，只把它所在数组的指针后移一位。
为什么可以扔掉当前最小元素 $m$：它和其余两个数组中**当前及以后**的任何元素组合时，最小值 ≤ $m$，最大值 ≥ 当前的最大值，所以距离 ≥ 当前的 D，已经算过的 D 不会被它改进。
任一指针越界（某个集合扫完）就结束，输出 D_min。
~手跑题目的例子（草图表格）：依次得到 54、24、22、20、16、2，最小距离 2，与题目给的一致。
复杂度：每轮恰有一个指针前进一步，最多 $n=|S_1|+|S_2|+|S_3|$ 轮 ⟹ 时间 $O(n)$；只用了几个变量 ⟹ 空间 $O(1)$。
::paper
**（1）基本设计思想** ⛳4
设三元组中最小的数为 $\min$、最大的为 $\max$，则 $D=|a-b|+|b-c|+|c-a|=2(\max-\min)$。
用 i、j、k 三个下标分别从头扫描 $S_1$、$S_2$、$S_3$。每次计算当前三元组的距离并更新最小距离 D_min，然后将三个当前元素中**最小者**所在数组的下标后移一位（最小元素与其余数组中当前及以后的元素组成的三元组，距离都不小于当前距离，可以舍去）。任一数组扫描完毕时算法结束，D_min 即为所求。
**（2）算法实现** ⛳7
```
#define INT_MAX 0x7fffffff
int abs_(int x) { return x < 0 ? -x : x; }   /* 求绝对值 */
int xls_min(int a, int b, int c) {           /* a 是否为三者中最小 */
    return a <= b && a <= c;
}
int findMinofTrip(int A[], int n, int B[], int m, int C[], int p) {
    int i = 0, j = 0, k = 0, D_min = INT_MAX, D;
    while (i < n && j < m && k < p && D_min > 0) {
        D = abs_(A[i] - B[j]) + abs_(B[j] - C[k]) + abs_(C[k] - A[i]);
        if (D < D_min) D_min = D;                /* 更新最小距离 */
        if (xls_min(A[i], B[j], C[k])) i++;      /* 只后移最小者 */
        else if (xls_min(B[j], C[k], A[i])) j++;
        else k++;
    }
    return D_min;
}
```
**（3）复杂度** ⛳2
设 $n=|S_1|+|S_2|+|S_3|$。每轮循环恰有一个下标加 1，循环至多 $n$ 次，时间复杂度 $O(n)$；只使用常数个辅助变量，空间复杂度 $O(1)$。
::note
- {{扣|只写三重循环暴力}}：思路和代码正确也只能拿一部分分（往年评分大致一半左右），题干「尽可能高效」就是在提示这个。
- {{扣|没说明为什么只移最小者}}：思想部分要有这句理由，否则阅卷看不出你不是在碰运气。
- 循环条件里的 `D_min > 0` 只是提前结束的优化，不写也对。
::vary
只有两个升序数组，各取一个数使差的绝对值最小 >> 双指针，每轮算差后移较小者，$O(n+m)$
$k$ 个升序数组各取一个，使极差最小 >> 用小根堆维护 $k$ 个当前元素和当前最大值，每次弹出最小者并推进它的指针：$O(N\log k)$
若三个数组是降序存放 >> 指针从尾部往前扫，等价于升序；或每轮后移**最大者**所在数组的指针（降序时元素越往后越小）
