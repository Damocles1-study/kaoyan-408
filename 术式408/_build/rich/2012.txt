#1
@ans B
@tpl T递归复杂度
::rev
- **该花** 20 秒。每次调用 n 减 1，调用 n 次，每次常数时间。
- **卡点** 看到乘法 `n*fact(n-1)` 以为工作量在翻倍，选了 D；或把递归和折半混了选 A。
- **错了说明** 没分清「调用几次」和「每次干多少」。
- **带走** 递归函数的时间复杂度＝调用次数 × 每次调用自己干的活；参数每次减 1 就是调用 n 次。
::read
「return {{圈|n*fact(n-1)}}」 >> 一次调用里只调自己 1 次，参数从 n 变成 n−1；乘法只是一次运算，不影响调用次数
::fast
{{秒|参数每次减 1，减到 1 为止，共调用 n 次，每次 O(1)}} ⟹ $O(n)$，选 B。
::steps
设 `fact(n)` 的时间为 $T(n)$。$n\le1$ 时直接返回：$T(1)=1$。
$n\gt1$ 时：做一次比较、一次乘法（常数时间），再加上 `fact(n-1)` 的时间 ⟹ $T(n)=T(n-1)+1$。
展开：$T(n)=T(n-1)+1=T(n-2)+2=\dots=T(1)+(n-1)=n$。
所以时间复杂度是 $O(n)$，选 **B**。
::note
- {{扣|把结果的大小当成工作量}}：$n!$ 很大，但算它只做了 $n-1$ 次乘法。
- 顺带：这个函数的空间复杂度也是 $O(n)$——递归到最深时栈里压着 n 层。
::vary
改成 `return fact(n-1)+fact(n-1);`，时间复杂度是多少 >> 每次调用自己两次：$T(n)=2T(n-1)+1$ ⟹ $O(2^n)$
改成 `return n*fact(n/2);`，时间复杂度是多少 >> 参数每次减半，调用约 $\log_2n$ 次 ⟹ $O(\log_2n)$

@ans A
@tpl T遍历建树
::rev
- **该花** 1 分钟。两个序列各去掉根 a，剩下的一段先序以 e 开头、后序以 e 结尾。
- **卡点** 觉得「先序＋后序不能唯一确定二叉树」就直接选 D。
- **错了说明** 不知道先序加后序虽然定不了左右，但能定谁是谁的祖先、根有几个孩子。
- **带走** 先序＋后序：去掉根后，若剩余段「先序第一个＝后序最后一个」，根只有一个孩子（左右不定）；不相等，则先序第一个是左孩子、后序最后一个是右孩子。
::read
「先序 a,{{圈|e}},b,d,c」「后序 b,c,d,{{圈|e}},a」 >> 先序第一个、后序最后一个都是根 a。去掉 a：先序剩 e,b,d,c，后序剩 b,c,d,e——这一段又是「先序第一个＝后序最后一个＝e」
「则根结点的{{圈|孩子结点}}」 >> 只问根有哪些孩子，不要求把整棵树定下来
::sk 250 150 画 | 先画 a，下面只挂一个 e（左右随便），e 下面左 b 右 d，d 下面挂 c（左右随便）

::fast
{{秒|去掉根后，剩下那段的先序首和后序尾是同一个结点 e}} ⟹ 这一整段是以 e 为根的一棵子树 ⟹ a 只有 e 一个孩子，选 A。
::steps
先序＝根、左子树、右子树；后序＝左子树、右子树、根（见 [[后序遍历]]）。两个序列都指出根是 a。
去掉 a 后，先序剩 e,b,d,c，后序剩 b,c,d,e。
假设 a 有左右两个孩子：先序剩余段的第一个是左孩子（e），后序剩余段的最后一个是右孩子（也是 e）。左右孩子不可能是同一个结点 ⟹ 矛盾。
所以 a 只有一个孩子 e（是左是右定不了），b、d、c 都在 e 的子树里，选 **A**。
~继续往下：e 的子树去掉 e，先序 b,d,c、后序 b,c,d。先序首 b ≠ 后序尾 d ⟹ e 有两个孩子，左 b、右 d；d 下面只有 c 一个孩子。满足条件的树共 $2\times2=4$ 棵，但每一棵里 a 的孩子都只有 e。
::note
- {{扣|把「不能唯一确定树」当成「什么都确定不了」}}：不确定的只有「独生子挂左边还是右边」。
- 对照 2020 第 4 题、2021 第 4 题：那两题有中序，能把树完全画出来；没有中序时只做「首尾是否相同」这一步。
::vary
先序 a,b,c，后序 c,b,a，这样的二叉树有几棵 >> 每层都是独生子，每个独生子可左可右：$2\times2=4$ 棵
先序 a,b,d,c，后序 d,b,c,a，根有几个孩子 >> 去掉 a：先序首 b ≠ 后序尾 c ⟹ 两个孩子，左 b、右 c

#4
@ans B
@tpl TAVL最少结点
::rev
- **该花** 40 秒。「平衡因子全是 1」＝ 最省结点的平衡二叉树，写 1、2、4、7、12、20。
- **卡点** 没认出这是最少结点的情形；或递推漏了「+1」（根），写成斐波那契 1、2、3、5、8、13。
- **错了说明** 递推式 $N_h=N_{h-1}+N_{h-2}+1$ 没背，或不知道它是怎么来的。
- **带走** 看到「所有非叶结点平衡因子均为 1」就是「高度 h 时结点最少的平衡二叉树」，按 $N_h=N_{h-1}+N_{h-2}+1$ 列 1、2、4、7、12、20、33。
::read
「所有{{圈|非叶结点的平衡因子均为 1}}」 >> 每个非叶结点的左子树都恰好比右子树高 1 ⟹ 根的左子树高 5、右子树高 4，而且两棵子树自己也满足同样的条件 ⟹ 递推
::fast
{{秒|背数列 1、2、4、7、12、20}}，第 6 项是 20，选 B。
::steps
[[AVL|平衡因子]]＝左子树高 − 右子树高。设满足题意、高度为 $h$ 的树有 $N_h$ 个结点。
$h=1$：只有一个结点（叶子，没有非叶结点，条件自动满足），$N_1=1$。
$h=2$：根的平衡因子为 1 ⟹ 左子树高 1、右子树高 0（空）⟹ $N_2=2$。
$h\ge3$：根的左子树高 $h-1$、右子树高 $h-2$，两棵子树各自也是「非叶结点平衡因子全为 1」的树 ⟹ $N_h=N_{h-1}+N_{h-2}+1$。
| $h$ | 1 | 2 | 3 | 4 | 5 | 6 |
| $N_h$ | 1 | 2 | 4 | 7 | 12 | 20 |
$N_6=12+7+1=20$，选 **B**。
~这棵树也是高度为 6 的平衡二叉树里结点最少的：任何一个结点的两棵子树高度差都已经到了允许的上限。
::note
- {{扣|递推漏掉根}}：$N_h=N_{h-1}+N_{h-2}$ 会得到 13，不在选项里；发现算出的数不在选项里先查这个。
- C、D 是干扰：32、33 是 $2^5$、$2^5+1$，高度 6 的完全二叉树至少要 32 个结点，但平衡二叉树不必是完全二叉树。
- 这道题与「高度为 6 的平衡二叉树最少多少结点」「20 个结点的平衡二叉树最高几层」是同一张表。
::vary
含 12 个结点的平衡二叉树，最大高度是多少 >> $N_5=12\le12\lt N_6=20$ ⟹ 5 层
高度为 6 的平衡二叉树，所有非叶结点平衡因子均为 0，结点总数是多少 >> 每个结点左右等高 ⟹ 满二叉树，$2^6-1=63$
高度为 7、所有非叶结点平衡因子均为 −1，结点总数 >> 与全为 1 的情形左右对称，$N_7=20+12+1=33$

#5
@ans C
@tpl T图算法复杂度
::rev
- **该花** 15 秒。邻接表上遍历：顶点各访问一次，边表各扫一次。
- **卡点** 只想到「沿着边走」选 B，忘了还要逐个检查 n 个顶点；或记成邻接矩阵的 $O(n^2)$。
- **错了说明** 遍历的复杂度没和存储结构绑在一起记。
- **带走** 图的遍历（BFS、DFS 都一样）：邻接表 $O(n+e)$，邻接矩阵 $O(n^2)$；有向、无向不影响结论。
::read
「{{圈|邻接表}}存储的有向图进行广度优先遍历」 >> 复杂度由存储结构决定：邻接表 ⟹ $O(n+e)$
::fast
{{秒|邻接表 ⟹ O(n+e)}}，选 C。
::steps
BFS 的工作分两部分。
顶点部分：每个顶点入队一次、出队一次；外层还要把 n 个顶点的访问标记检查一遍（图可能不连通）⟹ $O(n)$。
边部分：某个顶点出队时，顺着它的边表把邻接点看一遍。全图所有边表的结点总数：有向图是 $e$ 个（无向图是 $2e$ 个）⟹ $O(e)$。
合计 $O(n+e)$，选 **C**。
~若用邻接矩阵：找一个顶点的邻接点要扫一整行 n 个元素，n 个顶点共 $O(n^2)$，与 e 无关。
::note
- {{扣|把 n 省掉}}：e 可以是 0（全是孤立顶点），这时仍然要做 n 次，所以不能写 $O(e)$。
- 对照 2016 第 7 题：同一张「存储结构 × 算法」的表，那题问的是拓扑排序（邻接表也是 $O(n+e)$）。
::vary
把存储结构换成邻接矩阵，BFS 的时间复杂度 >> $O(n^2)$
邻接表存储的无向图做 DFS，空间复杂度（不算图本身） >> 访问标记数组 $O(n)$ ＋ 递归栈最深 $O(n)$ ⟹ $O(n)$

#6
@ans C
@tpl T反例排除
::rev
- **该花** 40 秒。上三角 ⟹ 弧只从小编号指向大编号 ⟹ 无环；再举一个不唯一的小例子。
- **卡点** 觉得「按编号顺序就是拓扑序」于是选 A（唯一）；或者选 B，把「可能不唯一」说成了「一定不唯一」。
- **错了说明** 「存在」和「唯一」是两个问题，没有分开判。
- **带走** 邻接矩阵是上（或下）三角 ⟹ 一定无环、拓扑序列存在；是否唯一要看每一步入度为 0 的顶点是不是只有一个。
::read
「矩阵中{{圈|主对角线以下的元素均为零}}」 >> $i\gt j$ 时 $A[i][j]=0$ ⟹ 只可能有从小编号到大编号的弧 ⟹ 沿任何路径编号只增不减，回不到起点 ⟹ 无环
「{{波|存在，可能不唯一}}」对比「存在，且不唯一」 >> B 说的是「一定不唯一」，C 说的是「有的唯一、有的不唯一」。只要找到一个唯一的例子和一个不唯一的例子，就是 C
::fast
{{秒|无环 ⟹ 存在。举两个 3 顶点的例子}}：只有弧 1→2、2→3 时唯一（1,2,3）；只有弧 1→2、1→3 时有两个（1,2,3 和 1,3,2）⟹ 选 C。
::steps
存在性：有向图有[[拓扑序]] ⟺ 无环。本题弧只能从小编号指向大编号 ⟹ 无环 ⟹ 拓扑序列一定存在（1,2,…,n 本身就是一个）。
唯一性：要看具体有哪些弧。
例 1：上三角里的弧为 1→2、2→3。每一步入度为 0 的顶点只有一个 ⟹ 只有 1,2,3，唯一。
例 2：弧为 1→2、1→3（第 2、3 行全 0）。输出 1 之后，2 和 3 的入度同时为 0 ⟹ 1,2,3 与 1,3,2 都行，不唯一。
两种情况都会出现 ⟹「存在，可能不唯一」，选 **C**。
::note
- {{扣|B 与 C 只差两个字}}：「且不唯一」＝一定不唯一，被例 1 否定。
- 反过来不成立：无环图的邻接矩阵不一定是三角矩阵（把顶点重新编号后才能变成上三角）。
- 对照 2021 第 7 题：那题给具体的图数拓扑序列个数，用的是同一个动作「每一步看入度为 0 的有几个」。
::vary
若邻接矩阵主对角线以下全为 0、且主对角线上方紧邻的那条斜线上（$A[i][i+1]$）全为 1，拓扑序列唯一吗 >> 唯一：存在路径 1→2→…→n，每个顶点都必须排在下一个之前，只能是 1,2,…,n
一个有向图的拓扑序列唯一，它的邻接矩阵一定是三角矩阵吗 >> 不一定，取决于顶点怎么编号；但按拓扑序重新编号后一定能写成上三角

#7
@ans C
@tpl TDijkstra表
::rev
- **该花** 1 分半。列 dist 表，每轮圈最小的，再用它更新邻接点。
- **卡点** 选完 c 没有用 c 去更新 f（5→不对，f 应变成 4），按初始的边权排序，选了 A。
- **错了说明** 每轮「选中一个 ⟹ 立刻用它松弛出边」这一步漏做。
- **带走** Dijkstra 的选点顺序就是各顶点最终最短距离从小到大的顺序；每选中一个，先更新它的出边再选下一个。
::read
「第一条最短路径的目标顶点是 b，第二条……是 c」 >> 题目已经替你做了前两轮；接着从「b、c 都选完」的状态往下列表
「{{圈|后续}}得到的其余各最短路径的目标顶点{{圈|依次}}是」 >> 问的是选点顺序 ⟹ 按最终 dist 从小到大排
::sk 330 150 列 | 先抄下 6 个顶点，每轮一行：圈出最小的，再改它的邻接点
s.cells(10,8,[['轮','b','c','d','e','f','选'],['1','!2','5','∞','∞','∞','b'],['2','','!3','5','∞','∞','c'],['3','','','5','7','!4','f'],['4','','','!5','7','','d'],['5','','','','!6','','e']],cw=[36,40,40,40,40,40,40],ch=22,size=11)
s.text(296,60,'红＝本轮',10,'r');s.text(296,74,'选中',10,'r')
::fast
{{秒|直接算每个顶点的最短距离}}：b 2、c 3（经 b）、f 4（经 c）、d 5（经 b）、e 6（经 d）⟹ 从小到大 b、c、f、d、e ⟹ 后三个是 f、d、e，选 C。
::steps
图中的弧（从题图读出）：a→b 2、a→c 5、b→c 1、b→d 3、c→d 3、c→e 4、c→f 1、d→e 1、d→f 4、e→f 1。做法见 [[TDijkstra表]]。
第 1 轮：dist＝b 2、c 5，其余 ∞。最小是 b（2），选 b。用 b 更新：c＝min(5, 2+1)＝3，d＝2+3＝5。
第 2 轮：c 3、d 5、e ∞、f ∞。选 c。用 c 更新：d＝min(5, 3+3)＝5，e＝3+4＝7，f＝3+1＝4。
第 3 轮：d 5、e 7、f 4。选 **f**。f 没有出边，不更新。
第 4 轮：d 5、e 7。选 **d**。用 d 更新：e＝min(7, 5+1)＝6。
第 5 轮：只剩 e（6），选 **e**。
后续顺序是 f、d、e，选 **C**。
::note
- {{扣|凭边权直觉排}}：a→c 的边权是 5，但 c 的最短距离是 3；一定要更新后再比。
- 提速：选项只问顺序，第 3 轮选出 f 就排除 A、B；再比较 d（5）和 e（7）即得 C。
- 对照 2016 第 8 题、2021 第 8 题：同样问选点顺序，表的列法完全相同。

**解法一（保底，时间 $O(mn)$）**
**1）基本设计思想** ⛳3
共同后缀的结点被两个链表共用，因此只需找到第一个同时属于两个链表的结点（地址相同）。依次取 str1 链表中的每个结点 p，对每个 p 从头扫描 str2 链表，若发现某结点 q 与 p 是同一结点（p == q），则 p 即为共同后缀的起始位置；若都没有，返回 NULL。
**2）算法描述** ⛳6
```
typedef struct Node{
    char data;
    struct Node *next;
} Node, *LinkList;
Node *FindBrute(LinkList str1, LinkList str2){
    Node *p, *q;
    for(p = str1->next; p != NULL; p = p->next)       // 表 1 的每个结点
        for(q = str2->next; q != NULL; q = q->next)   // 到表 2 里从头找
            if(p == q) return p;                      // 比的是结点地址，不是 data
    return NULL;                                      // 没有共同后缀
}
```

**解法二（最优，时间 $O(m+n)$）**
**1）基本设计思想** ⛳4
① 分别求出 str1、str2 所指两个链表的长度 m 和 n；② 令指针 p、q 分别指向两个链表的第一个数据结点，若 m > n，则 p 先后移 m−n 个结点，若 n > m，则 q 先后移 n−m 个结点，使 p、q 所指结点到表尾的长度相等；③ p、q 同步后移，直到 p、q 指向同一结点为止，该结点即为共同后缀的起始位置；若到表尾仍未相遇，则无共同后缀。
**2）算法描述** ⛳8
```
int Length(LinkList L){                 // 求表长（不算头结点）
    int len = 0;
    Node *p = L->next;
    while(p != NULL){ len++; p = p->next; }
    return len;
}
Node *FindCommon(LinkList str1, LinkList str2){
    int m = Length(str1), n = Length(str2);
    Node *p = str1->next, *q = str2->next;
    for(; m > n; m--) p = p->next;      // 表 1 长：p 先走 m-n 步
    for(; n > m; n--) q = q->next;      // 表 2 长：q 先走 n-m 步
    while(p != NULL && p != q){         // 尾部对齐后齐步走
        p = p->next;
        q = q->next;
    }
    return p;                           // 第一个地址相同的结点；没有则为 NULL
}
```

**第 1 问**。磁盘总块数＝$4\text{TB}\div1\text{KB}=2^{42}\div2^{10}=2^{32}$ 块。

**第 2 问**。文件＝预分配的连续区 ＋ 直接索引指向的块。

~严格说 16 位能表示的最大值是 $2^{16}-1$；标准答案按 $2^{16}$ 块算（块数字段存「块数减 1」即可），照它写。
直接索引：$512-8=504$ B，每项 6B ⟹ $504\div6=84$ 项 ⟹ $84\times1\text{KB}=84$ KB。
