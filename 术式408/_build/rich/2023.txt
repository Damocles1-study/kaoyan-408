#1
::read
「{{圈|顺序存储}}的有序表（长度为 n）」 >> 顺序存储＝数组，能按下标直接算地址（随机存取）；「有序」只帮得上查找（可以折半）
「平均时间复杂度为 {{圈|O(1)}} 的是」 >> 要找的是「不管 n 多大都一步完成」的操作——不能有循环、不能挪元素
「A 查找包含指定值元素」 >> 按值找：有序可折半，$O(\log_2 n)$；不是 $O(1)$
「B 插入包含指定值元素」 >> 先找位置，再把后面的元素整体后移一位：平均挪 $n/2$ 个 ⟹ $O(n)$
「C 删除第 i 个元素」 >> 位置已知，但第 i 个之后的元素都要前移补空：平均 $(n-1)/2$ 个 ⟹ $O(n)$
「D 获取第 i 个元素」 >> 按序号取：地址＝首址＋$(i-1)\times$元素长度，一步算出 ⟹ $O(1)$
::think
1. 顺序表的唯一「超能力」是随机存取：知道序号就能直接算出地址。
2. 凡是要「按值找位置」或者「挪动一串元素」的操作都和 $n$ 有关。
3. 四个选项里只有 D 是「按序号取」，其余三个不是要找就是要挪。
::fast
{{秒|顺序表 O(1) 的只有「按序号存取」}}：看到「第 i 个」＋「获取/修改」就是它；「第 i 个」＋「删除/插入」仍要挪元素，是 $O(n)$——C 和 D 只差一个动词。
::steps
顺序表的元素在内存里连续存放，第 $i$ 个元素的地址 $\mathrm{Loc}(a_i)=\mathrm{Loc}(a_1)+(i-1)L$（$L$ 为每个元素的长度），一次计算就得到。
A：按值查找。有序表可以折半，平均比较约 $\log_2 n$ 次 ⟹ $O(\log_2 n)$，不是 $O(1)$。
B：插入指定值。先找到插入位置（折半 $O(\log n)$），再把它之后的元素全部后移一位，平均移动 $n/2$ 个 ⟹ 整体 $O(n)$。
C：删除第 $i$ 个。位置不用找，但第 $i+1$～$n$ 个元素都要前移一位，平均移动 $(n-1)/2$ 个 ⟹ $O(n)$。
D：获取第 $i$ 个。直接按上面的地址公式取 ⟹ $O(1)$。选 **D**。
::note
- {{扣|把 C 当成 $O(1)$}}：「知道位置」只省掉了查找，没省掉移动。顺序表的删除、插入，时间都花在挪元素上。
- 对照链表：链表正好反过来——已知结点指针时插入删除 $O(1)$，按序号取第 $i$ 个要从头走 $O(n)$。
- 「有序」这个条件只影响 A（能折半），对 D 毫无影响——是个干扰修饰语。
::vary
同一顺序表，删除最后一个元素的时间复杂度 >> 不用挪任何元素，$O(1)$
改成单链表（带头结点），获取第 $i$ 个元素 >> 要从头顺着 next 走 $i$ 步，平均 $O(n)$
改成无序顺序表，删除第 $i$ 个元素且不要求保持次序 >> 用最后一个元素覆盖第 $i$ 个、表长减 1：$O(1)$
有序顺序表中插入一个值后仍保持有序，若用折半找位置，比较次数和移动次数分别是什么量级 >> 比较 $O(\log n)$，移动仍 $O(n)$，总体 $O(n)$

@tpl T双链表插入
::read
「非空[[双链表]] L，结点结构 [prev, data, next]」 >> 每个结点两个指针：插一个结点一共要改 {{圈|4 个指针}}
「在 p 所指结点（{{圈|非尾结点}}）之后插入 s」 >> 非尾 ⟹ p 后面确实有个原后继，记作 r，r→prev 也要改
「在执行 `s->next=p->next; p->next=s;` 后」 >> 已经做了 2 个：s→next＝r、p→next＝s。{{波|注意 p→next 已经不是 r 了}}
「还需要执行的是」 >> 还差 s→prev＝p、r→prev＝s；而此刻 r 只能写成 `s->next`
::sk 420 152 画 | 草稿：灰虚线是插入前的 p⇄r；①② 是题干已执行的两句，③④ 是 C 的两句，执行完图上 4 个指针全对

s.text(357,136,'r（原后继）',11,'g','middle')
s.text(10,146,'① s→next＝r ② p→next＝s ③ s→prev＝p ④ r→prev＝s',11)
::think
1. 插入一个结点要改 4 个指针，题干做了 2 个，选项要补另外 2 个：$s\to prev=p$、$r\to prev=s$。
2. 难点不在「要做什么」，而在「怎么写」：此刻 `p->next` 已经指向 s，不再是 r；能找到 r 的只有 `s->next`。
3. 所以选项里凡是用 `p->next->prev` 去表示 r→prev 的，都已经写到 s 身上去了。
4. 每个选项在草图上逐句执行，最后核对 4 个指针。
::fast
{{秒|题干执行后 `p->next` 就是 s}} ⟹ B、D 里的 `p->next->prev` 其实是 `s->prev`，B 让 s 指向自己、D 写成 s→prev＝s→prev，都没碰 r，排除；A 让 r→prev＝p，原样没改，排除 ⟹ C。
::steps
设原后继为 r。插入前：p→next＝r，r→prev＝p。
执行题干两句后：s→next＝r（①），p→next＝s（②）。此时还没有改的是 s→prev（尚未赋值）和 r→prev（仍指向 p）。
目标状态需要：s→prev＝p，r→prev＝s。此刻 r 只能通过 s→next 访问，p 可以直接用 p，也可以用 r→prev（它还是 p）。
A：`s->next->prev=p` 把 r→prev 设成 p（原样不变，没改成 s）✗；第二句 s→prev＝p ✓。r→prev 错，排除。
B：`p->next->prev=s` 中 p→next 已是 s，等于 s→prev＝s（指向自己）✗；接着 s→prev＝p 又改回来，但 r→prev 始终没改，排除。
C：`s->prev=s->next->prev`：s→next 是 r，r→prev 此刻还是 p ⟹ s→prev＝p ✓（③）；`s->next->prev=s` ⟹ r→prev＝s ✓（④）。4 个指针全对，选 **C**。
D：`p->next->prev=s->prev` 即 s→prev＝s→prev（没有意义）；`s->next->prev=p` 即 r→prev＝p，没改成 s ✗，排除。
~复算：程序把四个选项逐个在三个结点上执行，只有 C 得到 p⇄s⇄r 的正确双向链接。
::note
- C 的两句**不能交换顺序**：若先执行 `s->next->prev=s`，r→prev 就变成 s，再执行 `s->prev=s->next->prev` 会得到 s→prev＝s。指针题的每一句都要在「上一句改过的图」上读。
- 教材的标准顺序是先改 s 的两个指针、再改 r→prev、最后改 p→next：`s->next=p->next; p->next->prev=s; s->prev=p; p->next=s;`——把「p→next＝s」放最后，前面就能一直用 p→next 表示 r。本题故意把它提前，逼你改用 s→next。
- {{扣|只看「每句话看上去在改谁」}}：B 看着像在改 r→prev，实际改的是 s 自己。
::vary
在 p **之前**插入 s（p 不是头结点后第一个），写出 4 句 >> `s->prev=p->prev; p->prev->next=s; s->next=p; p->prev=s;`（同理，`p->prev=s` 放最后）
删除 p 的后继 q（q 非尾），要改几个指针，怎么写 >> 2 个：`p->next=q->next; q->next->prev=p; free(q);`
若题干只先执行了 `p->next=s;`，接下来怎么写才对 >> 原后继已经丢了，无法补救——必须先用临时指针保存 r：`r=p->next;` 要在 `p->next=s;` 之前
循环双链表在尾结点后插入 s，与本题有何不同 >> 尾结点的「原后继」就是头结点，代码完全一样，不需要「非尾结点」这个前提

@tpl T哈夫曼
::read
「6 个字符，频次 3, 4, 5, 6, 8, 10」 >> 频次就是权值，构造[[哈夫曼树]]
「哈夫曼编码的{{圈|加权平均长度}}」 >> ＝$\sum$(频次 × 码长) ÷ 总频次 ＝ WPL ÷ 36——{{波|别忘了除以总频次}}
「选项 2.4、2.5、2.67、2.75」 >> 都在 2～3 之间：等长编码要 $\lceil\log_2 6\rceil=3$ 位，哈夫曼一定 ≤ 3
::sk 420 200 画 | 草稿：每次取最小两个合并；合并出来的数（非叶结点）加起来就是 WPL
s.tree(('36',('15',('7',('3',),('4',)),('8',)),('21',('10',),('11',('5',),('6',)))),210,20,dx=100,dy=42,r=13,size=11)
s.text(165,132,'2 位',11,'r','middle');s.text(255,132,'2 位',11,'r','middle')
for x in (25,85,335,395): s.text(x,174,'3 位',10,'r','middle')
s.text(10,196,'WPL = 7+11+15+21+36 = 90   平均 = 90 ÷ 36 = 2.5',12,'b')
::think
1. 构造哈夫曼树：每次从集合里取两个最小的合并，新结点放回去。
2. WPL 两种算法互相验算：叶子权 × 深度；或者把每次合并得到的数加起来。
3. 最后一步除以总频次 36——选项给的是平均码长，不是 WPL。
::fast
{{秒|WPL＝所有合并出来的数之和}}：7、11、15、21、36，加起来 90；$90\div36=2.5$。不用画树也能算。
::steps
合并过程（每次取最小两个）：$\{3,4,5,6,8,10\}$ → 合并 3、4 得 7 → $\{5,6,7,8,10\}$。
合并 5、6 得 11 → $\{7,8,10,11\}$；合并 7、8 得 15 → $\{10,11,15\}$。
合并 10、11 得 21 → $\{15,21\}$；合并 15、21 得 36（根）。
读码长（深度）：8、10 在第 2 层，码长 2；3、4、5、6 在第 3 层，码长 3。
WPL $=(3+4+5+6)\times3+(8+10)\times2=54+36=90$；验算：非叶结点之和 $7+11+15+21+36=90$ ✓。
加权平均长度 $=90\div(3+4+5+6+8+10)=90\div36=2.5$，选 **B**。
::note
- {{扣|算出 90 就慌}}：90 不在选项里，是因为还没除以总频次。「加权平均长度」＝平均每个字符几位。
- 哈夫曼树形不唯一（相等权值的合并次序、左右孩子可以换），但 WPL 唯一，所以平均码长唯一。
- 等长编码需要 3 位，哈夫曼省到 2.5 位，压缩了约 17%。
::vary
若改用等长编码，平均码长是多少 >> $\lceil\log_2 6\rceil=3$ 位
频次改为 1, 2, 4, 8, 16, 32，平均码长 >> 每次合并都是「新结点＋下一个」，码长 5,5,4,3,2,1：WPL $=5+10+16+24+32+32=119$，总 63 ⟹ $119/63\approx1.89$
本题哈夫曼树一共有几个结点，有没有度为 1 的结点 >> $2\times6-1=11$ 个结点，没有度为 1 的结点
给出一组可能的编码（左 0 右 1） >> 3：000、4：001、8：01、10：10、5：110、6：111（左右可交换，码长不变）

后序的最后一个是根：a 填在最上面的圈。
后序顺序是「左子树 → 右子树 → 根」。根的左子树有 4 个结点、右子树 1 个结点 ⟹ 后序前 4 个 f, d, b, e 属于左子树，第 5 个 c 是右子树（右孩子）。

1. Prim、Kruskal 求最小生成树：只管所有边加起来最小，不管某两点之间走多远。
2. 「一定能」⟹ 只要造出一张图让 MST 上的路径比最短路径长，Ⅰ、Ⅱ 就排除。最小反例：边权全 1 的三角形。
3. BFS 在边权全相等的图上，按层扩展的层数就是最短距离 ⟹ Ⅲ 一定行。
::fast
{{秒|MST ≠ 最短路径树}}，三角形一画就排除 Ⅰ、Ⅱ ⟹ 选项里不含 Ⅰ、Ⅱ 的只有 B（仅 Ⅲ）。

Ⅲ：BFS 从源点出发一层层扩展，第 $k$ 层的顶点恰是从源点出发至少要走 $k$ 条边才能到的顶点；边权全为 1 时路径长度＝边数 ⟹ BFS 生成树上的路径就是最短路径 ✓。

边权全为 1 时，深度优先搜索能否求最短路径 >> 不能，DFS 可能先绕远路到达某顶点；反例同样是三角形：DFS 走 a→b→c，c 的深度是 2

{{秒|快些选堆}}：五个里命中希尔、快速、堆 ⟹ Ⅰ、Ⅲ、Ⅳ，选 C。含 Ⅱ（归并）或 Ⅴ（基数）的选项全排除。
::steps
希尔排序：按增量把元素分到不同子表各自排序，相等的元素可能被分进不同子表、各排各的，相对次序会乱 ⟹ 不稳定。
归并排序：合并两个有序段时，相等元素先取前一段的，相对次序不变 ⟹ 稳定。
快速排序：划分时从两头交换，反例 {3, 2, 2̄} 以 3 为枢轴划分后变成 {2̄, 2, 3}（草图）⟹ 不稳定。
堆排序：建堆和每趟把堆顶换到末尾都会跨越交换，反例 {1, 2, 2̄} 建大根堆后输出顺序颠倒 ⟹ 不稳定。
基数排序：每趟按某一位分配进桶（队列，先进先出）、再按序收集，相等的元素保持原序 ⟹ 稳定。
不稳定的是 Ⅰ、Ⅲ、Ⅳ，选 **C**。
~复算：五种算法各写一份，在 2000 组含重复关键字的随机数据上检查相等元素的先后，被抓到颠倒的恰是希尔、快排、堆。
::note
- {{扣|勾成稳定的那一栏}}：题干问「不稳定」，草稿两栏写好后回头再看一眼题干。
- 稳定性与实现有关：归并里把 `<=` 写成 `<`、基数排序里把队列换成栈，都会变得不稳定。考试默认教材的标准写法。
- 简单选择是「简单方法里唯一不稳定的」：{2, 2̄, 1} 第一趟 1 与第一个 2 交换 ⟹ 两个 2 颠倒。
::vary
稳定的是：直接插入、简单选择、冒泡、堆 >> 直接插入、冒泡
链表上实现的简单选择排序（每趟把最小结点摘下接到新链尾）稳定吗 >> 稳定：不再跨越交换，只是按序摘取（取第一个最小者）
对 {5, 3, 3̄, 1} 做简单选择排序，写出第一趟后的序列并判断稳定性 >> 1 与 5 交换：{1, 3, 3̄, 5}，这一趟碰巧没颠倒；换成 {3, 3̄, 1} 第一趟 1 与 3 交换得 {1, 3̄, 3} ⟹ 不稳定

@tpl T主频周期
::read
「主频 1.5GHz」 >> 每秒 $1.5\times10^9$ 个时钟周期；一个周期 $\frac{1}{1.5}$ ns ≈ 0.667 ns
「指令条数 $5\times10^5$」「平均 [[CPI]] 1.2」 >> 总周期数＝条数 × CPI＝$6\times10^5$
「{{圈|指令执行速度}}」 >> 每秒执行多少条指令（IPS）＝主频 ÷ CPI
「{{圈|用户 CPU 时间}}」 >> 程序 P 自己占 CPU 的时间＝总周期数 ÷ 主频
「选项 0.8 / 1.25 GIPS，0.4 ms / 0.4 μs」 >> 两个小问各有一对：一个算反了公式，一个错了量级
::think
1. 速度：每条指令平均 1.2 个周期，每秒 $1.5\times10^9$ 个周期 ⟹ 每秒 $1.5\times10^9/1.2$ 条。
2. 时间：总周期 $5\times10^5\times1.2$，除以每秒周期数。
3. 用量纲防反：周期/秒 ÷ 周期/条＝条/秒。
::fast
{{秒|量纲}}：速度只能是「主频 ÷ CPI」＝1.25G，排除 A、B（0.8＝1.2÷1.5 是倒过来除的）；时间 $\approx5\times10^5$ 条 ÷ $1.25\times10^9$ 条/秒 $=4\times10^{-4}$ s，是毫秒级 ⟹ C。
::steps
指令执行速度 $=\dfrac{\text{主频}}{\text{CPI}}=\dfrac{1.5\times10^9\ \text{周期/s}}{1.2\ \text{周期/条}}=1.25\times10^9$ 条/s $=1.25$ GIPS。
程序 P 的总时钟周期数 $=5\times10^5\times1.2=6\times10^5$。
用户 CPU 时间 $=\dfrac{6\times10^5}{1.5\times10^9}\ \text{s}=4\times10^{-4}\ \text{s}=0.4$ ms。
~交叉验证：时间＝指令条数 ÷ 速度 $=5\times10^5\div(1.25\times10^9)=4\times10^{-4}$ s，一致。
所以是 1.25 GIPS、0.4 ms，选 **C**。
::note
- {{扣|ms 与 μs 混}}：$10^{-3}$ s＝1 ms，$10^{-6}$ s＝1 μs。$4\times10^{-4}$ s＝0.4 ms。
- GIPS＝$10^9$ 条/秒，MIPS＝$10^6$ 条/秒：本题也可以写成 1250 MIPS。
- 「用户 CPU 时间」只算程序自己的指令，不含 I/O 等待、OS 开销——题目给的条数就是 P 的，直接算。
::vary
若 CPI 降到 0.8，速度和时间变成多少 >> 速度 $1.5\text{G}/0.8=1.875$ GIPS；时间 $5\times10^5\times0.8/1.5\times10^9\approx0.267$ ms
若主频翻倍、CPI 也因访存等待变成 1.8，性能提升多少 >> 时间比 $\frac{1.2/1.5}{1.8/3}=\frac{0.8}{0.6}$ ⟹ 快了约 1.33 倍
程序中 60% 指令 CPI＝1、40% 指令 CPI＝1.5，平均 CPI >> $0.6\times1+0.4\times1.5=1.2$（正好是本题的 1.2）

所以 OF＝0、CF＝1，选 **B**。
::note
- {{扣|「减一个负数＝加」所以不会借位}}：那是有符号的想法。CF 只看无符号，负数在无符号眼里是很大的正数。
- 两组数据结果相同不是巧合：两次都是「小数减大数（无符号）、结果不出有符号范围」。
- x86 用两套条件跳转：JA / JB 看 CF（无符号比较），JG / JL 看 OF 与 SF（有符号比较）——同一条 cmp 指令两种用法。
::vary
x＝$2^{31}-1$，y＝−1，执行 x 减 y 的 OF、CF >> 有符号 $2^{31}$ 溢出 OF＝1；无符号 $(2^{31}-1)-(2^{32}-1)\lt0$ 借位 CF＝1
x＝−1，y＝1，执行 x 减 y >> 有符号 −2 不溢出 OF＝0；无符号 $(2^{32}-1)-1$ 够减 CF＝0
x＝10，y＝−20，执行 x 加 y >> 有符号 −10 不溢出 OF＝0；无符号 $10+(2^{32}-20)=2^{32}-10$，没有超出 32 位，无进位 CF＝0
用 OF、SF、ZF 判断「有符号 x ＜ y」的条件 >> $SF\oplus OF=1$

::think
1. A、B 是一对：异常在指令执行过程中检测，中断在指令执行结束时检测——标准说法。
2. C 的「检测到」三个字已经包含「没被屏蔽」：屏蔽了就检测不到；开中断时检测到了当然响应。
3. D 凭空造了一个「中断结束信号」：一次中断只有请求、响应、类型号这几种信号，结束靠中断返回指令。
::fast
{{秒|「中断结束信号」是不存在的名词}}：中断服务程序以中断返回指令结尾，CPU 执行它就自己回去了 ⟹ D。
::steps
A：异常（内中断）由正在执行的指令引起，如缺页、除数为 0、非法操作码，CPU 在执行这条指令的过程中就能检测到 ⟹ 正确。
B：中断（外中断）来自 CPU 外部，与当前指令无关；CPU 在每条指令执行结束时检查有无中断请求 ⟹ 正确。
C：开中断时，CPU 在指令结束时检测中断请求，检测到就响应；被中断屏蔽字屏蔽的低级请求根本检测不到，所以「检测到 ⟹ 响应」成立 ⟹ 正确。
D：外设通过中断控制器向 CPU 发的是**中断请求**信号；中断服务程序执行完后，靠最后一条中断返回指令（IRET）自行返回，不需要外设发什么「中断结束信号」⟹ 错误。选 **D**。

1. 中断响应要在极短时间内完成：由中断类型号 n 找到入口地址。
2. 「按序号找」正是顺序存储（数组）的强项：地址一算就到，$O(1)$。
3. 链表要从头走 n 步；队列只能从队头取，根本不支持按号查。
4. 而且中断向量表开机后大小固定、几乎不变，链表擅长的插入删除用不上。

::steps
中断向量表存放各中断服务程序的入口地址，中断类型号就是表项的序号。
CPU 响应中断时取得中断类型号 n，需要立即找到第 n 个表项：用数组存储，表项地址＝表基址＋n×表项长度，一次计算即可访问，$O(1)$。
用单向或双向链表，要从表头开始沿指针走 n 步，$O(n)$，还要额外存指针；队列只支持在两端操作，不能按序号访问。
中断类型号个数由硬件决定、表的大小固定，开机初始化后基本不改，不需要插入删除。
所以适合采用数组，选 **A**。

2. 内存、硬盘多大只决定「这个空间里有多少能真正放下数据」，即虚拟存储器的实际容量。

B：用户程序使用的地址都是虚拟地址，malloc() 返回的指针也是虚拟地址，由 MMU 在访问时转换 ⟹ 正确。

**（1）基本设计思想** ⛳4
有向图用邻接矩阵存储时，顶点 $k$ 的出度等于矩阵第 $k$ 行非零元素的个数，入度等于第 $k$ 列非零元素的个数。依次对每个顶点 $k$ 扫描第 $k$ 行和第 $k$ 列，分别统计出度 outdegree 与入度 indegree；若 outdegree ＞ indegree，则 $k$ 是 K 顶点，输出 `G.VerticesList[k]` 并将计数器 count 加 1。所有顶点处理完毕后返回 count。
**（2）算法实现** ⛳7
```
int printVertices(MGraph G){
    int k, m, indeg, outdeg, count = 0;          /* count：K 顶点个数 */
    for(k = 0; k < G.numVertices; k++){
        indeg = outdeg = 0;
        for(m = 0; m < G.numVertices; m++){
            if(G.Edge[k][m] != 0) outdeg++;      /* 第 k 行非零元个数 = 出度 */
            if(G.Edge[m][k] != 0) indeg++;       /* 第 k 列非零元个数 = 入度 */
        }
        if(outdeg > indeg){                      /* 出度大于入度：K 顶点 */
            printf("%c ", G.VerticesList[k]);
            count++;
        }
    }
    return count;                                /* 返回 K 顶点的个数 */
}
```
**（3）复杂度** ⛳2
设顶点数为 $n$。两重循环共访问矩阵元素 $2n^2$ 次，时间复杂度 $O(n^2)$；只使用常数个辅助变量，空间复杂度 $O(1)$。

1. 改错题先默写标准写法：`key=TRUE; while(key==TRUE) swap(key,lock); 临界区; lock=FALSE;`，再逐行比对。
2. 差异一：if 应为 while——swap 之后 key 拿到 lock 的旧值，旧值为 TRUE 说明有人在里面，必须再试，直到换回 FALSE。
3. 差异二：退出区应置 FALSE——题目规定 FALSE 才能进。
4. 第 2 问抓「原子性」：swap 是一条硬件指令，执行中不会被打断；newSwap 是三条语句，读 lock（`*a=*b`）与写 lock（`*b=temp`）之间可能切换，两个线程都读到 FALSE。必须给出一个具体交错。
::steps
标准写法：进入区 `key=TRUE; while(key==TRUE) swap key, lock;`，退出区 `lock=FALSE;`。
错误 ①：`if (key == TRUE)` 应改为 `while (key == TRUE)`。swap 执行后 key 中是 lock 原来的值：若原来是 TRUE（已有线程在临界区），用 if 只判断一次，仍会继续往下执行进入临界区，互斥失效；用 while 则一直交换，直到换回 FALSE（说明原来没人，并且自己已把 lock 置为 TRUE）才进入。
错误 ②：退出区 `lock = TRUE;` 应改为 `lock = FALSE;`。线程离开临界区要把锁打开，FALSE 表示其他线程可以进入；写成 TRUE 后其他线程永远进不去。
第 2 问：不能代替。swap 指令由硬件保证原子执行；newSwap() 是由三条语句组成的普通函数，执行中可能发生线程切换，而形参 b 指向共享变量 lock，函数中对 lock 先读（`*a=*b`）后写（`*b=temp`），读和写之间被打断就不能保证交换的原子性。
具体交错（草图）：lock＝FALSE。线程 A 执行 `temp=*a`（temp＝TRUE）、`*a=*b`（key_A＝FALSE）后被切换；线程 B 执行完整个 newSwap：key_B＝FALSE、lock＝TRUE，while 条件不成立，进入临界区；切回 A，A 执行 `*b=temp`（lock＝TRUE），key_A 为 FALSE，A 也进入临界区 ⟹ 两个线程同时在临界区，互斥失败。
~复算：把三种写法建成状态机穷举所有交错——if 版即使用原子 swap 也会同时进入；while＋原子 swap 永不同时进入；while＋newSwap 存在同时进入的交错。
::paper

① 进入区的 `if (key == TRUE)` 应改为 `while (key == TRUE)`。⛳2
