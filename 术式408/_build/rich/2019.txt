#1
@tpl T循环次数
::read
「设 n 是描述问题规模的非负整数」 >> 问的是循环次数随 $n$ 增长的阶，不用管 $n=0$ 这类边角
「`x=0;`」 >> 循环变量从 0 开始，**每次只加 1** ⟹ 循环次数就等于 $x$ 最后的值
「`while(n>=(x+1)*(x+1))`」 >> 条件里藏着{{圈|平方}}：能继续 ⟺ $(x+1)^2\le n$ ⟹ $x$ 最多长到 $\sqrt n$ 附近
「`x=x+1;`」 >> 线性增长，不是倍增——排除 $\log_2 n$
::sk 400 150 | 草稿：拿 $n=10$ 手跑一遍，$x$ 停在 3＝$\lfloor\sqrt{10}\rfloor$
s.cells(14,10,[['x','(x+1)²','n≥?','做不做'],['0','1','10≥1','✓'],['1','4','10≥4','✓'],['2','9','10≥9','✓'],['!3','16','10≥16','✗ 停']],cw=[34,56,62,56],ch=22,size=12)
s.text(240,40,'循环体执行 3 次',12)
s.text(240,64,'3 = ⌊√10⌋',13,'r',bold=True)
s.text(240,96,'一般地：执行 k 次后 x = k',12,'b')
s.text(240,118,'停的时候 (k+1)² > n',12,'b')
s.text(240,140,'⟹ k ≈ √n',13,'r')
::think
1. 循环变量每次 $+1$，所以「执行次数＝$x$ 的终值」。
2. 只要找出 $x$ 停在多大：条件 $(x+1)^2\le n$ 一旦不成立就停。
3. 解不等式就得到次数的阶。
::fast
{{秒|条件里是 $x$ 的平方和 $n$ 比，$x$ 又是每次加 1}} ⟹ $x$ 走到 $\sqrt n$ 就停 ⟹ $O(n^{1/2})$。看到「平方 ≤ n」直接想开方。
::steps
设循环体执行了 $k$ 次。因为 $x$ 从 0 开始每次加 1，执行 $k$ 次后 $x=k$。
循环继续的条件是 $n\ge(x+1)^2$；第 $k$ 次执行前条件成立：$n\ge k^2$；第 $k+1$ 次判断时不成立：$n<(k+1)^2$。
所以 $k^2\le n<(k+1)^2$，即 $k=\lfloor\sqrt n\rfloor$。
~用 $n=10$ 验证（草图）：$x$ 依次为 0、1、2 时条件成立，$x=3$ 时 $16>10$ 停，执行 3 次＝$\lfloor\sqrt{10}\rfloor$。
时间复杂度 $T(n)=O(\sqrt n)=O(n^{1/2})$，选 **B**。
::note
- 判断复杂度只看「循环体执行次数的最高阶」，循环里那句 `x=x+1` 是基本语句。
- 对照三种增长方式：`x=x+1` 配 `x<n` 是 $O(n)$；`x=x*2` 配 `x<n` 是 $O(\log n)$；`x=x+1` 配 `x*x<n` 是 $O(\sqrt n)$。
- {{扣|看到 while 就想 $\log$}}：$\log$ 来自倍增，本题是加 1。
::vary
把条件改成 `while(n>=x*x*x)` >> 执行到 $x^3>n$ 停，$x\approx\sqrt[3]n$ ⟹ $O(n^{1/3})$
把 `x=x+1` 改成 `x=x*2`、初值 `x=1`，条件仍为 `n>=x*x` >> 执行 $k$ 次后 $x=2^k$，停在 $4^k>n$ ⟹ $k\approx\frac12\log_2n$ ⟹ $O(\log n)$
外面再套一层 `for(i=1;i<=n;i++)`，内层每次从 `x=0` 重跑本循环 >> 内层次数与 $i$ 无关，都是 $\lfloor\sqrt n\rfloor$ ⟹ $O(n\sqrt n)$
内层条件改成 `while(i>=(x+1)*(x+1))`（随外层 $i$ 变） >> 内层 $\lfloor\sqrt i\rfloor$ 次，求和 $\sum_{i=1}^n\sqrt i\approx\frac23n^{3/2}$ ⟹ 仍是 $O(n^{3/2})$，但要按 [[T循环求和]] 列表求和

::read
「将一棵树 T 转化为对应的二叉树 BT」 >> 「对应」＝[[孩子兄弟]]：左指针＝第一个孩子，右指针＝下一个兄弟
「BT 的遍历中，其遍历序列与 T 的{{圈|后根}}遍历序列相同」 >> 树只有先根、后根两种（没有中根）；两种各对应二叉树的一种遍历
「先序 / 中序 / 后序 / 按层」 >> 背的是那张两行表：先根 ↔ 先序，**后根 ↔ 中序**；拿不准就画三个结点的小树验证
::sk 420 186 | 草稿：画最小的「一个根挂三个孩子」，左边写树的后根，右边转成二叉树写中序，两者一样
s.node(70,26,'1');s.node(30,86,'2');s.node(70,86,'3');s.node(110,86,'4')
s.edge(70,26,30,86);s.edge(70,26,70,86);s.edge(70,26,110,86)
s.text(10,128,'后根：2 3 4 1',12,'b')
s.text(10,150,'先根：1 2 3 4',12,'g')
s.arrow(140,60,190,60,'r');s.text(146,50,'孩子兄弟',11,'r')
s.tree(('1',('2',None,('3',None,('4',)))),240,22,dx=44,dy=32)
s.text(296,50,'左指针＝第一个孩子',11,'g');s.text(296,72,'右指针＝下一个兄弟',11,'g')
s.text(250,158,'BT 中序：2 3 4 1 ✓',12,'r')
s.text(250,178,'BT 后序：4 3 2 1 ✗',12,'g')
::think
1. 树的后根遍历：先依次后根遍历各棵子树，最后访问根。
2. 翻译成二叉树：根的孩子们挂在根的**左子树**里（左指针 → 第一个孩子，孩子们之间用右指针连成一串）。
3. 「孩子们都先于根」＝「左子树先于根」；「根访问完再去访问它的兄弟」＝「根先于右子树」⟹ 左 → 根 → 右 ⟹ 中序。
::fast
{{秒|画三个结点就够}}：根 1 挂孩子 2、3。树后根 2 3 1；二叉树是 1 的左孩子 2、2 的右孩子 3，中序 2 3 1，后序 3 2 1 ⟹ 中序。或者直接背 ==后根 ＝ 中序==。
::steps
树 T 的后根遍历规则：对每个结点，先从左到右依次后根遍历它的各棵子树，再访问它自己。
在 BT 中，结点 $v$ 的左子树＝$v$ 的全部子孙（第一个孩子及其兄弟链），右子树＝$v$ 在 T 中右边的兄弟们及其子孙。
后根遍历中，$v$ 的子孙都在 $v$ 之前访问 ⟺ BT 中 $v$ 的左子树先于 $v$；访问完 $v$ 再去访问它右边的兄弟 ⟺ $v$ 先于 BT 中 $v$ 的右子树。
「左子树 → 根 → 右子树」正是中序遍历，所以 T 的后根序列＝BT 的中序序列，选 **B**。
~验证（草图）：树 1(2,3,4) 的后根 2 3 4 1；BT 为 1 的左孩子 2、2 的右孩子 3、3 的右孩子 4，中序 2 3 4 1，一致；后序是 4 3 2 1，不一致。
::note
- 只有两组对应：==先根 ↔ 先序；后根 ↔ 中序==。森林也一样（森林先根＝二叉树先序，森林后根＝二叉树中序）。
- {{扣|凭名字联想「后根 ↔ 后序」}}：这是 C 选项的来路。草图里一试就露馅。
- 按层遍历与 BT 的层序不对应：树里同一层的兄弟在 BT 里被右指针拉成了斜线，层次全变了。
::vary
同一棵树，与 T 的{{圈|先根}}序列相同的是 BT 的哪种遍历 >> 先序遍历
森林 F 转成二叉树 B，F 的后根序列是 $b,a,d,c$，问 B 的中序 >> 就是 $b,a,d,c$，不用建树（2020 第 4 题同一结论）
树 T 有 $n$ 个结点、叶子 $n_0$ 个，问 BT 中左指针为空的结点数 >> 叶子没有孩子 ⟹ 左指针空 ⟹ 恰为 $n_0$ 个
已知 BT 的先序 1 2 3 4、中序 2 3 4 1，还原 T >> 先建 BT：1 的左孩子 2，2 的右孩子 3，3 的右孩子 4 ⟹ T 是 1 挂三个孩子 2、3、4

@tpl T度数方程, T哈夫曼
::read
「n 个互不相同的符号进行{{圈|哈夫曼编码}}」 >> 每个符号是一片叶子 ⟹ 叶子数＝$n$
「生成的哈夫曼树共有 {{圈|115}} 个结点」 >> 哈夫曼树每次合并两个造一个新结点，**没有度为 1 的结点**——[[严格k叉树]]，$k=2$
「n 的值」 >> 反解 $2n-1=115$
::sk 380 140 | 草稿：$n=3$ 的小例子数一下结点：3 片叶子合并 2 次，共 5＝2×3−1 个
s.tree(('6',('3',('1',),('2',)),('3',)),110,24,dx=56,dy=42)
s.text(30,138,'叶 3 个 + 合并新建 2 个 = 5',12,'b')
s.text(210,40,'n 片叶 ⟹ 合并 n−1 次',12)
s.text(210,62,'每次新建 1 个结点',12)
s.text(210,90,'总数 = n + (n−1) = 2n−1',13,'r')
s.text(210,118,'2n−1 = 115 ⟹ n = 58',13,'r',bold=True)
::think
1. 哈夫曼树只有度 0（叶子＝符号）和度 2（合并出来的）两种结点。
2. 用 $n_0=n_2+1$ 把总数写成叶子数的式子，再反解。
::fast
{{秒|哈夫曼树结点总数一定是奇数 $2n-1$}} ⟹ $n=(115+1)/2=58$。
::steps
叶子数 $n_0=n$（每个符号一片叶子）。
构造过程每次取两棵树合并、新建一个根，共合并 $n-1$ 次 ⟹ 度为 2 的结点 $n_2=n-1$，且没有度为 1 的结点。
~也可由 [[T度数方程]]：$n_0+n_2=2n_2+1$ ⟹ $n_0=n_2+1$。
总结点数 $=n_0+n_2=n+(n-1)=2n-1$。
$2n-1=115$ ⟹ $n=58$，选 **C**。
::note
- 结点总数是偶数的「哈夫曼树」不存在——题目若给偶数，一定是陷阱或别的树。
- 同一个公式的反问法：给总数求叶子数 $(N+1)/2$；给叶子数求分支结点 $n-1$。
- 哈夫曼编码的码字数＝叶子数，不是结点数；{{扣|把 115 当成符号数}}。
::vary
若改成{{圈|3 叉}}哈夫曼树（每次合并 3 个），共 115 个结点，求叶子数 >> $n_0=2n_3+1$，$n_0+n_3=115$ ⟹ $n_3=38$，$n_0=77$
对 58 个符号做（二叉）哈夫曼编码，最长码字最多多少位 >> 树最高时是一条「斜链」，高 58，最长码 57 位
有 58 个叶子的二叉树一定有 115 个结点吗 >> 不一定，允许度为 1 的结点时可以更多；只有「没有度 1 结点」（如哈夫曼树）才是 $2n-1$

@tpl TAVL旋转, T反例排除
::read
「{{圈|任意}}一棵非空平衡二叉树 T₁」 >> 选项要对所有 AVL 都成立才算对；「一定」类说法造一个反例就倒——[[T反例排除]]
「删除某结点 v 之后形成平衡二叉树 T₂」 >> 删除后可能失衡 ⟹ 可能**旋转**，形态会变
「再将 v 插入 T₂ 形成 T₃」 >> AVL 插入永远先插在叶子位置，失衡再旋转
「Ⅰ 若 v 是叶结点，则 T₁ 与 T₃ {{波|可能}}不相同」 >> 「可能」：找到一个「不同」的例子就对
「Ⅱ 非叶结点 ⟹ {{波|一定}}不相同；Ⅲ 非叶结点 ⟹ {{波|一定}}相同」 >> 两个「一定」方向相反：各找一个反例
::sk 440 270 | 草稿：三个最小例子，每行「T₁ → 删 v → 插回 v」
s.text(6,16,'Ⅰ 删叶 1：',12,'r')

s.arrow(160,46,190,46);s.text(162,38,'删 1',10,'g')
s.text(196,30,'2 失衡',10,'r');s.text(196,44,'RL 旋转',10,'r')
s.tree(('3',('2',),('4',)),270,22,dx=24,dy=28,r=10,size=11)
s.arrow(310,46,336,46);s.text(312,38,'插 1',10,'g')
s.tree(('3',('2',('1',),None),('4',)),390,22,dx=24,dy=28,r=10,size=11)
s.text(330,104,'≠ T₁ ⟹ Ⅰ 对',11,'r')
s.text(6,130,'Ⅱ 删非叶 2：',12,'r')
s.tree(('2',('1',),('3',)),110,124,dx=24,dy=28,r=10,size=11)
s.arrow(150,138,186,138);s.text(150,130,'后继 3 顶上',10,'g')

s.text(368,150,'= T₁ ⟹ Ⅱ 错',11,'r')
s.text(6,206,'Ⅲ 删非叶 3：',12,'r')

s.arrow(160,214,190,214);s.text(160,206,'4 顶上',10,'g')
s.tree(('2',('1',),('4',)),226,200,dx=24,dy=26,r=10,size=11)
s.arrow(260,214,290,214);s.text(262,206,'插 3',10,'g')
s.tree(('2',('1',),('4',('3',),None)),336,200,dx=24,dy=26,r=10,size=11)
s.text(376,248,'≠ T₁ ⟹ Ⅲ 错',11,'r')
::think
1. 三个说法都是「若…则…」，不用证明，各造一个最小的 AVL 试一下。
2. 「可能不同」要一个「不同」的正例；「一定不同」「一定相同」各要一个反例。
3. 最小的例子用 3～4 个结点就够；删除有两个孩子的结点时用中序后继（或前驱）顶替，两种约定结论都一样。
::fast
{{秒|措辞已经泄底}}：Ⅰ 说「可能」，Ⅱ、Ⅲ 都说「一定」且方向相反——Ⅱ、Ⅲ 不可能同时对；AVL 有旋转这个变数，「一定」几乎站不住 ⟹ 先猜「仅 Ⅰ」，再用草图上的例子各坐实一下。
::steps
Ⅰ（v 是叶子）：取 T₁＝2(1, 4(3,·))，平衡。删叶子 1 后，结点 2 的左高 0、右高 2，失衡，属 RL 型，双旋后 3 上位得 3(2,4)。
再插入 1：1＜3 走左，1＜2 成为 2 的左孩子，得 3(2(1,·),4)，各结点平衡、不再旋转。
T₃ 的根是 3，T₁ 的根是 2，二者不同 ⟹ 「可能不相同」成立，**Ⅰ 正确**。
~（若删叶子不引起失衡，插回去它回到原位，T₃＝T₁——所以只能说「可能」不同。）
Ⅱ（v 非叶、说「一定不同」）：取 T₁＝2(1,3)，删根 2（有两个孩子，用中序后继 3 顶替）得 3(1,·)，平衡。
插回 2：2＜3 走左，2＞1 成为 1 的右孩子；结点 3 失衡，属 LR 型，双旋后 2 上位，得 2(1,3)＝T₁。找到了「相同」的例子 ⟹ **Ⅱ 错误**。
Ⅲ（v 非叶、说「一定相同」）：取 T₁＝2(1, 3(·,4))，删 3（只有右孩子 4，4 顶上）得 2(1,4)，平衡。
插回 3：3＞2 走右，3＜4 成为 4 的左孩子，得 2(1, 4(3,·))，平衡不旋转。与 T₁ 中「3 是 4 的父亲」不同 ⟹ **Ⅲ 错误**。
只有 Ⅰ 正确，选 **A**。
::note
- 对照 2013 年的 BST 版本：BST 没有旋转 ⟹ 删叶再插回**一定相同**、删非叶再插回**一定不同**。AVL 多了旋转，两个「一定」都被打破，只剩「可能」。
- 删除有两个孩子的结点：用前驱或后继顶替都行，本题三个例子在两种约定下结论相同（复算脚本对 4000 棵随机 AVL 也找到了三类情形）。
- {{扣|选 C（仅 Ⅰ、Ⅱ）}}：以为「非叶结点插回来一定变成叶子」，忘了插入后还会旋转，旋转能把它重新送回内部。
::vary
把 T₁ 换成普通二叉排序树（不调平），三个说法谁对 >> 删叶再插回一定相同（Ⅰ 错）；删非叶再插回一定不同（Ⅱ 对、Ⅲ 错）——这正是 2013 真题
AVL 中依次插入 1、2、3、4、5、6、7 后的根 >> 4（每次失衡都 RR 单旋，最终是满二叉树 4(2(1,3),6(5,7))）
AVL 删除一个结点，最多需要几次旋转 >> 可能沿路径向上连锁失衡，最多 $O(\log n)$ 次；插入最多只需调整最低失衡点那一次（一次单旋或双旋）
在 T₁＝3(2(1,·),4) 中删叶子 4，再插回 4，T₃ 是什么 >> 删 4 后 3 失衡（LL），右旋得 2(1,3)；插回 4 成 3 的右孩子，得 2(1,3(·,4))，与 T₁ 不同

- 干扰项 9 是漏了失配那一次；15 是朴素算法的次数（6＋1＋2＋6）。

::vary

「B 操作系统为{{波|每个用户级线程}}建立一个线程控制块」 >> ULT 由用户空间的线程库管理，内核根本看不见它们 ✗
「C 用户级线程间的切换比内核级线程间的切换效率高」 >> ULT 切换不进内核 ✓
「D 用户级线程可以在不支持内核级线程的操作系统上实现」 >> 线程库自己实现，内核只看见进程 ✓
::think
1. 用户级线程的定义就是「内核感知不到」：OS 只给进程建 PCB。
2. 若 OS 为每个 ULT 建了 TCB，它就知道这些线程、能单独调度——那就成了内核级线程，B 自相矛盾。
::fast
{{秒|自洽性检验}}：OS 为 ULT 建 TCB ⟹ OS 能看见并调度它 ⟹ 它就是 KLT ⟹ B 自我否定。
::steps
A：内核级线程的创建、撤销、切换和调度都由操作系统内核完成，应用程序只有调用接口——正确。
B：用户级线程的控制块由用户空间的线程库建立和维护（放在用户空间的链表或数组里），操作系统只为整个进程建立 PCB，不知道用户级线程的存在，不会为它们建 TCB——错误。
C：用户级线程切换在用户空间由线程库完成，不需要陷入内核；内核级线程切换要进内核、由 OS 调度 ⟹ 用户级线程切换效率更高——正确。
D：用户级线程的管理全在用户空间，不依赖内核支持，所以能在只支持进程的操作系统上实现——正确。
选 **B**。
::note
- 用户级线程两优：切换快、可移植（C、D）；两劣：一个线程阻塞整个进程阻塞、多个线程不能在多核上并行。
- 内核级线程的 TCB 由 OS 建立、放在内核空间。
- 多对一模型就是纯用户级线程；一对一是纯内核级线程；多对多兼顾两者。
::vary
一个进程有 3 个用户级线程，其中一个执行阻塞的 read 系统调用，其余两个能运行吗 >> 不能：内核只看见进程，整个进程被阻塞
同样 3 个用户级线程，在 4 核 CPU 上最多几个同时运行 >> 1 个：内核把整个进程当作一个调度单位
采用内核级线程时，调度的基本单位是什么 >> 线程（内核级线程）；资源分配的基本单位仍是进程

@tpl T链表三板斧
::read
「L＝($a_1,a_2,\dots,a_{n-1},a_n$) 采用{{圈|带头结点}}的单链表保存」 >> 头结点不存数据；只能从前往后走，没有前驱指针
「空间复杂度为 {{圈|O(1)}}」 >> 不许把结点复制到数组里再重排——只能改指针
「时间上{{圈|尽可能高效}}」 >> 目标 $O(n)$；每次去尾部找 $a_n$ 的 $O(n^2)$ 拿不到满分
「得到 L′＝($a_1,a_n,a_2,a_{n-1},a_3,a_{n-2},\dots$)」 >> 前半段正着取、后半段**倒着**取，交替穿插 ⟹ 后半段要先逆置

1. 结构上看：L′ 是「前半段 $a_1,a_2,a_3,\dots$」与「后半段倒过来 $a_n,a_{n-1},\dots$」交替合并。
2. 单链表倒着取代价高 ⟹ 先把后半段就地逆置，变成正着取。
3. 三步都是 $O(n)$ 的链表基本操作：快慢指针找中点 → 头插法逆置后半段 → 两个链表交替合并。
4. 找中点要让前半段的长度为 $\lceil n/2\rceil$（奇数时前半多一个），这样交替插入时后半段先用完。
::steps
设指针 p、q 都从头结点出发：q 每次走两步、p 每次走一步；q 走到尾结点时 p 恰好在前半段的最后一个结点（前半段 $\lceil n/2\rceil$ 个）。
  为什么：q 走过的结点数是 p 的两倍，q 到第 $n$ 个结点时 p 在第 $\lceil n/2\rceil$ 个。
令 q＝p→next 指向后半段第一个结点，并置 p→next＝NULL，把链表断成两段。
用头插法把后半段逐个插到 p 的后面：每摘下一个结点 q，就令 q→next＝p→next、p→next＝q。后半段由 $a_{\lceil n/2\rceil+1},\dots,a_n$ 变成 $a_n,\dots,a_{\lceil n/2\rceil+1}$。
令 s＝h→next 指向前半段第一个结点，q＝p→next 指向逆置后的后半段第一个结点，再置 p→next＝NULL（前半段以 NULL 结尾）。
交替插入：把 q 插到 s 之后，然后 s 跳到「q 原来的后继」即前半段下一个结点（s＝q→next），q 移到后半段下一个结点；直到后半段插完。
~手跑 $n=6$（草图）：中点 $a_3$；后半段逆置为 $a_6,a_5,a_4$；依次把 $a_6$ 插到 $a_1$ 后、$a_5$ 插到 $a_2$ 后、$a_4$ 插到 $a_3$ 后，得 $a_1,a_6,a_2,a_5,a_3,a_4$。
~手跑 $n=5$：中点 $a_3$（前半 3 个）；后半 $a_5,a_4$；结果 $a_1,a_5,a_2,a_4,a_3$，$a_3$ 收尾。
复杂度：三步各扫描链表一遍（或半遍），时间 $O(n)$；只用了几个指针变量，空间 $O(1)$。
::paper
**（1）基本设计思想** ⛳3
先观察 L′：它是由前半段 $a_1,a_2,\dots$ 与后半段逆序 $a_n,a_{n-1},\dots$ 交替合并而成。为了不使用额外空间，分三步：
① 用两个指针 p、q 从头结点出发，p 每次走一步、q 每次走两步，q 到达表尾时 p 指向中间结点（前半段最后一个结点）；
② 将 p 之后的后半段链表用头插法原地逆置；
③ 从前半段第一个结点和逆置后的后半段第一个结点开始，依次将后半段的结点插入前半段对应结点之后。
**（2）算法实现** ⛳8
```
typedef struct node {
    int data;
    struct node *next;
} NODE;

void change_list(NODE *h) {
    NODE *p, *q, *r, *s;
    p = q = h;
    while (q->next != NULL) {      /* 1. 找中间结点：p 走一步，q 走两步 */
        p = p->next;
        q = q->next;
        if (q->next != NULL) q = q->next;
    }
    q = p->next;                    /* q 指向后半段的第一个结点 */
    p->next = NULL;
    while (q != NULL) {             /* 2. 后半段用头插法逆置到 p 之后 */
        r = q->next;
        q->next = p->next;
        p->next = q;
        q = r;
    }
    s = h->next;                    /* s 指向前半段的第一个结点 */
    q = p->next;                    /* q 指向逆置后的后半段第一个结点 */
    p->next = NULL;                 /* 前半段以 NULL 结尾 */
    while (q != NULL) {             /* 3. 把后半段结点依次插到前半段结点之后 */
        r = q->next;                /* r 记住后半段的下一个结点 */
        q->next = s->next;
        s->next = q;
        s = q->next;                /* s 移到前半段的下一个结点 */
        q = r;
    }
}
```
**（3）复杂度** ⛳2
找中间结点、逆置后半段、交替合并各扫描链表一遍（或半遍），时间复杂度 $O(n)$；只使用常数个指针变量，空间复杂度 $O(1)$。
::note

**（1）存储方式** ⛳2
采用链式存储，用带队头指针 front 和队尾指针 rear 的**循环单链表**。顺序存储扩充空间时需整体移动元素，不能保证入队 $O(1)$，且无法做到空间只增不减地复用。
**（2）初始状态与判空、判满** ⛳3
初始时创建只含一个空闲结点的循环单链表，该结点的 next 指向自身，front 和 rear 都指向它（草图「初始」）。
约定 front 指向队头元素结点，rear 指向队尾元素之后的空闲结点，队列中始终保留一个空闲结点。
队空条件：`front == rear`；队满条件：`front == rear->next`。
**（3）第一个元素入队后的状态** ⛳2
链表中有两个结点构成环：front 指向存放该元素的结点，rear 指向其后的空闲结点（草图「入队 a 后」）；此时 `front == rear->next`，队列又满。
**（4）入队、出队的基本过程** ⛳3
入队：若 `front == rear->next`（队满），在 rear 之后插入一个新的空闲结点；将元素存入 rear 所指结点；`rear = rear->next`。
出队：若 `front == rear`（队空），出队失败；否则取出 front 所指结点的元素，`front = front->next`，结点不释放，留作以后入队使用。
参考代码（题目未要求，供对照）：
```
typedef int ElemType;
typedef struct QNode {
    ElemType data;
    struct QNode *next;
} QNode;
typedef struct {
    QNode *front, *rear;   /* front 指队头元素，rear 指队尾之后的空闲结点 */
} LinkQueue;

void InitQueue(LinkQueue *Q) {          /* 初始：一个空闲结点自成循环 */
    QNode *p = (QNode *)malloc(sizeof(QNode));
    p->next = p;
    Q->front = Q->rear = p;
}
int QueueEmpty(LinkQueue *Q) { return Q->front == Q->rear; }
int QueueFull(LinkQueue *Q)  { return Q->front == Q->rear->next; }

void EnQueue(LinkQueue *Q, ElemType x) {
    if (QueueFull(Q)) {                 /* 满：在 rear 后插入一个新空闲结点 */
        QNode *p = (QNode *)malloc(sizeof(QNode));
        p->next = Q->rear->next;
        Q->rear->next = p;
    }
    Q->rear->data = x;                  /* 存入 rear 所指的空闲结点 */
    Q->rear = Q->rear->next;            /* rear 移到下一个空闲结点 */
}
int DeQueue(LinkQueue *Q, ElemType *x) {
    if (QueueEmpty(Q)) return 0;        /* 队空 */
    *x = Q->front->data;
    Q->front = Q->front->next;          /* 结点不释放，留待复用 */
    return 1;
}
```

1. 第 1 问：算主机所在网络：.2/26、.3/26 在 192.168.1.0/26；.66/26、.67/26 在 192.168.1.64/26——两个不同网络 ⟹ 设备 1 要连接两个网络并隔离广播域 ⟹ 路由器；设备 2、3 只在本网络内连主机 ⟹ 交换机。
2. 第 2 问：交换机不配 IP；设备 1 的三个接口都要配。IF1 与 R 的 .253/30 在同一个 /30 块（.252～.255），可用的只有 .253、.254 ⟹ IF1＝.254；IF2、IF3 是两个 LAN 的默认网关 ⟹ .1 和 .65。
3. 第 3 问：H1～H4 都是 192.168.0.0/16 私有地址，Internet 上的路由器不转发 ⟹ R 做 NAT。
4. 第 4 问：.127＝.64/26 的主机号全 1 ⟹ LAN2 的直接广播地址；H3 在 LAN2 内广播，交换机转发给 LAN2 的所有主机，设备 1（路由器）不转发到 LAN1 ⟹ 只有 H4 收到。
::steps
网络地址：192.168.1.2/26 与 192.168.1.3/26，第 4 字节与掩码 192（1100 0000）相与得 0 ⟹ 网络 192.168.1.0/26（LAN1）；192.168.1.66/26、192.168.1.67/26 与 192 相与得 64 ⟹ 192.168.1.64/26（LAN2）。
LAN1 与 LAN2 是两个不同的网络（两个广播域），把它们连起来并转发 IP 分组的设备 1 必须是路由器；设备 2、设备 3 只连接同一网络内的主机，用以太网交换机。
交换机（无 VLAN）工作在数据链路层，接口不需要 IP 地址；只有设备 1（路由器）的 IF1、IF2、IF3 需要配置。
IF1 与 R 下口相连：192.168.1.253/30，253＝1111 1101，与 /30 掩码（252）相与得 252 ⟹ 链路网络 192.168.1.252/30，地址 .252（网络地址）、.253、.254、.255（广播），.253 已被 R 使用 ⟹ IF1＝192.168.1.254（掩码 255.255.255.252）。
IF2 连 LAN1，主机默认网关是 192.168.1.1 ⟹ IF2＝192.168.1.1（掩码 255.255.255.192）；IF3 连 LAN2，默认网关 192.168.1.65 ⟹ IF3＝192.168.1.65（掩码 255.255.255.192）。
H1～H4 的地址属于私有地址 192.168.0.0/16，不能在 Internet 上路由 ⟹ R 需提供 NAT（网络地址转换）服务，把私有地址转换为公网地址 101.1.2.10。
192.168.1.127 的第 4 字节 127＝0111 1111，在 192.168.1.64/26 中主机号（低 6 位）全 1 ⟹ 是 LAN2 的广播地址。H3 发出的该数据报在 LAN2 内广播，H4 接收；设备 1 是路由器，不转发广播 ⟹ LAN1 的 H1、H2 收不到；H3 是发送方本身。所以只有 H4 接收。
::paper
**（1）** H1、H2 的网络地址为 192.168.1.0/26，H3、H4 的网络地址为 192.168.1.64/26，属于两个不同的网络，需要由能隔离广播域、转发 IP 分组的路由器连接。所以设备 1 为路由器，设备 2、设备 3 为以太网交换机。 ⛳2
**（2）** 只有设备 1（路由器）的接口需要配置 IP 地址。 ⛳1
IF1 与 R 的接口 192.168.1.253/30 处于同一网络 192.168.1.252/30，该网络可分配地址只有 .253 和 .254，故 IF1 的 IP 地址为 192.168.1.254（子网掩码 255.255.255.252）。 ⛳1
IF2、IF3 分别为 LAN1、LAN2 的默认网关，IF2 的 IP 地址为 192.168.1.1，IF3 的 IP 地址为 192.168.1.65（子网掩码均为 255.255.255.192）。 ⛳2
**（3）** H1～H4 使用的是私有 IP 地址，R 需要提供 NAT（网络地址转换）服务。 ⛳1
**（4）** 192.168.1.127 是网络 192.168.1.64/26 的广播地址，路由器（设备 1）隔离广播域，该数据报只在 LAN2 内广播，因此只有主机 H4 会接收该数据报。 ⛳2
::note
- {{扣|第 2 问给交换机也配 IP}}：无 VLAN 的二层交换机不需要 IP 地址。
- {{扣|IF1 填 .252 或 .255}}：/30 的首尾是网络地址和广播地址，只剩 .253、.254。2023 年第 38 题同一招。
- {{扣|第 4 问答 H3、H4 或 H1～H4}}：发送方不算接收方；路由器挡住了到 LAN1 的广播。
- 第 3 问写「NAT」即可，展开说「把内网私有地址转换为 R 的公网地址 101.1.2.10」更稳。
::vary
若 H3 发送目的地址为 255.255.255.255 的数据报，谁会收到 >> 受限广播只在本网络内：LAN2 中的 H4
若 H1 发送目的地址为 192.168.1.127 的数据报，谁会收到 >> 直接广播要先由设备 1 转发到 LAN2；路由器默认不转发直接广播 ⟹ 通常无人接收（若路由器开启了定向广播转发，则 H3、H4 收到）
若把设备 1 也换成交换机，H1 能 ping 通 H3 吗 >> 不能直接通：两者不在同一网络，H1 会把分组发给网关 192.168.1.1，而这个网关地址已无设备使用
LAN1 还能再接多少台主机 >> /26 可分配 62 个，已用 H1、H2 和网关 .1 共 3 个 ⟹ 还能接 59 台
