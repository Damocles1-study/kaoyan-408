#1
::read
「头指针 h 指向一个{{圈|带头结点}}的{{圈|非空循环}}单链表」 >> 头结点不存数据，首元结点是 `h->next`；尾结点的 next 指回 h
「p 是{{圈|尾指针}}」 >> 删首元一般碰不到 p——{{波|唯一的例外：首元恰好也是尾结点}}（表里只有 1 个元素）
「q 是临时指针」 >> 删除的固定三步：q 记住要删的结点 → 前驱的 next 跨过它 → free(q)
「删除该链表的第一个元素」 >> 前驱是头结点 h；q 必须在改 `h->next` **之前**取，否则就取错了人
::sk 420 200 画 | 草稿：一般情况只改 h 的 next（红）；只剩一个结点时 p 也指着它，删后要把 p 拉回 h
s.text(10,14,'一般情况（≥2 个元素）',12,'b')
s.chain(20,40,['h','a₁','a₂','a₃'],cw=38,ch=24,gap=26)
s.text(126,36,'q',12,'r');s.text(254,36,'p',12,'b')
s.bend(40,40,167,40,k=-22,c='r');s.text(176,24,'h->next = q->next',11,'r')
s.bend(231,64,39,64,k=-20,c='g');s.text(135,98,'尾的 next 指回 h',10,'g','middle')
s.text(10,124,'只剩 1 个元素（p == q）',12,'b')
s.chain(20,134,['h','a₁'],cw=38,ch=24,gap=26)
s.bend(103,158,39,158,k=-14,c='g');s.text(126,130,'p、q',11,'r')
s.text(190,146,'摘链后 h->next = h（空表）',11)
s.text(190,170,'free(q) 后 p 悬空 ⟹ 必须 p = h',11,'r',bold=True)
::think
1. 删除操作的骨架永远是「先保存、再摘链、最后释放」，先用它筛选项的语句顺序。
2. 再想特殊情况：循环单链表带尾指针时，会动到尾结点的操作都要顺手维护 p。删首元什么时候会动到尾结点？——首元就是尾结点时。
3. 最后看条件写成 `p==q` 还是 `p!=q`。
::fast
{{秒|q 被 free 后若 p 还指着它就悬空}} ⟹ 特判条件只能是「p 和 q 指同一个结点」⟹ `if(p==q) p=h;` ⟹ D。A、B 连特判都没有，C 条件写反。
::steps
`q=h->next;` 先用 q 记住首元结点，它就是要删的那个。
`h->next=q->next;` 头结点直接连到第二个元素（若只有一个元素，q->next 是 h，于是 h->next＝h，表变空，正是空循环链表的样子）。
特殊情况：表里只有一个元素时，尾指针 p 也指向这个结点（p＝q）。不处理的话 free(q) 之后 p 指向被释放的内存。空循环单链表的尾就是头结点，所以写 `if(p==q) p=h;`。
`free(q);` 释放结点。四句连起来就是选项 D。
~核对 A：先执行 `h->next=h->next->next` 已经把首元摘掉了，再 `q=h->next` 取到的是原来的**第二个**元素，free 掉的是还挂在链上的结点；若只有一个元素，q 取到 h，连头结点都被释放。
~核对 B：多个元素时正确，只有一个元素时 p 悬空。
~核对 C：条件反了——多个元素时把 p 错改成 h，尾指针丢失；只有一个元素时反而不改。
答案 **D**。（复算：对长度 1 和长度 3 的表各执行四个选项，只有 D 两次都得到正确的表和尾指针。）
::note
- 改指针前先保存：凡是「先改 next 再去取」的写法几乎都是错的，这是所有链表题的第一条检查。
- {{扣|只考虑一般情况}}：带尾指针的循环链表，凡是删除/插入可能碰到尾结点，都要问一句「尾指针要不要改」。
- 带头结点的好处：空表与非空表处理统一，所以只需特判尾指针，不需要特判头指针。
::vary
不带头结点的循环单链表，h 指首元、p 指尾，删首元 >> `q=h; if(p==q) h=p=NULL; else { h=q->next; p->next=h; } free(q);`——要多改尾结点的 next
同一个带头结点循环单链表，在表尾插入结点 s >> `s->next=h; p->next=s; p=s;`，$O(1)$
同一个链表删除尾结点 >> 要找 p 的前驱，只能从 h 沿链走，$O(n)$；所以「只有尾指针的单链表」删尾不是 $O(1)$，要双向链表才行
只给尾指针 p（不给 h），删首元 >> 头结点是 `p->next`：`q=p->next->next; p->next->next=q->next; if(p==q) p=p->next; free(q);`

@tpl T受限双端队列
::read
「一端仅能进行入队操作，另一端既能入队又能出队」 >> 两端都能进、只有一端能出 ⟹ {{圈|输出受限}}的双端队列
「入队序列 1,2,3,4,5」 >> 每个元素只能按这个次序进队，但可以选左端或右端
「不能得到的出队序列」 >> 逐个选项看第一个出队的元素：它出队前，比它早进队的全在队里

1. 先确认结构：两端可入、一端可出 ⟹ 队里元素从第一个进队的元素向两边「长」，出口只有一个。
2. 对每个选项，看第一个要出的元素 $x$：$1\sim x$ 都已进队，它们的排列必须能按选项接下来的顺序从出口依次出来。
3. 只要某个选项排不出来就选它，不必把每个可行方案都写全（但考场上不放心可以验一两个）。
::fast
{{秒|四个选项里只有 D 以 4,1 开头且后面 3 在 2 前}}：4 出队后 1、2、3 都在队里，1 要紧接着出 ⟹ 1 在出口端；而 2、3 只能贴在「1 那一块」的两头——贴在出口一侧会挡住 1，只能都贴在另一侧，于是 1 后面必然是 2、3 ⟹ D 不可能。
::steps
约定左端是出口（能进能出），右端只能进。
A 5,4,3,1,2：1 进右、2 进右、3 进左、4 进左、5 进左 ⟹ 队里 [5,4,3,1,2]，从左依次出 ⟹ 可以。
B 5,3,1,2,4：1 进右、2 进右、3 进左、4 进右、5 进左 ⟹ [5,3,1,2,4] ⟹ 可以。
C 4,2,1,3,5：1 进右、2 进左 ⟹ [2,1]；3 进右 ⟹ [2,1,3]；4 进左 ⟹ [4,2,1,3]；依次出 4、2、1、3；最后 5 进、出 ⟹ 可以。
D 4,1,3,2,5：第一个出 4 ⟹ 1、2、3、4 都已进队，且 4 在出口端。第二个出 1 ⟹ 去掉 4 后，1 必须在最左。
  1 最先进队；2 进来只能在 1 的左边或右边，若在左边，1 就不在最左了 ⟹ 2 只能在 1 右边：[1,2]；3 同理只能在右边：[1,2,3]。
  于是出完 4、1 后队里是 [2,3]，只能先出 2 ⟹ 得不到「3 在 2 前」⟹ D 不可能。
答案 **D**。（复算：穷举每个元素的进队端与出队时机，5 个元素共可得 90 种序列，A、B、C 在其中，D 不在。）
::note
- 判这类题的核心画面：输出受限时，队里的排列就像往一根棍子两头串珠子——第一个进来的永远在「中间」，后来的只能挂两头。
- 输入受限（一端进、两端出）正好相反：队里顺序就是入队顺序，靠「两头都能取」来变顺序。
- {{扣|把题目的结构看反}}：「一端仅能入队」说的是那一端不能出，所以是输出受限，不是输入受限。
::vary
同一结构（输出受限），4 个元素 1,2,3,4 哪两个序列得不到 >> 4,1,3,2 和 4,2,3,1（共 22 种可得）
改成输入受限（一端进、两端出），本题 C 4,2,1,3,5 能得到吗 >> 不能：1～4 按顺序在队里 [1,2,3,4]，出 4 后两头是 1 和 3，取不到 2
改成输入受限，本题 D 4,1,3,2,5 能得到吗 >> 能：[1,2,3,4] 右出 4、左出 1、右出 3、出 2，最后 5 进出
若是普通栈，1～5 能否得到 4,1,3,2,5 >> 不能：4 出栈时 1、2、3 在栈里且 3 在栈顶，下一个只能是 3

「A[0][0] 的地址是 100，A[3][3] 的地址是 220」 >> 两个点 ⟹ 一个方程 ⟹ 解出{{圈|列数}}
「A[5][5] 的地址」 >> 解出列数后代公式
::sk 400 150 列 | 草稿：行优先排成一长条，A[3][3] 前面隔了 3 整行再加 3 个
s.cells(20,20,[['A[0][0]','…','A[0][n−1]'],['A[1][0]','…','…'],['A[2][0]','…','…'],['A[3][0]','…','!A[3][3]']],cw=[70,40,80],ch=22,size=11)

s.text(220,124,'3n + 3 = 220 − 100 = 120',12,'r',bold=True)
s.text(220,144,'n = 39',13,'r',bold=True)
::think
1. 行优先：数清楚目标元素前面有多少个元素。$A[3][3]$ 前面有 3 整行（$3n$ 个）加本行 3 个。
2. 地址差 ÷ 元素大小 ＝ 隔了几个元素 ⟹ 方程 $3n+3=120$。
3. 再用同一公式算 $A[5][5]$。
::fast
{{秒|i＝j 时地址差 ＝ $i(n+1)$}}：$3(n+1)=120$ ⟹ $n+1=40$ ⟹ $A[5][5]=100+5\times40=300$。
::steps
设每行 $n$ 个元素（列数为 $n$），行优先下标从 0：$\mathrm{LOC}(A[i][j])=100+(i\times n+j)\times1$。
代入 $A[3][3]$：$100+3n+3=220$ ⟹ $3n=117$ ⟹ $n=39$。
$\mathrm{LOC}(A[5][5])=100+5\times39+5=100+195+5=300$，选 **B**。
~核对：$300-220=120$，正好是「再隔 2 行（78 个）＋2 个（共 80）」？——$2\times39+2=80$，$220+80=300$ ✓。
::note
- 行数在本题里用不到，题目也没给；只要列数（每行多长）。
- 若题目说「每个元素占 $L$ 个单元」，方程两边都要带 $L$：$(3n+3)L=120$。
- 下标从 1 开始时先减 1：$A[i][j]$ 前面有 $(i-1)n+(j-1)$ 个元素。
::vary
若已知的是 $A[2][4]$ 的地址 220（其余不变），$A[5][5]$ 在哪 >> $2n+4=120$ ⟹ $n=58$ ⟹ $100+5\times58+5=395$
改成列优先，同样两点，$A[5][5]$ 在哪 >> 设行数 $m$：$3m+3=120$ ⟹ $m=39$，$A[5][5]=100+5\times39+5=300$（$i=j$ 时行、列优先结果对称）
本题求 $A[2][3]$（行优先）的地址 >> $100+2\times39+3=181$
每个元素占 2 个单元，$A[0][0]$＝100、$A[3][3]$＝220 >> $(3n+3)\times2=120$ ⟹ $n=19$ ⟹ $A[5][5]=100+(5\times19+5)\times2=300$

@tpl T哈夫曼
::read
「二叉树有 5 个叶结点，权值 10,12,16,21,30」 >> 带权叶子 ⟹ 想到 [[哈夫曼树]]
「{{圈|最小}}的带权路径长度」 >> 最小 WPL ＝ 哈夫曼树的 WPL，构造它就行
「选项 89」 >> $10+12+16+21+30=89$ 是根的权值，{{波|不是 WPL}}
::sk 420 190 画 | 草稿：每次合并最小的两个；WPL 直接把四个内结点的权加起来
s.text(10,20,'{10,12,16,21,30}',12);s.text(10,40,'10+12 → 22',12,'b');s.text(10,58,'16+21 → 37',12,'b');s.text(10,76,'22+30 → 52',12,'b');s.text(10,94,'37+52 → 89',12,'b')
s.text(10,130,'WPL = 22+37+52+89',12,'r');s.text(10,150,'    = 200',14,'r',bold=True)
s.tree(('89',('37',('16',),('21',)),('52',('22',('10',),('12',)),('30',))),290,22,dx=70,dy=46,r=13,size=11)
s.text(200,182,'10、12 深 3；16、21、30 深 2',11,'g')
::think
1. 「最小 WPL」就是要构造哈夫曼树，没有别的办法。
2. 构造：每次取集合中最小的两个合并。
3. WPL 用「非叶结点权值之和」算最快，再用「叶子权 × 深度」验一遍。
::fast
{{秒|WPL ＝ 所有合并结果之和}}：22＋37＋52＋89＝200 ⟹ B。89 是总和（根），一眼排除 A。
::steps
集合 {10,12,16,21,30}，最小的两个是 10、12 ⟹ 合并为 22，集合变为 {16,21,22,30}。
最小的两个是 16、21 ⟹ 合并为 37，集合 {22,30,37}。
最小的两个是 22、30 ⟹ 合并为 52，集合 {37,52}。
合并 37、52 ⟹ 89，就是根。
各叶子深度（根为第 1 层，路径长度＝深度 − 1）：10、12 在第 4 层，路径长 3；16、21、30 路径长 2。
$\mathrm{WPL}=(10+12)\times3+(16+21+30)\times2=66+134=200$，选 **B**。
~验算：$22+37+52+89=200$，两种算法一致。
::note
- 「WPL＝非叶结点权值之和」的理由：每个非叶结点的权值是它下面所有叶子的权值之和，每个叶子到根的路径上有几个非叶结点，它的权就被加了几次——正好是它的路径长度。
- 选项 289＝200＋89，是把根也重复算了一次；208 是算错了某个叶子的深度。

::sk 420 160 列 | 草稿：两条数轴。无符号时负数补码都跑到右端最大处；有符号时它们回到 0 的左边

::think
1. 无符号：直接按十六进制从高位往低比，不用换算。
2. 有符号：先看符号位，正的一定最大；两个负数用「补码数值位越大真值越大」比较。
3. 把四个选项分成两组（A、B 无符号；C、D 有符号），各算一次就能定。
::fast
{{秒|无符号 FFFD＞FFDF＞7FFC，A、B 的顺序都不对}}；有符号时 z 是唯一的正数，一定最大 ⟹ C（x＜y＜z）与 D（y＜x＜z）只差 x、y；同为负数补码，FFFD＞FFDF ⟹ x＞y ⟹ D。
::steps

有符号（补码，16 位）：z＝7FFCH 最高位 0 ⟹ 正数 32764。
x＝FFFDH 最高位 1 ⟹ 负数，真值 $65533-65536=-3$；y＝FFDFH ⟹ $65503-65536=-33$。
$-33<-3<32764$ ⟹ $y<x<z$，选 **D**。
~快速比较两个负数：同为 16 位补码负数，机器数（按无符号看）越大，真值越大——它们都等于「机器数 $-2^{16}$」，减的是同一个数。

- C 语言里 int 与 unsigned 比较时 int 会被转成 unsigned：`-1 > 0u` 为真，就是本题的翻转现象。

::vary
实现「短作业优先」非抢占调度，是否需要时钟中断处理程序 >> 不需要靠它来抢占（进程主动结束或阻塞时才调度）；但系统计时仍用时钟中断

@tpl T调度时机
::read
「{{圈|可能}}引起进程调度程序执行」 >> 口径宽：只要有机会触发调度就算，不要求「一定」
「Ⅰ 中断处理结束」 >> 中断返回前是 OS 的调度检查点（时钟中断发现时间片到了、I/O 完成唤醒了高优先级进程）
「Ⅱ 阻塞、Ⅲ 结束、Ⅳ 时间片用完」 >> 当前进程让出 CPU ⟹ 必然调度
::think
1. 先钉死口径：「可能引起」⟹ 宽口径。
2. Ⅱ、Ⅲ、Ⅳ 都让当前进程离开 CPU ⟹ 必然调度。
3. Ⅰ：中断处理完，OS 要决定返回原进程还是换一个 ⟹ 可能调度。
::fast
{{秒|「可能」口径下四个都对}} ⟹ D。
::steps
Ⅰ 中断处理结束：返回前 OS 检查是否需要调度，例如时钟中断处理后发现时间片用完、I/O 中断唤醒了更高优先级进程（抢占式）⟹ 可能引起调度。
Ⅱ 进程阻塞：当前进程放弃 CPU，就绪队列不空就调度新进程 ⟹ 引起。
Ⅲ 进程执行结束：释放 CPU ⟹ 引起。
Ⅳ 时间片用完：当前进程回就绪队列 ⟹ 引起。
四项都可能，选 **D**。
::note
- 口径要分清：问「可能引起」用宽口径（中断处理结束算）；问「直接原因 / 必然引起」用严口径（CPU 必须空出来）。
- 三个标准调度检查点：中断返回前、系统调用返回用户态前、当前进程主动放弃 CPU 时。
- 不能调度的时刻：处理中断过程中、在 OS 内核临界区中、原子操作中。
::vary
「新进程创建并进入就绪队列」可能引起调度吗 >> 抢占式系统中可能（新进程优先级更高）；非抢占式不会立即引起
进程在内核临界区（访问就绪队列）时能否进行调度 >> 不能，否则可能破坏内核数据结构
进程在普通临界区（如打印机）内能否被调度 >> 可以

- 优先级记法：$(A,M)$ 当二进制数，$00<01<10<11$，越小越先被淘汰；同级时看指针位置。
- 页框只有两个，所以「扫圈、清 A」可以一眼比出来；页框多时必须老老实实转指针。
::vary

若改用简单 CLOCK（只看访问位），指针指向页 3 >> 两页 A 都是 1：页 3 清 0 跳过、页 4 清 0 跳过，回到页 3 淘汰 ⟹ 60A01H
访问虚拟地址 03B20H，物理地址 >> 页 3 在内存，页框 60H ⟹ 60B20H，不缺页
本题缺页处理时，被换出的页 3 需要写回磁盘吗 >> 不需要：M＝0，没被修改过；若换出页 4（M＝1）才要写回

~公式验证：$m>n(k-1)=n(2-1)=n$ ⟹ $m\ge n+1$。
~复算：对 $n=2\sim6$ 穷举所有逐个申请的状态，$m=n$ 时存在死锁状态，$m=n+1$ 时不存在。
::note

2. 邻接矩阵上，无向图顶点 $i$ 的度 ＝ 第 $i$ 行非零元素的个数；两重循环扫一遍矩阵。

::steps
设 $n$＝G.numVertices。对每个顶点 $i$（$0\le i\lt n$），令 degree＝0，扫第 $i$ 行的 $n$ 个元素，遇到非零就 degree 加 1。
  为什么数非零而不是直接相加：若矩阵存的是 0/1，相加也对；写成「非零计数」对带权的情况也不出错，更稳。
第 $i$ 行扫完，若 degree 为奇数，count 加 1。
所有顶点处理完：count 为 0 或 2 ⟹ 返回 1；否则返回 0。
~count 不可能是奇数：所有顶点度之和 ＝ $2|E|$ 是偶数 ⟹ 奇度顶点必成对出现。所以 `count<=2` 与 `count==0||count==2` 在本题等价，但照题干写「0 或 2」最稳。
~手跑草图例子：度 2、2、3、1，奇度顶点 2 个 ⟹ 返回 1；确实存在 D→C→A→B→C 这样走遍 4 条边的路径。
复杂度：外层 $n$ 次、内层 $n$ 次 ⟹ 时间 $O(n^2)$；辅助变量 i、j、degree、count ⟹ 空间 $O(1)$。
::paper
**（1）算法的基本设计思想** ⛳4
无向图用邻接矩阵存储时，顶点 $i$ 的度等于邻接矩阵第 $i$ 行（或第 $i$ 列）中非零元素的个数。依次扫描邻接矩阵的每一行，求出各顶点的度，用 count 统计度为奇数的顶点个数。扫描结束后，若 count 为 0 或 2，则 G 存在 EL 路径，返回 1；否则返回 0。
**（2）算法实现** ⛳8
```
int IsExistEL(MGraph G) {
    int i, j, degree, count = 0;          /* count：度为奇数的顶点个数 */
    for (i = 0; i < G.numVertices; i++) {
        degree = 0;
        for (j = 0; j < G.numVertices; j++)
            if (G.Edge[i][j] != 0)        /* 第 i 行非零元素个数即顶点 i 的度 */
                degree++;
        if (degree % 2 != 0)              /* 度为奇数的顶点计数 */
            count++;
    }
    if (count == 0 || count == 2)         /* 奇度顶点数为不大于 2 的偶数 */
        return 1;                         /* 存在 EL 路径 */
    else
        return 0;                         /* 不存在 EL 路径 */
}
```
**（3）复杂度** ⛳3
算法需要扫描整个邻接矩阵，时间复杂度为 $O(n^2)$（$n$ 为顶点数）；只使用了常数个辅助变量，空间复杂度为 $O(1)$。
::note
- 本代码已 gcc 编译，在 3000 个随机无向图（含与 Python 统计结果对拍）上零失配；另用暴力搜索在 400 个随机连通小图上验证了「奇度顶点 0 或 2 ⟺ 存在一笔画」这条定理本身。
- {{扣|三问缺一问}}：思想、代码、复杂度各有分；代码没写全时，把思想和复杂度写清楚也能拿大半分。

**（1）** ⛳3
cmpCountSort 中 count[i] 记录数组 a 中比 a[i] 小的元素个数（相等元素按比较规则计入），a[i] 的最终位置就是 b[count[i]]。对本题数据求得 count＝{5, 0, 4, 1, 2, 3}，所以

**（2）** ⛳2
每个元素都与它后面的所有元素各比较一次（所有元素两两比较一次），比较次数为 $(n-1)+(n-2)+\cdots+1=\dfrac{n(n-1)}{2}$。
**（3）** ⛳3

```
void cmpCountSort(int a[], int b[], int n) {
    int i, j, *count;
    count = (int *)malloc(sizeof(int) * n);
    for (i = 0; i < n; i++) count[i] = 0;
    for (i = 0; i < n - 1; i++)
        for (j = i + 1; j < n; j++)
            if (a[i] <= a[j]) count[j]++;   /* 原为 <：相等时改为给靠后的 a[j] 计数 */
            else count[i]++;
    for (i = 0; i < n; i++) b[count[i]] = a[i];
    free(count);
}
```
::note
- 本代码与原代码都已 gcc 编译，在 2000 组含大量重复值的随机数据上验证：结果有序；比较次数恒为 $n(n-1)/2$；原代码相等元素必定倒序、修改后必定保持原序。
- {{扣|第 2 问只答 $O(n^2)$}}：问「比较次数」要给精确式子 $n(n-1)/2$；问「复杂度」才给数量级。
- {{扣|第 3 问只答「不稳定」}}：题目要求「修改为稳定排序算法」，要写出改后的那一行（或整段）并指出改了什么。
- 这不是 8.5 节按值域计数的计数排序：本题靠两两比较，比较次数 $n(n-1)/2$、时间 $O(n^2)$、空间 $O(n)$，能处理负数；值域计数排序不比较、$O(n+k)$，只适合范围不大的非负整数。
- 同年第 10 题考「LSD 靠稳定才成立」，本题考「少个等号就不稳定」——2021 年两道题都盯着稳定性。
::vary

  0 号组只有 16，7 号组只有 7，2 号组有 10、26 两个——都不超过 2 路，不会替换。

**（1）** ⛳2

**（2）** ⛳2

**（4）** ⛳1

::note

- {{扣|第（2）问只写虚页号的位而没换成虚拟地址的位号}}：题目问「虚拟地址中哪几位」，写 A29～A15、A14～A12 最稳，两种都写更好。

::vary

1. 第 1 问：多个进程都会读写 S，wait 里的「判断＋减 1」、signal 里的「加 1」都是读-改-写，交错执行会丢失更新或让两个进程同时通过 wait。
2. 第 2 问：关中断的效果是「本进程不会被切换下去」。方法 1 在 S≤0 时关着中断死等，能改变 S 的只有别的进程的 signal，而它们根本得不到 CPU ⟹ 死循环。方法 2 在循环里开一下中断，别的进程就能被调度、执行 signal。
3. 第 3 问：开/关中断影响整个系统，是特权指令，只能在内核态执行。
::steps
（1）信号量 S 是多个进程共享的变量，多个进程都通过 wait() 和 signal() 读、写 S。
  例如两个进程同时执行 wait 且 S＝1：都读到 S＞0、都通过了循环，再各减 1，两个进程同时进入临界区；或两次 `S=S+1` 交错只加了 1——共享变量的读-改-写必须互斥。
（2）方法 1 错误：在 wait() 中关中断后，若 S≤0，进程进入 while 循环。此时中断被关闭，时钟中断等无法响应，不会发生进程切换，其他进程无法运行，也就不能执行 signal() 增大 S ⟹ 循环条件永远成立，while 陷入死循环（系统卡死）。
  方法 2 正确：while 循环体内先开中断再关中断，开中断期间允许中断和进程切换，其他进程可以运行并执行 signal() 修改 S；重新关中断后再判断 S，判断与 `S=S-1` 仍在关中断状态下执行，保证了对 S 访问的互斥。

  ~（补充）即使允许，用户关中断后可能不再打开，系统就失控了；而且多处理机上关中断只对本 CPU 有效，不能实现互斥。
::paper
**（1）** ⛳2
信号量 S 是能被多个进程共享的变量，多个进程都可以通过 wait() 和 signal() 对 S 进行读、写操作。若不互斥执行，可能因读-改-写交错而使 S 的值出错，因此对 S 的访问必须互斥。
**（2）** ⛳4
方法 1 错误。在 wait() 中，当 S≤0 时，进程在关中断状态下执行 while 循环，此时其他进程无法被调度运行，不能修改 S 的值，while 语句陷入死循环。
方法 2 正确。方法 2 在 while 循环体中先开中断、再关中断，使其他进程有机会运行并修改 S 的值，从而避免 while 语句陷入死循环；对 S 的判断和修改仍在关中断状态下进行，保证了互斥。
**（3）** ⛳2
用户程序不能使用开/关中断指令实现临界区互斥。因为开中断和关中断指令都是特权指令，不能在用户态下执行，只能在内核态下执行。
::note
- 复算：用一个小模型（单处理机、只有开中断时才可能切换进程）穷举所有调度，方法 1 存在走不出来的状态，方法 2 从任何状态都能走到「两个进程都完成」。
- 三问的关键词一定要落在卷面上：「关中断后不会发生进程切换 / 其他进程无法运行」「死循环」「特权指令、只能在内核态执行」。

- 本卷第 23 题（I/O 指令是特权指令）和本题第 3 问是同一条知识。
::vary
多处理机系统中，方法 2 还能保证互斥吗 >> 不能：关中断只关本 CPU，另一个 CPU 上的进程可同时读写 S；要用 TSL、Swap 等原子指令（或自旋锁）
若把方法 2 的 signal 改成不开关中断、直接 `S=S+1`，会有什么问题 >> 单处理机上 signal 可能在读-改-写中途被切换，与另一个进程的 wait 交错，导致更新丢失
用关中断实现互斥有什么缺点 >> 限制了并发（关中断期间不能响应中断），交给用户不安全，不适用于多处理机
方法 1 中若把 while 改为「S≤0 时调用 block 阻塞自己」，还要注意什么 >> 阻塞前必须开中断（或由 block 原语负责切换），否则同样卡死；这就是记录型信号量的实现思路

::think
1. 先排「H1 要做的事」：用域名访问 ⟹ 先发 DNS 查询；拿到 Web 服务器的 IP 后发现它不在本网段 ⟹ HTTP 请求要交给默认网关 R。
2. 每发一个 IP 分组前问：下一跳的 MAC 知道吗？ARP 表为空 ⟹ DNS 查询前要 ARP 问 DNS 服务器（同网段，直接问它）；HTTP 前要 ARP 问 R。两次 ARP 请求都是广播。
3. 交换机：每收到一帧，记（源 MAC，进入端口）；目的是广播或未知 ⟹ 泛洪，已知 ⟹ 单播。
4. H2 从头到尾没发过帧 ⟹ 不在交换表里；它只能收到被泛洪的帧。
::steps
（1）H1 用域名访问，必须先把 www.abc.com 解析成 IP 地址 ⟹ 还运行了 DNS。
  DNS 报文交给传输层 UDP（DNS 查询用 UDP，端口 53），加 UDP 首部成为 UDP 数据报；交给网络层，封装成 IP 数据报；交给数据链路层，封装成以太网帧（标准答案写「CSMA/CD 帧」）。
  ⟹ DNS 报文 → UDP 数据报 → IP 数据报 → CSMA/CD 帧（以太网帧）。
（2）按时间排 t₀～t₁ 的帧，跟踪 S 的交换表：
  ① H1 要发 DNS 查询，本地域名服务器与 H1 同网段，但 ARP 表空 ⟹ H1 广播 ARP 请求（目的 MAC 全 F）。S 从端口 4 收到，记下 cc→4；广播帧从端口 1、2、3 泛洪。
  ② 本地域名服务器单播 ARP 响应给 H1：S 从端口 1 收到，记下 bb→1；目的 cc 已知 ⟹ 只从端口 4 转出。
  ③④ H1 发 DNS 查询、收到 DNS 响应：源 MAC 分别是 cc、bb，交换表里已有，不增加表项；都按表单播，H2 收不到。
  ⑤ H1 得到 Web 服务器的 IP，判断它不在本网段 ⟹ 要发给默认网关 R；ARP 表中没有 R 的 MAC ⟹ 再广播一次 ARP 请求。S 已有 cc→4，泛洪该帧。
  ⑥ R 单播 ARP 响应：S 从端口 2 收到，记下 aa→2，转给端口 4。
  ⑦ H1 发出封装 HTTP 请求的帧（目的 MAC 为 R 的 aa）⟹ 这就是 t₁。
  H2 没有发送过任何帧，S 不会记录它。t₁ 时刻交换表：（00-11-22-33-44-cc，4）、（00-11-22-33-44-bb，1）、（00-11-22-33-44-aa，2）。
（3）H2 只能收到 S 泛洪的帧：①、⑤ 两个 ARP 请求（广播）。其余帧的目的 MAC 都已在交换表中，S 定向转发，不经过端口 3。
  ⟹ H2 至少收到 2 个帧，都是封装 ARP 查询（请求）报文的以太网帧，目的 MAC 地址都是 FF-FF-FF-FF-FF-FF。
  ~为什么是「至少」：本地域名服务器若没有缓存，要经 R 向外迭代查询，它自己也可能广播 ARP 问 R 的 MAC，H2 会再收到一个广播帧；题目问的是最少情况。
::paper
**（1）** ⛳3
H1 还运行了 DNS 协议（把域名 www.abc.com 解析为 IP 地址）。逐层封装：DNS 报文 → UDP 数据报 → IP 数据报 → CSMA/CD 帧（以太网帧）。
**（2）** ⛳3
t₁ 时刻 S 的交换表：
| MAC 地址 | 端口 |
| 00-11-22-33-44-cc | 4 |
| 00-11-22-33-44-bb | 1 |
| 00-11-22-33-44-aa | 2 |
（H1 先后广播 ARP 请求查询本地域名服务器和路由器 R 的 MAC 地址，S 由收到的帧学习到 H1、本地域名服务器和 R 的 MAC 地址与端口的对应关系；H2 未发送帧，不在表中。）
**（3）** ⛳3
H2 至少接收到 2 个与此次 Web 访问相关的帧，都是封装 ARP 查询报文（ARP 请求）的以太网帧，帧的目的 MAC 地址均为 FF-FF-FF-FF-FF-FF。
::note
- {{扣|漏了第二次 ARP}}：访问外网主机时，ARP 问的是默认网关 R 的 MAC，不是 Web 服务器的——第 2 问少 aa 一行、第 3 问答成 1 个帧。
- {{扣|交换表里写上 H2（dd）}}：自学习只记发过帧的源地址，H2 只是被动收到广播。
- 第 1 问的数据链路层，教材在解析里自己补了一句：写「以太网 V2 帧（以太网帧）」更合适，因为交换机全双工工作时不用 CSMA/CD；考场上照标答写「CSMA/CD 帧」，后面括号注明以太网帧最稳。
- 复算：按 7 帧的时间顺序模拟交换机的学习与转发，交换表与 H2 收到的帧和上面一致。
- 这是第一道成型的「全栈题」：一次 Web 访问串起 DNS、UDP、IP、ARP、交换机——2023 年的综合题沿着同一条路往下问了 TCP 和 HTTP 的 RTT（[[TRTT账本]]）。
::vary
若 t₀ 时 H1 的 ARP 表中已有本地域名服务器的 MAC（S 的交换表仍为空），H2 至少收到几个帧 >> 2 个：H1 的 DNS 查询帧（目的 bb，S 还没学到 ⟹ 泛洪）和问 R 的 ARP 请求（广播）
若把交换机 S 换成集线器，t₀～t₁ 之间 H2 收到几个帧 >> 集线器向所有端口转发：2 个 ARP 请求、2 个 ARP 响应、DNS 查询、DNS 响应，共 6 个
若 Web 服务器与 H1 在同一局域网，H1 第二次 ARP 问谁 >> 直接问 Web 服务器的 MAC，不经过 R
t₁ 之后 H1 与 Web 服务器建立 TCP 连接（HTTP/1.1），从 H1 发出 SYN 到收到第一个 HTTP 响应报文至少要几个 RTT（不计 DNS） >> 三次握手 1 个 RTT ＋ 请求/响应 1 个 RTT ＝ 2 个 RTT（请求可随第三次握手的 ACK 一起发）
