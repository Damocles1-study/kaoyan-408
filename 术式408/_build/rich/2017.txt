#1
@tpl T循环次数
::read
「`while(sum<n)`」 >> 循环停不停看的是 {{圈|sum}}，不是 i ⟹ 要先弄清 sum 长多快
「`sum += ++i;`」 >> 先 `++i` 再加：第 1 次加 1、第 2 次加 2……{{波|sum 是 1＋2＋…＋i}}，是平方级增长
「求时间复杂度」 >> 设循环执行 $k$ 次，写出 $k$ 次后 sum 的值，代入「刚好停下」的条件解 $k$
::sk 420 150 列 | 草稿：列出前几轮 i 与 sum，看出 sum ≈ i²/2
s.cells(10,14,[['第 k 轮','1','2','3','4','5','…','k'],['i','1','2','3','4','5','…','k'],['sum','1','3','6','10','15','…','!k(k+1)/2']],cw=[60,30,30,30,30,30,26,88],ch=24)
s.text(10,110,'停下：k(k+1)/2 ≥ n  ⟹  k²/2 ≈ n',13,'r')
s.text(10,136,'⟹ k ≈ √(2n) ⟹ O(n^{1/2})',13,'r',bold=True)
::think
1. 循环体每次 $O(1)$，总时间＝循环次数。
2. 循环变量是 sum，它每次加上一个越来越大的数 ⟹ 长得比 $k$ 快、比 $2^k$ 慢 ⟹ 次数应在 $\log n$ 与 $n$ 之间，√n 最可能。
3. 用「设执行 $k$ 次」把它算实。
::fast
{{秒|sum 是等差数列求和 ≈ $k^2/2$}}：到 $n$ 停 ⟹ $k\approx\sqrt{2n}$。看到「累加一个递增的计数器」就是 √n 型；「每次乘 2」才是 log 型。
::steps
循环执行第 $k$ 次时，`++i` 使 $i=k$，sum 加上 $k$；所以执行 $k$ 次后 $i=k$，$\text{sum}=1+2+\cdots+k=\dfrac{k(k+1)}{2}$。
循环在 sum ≥ n 时第一次停下：$\dfrac{k(k+1)}{2}\ge n$，而上一次 $\dfrac{(k-1)k}{2}\lt n$。
$k(k+1)/2\approx k^2/2$，所以 $k^2/2\approx n$ ⟹ $k\approx\sqrt{2n}$。
常数 $\sqrt2$ 不影响量级 ⟹ $T(n)=O(n^{1/2})$，选 **B**。
~验算一个数：$n=100$ 时 $k(k+1)/2\ge100$ 的最小 $k=14$（$14\times15/2=105$），$\sqrt{200}\approx14.1$，吻合。
::note
- 函数返回的 i 恰好就是循环次数，也≈$\sqrt{2n}$——这题的函数其实是在「求最小的 $k$ 使 $1+\dots+k\ge n$」。
- {{扣|看到 while 只有一层就选 O(n)}}：单层循环的次数取决于循环变量的增长方式，不取决于层数。
- 三种单层循环的增长方式要一眼认：`i++` ⟹ $O(n)$；`i*=2` ⟹ $O(\log n)$；`sum+=++i` 或 `i*i<=n` ⟹ $O(\sqrt n)$。
::vary
把循环体改成 `sum += i; i *= 2;`（初值 i=1）>> sum＝$2^k-1$，到 $n$ 停 ⟹ $k\approx\log_2 n$，$O(\log n)$
条件改成 `while(i*i<n) i++;` >> 停在 $i\approx\sqrt n$，仍是 $O(\sqrt n)$；这就是 2019 年第 1 题的写法
改成两层：`for(i=1;i<=n;i++) for(sum=0,j=1;sum<i;j++) sum+=j;` >> 内层约 $\sqrt{2i}$ 次，总次数 $\sum\sqrt{2i}\approx\frac{2\sqrt2}{3}n^{3/2}$，$O(n^{3/2})$
改成 `sum += i*i`（每次加平方）>> sum ≈ $k^3/3$，$k\approx\sqrt[3]{3n}$，$O(n^{1/3})$

@tpl T罗马数字组合
::read
「采用非递归方式重写递归程序时{{圈|必须}}使用栈」 >> 「必须」⟹ 找反例：尾递归（如求阶乘、斐波那契迭代）直接改成循环，不用栈 ⟹ Ⅰ 错
「函数调用时，系统要用栈保存必要的信息」 >> 调用栈：返回地址、实参、局部变量 ⟹ Ⅱ 对
「只要确定了入栈次序，即可确定出栈次序」 >> 入栈 1、2：可以「进 1 出 1 进 2 出 2」得 12，也可以「进 1 进 2 出 2 出 1」得 21 ⟹ 不唯一 ⟹ Ⅲ 错
「栈是一种受限的线性表，允许在其{{圈|两端}}进行操作」 >> 栈只在栈顶一端插入删除；两端都能操作的是双端队列 ⟹ Ⅳ 错
「错误的是」 >> 选错的：Ⅰ、Ⅲ、Ⅳ
::sk 420 150 画 | 草稿：Ⅲ 的反例（同一入栈次序两种出栈次序）和 Ⅳ 的「只开一个口」
s.text(10,18,'入栈次序 1, 2：',12)

s.text(10,64,'进1 进2 出2 出1 ⟹ 出栈 2 1',12)
s.text(10,88,'⟹ Ⅲ 错（出栈次序不唯一）',12,'r')
s.line(300,30,300,130);s.line(360,30,360,130);s.line(300,130,360,130)
s.box(304,98,52,28);s.text(330,117,'1',12,'k','middle',rot=0)
s.box(304,68,52,28);s.text(330,87,'2',12,'k','middle',rot=0)
s.arrow(318,10,318,58,'b');s.arrow(342,58,342,10,'b')
s.text(380,40,'只有栈顶',11,'r');s.text(380,58,'一个口',11,'r')
s.text(250,146,'⟹ Ⅳ 错',12,'r')
::think
1. 四条各自独立判，先判最确定的。
2. Ⅳ 一眼错（栈只有一端），Ⅱ 一眼对 ⟹ 选项里「含 Ⅳ 不含 Ⅱ」的只有 C。
3. 再验 Ⅰ、Ⅲ 确实都错，答案稳。
::fast
{{秒|Ⅱ 必对、Ⅳ 必错}}：排除含 Ⅱ 的 B、D 和不含 Ⅳ 的 A ⟹ 只剩 C。
::steps
Ⅰ：递归改非递归不一定要栈。尾递归（递归调用是最后一步）可以直接改写成循环，例如 `fact(n)` 改成 `for` 连乘；只有一般的递归（如二叉树的中序遍历）才需要用栈模拟。「必须」说得太绝对 ⟹ 错。
Ⅱ：函数调用时，系统用调用栈保存返回地址、实参、局部变量等，返回时按后进先出恢复 ⟹ 对。
Ⅲ：入栈次序确定后，出栈与入栈可以穿插进行，出栈次序有多种。$n$ 个元素按固定次序入栈，可能的出栈序列有卡特兰数 $\frac{1}{n+1}C_{2n}^{n}$ 种（$n=2$ 时 2 种）⟹ 错。
Ⅳ：栈只允许在栈顶一端插入和删除；允许两端操作的是双端队列 ⟹ 错。
错误的是 Ⅰ、Ⅲ、Ⅳ，选 **C**。
::note
- 「必须」「只要……即可」「两端」都是绝对化的措辞，罗马数字题里先怀疑它们。
- 卡特兰数：$n=3$ 时 5 种、$n=4$ 时 14 种——「入栈次序确定，出栈次序有卡特兰数种」正是第 Ⅲ 条的反面。
- 栈的两个硬性质一起记：只在一端（栈顶）操作、后进先出；函数调用、表达式求值、括号匹配、递归都靠它。
::vary
若 Ⅲ 改为「若一次性全部入栈后再全部出栈，则出栈次序唯一确定」>> 对：此时出栈次序恰好是入栈次序的逆序
「消除递归一定要用栈」与「消除递归可以不用栈」哪个对 >> 后者对：尾递归、单向递归可直接改成循环；一般递归才需要栈
「队列是一种允许在两端进行操作的线性表」对吗 >> 不严格：队列在一端插入、另一端删除，两端各只做一种操作；两端都能插入删除的是双端队列
入栈次序 1、2、3，出栈次序有几种，哪一种不可能 >> 5 种；3、1、2 不可能（3 先出说明 1、2 都在栈里且 2 在上，2 必先于 1 出）

::read
「适用于压缩存储{{圈|稀疏矩阵}}」 >> 稀疏矩阵：非零元很少且分布没有规律 ⟹ 只能逐个记下非零元的位置和值
「两种存储结构」 >> 一顺序一链式：顺序的是 [[三元组]] 表；链式的是十字链表（每个非零元结点同时挂在行链表和列链表上）
「邻接矩阵」「二叉链表」 >> 邻接矩阵是 $n\times n$ 全存，本身就不压缩；二叉链表存树 ⟹ 含它们的选项都排除

s.cells(10,20,[['0','0','3','0'],['0','0','0','0'],['5','0','0','0'],['0','0','0','7']],cw=26,ch=24)

::think
1. 压缩存储只存非零元。非零元没有规律 ⟹ 每个都要记（行, 列, 值）。
2. 顺序存放这些三元组 ⟹ 三元组表；要频繁插入删除非零元时用链式 ⟹ 十字链表。
::fast
{{秒|邻接矩阵本身就是满存}}：含邻接矩阵的 B、D 排除；二叉链表是树的存储 ⟹ C 排除 ⟹ A。
::steps
稀疏矩阵非零元少、位置无规律，压缩存储只能把每个非零元写成（行号, 列号, 值）一条记录。
顺序存放这些记录 ⟹ 三元组表：节省空间，但插入删除非零元要移动大量记录。
链式存放 ⟹ 十字链表：每个非零元一个结点，含行、列、值和「同行下一个」「同列下一个」两个指针，行头、列头各一组指针数组；插入删除方便。
邻接矩阵存 $n^2$ 个元素，不压缩；二叉链表用于二叉树（或树的孩子兄弟表示），与矩阵无关。
选 **A**。
::note
- 三元组表要另存矩阵的行数、列数（最后几行全 0 时表里体现不出来），通常还存非零元个数。
- 压缩之后都失去随机存取：要找 $a_{ij}$ 得在三元组表里查。
- 对照「特殊矩阵」（对称、三角、对角）：非零元有规律 ⟹ 用一维数组＋下标公式压缩，不需要三元组。
::vary
十字链表还用来存什么 >> 有向图（每条弧同时挂在弧尾的出弧链和弧头的入弧链上）；无向图用邻接多重表
6×7 的矩阵有 8 个非零元，用三元组表（每个整数 2 字节）存，至少多少字节 >> 8×3×2＝48 字节存非零元，另加行数、列数（、非零元个数）共 52（或 54）字节
对称矩阵适合用三元组表压缩吗 >> 不必：对称矩阵有规律，只存下（上）三角共 $n(n+1)/2$ 个元素，用下标公式直接定位，保留随机存取

@tpl T两序相同
::read
「非空二叉树的{{圈|先序序列与中序序列相同}}」 >> 先序 N L R，中序 L N R：两者的差别只在 N 与 L 的先后
「其所有非叶结点须满足」 >> 要让 N 和 L 先后无关 ⟹ {{波|L 必须为空}} ⟹ 每个结点没有左孩子
「结点的度均为 1」 >> 度为 1 的单支树可能向左拐 ⟹ 不能保证 ⟹ 陷阱
::sk 420 160 画 | 草稿：只有右子树的树先序＝中序；拐一次左就不同
s.tree(('A',None,('B',None,('C',))),60,24,dx=50,dy=40,r=12)
s.text(10,150,'先序 ABC  中序 ABC ✓',12,'r')
s.tree(('A',None,('B',('C',),None)),280,24,dx=50,dy=40,r=12)
s.text(210,150,'先序 ABC  中序 ACB ✗',12)
s.text(350,110,'度都是 1',11,'b');s.text(350,126,'但拐了左',11,'b')
::think
1. 写出两种顺序：先序 NLR、中序 LNR。
2. 两者唯一的差别：N 与 L 谁先。要对每个子树都相同 ⟹ 每个结点的 L 都必须空。
3. 只要有一个结点有左孩子，那个结点在先序里排在左孩子前、在中序里排在左孩子后 ⟹ 立刻不同。
::fast
{{秒|把 NLR 与 LNR 并排写}}：去掉 L 后都变成 NR ⟹ 只有右子树。度为 1 只是必要不充分（向左拐就不行）⟹ C 排除。
::steps
先序：根 → 左子树 → 右子树；中序：左子树 → 根 → 右子树。
若某个结点 $x$ 有左孩子，则在先序中 $x$ 排在其左子树全部结点之前，在中序中 $x$ 排在其左子树全部结点之后 ⟹ 两个序列不同。
所以所有结点都不能有左孩子 ⟹ 非叶结点只有右子树。
反过来，若所有结点都只有右子树，先序是「根、右子树的先序」，中序是「根、右子树的中序」，递归下去完全相同。
选 **B**。
~A「只有左子树」：中序＝后序的条件。D「度均为 2」：根的左子树非空，先序≠中序。
::note
- {{扣|选 C「度均为 1」}}：度为 1 的单支树每个结点都可以挂左或挂右；只要有一个挂左，序列就不同。
- 三组条件一起记：先序＝中序 ⟺ 无左孩子；中序＝后序 ⟺ 无右孩子；先序＝后序 ⟺ 只有根。
- 本题已用程序枚举所有 ≤7 个结点的二叉树验证：先序＝中序 ⟺ 每个结点都没有左孩子。
::vary
后序序列与中序序列相同，非叶结点须满足什么 >> 只有左子树（LRN 与 LNR 差别在 N、R，去掉 R）
先序与后序相同的二叉树有几个结点 >> 只有 1 个（N 一个在头一个在尾，L、R 都得空）
先序序列与后序序列恰好相反，二叉树须满足什么 >> 每个结点至多一个孩子（高度＝结点数），左右都可以
先序为 a b c d 且中序也为 a b c d 的二叉树有几棵 >> 1 棵：a 的右孩子 b、b 的右孩子 c、c 的右孩子 d

1. 判定树由「元素个数 + 取整方式」唯一确定；判断时不必真去建，逐结点数左右子树大小就行。
2. 下取整：区间 $[low,high]$ 有 $m$ 个元素，mid 左边 $\lfloor(m-1)/2\rfloor$ 个、右边 $\lceil(m-1)/2\rceil$ 个 ⟹ 左 ≤ 右，差至多 1；上取整反过来。
3. 所以全树的「左右之差」只能同号（或 0）。最快查的是只有一个孩子的结点：它们的孩子必须全在同一侧。
::fast
{{秒|盯单孩子结点}}：B 中有的单孩子挂左、有的挂右 ⟹ 出局；C 的结点 2（左 1、右 2，左少）和结点 8（左 2、右 1，左多）打架；D 的根左 4 右 5（左少）而根的左孩子左 2 右 1（左多）打架 ⟹ 只有 A。
::steps
记每个结点的左子树结点数为 L、右子树为 R。mid 向下取整时恒有 $L=R$ 或 $L=R-1$；向上取整时恒有 $L=R$ 或 $L=R+1$；同一棵判定树只能是其中一种。
A（10 个结点，按中序记为 1～10）：根 6 为 5|4；结点 3 为 2|2；结点 9 为 2|1；结点 2、5、8 各只有一个左孩子，为 1|0；其余为叶子。只出现「相等」和「左多 1」⟹ 符合上取整。
B（11 个结点）：根 5|5，但左半边的两个单孩子结点挂的是左孩子（1|0），右半边的两个挂的是右孩子（0|1）⟹ 两种取整混用 ⟹ 不可能。
C（9 个结点）：根 4|4；根的左孩子为 1|2（左少 1，下取整），根的右孩子为 2|1（左多 1，上取整）⟹ 打架 ⟹ 不可能。
D（10 个结点）：根 4|5（左少 1，下取整），根的左孩子却是 2|1（左多 1，上取整）⟹ 不可能。
选 **A**。
~验证：对 1～10 用 mid＝⌈(low+high)/2⌉ 真正建树：根 6；左区间 1～5 的 mid＝3，右区间 7～10 的 mid＝9；再往下 2、5、8、10、1、4、7——与 A 逐结点相同。
::note
- {{扣|用「是不是平衡二叉树」或「高度对不对」来判}}：四个选项都平衡、都高 4，这两条只是必要条件。
- 判据「逐结点 L＝R 或 L＝R−1」是充要的：已用程序穷举 1～14 个结点的全部二叉树，每个 $n$ 恰有一棵满足，且就是 mid 下取整建出的判定树（上取整对称）。
- 「判定树唯一」是对给定 $n$ 与取整方式而言：$n=10$ 有两棵合法判定树（下取整一棵、上取整一棵），A 是上取整那棵。
::vary
若题目明确 mid＝⌊(low+high)/2⌋，n＝10 的判定树根是几、根的左右子树各几个结点 >> 根是 5，左 4 个、右 5 个（左少 1）

@tpl T排序特性对比
::read
「选择了归并排序而{{圈|未选择插入排序}}」 >> 问的是「归并比插入强在哪」：把两者三项指标并排比
「Ⅰ. 程序代码更短」 >> 归并要递归分解＋Merge 合并两个函数；直接插入只有一个双重循环 ⟹ 插入更短 ⟹ Ⅰ 错
「Ⅱ. 占用空间更少」 >> 归并要 $O(n)$ 辅助数组，插入 $O(1)$ ⟹ Ⅱ 错
「Ⅲ. 运行效率更高」 >> 归并 $O(n\log n)$，插入 $O(n^2)$ ⟹ Ⅲ 对
::sk 420 130 看 | 草稿：两列体检表，题目问「选归并的理由」＝归并赢的那几行
s.cells(10,10,[['','归并','直接插入','谁赢'],['Ⅰ 代码','递归+Merge','双重循环','插入'],['Ⅱ 空间','O(n)','O(1)','插入'],['Ⅲ 时间','O(n log n)','O(n²)','!归并']],cw=[60,100,90,60],ch=26)
s.text(330,72,'⟹ 仅 Ⅲ',13,'r',bold=True)
::think
1. 把两个算法的指标列成两列，逐行看谁赢。
2. 「选 A 不选 B 的理由」只能是 A 赢的那几行。
::fast
{{秒|归并的短板就是空间}}：Ⅱ 必错 ⟹ 排除 A、C；归并代码明显更长 ⟹ Ⅰ 错 ⟹ 排除 D ⟹ B。
::steps
Ⅰ：归并排序要写递归的 MergeSort 和合并两个有序段的 Merge（三个 while），直接插入排序只是一个双重循环 ⟹ 归并代码更长 ⟹ 错。
Ⅱ：归并排序需要与原数组等长的辅助数组，空间 $O(n)$；直接插入排序只用一个辅助变量，$O(1)$ ⟹ 错。
Ⅲ：归并排序最好、最坏、平均都是 $O(n\log_2n)$；直接插入排序平均和最坏 $O(n^2)$ ⟹ 归并效率更高 ⟹ 对。
选 **B**。
::note
- 归并排序是八种内部排序里空间最大的（$O(n)$），用这份空间换来：时间稳定 $O(n\log n)$、算法稳定。
- 若再加一项「Ⅳ. 归并排序是稳定的」，那不是理由：直接插入也稳定，两者打平。
- 这类「为什么选 A 不选 B」的题都这样做：列表，逐行比，选 A 赢的行。2020 年第 19 题（插入 vs 选择）、2022 年第 20 题同法。
::vary
若改为「选择了插入排序而未选择归并排序」，可能的理由是 >> 代码短、空间 $O(1)$；另外数据基本有序或 $n$ 很小时插入更快
链式存储时，归并排序的空间复杂度是多少 >> 只改指针不需要辅助数组，额外空间 $O(1)$（递归实现还有 $O(\log n)$ 的栈）
「选了快排而没选归并」的理由可能是 >> 空间更少（$O(\log n)$ 对 $O(n)$）、平均常数更小；不能是「稳定」或「最坏更快」

#11
@tpl T链式存储排序
::read
「将{{圈|顺序存储更换为链式存储}}」 >> 链表没有随机存取：取「下一个」$O(1)$，取「第 i 个」$O(n)$
「时间效率会降低」 >> 看算法访问元素时是 ±1 顺着走还是跳着走
「插入、选择、冒泡」 >> 都只需顺序扫描或比较相邻元素 ⟹ 换链表不变慢
「希尔、堆」 >> 希尔按增量 d 跳着取，堆排序按 2i、2i＋1 找孩子 ⟹ 都依赖下标随机访问 ⟹ 变慢
::think
1. 链表能做的：从前往后走一步、在已知位置插入删除。做不到的：$O(1)$ 访问第 i 个。
2. 逐个看五种算法访问元素的方式。
::fast
{{秒|只能顺序存储的四个：折半插入、希尔、快排、堆}}：选项里出现的是希尔和堆 ⟹ D。
::steps
直接插入排序：从后往前逐个比较、后移（链表上从前往后找插入位置、改指针即可）⟹ 仍是 $O(n^2)$，不变慢。
简单选择排序：每趟顺序扫描找最小 ⟹ 链表照样 $O(n^2)$。
冒泡排序：只比较相邻元素 ⟹ 链表照样 $O(n^2)$。
希尔排序：要按增量 $d$ 访问 A[i]、A[i－d]、A[i－2d]……链表上每次定位都要从头走 ⟹ 变慢。
堆排序：结点 $i$ 的孩子是 $2i$、$2i+1$，调整时要随机访问 ⟹ 链表上变慢。
会降低效率的是 Ⅳ、Ⅴ，选 **D**。
::note
- 记法：访问下一个元素时下标是 ±1 ⟹ 链表友好；是 ±d、mid、2i、两头夹 ⟹ 必须顺序存储。
- 链表对某些算法反而有好处：直接插入不再移动元素；归并不再需要辅助数组。但比较次数不变，时间复杂度不变。
- {{扣|把「插入排序」当成折半插入}}：本题的插入排序指直接插入；若写「折半插入」，它也要选进去（要随机访问 A[mid]）。
::vary
快速排序换成单链表会怎样 >> 双向划分（i 从左、j 从右）在单链表上做不到；可改用单向划分（两个指针都从左往右），平均仍 $O(n\log n)$
基数排序适合哪种存储 >> 链式（链式基数排序：分配、收集都是改指针），顺序存储时要额外 $O(n)$ 空间
折半插入排序换成链表后比较次数还是 $O(n\log n)$ 吗 >> 不行：链表上没法折半，只能顺序找插入位置，退化成直接插入

::think
1. 参数必须在陷入之前准备好：陷入后内核要立刻知道「你要做什么、参数在哪」。
2. 服务程序必须在陷入之后执行（内核态代码）；返回用户态最后。
::fast

::steps
用户程序先在用户态传递系统调用参数（把调用号和参数放入寄存器或用户栈）——③。
然后执行陷入指令，CPU 由用户态转入内核态，硬件保存断点和程序状态——②。
内核根据系统调用号执行相应的服务程序——④。
服务完成后返回用户态，回到断点继续执行——①。
顺序为 ③→②→④→①，选 **C**。
::note
- A、B 都把传参放到陷入之后，错在「陷入后才告诉内核要干什么」。
- 陷入指令本身在用户态执行（它是非特权指令），执行后才进入内核态。
- 2022 年真题把第 ② 步再切开考「硬件保存了什么、OS 保存了什么」。

Ⅰ：多个进程打开同一个文件时，读写指针保存在各自进程的用户打开文件表中，互不影响（否则一个进程读文件会搅乱另一个的读写位置）⟹ 错。
Ⅱ：硬链接是基于索引节点的共享，f1 和 f2 是同一个 inode；打开时内存中只有一份内存索引节点，两次打开都指向它 ⟹ 对。
Ⅲ：每个进程有自己的用户打开文件表，文件描述符是该表的下标，fd1、fd2 分别指向各自进程用户打开文件表中的一项 ⟹ 对。
选 **B**。
::note
- {{扣|以为同一文件就共享读写指针}}：共享的是文件（inode），不是读写位置。
- 若是软链接：f2 是一个独立的小文件（有自己的 inode），里面存 f1 的路径；打开 f2 时系统顺着路径找到 f1 的 inode——最终打开的还是 f1 的 inode。
- 2020 年真题考同一张图：系统打开文件表只有一项（对），各进程用户表项内容相同（错）。
::vary
同一进程先后两次 open 同一文件，得到几个 fd、读写指针几个 >> 2 个 fd，各有自己的读写指针（共享同一个系统表项、计数加 2）
父进程 open 后 fork，子进程与父进程的读写指针 >> UNIX 中 fork 复制文件描述符，父子指向同一个打开文件对象，共享读写指针（这是 UNIX 实现，与本题「两个进程各自 open」不同）
删除 f1 后还能通过 f2 访问文件吗 >> 硬链接能：inode 的链接计数从 2 减为 1，文件仍在；软链接则失效

@tpl TIO全程时序
::read
「系统将数据从磁盘读到内存的过程」 >> [[DMA三阶段]]：预处理（CPU）→ 数据传送（DMA）→ 后处理（中断）
「初始化 DMA 控制器并启动磁盘」 >> 预处理，最先
「从磁盘传输一块数据到内存缓冲区」 >> 数据传送，DMA 控制器接管总线
「DMA 控制器发出中断请求」「执行“DMA 结束”中断服务程序」 >> 后处理：先请求、后执行服务程序
::think
1. DMA 的三阶段顺序固定：预处理、数据传送、后处理。
2. 后处理里「发中断请求」在前，「执行中断服务程序」在后，中间隔着一次中断响应。
::fast
{{秒|第一步只能是初始化（②）}}：以 ② 开头的 B、C；C 在传数据之前就发中断 ⟹ B。
::steps
预处理：CPU 执行驱动程序，初始化 DMA 控制器（内存地址、传送字数、方向），并启动磁盘——②。
数据传送：DMA 控制器控制总线，把一块数据从磁盘（经接口）直接送入内存缓冲区，期间 CPU 可做别的事——③。
后处理：传送完毕，DMA 控制器向 CPU 发出中断请求——①；CPU 响应后执行「DMA 结束」中断服务程序做善后——④。
顺序为 ②→③→①→④，选 **B**。
::note
- DMA 一次中断处理一整块数据，而程序中断方式每传一个字（字节）就中断一次。
- 读盘的进程在 ② 之后被阻塞，在 ④ 中被唤醒（2023 年第 46 题把键盘输入拆成六步排序）。
- ① 是硬件（DMA 控制器）做的，④ 是软件（CPU 执行程序）做的。
::vary
数据传送阶段，数据经过 CPU 吗 >> 不经过：设备与主存之间直接传送，DMA 控制器只是占用总线
若改为程序中断方式读一块 512B 数据（每次中断传 1 字节），要几次中断 >> 512 次
DMA 采用周期挪用方式时，CPU 与 DMA 同时访存，谁优先 >> DMA 优先（I/O 设备数据不及时取走会丢失）

1. 表达式树的中序序列＝去掉括号的中缀表达式 ⟹ 骨架用中序递归。

若 root 是叶结点（左右孩子都空），它是操作数：输出 `root->data`，不加括号。

~手跑第二棵树：根 +（不加括号）→ 左子树 *（deep＝2，加括号）输出 (a*b)；输出 +；右子树 -（一元，deep＝2）输出「(」、左空、「-」，右子树 -（二元，deep＝3）输出 (c-d)，再「)」⟹ (a*b)+(-(c-d))。

**（1）基本设计思想** ⛳5
表达式树的中序序列加上必要的括号就是等价的中缀表达式，所以基于中序遍历实现。叶结点是操作数，直接输出，不加括号；分支结点是运算符，它所代表的子表达式要用括号括起来：在遍历其左子树之前输出「(」，遍历完其右子树之后输出「)」。整个表达式的最外层（根结点）不需要括号。用递归深度 deep 区分根结点：根的深度为 1，只有 deep＞1 的分支结点才加括号。
**（2）算法实现** ⛳10
```
void BtreeToExp(BTree *root, int deep) {
    if (root == NULL) return;                     /* 空结点（一元运算符的左子树） */
    else if (root->left == NULL && root->right == NULL)
        printf("%s", root->data);                 /* 叶结点：操作数，不加括号 */
    else {
        if (deep > 1) printf("(");                /* 非根的分支结点：先输出左括号 */
        BtreeToExp(root->left, deep + 1);         /* 中序：左子树 */
        printf("%s", root->data);                 /* 输出运算符 */
        BtreeToExp(root->right, deep + 1);        /* 右子树 */
        if (deep > 1) printf(")");                /* 再输出右括号 */
    }
}
void BtreeToE(BTree *root) {
    BtreeToExp(root, 1);                          /* 根的深度为 1，根不加括号 */
}
```
（时间复杂度 $O(n)$，空间复杂度 $O(h)$，$h$ 为树高。）
::note

- {{扣|用 `%c` 输出}}：data 是字符串（`char data[10]`），要用 `%s`。
- 不用 deep 也行：在主函数里对根单独处理（先递归左子树、输出根、递归右子树），子函数里分支结点一律加括号——效果相同。
- 只按「运算符优先级」决定加不加括号（最少括号）更难写，题目不要求；只要括号能反映计算次序即可得满分。
- 本代码已与测试桩一起 gcc 编译：题给两棵树输出与例子逐字相同；另随机生成 3000 棵含一元负号的表达式树，输出串按 Python 求值与树的后序求值全部相等，括号对数恰为「非根分支结点数」。
::vary

1. 只有全局变量才可能需要互斥；局部变量 w、函数 add 里的 s 是各线程自己的。
2. 互斥是「哪两个线程对哪个变量」的关系，不能笼统说「y 要互斥」。按读者—写者原则逐对检查：
- t1 与 t2：对 y 都只读 ⟹ 不互斥；
- t1 与 t3：t1 读 y、t3 写 y ⟹ 互斥；

**解：** ⛳2
全局变量只有 x、y、z。thread1 只读 x、y；thread2 只读 y、z；thread3 对 z、y 既读又写。由「读与读不需要互斥，读与写、写与写需要互斥」，得三组互斥关系：thread1 与 thread3 对 y、thread2 与 thread3 对 y、thread2 与 thread3 对 z；thread1 与 thread2 之间无须互斥。故定义三个互斥信号量，初值均为 1：
```
semaphore mutex_y1 = 1;   // thread1 与 thread3 对 y 的互斥
semaphore mutex_y2 = 1;   // thread2 与 thread3 对 y 的互斥
semaphore mutex_z  = 1;   // thread2 与 thread3 对 z 的互斥
```
thread1 ⛳1
```
thread1 {
    cnum w;
    wait(mutex_y1);
    w = add(x, y);
    signal(mutex_y1);
    ...
}
```
thread2 ⛳2
```
thread2 {
    cnum w;
    wait(mutex_y2);
    wait(mutex_z);
    w = add(y, z);
    signal(mutex_z);
    signal(mutex_y2);
    ...
}
```
thread3 ⛳3
```
thread3 {
    cnum w;
    w.a = 1;
    w.b = 1;
    wait(mutex_z);
    z = add(z, w);
    signal(mutex_z);
    wait(mutex_y1);
    wait(mutex_y2);
    y = add(y, w);
    signal(mutex_y1);
    signal(mutex_y2);
    ...
}
```
thread1 与 thread2 对 y 只读，持有不同的信号量，可以并发执行，满足最大限度并发的要求。
::note
- {{扣|只用一个 mutex（或给 y 只设一个信号量）}}：互斥满足了，但 thread1 与 thread2 本可同时读 y，被迫互斥 ⟹ 并发度降低，要扣分。题干「最大限度地并发执行」就是冲着这点。
- {{扣|给 x 也加信号量}}：x 只有 thread1 访问，不存在互斥关系。
- {{扣|thread3 持有 mutex_z 时去申请 mutex_y2}}：与 thread2「先 y2 后 z」相反，可能死锁。复算程序穷举全部交错：本解法 201 个状态无死锁、无读写冲突，且确有 thread1、thread2 同时读 y 的状态；改成「持 z 抢 y」的写法会出现死锁状态；只用一个信号量则 thread1、thread2 永远不能同时读。
- 互斥关系要写成「哪两个线程对哪个变量」——这句分析本身就有分。
- 用读者—写者的计数器写法（读者计数、第一个读者加锁）也能做到 t1、t2 并发读 y，但更复杂；本题三个信号量是最简答案。
::vary
若 thread1 改为 `x = add(x, y);`（写 x），信号量要怎么改 >> x 仍只有 thread1 访问，不用加；其余不变
若 thread2 改为 `y = add(y, z);`（写 y），t1 与 t2 还能并发吗 >> 不能：t1 读 y、t2 写 y 要互斥，再加一个 mutex_y3（t1–t2 对 y），或者把 y 的三对关系合成一个 mutex_y（此时三者两两冲突，一把锁就是最大并发）
thread3 能不能把两段合成一段：P(mutex_z)、P(mutex_y1)、P(mutex_y2)，做完两句再全释放 >> 能互斥，但持锁时间变长、并发度降低；且申请顺序要与 thread2 一致（先 y2 后 z）才不死锁
若只要求互斥、不要求最大并发，最少用几个信号量 >> 1 个（所有访问共享变量的语句都用同一个 mutex 包住）

3. 第 2 问：发送窗口 7，左沿＝乙期望的 3 ⟹ 窗口 3,4,5,6,7,0,1；已发 3、4 ⟹ 还能发 5 帧。帧上的确认号＝甲期望乙的下一帧：甲收到 R0、R1，R3 越序被丢弃（GBN 接收窗口为 1），所以仍期望 2。
4. 第 3 问：GBN 超时 ⟹ 重发出错帧及其后已发出的所有帧；确认号用当前最新值。
5. 第 4 问：一个发送周期 $T_D+RTT+T_A$，捎带确认 ⟹ $T_A=T_D$；窗口 7 帧，$U=7T_D/(2T_D+RTT)$。
::steps
第 1 问。甲收到的乙方帧中确认号最大的是 R3,3，确认号 3 表示乙希望接收甲的 3 号帧，说明乙已正确接收 0～2 号帧 ⟹ 甲可断定乙已正确接收 3 个数据帧：S0,0、S1,0、S2,0。
第 2 问。发送序号 3 位，共 8 个序号；GBN 的发送窗口 $W_T\le2^3-1=7$，取最大值 7。
乙已确认到 2 号，发送窗口左沿为 3，窗口内的序号为 3、4、5、6、7、0、1。
甲已发出 S3,0、S4,1 两帧 ⟹ 在不超时、未收到乙方新帧之前，最多还能发送 $7-2=5$ 帧，发送序号依次为 5、6、7、0、1。
这些帧捎带的确认号：甲已按序收到乙的 R0、R1；R3 是越序帧（缺 R2），GBN 只按序接收，R3 的数据被丢弃，所以甲期望乙的下一帧仍是 2 号 ⟹ 确认号为 2。
第一个帧是 S5,2，最后一个帧是 S1,2。
第 3 问。图 (b) 中甲收到 R0,1、R1,2、R2,2，乙一直在等 2 号帧 ⟹ S2,0 丢失或出错；t₁ 时 S2,0 超时。
GBN 超时后要重发出错帧及其后所有已发送的帧：甲已发出 S2、S3、S4 ⟹ 重发 3 帧。
甲已收到乙的 0、1、2 号帧，期望乙的下一帧是 3 ⟹ 重发帧的确认号为 3，第一个重发帧是 S2,3。
第 4 问。$T_D=\dfrac{1000\times8\text{b}}{100\text{Mb/s}}=80\mu s$；捎带确认时确认信息由对方的数据帧携带，$T_A=T_D=80\mu s$。
一个发送周期：$T=T_D+RTT+T_A=80+960+80=1120\mu s$。
发送窗口最大 7，一个周期内最多发 7 帧：$U=\dfrac{7\times80}{1120}=\dfrac{560}{1120}=50\%$。
::paper
**1）** ⛳2
甲方可以断定乙方已正确接收了 3 个数据帧，分别是 $S_{0,0}$、$S_{1,0}$、$S_{2,0}$。理由：$R_{3,3}$ 的确认序号为 3，表示乙方希望接收甲方序号为 3 的数据帧，说明乙方已正确接收序号为 0～2 的数据帧。
**2）** ⛳3
甲方最多还可以发送 5 个数据帧，第一个帧是 $S_{5,2}$，最后一个帧是 $S_{1,2}$。理由：发送序号为 3 位，有 8 个序号，GBN 协议的发送窗口最大为 $2^3-1=7$。乙方已确认到 2 号帧，发送窗口为 3、4、5、6、7、0、1，甲方已发送 $S_{3,0}$ 和 $S_{4,1}$，所以最多还能发送 5 帧（序号 5、6、7、0、1）；甲方已按序收到乙方的 0、1 号帧，期望乙方的下一帧为 2 号，故确认序号为 2。
**3）** ⛳2
甲方需要重发 3 个数据帧，重发的第一个帧是 $S_{2,3}$。理由：GBN 协议中出错帧超时后要重发该帧及其后已发送的帧；$S_{2,0}$ 超时，甲方已发出 2、3、4 号帧，需重发这 3 帧；甲方已收到乙方的 $R_{2,2}$，期望乙方的下一帧为 3 号，所以确认序号为 3。
**4）** ⛳2
甲方可以达到的最大信道利用率为 50%。
$$U=\frac{7\times\frac{1000\times8}{100\times10^6}}{0.96\times10^{-3}+2\times\frac{1000\times8}{100\times10^6}}=\frac{7\times80\mu s}{960\mu s+160\mu s}=50\%$$
其中采用捎带确认，确认帧的发送时间等于数据帧的发送时间。
