#16
@stem
某计算机按字节编址，虚拟地址 36 位，物理地址 32 位，页大小为 8KB。TLB 共有 64 个表项，采用 8 路组相联映射方式。TLB 表项中标记（Tag）字段的位数是（　）。
@A 17
@B 19
@C 20
@D 23
@ans C
::read
「虚拟地址 36 位」「页大小 8KB」 >> 页内偏移 13 位，虚页号 36 − 13 ＝ 23 位
「64 个表项，8 路组相联」 >> 组数 64 ÷ 8 ＝ 8，组号 3 位
::fast
{{秒|把虚页号当成 Cache 的块号}}：标记 ＝ 23 − 3 ＝ 20 ⟹ C。
::steps
TLB 是按虚页号查的，物理地址的位数与标记无关。
虚页号 $36-13=23$ 位；组数 $64/8=8$，组号 $\log_2 8=3$ 位。
标记 ＝ 虚页号 − 组号 ＝ $23-3=20$ 位，选 **C**。
::note
- 干扰项来路：23 ＝ 当成全相联（不减组号）；19 ＝ 用物理地址 32 − 13 算；17 ＝ 把 64 个表项当成 64 组。
::

#31
@stem
某文件系统用位图管理空闲盘块。磁盘容量为 32GB，盘块大小为 4KB，位图本身也存放在磁盘上。位图至少要占用的盘块数是（　）。
@A 64
@B 128
@C 256
@D 512
@ans C
::read
「磁盘容量 32GB，盘块 4KB」 >> 盘块数 $2^{35}/2^{12}=2^{23}$，每块一位
::fast
{{秒|位数 ＝ 盘块数}}：$2^{23}$ 位 ＝ $2^{20}$ B ＝ 1MB，÷4KB ＝ 256 ⟹ C。
::steps
盘块总数 $32\text{GB}/4\text{KB}=2^{35}/2^{12}=2^{23}$。
位图每块一位：$2^{23}$ 位 $=2^{20}$ 字节 $=1$MB。
占用盘块 $1\text{MB}/4\text{KB}=256$ 个，选 **C**。
::note
- 512 ＝ 忘了把位换成字节以外又多乘了 2；64、128 是把 GB/KB 的指数算错一两位。
- 位图大小只与盘块总数有关（2024 年真题第 26 题考的就是这句）。
::

#39
@stem
主机甲通过 TCP 向主机乙发送 5KB 的数据，MSS ＝ 1KB，RTT ＝ 20ms，乙的接收窗口足够大，慢开始门限初值为 16KB。甲在 $t=0$ 时发出 SYN 段，第三次握手的 ACK 段不携带数据，连接建立后甲立即开始发送数据。忽略各报文段的发送时延，不发生丢失。从 $t=0$ 起到甲收到全部数据的确认为止，至少经过（　）。
@A 60ms
@B 80ms
@C 100ms
@D 120ms
@ans B
::read
「$t=0$ 时发出 SYN」 >> 先花 1 个 RTT 完成握手（甲在 20ms 收到 SYN＋ACK）
「门限初值 16KB」 >> 5KB 用不到门限，全程慢开始：每个 RTT 窗口翻倍
::fast
{{秒|握手 1 ＋ 发送 1、2、2 段共 3 轮}} ＝ 4 RTT ＝ 80ms ⟹ B。
::steps
0～20ms：三次握手，甲 20ms 收到 SYN＋ACK，发出 ACK 后立即可以发数据。
20～40ms：cwnd ＝ 1KB，发 1 段，40ms 收到确认，cwnd 变 2KB。
40～60ms：发 2 段（累计 3KB），60ms 收到确认，cwnd 变 4KB。
60～80ms：只剩 2KB，发 2 段，80ms 收到确认 ⟹ 共 80ms，选 **B**。
::note
- 60ms ＝ 漏了握手的 1 RTT；100ms ＝ 把释放连接也算进去（题目问的是「收到全部数据的确认」）。
- 若题目说第三次握手可以携带数据，第一段跟着 ACK 一起发，结果不变（仍在 20ms 发出）。
::

#41
::think
1. 循环右移 k 位 ＝ 把最后 k 个结点整体搬到表头。
2. 链表不能按下标取 ⟹ 先走一遍求表长 n 并记下尾结点，再从头走到第 n−k 个结点，在它后面断开。
3. 原尾接原头、断点后的结点作新头；一趟遍历加一段前进，$O(n)$ 时间、$O(1)$ 空间。
::paper
解　(1) 基本设计思想 ⛳4
先遍历一次求表长 n，同时用 tail 记下尾结点；再从头结点出发走到第 n−k 个结点 p。p 的后继是新的首结点，令 p->next＝NULL 成为新尾，再让原尾结点指向原首结点，返回新首结点。
(2) 算法实现 ⛳7
```
typedef struct LNode { int data; struct LNode *next; } LNode, *LinkList;
LinkList Rotate(LinkList L, int k){
    LNode *p = L, *tail, *newhead;
    int n = 1;
    while (p->next) { p = p->next; n++; }    // 求表长，p 停在尾结点
    tail = p;
    p = L;
    for (int i = 1; i < n - k; i++)           // p 走到第 n-k 个结点
        p = p->next;
    newhead = p->next;                         // 后 k 个结点的第一个
    p->next = NULL;                            // 断开，p 成为新尾
    tail->next = L;                            // 原尾接原头
    return newhead;
}
```
(3) 时间复杂度 $O(n)$，空间复杂度 $O(1)$。⛳2
::note
- 不带头结点 ⟹ 首结点会变，函数必须返回新的头指针（或传二级指针），只在函数里改 L 不会影响调用者。{{扣|没返回新头}}
- 另一种写法：先把链表连成环，再从尾结点走 n−k 步断开，同样 $O(n)$。
- 借助辅助数组整体搬移能拿部分分（空间 $O(n)$）。
- 代码已与数组模拟随机对拍 30 万组（`_build/mock/chk/listrot.c`）。
::

#43
::think
1. 先把 −68、−8.25 写成 $\pm1.xxx\times2^e$，阶码 ＝ e ＋ 127，尾数去掉隐藏位补齐 23 位。
2. 加减按「对阶 → 尾数加减 → 规格化 → 舍入」四步；两个负数相加符号不变，相减实际是 −68 ＋ 8.25。
::paper
解　(1) ⛳5
$x=-68=-1000100_2=-1.0001\times2^6$：符号 1，阶码 $127+6=133=1000\,0101$，尾数 $000\,1000\,0\cdots0$ ⟹ A ＝ **C288 0000H**。
$y=-8.25=-1000.01_2=-1.00001\times2^3$：符号 1，阶码 $130=1000\,0010$，尾数 $000\,0100\,0\cdots0$ ⟹ B ＝ **C104 0000H**。
(2) ⛳4
对阶：小阶向大阶看齐，$y=-0.00100001\times2^6$。尾数相加（同号）：$-(1.0001+0.00100001)=-1.00110001$，已规格化。
结果 $-1.00110001\times2^6$：符号 1，阶码 1000 0101，尾数 $001\,1000\,1000\cdots$ ⟹ C ＝ **C298 8000H**（即 −76.25）。
(3) ⛳4
$x-y=-68+8.25$：尾数 $-(1.0001-0.00100001)=-0.11101111$，左规一位得 $-1.1101111\times2^5$。
符号 1，阶码 $127+5=132=1000\,0100$，尾数 $110\,1111\,0\cdots$ ⟹ D ＝ **C26F 0000H**（即 −59.75）。
::note
- 对阶一定是小阶对大阶、尾数右移；本题右移的位都能保留在 23 位尾数内，不涉及舍入。
- 相减后尾数变成 0.111…，要左规（阶码减 1），漏掉左规就会写成 C2EF 0000H。{{扣|没规格化}}
- 最后用真值验算：C298 8000H ＝ −76.25 ＝ −68 − 8.25 ✓；C26F 0000H ＝ −59.75 ✓。
::

#44
::think
1. 只看数组访存：每 8 个 int 一块；Cache 8 行，直接映射 8 行、2 路组相联 4 组。
2. 一轮内层循环访问哪几个元素 ⟹ 它们在第几块 ⟹ 映射到同一行（组）会不会互相挤掉。
3. 外层循环 10000 次：直接映射下互相冲突的块每次都缺失；2 路组相联里能共存就只在第一次缺失。
::paper
解　块大小 32B ＝ 8 个 int，第 j 个元素在主存块 ⌊j/8⌋；Cache 共 256B/32B ＝ 8 行。⛳2
(1) 直接映射（块号 mod 8 定行）：⛳4
s ＝ 64：每轮访问 a[0]、a[64]，分别在第 0、8 块，都映射到第 0 行，交替访问每次都把对方挤掉 ⟹ 缺失率 100%。
s ＝ 63：每轮访问 a[0]、a[63]、a[126]，在第 0、7、15 块；第 7、15 块都映射到第 7 行，互相冲突每次缺失，第 0 块只在第一次缺失 ⟹ 缺失率约为 2/3（≈67%）。
(2) 2 路组相联（块号 mod 4 定组）：⛳4
s ＝ 64：第 0、8 块都在第 0 组，2 路正好放下，只有最初 2 次缺失 ⟹ 缺失率约为 0（2/20000）。
s ＝ 63：第 7、15 块都在第 3 组，可同时放下，第 0 块在第 0 组 ⟹ 只有最初 3 次缺失，缺失率约为 0（3/30000）。
::note
- 这道题说明：步长恰好是 Cache 容量的整数倍时，直接映射会「乒乓冲突」，组相联靠多路化解。
- 卷面写清「哪几块映射到同一行 / 组」就能拿到主要分数，最后的百分比写近似值即可。
- 四个缺失次数已用程序逐次模拟（`_build/mock/chk/3002.py`）。
::

#45
::think
1. 临界资源：水井（一次只能一个桶）、水缸（一次只能一人倒或取）⟹ 两个互斥信号量 well、vat。
2. 计数资源：水缸还能放几桶 empty＝10、已有几桶 full＝0、水桶 pail＝3。
3. 先申请计数资源（empty/full、桶），最后才申请互斥资源，避免拿着井或缸去等桶。
::paper
解　信号量：⛳2
`semaphore well = 1;`　// 水井互斥
`semaphore vat = 1;`　// 水缸互斥
`semaphore empty = 10, full = 0;`　// 缸里还能放的桶数、已有的桶数
`semaphore pail = 3;`　// 可用的水桶
```
小和尚:
while (1) {
    P(empty);
    P(pail);
    P(well);  从井中打一桶水;  V(well);
    P(vat);   将水倒入缸中;    V(vat);
    V(full);
    V(pail);
}
```
⛳3
```
老和尚:
while (1) {
    P(full);
    P(pail);
    P(vat);   从缸中打一桶水;  V(vat);
    V(empty);
    喝水;
    V(pail);
}
```
⛳3
::note
- {{扣|死锁}}：若小和尚先 P(pail) 再 P(empty)，缸满时 3 个小和尚可能拿着 3 个桶都在等 empty，老和尚没桶可用 ⟹ 死锁。所以 P(empty)、P(full) 要放在 P(pail) 之前。
- 打水和倒水是两个互斥段，打完水先 V(well) 再去等缸，不要占着井。
::

#46
::think
1. 每块能放 4KB/4B ＝ 1024 个地址 ⟹ 一次间接 1024 块、二次 $1024^2$、三次 $1024^3$。
2. 第 2 问：2GB 文件有 $2^{19}$ 个数据块，先扣直接 10、一次间接 1024，剩下的落在二次间接里，数要用几个索引块。
::paper
解　(1) 每个索引块可存 $4\text{KB}/4\text{B}=1024$ 个地址。⛳3
最大块数 $=10+1024+1024^2+1024^3$，最大文件长度 $=(10+1024+1024^2+1024^3)\times4\text{KB}=40\text{KB}+4\text{MB}+4\text{GB}+4\text{TB}\approx4\text{TB}$。
(2) 2GB 文件的数据块数 $2\text{GB}/4\text{KB}=2^{19}=524288$。⛳4
直接地址项 10 块，一次间接 1 个索引块管 1024 块，剩余 $524288-1034=523254$ 块用二次间接：需二级下层索引块 $\lceil523254/1024\rceil=511$ 个，外加 1 个二次间址块。
索引块共 $1+1+511=513$ 个，占 $513\times4\text{KB}=2\text{MB}+4\text{KB}$。
该文件实际占用 $2\text{GB}+2\text{MB}+4\text{KB}$（再加 i_node 本身 $13\times4\text{B}=52\text{B}$）。
::note
- {{扣|漏顶层}}：二次间接要算上最上面那一个二次间址块。
- i_node 是否算进占用空间各家口径不同，卷面写上「另加 i_node 52B」两种口径都照顾到。
::

#47
::think
1. TCP 首部固定 20B：源端口 2、目的端口 2、序号 4、确认号 4、首部长度 4 位 ＋ 保留 ＋ 标志 6 位、窗口 2、检验和 2、紧急指针 2。
2. 按偏移切字节，十六进制转十进制；看标志位判断处在连接的哪一步。
::paper
解　(1) 第 1、2 字节 0D28H ＝ 3368 为源端口；第 3、4 字节 0015H ＝ 21 为目的端口。⛳2
(2) 第 5～8 字节 505F A906H 为序号（十进制 1348446470）；第 9～12 字节 0000 0000H，确认号为 0。⛳2
(3) 第 13 字节 70H 的高 4 位为 7，首部长度 $7\times4=28$B，说明有 8B 选项。⛳2
(4) 目的端口 21 ⟹ FTP 的控制连接。第 14 字节 02H：只有 SYN＝1，ACK＝0 ⟹ 这是客户发起连接的第一次握手报文（客户端处于 SYN_SENT 状态）。⛳3
::note
- {{扣|首部长度单位}}：数据偏移以 4B 为单位，写成「7 字节」直接扣分。
- 序号写十六进制或十进制都可以；ACK＝0 时确认号字段无意义，写「为 0 / 无效」都行。
- 字段值已用程序逐字节解析（`_build/mock/chk/3002.py`）。
