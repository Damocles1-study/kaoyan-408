文件最终都落在磁盘上。这一话回答三个问题：读一块要多久，多个请求排队时先做谁，以及没有磁头的 SSD 又有什么不同。

其之壹结构

结构：磁盘有多个盘面，每面一个磁头；盘面上一圈圈的是磁道；磁道分成扇区；所有盘面半径相同的磁道组成柱面。地址 = 柱面号 + 盘面号 + 扇区号。

为什么按柱面编址？磁头臂一起动，同一柱面上换盘面不用寻道。所以连续数据应放同一柱面。

读一个扇区要三步：把磁头移到磁道（寻道）；等扇区转到磁头下（旋转延迟）；读过这个扇区（传输）。

术式
磁盘访问时间

Ta = 寻道时间 + 平均旋转延迟 + 传输时间 + 控制器延迟
平均旋转延迟 = 转一圈时间的一半 = 1/(2r)。
传输时间 = 字节数 ÷ (每圈字节 × 转速)，或字节数 ÷ 传输率。

算一遍：6000 转/分，即 10 ms 一圈，旋转延迟 5 ms。平均寻道 8 ms，每道 100 个扇区，读一个扇区要 10÷100 = 0.1 ms。一次访问 8 + 5 + 0.1 = 13.1 ms。其中寻道和旋转占了绝大部分，所以优化它们最划算。

磁盘最小读写单位是扇区，不是字节。RAID 把多块盘组成一个：RAID 0 条带（快，无冗余）；RAID 1 镜像（可靠）；RAID 5 分布式校验（兼顾）。条带化靠并行提速，镜像和校验才提高可靠性。

磁盘的管理：

格式化：

  • 物理（低级）格式化：划分扇区，写校验。
  • 分区：把磁盘分成多个逻辑盘。
  • 逻辑（高级）格式化：建立文件系统（根目录、空闲空间管理）。

引导块：开机时 ROM 里的自举程序把引导块读入内存。它在磁盘的固定位置。坏块：低级格式化时会预留备用扇区，坏了就用备用的替换（简单系统由 FAT 标记）。

合上页面说一遍：访问一个扇区的时间由哪几段组成？三种格式化各做什么？

寻道、旋转、传输。物理格式化划扇区；分区分逻辑盘；逻辑格式化建文件系统。

其之參其他优化

除了调度，还有几种办法：提前读（读一块时连带读后面的，靠空间局部性）、延迟写（先放缓冲区，以后一起写）、磁盘高速缓存、连续分配（减少寻道）。

交替编号：磁盘转得快，读完一个扇区要处理一下，这时下一个扇区已经过头了，又得等一圈。于是把逻辑相邻的扇区在物理上隔开放。例如交替因子 2:1 时物理顺序是 0 4 1 5 2 6 3 7。错位命名：相邻盘面的 0 号扇区错开一点，换盘面的那一点时间正好转到。

其之肆固态硬盘

术式
SSD 的特点

由闪存块构成，每块多个页；按页读写，按块擦除。写之前必须先擦。
读快（随机访问），写比读慢；没有机械部件，所以无寻道延迟，调度算法基本用 FCFS。
闪存转换层（FTL）：逻辑块到物理页的映射。
磨损均衡：每块擦写次数有限。动态：写入时选低磨损的块；静态：周期性搬动长时间不变的数据。

为什么有 FTL？闪存不能原地改写，改一页要把新数据写到别处，并把旧页标记为无效。闪存翻译层负责维护这个映射，让上层仍然觉得是在写同一个块号。之后再集中回收无效页（垃圾回收）：把块里还有效的页搬走，擦除整块。

为什么写慢：不只是擦除慢，有时写一页要先搬动一整块。这种情况越多，写得越多，寿命也越短。

合上页面说一遍：六种磁盘算法各有什么特点？SSD 的读、写、擦单位？

FCFS 公平慢；SSTF 最近优先会饥饿；SCAN 到头掉头；LOOK 到最后请求掉头；C- 版本单向。按页读写，按块擦除。

领域展开

时间：寻道 + 1/(2r) + 传输 + 控制。
算法：SCAN 到头、LOOK 到请求、C- 单向。
C-SCAN 返程：口径看题。
SSD：页读写、块擦除；磨损均衡。

2013實戰磁盘存取时间四项式
某磁盘的转速为 10000 转/分，平均寻道时间是 6ms，磁盘传输速率是 20MB/s，磁盘控制器延迟为 0.2ms，读取一个 4KB 的扇区所需的平均时间约为（　）。

磁盘转速是 10000 转/分，转一圈的时间为 6ms，因此平均查询扇区的时间为 3ms（转半周）；平均寻道时间为 6ms；读取 4KB 扇区信息的时间为 4KB ÷ 20MB/s = 0.2ms；磁盘控制器延迟为 0.2ms。总时间 = 3 + 6 + 0.2 + 0.2 = 9.4ms。
6 + 3 + 0.2 + 0.2 = 9.4 ms。转一圈 6 ms，一半 3 ms。4KB / 20 MB/s = 0.2 ms。

📌 "平均旋转等待 = 转半周"要能说出理由：目标扇区在盘上的位置是随机的，最好情况刚好转到（0），最坏情况差一整圈（T），均匀分布下期望值就是 T/2。同理，"平均寻道时间 ≈ 最大寻道时间的一半"也是这个道理。
⚠️⚠️ 与 2015 真题（3.4-11）的唯一区别：本题多了"控制器延迟"这一项。⟹ 铁律：题目给什么就加什么，不要自己脑补，也不要漏加。完整的响应时间还包括"排队延迟"，但那属于 OS 的磁盘调度，组原题里一般不给。
📌 心算加速：10000 转/分 = 6ms/圈是个应该背下来的数（60000 ÷ 10000 = 6）。常见转速对照：5400 → 11.1ms、7200 → 8.33ms、10000 → 6ms、15000 → 4ms。
📌 传输时间那一步别被单位绕：4KB ÷ 20MB/s = 4/(20×1024) 秒 ≈ 0.195ms，书取 0.2ms。选项间距很大（9 / 9.4 / 12 / 12.4），四舍五入不影响判断。
2015實戰磁盘平均存取时间（无控制器延迟）

8 + 4.17 + 1/1000 × 8.33 ≈ 12.2 ms。

2019實戰磁盘存储器概念综合
下列关于磁盘存储器的叙述中，错误的是（　）。

磁盘存储器的最小读/写单位为一个扇区，即磁盘按块存取，故 C 错误。磁盘存储数据之前需要进行格式化，将磁盘分成扇区并写入信息，因此磁盘的格式化容量比非格式化容量小；磁盘扇区中包含数据、地址和校验等信息；磁盘存储器由磁盘控制器、磁盘驱动器和盘片组成。
再深一层
选 C（它是错的）。⭐ 这道 2019 真题一题串起 3.4 的四个核心概念，是本节最佳收官题：
选项考的概念判定
A 格式化 < 非格式化格式开销（扇区标识、校验、间隙）✅
B 扇区含数据/地址/校验扇区的内部结构✅
C 最小读/写单位 1 字节磁盘是块设备❌ 应为一个扇区

📌 C 为什么必须是扇区而不能是字节？因为磁盘是靠"磁头相对盘片运动"来读写的，一旦磁头对准了目标扇区的起点，数据就连续不断地流出来，无法在中途"只取一个字节就停"。而且扇区自带地址标识和校验码，必须整段读出才能校验。
🔗 "按块存取"这条一路串到 OS：磁盘按扇区（块）读写 ⟹ 文件系统以"簇/块"为分配单位 ⟹ 虚拟存储以"页"为调入单位。整条链上"最小单位是一整块"这件事从未改变——代价是内部碎片（读 1 字节也得搬一整块），收益是摊薄了昂贵的定位开销。
📌 D 项的"三件套"要能背：磁盘控制器（与主机的接口，解析命令）+ 磁盘驱动器（转盘片、动磁头）+ 盘片（介质）。对照 SSD：闪存翻译层相当于磁盘控制器，闪存芯片相当于盘片，没有驱动器（无机械部件）。
2013實戰RAID 提高可靠性的措施
下列选项中，用于提高 RAID 可靠性的措施有（　）。
Ⅰ. 磁盘镜像　Ⅱ. 条带化　Ⅲ. 奇偶校验　Ⅳ. 增加 Cache 机制

RAID0 方案是无冗余和无校验的磁盘阵列技术，而 RAID1~RAID5 方案均是加入了冗余（镜像）或校验的磁盘阵列技术。因此，提高 RAID 可靠性的措施主要是对磁盘进行镜像和奇偶校验，其余选项不符合条件。条带化是一种将数据分片、分别存储至不同磁盘、提高读/写速度的技术，其缺点是没有冗余，若其中一块磁盘损坏则数据就会丢失，因此条带化通常和磁盘镜像或奇偶校验结合使用，形成不同的 RAID 级别。
镜像和校验提升可靠性。条带提升速度。
再深一层
选 B（仅 Ⅰ、Ⅲ）。本题只考一件事：分清"提速的手段"和"保命的手段"。
手段提速？提可靠？为什么
Ⅰ 磁盘镜像读可略快✅数据存两份，坏一块还有另一块
Ⅱ 条带化✅ 主要目的❌ 反而更危险多盘并行读写；但坏一块，整条数据就断了
Ⅲ 奇偶校验❌（写还变慢）✅坏一块可由其余盘 + 校验位推算恢复
Ⅳ 增加 Cache✅❌纯粹是加速手段，掉电还可能丢缓存中的数据
⚠️⚠️ Ⅱ 条带化是最险的错项：它是 RAID0 的核心技术，听起来"RAID 都是好东西"，但 RAID0 恰恰是唯一没有任何冗余的级别——盘越多，整体故障率越高。⟹ 条带化不但不提高可靠性，反而降低可靠性。
📌 RAID 级别速查（选择题足够用）：
RAID0  条带化，无冗余无校验      ← 只快，不保命
RAID1  镜像                    ← 保命，容量减半
RAID2  海明码纠错
RAID3  位交叉奇偶校验
RAID4  块交叉奇偶校验
RAID5  分布式奇偶校验，无独立校验盘
📌 记忆钩子：0 是零冗余，1 是一比一镜像，2 是海明，3 位 4 块，5 把校验摊开。王道只要求认得级别的定义，不要求算恢复过程。
🔗 Ⅲ 奇偶校验的原理就是 ch2 学过的那个奇偶校验：已知其余位和校验位，就能反推出缺失的那一位——RAID5 恢复坏盘用的正是这条，只是把"位"换成了"块"。
2017實戰逻辑格式化的内容
下列选项中，磁盘逻辑格式化程序所做的工作是（　）。
Ⅰ. 对磁盘进行分区　Ⅱ. 建立文件系统的根目录
Ⅲ. 确定磁盘扇区校验码所占位数　Ⅳ. 对保存空闲磁盘块信息的数据结构进行初始化

新磁盘是空白盘，必须分成扇区以便磁盘控制器能进行读/写操作，这个过程称为低级格式化（或物理格式化）。低级格式化为每个扇区使用特别的数据结构，说法Ⅲ错误。为了使用磁盘存储文件，操作系统还需要将自己的数据结构记录在磁盘上。这分为两步：第一步是将磁盘分为由一个或多个柱面组成的分区，每个分区可以作为一个独立的磁盘，说法Ⅰ错误。在分区之后，第二步是逻辑格式化（创建文件系统）。在这一步，操作系统将初始的文件系统数据结构存储到磁盘上。这些数据结构包括空闲和已分配的空间及一个初始为空的目录，说法Ⅱ、Ⅳ正确。

选 B（仅 Ⅱ、Ⅳ）。四项恰好分属三个不同阶段，是"格式化三步"的标准考法。
四项归位

Ⅰ 对磁盘进行分区       ⟹ 分区阶段（写 MBR 分区表）✗
Ⅱ 建立文件系统的根目录 ⟹ 逻辑格式化 ✓
Ⅲ 确定扇区校验码位数   ⟹ 低级（物理）格式化（扇区尾部 CRC）✗
Ⅳ 初始化空闲块数据结构 ⟹ 逻辑格式化 ✓

逻辑格式化 = 在分区上"建文件系统"，产物三样：
  ① 根目录（初始为空）
  ② 空闲空间管理数据结构（位示图 / 空闲链表）
  ③ 已分配空间的管理结构（FAT / inode 表）
⭐ 2017 与 2021 是同一考点连考：2017（本题）问"逻辑格式化做什么"，2021 综合真题问"四个操作的正确顺序 + 扇区划分与根目录建立各在哪一步"。⟹ 把"物理格式化 / 分区 / 逻辑格式化 / 装系统"这四步的产物列成表，两道题一起解决。
⚠️ Ⅰ 项最容易误选：因为"分区"在日常语境里常被说成"格式化磁盘"。但在 OS 术语里，分区是独立的一步，夹在物理格式化与逻辑格式化之间。
2009實戰SCAN 算法的访问序列
假设磁头当前位于第 105 道，正在向磁道序号增加的方向移动。现有一个磁道访问请求序列为 35, 45, 12, 68, 110, 180, 170, 195，采用 SCAN 调度（电梯调度）算法得到的磁道访问序列是（　）。

SCAN 算法的原理类似于电梯。首先，当磁头从 105 道向序号增加的方向移动时，便会按照从小到大的顺序服务所有大于 105 的磁道号（110, 170, 180, 195）；往回移动时又会按照从大到小的顺序进行服务（68, 45, 35, 12）。
105 上行：110, 170, 180, 195 走完，回到 68…。

2015實戰SCAN 的总移动磁道数 · 方向的中文表述
某硬盘有 200 个磁道（最外侧磁道号为 0），磁道访问请求序列为 130, 42, 180, 15, 199，当前磁头位于第 58 号磁道并从外侧向内侧移动。按照 SCAN 调度方法处理完上述请求后，磁头移过的磁道数是（　）。

SCAN 算法就是电梯调度算法。顾名思义，若开始时磁头向外移动，就一直要到最外侧，然后返回向内侧移动，就像电梯若往下，则一直要下到底层才会再上升一样。当前磁头位于 58 号并从外侧向内侧移动，先依次访问 130、180 和 199，然后返回向外侧移动，依次访问 42 和 15，因此磁头移过的磁道数是 (199 − 58) + (199 − 15) = 325。
58→199→15：141 + 184 = 325。SCAN 要走到最内侧 199。
再深一层
选 C（325）。本题第一步不是算数，是把"从外侧向内侧"翻译成"磁道号增大"。
两步走

第一步：翻译方向
  题给「最外侧磁道号为 0」
  ⟹ 越往内磁道号越大
  ⟹ 「从外侧向内侧移动」＝向磁道号增大的方向

     →折返→42→15
  距离 = (199−58) + (199−15) = 141 + 184 = 325 ✓

⚠️ 磁道 0～199，199 已是最内侧端点
  ⟹ 本题 SCAN 与 LOOK 结果相同，不必纠结端点
⭐ 本题的运气在于 199 恰好是端点：若请求序列里最大只到 180，则 SCAN 要走到 199（多走 19），LOOK 只到 180——两者就会差出 38 个磁道。⟹ 做题时先看"本方向最远的请求"是不是端点，是则两算法等价，否则必须看题干措辞。

2018實戰磁头臂黏着
系统总是访问磁盘的某个磁道而不响应对其他磁道的访问请求，这种现象称为磁头臂黏着。下列磁盘调度算法中，不会导致磁头臂黏着的是（　）。

当系统中总是持续存在某个磁道的访问请求时，均持续满足最短寻道时间优先、扫描算法和循环扫描算法的访问条件，会一直服务该访问请求，尽管系统中还存在其他磁道的访问请求，但却得不到响应。而先来先服务按照请求次序进行调度，比较公平。
磁臂黏着：只有 FCFS 不会。SSTF、SCAN、C-SCAN 都可能（新请求总在附近）。
再深一层
选 A（FCFS）。⚠️ 注意范围：饥饿只有 SSTF 一个，磁臂黏着有 SSTF/SCAN/C-SCAN 三个。
为什么 SCAN 也会黏着（这是本题最反直觉处）

  SCAN 保证「迟早会扫到远处」⟹ 所以不饥饿
  但若某个磁道的请求源源不断：
    磁头扫到该磁道时，那里总有活干
    ⟹ 磁头停在那儿一直服务，走不掉 ⟹ 黏着

  FCFS 按到达顺序处理，新请求只能排到队尾
    ⟹ 磁头处理完队首就必须走 ⟹ 不会黏着 ✓

饥饿 ⊂ 黏着：SSTF 两者都有；SCAN/C-SCAN 只黏着不饥饿
⭐ 治黏着的两个算法就是为此而生：NStepSCAN：把请求队列切成若干长度为 N 的子队列，队列间 FCFS、队列内 SCAN；处理某子队列时新到的请求放进别的子队列，不插入当前队列⟹ 当前队列迟早处理完，磁头必然走掉。
FSCAN：固定两个队列——"当前服务队列"（开始时已有的请求，按 SCAN 处理）与"新请求队列"（本轮新到的全部推迟到下一轮）。"冻结当前、延后新请求"就是它的八字方针。
⭐ NStepSCAN 的两端退化（明摆着的选择题）：N 很大 ⟹ 趋近 SCAN；N = 1 ⟹ 退化为 FCFS。⟹ 这也从侧面印证了本题：N=1 时不黏着，正因为它变成了 FCFS。
2018實戰提高文件访问速度的方法
下列优化方法中，可以提高文件访问速度的是（　）。

说法Ⅱ和Ⅳ显然均能提高文件访问速度。对于说法Ⅰ，提前读是指在读当前盘块时，将下一个盘块提前读入缓冲区，以便需要时直接从缓冲区中读取，提高了文件的访问速度。对于说法Ⅲ，延迟写是指先将数据写入缓冲区，并置上"延迟写"标志，以备不久之后访问，当缓冲区需要再次被分配出去时，才将缓冲区数据写入磁盘，减少了访问磁盘的次数，提高了文件的访问速度。

四项各减少了什么开销

Ⅰ 提前读   读当前块时顺带把下一块读进缓冲区
         ⟹ 顺序访问时后续块直接命中，不必访盘
Ⅱ 连续的簇 文件块物理相邻 ⟹ 寻道 + 旋转延迟都减少
Ⅲ 延迟写   先写缓冲区置标志，被替换时才真写盘
         ⟹ 合并多次写，减少访盘次数
Ⅳ 磁盘高速缓存 命中即不访盘

⟹ Ⅰ、Ⅲ、Ⅳ 减少访盘次数；Ⅱ 减少每次访盘的代价
⭐ Ⅲ"延迟写"最容易被怀疑：直觉上"推迟写入"像是变慢了，但对用户进程而言 write 立即返回 ⟹ 感知上更快；对系统而言多次小写被合并 ⟹ 访盘次数更少。代价是可靠性（断电丢数据），但题目问的是"速度"。

2010實戰位示图 · C-SCAN 的总时间 · Flash 的调度策略
假设计算机系统采用 C-SCAN（循环扫描）磁盘调度策略，使用 2KB 的内存空间记录 16384 个磁盘块的空闲状态。
1) 请说明在上述条件下如何进行磁盘块空闲状态的管理。
2) 某单面磁盘的旋转速度为 6000 转/分，每个磁道有 100 个扇区，相邻磁道间的平均移动时间为 1 ms。若在某时刻，磁头位于 100 号磁道处，并沿着磁道号增大的方向移动，磁道请求队列为 50, 90, 30, 120，对请求队列中的每个磁道需读取 1 个随机分布的扇区，则读完这 4 个扇区点共需要多少时间？要求给出计算过程。

1) 用位图表示磁盘的空闲状态。每位表示一个磁盘块的空闲状态，共需 16384/32 = 512 个字 = 512×4B = 2KB，正好可放在系统提供的内存中。2) 采用 C-SCAN 算法，访问磁道的顺序和移动的磁道数为：120（移动 20）、30（移动 90）、50（移动 20）、90（移动 40）。移动的磁道数为 20+90+20+40 = 170，因此总的移动磁道时间为 170 ms。转速为 6000 转/分，因此平均旋转延迟为 5 ms，总的旋转延迟时间 = 20 ms。转速为 6000 转/分，因此读取一个磁道上的一个扇区的平均读取时间为 0.1 ms，总的读取扇区的时间为 0.4 ms。综上，读取上述磁道上所有扇区所花的总时间为 190.4 ms。3) 采用先来先服务（FCFS）调度策略更高效。因为 Flash 半导体存储器的物理结构不需要考虑寻道时间和旋转延迟，可直接按 I/O 请求的先后顺序服务。

💭 思路
  1. 第 1 问是"倒着问"的位示图题：题目已经把内存大小（2KB）和块数（16384）都给了，实际要你验证"位示图恰好装得下"。2KB = 16384 位，一位管一块 ⟹ 不多不少正好。这种"数字刚好吻合"就是答案的信号。
  2. 第 2 问要把三段时间分开算再相加：寻道（移动磁道数 × 1 ms）+ 旋转延迟（每次半圈）+ 读扇区（每次 1/100 圈）。"随机分布的扇区"这句话是在告诉你每次都要算平均旋转延迟。
  3. C-SCAN 的顺序：磁头在 100 向大的方向 ⟹ 先服务 120，然后循环回到小端，依次 30、50、90。
  4. 第 3 问送分：Flash 无寻道、无旋转延迟，重排请求毫无意义 ⟹ FCFS。
✍️ 考场卷面
(1) 磁盘块空闲状态的管理
　采用位示图（位图）法管理：用一个二进制位表示一个磁盘块的空闲状态（如 0 表示空闲、1 表示已分配）。
　所需空间 = 16384 位 = 16384 / 8 = 2048 B = 2KB，（若以 32 位字为单位则为 16384/32 = 512 个字 = 512×4B = 2KB）
　与系统提供的 2KB 内存空间恰好相等，故可将整个位示图常驻内存，实现快速的分配与回收。 ⛳ 4 分
(2) 磁头位于 100 号磁道，沿磁道号增大方向移动，采用 C-SCAN 策略，访问顺序及移动距离如下：
　　被访问的下一个磁道号：120 → 移动 20
　　　　　　　　　　　　30 → 移动 90
　　　　　　　　　　　　50 → 移动 20
　　　　　　　　　　　　90 → 移动 40
　（i）寻道时间：移动磁道数 = 20 + 90 + 20 + 40 = 170，相邻磁道平均移动时间 1 ms，故寻道时间 = 170 ms　……(1) ⛳ 4 分
　（ii）旋转延迟：转速 6000 转/分 ⟹ 旋转一圈 60/6000 s = 10 ms，扇区随机分布，平均旋转延迟为半圈 = 5 ms；4 次访问共 4 × 5 = 20 ms　……(2) ⛳ 3 分
　（iii）读取扇区时间：每磁道 100 个扇区，读一个扇区需 10 / 100 = 0.1 ms；4 个扇区共 4 × 0.1 = 0.4 ms　……(3) ⛳ 2 分
　由 (1)(2)(3) 得总时间
　　T = 170 + 20 + 0.4 = 190.4 ms ⛳ 2 分
(3) 有，可采用先来先服务（FCFS）调度策略。
　理由：Flash 半导体存储器无机械运动部件，不存在磁头寻道与盘片旋转，访问任意存储单元的时间基本相同，因此重排请求顺序不能带来任何收益，反而增加调度开销；直接按 I/O 请求的先后顺序服务即可，且 FCFS 实现简单、绝对公平、不会产生饥饿。 ⛳ 4 分
即位示图恰好占用 2KB 内存；读完 4 个扇区共需 190.4 ms；对 Flash 存储器应改用 FCFS 调度策略。

2019實戰磁盘容量 · SSTF · 簇号转物理地址
某计算机系统中的磁盘有 300 个柱面，每个柱面有 10 个磁道，每个磁道有 200 个扇区，扇区大小为 512B。文件系统的每簇包含 2 个扇区。请回答下列问题：
1) 磁盘的容量是多少？
2) 设磁头在 85 号柱面上，此时有 4 个磁盘访问请求，簇号分别为 100260, 60005, 101660 和 110560。采用最短寻道时间优先 SSTF 算法，系统访问簇的先后次序是什么？
3) 簇号 100530 在磁盘上的物理地址是什么？将簇号转换成磁盘物理地址的过程由 I/O 系统的什么程序完成？

2019。容量 = 300×10×200×512B。每柱面 1000 簇（10×200÷2），所以 85 号柱面对应簇号 85000~85999。SSTF 就是先把簇号换算成柱面，再比距离。

💭 思路
  1. 第 1 问是纯乘法，但要小心单位：题目没说单位，写成 KB 或 MB 都行，但必须标注。
  2. 第 2 问的关键是"簇号也要先换成柱面号"——SSTF 比的是柱面距离（寻道距离），不是簇号大小！必须先算出每柱面有多少簇，再把四个簇号折算成柱面。
  3. 每柱面簇数 = 10 磁道 × 200 扇区 ÷ 2 扇区/簇 = 1000 簇⟹ 85 号柱面对应簇号 85000～85999。四个请求折算：100260→柱面 100、60005→柱面 60、101660→柱面 101、110560→柱面 110。
  4. 于是 SSTF 从柱面 85 出发：100（距 15）→ 101（距 1）→ 110（距 9）→ 60（距 50）。⚠️ 注意 60 号柱面虽然簇号最小，却最后才被访问——这就是 SSTF 的饥饿倾向。
  5. 第 3 问是三级换算，与综 01 同型，只是多了一层"簇 → 扇区"。扇区号那一步要乘回 2，这是最容易漏的。
✍️ 考场卷面
(1) 磁盘容量
　容量 = 柱面数 × 每柱面磁道数 × 每磁道扇区数 × 每扇区大小
　　　 = 300 × 10 × 200 × 512 B = 307 200 000 B
　　　 = 307 200 000 / 1024 KB = 3 × 10⁵ KB（约 293 MB） ⛳ 3 分
(2) SSTF 访问次序
　（i）每簇 2 个扇区，故
　　每磁道簇数 = 200 / 2 = 100；每柱面簇数 = 10 × 100 = 1000　……(1) ⛳ 2 分
　（ii）由 (1) 式，簇号 n 所在柱面号 = ⌊n / 1000⌋，故
　　100260 → 柱面 100；60005 → 柱面 60；101660 → 柱面 101；110560 → 柱面 110
　　（85 号柱面对应的簇号范围为 85000～85999） ⛳ 3 分
　（iii）磁头初始在柱面 85，按 SSTF 每次选择柱面距离最近者：
　　85 → 100（距 15，最近）→ 101（距 1）→ 110（距 9）→ 60（距 50）
　故访问簇的先后次序为 100260 → 101660 → 110560 → 60005。 ⛳ 3 分
(3) 簇号 100530 的物理地址
　　柱面号 = ⌊100530 / 1000⌋ = 100
　　磁头号 = ⌊(100530 mod 1000) / 100⌋ = ⌊530 / 100⌋ = 5
　　扇区号 = (530 × 2) mod 200 = 1060 mod 200 = 60 ⛳ 4 分
　即物理地址为（柱面号 100，磁头号 5，扇区号 60）。
　将簇号转换为磁盘物理地址的工作与具体磁盘的几何参数相关，由 I/O 系统中的磁盘驱动程序完成。 ⛳ 2 分
即磁盘容量为 3×10⁵ KB；访问次序为 100260, 101660, 110560, 60005；簇号 100530 的物理地址为（100, 5, 60），该转换由磁盘驱动程序完成。
📌 批注
⚠️ 第 2 问的最大陷阱：拿簇号直接比大小
若按簇号比：85000 附近最近的会被误判。SSTF 比的是柱面距离（寻道代价），必须先把簇号折算成柱面号。
本题的巧妙之处在于——60005 的簇号最小，却因为柱面 60 离 85 最远（距 50），排在最后。⟹ 出题人正是用它来验你有没有真的做换算。
⚠️ 第 3 问扇区号那一步为什么要 ×2
柱面号与磁头号是按簇算的（每柱面 1000 簇、每磁道 100 簇），但扇区号必须用扇区计——簇内偏移 530 簇 ⟹ 530 × 2 = 1060 个扇区 ⟹ mod 200 = 60。
漏掉这个 ×2 会得到 30，是最典型的错法。
扣分点 容量不写单位或漏除 1024。
扣分点 第 2 问只给次序不给柱面折算过程：折算才是采分点。
扣分点 第 3 问漏答"由磁盘驱动程序完成"——这一小问与 2013 真题（5.3-40）完全同源："计算柱面号、磁头号、扇区号的程序是设备驱动程序"。同一考点，2013 出选择、2019 出综合。
通用模板（含簇的三级换算）
设每簇 k 个扇区、每磁道 S 个扇区、每柱面 H 个磁道，则
　每磁道簇数 = S/k，每柱面簇数 = H·S/k
　柱面 = ⌊n /(H·S/k)⌋ · 磁头 = ⌊(n mod H·S/k)/(S/k)⌋ · 扇区 = (余簇 × k) mod S

时间题：别漏旋转延迟的一半，也别把转速单位弄错。 调度题直接按定义走；可能给请求和方向，问访问顺序或总距离。 C-SCAN 的返程：历年口径不一，这就是它最容易丢分的原因。 大题把 C-SCAN 和块号到柱面、扇区的换算连在一起，再加 DMA 或时间计算。 「能提高性能」题：提前读、延迟写、缓存、连续分配都算；改调度只对多请求有效。
