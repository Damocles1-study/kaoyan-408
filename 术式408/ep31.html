Cache 的大题差不多每年都在。不难，但有几个地方算错了后面全错。流程固定：先画地址结构，再说映射，最后算命中率。

其之壹基本原理

CPU 要访问主存时，先在 Cache 里找。数据以块（行）为单位在 Cache 和主存之间搬。

术式
性能公式

命中率 H = 命中次数 / 总访问次数。
先访问 Cache，不命中再访问主存：T = H·Tc + (1−H)(Tc+Tm)。
同时访问：T = H·Tc + (1−H)·Tm。
CPI 带缺失：CPI = CPI₀ + 每条指令访存次数 × 缺失率 × 缺失损失。

2009實戰命中率的定义·审题
假设某计算机的存储系统由 Cache 和主存组成，某程序执行过程中访存 1000 次，其中访问 Cache 缺失（未命中）50 次，则 Cache 的命中率是（　）。

命中率 = Cache 命中次数 / 总访问次数 = (1000 − 50)/1000 = 95%。注意看清题目，题中说明的是缺失 50 次，而不是命中 50 次，仔细审题是做对题的第一步。
再深一层
选 D。2009 年的送分题，唯一的考点是审题：题给的是「缺失 50 次」，不是「命中 50 次」。
命中次数 = 1000 − 50 = 950
命中率   = 950 / 1000 = 95% ✔

（若误读成"命中 50 次"，就会算出 5% —— 正是选项 A）
📌 Cache 性能的三个基本量，定义要背准：
量定义
命中率 H命中次数 ÷ 总访问次数
缺失率 M1 − H
平均访问时间 AMATH×Tc + (1−H)×(Tc + Tm)（408 串行口径，见 3.5-03）
⚠️ 选项 A（5%）就是为"看反了"准备的——四个选项里 5% 和 95% 成对出现，是典型的"审题陷阱题"标志。凡看到互补的一对选项（5%/95%、40%/60%），先回头确认题问的是命中还是缺失。
📌 顺带做个量感检查：95% 的命中率听起来很高，但按 3.5-03 的参数（2ns/42ns）算，AMAT = 0.95×2 + 0.05×42 = 4ns，是纯 Cache 的两倍。⟹ 95% 在 Cache 世界里其实算差的，实际系统普遍要 98%~99% 以上。

其之貳三种映射

比方

停车场

直接映射：每辆车只能停指定的车位（车牌尾号决定），停了就要赶走原来那辆。全相联：随便停，但找车时要所有车位都看一遍。组相联：分成几个区，指定区内随便停。

假设主存地址 32 位、块 64 B（2⁶）、Cache 共 128 行（2⁷）：

▣ 同一个地址的三种切法
直接映射：块内 6 位（64 B）；行号 7 位（128 行）；其余 19 位是标记。Cache 行号 = 块号 % 行数。比较 1 个标记，冲突多。
全相联：没有行号，地址除了块内都是标记。要比较所有行的标记，冲突最少，硬件最贵。
4 路组相联：128/4 = 32 组，组号 5 位。行数不变，路数翻倍，组号少一位，标记多一位。组内比较 4 个。
术式
地址划分三步

① 块内偏移 = log₂(块大小)，块大小以字节算要用「编址单位」。
② 组号 = log₂(行数 / 路数)。
③ 标记 = 地址总位数 − 前两者。
找块：块号 = 地址 / 块大小，组号 = 块号 % 组数。

2009實戰2 路组相联·标准口径求组号
某计算机的 Cache 共有 16 块，采用 2 路组相联映射方式（每组 2 块）。每个主存块大小为 32B，按字节编址，主存 129 号单元所在主存块应装入的 Cache 组号是（　）。

因为 Cache 共有 16 块，采用 2 路组相联映射方式，共分为 8 组，组号为 0, 1, 2, …, 7，组号占 3 位。主存块大小为 32B，按字节编址，块内地址占 5 位。主存单元地址 129 = 0…0 100 00001，后 5 位是块内地址，块内地址的前 3 位是组号，所以将映射到组号 4 的任意一个 Cache 块中。
129/32 = 4 号块。8 组，4%8 = 4。
再深一层
选 C。标准口径（本书 / 唐朔飞 / 2009 真题）：组号 = 主存块号 mod 组数。
组数 = 16 块 ÷ 2 路 = 8 组 ⟹ 组号 3 位
块内地址 = log₂32 = 5 位

主存块号 = 129 div 32 = 4
组号     = 4 mod 8 = 4 ✔

位串验证：129 = 100 00001₂
           └组号┘└块内 5 位┘
           = 100₂ = 4 ✔

2012實戰组相联的两种分组口径 · LRU 模拟
假设某计算机按字编址，Cache 有 4 行，Cache 和主存之间交换的块大小为 1 个字。若 Cache 的内容初始为空，采用 2 路组相联映射方式和 LRU 算法，则访问的主存地址依次为 0, 4, 8, 2, 0, 6, 8, 6, 4, 8 时，命中 Cache 的次数是（　）。⚠️ 本题的映射方式与本书正文所讲的不同，务必看核对栏的双口径说明。

地址映射采用 2 路组相联，本题按“地址范围分组”：主存字地址为 0~1、4~5、8~9 可映射到第 0 组 Cache 中，主存地址为 2~3、6~7 可映射到第 1 组 Cache 中。经 LRU 置换过程模拟，命中 3 次（分别在访问 8、6、8 时）。
📕 书上“注意”框原文：在不同的计算机组成原理教材中，关于组相联映射的介绍并不相同。通常是采用上题（第 29 题）中的方式，也是本书和唐朔飞所编教材中的方式，但本题中采用的是蒋本珊所编教材中的方式。可以推断两次命题的老师应该不是同一老师，这也给考生答题带来了困扰。

术式
Cache 总容量（真题常考）

每行 = 数据位 + 标记位 + 有效位(1) + 脏位(回写才有，1) + 替换位(LRU 才有)。
总容量 = 行数 × 每行位数。

2015實戰直接映射 Cache 总容量
假定主存地址为 32 位，按字节编址，主存和 Cache 之间采用直接映射方式，主存块大小为 4 个字，每字 32 位，采用回写方式，则能存放 4K 字数据的 Cache 的总容量的位数至少是（　）。

按字节编址，块大小为 4×32 位 = 16B = 24B，则字块内地址占 4 位；能存放 4K 字数据的 Cache 即存储容量为 4K 字，则 Cache 共有 1K = 210 个 Cache 行，Cache 字块标记占 10 位；主存字块标记占 32 − 10 − 4 = 18 位。Cache 总容量包括存储容量和标记阵列容量（有效位、标记位、脏位和替换算法控制位）。标记阵列中的有效位和标记位一定存在，而脏位和替换算法控制位的取舍需要看题意：题目中明确说明了采用回写法，则一定包含一致性维护位，而关于替换算法的词眼题目中未提及，所以不予考虑。因此每个 Cache 行标记项包含 18 + 1 + 1 = 20 位，标记阵列容量为 210×20 = 20K 位；存储容量为 4K×32 = 128K 位；总容量为 128K + 20K = 148K 位。
块 16B（4 字），4K 字 = 1K 行。标记 32−10−4 = 18，+有效 1 + 脏 1 = 20 位，+数据 128 位 = 148 位。总共 148K 位。这是公式的直接应用。
再深一层
选 C。⭐ Cache 总容量题的标准流程，五步，一步都不能跳：
① 块大小（字节）= 4 字 × 4B = 16B ⟹ 块内地址 4 位
② 行数 = 数据区容量 ÷ 块大小
        = 4K 字 ÷ 4 字/块 = 1K 行 ⟹ 行号 10 位
   （也可写成 16KB ÷ 16B = 1024 行）
③ 标记 = 32 − 10 − 4 = 18 位
④ 每行标记项 = 标记 18 + 有效位 1
             + 脏位 1（回写）+ 替换位 0（题里没提）
             = 20 位
⑤ 总容量 = 数据 + 标记阵列
        = 4K字×32位 + 1K×20位
        = 128K + 20K = 148K 位 ✔
⚠️⚠️ 第 ④ 步的"该不该加"是本题（也是本节）的分水岭，书上把判据写得很清楚：
· 有效位和标记位一定存在；
· 脏位看写策略——题里写了"回写方式" ⟹ 加 1 位；
· 替换控制位看替换算法——题里根本没提替换算法 ⟹ 不加。
⟹ "题目没提到的就不加"，别自作主张假设它用 LRU。

其之參替换算法

只有全相联和组相联需要。随机；FIFO（不考虑局部性）；LRU（用计数器，n 行 log₂n 位，最常用，块数大于组大小时可能抖动）；LFU。

其之肆写策略

术式
写命中和写不命中

写命中：全写（同时写主存，配写缓冲）；回写（只写 Cache，被替换时才写回，每行加脏位）。
写不命中：写分配（调入 Cache，再写，配回写）；非写分配（只写主存，配全写）。

现代常用组合：回写 + 写分配。

咒灵
多级 Cache 和分离

L1 分离（指令 Cache、数据 Cache）解决结构冒险。L1 和 L2 之间常全写，L2 和主存之间常回写。Cache 中的数据是主存的副本，多核时有一致性问题。

其之伍C 程序命中率

这是最爱考的题型。方法：只看第一次访问这一块时缺失，然后这一块的其他元素全命中。

术式
算命中率的步骤

① 算每块放几个元素：块大小 / 元素大小。
② 按代码访问顺序看：按行访问（空间局部性好）：每块缺失 1 次。
③ 循环内读 + 写同一元素：写的那一次一定命中（刚读过）。
④ 按列访问：看 Cache 能不能装下一列的所有块。

2016實戰代码的 Cache 缺失率 · 一条赋值语句访存几次
有如下 C 语言程序段。若数组 a 和变量 k 均为 int 型，int 型数据占 4B，数据 Cache 采用直接映射方式，数据区大小为 1KB、块大小为 16B，该程序段执行前 Cache 为空，则该程序段执行过程中访问数组 a 的 Cache 缺失率约为（　）。
for(k = 0; k < 1000; k++)
    a[k] = a[k] + 32;

分析语句“a[k] = a[k] + 32”：首先读取 a[k] 需要访问一次，之后将结果赋值给 a[k] 需要访问一次，共访问两次。第一次访问 a[k] 未命中，并将该字所在的主存块调入 Cache 对应的块中，块大小 16B ÷ 4B = 4 个整数，对这一主存块中的 4 个整数的两次访问中，只在访问第一个元素的第一次时发生缺失，其他 7 次访问全部命中，因此该程序段执行过程中访问数组 a 的 Cache 缺失率约为 1/8 = 12.5%。
每块 4 个元素。每个 a[k] 读 1 次写 1 次，共 8 次访问，只有第 1 次缺失。缺失率 1/8 = 12.5%。这里 Cache 容量够不够都一样，因为是顺序访问。
再深一层
选 C。⚠️⚠️ 本题最大的坑：a[k] = a[k] + 32 要访问内存两次（读一次、写一次）。
一个主存块 = 16B ÷ 4B/int = 4 个 int：a[4m] ~ a[4m+3]

访问顺序（同一块内）：
  a[4m]   读 ← 【缺失】此时把整块调入 Cache
  a[4m]   写 ← 命中
  a[4m+1] 读 ← 命中
  a[4m+1] 写 ← 命中
  a[4m+2] 读/写 ← 命中、命中
  a[4m+3] 读/写 ← 命中、命中
  ──────────────────────
  共 8 次访问，缺失 1 次

缺失率 = 1/8 = 12.5% ✔
⚠️ 若漏掉写访问，每块只算 4 次访问、1 次缺失 ⟹ 1/4 = 25%，正是选项 D。命题人把这个错误答案摆在最后一个位置。
📌 "一条语句访问几次内存"的判法（本节两道大题都靠它）：
语句访存次数说明
sum += a[i]1 次只读 a[i]；sum 在寄存器里
a[k] = a[k] + 322 次读 a[k] + 写 a[k]
s[k] = 2 * s[k]2 次同上（综 06 · 2020 真题）
c = a[j]1 次只读（综 03）
⟹ 判据：数组元素出现在赋值号右边算一次读，出现在左边算一次写；两边都出现就是 2 次。标量变量在寄存器里，不算访存。
📌 本题"直接映射、数据区 1KB"这两个条件其实没用上——因为数组是顺序访问的，无论怎么映射都不会冲突（顺序访问天然不撞车）。它们是干扰项，也是在暗示：顺序访问时，缺失率只由"块大小 ÷ 元素大小"决定。（对照综 04 的程序 B：一旦改成跨行访问，映射方式立刻变成决定性因素。）
2010實戰Cache 总容量 · 求 Cache 行号 · 行优先 vs 列优先的命中率
某计算机的主存地址空间大小为 256MB，按字节编址。指令 Cache 和数据 Cache 分离，均有 8 个 Cache 行，每个 Cache 行大小为 64B，数据 Cache 采用直接映射方式。现有两个功能相同的程序 A 和 B，其伪代码如下所示。
假定 int 型数据用 32 位补码表示，程序编译时 i、j 和 sum 均分配在寄存器中，数组 a 按行优先方式存放，其首地址为 320（十进制数）。请回答下列问题，要求说明理由或给出计算过程。
（1）不考虑用于 Cache 一致性维护和替换算法的控制位，数据 Cache 的总容量为多少？
（2）数组元素 a[0][31] 和 a[1][1] 各自所在的主存块对应的 Cache 行号是多少（Cache 行号从 0 开始）？
（3）程序 A 和 B 的数据访问命中率各是多少？哪个程序的执行时间更短？
// 程序 A                          // 程序 B
int sum_array1(){                  int sum_array2(){
    int i, j, sum = 0;                 int i, j, sum = 0;
    for(i = 0; i < 256; i++)           for(j = 0; j < 256; j++)
        for(j = 0; j < 256; j++)           for(i = 0; i < 256; i++)
            sum += a[i][j];                    sum += a[i][j];
    return sum;                        return sum;
}                                  }
（1）地址总长度为 28 位（228 = 256M），块内地址为 6 位（26 = 64），Cache 块号为 3 位（23 = 8），因此标记的位数为 28 − 6 − 3 = 19 位，还需使用一个有效位。数据 Cache 共有 8 行，因此数据 Cache 的总容量为 8×(64 + 20/8)B = 532B。
（2）数组按行优先方式存放，首地址为 320，数组元素占 4B。a[0][31] 所在的主存块对应的 Cache 行号为 [(320 + (0×256 + 31)×4) div 26] mod 23 = 6；a[1][1] 所在的主存块对应的 Cache 行号为 [(320 + (1×256 + 1)×4) div 26] mod 23 = 5。【另解】a[0][31] 的地址为 320 + 31×4 = 444 = 1 1011 1100B，其对应的 Cache 行号为 110B = 6；a[1][1] 的地址为 320 + 256×4 + 1×4 = 1348 = 101 0100 0100B，其对应的 Cache 行号为 101B = 5。
（3）数组 a 的大小为 256×256×4B = 218B，占 218/64 = 212 个主存块，按行优先存放。程序 A 逐行访问数组 a，共需访问 216 次，未命中次数为 212 次（每个字块中的第一个数未命中），因此程序 A 的命中率为 (216 − 212)/216 = 93.75%。【另解】每个字块中存放 16 个 int 型数据，除访问的第一个不命中外，随后的 15 个全都命中，故命中率为 15/16 = 93.75%。程序 B 逐列访问数组 a，Cache 总数据容量为 64B×8 = 512B，数组 a 一行的大小为 1KB，正好是 Cache 容量的 2 倍，可知不同行的同一列数组元素使用的是同一个 Cache 单元，因此逐列访问每个数据时都会将之前的字块置换出，即每次访问都不会命中，命中率为 0。因为从 Cache 读数据比从主存读数据快很多，所以程序 A 的执行比程序 B 快得多。
2010 大题。程序 A 按行访问，程序 B 按列访问。Cache 只有 8 行（512 B）。这是 行优先和 Cache 的连接：A 的命中率高得多。
再深一层
⭐⭐ 这道 2010 真题是 3.5 的期末考——它把「Cache 总容量」「地址划分求行号」「行优先 vs 列优先的命中率」三件事一次考完。逐问拆：
【第 1 问：总容量 532B】
地址位数 = log₂256M = 28 位
块内地址 = log₂64B = 6 位
行号     = log₂8   = 3 位
标记     = 28 − 6 − 3 = 19 位

每行 = 数据 64B(=512bit) + 标记 19 + 有效位 1 = 532 bit
  （题目明说"不考虑一致性维护和替换算法的控制位"
    ⟹ 脏位、替换位都不加）
总容量 = 8 × 532 bit = 4256 bit = 532 B ✔
📌 数字上的巧合值得一提：每行 532 bit，8 行合计恰好 532 B（4256/8 = 532）。书上写成 8×(64 + 20/8)B 就是这个意思：每行数据 64B、标记项 20bit = 2.5B。
【第 2 问：两个元素的 Cache 行号】
行优先存放 ⟹ a[i][j] 的地址 = 首地址 + (i×256 + j) × 4

a[0][31]：地址 = 320 + 31×4 = 444
          块号 = 444 div 64 = 6 ; 行号 = 6 mod 8 = 6 ✔

a[1][1] ：地址 = 320 + (256 + 1)×4 = 1348
          块号 = 1348 div 64 = 21 ; 行号 = 21 mod 8 = 5 ✔
⚠️ 易错点：算 a[1][1] 的地址时，i = 1 要乘的是一整行的元素数 256，不是 1。二维数组行优先的通式 addr = base + (i × 列数 + j) × 元素大小 要写熟。
【第 3 问：93.75% vs 0%，本题的灵魂】
每块 64B ÷ 4B = 16 个 int

程序 A（行优先访问，与存放顺序一致）：
   顺着地址走 ⟹ 每调入一块，接下来 15 个元素都在这一块里
   ⟹ 每 16 次访问缺 1 次 ⟹ 命中率 15/16 = 93.75% ✔

程序 B（列优先访问，与存放顺序垂直）：
   a[0][0] → a[1][0] → a[2][0] … 每次地址跳 256×4B = 1KB
   而 Cache 数据区只有 64B × 8 = 512B
   ⟹ 跳一步就跨过了 2 整个 Cache！
   ⟹ 不同行的同一列元素全部映射到【同一个 Cache 行】
   ⟹ 每次访问都把上一次调入的块挤掉 ⟹ 命中率 0% ✔
📌 程序 B 为什么是 0% 而不是"低一点"？关键在那个 1KB = Cache 容量的 2 倍：
行跨距 1024B ÷ 块大小 64B = 16 块，而 Cache 只有 8 行 ⟹ 16 是 8 的整数倍 ⟹ 每一行的同一列必然落到同一个 Cache 行。这与综 03 的"块号相差 8 的倍数必撞"是同一条规律。
⚠️ 若行跨距不是 Cache 容量的整数倍会怎样？那就不会每次都撞，命中率会介于 0 与 93.75% 之间。⟹ 本题的 0% 是精心设计的极端值，不要以为"列优先一定是 0%"。
📌 答题格式建议（本题按 12 分写）：(1) 先给地址三段划分再算每行位数，写明"因题目不考虑脏位与替换位故不加"；(2) 用通式 addr = 320 + (i×256+j)×4 逐个算，div/mod 两步都写出来；(3) 程序 A 用"每块 16 个 int，缺 1 命 15"说明；程序 B 必须写出"行跨距 1KB 是 Cache 数据区 512B 的 2 倍，故同列元素映射到同一 Cache 行"这句话——那是本问的采分点。
🔗 本题就是 3.5-07（三维数组循环顺序）的二维实测版：那题问"怎么改能提高空间局部性"，本题把不改的代价量化成 93.75% → 0%。
2013實戰总线带宽 · 突发传送时间 · CPU 执行时间与缺失开销
某 32 位计算机，CPU 主频为 800MHz，Cache 命中时的 CPI 为 4，Cache 块大小为 32B；主存采用 8 体交叉存储方式，每个体的存储字长为 32 位、存取周期为 40ns；存储器总线宽度为 32 位，总线时钟频率为 200MHz，支持突发传送总线事务。每次读突发传送总线事务的过程包括：传送首地址和命令、存储器准备数据、传送数据。每次突发传送 32B，传送地址或 32 位数据均需要一个总线时钟周期。请回答下列问题，要求给出理由或计算过程。
（1）CPU 和总线的时钟周期各为多少？总线的带宽（最大数据传输速率）为多少？
（2）Cache 缺失时，需要用几个读突发传送总线事务来完成一个主存块的读取？
（3）存储器总线完成一次读突发传送总线事务所需的时间是多少？
（4）若程序 BP 执行过程中共执行了 100 条指令，平均每条指令需进行 1.2 次访存，Cache 缺失率为 5%，不考虑替换等开销，则 BP 的 CPU 执行时间是多少？
（1）CPU 的时钟周期是主频的倒数，即 1/800MHz = 1.25ns；总线的时钟周期是总线频率的倒数，即 1/200MHz = 5ns。总线宽度为 32 位，因此总线带宽为 4B×200MHz = 800MB/s（或 4B/5ns = 800MB/s）。
（2）Cache 块大小是 32B，每次突发传送 32B，因此 Cache 缺失时需要一个读突发传送总线事务读取一个主存块。
（3）用一个总线时钟周期传输地址；之后每隔 40ns/8 = 5ns 启动一个存储体（各进行一次读操作），第一个体准备数据花费 40ns，之后这个字的传送操作与下一个字的准备操作重叠；用 8 个总线时钟周期传送数据。读突发传送总线事务用时为 5ns + 40ns + 8×5ns = 85ns。
另解：将从数据准备到传输结束视为一个完整的流水线，共视为 9 个流水段，每段 5ns，总花费 5 + 45 + 7×5 = 85ns。📕 书上金句：只要是有关于流水线思想的，最关键的就是分清楚流水段，剩下的就是简单计算，不同的算法不是关键，本质上都是一样的。
（4）一条指令在 Cache 命中时的执行时间 = CPI × 时钟周期 = 4 × 1.25ns = 5ns；一条指令因 Cache 缺失而导致的平均访存开销 = 平均访存次数 × 一次突发传送总线事务时间 = 1.2 × 85ns = 102ns。因此 BP 的 CPU 执行时间 = (5ns + 102ns×5%) × 100 = 1010ns。📕 书上明写：本题说明了 408 真题采用先访问 Cache 再访问主存的方式。
2013 大题：把 CPI、低位交叉、Cache 缺失损失串在一起。缺失损失 = T + (n−1)·r，这里用的就是 第30话 的公式。
再深一层
本题把 Cache、总线、CPU 性能三块知识串成一条链，是 3.5 里最"综合"的一道。四问逐个拆：
【第 1 问：两个时钟周期 + 带宽】
CPU 时钟周期 = 1/800MHz = 1.25 ns
总线时钟周期 = 1/200MHz = 5 ns      ← 总线比 CPU 慢 4 倍
总线带宽 = 总线宽度 × 总线频率
         = 4B × 200MHz = 800 MB/s
         （或 4B ÷ 5ns = 800 MB/s，两种写法都给分）
【第 2 问：1 个事务】Cache 块 32B，每次突发正好传 32B ⟹ 1 个突发传送事务搞定。（对照 3.5-23：那题块 64B、每次只传 8B，就要 8 个事务。）
【第 3 问：85ns —— 本题的核心，必须能画出流水线】
32B ÷ 4B(32位) = 8 个数据，恰好用 8 体交叉
每隔 40ns ÷ 8 = 5ns 启动一个体（= 一个总线周期），流水线刚好接得上

  传地址 ├5ns┤
  体0        ├────40ns 准备────┤传5
  体1          ├────40ns────┤     传5
  体2            ├────40ns────┤        传5
  …                                        …
  体7                     ├──40ns──┤            传5

总时间 = 5（地址）+ 40（首个数据准备）+ 8×5（传 8 个数据）= 85 ns ✔
📌 为什么后 7 个数据的"准备"不占时间？因为 8 个体是错开 5ns 依次启动的，等体 0 的数据传完时体 1 的数据早就备好了——准备与传送重叠，这正是 3.2.3 交叉存储器流水线的原理。与 3.5-24 的 1 + 8 + 8 = 17 是同一个结构（只是那题用"周期"作单位）。
【第 4 问：1010ns —— 注意"缺失开销要加在命中时间之上"】
命中时每条指令 = CPI × CPU 周期 = 4 × 1.25 = 5 ns
每条指令的平均缺失开销
   = 平均访存次数 × 缺失率 × 一次缺失损失
   = 1.2 × 5% × 85 ns = 5.1 ns
每条指令平均耗时 = 5 + 5.1 = 10.1 ns

100 条指令 ⟹ 1010 ns ✔
⚠️⚠️ 这里体现了 408 的"串行口径"（书专门点了这句）：Cache 命中的 5ns 是每条指令都要付的；缺失时在此之上再加 85ns，不是"用 85ns 替换 5ns"。与 3.5-03 的"不命中 = 2 + 40 = 42ns"是同一条口径。
📌 另一种等价写法（更直观，答题可用）：
95 条指令命中：5 ns 每条
 5 条指令缺失：5 + 1.2×85 = 5 + 102 = 107 ns 每条
合计 = 95×5 + 5×107 = 475 + 535 = 1010 ns ✔
📌 答题格式建议（本题 12~15 分）：每一问先写公式再代数；第 3 问务必画出或文字描述流水线的三段（地址 / 首个数据准备 / 连续传送），并写明"后续数据的准备与前一个数据的传送重叠"；第 4 问要写出"缺失开销是额外叠加的"这句话。
领域展开

地址：标记 | 组号 | 块内；路数翻倍，标记多一位。
容量：行数 × (数据 + 标记 + 有效 + 脏)。
写：全写配非写分配，回写配写分配。
C 程序：每块只缺一次；写紧跟读必命中。
