术式
流水线指标（k 段、n 条、周期 Δt）

总时间 T = (k + n − 1)Δt。
吞吐率 TP = n / T，理想最大 1/Δt。
加速比 S = n·k·Δt / T，n 很大时趋近 k。
效率 E = S / k。
时钟周期 = 最慢段的时间 + 段寄存器延迟。

2009实战流水线时钟周期取最长段
某计算机的指令流水线由 4 个功能段组成，指令流经各功能段的时间（忽略各功能段之间的缓存时间）分别为 90ns、80ns、70ns 和 60ns，则该计算机的 CPU 周期至少是（　）。

时钟周期应以各功能段的最长执行时间为准，否则用时长的流水段将不能正确完成。
按最慢段。
再深一层
选 A。⭐ 流水线四大公式的第一条，2009 与 2018 两年真题都从这出，是本节最基础的送分题。
🐍 复算：Δt = max(90, 80, 70, 60) = 90ns  ✔

为什么必须取最大值（而不是平均值）—— 一句话：
  所有流水段【共用同一个时钟】，一拍到了就必须整体往前推一格。
  若 Δt 取 80ns，那个 90ns 的段【还没做完就被推走了】⟹ 结果是错的。
  ⟹ 木桶效应：时钟周期由【最慢的那一段】决定，短的段只能干等。
📌 题干里「忽略各功能段之间的缓存时间」这半句是关键限定——它明说了不考虑流水段寄存器延时。对照书上的「注意」框：「流水段寄存器本身也引入一定时延，但考试中若无明确说明则可忽略」。
⚠️⚠️ 2018 真题（选 27）就是那个「明确说明了」的例外：给出流水段寄存器延时 20ps，答案变成 max(各段) + 20。⟹ 这两道真题必须并排记：给了就加，没给就不加，全看题干那一句。
⚠️ 常见错解：取平均值 (90+80+70+60)/4 = 75ns；或取总和 300ns（那是单条指令的总延迟，不是时钟周期）。「单条指令延迟 = 各段之和」与「时钟周期 = 各段最大值」是两个不同的量，本节至少三道题在这上面设干扰项。
🔗 这条约束和 5.3 单周期 CPU 的「时钟周期以最耗时指令为准」是同一个物理道理，只是粒度从「整条指令」细化到了「一个流水段」——这正是流水线能把主频提上去的全部原因。
2018实战流水线时钟周期 · 流水段寄存器延时
若某计算机最复杂指令的执行需要完成 5 个子功能，分别由功能部件 A~E 实现，各功能部件所需时间分别为 80ps、50ps、50ps、70ps 和 50ps，采用流水线方式执行指令，流水段寄存器延时为 20ps，则 CPU 时钟周期至少为（　）。

指令流水线中每个流水段的时间单位为一个时钟周期，题中指令流水线的指令需要用到 A~E 五个部件，所以每个流水段时间应取最大部件时间 80ps，此外还有流水段寄存器延时 20ps，因此 CPU 时钟周期至少是 100ps。
最慢 80ps + 寄存器 20ps = 100ps。
再深一层
选 D。⚠️⚠️ 本题是历年真题中唯一一次明确给出流水段寄存器延时的，与 2009 真题（选 19）必须并排记。
🐍 复算：
  Δt = max(各段延迟) + 流水段寄存器延时
     = max(80, 50, 50, 70, 50) + 20
     = 80 + 20 = 100ps   ✔

两道真题，同一个公式，一个加一个不加：
  2009 选 19：写「【忽略】各功能段之间的缓存时间」⟹ Δt = 90ns，不加
  2018 选 27：写「流水段寄存器延时为 20ps」    ⟹ Δt = 100ps，要加
  ⟹ 判据只有一条：题干给没给。给了就加，没给就忽略。
📌 书上「注意」框的原话：「流水段寄存器本身也引入一定时延。但在考试中，若无明确说明，则可忽略寄存器时延。」——这句话就是为这两道真题写的。
⚠️ 干扰项 C（80ps）就是「看见 max 就交卷」的人的答案，恰恰漏掉题干里最扎眼的那个条件。凡题干出现「流水段寄存器 / 锁存器 / 缓存」的延时数值，它一定是要用的，出题人不会白给。
⭐ 顺手把「为什么要加」想清楚（不是硬记）：一拍的时间必须够做完两件事——① 本段的组合逻辑算完（80ps）；② 结果稳定地锁进段寄存器（20ps）。下一拍开始时，下一段才能从这个寄存器里读到确定的值。⟹ 这与 5.3 的 T ≥ T_clk-to-q + T_max + T_setup 是同一条物理约束，只是本题把它简化成了「+20ps」。
🔗 这个「削不掉的 20ps」也正是 16 题「流水段不能无限增加」的第一条理由：段切得越细，max(各段) 越小，那 20ps 的占比就越大，边际收益趋近于零。
2013实战流水线吞吐率 · 流水线执行时间公式 · 主频与时钟周期
某 CPU 主频为 1.03GHz，采用 4 级指令流水线，每个流水段的执行需要 1 个时钟周期。假定 CPU 执行了 100 条指令，在其执行过程中，没有发生任何流水线阻塞，此时流水线的吞吐率为（　）。

采用 4 级流水执行 100 条指令，在执行过程中共使用 4 + (100 − 1) = 103 个时钟周期。CPU 的主频是 1.03GHz，即每秒有 1.03G 个时钟周期。流水线的吞吐率为 1.03G × 100 / 103 = 1.0×10⁹ 条指令/秒。
n=100，k=4，时间 = 103 个周期 = 100 ns，100/10⁻⁷ = 10⁹ 条/秒。主频 1.03 GHz 就是为了让数字好算。
再深一层
选 C。⭐⭐ 本题是吞吐率公式的标准考法，而且 1.03 与 103 恰好整除——这是命题人设计好的，算出漂亮数字说明你走对了路。
🐍 复算（两条路都通，互为验算）：

  路线一：先算总时间，再用 TP = n / T
    总周期数 = k + n − 1 = 4 + 100 − 1 = 103 个时钟周期
    时钟周期 Δt = 1 / 1.03GHz
    总时间 T = 103 / 1.03e9 s = 1.0e−7 s
    TP = 100 / 1.0e−7 = 1.0e9 条/秒   ✔

  路线二：直接代公式 TP = n / [(k+n−1)Δt]
    TP = 100 × 1.03e9 / 103 = 1.0e9 条/秒   ✔

  ⟹ 两法一致，且 1.03e9/103 = 1.0e7 整除 —— 干净得可疑，正是对的信号
📌 ⭐ 四个选项分别对应四种典型错法，看懂了就再不会错：
选项怎么算出来的错在哪
A 0.25×10⁹1.03e9 ÷ 4误以为「4 级流水 ⟹ 每条指令要 4 拍」，把 CPI 当成 4——那是非流水线的算法
B 0.97×10⁹1.03e9 × 100/103 算反成 103/100 之类比值倒置
C 1.0×10⁹1.03e9 × 100/103✔

⚠️⚠️ D 项是最值得警惕的一个：TP_max = 1/Δt 确实等于主频，但那是 n 趋于无穷时的极限值。本题只跑 100 条，103 拍里有 3 拍在装管，所以实际吞吐率必然略小于主频。⟹ 记住这条不等关系：实际 TP < 1/Δt，且 n 越大越接近。看到答案等于主频，先怀疑漏了 k−1。
📌 「没有发生任何流水线阻塞」这半句题干必须注意——有阻塞时总周期 = k + n − 1 + 阻塞拍数，公式要加一项。（2014 综合真题就是「有阻塞」的版本，那里每条数据相关赔 3 拍、分支赔 3 拍。）

📌 ⭐ 第 ② 条最值得单独想一遍：为什么「格式规整」这么重要？因为 ID 段要在同一拍里干两件事——译码 + 读寄存器堆。若寄存器号的位置随指令类型而变，就必须先译完码才知道去读哪个寄存器，一拍根本做不完。把 rs、rt 字段钉死在固定位上，硬件就能「不管三七二十一先把这两个寄存器读出来」，用不上再扔掉。⟹ 这是「空间换时间」的又一例（多读了可能没用的数据，换来时序上来得及）。
⚠️ 本题四个选项里没有干扰陷阱，三条全对——但反过来要能判断：CISC 的变长指令、多种寻址方式、任意指令都能访存，恰好逐条与这四条对着干，这正是「CISC 难以流水化、x86 要先拆成微操作」的根本原因。（⚠️ 但别把它读成「CISC 不能流水线」——见 01 题 B 项。）

下列关于指令流水线数据通路的叙述中，错误的是（　）。

📌 ⭐ 判据一句话：「数据流过它吗？」流过 ⟹ 数据通路；只发信号不流数据 ⟹ 控制器。ALU 里流数据（B 对）、寄存器里存数据（C 对）、译码器里流的是控制信号不是数据（A 错）。
⚠️ D 项值得单独记：数据通路 = 组合逻辑（ALU、MUX、加法器）+ 时序逻辑（寄存器、存储器）两类都有。「有记忆的」归时钟管，「无记忆的」归控制信号管——这条正是 08 题 B 项的判据，两题互为印证。

结构冒险

🔗 三章一线（本章最值得记的跨章串联之一）：ch3 的哈佛结构 / L1 分离设计 ↔ 5.3 单周期数据通路「指令存储器与数据存储器必须分开」 ↔ 本节的结构冒险。⟹ 同一个设计决策，三章各给了一个理由：ch3 说带宽、5.3 说一拍内做不完两次访存、5.6 说资源冲突。

数据冒险

只考写后读（RAW）：后一条的源寄存器等于前面某一条的目的寄存器。

指令\周期12345678
add R1,R2,R3IFIDEXMEMWB
sub R4,R1,R5IF✕✕IDEXMEMWB
术式
数据冒险三种解法

① 阻塞（插 nop）：简单，慢。
② 转发（旁路）：把 EX 或 MEM 的结果直接送到 ALU 入口。ALU 结果一般不用阻塞。
③ 编译器重排：把无关的指令调到中间。
Load-use 特例：load R1 后紧跟使用 R1，转发也要阻塞 1 个周期，因为 MEM 才有数据。

判定数据冒险

只看每条的源寄存器是否是前面还没写回的目的寄存器。 距离 ≥ 3 条（没有转发、WB 前半写）就没事。

2016实战数据冒险 · RAW判定 · WAW干扰项
在无转发机制的五段基本流水线（取指、译码/读寄存器、运算、访存、写回寄存器）中，下列指令序列存在数据冒险的指令对是（　）。
I1: add   R1, R2, R3;   (R2) + (R3) → R1
I2: add   R5, R2, R4;   (R2) + (R4) → R5
I3: add   R4, R5, R3;   (R5) + (R3) → R4
I4: add   R5, R2, R6;   (R2) + (R6) → R5

数据冒险即数据相关，指在一个程序中存在必须等前一条指令执行完才能执行后一条指令的情况，此时这两条指令即为数据相关。首先这两条指令发生写后读相关，且两条指令在流水线中的执行情况（发生数据冒险）如下表所示。
指令123456
I2取指译码/读寄存器运算访存写回
I3取指译码/读寄存器运算访存写回

术式
Flynn 分类

SISD：普通单核。SIMD：一条指令处理多个数据（向量、GPU、数组运算）。MISD：现实中几乎没有。MIMD：多核、多处理器。

概念一句话辨析
向量处理器SIMD 的代表专做数组运算
硬件多线程一个核同时维护多个线程的 PC/寄存器细粒度（每周期切）、粗粒度（阻塞才切）、同时（SMT，一周期发多线程指令）
多核一块芯片多个核共享 L3（常见）和主存
SMP共享内存多处理器所有处理器地址空间相同、访问对等（UMA）；需要 Cache 一致性
领域展开

指标：T=(k+n−1)Δt，周期按最慢段 + 寄存器延迟。
冒险：结构（分离 Cache）、数据（转发，load-use 仍阻 1）、控制（预测、flush）。
超标量：一周期发多条，不缩短每段时间。
分类：向量=SIMD，多核=MIMD。
