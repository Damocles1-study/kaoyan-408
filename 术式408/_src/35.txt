== 文件是什么 {what}
文件在磁盘上由**元数据**（大小、权限、时间、物理位置）和**数据块**组成。元数据放在**文件控制块 FCB**，和文件一一对应。Linux 把文件名和其他元数据拆开：目录项只放「文件名 + inode 号」，其余都放 **inode**（索引节点）。这样查目录时一个磁盘块能放下更多目录项，读盘次数就少了。

:::shu 文件操作
**create**：分配空间 + 建目录项。**delete**：释放空间 + 删目录项。
**open**：按路径找目录，找到 FCB ==读入内存==，返回描述符（==不读数据==）。
**read/write**：按指针找数据块。
**close**：写回 FCB。
**打开文件表**：系统一张（FCB、引用计数），每个进程一张（读写指针、指向系统表）。
:::

为什么要两张打开文件表？同一个文件被两个进程打开时，FCB 只要一份，但读写位置各走各的。**系统表**放共享的 FCB 和引用计数；**进程表**放各自的读写指针。引用计数减到 0 才把系统表项撤掉、写回 inode。

:::vow 一次 open 之后的事
`open` 之后读写都不用再查目录，这正是它的意义。所以 `read` 不需要文件名，只要 fd。
:::

**文件保护**有三种：口令、加密、**访问控制**。访问控制把每个文件的「谁能做什么」记在**存取控制**表里（常按所有者、同组、其他分类），这张表放在 FCB 中。

**逻辑结构**是用户看到的样子，和磁盘上怎么放无关。无结构（流式）就是一串字节；有结构（记录式）分四种：

- **顺序文件**：记录一个接一个。定长记录可以算出第 i 条的位置，能随机存取；变长记录只能从头找。
- **索引文件**：每条记录一个索引项，索引表按关键字排序。查得快，但索引表可能比数据还大。
- **索引顺序文件**：记录分组，每组一个索引项，只有一部分记录进索引表。N 条记录分 √N 组，平均查找约 √N 次，比顺序查找的 N/2 少得多。
- **散列文件**：由关键字直接算地址，没有顺序。

:::recall open 做了什么、没做什么？两张打开文件表分别放什么？
按路径找到 FCB 读入内存、建表项、返回描述符；不读数据块。系统表放 FCB 和引用计数，进程表放读写指针。
:::

== 物理结构 {physical}
物理结构回答：文件的块在磁盘上怎么放。一共三种，思路和内存管理相通。

**连续分配**：占一串相邻的块，目录项记首块和长度。第 k 块的位置直接算，读一次就到，所以随机访问最快，磁头移动也少。但文件难扩展，还有外部碎片。

**链接分配（隐式）**：每块末尾放下一块的指针。不要连续，能扩展；但读第 k 块要从头读 k 次盘，指针也占空间，一块坏了后面全丢。

**链接分配（显式 FAT）**：把指针集中到一张**文件分配表 FAT**，每个盘块一项，常驻内存。找第 k 块只要在内存里走 k 步，不用读盘。

**索引分配**：每个文件一张索引表，存所有块号。随机访问好，也能扩展；代价是索引块占空间，小文件也要一块。

:::ana 三种找书法
**连续**：一本书就是一排书架。**链接**：每页最后写着下一页在哪。**索引**：每本书有个目录页。
:::

:::recall 三种分配分别怎样找第 k 块？各要读几次盘（目录和 FCB 已在内存）？
连续：首块加 k，1 次。隐式链接：从头走，k+1 次。FAT：内存里走表，1 次。一级索引：读索引块再读数据，2 次。
:::

=== inode 计算：本节核心

:::shu 混合索引公式
设块大小 B、指针大小 p，每块放 `k = B / p` 个指针。
**最大文件块数** = 直接 + k·(一级) + k²·(二级) + k³·(三级)。
**访盘次数**（inode 已在内存）：直接 1，一级 2，二级 3，三级 4。
:::

文件太大时一张索引块放不下，就让索引块指向索引块，这就是**多级索引**。小文件用直接地址，大文件才走间接，这叫**混合索引**。

算一遍：块 4 KB，指针 4 B，k = 1024。inode 有 10 个直接、1 个一级、1 个二级、1 个三级。

- 直接覆盖 10 块（40 KB）。
- 一级再覆盖 1024 块（4 MB）。
- 二级再覆盖 1024² 块（4 GB）。
- 三级再覆盖 1024³ 块（4 TB）。

定位：要读偏移 5 MB 的字节。块号 = 5 MB ÷ 4 KB = 1280。减去直接 10、一级 1024，还剩 246，落在二级。246 ÷ 1024 = 0 余 246，所以读二级索引块的第 0 项，再读那个一级索引块的第 246 项，再读数据：3 次盘。

**指针要多大**：能表示所有块号。4 TB 磁盘、4 KB 块，有 2³⁰ 块，至少 30 位，取 4 B。

**簇**：文件系统分配的单位，可以是多个扇区。不足一簇也占一簇，这就是内部碎片。比如簇 1 KB，1026 字节的文件占 2 簇。

== 目录 {dir}
目录的作用是把名字映射到 FCB。**树形目录**是主流，目录本身也是文件，一个目录项 = 文件名 + inode 号。**绝对路径**从根开始，**相对路径**从当前目录开始：设置当前目录的目的是==减少访盘==。

**实现**：线性列表（查找 O(n)）或哈希表（快，但要处理冲突）。

:::shu 打开路径的访盘
打开 /a/b/c：读根目录 inode（一般已在内存）→ 根目录块 → a 的 inode → a 的目录块 → b 的 inode → b 的目录块 → c 的 inode。每层目录大约 2 次。
:::

**目录操作**：搜索、创建文件、删除文件、遍历、改名，本质都是读写目录文件。删除文件时要释放块、删目录项；有硬链接时只把计数减 1。

=== 硬链接和软链接

:::shu 链接的三句话
**硬链接**：目录项指向同一个 inode，`link count` +1，删一个 count −1，减到 0 才真正删除。**不能跨文件系统**，因为 inode 号只在本文件系统内有意义。
**软链接**：一个新文件，有自己的 inode，内容是路径。可以跨文件系统；原文件删了就断了。
**软链接不增加原文件引用计数。** 软链接访问多走一步，要多读一次盘。
:::

:::recall 硬链接和软链接分别新增了什么？混合索引的最大块数怎么算？
硬链接只新增目录项，引用计数加一。软链接新增一个文件。直接 + k + k² + k³。
:::

:::domain
**open：**读 FCB 到内存，不读数据。
**inode：**k=B/p；最大块数 = 直接 + k + k² + k³；访盘 1、2、3、4。
**硬链接：**同 inode，不跨 FS；软链接：存路径。
:::
