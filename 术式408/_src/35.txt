== 文件是什么 {what}
文件在磁盘上由**元数据**（FCB / inode：大小、权限、时间、物理位置）和**数据块**组成。**文件控制块 FCB** 和文件一一对应。Linux 把文件名和其他元数据拆开：目录项只放「文件名 + inode 号」，其余都放 inode。

:::shu 文件操作
**create**：分配空间 + 建目录项。**delete**：释放空间 + 删目录项。
**open**：按路径找目录，找到 FCB ==读入内存==，返回描述符（==不读数据==）。
**read/write**：按指针找数据块。
**close**：写回 FCB。
**打开文件表**：系统一张（FCB、引用计数），每个进程一张（读写指针、指向系统表）。
:::

:::vow 一次 open 之后的事
`open` 之后读写都不用再查目录，这正是它的意义。所以 `read` 不需要文件名，只要 fd。
:::

**文件保护**：口令、加密、访问控制（用户 × 权限）。

**逻辑结构**：无结构（流式）和有结构（记录式）：顺序文件、索引文件、索引顺序文件、散列文件。

:::shu 混合索引公式
设块大小 B、指针大小 p，每块放 `k = B / p` 个指针。
**最大文件块数** = 直接 + k·(一级) + k²·(二级) + k³·(三级)。
**访盘次数**（inode 已在内存）：直接 1，一级 2，二级 3，三级 4。
:::

== 目录 {dir}
**树形目录**是主流。目录也是文件，一个目录项 = 文件名 + inode 号。**绝对路径**从根开始，**相对路径**从当前目录开始：设置当前目录的目的是==减少访盘==。

**实现**：线性列表（查找 O(n)）或哈希表（快，但要处理冲突）。

:::shu 打开路径的访盘
打开 /a/b/c：读根目录 inode（一般已在内存）→ 根目录块 → a 的 inode → a 的目录块 → b 的 inode → b 的目录块 → c 的 inode。每层目录大约 2 次。
:::

:::shu 链接的三句话
**硬链接**：目录项指向同一个 inode，`link count` +1，删一个 count −1，减到 0 才真正删除。**不能跨文件系统**。
**软链接**：一个新文件，有自己的 inode，内容是路径。可以跨文件系统；原文件删了就断了。
**软链接不增加原文件引用计数。**
:::

:::domain
**open：**读 FCB 到内存，不读数据。
**inode：**k=B/p；最大块数 = 直接 + k + k² + k³；访盘 1、2、3、4。
**硬链接：**同 inode，不跨 FS；软链接：存路径。
:::
