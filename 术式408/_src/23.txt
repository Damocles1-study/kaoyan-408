== 为什么要有两种模式 {why}
如果任何程序都能访问磁盘、修改别人的内存、关掉中断，一个错误或恶意程序就能拖垮整台机器。所以要把危险的操作收归操作系统。

:::ana 银行柜台
你的程序是储户，操作系统是柜员。储户不能自己进金库（硬件、其他人的内存），要办事就按铃（系统调用），由柜员进去。CPU 里有一位专门记录现在谁在操作：PSW 的模式位。比方的局限：柜员也是在同一台 CPU 上运行的程序，并没有另一个人。
:::

:::shu 用户态与内核态
**内核态**（管态）：所有指令都能执行。**用户态**（目态）：只能执行非特权指令。
**特权指令**：开关中断、I/O、改 PSW、改基址/界限寄存器、设置时钟、加载页表基址。
**用户→内核，只有一条路：中断或异常（包括 trap）。** 内核→用户：修改 PSW（iret）。
:::

为什么不能让用户程序自己切到内核态？如果有这样的指令，保护就形同虚设。所以切换时机由硬件决定，入口由操作系统事先设好。

:::flash 判断指令能不能在用户态执行
访问内存（通过 MMU）、算术运算、读时钟、trap 指令（**用户态才用得上**）：能。
关中断、停机、写 PSW、写时钟、I/O：不能。
:::

== 中断和异常 {int}
打断当前程序的事件分两大类，按来源分。

**外部中断**（简称中断）：来自 CPU 之外，和当前指令没关系，什么时候来不可预测（异步）。比如 I/O 完成、时钟到点。

**内部异常**（简称异常）：由正在执行的指令引起（同步）。又分三种，区别是能不能恢复、回到哪。

@ table([['分类','来源','例子','返回到'],['外中断','CPU 外部，异步','I/O 完成、时钟、断电','<b class="r">下一条指令</b>'],['故障 fault','指令执行中，同步','<b class="r">缺页</b>、除零','<b class="r">重新执行本条</b>'],['陷阱 trap','主动请求，同步','系统调用、断点','下一条指令'],['终止 abort','硬件致命错误','奇偶校验错','不返回']])

为什么故障回到本条？缺页时这条指令没做成，页调进来后当然要重新做。为什么陷阱回下一条？陷阱指令本身已经完成了，它就是用来请求服务的。

:::trap 三条分界线
**① 缺页是异常（故障），不是中断。** 处理完==重新执行这条指令==。
**② 除零的归属**：一般归为「故障」的例子，不可恢复时终止。判断时认准它属于内部异常即可。
**③ 外中断只能在指令结束后响应；异常是指令执行过程中当场处理。**
:::

:::recall 四种事件各来自哪里、返回到哪？
外中断来自外部，回下一条。故障是指令出错，回本条。陷阱是主动请求，回下一条。终止是致命错误，不返回。
:::

== 硬件做什么，OS 做什么 {flow}
CPU 每条指令执行完，检查有没有中断请求。

**响应条件**：有请求，CPU 处于**开中断**状态（中断允许触发器 IF=1），一条指令执行完毕。

响应后，要做的事分两部分。这条分界线非常关键。

@ steps([
 (flow([('①关中断','gd'),('②保存断点\nPC、PSW','gd'),('③引出中断\n服务程序入口','gd')],gap=22,size=12),'<b>硬件（中断隐指令）</b>完成响应的三件事，全部自动。这三步不是任何一条指令。'),
 (flow([('④保存现场\n通用寄存器','bk'),('⑤设屏蔽字','bk'),('⑥开中断','bk')],gap=22,size=12),'<b>中断服务程序（OS）</b>开始执行。开中断之后才能响应更高优先级的中断（多重中断）。'),
 (flow([('⑦执行\n服务内容','bk')],gap=22,size=12),'真正的处理工作。'),
 (flow([('⑧关中断','bk'),('⑨恢复现场\n恢复屏蔽字','bk'),('⑩开中断','bk'),('⑪iret 返回','rd')],gap=22,size=12),'恢复期间不能被打断，所以要关中断；iret 恢复 PC、PSW，回到用户态。')],'中断处理的完整流程')

**为什么硬件必须先关中断**：如果响应中又来一个中断，断点还没存好，就全乱了。

**为什么 PC、PSW 由硬件存**：一旦开始执行服务程序，PC 马上就变了，PSW 也要变成内核态。通用寄存器则可以由软件存，用到哪个存哪个。

**断点**就是被打断的返回地址，加上 PSW。**现场**是通用寄存器这些。

**怎样找到入口**：**中断向量法**。每种中断有一个编号，内存里一张**中断向量表**存放各处理程序的入口地址，硬件用编号查表。比如编号 n，每项 4 字节，入口地址放在表基址 + 4n。表由操作系统设好。

:::shu 分界线
**硬件**：关中断、保存断点（PC、PSW）、形成入口地址（中断向量）。
**OS**：保存通用寄存器、保存/设屏蔽字、处理、恢复、iret。
**响应时机**：指令周期==结束==时，且开中断、有请求。
:::

**中断和子程序调用的差别**：子程序调用是程序自己安排的，只保存 PC。中断随时可能来，还要保存 PSW，并切到内核态。

**时钟中断**很有代表性。定时器到点产生中断，处理程序做的是：更新系统时间，更新当前进程已用时间，减少时间片，时间片用完就调度。这就是[[26|时间片轮转]]的发动机。

:::link 多重中断与屏蔽字
中断屏蔽字的计算放在 [[39|第 39 话]]，和 I/O 一起讲。这里只需要记住开中断是由 OS 软件做的。
:::

:::recall 不看书，说出中断处理的全过程，并分开硬件和软件。
硬件：关中断、存 PC 和 PSW、取入口。软件：存通用寄存器、设屏蔽字、开中断、处理、关中断、恢复现场和屏蔽字、开中断、iret。
:::

== 系统调用 {syscall}
应用程序请求操作系统服务的唯一接口（程序接口）。用的正是上面的陷阱机制。

@ flow([('传参\n（放寄存器）','bx'),('执行 trap\n陷入内核','gd'),('内核态运行\n服务例程','bk'),('返回用户态','bx')],gap=26,cap='系统调用的过程。传参和发起都在用户态')

:::shu 系统调用三句话
**发起在用户态，执行在内核态。**
**分类**：设备管理、文件、进程控制、进程通信、内存管理。
**库函数和系统调用**：`printf` 是库函数，内部调用 `write`；`sin()` 不进内核。命令解释程序（Shell）也是用户程序。
:::

:::trap 「发生」vs「执行」
缺页==发生==在用户态（用户程序访存时），==处理==在内核态。系统调用==发起==在用户态，==执行==在内核态。**进程切换连「发生」都只能在内核态。**
:::

:::recall 哪些操作会使 CPU 从用户态进内核态？
系统调用、异常（缺页、除零）、外中断。普通算术运算不会，除非它引发了异常。
:::

:::domain
**进内核只有一条路：**中断或异常。
**缺页 = 异常**，重新执行本条；**外中断**回下一条。
**硬件：**关中断、存 PC+PSW、形成入口。**OS：**存通用寄存器、处理、恢复。
**发起/发生在用户态，执行/处理在内核态。进程切换例外。**
:::
