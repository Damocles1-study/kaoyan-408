== 问题的起点：为什么要有两种模式 {why}
:::ana 银行柜台
你的程序是储户，操作系统是柜员。储户不能自己进金库（硬件、其他人的内存），要办事就按铃（系统调用），由柜员进去。CPU 里有一位专门记录现在谁在操作：PSW 的模式位。
:::

:::shu 用户态与内核态
**内核态**（管态）：所有指令都能执行。**用户态**（目态）：只能执行非特权指令。
**特权指令**：开关中断、I/O、改 PSW、改基址/界限寄存器、设置时钟、加载页表基址。
**用户→内核，只有一条路：中断或异常（包括 trap）。** 内核→用户：直接修改 PSW（iret）。
:::

:::flash 判断指令能不能在用户态执行
访问内存（通过 MMU）、算术运算、读时钟（读可以、写不行）、trap 指令（**用户态才用得上**）：都能。
关中断、停机、写 PSW、写时钟、I/O：不能。
:::

== 中断和异常 {int}

:::trap 三条分界线
**① 缺页是异常（故障），不是中断。** 处理完==重新执行这条指令==。2016 年就考这句。
**② 除零的归属**：王道把它归为「故障」的例子，不可恢复时终止。考试只要答「内中断/异常」即可。
**③ 外中断只能在指令结束后响应；异常是指令执行过程中当场处理。**
:::

这是最容易丢分的分界线。

:::shu 分界线
**硬件**：关中断、保存断点（PC、PSW）、形成入口地址（中断向量）。
**OS**：保存通用寄存器、保存/设屏蔽字、处理、恢复、iret。
**响应时机**：指令周期==结束==时，且开中断、有请求、无更高优先级在执行。
:::

== 系统调用 {syscall}
应用程序请求 OS 服务的唯一接口。

@ flow([('传参\n（放寄存器）','bx'),('执行 trap\n陷入内核','gd'),('内核态运行\n服务例程','bk'),('返回用户态','bx')],gap=26,cap='系统调用的过程（2017 真题的顺序）。调用前的库函数在用户态。')

:::shu 系统调用三句话
**发起在用户态，执行在内核态。**
**分类**：设备管理、文件、进程控制、进程通信、内存管理。
**库函数和系统调用**：`printf` 是库函数，内部调用 `write`；`sin()` 不进内核。
:::

:::trap 「发生」vs「执行」
选择题最爱玩这个：缺页==发生==在用户态（用户程序访存时），==处理==在内核态。系统调用==发起==在用户态，==执行==在内核态。**进程切换连「发生」都只能在内核态。**
:::

:::domain
**进内核只有一条路：**中断或异常。
**缺页 = 异常**，重新执行本条；**外中断**回下一条。
**硬件：**关中断、存 PC+PSW、形成入口。**OS：**存通用寄存器、处理、恢复。
**发起/发生在用户态，执行/处理在内核态。进程切换例外。**
:::
