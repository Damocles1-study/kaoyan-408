== CPU 的组成 {parts}
CPU 分两部分：

**运算器**：算。ALU、通用寄存器 GPR、程序状态字 PSW（放标志位）、暂存器。

**控制器**：指挥。程序计数器 PC、指令寄存器 IR、指令译码器、时序系统、微操作信号发生器（CU）。

和主存打交道的是 MAR（地址）和 MDR（数据）。

:::shu 寄存器位数和可见性
**PC** 位数 = 主存**地址**位数。指令按字对齐时，低位恒 0，可少 log₂(字节数) 位。
**MAR** = 地址位数；**MDR** = 存储字长；**IR** = 指令字长。
**程序员可见**：PC、GPR、PSW。**不可见**：MAR、MDR、IR、暂存器。
:::

== 指令周期 {cycle}
时间单位有三层，大的包含小的：

- **时钟周期**：最小单位，节拍。
- **机器周期**（CPU 周期）：完成一个基本动作，比如读一次内存。
- **指令周期**：执行一条指令的全部时间。不同指令的指令周期可以不同，空指令只要取指，而间址寻址的加法要更长。

一条指令的流程：

@ flow([('取指周期\nFE=1','gd'),('间址周期\nIND=1',),('执行周期\nEX=1','bk'),('中断周期\nINT=1',)],gap=34,cap='四个周期靠触发器区分。取指后判断是否间址，执行结束时判断是否有中断')

指令和数据都放在内存，都是二进制，CPU 怎么分？**看现在处于哪个周期**：取指周期取回的是指令，执行周期取回的是数据。

:::shu 四个周期的微操作（默写）
**取指**：`PC→MAR`；`MEM→MDR`；`MDR→IR`；`PC+1→PC`（读命令由 CU 发）。
**间址**：`Ad(IR)→MAR`；`MEM→MDR`；`MDR→Ad(IR)`。
**执行**：看指令。
**中断**：`SP−1→SP, SP→MAR`；`PC→MDR` 写入内存；向量地址 `→PC`。
:::

就算是空操作指令，也要取指，PC 也要加 1，寄存器内容是会变的。

:::recall 默写取指周期四步，并说明 CPU 怎样区分指令和数据。
PC→MAR；MEM→MDR；MDR→IR；PC+1→PC。靠当前处于指令周期的哪个阶段。
:::

== 数据通路 {path}
数据通路是指令执行时数据走的路。两种基本结构：

**CPU 内部单总线**：所有部件接一条内部总线，一个时钟周期只能走一个数。结构简单，但 ALU 要两个输入，所以要**暂存器 Y** 放一个操作数；输出没法马上上总线（一个周期总线只有一个源），所以要**暂存器 Z** 放结果。

@ svg(600,230,'<line x1="30" y1="110" x2="580" y2="110" class="ln" style="stroke-width:6"/>',T(555,95,'内部总线',12,'mt'),box(40,20,60,34,'PC','gd'),box(120,20,60,34,'MAR'),box(200,20,60,34,'MDR'),box(280,20,60,34,'IR','bk'),box(40,160,70,34,'R0~Rn'),box(170,160,50,34,'Y','bu'),box(240,145,80,50,'ALU','rd'),box(350,160,50,34,'Z','bu'),box(450,20,110,34,'主存 MEM','tn'),*[f'<line x1="{x}" y1="54" x2="{x}" y2="110" class="ln"/>' for x in (70,150,230,310)],'<line x1="75" y1="110" x2="75" y2="160" class="ln"/>','<line x1="195" y1="110" x2="195" y2="160" class="ln"/>',arrow(220,177,240,177),arrow(320,177,350,177),'<line x1="375" y1="110" x2="375" y2="160" class="ln"/>',arrow(280,110,280,145),arrow(450,37,340,37,'ln'),cap='单总线数据通路：Y 暂存一个操作数，Z 暂存 ALU 结果')

**专用通路**：部件之间连专门的线，同一周期可以走多路数据。速度快，线多。多总线结构介于两者之间，三总线下 `R1+R2→R3` 一个周期就能做完。

走一遍单总线上的加法。指令 `add R1, [R2]`：把 R1 和内存 M[R2] 相加，放回 R1。

|周期|微操作|控制信号|
|1|`PC→MAR`|PCout，MARin|
|2|`MEM→MDR`，`PC+1→PC`|MemR，MDRin|
|3|`MDR→IR`|MDRout，IRin|
|4|`R2→MAR`|R2out，MARin|
|5|`MEM→MDR`|MemR，MDRin|
|6|`MDR→Y`|MDRout，Yin|
|7|`R1+Y→Z`|R1out，ALU 加，Zin|
|8|`Z→R1`|Zout，R1in|

前 3 步是取指，4–5 步取操作数，6–8 步做加法并写回。**控制信号**就是控制器在每个周期发出的那组开关。写的时候只要保证：每个周期总线上只有一个源。

:::trap 内总线一个周期只能有一个源
要判断两件事能否同周期做，就看它们是否都要用同一条总线。`PC+1→PC` 单总线下要经过 Z，走单独的周期，除非 PC 自带自增电路。
:::

**单周期、多周期**：单周期处理器每条指令一个时钟周期（CPI=1），时钟按最慢的指令定；一个周期内要做完所有事，所以不能用单总线。多周期处理器把指令分成几个周期，部件可以复用。

== 控制器 {ctrl}
控制器把指令翻译成控制信号。输入是 IR 的操作码、节拍、PSW 标志、外部信号；输出就是上表第三列。两种做法：

:::ana 硬布线和微程序
**硬布线**：背下来的条件反射，快但改不了。**微程序**：查手册。把每条指令拆成一串微指令，存在控制存储器里。慢一点，改手册就行。
:::

@ table([['','硬布线','微程序'],['实现','组合逻辑电路','控存（ROM）中存微指令'],['速度','快','慢（要读控存）'],['扩展','难','容易'],['适用','RISC','CISC']])

**层次**：一条**机器指令**对应一段**微程序**，一段微程序是若干**微指令**，一条微指令是一个周期内发出的一组**微命令**，微命令对应一个**微操作**。**控存（CS）** 用 ROM 做，在 CPU 内部，按地址访问。

:::shu 微指令的编码
**直接编码**：一位对应一个命令，最长最快。
**字段直接编码**：互斥的命令放一个字段。一个字段 m 个命令需要 `⌈log₂(m+1)⌉` 位，==+1 是留给「什么都不做」==。
**下地址字段**：位数 = ⌈log₂ 微指令总数⌉。
:::

算一遍：三组互斥命令，分别 3、7、15 个，字段直接编码。分别要 2、3、4 位，共 9 位。而直接编码要 25 位。注意 3+1 = 4 恰好 2 位。

微指令总数：所有指令**共用同一段**取指微程序，只算一份。

:::shu 水平型和垂直型微指令
**水平型**：一条微指令能并行发出多个微命令。长、快、并行能力强，用户编写难。
**垂直型**：类似机器指令，一条只做一个动作，要译码。短、慢、易编。
:::

:::recall 字段直接编码每个字段几位？为什么要 +1？水平型和垂直型差在哪？
⌈log₂(m+1)⌉。留一个编码表示不发命令。水平型并行、长、快；垂直型一条一动作、短、慢。
:::

:::domain
**指令周期：**取指 → 间址 → 执行 → 中断。
**取指微操作：**PC→MAR，MEM→MDR，MDR→IR，PC+1→PC。
**单总线：**一个周期一个源，所以要 Y、Z。
**控制：**硬布线快，微程序易改；字段位数 ⌈log₂(m+1)⌉。
:::
