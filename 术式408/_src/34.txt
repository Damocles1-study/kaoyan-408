== 虚拟内存的基本概念 {base}
:::ana 你的书桌
书架（磁盘）很大，书桌（内存）很小。只把用到的书放在桌上，其余需要时再去书架取，感觉就像桌子无限大。这件事能成，靠的还是[[30|局部性]]。
:::

:::shu 虚拟内存三性
**多次性**：一个进程分多次调入。**对换性**：可以换入换出。**虚拟性**：逻辑上扩大内存。
必须基于**非连续分配**（请求分页、请求分段、请求段页）。
容量上限 = min(主存 + 外存, 地址空间大小)。
:::

== 请求分页 {demand}
页表项增加几个字段：

@ bits([('页框号',20),('存在位 P',1,'gd'),('访问位 A',1,'gd'),('修改位 M',1,'gd'),('外存地址',20)],cap='P 判断是否在内存；A 给置换算法用；M=1 换出要写回磁盘')

:::shu 缺页处理（硬件 + OS）
**① 硬件**：MMU 发现 P=0，产生缺页异常，内核接管。
**② OS**：若有空闲页框直接用；否则按置换算法选一个，若 M=1 写回磁盘。
**③ OS**：启动磁盘 I/O，进程阻塞；调入后修改页表。
**④ 重新执行**这条指令。
一条指令可能产生多次缺页（指令本身跨页，数据也跨页）。
:::

== 页面置换算法 {replace}
用同一个序列比较：`7 0 1 2 0 3 0 4 2 3 0 3 2 1 2 0 1 7 0 1`，3 个页框。

@ page_steps([7,0,1,2,0,3,0,4,2,3,0,3,2,1,2,0,1,7,0,1],3,'OPT')
@ page_steps([7,0,1,2,0,3,0,4,2,3,0,3,2,1,2,0,1,7,0,1],3,'FIFO')
@ page_steps([7,0,1,2,0,3,0,4,2,3,0,3,2,1,2,0,1,7,0,1],3,'LRU')

:::shu 置换算法的关键
**OPT**：淘汰最远将来才用的。无法实现，只作基准。
**FIFO**：淘汰最先进来的。可能 ==Belady 异常==（页框增加，缺页反而增加），只有 FIFO 会。
**LRU**：淘汰最久没用的。性能好，硬件开销大。
**CLOCK（NRU）**：每页一个访问位，指针循环；访问位 1 则清 0 继续，为 0 就换出。是 LRU 的廉价近似。
**改进 CLOCK**：(A,M) 按 `(0,0)→(0,1)→(1,0)→(1,1)` 优先淘汰，第一轮找 (0,0) 不改位，第二轮找 (0,1) 并清 A。
:::

@ page_steps([1,2,3,4,1,2,5,1,2,3,4,5],3,'CLOCK')

== 页框分配 {alloc}
:::shu 三种组合（只有这三种）
**固定分配局部置换**：页数不变。
**可变分配全局置换**：可以抢别人的。
**可变分配局部置换**：页数可变，置换只在自己的页。
**固定分配全局置换不存在**：全局置换要增加页数，和「固定」矛盾。
:::

**调入策略**：预调页（第一次）和请求调页（运行时）。**从哪调入**：对换区（快）或文件区。

== 抖动与工作集 {thrash}
:::ana 刚放下的书马上又要
桌子太小，总是刚放回书架的书又要拿，大部分时间都花在来回搬书上。这就是抖动。原因：页框数少于工作集。
:::

**工作集**：最近 Δ 次访问中涉及的页面集合（集合，不重复）。
**解决抖动**：降低多道程序度（撤销一些进程），增加内存。提高优先级、增大交换区都没用。

== 内存映射文件 {mmap}
:::shu 内存映射文件（2025 新考点）
把一个文件映射到进程的虚拟地址空间。进程读写内存，就等于读写文件，由 OS 在缺页时从文件调入。
**好处**：简化文件操作（不用 read/write）；多个进程可映射同一个文件，==实现共享==。
**页框回收**：OS 在空闲页框不足时，由后台回收进程（kswapd）提前回收一些页框，维护一批空闲页框。回收 M=0 的页不用写回。
:::

== 性能 {perf}
:::shu 缺页率的影响
`有效访问时间 = (1−p)·Tm + p·缺页处理时间`。
缺页处理时间是毫秒级，所以 p 必须非常小。
**影响缺页率的因素**：页大小、页框数、置换算法、程序的局部性（按行访问数组）。
**加快地址转换**：增大 TLB、页表常驻内存。
:::

:::domain
**缺页：**存在位=0 → 异常 → 选页（M=1 写回）→ 调入 → 重新执行。
**算法：**FIFO 有 Belady；LRU 好但贵；CLOCK 廉价。
**分配：**没有「固定 + 全局」。
**抖动：**撤进程、加内存。
:::
