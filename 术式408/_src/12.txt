:::say
查找就是在一堆数据里找一个值。衡量好坏只有一把尺子：ASL（平均查找长度）。这一话把顺序、折半、分块、散列四种放在一起比，并练到判定树和线性探测不会算错。
:::

== 顺序与折半 {seq}
**静态查找**只查不改（顺序、折半、分块）；**动态查找**还要插入删除（BST、散列）。

**ASL** = Σ 查找概率 × 比较次数。成功和失败要分开算。

:::shu 顺序查找
成功 ASL = **(n+1)/2**。失败（无序、有哨兵）= **n+1**。
**有序顺序表的失败** ASL 可以提前结束，= n/2 + n/(n+1)。
:::

:::code c 模板：折半查找（要求有序 + 顺序存储）
int BinSearch(int a[], int n, int key) {
    int low = 0, high = n - 1, mid;
    while (low <= high) {
        mid = (low + high) / 2;
        if (a[mid] == key) return mid;
        else if (a[mid] > key) high = mid - 1;
        else low = mid + 1;
    }
    return -1;
}
:::

数组有序就能对半砍，每比较一次排除一半。代价是要求顺序存储（链表不能随机存取）和有序，所以不适合频繁插入。

折半的过程可以画成**判定树**：第一个比的 mid 作为根，比它小去左子树，比它大去右子树。n=11 时：

@ tree('6(3(1(,2),4(,5)),9(7(,8),10(,11)))',hl='',cap='判定树：mid 向下取整时，每个结点的右子树比左子树多 0 或 1 个结点。结点所在层 = 成功时的比较次数')

**算 ASL**：第 i 层的结点比较 i 次。这棵树第 1 层 1 个、第 2 层 2 个、第 3 层 4 个、第 4 层 4 个。成功 ASL = (1×1 + 2×2 + 4×3 + 4×4) ÷ 11 = 33/11 = 3。失败时落到外部结点（方框），比较次数等于它的父结点的层数，共 12 个外部结点：4 个在第 3 层下（比 3 次），8 个在第 4 层下（比 4 次），失败 ASL = (4×3 + 8×4) ÷ 12 ≈ 3.67。

:::shu 判定树三条
**高度** `h = ⌈log₂(n+1)⌉` = 最多比较次数（成功或失败都不超过 h）。
**逐结点判据**：mid 向下取整时，每个结点 `右子树结点数 − 左子树结点数 ∈ {0, 1}`；向上取整时反过来。整棵树要==始终如一==。
**中序遍历有序**（它也是 BST）。失败结点有 n+1 个，都在外部。
:::

:::recall n=7 时，判定树是什么形状？成功 ASL 是多少？
满二叉树三层。ASL = (1 + 2×2 + 4×3) ÷ 7 = 17/7。
:::

== 分块查找 {block}
既想有序的快，又想方便插入：把表分成若干块，块内无序、块间有序（前一块的最大值小于后一块的最小值），再建一个索引表记录每块的最大值和起始位置。查找时先查索引确定块，再在块内顺序找。**ASL = 索引查找 + 块内查找**。

:::shu 分块 ASL
长度 n 分 b 块、每块 s 个：
索引和块内都顺序查：`ASL = (b+1)/2 + (s+1)/2`，当 `s = √n` 时最小，为 `√n + 1`。
索引用折半：`ASL = ⌈log₂(b+1)⌉ + (s+1)/2`。
:::

例：n = 10000。每块 100 个时最优，顺序查找 ASL = 50.5 + 50.5 = 101。如果每块 1000 个，索引也用顺序：5.5 + 500.5 = 506。

== 散列 {hash}
:::ana 储物柜
不比较，直接算出柜号。两个人算出同一个柜号就是冲突，主要工作就是处理冲突。
:::

:::shu 常用构造与冲突处理
**散列函数**：除留余数法 `H(k)=k%p`（p 取不大于表长的最大质数，这样余数分布均匀）；直接定址、数字分析、平方取中。
**开放定址法**：`Hᵢ = (H(k)+dᵢ) % m`。线性探测 dᵢ=1,2,3…；平方探测 dᵢ=1²,−1²,2²,−2²…；双散列 dᵢ=i·H₂(k)。
**拉链法**：同一个地址的放一条链表。
**装填因子** `α = n / m`。ASL 只依赖 α，==不直接依赖 n==。
:::

三种探测的差别：**线性探测**一冲突就看下一格，会造成同义词和非同义词挤成一团（**聚集**）。**平方探测**跳着看，减轻聚集，但不一定能探测到所有位置（m 要满足 4k+3 形的质数才能探测全部）。**双散列**用第二个函数决定步长，最分散。

走一遍：表长 11，H(k)=k%11。插入 22、33：22 放 0；33 也是 0，线性探测放 1；平方探测也放 1（d=1）。再插入 44：线性探测放 2；平方探测看 0+1=1（占）、0−1=10（空），放 10。

:::trap 删除和聚集
**开放定址法不能直接删除**，只能做标记（否则断了后面的探测路径）。拉链法可以直接删。
**堆积（聚集）**是线性探测的特点，它让不同同义词竞争同一批地址，直接影响的是 ASL，不影响存储效率。
:::

:::shu 手算 ASL
**成功**：每个关键字比较次数之和 ÷ 关键字数。
**失败**：对散列函数的每个可能取值（注意是 `mod p` 的 p 个，不是表长 m），一直走到空位，比较次数算上这次碰到空位的比较 ÷ p。
:::

走一个完整例子。表长 11，H=key%11，线性探测，全部由程序计算：

@ hash_lp([22,41,53,46,30,13,1,67],11,11,1)

**怎样提高散列表的效率**：设计好散列函数；处理冲突方法上避免聚集；降低装填因子。α 变小才有用，改大表长但 α 不变的话不会变好。

:::recall 成功和失败 ASL 分别怎么算？失败时除以谁？开放定址为什么不能直接删？
成功除以关键字数；失败是每个可能地址走到空位的比较次数之和除以 p。直接删会断开探测路径。
:::

:::domain
**折半：**判定树高 ⌈log₂(n+1)⌉，右比左多 0 或 1。
**分块：**s=√n 最优。
**散列：**ASL 只看 α；失败除 p 不除 m；开放定址不能硬删。
:::
