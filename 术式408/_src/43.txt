链路层第一半：怎样把一段不可靠的线路变成可靠的。==滑动窗口==在这里第一次出现，到 [[49|TCP]] 会再用一遍。两个公式配真题。

== 组帧 {frame}
:::shu 四种组帧方法
**字符计数法**：首字节写长度。一错全错。
**字节填充**：FLAG 定界，内容中有 FLAG 就加转义字符。
**零比特填充（HDLC）**：FLAG = 01111110；发送方遇到 5 个连续 1 就插入 0。
**违规编码**：用曼彻斯特中不用的码。
:::

== 差错控制 {err}
:::shu CRC（检错，不纠错）
生成多项式最高次 r，就在数据后补 r 个 0，模 2 除，余数就是校验码。
接收方再除，余数 0 则无错。
:::

@ svg(620,110,box(10,30,300,36,'数据 M（m 位）','bx'),box(310,30,110,36,'r 位 CRC','gd'),T(250,88,'接收方：整个帧 ÷ 生成多项式，余数 = 0 就正确',13,'rdt'),cap='CRC 帧结构')

:::shu 海明码（纠 1 位，检 2 位）
**校验位数 r**：`2ʳ ≥ m + r + 1`。
**校验位放在 2 的幂次位**（1,2,4,8…）。
第 i 个校验位负责所有编号二进制第 i 位为 1 的位。
**纠错**：把校验的异或结果拼起来，就是错的那一位的编号。
**海明距离** d：检错 d−1，纠错 (d−1)/2。
:::

== 滑动窗口 {window}
@ steps([
 (seq(['发送方','接收方'],[(0,1,'帧 0'),(1,0,'ACK 0','d'),(0,1,'帧 1'),(1,0,'ACK 1','d')],bare=True),'<b>停止等待</b>：发一个，等确认。窗口大小 1。序号 1 位就够。'),
 (seq(['发送方','接收方'],[(0,1,'帧 0'),(0,1,'帧 1'),(0,1,'帧 2','x'),(0,1,'帧 3'),(1,0,'ACK 1 (累积)','d'),('note',0,'超时：重传 2、3'),(0,1,'帧 2','r'),(0,1,'帧 3','r')],bare=True),'<b>GBN 后退 N 帧</b>：连续发，接收方只收按序的（接收窗口 1），累积确认。丢一帧后面全部重传。'),
 (seq(['发送方','接收方'],[(0,1,'帧 0'),(0,1,'帧 1','x'),(0,1,'帧 2'),(1,0,'ACK 0','d'),(1,0,'ACK 2','d'),('note',0,'只重传 1'),(0,1,'帧 1','r')],bare=True),'<b>SR 选择重传</b>：接收方缓存乱序帧，每帧单独确认。只重传丢的那一帧。')],'三种协议')

:::shu 三协议窗口上限（序号 n 位）
|协议|发送窗口|接收窗口|
|S-W|1|1|
|GBN|`≤ 2ⁿ − 1`|1|
|SR|`≤ 2^(n−1)`|`≤ 2^(n−1)`|
SR 中 `W发 + W收 ≤ 2ⁿ`。
:::

:::ana 为什么有上限
序号是循环的。窗口太大，重传的旧帧编号和新帧编号一样，接收方分不清。
:::

== 信道利用率 {util}
:::shu 利用率母公式
`U = min(1, N · T_D / T)`
N：窗口大小（S-W 为 1）；`T_D`：发一帧的时间；`T`：发送周期，从开始发到收到确认 `= T_D + RTT + T_A`。
**不计确认帧**：`T_A = 0`。
**捎带确认等长帧**：`T_A = T_D`。
**实际速率** = U × 带宽。
:::

:::link 同一个窗口
[[49|TCP]] 用的也是滑动窗口，只是单位变成字节，累积确认 + 快重传更接近 GBN 和 SR 的混合。
:::

:::domain
**组帧：**5 个 1 插 0。**CRC：**补 r 个 0，模 2 除。**海明：**2ʳ≥m+r+1。
**窗口：**GBN ≤2ⁿ−1；SR ≤2^(n−1)。
**利用率：**U = N·T_D / T。
:::
