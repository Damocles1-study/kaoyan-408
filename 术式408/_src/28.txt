:::say
同步问题的难点不在 P、V 的语法，而在 ==能否把一段故事翻译成「谁等谁、谁和谁互斥」==。这一话给一个固定翻译步骤，然后讲透五个模子。绝大部分同步问题都是它们的变形。
:::

== 固定四步 {steps}
:::vow 写同步问题的四步
**① 关系分析**：谁和谁互斥，谁和谁同步。写成句子。
**② 定义信号量**：每个互斥一个 mutex=1；每种资源一个，初值 = 数量；每个同步一个，初值 = 0。写清含义和初值。
**③ 写进程**：先写出动作骨架，再插入 P、V。
**④ 检查**：同步 P 在互斥 P 之前；每个 P 都有配对的 V；并发度是否最大。
:::

:::trap 三个常见错误
**① 只写 semaphore，不写初值和含义。**
**② 互斥和同步的 P 次序反了**，导致死锁。
**③ 把判断写在 mutex 外面**：`if (count==0) P(rw)` 的判断和修改必须在同一个 mutex 内，否则判断时的值已经过时。
:::

== 模子一：生产者-消费者 {pc}
一个缓冲区，有 n 个空位。生产者放，消费者取。翻译：

- **互斥**：缓冲区一次只能一人动，`mutex = 1`。
- **同步**：满了生产者等消费者；空了消费者等生产者。
- **资源**：`empty = n`（空位数），`full = 0`（产品数）。

:::code c 生产者消费者（缓冲区 n）
semaphore mutex = 1, empty = n, full = 0;

producer() {
    while (1) {
        生产;
        P(empty);       // 先申请空位（同步）
        P(mutex);       // 再申请缓冲区（互斥）
        放入;
        V(mutex);
        V(full);
    }
}
consumer() {
    while (1) {
        P(full);
        P(mutex);
        取走;
        V(mutex);
        V(empty);
        消费;
    }
}
:::

:::rev 如果把 producer 的 P(empty)、P(mutex) 交换，缓冲区满时会发生什么？
生产者先拿到 mutex，然后 P(empty) 阻塞。消费者要 P(mutex) 才能取走，也阻塞。两人互等，==死锁==。所以「同步 P 在前，互斥 P 在后」。
:::

**最容易见到的变形**：

- **多种产品**：每种产品一个 full 型信号量（比如 `odd`、`even`），共用 `empty` 和 `mutex`。
- **一次取多个**：多一个信号量，让消费者之间排队，保证这一批不被别人打断。
- **双向**：两个人互相写信，就是两组生产者消费者叠在一起。

== 模子二：读者-写者 {rw}
读可以同时，写必须独占。如果读者每人都要 P(rw)，那读者之间也互斥了。怎样让读者共用？**让第一个读者上锁，最后一个读者解锁**，中间的读者直接进。这要有一个计数器，计数器本身也要保护。

:::code c 读者优先
int count = 0;
semaphore mutex = 1;    // 保护 count
semaphore rw = 1;       // 读写互斥

writer() {
    P(rw); 写; V(rw);
}
reader() {
    P(mutex);
    if (count == 0) P(rw);     // 第一个读者负责占坑
    count++;
    V(mutex);
    读;
    P(mutex);
    count--;
    if (count == 0) V(rw);     // 最后一个读者负责放坑
    V(mutex);
}
:::

问题：读者接连不断地来，写者永远轮不到。改法：

:::shu 写者优先（读写公平）的改法
多加一个 `w=1`，读者和写者都先 `P(w)`。读者拿到 count 之后就 `V(w)`；写者写完才 `V(w)`。写者一来占住 w，后面的读者就进不去了。
:::

:::flash 看到什么想到读者写者
「多个 A 可以同时，但 A 和 B 互斥」「第一个开门、最后一个关门」。比如过独木桥（同方向一起走）。
:::

== 模子三：哲学家进餐 {phil}
5 个人围坐，5 根筷子放在两人之间，每人要拿到左右两根才能吃。每根筷子是一个互斥信号量。

如果每人都先拿左边的，5 人同时拿，每人都等右边那根，就是死锁。

:::shu 三种解法
**① 限制人数**：最多 4 人同时拿筷子，就至少有一人能拿到两根。
**② 奇偶法**：奇数号先左后右，偶数号先右后左，破坏环。
**③ 一次拿两根**：拿筷子的动作用一个 mutex 保护。
:::

:::code c 限制上桌人数
semaphore chopstick[5] = {1,1,1,1,1};
semaphore room = 4;        // 最多 4 人同时拿筷子

philosopher(int i) {
    while (1) {
        P(room);
        P(chopstick[i]);
        P(chopstick[(i + 1) % 5]);
        吃;
        V(chopstick[(i + 1) % 5]);
        V(chopstick[i]);
        V(room);
        思考;
    }
}
:::

**吸烟者问题**是另一种资源分配：一个供应者轮流放两样材料，三个吸烟者各缺一样。供应者放了哪两样，就 V 对应的吸烟者，等他抽完再放下一轮。本质上是一个缓冲区、多种产品的生产者消费者。

== 模子四：前驱关系 {prec}
一个操作结束后，另一个才能开始。每一条边一个信号量，初值 0。

@ graph({'S1':(50,70),'S2':(170,20),'S3':(170,120),'S4':(290,20),'S5':(290,120),'S6':(410,70)},[('S1','S2'),('S1','S3'),('S2','S4'),('S2','S5'),('S3','S6'),('S4','S6'),('S5','S6')],directed=True,cap='每条边 = 一个初值 0 的信号量。前驱做完 V，后继开始前 P')

:::code c 前驱图的写法
semaphore a1=0, a2=0, b1=0, b2=0, c=0, d=0, e=0;
S1() { 做; V(a1); V(a2); }
S2() { P(a1); 做; V(b1); V(b2); }
S3() { P(a2); 做; V(e); }
S4() { P(b1); 做; V(c); }
S5() { P(b2); 做; V(d); }
S6() { P(c); P(d); P(e); 做; }
:::

这和 [[11|拓扑排序]]是同一张图：入度就是这个结点开头要 P 几次。

== 模子五：理发师（有界排队） {barber}
银行取号、博物馆、公交车都是它：有座位限制，加一个服务员。

翻译：一个计数器记录等待人数，由 mutex 保护；顾客到了要叫醒服务员（customers），然后等服务员就位（barbers）。这是一对方向相反的同步。

:::code c 顾客与服务员
int waiting = 0;                 // 等待人数，受 mutex 保护
semaphore mutex = 1;
semaphore customers = 0;         // 同步：有顾客了
semaphore barbers = 0;           // 同步：服务员准备好了

customer() {
    P(mutex);
    if (waiting < N) {
        waiting++;
        V(customers);            // 叫醒服务员
        V(mutex);
        P(barbers);              // 等服务员
        接受服务;
    } else V(mutex);             // 座位满，离开
}
barber() {
    while (1) {
        P(customers);            // 没顾客就睡
        P(mutex);
        waiting--;
        V(barbers);
        V(mutex);
        服务;
    }
}
:::

注意 `else` 分支也要 `V(mutex)`。每条路径都要放开拿到的锁，这是最常见的笔误。

**有时候不用计数器**：如果多出来的人只是**等**而不是走，直接用资源信号量（初值 = 座位数）就行。只有「人满就走」这种要判断的场景才要计数器，因为 P 操作判断不了「能不能拿到」，它只会阻塞。

:::recall 合上页面，默写生产者消费者和读者优先。
生产者：P(empty) P(mutex) 放 V(mutex) V(full)。消费者：P(full) P(mutex) 取 V(mutex) V(empty)。读者：P(mutex)，count==0 时 P(rw)，count++，V(mutex)，读，P(mutex)，count--，count==0 时 V(rw)，V(mutex)。
:::

:::domain
**四步：**关系、定义（写初值）、骨架、检查。
**五个模子：**生产消费、读者写者（首尾开关门）、哲学家（限人数）、前驱（每边一信号量）、理发师（计数 + 叫号）。
**顺序：**同步 P 先，互斥 P 后。
:::
