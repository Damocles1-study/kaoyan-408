:::say
408 每年一道 8 分左右的同步大题。这种题的难点不在语法，而是 ==你能否把题目翻译成「谁等谁、谁互斥」==。这一话给固定步骤，然后把历年常考的五个模子全部讲完。
:::

== 固定四步 {steps}
:::vow PV 大题四步（卷面就这么写）
**① 关系分析**：列出谁和谁互斥、谁和谁同步。写在卷面上，这几句能拿过程分。
**② 定义信号量**：每个互斥一个 mutex=1；每种资源一个，初值=数量；每个同步一个，初值=0。写清楚含义和初值。
**③ 写进程**：先写出动作骨架，再插入 P、V。
**④ 检查**：同步 P 在互斥 P 之前；每个 P 都有配对的 V；是否最大并发。
:::

:::trap 三个扣分点
**① 只写 semaphore 不写初值和含义** 直接扣。
**② 互斥和同步 P 的次序错了导致死锁。**
**③ 把判断写在 mutex 外面**：`if (count==0) P(rw)` 中的判断和修改必须在同一个 mutex 里。
:::

== 模子一：生产者-消费者 {pc}
:::code c 生产者消费者（缓冲区 n）
semaphore mutex = 1, empty = n, full = 0;

producer() {
    while (1) {
        生产;
        P(empty);       // 先申请空位（同步）
        P(mutex);       // 再申请缓冲区（互斥）
        放入;
        V(mutex);
        V(full);
    }
}
consumer() {
    while (1) {
        P(full);
        P(mutex);
        取走;
        V(mutex);
        V(empty);
        消费;
    }
}
:::

:::rev 如果把 producer 的 P(empty)、P(mutex) 交换，缓冲区满时会发生什么？
生产者先拿到 mutex，然后 P(empty) 阻塞。消费者要 P(mutex) 才能取走，也阻塞。两人互等：==死锁==。所以「同步 P 在前，互斥 P 在后」。
:::

@q os:2.3-综20 | 2014。消费者要连续取 10 件：多一个 `mutex1` 让消费者之间排队，这样一个消费者取 10 件时不会被其他消费者穿插。**放在外面**，它保护的是「连续 10 次」这个动作。
@q os:2.3-综21 | 2015。两人互相给对方写信，就是两组「生产者-消费者」叠在一起。信箱 A：Full_A=x，Empty_A=M−x，mutex_A；信箱 B 同理。

== 模子二：读者-写者 {rw}
读可以同时，写必须独占。**关键：第一个读者上锁，最后一个读者解锁**。

:::code c 读者优先
int count = 0;
semaphore mutex = 1;    // 保护 count
semaphore rw = 1;       // 读写互斥

writer() {
    P(rw); 写; V(rw);
}
reader() {
    P(mutex);
    if (count == 0) P(rw);     // 第一个读者负责占坑
    count++;
    V(mutex);
    读;
    P(mutex);
    count--;
    if (count == 0) V(rw);     // 最后一个读者负责放坑
    V(mutex);
}
:::

:::shu 写者优先（读写公平）的改法
多加一个 `w=1`，读者和写者都先 `P(w)`，读者拿到 count 之后 `V(w)`，写者写完才 `V(w)`。这样写者来了之后，后面的读者进不去。
:::

:::flash 看到什么想到读者写者
「多个 A 可以同时，但 A 和 B 互斥」「第一个开门、最后一个关门」：都是这个模子。过桥（同方向一起走）、复杂的共享变量。
:::

@q os:2.3-综22 | 2017。三个线程，读 x、y、z，修改 y、z。要最大并发：对每一对变量按读写分别加信号量，只有都是读时才不互斥。这题对「最大并发」要求很高。

== 模子三：哲学家进餐 {phil}
:::ana 问题和解法
5 人 5 筷子，都拿左边那根，就死锁。解决方法：① 最多让 4 个人上桌；② 奇数号先左后右，偶数号先右后左；③ 拿两根筷子的动作用 mutex 保护（一起拿）。
:::

:::code c 限制上桌人数（最常用）
semaphore chopstick[5] = {1,1,1,1,1};
semaphore room = 4;        // 最多 4 人同时拿筷子

philosopher(int i) {
    while (1) {
        P(room);
        P(chopstick[i]);
        P(chopstick[(i + 1) % 5]);
        吃;
        V(chopstick[(i + 1) % 5]);
        V(chopstick[i]);
        V(room);
        思考;
    }
}
:::

@q os:2.3-综23 | 2019。m 个碗，就是天然的「room」：碗数 `bowl = min(n−1, m)`。为什么要取 min？碗比 n−1 多时也要限制 n−1，否则还是能死锁。一眼看出才是硬本事。

== 模子四：前驱关系 {prec}
一个操作结束后，另一个才能开始。每一条边一个信号量，初值 0。

:::code c 前驱图的写法
semaphore a1=0, a2=0, b1=0, b2=0, c=0, d=0, e=0;
S1() { 做; V(a1); V(a2); }
S2() { P(a1); 做; V(b1); V(b2); }
S3() { P(a2); 做; V(e); }
S4() { P(b1); 做; V(c); }
S5() { P(b2); 做; V(d); }
S6() { P(c); P(d); P(e); 做; }
:::

== 模子五：理发师（有界排队） {barber}
银行取号、博物馆、公交车都是它：有座位数限制 + 服务员。

:::code c 顾客与服务员
int waiting = 0;                 // 等待人数，受 mutex 保护
semaphore mutex = 1;
semaphore customers = 0;         // 同步：有顾客了
semaphore barbers = 0;           // 同步：服务员准备好了

customer() {
    P(mutex);
    if (waiting < N) {
        waiting++;
        V(customers);            // 叫醒服务员
        V(mutex);
        P(barbers);              // 等服务员
        接受服务;
    } else V(mutex);             // 座位满，离开
}
barber() {
    while (1) {
        P(customers);            // 没顾客就睡
        P(mutex);
        waiting--;
        V(barbers);
        V(mutex);
        服务;
    }
}
:::

@q os:2.3-综18 | 2011。取号机 = mutex，座位 = 计数，叫号 = 上面 customers/barbers 那一对同步。
@q os:2.3-综19 | 2013。两个互斥：博物馆容量 `empty=500`，出入口 `mutex=1`。进门、出门都要 P(mutex)。注意 empty 要在门外申请，==否则人进不来也出不去==，这正是同步 P 先于互斥 P。

:::domain
**四步：**关系、定义（写初值）、骨架、检查。
**五个模子：**生产消费、读者写者（首尾开关门）、哲学家（限人数）、前驱（每边一信号量）、理发师（计数 + 叫号）。
**顺序：**同步 P 先，互斥 P 后。
:::
