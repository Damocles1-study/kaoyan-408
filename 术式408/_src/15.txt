== 简单选择排序 {sel}
每趟从未排序部分选出最小的，放到前面。不管数据如何，比较次数都是 `n(n−1)/2`，时间 O(n²)，**不稳定**（交换会跨过相同元素）。交换次数不超过 n−1，所以移动少。

== 堆 {heap}
简单选择每趟都重新比一遍，之前比较的信息全扔了。堆把比较结果留下来。堆是一棵存在数组里的完全二叉树。大根堆：父 ≥ 子，所以堆顶是最大值。

**下沉**：某结点比孩子小时，和较大的孩子交换，一路往下。**建堆**：从最后一个分支结点 ⌊n/2⌋ 开始，向前逐个下沉。**排序**：堆顶和末尾交换，堆缩小一个，对新堆顶下沉，重复。

@ heap_steps([53,17,78,9,45,65,87,32])

:::code c 模板：堆的下沉（下标从 1 开始）
void HeadAdjust(int A[], int k, int len) {
    A[0] = A[k];
    for (int i = 2 * k; i <= len; i *= 2) {
        if (i < len && A[i] < A[i + 1]) i++;   // 取较大的孩子
        if (A[0] >= A[i]) break;
        A[k] = A[i];
        k = i;
    }
    A[k] = A[0];
}
void HeapSort(int A[], int len) {
    for (int i = len / 2; i > 0; i--) HeadAdjust(A, i, len);   // 建堆
    for (int i = len; i > 1; i--) {
        int t = A[1]; A[1] = A[i]; A[i] = t;                   // 堆顶换到末尾
        HeadAdjust(A, 1, i - 1);
    }
}
:::

:::shu 堆的几个结论
**建堆**：从 ⌊n/2⌋ 向前下沉，时间 **O(n)**（书上界 4n，比较次数实际约 1.88n）。
**下沉**：比较两个孩子 1 次，较大孩子和父亲 1 次，所以每层最多 **2 次比较**。
**插入**：放到末尾向上调，每层 **1 次比较**。
**删除**：末尾补到堆顶，向下调。
**堆排序**：最好最坏都是 O(n log n)，O(1) 空间，不稳定。
**应用**：取前 k 大（维护大小为 k 的小根堆）；优先队列。
:::

:::trap 插入比较和下沉比较次数不同
上滤一层比 1 次（和父亲比）；下滤一层比 2 次（先比两个孩子）。依次插入建堆 ≠ 整体建堆，结果常常不一样。
:::

:::recall 建堆从哪开始？为什么是 O(n)？下沉一层比较几次？
从 ⌊n/2⌋ 向前。大部分结点在底层，下沉距离短，累计线性。2 次。
:::

== 归并排序 {merge}

两个有序序列合成一个，这是[[02|有序合并]]。从每个元素自成一段开始，两两合并，段长翻倍。
@ merge_steps([49,38,65,97,76,13,27])

:::code c 模板：归并
void Merge(int A[], int low, int mid, int high) {
    int i = low, j = mid + 1, k = low;
    for (int t = low; t <= high; t++) B[t] = A[t];     // B 是辅助数组
    while (i <= mid && j <= high)
        A[k++] = (B[i] <= B[j]) ? B[i++] : B[j++];     // <= 保证稳定
    while (i <= mid) A[k++] = B[i++];
    while (j <= high) A[k++] = B[j++];
}
void MergeSort(int A[], int low, int high) {
    if (low < high) {
        int mid = (low + high) / 2;
        MergeSort(A, low, mid);
        MergeSort(A, mid + 1, high);
        Merge(A, low, mid, high);
    }
}
:::

:::shu 归并
时间永远 **O(n log n)**，空间 **O(n)**，**稳定**。趟数 ⌈log₂n⌉。m 路归并趟数 ⌈log_m n⌉。
两个长 m、n 的有序表合并：最少比较 min(m,n) 次，最多 m+n−1 次。
:::

== 基数排序 {radix}
前面的都靠比较。基数排序不比较：按位分配、收集。从最低位开始，把元素分到 0–9 十个队列，再按序收回；然后看下一位。因为每趟稳定，所以高位相同的元素，低位顺序不变。

@ radix_steps(['329','457','657','839','436','720','355'])

:::shu 基数排序
d 位、r 进制：时间 **O(d(n+r))**，空间 **O(r)**，**稳定**。
用的是链式队列，每趟 r 个队列。
移动次数与初始序列无关。
:::

== 外部排序 {ext}
数据放不下内存，就要分段读、归并。总时间几乎全部耗在 ==磁盘 I/O== 上，所以优化目标是减少归并趟数。

先用内部排序把每段（内存能装多少）排好，这叫**初始归并段**；再多路归并。

@ flow([('初始段\n（内排生成）','bx'),('归并','bk'),('归并','bk'),('一个有序文件','gd')],gap=30,cap='外部排序的两步：生成初始归并段，然后多路归并')

:::shu 外排四个工具
**① 归并趟数** `S = ⌈log_k r⌉`（k 路、r 个初始段）。k 越大或 r 越小，趟数越少。
**② 败者树**：k 路归并时选最小值的比较从 k−1 次降为 ⌈log₂k⌉ 次，使总比较次数和 k 无关。这就是**多路平衡归并**。
**③ 置换-选择排序**：内存区 w 时生成更长的初始段（平均 2w），减小 r。
**④ 最佳归并树**：段长不等时，归并顺序按哈夫曼树（WPL 就是 I/O 次数）。严格 k 叉，要补虚段：若 `(r−1) % (k−1) = u ≠ 0`，补 `k−1−u` 个长度 0 的虚段。
:::

**败者树**：k 路归并的一棵完全二叉树，叶子是各段当前元素。分支结点存的是这场比赛的**败者**（段号），胜者继续往上；根之上再放一个结点存冠军。取走冠军后，只要从它那一路向上重赛，⌈log₂k⌉ 次比较就决出新冠军。

**置换-选择**走一遍：内存放 6 个，输入 `51 49 39 46 38 29 14 61 15 30 1 48 52 3 63 27 4 13 89 24 46 58 33 76`。每次输出内存里最小的、且不小于刚输出值的元素，再读入一个。放不进当前段的留到下一段。得到三段：

- `29 38 39 46 49 51 61`（7 个）
- `1 3 14 15 27 30 48 52 63 89`（10 个）
- `4 13 24 33 46 58 76`（7 个）

每段都比内存的 6 个长。

**最佳归并树**走一遍：段长 2、3、6、9、12、17、18、24，3 路。(8−1) % 2 = 1，补 2−1 = 1 个虚段。每次取最小的 3 个：0+2+3=5；5+6+9=20；12+17+18=47；20+24+47=91。WPL = 5+20+47+91 = 163，读写块数 = 163×2。

:::link 最佳归并树 = 哈夫曼树
[[07#huff|第 07 话]]的哈夫曼树就是它：先合并的部分被多读写几次，所以把小的放在最下面。
:::

:::trap 趟数和比较次数
败者树减少的是每次选最小的比较次数，==不会减少归并趟数==；k 变大 I/O 趟数减少，但内存要给 k+1 个缓冲区。两者不要混。
:::

:::recall 外排的四个优化工具，各自减少什么？虚段怎么算？
增大 k：减少趟数。败者树：减少选最小的比较。置换-选择：减少段数。最佳归并树：减少 I/O。(r−1)%(k−1)=u≠0 时补 k−1−u。
:::

:::flash 口诀
**不稳定四兄弟：**快（快排）些（希尔）选（简单选择）堆（堆排）。
**与初始序列无关：**简单选择、堆、归并、基数——「选一堆龟（归）基」。
**每趟至少一个到最终位置：**冒泡、选择、快排、堆。
**数组变链表反而变慢：**希尔、堆（都依赖下标随机存取）。
:::

:::shu 怎么选排序
n 小：直接插入或简单选择。基本有序：直接插入或冒泡。n 大：快排、堆、归并。要稳定且 n 大：归并。关键字位数少、n 大：基数。内存放不下：外排。
:::
