:::say
三种树解决同一个问题：查找要快。有序数组查找快但插入慢，链表插入快但查找慢。BST 兼顾两者，但可能退化成链；AVL 严格平衡，红黑树放宽要求换来调整更少。
:::

== 二叉搜索树 BST {bst}
定义：左子树全部小于根，右子树全部大于根，左右子树也都是 BST。所以 ==中序遍历就是递增序列==，这也是判定 BST 的标准方法。

:::shu BST 三个操作
**查找**：比根小往左，比根大往右。平均 O(log n)，最坏（退化成链）O(n)。
**插入**：查找失败的那个位置就是插入位置，新结点==必定是叶子==。
**删除**：叶子直接删；只有一棵子树的让子树顶替；有两棵子树的，用==中序后继（右子树最左）或中序前驱==的值替换，再删那个结点。
:::

@ svg(620,190,tree_inline('50(30(20,40),70(60,80))',8,10,28,40),T(190,150,'删 50：两棵子树',12,'rdt'),arrow(290,70,350,70),tree_inline('60(30(20,40),70(,80))',350,10,28,40),T(520,150,'用后继 60 顶替，再删原 60',12,'rdt'),cap='删除有两个孩子的结点：值替换成中序后继')

**查找长度**：ASL 取决于树的形状。依次插入 1,2,3,4,5 得到一条链，ASL = (1+2+3+4+5)/5 = 3；插入 3,1,4,2,5 得到矮树，ASL = (1+2+2+3+3)/5 = 2.2。同样的元素，顺序不同，形状不同。

**查找路径**上有一个性质：每走一步，可能的范围就收窄一次。往左走，后面所有值都要小于当前结点；往右走，都要大于。可以用它判断一个序列能否作为查找路径。

:::recall BST 删除三种情况怎么处理？新插入的结点一定是什么？
叶子直接删；一个孩子让孩子顶替；两个孩子用中序后继（或前驱）的值替换，再删那个结点。一定是叶子。
:::

== 平衡二叉树 AVL {avl}
BST 的问题是可能退化成链。AVL 规定：每个结点左右子树高度差（**平衡因子** = 左高 − 右高）只能是 −1、0、1。

:::shu 高度为 h 的 AVL 最少结点数
`N(h) = N(h−1) + N(h−2) + 1`，N(0)=0，N(1)=1。
序列：1, 2, 4, 7, 12, 20, 33, 54……
n 个结点的 AVL 高度是 O(log n)，查找也是 O(log n)。
:::

=== 四种旋转
插入后沿路径向上找到==第一个失衡的结点==，称为最小不平衡子树的根 A。判断新结点插在 A 的哪个方向：

@ table([['类型','新结点插在','做法'],['LL','A 左孩子的左子树','A 右旋一次'],['RR','A 右孩子的右子树','A 左旋一次'],['LR','A 左孩子的右子树','先左旋 B，再右旋 A（中间那个升上去）'],['RL','A 右孩子的左子树','先右旋 B，再左旋 A（中间那个升上去）']])

:::flash 不用背左旋右旋
LL / RR：==中间那个结点==升上去当根。LR / RL：==最下面那个（新的中间值）==升上去当根。三个结点排大小，中间值当根，另外两个当左右孩子，其余子树按大小挂回去。这样永远不会转错。
:::

走一遍 LR：A=50（左孩子 B=20），新结点 C=30 插在 B 的右边。三个数排序 20、30、50，30 当根，20 是左孩子，50 是右孩子。30 原来的左子树（都在 20 和 30 之间）挂给 20 的右边，右子树（都在 30 和 50 之间）挂给 50 的左边。

**删除**：像 BST 一样删，然后从删除点向上检查，失衡就旋转，**可能一路调整到根**。判断类型时看较高的子树：A 的较高子树是左，再看左孩子较高的那边。

@ avl_steps([16,3,7,11,9,26,18])

:::trap AVL 删除
插入至多调整一次（最多两次旋转），之后整棵树高度恢复，不用再往上。删除可能让失衡一路传到根，最多旋转 O(log n) 次。这是 AVL 不如红黑树的地方。
:::

:::recall 插入后找谁调整？四种类型怎样靠「中间值」一招解决？
找第一个失衡的结点 A。A 和路径上的两个结点排序，中间值当根，其余子树按大小挂回。
:::

== 红黑树 {rb}
AVL 太「较真」，插入删除老是要旋转。红黑树放宽要求：==不要求严格平衡，保证最长路径不超过最短路径的 2 倍==。这样查找仍是 O(log n)，而调整通常只改颜色。

:::shu 红黑树五条性质
1. 每个结点非红即黑。
2. 根是黑的。
3. 叶（NIL 空结点）是黑的。
4. ==红结点的孩子必须是黑的==（不能连续两个红）。
5. 任一结点到其所有后代 NIL 的路径上，==黑结点数相同==（称为黑高 bh）。
:::

@ tree('13:b(8:r(1:b(,6:r),11:b),17:r(15:b,25:b(22:r,27:r)))',cap='一棵红黑树。所有叶结点外都接着 NIL（图中省略）')

:::shu 红黑树的结论
**① 最长路径 ≤ 2 × 最短路径**（最短全黑，最长红黑相间）。
**② n 个内部结点的树高 h ≤ 2log₂(n+1)**。
**③ 黑高为 bh 的子树至少有** `2^bh − 1` 个内部结点。
**④ 根黑高为 k 时，内部结点数最少** `2^k − 1`（全黑满二叉树），**最多** `2^(2k) − 1`（红黑相间的满二叉树）。
**⑤ 新插入的结点染红**（染黑会破坏性质 5，染红只可能破坏性质 4，好修）。
**⑥ 删除或插入的调整都是 O(log n)，旋转次数至多常数次。**
:::

=== 插入的调整
新结点 z 是红的，只有当父亲也是红的时候才需要调整。此时看==叔叔==的颜色：

|叔叔|操作|
|红色|父、叔变黑，爷爷变红；把爷爷当成新的 z 继续向上（若爷爷是根则再变黑）|
|黑色（或 NIL），LL/RR 型|旋转一次（像 AVL），父变黑、爷变红|
|黑色（或 NIL），LR/RL 型|旋转两次（像 AVL），z 变黑、爷变红|

:::ana 判断「要不要旋转」
叔叔红：大家一起换颜色，把问题往上推。叔叔黑：换颜色解决不了，只能旋转。旋转方向和 AVL 完全相同，所以你不需要再学一遍。
:::

:::deep 红黑树删除
先按 BST 删除，真正被摘掉的结点要么是叶子，要么只有一个孩子。如果被摘掉的是红的，什么都不用做。如果是黑的，那条路径黑高少 1，这叫双黑，要靠兄弟的颜色分情况旋转或染色。这部分要求只到了解思路，具体分支不用背。
:::

:::link 工程中的使用
Linux 的 CFS 调度器和 Java 的 TreeMap 用红黑树；MySQL 索引和文件系统用 [[13|B⁺ 树]]，因为后者更矮，适合磁盘。
:::

:::domain
**BST：**中序递增；删两子树用后继替换。
**AVL：**N(h) = N(h−1)+N(h−2)+1；三结点排大小，中间值当根。
**红黑：**根黑、红不连红、黑高相同；h ≤ 2log₂(n+1)；叔红变色，叔黑旋转。
:::
