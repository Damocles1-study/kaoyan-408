== 进程 {proc}
一台机器要同时跑好几个程序。程序本身只是磁盘上的一个文件，它不能说明「这次运行到哪了」。所以要一个新概念，表示**一次运行**。

:::ana 菜谱和做菜
**程序**是菜谱（静态）；**进程**是照着菜谱做菜的这一次过程（动态）：要占灶台（CPU）、用食材（内存）、记住切到哪一步（PC）。同一本菜谱可以同时被两个厨师做，所以一个程序可以对应多个进程。比方的局限：一个厨师在做一半时可以被叫走，回来时要完全恢复现场，这正是下面 PCB 的工作。
:::

**进程 = PCB + 程序段 + 数据段**。**PCB**（进程控制块）是进程存在的唯一标志，操作系统靠它管理进程。里面有四类信息：

- **进程描述**：PID、所属用户。
- **进程控制和管理**：状态、优先级、代码和数据的位置。
- **资源分配**：页表地址、打开的文件。
- **CPU 现场**：切走时保存的 PC、PSW、通用寄存器。

**进程的特性**：动态性（最基本）、并发性、独立性、异步性。

:::shu 五态及转换
@ svg(600,180,box(10,70,80,36,'创建'),box(160,20,90,36,'就绪','gd'),box(330,20,90,36,'运行','bk'),box(245,120,90,36,'阻塞','tn'),box(490,70,80,36,'终止'),arrow(90,80,160,48),arrow(250,30,330,30),arrow(330,46,250,46),T(290,16,'调度',12,''),T(290,64,'时间片到/抢占',12,''),arrow(360,56,320,120),T(385,92,'等事件（主动）',12,''),arrow(260,120,210,56),T(190,92,'事件发生',12,''),arrow(420,48,490,80))
**就绪**：什么都有，只差 CPU。**阻塞**：等某件事（I/O 完成、信号量），给它 CPU 也没用。
**运行→阻塞**是进程自己主动做的。**阻塞→就绪**是别人唤醒的。**运行→就绪**是被动的（时间片到、被抢占）。
**阻塞不能直接变运行**，**就绪不能直接变阻塞**。
:::

判断一个事件属于哪种转换，只问一句：**进程现在还能不能接着算？** 时间片用完，它能算，只是轮不到它，所以回就绪。等磁盘，它算不下去，所以阻塞。磁盘读完，它又能算了，但 CPU 不一定空，所以先回就绪，等调度。

=== 进程控制与组织
**原语**：不可被中断的一段程序，靠关中断或原子指令实现。创建、撤销、阻塞、唤醒都用原语，在内核态执行。

:::shu 创建和终止
**创建**：申请 PID 和 PCB → 分配资源 → 初始化 PCB → 插入就绪队列。
**引起创建**：用户登录、作业调度、提供服务、程序请求（`fork`）。
**fork 后**：子进程得到父进程地址空间的一份副本（[[34|写时复制]]），有自己的 PID。父子谁先运行不确定。`exec` 用新程序替换地址空间。
**终止**：正常结束、异常结束、外界干预。
:::

**组织**：相同状态的 PCB 串成[[04|队列]]（就绪队列、各种阻塞队列），或者用索引表。

:::recall 五态画出来，说出三个转换各由谁触发。
调度：就绪→运行。主动等事件：运行→阻塞。事件发生，被唤醒：阻塞→就绪。时间片到或抢占：运行→就绪。
:::

== 线程 {thread}
进程切换代价很大：要切页表、TLB 作废、Cache 里全是别人的数据。而且同一个应用里的多个任务（下载、渲染、响应点击）其实想共用数据，进程之间却隔离得严严实实。

所以把进程拆开：**资源归进程，执行归线程**。一个进程可以有多个线程，它们共享地址空间，各走各的。切换时只换寄存器和栈，不用换页表。

:::shu 进程 vs 线程
**进程**：资源分配的基本单位。**线程**：CPU 调度的基本单位。
**线程共享**：代码段、数据段、堆、打开的文件。
**线程私有**：PC、寄存器组、==栈==（含栈指针）、线程 ID、TCB。
同一进程内线程切换**不引起**进程切换，不切地址空间。
:::

为什么栈私有？每个线程在执行不同的函数调用链，局部变量和返回地址当然要各管各的。

:::trap 线程的栈
技术上，同一进程的线程在同一个地址空间，可以用指针碰到别的线程的栈。但默认的说法仍是「栈私有」，按这个判断。
:::

=== 线程的实现
谁来管线程？有两种答案。

@ table([['','用户级线程（线程库）','内核级线程（内核支持）'],['管理','用户空间的库','操作系统内核'],['切换','不进内核，快','要进内核'],['OS 感知','<b class="r">看不到</b>，只知道进程','有 TCB'],['调度单位','进程','线程'],['一个线程阻塞','<b class="r">整个进程阻塞</b>','其他线程继续跑'],['多核并行','不能','能']])

用户级线程一个进程阻塞全阻塞的原因：内核只看到一个进程，这个进程发起了阻塞的系统调用，内核就把整个进程挂起，根本不知道里面还有别的线程。

两者可以组合，用户线程映射到内核线程：

:::shu 三种多线程模型
**多对一**：多个用户线程映射到一个内核线程。切换快，但一个阻塞全部阻塞，不能并行。
**一对一**：每个用户线程一个内核线程。并发好，开销大（Linux 的做法）。
**多对多**：折中。
:::

:::recall 哪些东西线程共享，哪些私有？用户级线程为什么一个阻塞全阻塞？
共享地址空间内的东西和打开的文件；私有 PC、寄存器、栈。内核只看得见进程，一次阻塞调用把整个进程挂起。
:::

== 进程通信 {ipc}
进程地址空间互相隔离，你写的内存我读不到。所以进程要传数据，必须借助操作系统。

:::shu 四种通信方式
**共享内存**：两个进程映射同一块物理内存。之后直接读写，不再经过内核，所以==最快==；互斥同步要自己用 PV 做。
**消息传递**：`send` / `receive`，内核负责复制。可直接发给对方，也可间接经过**信箱**。不用共享，天然同步，但慢。
**管道**：内存中的一个固定大小的缓冲区，当文件操作。**半双工**，字节流，一端写一端读。满了写阻塞，空了读阻塞，所以它就是一个==有容量限制的生产者消费者==。读过的数据就没了，所以多个读者要小心。
**信号**：异步通知（比如 Ctrl+C）。发给进程后先挂起，进程从内核态返回用户态时检查并执行处理函数。只传一个信号编号，不传数据。
:::

:::recall 四种通信方式哪个最快？管道满了、空了分别怎么样？
共享内存最快。管道满时写阻塞，空时读阻塞。
:::

:::domain
**状态：**运行→阻塞是主动，阻塞→就绪被唤醒，时间片到回就绪。
**进程 = 资源单位，线程 = 调度单位。**
**栈私有**；用户级线程 OS 看不到、一个阻塞全阻塞。
**通信：**共享内存最快，管道半双工。
:::
