这是整个存储卷的汇合点。组原讲 Cache，操作系统讲页表，其实是同一次内存访问路上的两段。这一话把整条路走通，走通之后，所有这类分析都是这张图的子集。

== 一条路 {path}
CPU 发出的是虚拟地址，而 Cache 和主存认的是物理地址，所以先翻译，再访问。翻译靠页表，页表在主存里，为了不用每次跑一趟主存，再加一个专门缓存页表项的 TLB。于是：

 (flow([('虚拟地址','bx'),('TLB','bx'),('页表\n有效=0','rd'),('缺页异常\n调入页面','rd'),('重新执行\n本条指令','gd')],gap=22,size=12),'页表项有效位是 0，就是缺页。操作系统把页调入后，重新执行这条指令。'),
 (flow([('虚拟地址','bx'),('TLB','bx'),('页表','bx'),('物理地址\nTag|组|块内','gd'),('Cache','gd'),('主存','bx')],gap=22,size=12),'拿到物理地址后，==重新切一次==：标记、组号、块内。用物理地址查 Cache。'),
 (flow([('虚拟地址','bx'),('TLB','bx'),('页表','bx'),('物理地址','bx'),('Cache\n缺失','rd'),('主存\n取一块','gd')],gap=22,size=12),'Cache 缺失：从主存取一块进 Cache，然后完成访问。')],'一次内存访问的全过程')

:::shu 地址一共切两次
**第一次（虚拟地址）**：VPN | 页内偏移。偏移位数 = log₂(页大小)。
**第二次（物理地址）**：标记 | 组号 | 块内。
TLB 全相联时，整个 VPN 就是 TLB 标记；组相联时，VPN 再切成 TLB 标记 | TLB 组号。
:::

== 页表项和 TLB {tlb}
**页表项（PTE）** 至少有：实页号、**有效位**（在不在内存）。请求分页还有访问位、修改位、外存地址等，下一话讲。页表放在主存，由操作系统维护，每个进程一张。

**TLB**（快表）是页表项的专用 Cache，用 SRAM 做的相联存储器，容量很小（几十到几千项）。因为一页有几千字节，程序在同一页内的访问非常多，所以 TLB 只有几十项也能有很高的命中率。这还是局部性。

TLB 每一项存：VPN（作标记）、PPN、有效位等。全相联时比较全部项；组相联时用 VPN 低位选组。

@ table([['','TLB','Cache','页表'],['存什么','页表项（VPN→PPN）','主存块','VPN→PPN'],['用什么做','<b class="r">SRAM（相联）</b>','SRAM','主存 DRAM'],['缺失谁处理','硬件（或 OS）','硬件','缺页由 OS 处理'],['映射','全相联/组相联','三种都有','—']])

进程切换时，TLB 里存的是旧进程的映射，要清空（或者带上进程标识）。切换后最初的一段访问 TLB 全缺失，这是[[26|上下文切换]]的隐藏代价之一。

=== 三个部件的合法组合
TLB 是页表的子集，Cache 是主存的子集。由此直接推出：

@ table([['TLB','页表','Cache','可能吗','访存次数（一级页表，不含缺页处理）'],['命中','命中','命中','可能','0'],['命中','命中','缺失','可能','1（取块）'],['缺失','命中','命中','可能','1（页表）'],['缺失','命中','缺失','可能','2（页表、取块）'],['缺失','缺失','缺失','可能','缺页，处理后重来'],['命中','缺失','任意','<b class="r">不可能</b>','TLB 有的页一定在内存'],['任意','缺失','命中','<b class="r">不可能</b>','不在内存的页不会在 Cache']])

:::trap 什么是「不可能」
**TLB 命中，页表一定有效**：页换出时操作系统会让 TLB 里对应的项失效。
**页不在内存，Cache 里一定没有**：页换出时 Cache 里的相关块也要作废。
:::

:::recall 不看表，说出哪两种组合不可能，以及为什么。
TLB 命中但缺页：TLB 是页表的子集。缺页但 Cache 命中：Cache 是主存的子集。
:::

== 用真实数字走完全程 {walk}
假设：虚拟地址 32 位，物理地址 28 位，页 4 KB。TLB 共 64 项，4 路组相联。Cache 32 KB，4 路组相联，块 64 B。

**先定位数。**

- 页内偏移 12 位，所以 VPN 20 位，PPN 28−12 = 16 位。
- TLB 64 ÷ 4 = 16 组，组号 4 位，TLB 标记 20−4 = 16 位。
- Cache 共 32 KB ÷ 64 B = 512 行，512 ÷ 4 = 128 组，组号 7 位，块内 6 位，标记 28−13 = 15 位。

@ bits([('VPN：TLB 标记',16,'bk'),('TLB 组号',4,'gd'),('页内偏移',12)],cap='第一次切：虚拟地址 32 位')
@ bits([('PPN',16,'bk'),('页内偏移',12)],cap='翻译后：物理地址 28 位')
@ bits([('Cache 标记',15,'bk'),('Cache 组号',7,'gd'),('块内',6)],cap='第二次切：物理地址 28 位')

**再走地址。** 虚拟地址 0x12345ABC。

1. VPN = 0x12345，偏移 = 0xABC。
2. TLB 组号 = VPN 低 4 位 = 0x5，TLB 标记 = 0x1234。在第 5 组比较 4 项。
3. 假设 TLB 缺失。查页表，访存一次，读到有效位 1，PPN = 0x0A7C。填回 TLB。
4. 物理地址 = 0x0A7C 拼 0xABC = 0x0A7CABC。
5. 切物理地址：块内 = 低 6 位 = 60；组号 = 接下来 7 位 = 42；标记 = 0x53E。
6. 到 Cache 第 42 组比较 4 个标记。假设缺失：从主存读一块放入第 42 组，返回数据。

这一趟访存 2 次：页表一次，取块一次。

:::deep 为什么页表项放不放进 Cache 也有讲究
页表项本身也是主存里的数据，所以访问页表时，它也可能在 Cache 里命中。书上通常为了简化，默认页表访问直接算一次主存访问，以题目说明为准。
另外注意上面第 5 步：Cache 组号和块内共 13 位，比页内偏移的 12 位多一位。多出来这一位来自 PPN，所以必须等翻译完才知道组号，不能提前查。如果组号和块内不超过页内偏移，就可以边翻译边查 Cache。
:::

=== 时间怎么算
设 TLB 用 Tt，主存一次 Tm，缺页处理 Tp，不考虑 Cache：

:::shu 带 TLB 的访存时间
TLB 命中：`Tt + Tm`。
TLB 缺失，页在内存：`Tt + Tm（页表）+ Tm（数据）`，有时题目还给更新 TLB 的时间。
缺页：`Tt + Tm（页表）+ Tp + Tt + Tm（数据）`。末尾再来一遍 TLB 和数据，是因为==要重新执行这条指令==，此时 TLB 已经有了。
:::

代入 Tt = 10 ns，Tm = 100 ns，Tp = 1 ms。命中：110 ns。TLB 缺失：210 ns。缺页：10 + 100 + 1000000 + 10 + 100 = 1000220 ns。缺页比其他情况慢近一万倍，所以缺页率必须非常低。

:::recall 给定地址位数和 Cache 参数，默写出两次切分怎么算。
虚拟地址切 VPN | 偏移；物理地址切 标记 | 组号 | 块内；组号 = log₂(行数/路数)。两张草图都要画。
:::

== 段式和段页式虚拟存储器 {seg}
前面都是页式。**段式虚拟存储器**：按程序的逻辑段调入调出，段表记录段长、基址、是否在内存、是否修改等；虚拟地址 = 段号 + 段内偏移。段长不一，换入换出时会产生外部碎片。

**段页式虚拟存储器**：虚拟地址 = 段号 + 页号 + 偏移。先查段表得页表基址，再查页表得页框号。以页为单位调入。TLB 同样可以用在这里。

:::deep 反置页表
普通页表每个进程一张，按虚页号索引。**反置页表**整个系统只有一张，按物理页框索引，每项记录「这一页框里放的是哪个进程的哪一页」。表的大小只和物理内存有关，省空间，代价是查找要搜索，通常配散列加速。
:::

:::domain
**一条路：**VA → TLB → 页表 → PA → Cache → 主存。
**切两次：**VPN | 偏移；标记 | 组号 | 块内。
**不可能：**TLB 命中而缺页；缺页而 Cache 命中。
**缺页：**处理完重新执行本条，TLB 和数据再来一遍。
:::
