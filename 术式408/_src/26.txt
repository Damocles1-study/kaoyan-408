:::old
PCB 里至少有哪几类信息？ || 描述（PID）、控制管理（状态、优先级）、资源（页表、文件）、CPU 现场（PC、寄存器）。
时间片用完，进程进入什么状态？ || 就绪。阻塞是等事件时才进的。
线程私有什么？ || PC、寄存器、栈。
:::

:::say
就绪队列里排着好几个进程，CPU 只有一个。这一话讲两件事：**什么时候**可以换人，**换谁**。算法靠画甘特图，手算很轻松，重点是看清每种算法在照顾谁。
:::

== 三级调度 {levels}
调度发生在三个层面，从慢到快：

- **高级调度（作业调度）**：外存后备队列 → 内存，一个作业只调入一次。
- **中级调度（内存调度）**：内存不够时把进程换到外存（挂起），之后再换回。
- **低级调度（进程调度）**：就绪 → 运行。最频繁，每几十毫秒一次。

这一话说的调度，默认指最后一种。

:::shu 衡量好坏的指标
**周转时间** = 完成时间 − 到达时间。
**带权周转时间** = 周转时间 ÷ 服务时间（≥1）。
**等待时间** = 周转 − 服务（I/O 不计入等待时，还要减）。
**响应时间** = 首次得到 CPU − 到达。
**CPU 利用率** = 忙 ÷ 总。**吞吐量** = 完成数 ÷ 时间。
:::

带权周转把「等了多久」和「活有多长」放在一起看。同样等 10 分钟，1 分钟的活和 100 分钟的活感受完全不同。

== 调度的时机和方式 {when}
**调度时机**分两类：

:::shu 什么时候能调度
**要调度**：当前进程结束、阻塞；时间片用完；有更高优先级进程到达（抢占）。
**不能调度**：正在处理中断；执行原语；进程在==内核程序的临界区==中。
**普通临界区可以调度**：进程在用户程序的临界区（比如正在用打印机）时可以被抢占，只是别人进不了这个临界区。
:::

内核临界区不能切，因为它保护的是调度器自己要用的数据（比如就绪队列），切走会乱。打印机这种临界区要占用很久，如果不让调度，CPU 就白等了。

**非抢占式**：除非进程自己放弃，否则一直运行。**抢占式**：新来的更紧急就立刻换。

**闲逛进程**：就绪队列为空时运行它。优先级最低，只要有别的进程就绪就让出，不占资源，也可以让 CPU 降低功耗。它保证了 CPU 永远有事可做，调度器不用特判。

:::shu 上下文切换
**调度**是选一个；**切换**是实施。
**切换内容**：保存 PC、PSW、通用寄存器到 PCB；更新 PCB 状态并放入队列；选中新进程，加载它的现场；==切换地址空间（页表基址），TLB 随之作废==。
切换本身不做有用功，还让 TLB 和 Cache 失效。同一进程内的线程切换不用换地址空间，开销小得多。
:::

**调度程序（scheduler）** 由排队器、分派器、上下文切换器组成。排队器把就绪进程排好，分派器把选中的进程放上 CPU。

:::recall 为什么内核临界区不能调度，普通临界区可以？切换比线程切换多了什么？
内核临界区保护调度器自己要用的数据，普通临界区只是别人进不来。进程切换还要换页表、作废 TLB。
:::

== 算法 {algo}
下面所有例子用同一组进程，图都是按规则程序算出来的。

@ table([['进程','到达','服务'],['P1','0','7'],['P2','2','4'],['P3','4','1'],['P4','5','4']],mono=True)

=== FCFS 先来先服务
最简单：按到达顺序，一个做完再下一个。

@ sched([('P1',0,7),('P2',2,4),('P3',4,1),('P4',5,4)],'FCFS',cap='非抢占')

问题是短作业排在长作业后面要等很久。对长作业、CPU 繁忙型有利。

=== SJF 短作业优先
当前到达的进程里，选服务时间最短的。**非抢占**，已经在跑的会跑完。

@ sched([('P1',0,7),('P2',2,4),('P3',4,1),('P4',5,4)],'SJF',cap='非抢占。0 时刻只有 P1，所以 P1 先跑完')

=== SRTN 最短剩余时间优先
SJF 的抢占版本：每来一个新进程，比较它和当前进程的**剩余**时间。

@ sched([('P1',0,7),('P2',2,4),('P3',4,1),('P4',5,4)],'SRTN',cap='抢占。平均等待和周转时间最优')

:::trap SJF 和 SRTN 的问题
服务时间要预估，用户可能乱报。==长作业可能饥饿==：短作业一直来，长作业永远轮不到。
SJF 只有在所有进程同时到达时才保证平均周转最短；考虑不同时到达时，SRTN 才是真正的最优。
:::

=== HRRN 高响应比优先
怎么既偏向短作业，又让长作业等久了能轮到？把等待时间算进去。

:::shu HRRN 公式
`响应比 = (等待时间 + 服务时间) ÷ 服务时间`。
等待相同时，短的优先。服务相同时，等得久的优先。长作业等久了响应比一直涨，==不会饥饿==。非抢占。
:::

@ sched([('P1',0,7),('P2',2,4),('P3',4,1),('P4',5,4)],'HRRN',cap='非抢占。每次有进程完成时才重算响应比')

=== RR 时间片轮转
前面的算法都是给批处理设计的。交互系统要的是**响应快**：每个进程跑一小段，轮着来。

@ sched([('P1',0,7),('P2',2,4),('P3',4,1),('P4',5,4)],'RR',q=2,cap='时间片 2。同时发生时，新到达的进程先入队，用完时间片的再放队尾')

:::shu RR 的结论
时间片太大退化成 FCFS；太小切换开销占比太大。不会饥饿。
**到达和时间片到同时发生**：默认新进程先入队（题目另有说明除外）。
:::

=== 优先级与多级反馈
**优先级调度**：可以抢占或非抢占；优先级可以**静态**（不变，可能饥饿）或**动态**（等久了提高，防饥饿）。

**排序的常识**：系统进程高于用户进程，交互型高于批处理，==I/O 型高于 CPU 型==。原因是 I/O 型用一会儿 CPU 就去等 I/O 了，先让它用，既不占 CPU 多久，又让设备保持忙碌。

**多级反馈队列**：多个队列，优先级从高到低，时间片从短到长。

1. 新进程进第 1 级队列。
2. 用完时间片还没结束，掉到下一级。
3. 只有上一级队列空了，才运行下一级。
4. 高优先级来人时抢占，被抢的放回本级队尾。

这样短作业和 I/O 型在高层很快完成，长作业沉到底层，一次能跑很久。它不用事先知道服务时间，最全面；但如果一直有新进程来，底层的可能饥饿。

:::shu 算法总表
|算法|抢占|饥饿|照顾谁|
|FCFS|否|否|长作业、CPU 型|
|SJF / SRTN|否 / 是|是|短作业|
|HRRN|否|否|折中|
|RR|是|否|响应时间|
|优先级|都有|静态时会|紧迫的|
|多级反馈|是|是|综合最好|
:::

:::recall 不看书，说出每个算法：抢不抢占、会不会饥饿。
FCFS、SJF、HRRN 非抢占，SRTN、RR、多级反馈抢占。SJF、SRTN、静态优先级、多级反馈可能饥饿，FCFS、RR、HRRN 不会。
:::

=== 带 I/O 的情况
进程不是一直占着 CPU。遇到 I/O 就阻塞，CPU 转给别人，I/O 和 CPU 可以同时进行。这种情况要**画两条时间线**：一条 CPU、一条设备。

例：P1 计算 10 → I/O 20 → 计算 10；P2 计算 30。P1 先跑。0–10 P1 算；10–30 P1 在 I/O，CPU 给 P2；30 时 P1 回来了，非抢占的话 P2 接着跑到 40，P1 在 40–50 算完。总用时 50，CPU 没有闲过。如果两者串行要 70。这就是多道程序的好处。

== 多处理机和线程调度 {mp}
**用户级线程的调度**：操作系统只调度进程，进程内部线程由线程库决定。同一进程的线程切换不进内核。

**内核级线程的调度**：操作系统直接调度线程。如果切换的两个线程属于不同进程，就要切地址空间；同属一个进程就不用。

**多处理机调度**有两种：

- **公共就绪队列**：所有 CPU 从同一个队列取。天然负载均衡，但访问要互斥，而且进程容易换 CPU。
- **私有就绪队列**：每个 CPU 自己一个队列。进程留在原来的 CPU 上，**处理机亲和性**好（Cache 里还有它的数据）。但要主动做**负载均衡**：把忙的 CPU 上的进程迁到闲的 CPU（push 或 pull）。

:::domain
**指标：**周转 = 完成 − 到达；带权 = 周转 ÷ 服务。
**算法：**SRTN 周转最优、HRRN 折中不饥饿、RR 响应快、多级反馈最全面。
**不能调度：**中断处理、原语、内核临界区。
**切换代价：**进程切换要换页表，线程不用。
:::
