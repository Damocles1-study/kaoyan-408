:::say
调度算法是整个 408 手算最轻松的部分：画甘特图、算周转时间。但 2018 那种「把调度开销也算进去」的题要小心读。
:::

== 三级调度 {levels}
**高级（作业）调度**：外存→内存，从后备队列选作业，一个作业只调一次。**中级（内存）调度**：换入换出，提高内存利用率（挂起）。**低级（进程）调度**：就绪→运行，最频繁。

:::shu 指标（公式）
**周转时间** = 完成时间 − 到达时间。
**带权周转** = 周转时间 / 服务时间（≥1）。
**等待时间** = 周转 − 服务。
**响应时间** = 首次响应 − 到达。
**CPU 利用率** = 忙 / 总。**吞吐量** = 完成数 / 时间。
:::

== 调度的时机和方式 {when}
:::shu 什么时候可以调度
**可以调度**：进程结束、阻塞、时间片用完、新进程到（抢占）、优先级变化。
**不能调度**：处理中断时；原语执行中；在内核的**临界区**中（操作系统内核程序的临界区）。
注意，**普通临界区可以调度**：进程在用户程序的临界区（比如打印机）时也可以被抢占。
:::

@q os:2.2-41 | 进程在（普通）临界区也可以被调度，只是别的进程进不来。
@q os:2.2-46

**闲逛进程**：就绪队列为空时运行的，优先级最低，能耗低，不需要占其他资源。

:::shu 上下文切换
**调度**是选一个；**切换**是实施。切换要保存 PC、PSW、寄存器到 PCB，加载新进程，==切换地址空间（页表基址，TLB 失效）==。
切换本身有代价，太频繁得不偿失。线程切换（同一进程）不用切地址空间，所以开销小。
:::

@q os:2.2-47 | 三个进程依次运行，每次调度切换开销 1μs，计算等待：要把调度开销都加上。

=== HRRN 高响应比优先
@ sched([('P1',0,7),('P2',2,4),('P3',4,1),('P4',5,4)],'HRRN',cap='非抢占。响应比 =（等待 + 服务）/ 服务 ；两者折中，不会饥饿')

:::shu HRRN 公式
`响应比 = (等待时间 + 服务时间) / 服务时间`。
短作业优先、等久了也会轮到，==综合考虑等待和服务==。

=== RR 时间片轮转
@ sched([('P1',0,7),('P2',2,4),('P3',4,1),('P4',5,4)],'RR',q=2,cap='时间片 2。新到达的进程先入队，再把用完时间片的进程放到队尾')

=== 优先级与多级反馈
**优先级**：抢占或非抢占。**静态**或**动态**（等久了提高）。**系统进程高于用户进程，I/O 型高于 CPU 型**，因为 I/O 型用一会儿 CPU 就去等待了。

@q os:2.2-42 | I/O 比例越大的优先级越高。
@q os:2.2-38 | 时间片用完了，说明它是 CPU 型，降低它。

**多级反馈队列**：有好几个优先级不同的队列，高优先级时间片短；用完时间片还没结束就掉到下一级。兼顾短作业、I/O 型和长作业（综合最好），但低优先级可能饥饿。

:::shu 算法总表
|算法|抢占|饥饿|特点|
|FCFS|否|否|公平，不利短作业|
|SJF / SRTN|否 / 是|是|周转最短|
|HRRN|否|否|折中|
|RR|是|否|响应快|
|优先级|都有|是（静态）|紧迫优先|
|多级反馈|是|是|综合最好|
:::

== 多处理机调度与线程 {mp}
:::shu 其他调度知识点
**用户级线程调度**：OS 只调度进程，线程调度在进程内部（库做）；**内核级线程调度**：OS 直接调度线程。切换不同进程的线程时要切地址空间。
**多处理机**：**负载均衡**（各 CPU 忙闲相近，push/pull 迁移）；**处理器亲和性**（尽量留在原 CPU，Cache 还热）。公共就绪队列 vs 私有就绪队列。
:::

@q os:2.2-综10 | 第 1 问：静态优先数会饥饿。第 2 问：priority = nice + k₁×cpuTime − k₂×waitTime（优先数越小越优先），运行久了优先级降、等久了优先级升。这个公式就是考点。

:::domain
**指标：**周转 = 完成 − 到达；带权 = 周转/服务。
**算法：**SRTN 最优、HRRN 折中不饥饿、RR 响应快、多级反馈最全面。
**不能调度：**中断处理、原语、内核临界区。
**切换代价：**进程切换要换页表，线程不用。
:::
