死锁这节没有大题（0 道综合真题），全是选择题，且只有两样：==一个公式 + 一个算法==。练熟就是白拿分。

== 什么是死锁 {what}
一组进程都在等别人手里的东西。例如 P1 持有 A 等 B，P2 持有 B 等 A。

:::shu 四个必要条件（缺一不可）
**① 互斥**：资源不能共用。
**② 不可剥夺**：不能抢。
**③ 请求和保持**：拿着一个，还要别的。
**④ 循环等待**：等待关系成环。
:::

:::trap 三组容易混的词
**有环不一定死锁**：每类资源多于一个时，环只是必要条件。每类只有一个时才等价。
**不安全状态不一定死锁**：只是可能进入死锁。**死锁一定不安全**。
**饥饿不是死锁**：饥饿是单个进程长期等；死锁至少两个。
:::

== 公式：资源够不够 {formula}
:::shu 不死锁公式
n 个进程，每个最多要 k 个资源，资源总数 m：
==`m > n(k−1)` ⟺ 一定不死锁==
最危险的情况：每个人都拿到 k−1 个，就差一个。只要再多 1 个，就有人能完成。
需求各不相同（kᵢ）时：`m > Σ(kᵢ − 1)`，也就是 `m ≥ Σkᵢ − n + 1`。
:::

:::vow 三道真题全在等号上设坑
不死锁要求==严格大于==。「可能发生死锁的最小 K」和「确保不死锁的最小 m」差着这一个等号。
:::

@q os:2.4-34 | 8 > K×2 时一定不死锁，也就是 K ≤ 3。所以 K=4 开始可能死锁。
@q os:2.4-38 | Σ(kᵢ−1) = 2+3+4 = 9，n > 9，最小 10。

== 三种策略 {strategy}
@ table([['策略','做法','代价'],['预防','破坏四条件之一','严格，资源利用率低'],['避免','动态判断，不进入不安全状态（银行家）','需要知道最大需求'],['检测与解除','允许发生，事后处理','检测开销'],['鸵鸟','不管（Linux 常规用户级）','']])

:::shu 预防：破坏哪一条
**互斥**：把资源改为可共享（如 SPOOLing）。多数资源做不到。
**不可剥夺**：申请失败就放弃已有的。适合 CPU、内存，不适合打印机。
**请求和保持**：一次申请全部（静态分配）。资源浪费，可能饥饿。
**循环等待**：资源编号，==按编号递增申请==。编号要稳定，不便加设备。
:::

@q os:2.4-40 | 画「进程–资源」图找环：两个进程之间成不了环，P₁、P₂、P₃ 恰好能绕成一个环，所以至少 3 个。P₄ 只要一种资源，不在环上。
@q os:2.4-39 | 避免要总量信息（Ⅱ 对）；Ⅰ 中限制申请顺序的是预防，不是避免；Ⅲ S₁ 不会死锁、S₂ 可能。

== 银行家算法 {banker}
:::ana 贷款给你我要算账
银行家手里有一笔钱。答应客户前先算：如果借了，还能不能找到一个顺序让所有客户都把钱还回来？能就是**安全**，否则就不借。
:::

:::shu 四步
**① 检查** `Request ≤ Need`，否则出错（超过声明）。
**② 检查** `Request ≤ Available`，否则等待（==不用查安全性==）。
**③ 试探分配**：Available −= Request，Allocation += Request，Need −= Request。
**④ 安全性算法**：Work = Available，反复找 `Need ≤ Work` 的进程，让它跑完，`Work += Allocation`。全部能跑完才安全，不安全就回滚。
:::

:::trap 最大的坑
安全性算法中，完成后 `Work += Allocation`（它之前拿到的），而==不是加 Max==。2018 年选项 A/C 之争全在这里。
:::

**提速：集合推进法。** 找到能满足的就直接合入。推到天花板还谁都满足不了，就判不安全。

== 检测与解除 {detect}
**检测**：与安全性算法几乎相同，但把「Need」换成「当前的 Request」。**解除**：剥夺资源、撤销进程、进程回退（挂起）。

@q os:2.4-37 | 安全状态下，一定没有死锁。不安全不一定有死锁。
@q os:2.4-42 | Ⅲ 错：银行家算法判断的是安全不安全，不是死锁。

:::domain
**四条件：**互斥、不可剥夺、请求和保持、循环等待。
**公式：**m > n(k−1)；严格大于。
**银行家：**Request≤Need，≤Available，试探，安全性；Work += Allocation。
**不安全 ≠ 死锁；有环 ≠ 死锁。**
:::
