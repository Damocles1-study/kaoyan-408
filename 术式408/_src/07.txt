n 个结点的二叉链表有多少空指针？ || n+1。
能唯一确定二叉树的序列组合？ || 必须有中序。先序加后序不行。

这一话四件事都是树的变形，每一件都有一招：线索化把空指针用起来，孩子兄弟法把任意树变成二叉树，哈夫曼贪心，并查集用树表示集合。

== 线索二叉树 {thread}
遍历是把树变成序列，但每次都要从头走才知道前驱后继。上一话说 n 个结点的二叉链表有 n+1 个空指针。线索化就是废物利用：**空的左指针指向遍历前驱，空的右指针指向遍历后继**。为了区分指向的是孩子还是线索，每个结点加两个标记位 ltag、rtag（1 表示线索）。

这样找中序后继时：若 rtag=1 直接跟线索走；否则后继是右子树最左下的结点。不用栈就能遍历。

@ thread_fig('A(B(,D),C)')

:::shu 怎么做线索题
1. 把这棵树的遍历序列写出来（题目问哪种就写哪种）。
2. 只看**空指针**：左空指向序列中的前一个，右空指向序列中的后一个。
3. 序列的第一个没有前驱、最后一个没有后继，线索为 NULL。
:::

:::trap 后序线索树不能完全解决「找后继」
中序线索树能直接找前驱和后继；先序线索树找后继容易、找前驱难；**后序线索树找后继仍然需要栈**（或父指针），因为后继可能是父结点，而结点里没有父指针。
:::

:::recall 线索指向什么？ltag 为什么要有？哪种线索树找后继还需要栈？
空左指针指前驱，空右指针指后继。ltag 区分是孩子还是线索。后序线索树。
:::

== 长子兄弟法：一招通吃 {forest}
:::ana 家谱改造
一个家长可以有很多孩子，但二叉树只有两只手。规定：==左手牵大儿子，右手牵自己的下一个弟弟==。这样任何树都能变成二叉树。
:::

树的三种存储，各有所长：

- **双亲表示法**：数组里存父亲下标。找父亲快，找孩子要遍历。并查集用它。
- **孩子表示法**：每个结点挂一串孩子链表。找孩子快，找父亲慢。
- **孩子兄弟表示法**：二叉链表，左指针指第一个孩子，右指针指下一个兄弟，也就是上面的法子。操作方便，占用少。

**森林转二叉树**：每棵树转成二叉树，再把后一棵的根作为前一棵根的右孩子（各棵树的根互为兄弟）。**逆向**：二叉树的根的右链断开，得到各棵树的根。

:::shu 森林 / 树 / 二叉树的遍历对应
|树|森林|二叉树|
|先根|先序|先序|
|后根|中序|中序|
只有这两组，==没有后序的对应==。
:::

:::shu 数量对应
**森林的叶子数** = 对应二叉树中「左指针为空」的结点数（没孩子 ⟺ 没长子）。
**二叉树中右指针为空的结点数** = 非终端结点数 + 1（每个有孩子的家长，其最小孩子没有弟弟；再加上最后一棵树的根）。
:::

**树的遍历**：**先根**：先根后子树，和对应二叉树的先序相同。**后根**：先子树后根，和对应二叉树的**中序**相同。这和上表一致。遍历森林时，先序就是逐棵树先根，中序就是逐棵树后根。

== 哈夫曼树 {huff}
通信时希望高频字符编码短，让总长度最小。一棵二叉树的叶子代表字符，从根到叶子的路径代表编码，总编码长度就是**带权路径长度 WPL** = Σ(叶子权值 × 根到它的边数)。

让 WPL 最小的树叫**哈夫曼树**。做法是贪心：每次取最小的两个合并，和作为新结点放回去，重复。例如权值 {1,2,4,5}：1+2=3；3+4=7；7+5=12。WPL = 5×1 + 4×2 + 2×3 + 1×3 = 22。

:::shu 哈夫曼三条
1. **n 个叶子，总共 2n−1 个结点**，没有度为 1 的结点（因为每次合并新增 1 个，合并 n−1 次）。
2. **权越小离根越远**；最小的两个一定是兄弟。
3. **不唯一**（左右可换、权相等时选法不同），但 ==WPL 唯一==。
**m 叉哈夫曼树**：要补 0 权虚结点让 `(n−1) % (m−1) == 0`，否则根不满。
:::

@ huff_steps([5,9,12,13,16,45])

~~前缀编码~~：任何一个编码都不是另一个的前缀，这样译码才唯一。比如 A=0，B=01 就不行：看到 0 不知道是 A 还是 B 的开头。哈夫曼树的左 0 右 1 天然保证这一点，因为所有字符都在叶子上。编码长度不一定唯一（权相等时），但总长度（WPL）唯一。

== 并查集 {uf}
解决「这两个元素是不是一个集合的」，并支持合并。用树表示集合，树根就是集合的代表。用**双亲表示法**：`S[x]` 存父亲下标，根存负数（绝对值是集合大小）。

走一遍：`S = [-1,-1,-1,-1]`。`Union(0,1)`：两个根大小相同，后者并入前者（代码里是 r2 指向 r1 还是相反，看比较）。`Union(2,3)`、`Union(0,2)` 后四个元素同一集合。`Find` 时沿 S[] 一路向上到负数。路径压缩把路过的结点都直接挂到根下，下次就一步到位。

:::code c 模板：并查集（按大小合并 + 路径压缩）
int Find(int S[], int x) {
    int root = x;
    while (S[root] >= 0) root = S[root];
    while (x != root) {            // 路径压缩：沿路都直接指向根
        int t = S[x]; S[x] = root; x = t;
    }
    return root;
}
void Union(int S[], int a, int b) {
    int r1 = Find(S, a), r2 = Find(S, b);
    if (r1 == r2) return;
    if (S[r2] > S[r1]) {           // 根存负的大小，r1 的集合更大
        S[r1] += S[r2]; S[r2] = r1;
    } else {
        S[r2] += S[r1]; S[r1] = r2;
    }
}
:::

:::shu 并查集的复杂度
无优化：Find 最坏 O(n)。按大小合并：树高不超过 ⌊log₂n⌋+1，Find O(log n)。再加路径压缩：几乎 O(1)（α(n)）。
:::

:::link 并查集的三个应用
判断无向图连通分量数；[[10|Kruskal]] 判断加边是否成环；判断两个元素是否等价。
:::

:::recall 哈夫曼树有多少结点？m 叉时要补什么？并查集为什么要按大小合并？
2n−1。补 0 权虚结点使 (n−1)%(m−1)=0。让树矮，查找到根更快。
:::

:::domain
**线索：**写出序列，只管空指针。
**转换：**左长子、右兄弟；后根 = 中序。
**哈夫曼：**2n−1 个结点，WPL 唯一。
**并查集：**S[x]<0 是根，按大小并 + 路径压缩。
:::
