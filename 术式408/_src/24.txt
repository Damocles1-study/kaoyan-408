== OS 是什么 {what}
OS 管理硬件和软件资源，为用户提供接口。

:::shu 四个特征
**并发**：宏观同时，微观交替（单核）。**共享**：互斥共享、同时共享。**虚拟**：时分（虚拟 CPU）、空分（虚拟内存）。**异步**：走走停停，不可预知。
**并发和共享互为前提**，是最基本的两个特征。
:::

:::trap 并发不是并行
并发：一段时间内多个任务都在推进。并行：同一时刻多个任务同时运行（需要多核）。单核只有并发，没有并行。
:::

:::shu 多道程序的优点
CPU 利用率高、吞吐量大、I/O 设备利用率高。==代价==：系统开销变大、单个作业周转可能变长。
:::

== 体系结构 {arch}
@ table([['结构','思路','优点','缺点'],['分层','每层只用下一层','易调试、验证','定义层难；效率低'],['模块化','按功能分模块','灵活','模块间依赖乱'],['宏内核','所有功能在内核','<b class="r">性能高</b>','庞大、一个错全崩'],['微内核','内核只留最基本（进程、低级 I/O、IPC），其余放用户态','可靠、易扩展、适合分布式','<b class="r">频繁切换，性能低</b>'],['外核','内核只负责分配硬件资源，由应用自己管理（库 OS）','灵活、高效','实现复杂']])

:::shu 微内核的四个基本功能
进程（线程）管理、低级存储器管理、中断和陷入处理、进程通信。**服务器以用户态运行，通过消息传递通信。**
:::

== 引导 {boot}
@ flow([('上电\nCPU 执行 ROM','bx'),('BIOS 自检\nPOST','bx'),('读 MBR\n第一个扇区','gd'),('活动分区\n引导扇区','bx'),('加载 OS\n到内存','bk')],gap=24,cap='操作系统引导的主线')

:::shu 引导要记
BIOS 放在 ROM，不易失；OS 放在硬盘；启动完成后 OS 在 RAM。
MBR 包含引导代码和分区表，位于磁盘第一个扇区。
:::

== 虚拟机 {vm}
:::shu 两类虚拟机
**第一类（裸金属）**：Hypervisor 直接跑在硬件上，运行在最高特权级，性能好。虚拟机里的 OS 以为自己在内核态，其实是用户态，特权指令被捕获后模拟（陷入并模拟）。
**第二类（寄居）**：Hypervisor 作为应用跑在宿主 OS 上（如 VMware Workstation、VirtualBox），性能差。
**虚拟内核态**：虚拟机内部的 OS 看到的内核态，其实硬件上是用户态。
:::

:::domain
**四特征：**并发、共享、虚拟、异步。
**多道：**CPU 和设备利用率高，无交互。分时：有交互。实时：讲截止。
**结构：**宏内核性能好，微内核可靠但切换多，外核管分配。
**引导：**ROM→BIOS→MBR→分区引导→OS。
:::
