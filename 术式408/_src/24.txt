:::old
PC、PSW 由谁保存？通用寄存器由谁保存？ || PC、PSW 硬件保存；通用寄存器 OS 保存。
用户态到内核态的唯一途径？ || 中断或异常，包括 trap。

上一话讲完了操作系统最核心的机制。这一话把骨架搭起来：它是什么、怎么发展来的、内部怎么组织、怎么启动。内容不难，读一遍就够。

== 操作系统是什么 {what}
操作系统管理硬件和软件资源，并为用户提供接口。接口有两种：**命令接口**（给人用，Shell、图形界面）和**程序接口**（给程序用，系统调用）。

:::shu 四个特征
**并发**：宏观同时，微观交替（单核）。**共享**：互斥共享、同时共享。**虚拟**：时分（虚拟 CPU）、空分（虚拟内存）。**异步**：走走停停，不可预知。
**并发和共享互为前提**，是最基本的两个特征。
:::

:::trap 并发不是并行
并发：一段时间内多个任务都在推进。并行：同一时刻多个任务同时运行（需要多核）。单核只有并发，没有并行。多任务操作系统不一定要多 CPU。
:::

== 发展历程 {hist}
每一步都是为了解决上一步的毛病：单道批处理让 CPU 等 I/O，所以有了多道；多道没有交互，所以有了分时；分时响应不够确定，所以有了实时。

@ table([['类型','特点','缺点'],['单道批处理','自动、顺序、单道','CPU 闲置'],['<b class="r">多道批处理</b>','内存有多道程序，宏观并行、微观串行','<b class="r">无交互</b>、平均周转长'],['分时','时间片轮转，交互、独占感','不能处理紧急事件'],['实时','截止时间内必须响应（硬/软实时）','资源利用率低'],['网络/分布式','网络 OS 资源共享；分布式透明','—']])

:::shu 多道程序的优点
CPU 利用率高、吞吐量大、I/O 设备利用率高。==代价==：系统开销变大、单个作业周转可能变长。
:::

== 体系结构 {arch}
内核代码怎么组织？有两个问题：放多少在内核里，内部怎么分块。

@ table([['结构','思路','优点','缺点'],['分层','每层只用下一层','易调试、验证','定义层难；效率低'],['模块化','按功能分模块','灵活','模块间依赖乱'],['宏内核','所有功能在内核','<b class="r">性能高</b>','庞大、一个错全崩'],['微内核','内核只留最基本的，其余放用户态','可靠、易扩展、适合分布式','<b class="r">频繁切换，性能低</b>'],['外核','内核只负责分配硬件资源，由应用自己管理','灵活、高效','实现复杂']])

:::shu 微内核的四个基本功能
进程（线程）管理、低级存储器管理、中断和陷入处理、进程通信。**服务器以用户态运行，通过消息传递通信。**
:::

微内核慢的原因：文件系统也在用户态，一次读文件要在用户态和内核态之间来回好几次。

== 引导 {boot}
内存通电后是空的，CPU 从哪开始？从固定地址的 ROM。

@ flow([('上电\nCPU 执行 ROM','bx'),('BIOS 自检\nPOST','bx'),('读 MBR\n第一个扇区','gd'),('活动分区\n引导扇区','bx'),('加载 OS\n到内存','bk')],gap=24,cap='操作系统引导的主线')

:::shu 引导要记
BIOS 放在 ROM，不易失；OS 放在硬盘；启动完成后 OS 在 RAM。
MBR 包含引导代码和分区表，位于磁盘第一个扇区。
:::

== 虚拟机 {vm}
一台物理机上同时跑多个操作系统。管理它们的那层软件叫 **Hypervisor**（虚拟机管理程序）。

:::shu 两类虚拟机
**第一类（裸金属）**：Hypervisor 直接跑在硬件上，运行在最高特权级，性能好。虚拟机里的 OS 以为自己在内核态，其实是用户态，特权指令被捕获后模拟（陷入并模拟）。
**第二类（寄居）**：Hypervisor 作为应用跑在宿主 OS 上（如 VMware Workstation、VirtualBox），性能差。
**虚拟内核态**：虚拟机内部的 OS 看到的内核态，硬件上其实是用户态。
:::

:::recall 操作系统四特征？宏内核和微内核谁快，为什么？
并发、共享、虚拟、异步。宏内核快，微内核的服务在用户态，要频繁切换。
:::

:::domain
**四特征：**并发、共享、虚拟、异步。
**多道：**CPU 和设备利用率高，无交互。分时：有交互。实时：讲截止。
**结构：**宏内核性能好，微内核可靠但切换多，外核管分配。
**引导：**ROM→BIOS→MBR→分区引导→OS。
:::
