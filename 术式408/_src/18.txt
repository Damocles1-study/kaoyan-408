== 浮点的结构 {struct}
`N = (−1)^S × M × 2^E`。和科学计数法一样，只是底数是 2。阶码 E 决定范围，尾数 M 决定精度。

**规格化**：为了让表示唯一，也为了多存有效位，规定尾数最高位是 1，也就是写成 `1.xxx × 2^E` 的形式。既然总是 1，就不用存，这一位叫**隐藏位**，于是 23 位的尾数实际上有 24 位精度。

@ bits([('S',1,'rd'),('阶码（移码）8 位',8,'bk'),('尾数 23 位（隐含 1.）',23)],cap='float：1 + 8 + 23 = 32 位。double：1 + 11 + 52 = 64 位')

:::shu IEEE 754 单精度
|项目|float|double|
|偏置值|127|1023|
|规格化真值|(−1)^S × 1.f × 2^(e−127)|(−1)^S × 1.f × 2^(e−1023)|
|e 全 0（非规格化）|±0.f × 2⁻¹²⁶，含 ±0|±0.f × 2⁻¹⁰²²|
|e 全 1|f=0 是 ±∞，f≠0 是 NaN|同左|
|最大正数|`(2−2⁻²³) × 2¹²⁷`，7F7F FFFFH|(2−2⁻⁵²)×2¹⁰²³|
|最小规格化正数|`1.0 × 2⁻¹²⁶`，0080 0000H|1.0×2⁻¹⁰²²|
:::

:::trap 偏置值不是 128
IEEE 754 的移码偏置是 127，和普通移码的 128 不同。所以阶码 e 的实际范围是 1~254，对应指数 −126~+127。全 0 和全 1 留作特殊用途。
:::

**为什么要非规格化数**：规格化的最小正数是 2⁻¹²⁶，再小就是 0，中间有个断崖。阶码全 0 时规定隐藏位是 0、指数固定为 −126，用来表示接近 0 的很小的数，让小数可以平滑地趋向 0。

:::shu 手转三步（十进制 → 位模式）
1. **写成二进制**并规格化：`−6.5 = −110.1B = −1.101 × 2²`。
2. **算三段**：S=1；e = 2+127 = 129 = 1000 0001；f = 101 后面补 0。
3. **四位一组**：1100 0000 1101 0000… = C0D0 0000H。
:::

@ ieee(-6.5)

反过来读也一样：`C1A0 0000H` = 1100 0001 1010 0000…，S=1，e = 1000 0011 = 131，指数 4，f = 01，值 = −1.01B × 2⁴ = −10100B = −20。

:::recall 不看书，把 −6.5 转成十六进制位模式。隐藏位是什么意思？
−1.101×2²；S=1，e=129，f=101…；C0D00000H。规格化后最高位总是 1，不存，所以 23 位尾数有 24 位精度。
:::

== 精度与类型转换 {prec}
float 有 24 位有效数字（含隐藏位）。超过就要舍入，可能丢。而且相邻 float 的间距随数变大而变大：2²⁴ 以上连奇数都表示不出来。这里也解释了为什么 float 能表示的最大整数是 `(2−2⁻²³)×2¹²⁷ = 2¹²⁸ − 2¹⁰⁴`。

:::shu 转换谁会丢精度
**int → float**：可能丢（int 有 31 位有效，float 只有 24 位）。
**int → double**：不丢。**float → double**：不丢。
**float/double → int**：小数被截掉，可能溢出。
**double → float**：可能丢，可能溢出。
**大数吃小数**：`(d+f)−d` 不一定等于 f。
:::

== 浮点加减 {add}
:::shu 五步（顺序固定）
**① 对阶**：小阶向大阶看齐，小阶尾数右移（精度损失最小）。
**② 尾数相加减**。
**③ 规格化**：尾数溢出右规（阶码 +1），绝对值太小左规（阶码 −1）。
**④ 舍入**：0 舍 1 入或恒置 1，可能再触发规格化。
**⑤ 判溢出**：阶码上溢才是真溢出，阶码下溢当作机器零。
:::

走一遍：计算 `1.5 + 0.25`，用十进制指数看，尾数用二进制。

1. 写成 `1.1B × 2⁰`、`1.0B × 2⁻²`。
2. **对阶**：小阶看齐大阶，`1.0B × 2⁻²` 变成 `0.01B × 2⁰`（尾数右移两位，低位可能丢）。
3. **尾数相加**：1.10 + 0.01 = 1.11。
4. **规格化**：已经是 1.xx，不用动。结果 `1.11B × 2⁰` = 1.75。

如果尾数相加得 `10.11B`，就**右规**一位，阶码 +1。如果相减得 `0.001B`，就**左规**三位，阶码 −3。

**舍入**：对阶和右规时移出的位要处理。IEEE 754 默认就近舍入。舍入后尾数可能再次溢出，要再次规格化。

为什么小阶看大阶？小阶右移，丢的是最低位，影响小。如果大阶看小阶，要把最高位移出去，整个数就错了。

:::trap 溢出的判据
**尾数溢出不一定结果溢出**，右规后能救回来。真正溢出看阶码。对阶不会引起阶码溢出。阶码上溢是真溢出，阶码下溢当作机器零。
:::

== 对齐与大小端 {layout}
**大端**：最高字节放低地址（书写顺序）。**小端**：最低字节放低地址（x86）。

@ svg(560,120,T(55,20,'0x12345678',13,'',w=800),T(30,55,'大端',13,'rdt'),*[box(70+i*50,38,50,30,t,'bx') for i,t in enumerate(['12','34','56','78'])],T(30,95,'小端',13,'rdt'),*[box(70+i*50,78,50,30,t,'gd' if i==0 else 'bx') for i,t in enumerate(['78','56','34','12'])],T(320,55,'地址从左到右递增',12,'mt',a='start'),T(320,95,'小端：低地址放低字节',12,'rdt',a='start'),cap='同一个 int 的两种放法')

:::shu 结构体对齐规则
1. 每个成员的地址必须是自己大小的整数倍。
2. 整个结构体大小必须是最大成员大小的整数倍。
3. 成员顺序影响大小。`char+int+short`（1+3 空+4+2+2 空 = 12）比 `int+short+char`（4+2+1+1 空 = 8）费空间。
:::

@ mem([('int a（4 字节）','bk','C008'),('char b + 1 字节空 + short c','gd','C00C')],w=300,cap='struct{int a; char b; short c;} 从 C008 开始：b 在 C00C，c 在 C00E，共 8 字节')

**为什么要对齐**：CPU 按总线宽度成块读。如果 int 跨了两个 4 字节单元，就要访存两次并拼接。对齐是用一点空间换时间。

算地址：小端、结构体同上，a = 0x00000111。则 C008 放 11，C009 放 01，C00A、C00B 放 00。

:::recall 结构体大小怎么算？小端和大端差在哪？
每个成员放在自身大小的整数倍地址，末尾补到最大成员的倍数。小端低字节放低地址，大端低字节放高地址。
:::

:::domain
**754：**1.f × 2^(e−127)，手转三步。
**精度：**24 位，int→float 可能丢，大数吃小数。
**加减五步：**对阶小向大，真溢出看阶码。
**对齐：**成员对齐到自身大小，总大小对齐最大成员。**小端：**低地址放低字节。
:::
