单总线为什么要暂存器 Y 和 Z？ || 一个周期只能走一个数：ALU 要两个输入，所以 Y 存一个；结果不能和操作数同周期上总线，所以 Z 存结果。
指令周期的四个阶段？ || 取指、间址、执行、中断。

:::say
上一话一条指令做完才开始下一条。洗衣服如果一批洗完烘完叠完才开始下一批，机器大部分时间都在等。流水线让每个环节都同时有活干，==每个周期出一条指令==，代价是带来三种冒险。
:::

== 基本概念 {base}
把指令执行切成几段，每段一个时钟周期。经典 5 段：

- **IF** 取指：用 PC 读指令，PC+4。
- **ID** 译码：译码，读寄存器。
- **EX** 执行：ALU 运算（或算地址）。
- **MEM** 访存：Load/Store 读写内存。
- **WB** 写回：结果写寄存器。

每段之间有**段寄存器**（流水寄存器），把上一段的结果传给下一段。所有指令都走同样的段数：运算指令的 MEM 段空转，存数指令的 WB 段空转。

@ pipe([('I1',['IF','ID','EX','MEM','WB'],1),('I2',['IF','ID','EX','MEM','WB'],2),('I3',['IF','ID','EX','MEM','WB'],3),('I4',['IF','ID','EX','MEM','WB'],4)],'时空图：第 5 个周期之后每周期完成一条')

每条指令的时间没有变短，甚至更长了，但单位时间完成的指令多了。

:::shu 流水线指标（k 段、n 条、周期 Δt）
**总时间** `T = (k + n − 1)Δt`。
**吞吐率** `TP = n / T`，理想最大 1/Δt。
**加速比** `S = n·k·Δt / T`，n 很大时趋近 k。
**效率** `E = S / k`。
**时钟周期** = ==最慢段的时间 + 段寄存器延迟==。
:::

算一遍：四段时间 40、60、30、50 ns，段寄存器 10 ns。周期 Δt = 60 + 10 = 70 ns。5 段 Δt = 2 ns、100 条指令时：T = (5+99)×2 = 208 ns，TP = 100/208 ≈ 0.48 条/ns，S = 100×5×2/208 ≈ 4.8，E ≈ 0.96。

**适合流水线的指令系统**：指令定长、格式规整（译码快）；只有 Load/Store 访存（访存只在一段）；数据对齐（一次访存就够）。这就是 RISC。

:::recall 总时间公式？时钟周期由什么决定？n 很大时加速比趋近多少？
`(k+n−1)Δt`；最慢段 + 段寄存器；趋近 k。
:::

== 三种冒险 {hazard}
冒险（hazard）就是==下一条指令不能在下一个周期开始==。

:::ana 三种情况
**结构冒险**：两个人抢一台机器。**数据冒险**：我要的东西你还没做出来。**控制冒险**：还不知道下一步往哪走。
:::

=== 结构冒险
硬件资源不够。比如取指（IF）和访存（MEM）在同一周期都要用存储器。解决：**指令 Cache 和数据 Cache 分离**。

=== 数据冒险
主要是写后读（RAW）：后一条的源寄存器，是前面还没写回的目的寄存器。

@ pipe([('add R1,R2,R3',['IF','ID','EX','MEM','WB'],1),('sub R4,R1,R5',['IF','*','*','ID','EX','MEM','WB'],2)],'不转发：要等前一条 WB。假定 WB 前半周期写、ID 后半周期读，第 5 周期两者可同时进行，阻塞 2 个周期')

:::shu 数据冒险三种解法
**① 阻塞**：插 nop 或由硬件停顿。简单，慢。
**② 转发（旁路）**：把 EX 或 MEM 段已经算出来的结果，直接送到 ALU 入口，不等写回。运算指令一般不用再阻塞。
**③ 编译器重排**：把无关的指令调到中间。
**Load-use 特例**：`load R1` 后紧跟使用 R1，==转发也要阻塞 1 个周期==，因为 MEM 结束才有数据，而下一条的 EX 已经要用了。
:::

用具体序列判断（无转发，WB 前半写、ID 后半读）：

|指令|目的|源|要等谁|
|`I1 add R1,R2,R3`|R1|R2,R3|无|
|`I2 sub R4,R1,R5`|R4|R1,R5|I1，距离 1，阻塞 2|
|`I3 and R6,R1,R7`|R6|R1,R7|I1，I2 阻塞后距离够了，不用再等|
|`I4 or R8,R2,R4`|R8|R2,R4|I2，距离 2，阻塞 1|

:::flash 判定数据冒险
**看每条的源寄存器是否是前面还没写回的目的寄存器。** 无转发、WB 前半写时，距离 ≥ 3 条就安全。
:::

=== 控制冒险
转移指令要到 EX（或更晚）才知道转不转、转去哪，但下一个周期就要取指了，取哪条？

:::shu 控制冒险的处理
**① 阻塞**：等分支结果出来。在 EX 段出结果就损失 2 个周期；在 MEM 段损失 3 个。
**② 提前判断**：把比较放在 ID 段，只损失 1 个周期。
**③ 分支预测**：**静态**（比如总预测不转移）；**动态**（根据历史，循环命中率很高）。
**④ 延迟槽**：转移指令后一条总是执行（MIPS）。
预测错了要**清空**已经进入流水线的指令。
:::

:::recall 三种冒险各用什么解决？转发能解决所有数据冒险吗？
结构：分离 Cache。数据：阻塞、转发、重排。控制：提前判断、预测、延迟槽。不能，load-use 仍要阻塞 1 周期。
:::

== 高级流水线 {adv}
普通流水线理想 CPI = 1。想再快，要么一个周期干更多条，要么把周期切更短。

:::shu 超标量 / 动态
**超标量**：多条流水线，==一个周期发射多条指令==，CPI 可小于 1。功能段时间不缩短。靠硬件判断哪些指令能同时发。
**超流水**：把一段再切成更多小段，提高主频。
**超长指令字 VLIW**：由编译器把多条指令打包成一条。
**动态流水线**：硬件调度，可以**乱序执行**，**顺序提交**。指令被某操作数卡住时，后面无关的指令可以先走。
:::

== 多处理器 {mp}
**Flynn 分类**按指令流和数据流的数目：

:::shu Flynn 分类
**SISD**：单指令流单数据流，普通单核，可以用流水线。
**SIMD**：一条指令处理多个数据（向量运算、GPU）。
**MISD**：现实中几乎没有。
**MIMD**：多核、多处理器。
:::

|概念|一句话|要点|
|**向量处理器**|SIMD 的代表|专做数组运算，一条指令算一整个向量|
|**硬件多线程**|一个核维护多套 PC 和寄存器|**细粒度**：每周期切换；**粗粒度**：遇到长阻塞才切；**同时多线程** SMT：一周期内发多线程的指令|
|**多核**|一块芯片多个核|共享 L3 和主存（常见）|
|**SMP**|共享内存多处理器|所有处理器地址空间相同、访问对等（UMA）；需要 Cache 一致性|

硬件多线程和操作系统的线程不是一回事：前者是 CPU 怎么在硬件上切换，切换几乎没有开销；后者是调度器的工作。

:::domain
**指标：**T=(k+n−1)Δt，周期按最慢段 + 寄存器延迟。
**冒险：**结构（分离 Cache）、数据（转发，load-use 仍阻 1）、控制（预测、flush）。
**超标量：**一周期发多条，不缩短每段时间。
**分类：**向量=SIMD，多核=MIMD。
:::
