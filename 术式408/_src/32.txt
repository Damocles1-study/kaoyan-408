== 程序怎样变成内存里的东西 {load}
源程序经过三步才能跑起来：

1. **编译**：源文件变成目标模块。每个模块的地址都从 0 开始，这叫**逻辑地址**（相对地址）。
2. **链接**：把目标模块和库函数合在一起，形成统一的逻辑地址空间。
3. **装入**：把程序放进内存，这时才碰到**物理地址**（内存单元的真实地址）。

问题来了：程序里写的地址是从 0 算的，而它实际被放到了别处，地址什么时候换算？

:::shu 三种装入
**绝对装入**：编译时就算好物理地址。只适合单道程序。
**静态重定位**（可重定位装入）：装入时一次性改掉所有地址。装入后不能再移动，而且要一次分够全部内存。
**动态重定位**（动态运行时装入）：运行到那条指令时才转换，==靠重定位寄存器==。程序可以被移动，能分散放，是现代系统的方式。
:::

:::shu 三种链接
**静态链接**：运行前就合成一个文件。
**装入时动态链接**：边装入边链接。
**运行时动态链接**：用到某模块才链接。省内存，也便于共享和更新。
:::

=== 进程的内存映像
一个进程在内存里（逻辑上）长这样：

@ mem([('内核','tn','高地址'),('用户栈（向下长）','gd'),('共享库映射区'),('堆（向上长）','bu'),('未初始化数据 .bss'),('已初始化数据 .data'),('只读代码 .text','bk','低地址')],w=280)

- **代码段** `.text`：指令，只读，多个进程可以共享。
- **数据段** `.data`、`.bss`：全局和静态变量。
- **堆**：`malloc` 分配，向高地址长。
- **栈**：局部变量、函数调用，向低地址长，[[20|第 20 话]]讲过。

堆和栈之间那一大片目前都没用。这就是后面虚拟内存的发力点：没用到的地方不用占物理内存。

=== 内存管理要做的四件事
**分配与回收**（后面两节）；**地址转换**（上面的重定位）；**内存保护**；**内存共享**。

**保护**：进程不能访问别人的区域。两种做法：① 上、下限寄存器，地址要落在两者之间；② **重定位寄存器（基址）+ 界地址寄存器（长度）**：先判断 `逻辑地址 < 界地址`，再加基址，越界就产生中断。这两个寄存器只有内核能改。

**共享**：纯代码（**可重入代码**，运行时不修改自己）可以被多个进程映射到同一块物理内存。

**内存不够时的早期办法**：**覆盖**由程序员把程序分段，常用的留在内存，不常用的轮流占同一块区域。**交换**把整个进程换到外存（中级调度，[[26]]）。交换的是整个进程，后面讲的请求分页换的是页。

:::recall 静态重定位和动态重定位差在哪？界地址寄存器和基址寄存器怎么配合？
静态在装入时一次改完，之后不能移动。动态在运行时靠重定位寄存器转换，可以移动。逻辑地址先和界地址比，不越界再加基址。
:::

== 连续分配 {cont}
最朴素的想法：给每个进程一整段连续内存。

@ table([['方式','做法','碎片'],['单一连续','内存只放一个用户程序','内部碎片'],['固定分区','预先切好若干分区，大小可不同','<b class="r">内部碎片</b>'],['动态分区','进程来了按需切','<b class="r">外部碎片</b>']])

**内部碎片**：分给你的区域内，你用不完的那部分。**外部碎片**：分区之间剩下的小块，每块都太小，分不出去。外部碎片靠**紧凑**（把进程挪到一起，需要动态重定位）解决，但代价大。

=== 动态分区选哪块空闲区
空闲分区用链表或表来管。四种找法：

|算法|怎么找|后果|
|首次适应 FF|按地址从低到高，第一个够大的|综合最好；低地址留下小碎片|
|邻近适应 NF|从上次结束的地方接着找|高地址的大块也被切碎|
|最佳适应 BF|按容量从小到大，刚好够的|==留下最多的小碎片==|
|最坏适应 WF|按容量从大到小，最大的|大块很快没了|

走一遍：空闲区依次为 100K、500K、200K、300K、600K，依次申请 212K、417K、112K、426K。

|申请|首次适应|最佳适应|最坏适应|
|212K|500K 剩 288K|300K 剩 88K|600K 剩 388K|
|417K|600K 剩 183K|500K 剩 83K|500K 剩 83K|
|112K|288K 剩 176K|200K 剩 88K|388K 剩 276K|
|426K|==失败==|600K 剩 174K|==失败==|

这个例子里最佳适应胜出，但它留下的 83K、88K、88K 已经很难再用，这就是碎片的来源。

:::trap 回收要看邻居
回收一块时，看它前后相邻的是不是空闲区：
前后都不空闲：空闲区数 **+1**。只有一边空闲：合并，数量 **不变**。两边都空闲：三块合一，数量 **−1**。
合并之后还可能改变它在按大小排序的链表里的位置。
:::

:::recall 内部碎片和外部碎片分别是什么？四种适应算法的缺点各是什么？
内部是分配区内用不完的，外部是分区之间切不出去的。首次：低地址小碎片；邻近：大块被切碎；最佳：小碎片最多；最坏：大块没了。
:::

== 分页 {page}
连续分配的根本问题是必须连续。那就不连续：把进程和内存都切成等大的小片。进程的片叫**页**，内存的片叫**页框**（页帧、物理块）。任何一页可以放进任何页框。这样没有外部碎片，每个进程只在最后一页有不到一页的内部碎片。

页不连续了，就要一张表记录每页在哪：**页表**，每个进程一张，放在内存里，起始地址放在**页表基址寄存器 PTBR**（进程切换时换掉它）。

@ bits([('页号 P',20,'bk'),('页内偏移 W',12)],cap='32 位地址，页大小 4 KB：W = 12，P = 20')

:::shu 地址转换（基本分页）
`P = A ÷ 页大小`，`W = A % 页大小`。先判断 P 不超过页表长度。
查页表得页框号 F，`物理地址 = F × 页大小 + W`。
**偏移不变，只换页号**。
访问一个数据要访存两次：一次读页表项，一次读数据。
:::

:::ana 书和目录
虚拟页号是章节号，页框号是这章实际印在第几页。每次都要先翻目录（读页表），再翻到正文（读数据）。翻目录这一步太亏，下一话的 TLB 就是抄在手边的便签。
:::

@ steps([
 (bits([('0000 0000 0000 0000 0010',20,'gd'),('0000 0000 0100',12)],bare=True),'虚拟地址 0x00002004。页 4 KB，所以高 20 位是页号 2，低 12 位是偏移 0x004。'),
 (table([['页号','有效','页框号'],['0','1','0x105'],['1','0',''],['2','1','<b class="r">0x254</b>']],mono=True),'查页表第 2 项：有效位 1，页框号 0x254。'),
 (bits([('0x254',20,'rd'),('0x004',12)],bare=True),'物理地址 = 0x254 拼 0x004 = 0x254004。')],'一次基本分页地址转换')

**页表项多大**：至少要能放下页框号，再加一些控制位。比如物理地址 32 位、页 4 KB，页框号 20 位，通常取 4 B。

**页多大合适**：页大，内部碎片多，但页表小、一次读得多；页小反之。这是折中。

=== 多级页表
一级页表有两个毛病。32 位地址、4 KB 页，要 2²⁰ 项，×4 B = 4 MB，而且**要连续存放**；而且大部分地址根本没用（堆和栈之间那片），对应的页表项是浪费的。

解决办法是给页表也分页，再用一张**页目录表**记录每个页表页在哪。没用到的区域，连二级页表都不用建。

:::shu 多级页表的算法
每级页表最多占一页。一页能放 `页大小 ÷ 页表项大小` 项，==每级位数 = log₂(这个数)==。
**4 KB 页、4 B 页表项：一页 1024 项，每级 10 位**，32 位地址切成 10 + 10 + 12。
**k 级页表，访存 k+1 次**（没有 TLB 时）。
**优点**：不要求大块连续内存；不用的区域不建表。多级不减少访存次数，反而增加。
:::

走一遍：虚拟地址 0x00C03005，切成 10 + 10 + 12。

@ steps([
 (bits([('页目录号 3',10,'gd'),('页号 3',10,'bu'),('偏移 0x005',12)],bare=True),'0x00C03005 = 0000000011 0000000011 000000000101。'),
 (flow([('PTBR','bk'),('页目录表\n第 3 项','gd'),('二级页表所在页框','bx')],gap=24,size=12),'第一次访存：页目录起始地址 + 3×4，读出二级页表所在的页框号。'),
 (flow([('二级页表\n第 3 项','bu'),('数据所在页框 F','bx')],gap=24,size=12),'第二次访存：二级页表起始地址 + 3×4，读出页框号 F。'),
 (flow([('F 拼 0x005','rd'),('读数据','bk')],gap=24,size=12),'第三次访存：读真正的数据。一共 3 次。')],'二级页表走一遍')

:::link 这就是一棵树
多级页表是多叉树，根是页目录。和 [[13|B 树]]、[[35|inode 多级索引]]同一个算法：==一块能放多少指针，决定每层多宽==。
:::

:::recall 给你地址位数、页大小、页表项大小，怎么切多级页表？为什么要多级？
每级 log₂(页大小/表项大小) 位，偏移 log₂页大小。多级是为了不用连续大块内存、没用的地方不建表。
:::

== 分段与段页式 {seg}
分页是给系统方便的：它把程序按固定大小切，切的时候不管程序的结构，一个函数可能被切成两半。分段反过来，按程序的逻辑切：代码一段、数据一段、栈一段，长度各不相同。

@ bits([('段号 S',8,'bk'),('段内偏移',24)],cap='段号决定最多多少段，偏移决定一段最长多少')

段长各不相同，所以段表每项除了段基址，还要存**段长**。转换要做**两次检查**：

1. `段号 < 段表长度`，否则越界。
2. 查段表得段长和基址，`偏移 < 段长`，否则越界。
3. 物理地址 = 基址 + 偏移。（是**相加**，不是拼接，段基址可以是任意值。）

走一遍：段表第 0 段长 600、基址 219；第 1 段长 14、基址 2300；第 2 段长 100、基址 90。

- 逻辑地址 (0, 430)：430 < 600，物理地址 649。
- 逻辑地址 (1, 10)：10 < 14，物理地址 2310。
- 逻辑地址 (2, 500)：500 ≥ 100，越界异常。

:::shu 分页 vs 分段
|维度|分页|分段|
|目的|系统管理需要|用户（程序结构）需要|
|大小|固定，系统定|不固定，程序定|
|地址空间|一维|==二维==（段号 + 偏移）|
|碎片|内部|外部|
|共享和保护|难|==方便==，一段就是一个逻辑单位|
:::

分段的共享很自然：共享段在两个进程的段表里各有一项，指向同一块物理内存，**段号可以不同**。

**段页式**：先分段，段内再分页，综合两者。地址是（段号，页号，偏移）。每个进程一张段表，每段一张页表。没有 TLB 时访存 3 次：段表、页表、数据。

:::recall 分段转换要检查几次？段页式访存几次？
两次检查：段号和段表长度比，偏移和段长比。段页式 3 次。
:::

:::domain
**分页转换：**P=A÷页大小，物理地址=F×页大小+W。
**多级页表：**每级位数 = log₂(页大小÷表项大小)；k 级访存 k+1 次。
**分段：**段表多存段长，先判越界，基址相加；二维地址，便于共享。
**动态分区：**最佳适应碎片最多；回收看邻居：+1 / 0 / −1。
:::
