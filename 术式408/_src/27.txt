== 问题：x++ 不是一步 {why}
`x++` 在机器上是三步：读 → 加 → 写（[[20|第 20 话]]见过）。中断可以发生在任意两条指令之间。两个线程交错执行：

@ steps([
 (table([['','thread1','thread2','内存 x'],['t1','mov eax,[x] (eax=0)','','0']],mono=True),'thread1 读到 0。'),
 (table([['','thread1','thread2','内存 x'],['t1','mov eax,[x] (eax=0)','','0'],['t2','','mov eax,[x] (eax=0)','0']],mono=True),'切换。thread2 也读到 0。'),
 (table([['','thread1','thread2','内存 x'],['t1','mov eax,[x] (eax=0)','','0'],['t2','','mov eax,[x] (eax=0)','0'],['t3','','add, mov [x],eax','1']],mono=True),'thread2 写回 1。'),
 (table([['','thread1','thread2','内存 x'],['t1','mov eax,[x] (eax=0)','','0'],['t2','','mov eax,[x] (eax=0)','0'],['t3','','add, mov [x],eax','1'],['t4','add, mov [x],eax','','<b class="r">1</b>']],mono=True),'thread1 也写回 1。加了两次，x 只变成 1。')],'为什么要互斥')

结果取决于谁先谁后，这叫**竞争条件**。解决办法是：这三步要么全做，要么一步不做，中间不许别人碰 x。

:::shu 基本概念
**临界资源**：一次只能一个进程用（打印机、共享变量）。**临界区**：访问临界资源的那段**代码**。
**互斥**：不能同时用。**同步**：有先后，A 做完 B 才能做。
一个进程的结构：进入区 → 临界区 → 退出区 → 剩余区。
:::

:::shu 互斥的四条准则
**① 空闲让进**：临界区没人，要进的可以马上进。
**② 忙则等待**：有人在里面，其他人等。
**③ 有限等待**：不能无限等（不饥饿）。
**④ 让权等待**：进不去就让出 CPU，不要占着 CPU 空转。
前三条必须满足；第四条尽量满足，下面可以看到很多方法做不到。
:::

== 软件方法 {soft}
只用共享变量来实现互斥。先看三个有缺陷的，每个失败的方式都不同：

@ table([['算法','做法','问题'],['单标志 turn','turn 指向谁，谁能进；出来时交给对方','必须严格交替：对方不想进时，我也进不了。违反空闲让进'],['双标志先检查','先看对方 flag，再把自己的 flag 置位','两人同时看到对方没进，都进去了。违反忙则等待'],['双标志后检查','先把自己的 flag 置位，再看对方','两人都置位后都看到对方想进，谁也进不去。违反空闲让进和有限等待'],['<b class="r">Peterson</b>','flag 表意愿 + turn 谦让','满足前三条，<b class="r">不满足让权等待</b>']])

问题都出在「看」和「改」是两步。Peterson 算法的绝招是加一个「谦让」：

:::code c Peterson 算法（进程 i，另一方 j）
flag[i] = true;              // 我想进
turn = j;                    // 让你先
while (flag[j] && turn == j);  // 对方想进且轮到对方，我就等
/* 临界区 */
flag[i] = false;
:::

:::ana 走廊让路
两人都想过，都说「我想过，不过你先」。turn 只有一个值，最后说的那个人说的话算数，他就让到底，另一个人先走。所以只有一个人等。
:::

为什么它是对的：两人同时走到 while 时，turn 只能是其中一个，所以只有一个人会被挡住（互斥）；对方不想进时 flag[j]=false，我马上能进（空闲让进）；对方出来后再想进时会把 turn 给我，我不会一直等（有限等待）。while 循环一直占着 CPU，所以不满足让权等待。

== 硬件方法 {hard}
既然「看」和「改」分两步是祸根，就让硬件一步做完。

:::shu 三种硬件方法
**关中断**：进入临界区前关中断，就不会被切走。只适合单处理机内核：多核时别的 CPU 不受影响，交给用户又太危险。
**TestAndSet（TSL）**：原子地「读旧值、置 1」。
**Swap**：原子地交换两个值。
**共性**：后两者实现简单、适合多处理器；都==忙等==，不满足让权等待；可能饥饿。
:::

:::code c TSL 实现互斥
while (TSL(&lock));   // 返回旧值：旧值 true 表示已被占
/* 临界区 */
lock = false;
:::

**互斥锁**（自旋锁）就是用这种原子指令做的：`acquire` 等到锁可用就占上，`release` 放开。等待时一直循环，所以叫**自旋**。

:::link 自旋并不总是坏事
单处理器上自旋纯属浪费，因为持锁者不下 CPU 就放不了锁。多处理器且临界区很短时，自旋比阻塞还便宜：省掉一次进程切换的代价。
:::

:::recall 四条准则是什么？Peterson、TSL、关中断各满足哪些？
空闲让进、忙则等待、有限等待、让权等待。Peterson 满足前三条，TSL 满足前两条（可能饥饿），都不让权。关中断只用于单处理机内核。
:::

== 信号量 {sem}
前面的办法都在忙等。想让进不去的进程去睡觉，就要操作系统介入：提供一个数据结构，和两个原子操作。

:::code c 记录型信号量
typedef struct {
    int value;
    struct process *L;   // 阻塞队列
} semaphore;

void wait(semaphore S) {    // P
    S.value--;
    if (S.value < 0) block(S.L);    // 申请不到就阻塞：让权等待
}
void signal(semaphore S) {  // V
    S.value++;
    if (S.value <= 0) wakeup(S.L);  // 还有人在等就唤醒一个
}
:::

更早的**整型信号量**只有一个整数，`while (S<=0);` 还是忙等。这里的**记录型信号量**才解决了让权等待。

:::shu 信号量的语义
**value > 0**：还有这么多可用资源。**value < 0**：有 |value| 个进程在等。
**初值**：互斥 = 1；同步 = 0；资源 = 数量。
P、V 本身是原语，靠关中断或 TSL 实现，时间极短。
:::

算一遍：信号量初值 3，当前值 −2。说明 3 个资源都被占了，还有 2 个进程在等。

三种用法：

- **互斥**：同一进程内 `P(mutex)` 和 `V(mutex)` 夹住临界区。
- **同步**：A 做完 B 才能做。`S=0`，A 做完 `V(S)`，B 开始前 `P(S)`。P、V 在**两个进程**里。
- **资源数**：n 个打印机，`S=n`。

:::vow PV 三句诀
**互斥：**一个进程内成对，夹着临界区。
**同步：**前操作之后 `V`，后操作之前 `P`，分在两个进程里。
**顺序：**==同步 P 在前，互斥 P 在后==，否则死锁。V 的顺序无所谓。
:::

为什么顺序有讲究，[[28|下一话]]用生产者消费者说明。

== 条件变量与管程 {monitor}
PV 到处写，一个顺序错了就死锁。**管程**把共享数据和对它的操作封装成一个模块（像一个类），==任一时刻只有一个进程能在管程内执行==，互斥由编译器保证，不用程序员写。

同步怎么办？比如生产者进了管程发现缓冲区满了。它不能傻等，因为它占着管程，消费者进不来。所以需要**条件变量**：

:::code c 管程（生产者消费者）
monitor ProducerConsumer {
    condition full, empty;
    int count = 0;
    void insert(Item it) {
        if (count == N) wait(full);
        放入一项; count++;
        if (count == 1) signal(empty);
    }
    Item remove() {
        if (count == 0) wait(empty);
        取走一项; count--;
        if (count == N - 1) signal(full);
    }
}
:::

:::shu 条件变量 vs 信号量
**条件变量**没有值，只有队列。`x.wait()` 阻塞自己，==放开管程==；`x.signal()` 唤醒一个，没人等就什么都不做（不累积）。
**信号量**有值，V 会累积，能记住「曾经 V 过」。
**管程**既能实现互斥，也能实现同步。
:::

:::recall 信号量和条件变量差在哪？管程的互斥由谁保证？
信号量有值、V 累积；条件变量没有值、没人等的 signal 就丢了。互斥由管程的编译器保证。
:::

:::domain
**四准则：**空闲让进、忙则等待、有限等待、让权等待。
**只有信号量和管程让权等待**；Peterson、TSL、Swap 都忙等。
**PV：**互斥一进程内成对；同步跨进程；同步 P 在前。
**条件变量：**没有值，signal 不累积。
:::
