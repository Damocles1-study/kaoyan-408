== 问题：x++ 不是一步 {why}
`x++` 在机器上是三步：读 → 加 → 写（[[20|第 20 话]]见过）。两个线程交错执行：

@ steps([
 (table([['','thread1','thread2','内存 x'],['t1','mov eax,[x] (eax=0)','','0']],mono=True),'thread1 读到 0。'),
 (table([['','thread1','thread2','内存 x'],['t1','mov eax,[x] (eax=0)','','0'],['t2','','mov eax,[x] (eax=0)','0']],mono=True),'切换。thread2 也读到 0。'),
 (table([['','thread1','thread2','内存 x'],['t1','mov eax,[x] (eax=0)','','0'],['t2','','mov eax,[x] (eax=0)','0'],['t3','','add, mov [x],eax','1']],mono=True),'thread2 写回 1。'),
 (table([['','thread1','thread2','内存 x'],['t1','mov eax,[x] (eax=0)','','0'],['t2','','mov eax,[x] (eax=0)','0'],['t3','','add, mov [x],eax','1'],['t4','add, mov [x],eax','','<b class="r">1</b>']],mono=True),'thread1 也写回 1。加了两次，x 只变成 1，这就是竞争条件。')],'为什么要互斥')

:::shu 基本概念
**临界资源**：一次只能一个进程用。**临界区**：访问临界资源的那段代码。
**互斥**：不能同时。**同步**：有先后。两者都用 PV，但初值不同。
:::

:::shu 互斥的四条准则
**① 空闲让进**：临界区空闲，要进的可以马上进。
**② 忙则等待**：已有人在，其他人等待。
**③ 有限等待**：不能无限等（不饥饿）。
**④ 让权等待**：进不去就放弃 CPU，不「忙等」。（这条可以不完全满足，但选择题常问谁满足）
:::

@q os:2.3-49 | 三条指令的交错，结果可能是 0、1、2。同一模子。
@q os:2.3-53 | 同样分析三步交错。
@q os:2.3-50 | 只有访问同一进程的共享变量 x 才需要互斥。不同进程的 x 不是同一块内存。

== 软件方法 {soft}
只用变量实现互斥。都不能让权等待。

@ table([['算法','做法','问题'],['单标志 turn','轮流','违反空闲让进（必须交替）'],['双标志先检查','先看对方再上锁','不互斥（都看到空）'],['双标志后检查','先上锁再看对方','可能都进不去（活锁）'],['<b class="r">Peterson</b>','flag 表意愿 + turn 谦让','满足前三条，<b class="r">不满足让权等待</b>']])

:::code c Peterson 算法（进程 i，另一方 j）
flag[i] = true;              // 我想进
turn = j;                    // 让你先
while (flag[j] && turn == j);  // 对方想进且轮到对方，我就等
/* 临界区 */
flag[i] = false;
:::

:::ana 走廊让路
两人都想过。我说「我想过，不过你先」。如果对方也这么说，最后说的那个人让到底，所以只有一个人等。
:::

@q os:2.3-48 | 这是 Peterson。看书上解析：不会饥饿；互斥保证了。

== 硬件方法 {hard}
:::shu 三种硬件方法
**关中断**：只适合单处理机内核，不能给用户。
**TestAndSet（TSL）**：原子地「读旧值、置 1」。
**Swap**：原子交换。
**共性**：都==忙等==，不满足让权等待，但适合多处理器和短临界区。
:::

:::code c TSL 实现互斥（下面这道的代码）
while (TSL(&lock));   // 返回旧值：旧值 true 表示已被占
/* 临界区 */
lock = false;
:::

@q os:2.3-51 | TSL 必须是原子指令；等待时是在忙等，可以被调度，但不是让权等待。

:::link 自旋锁
TSL 就是自旋锁的实现。大纲的「锁」这一条，就是说这个：单处理器开销大；多处理器且锁很快释放时，自旋比阻塞还便宜（省去一次进程切换）。这个结论是一个分界线。
:::

== 信号量 {sem}
~~信号量~~是一个由 OS 管理的整数加一个等待队列。只有两个原子操作：

:::code c 记录型信号量
typedef struct {
    int value;
    struct process *L;   // 阻塞队列
} semaphore;

void wait(semaphore S) {    // P
    S.value--;
    if (S.value < 0) block(S.L);    // 申请不到就阻塞：让权等待
}
void signal(semaphore S) {  // V
    S.value++;
    if (S.value <= 0) wakeup(S.L);  // 还有人在等就唤醒一个
}
:::

:::shu 信号量的语义
**value > 0**：可用资源数。**value < 0**：|value| 个进程在等。
**初值**：互斥 =1；同步 =0；资源 =数量。
:::

:::vow PV 三句诀
**互斥：**一个进程内成对，`P(mutex)` 和 `V(mutex)` 夹着临界区。
**同步：**前操作之后 `V`，后操作之前 `P`，分别在两个进程里。
**顺序：**==同步 P 在前，互斥 P 在后==。否则死锁。V 的顺序无所谓。
:::

@q os:2.3-47 | 初值 3 现值 1，说明还有 1 个可用，没人等待。
@q os:2.3-55 | 这是信号量相对前面所有方法的优势。

== 条件变量与管程 {monitor}
PV 到处写，容易写错。~~管程~~把共享数据和操作封装在一起，==任一时刻只有一个进程在管程内==（互斥由编译器保证），同步用~~条件变量~~。

:::code c 管程（生产者消费者）
monitor ProducerConsumer {
    condition full, empty;
    int count = 0;
    void insert(Item it) {
        if (count == N) wait(full);
        放入一项; count++;
        if (count == 1) signal(empty);
    }
    Item remove() {
        if (count == 0) wait(empty);
        取走一项; count--;
        if (count == N - 1) signal(full);
    }
}
:::

:::shu 条件变量 vs 信号量
**条件变量**没有值，只有队列。`x.wait()` 阻塞自己（放开管程）；`x.signal()` 唤醒一个，==没人等就什么都不做==（不累积）。
**信号量**有值，V 操作会累积。
**管程** 也能实现同步，不只是互斥。
:::

@q os:2.3-52

:::domain
**四准则：**空闲让进、忙则等待、有限等待、让权等待。
**只有信号量和管程让权等待**；Peterson、TSL、Swap 都忙等。
**PV：**互斥一进程内成对；同步跨进程；同步 P 在前。
**条件变量：**没有值，signal 不累积。
:::
