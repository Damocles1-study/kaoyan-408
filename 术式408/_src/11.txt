:::say
这一话的两个算法都在有向无环图（DAG）上：做事有先后，拓扑排序回答「什么顺序能做」，关键路径回答「最快要多久、谁不能拖」。
:::

== 拓扑排序 {topo}
**AOV 网**：顶点表示活动，有向边表示先后。**拓扑序列**就是一个合法的执行次序，每个顶点出现时它所有前驱都已出现。图里有环就说明循环依赖，不可能完成。

@ topo_steps({'a':(50,100),'b':(170,40),'c':(170,160),'d':(290,100),'e':(410,100)},[('a','b'),('a','c'),('b','d'),('c','d'),('d','e')])

:::shu 拓扑排序三句话
**算法**：不断删入度为 0 的顶点，用栈或队列暂存。
**判环**：输出顶点数 < n ⟹ 有环。
**时间**：邻接表 **O(n+e)**，邻接矩阵 **O(n²)**。
**唯一性**：每一轮入度为 0 的顶点**恰好一个** ⟺ 拓扑序列唯一。
:::

**逆拓扑排序**：反过来，每次删出度为 0 的顶点。用 DFS 也可以：DFS 退出的顺序就是逆拓扑序。

:::flash 矩阵和拓扑序的关系
邻接矩阵是上三角（主对角线以下全 0）⟹ 存在拓扑序（就是 1,2,…,n），但不一定唯一。
拓扑序按顶点重新编号之后，邻接矩阵就一定是上三角。
:::

== DAG 描述表达式 {dag}
表达式可以画成二叉树，但相同的子表达式重复出现很浪费。DAG 让相同的子表达式只画一次。例如 `(a+b)*(a+b)`：a、b、+、* 共 4 个顶点。方法：操作数各一个顶点，从内往外加运算符，相同的共用。

== 关键路径 {aoe}
**AOE 网**：边是活动（带时间），顶点是事件（前面的活动都结束、后面的活动才能开始）。只有一个入度为 0 的源点和一个出度为 0 的汇点。从源到汇的==最长路径==决定工期，这条路径叫关键路径。

:::ana 全班等最慢的那个人
工程要所有活动都完成，所以总工期取决于最长的那条路。最长路径上的活动一秒钟都不能拖，所以叫关键活动。
:::

:::shu 四个量的算法（照表填）
**ve(事件最早)**：从前往后，`ve[k] = max(ve[j] + w(j,k))`。
**vl(事件最迟)**：从后往前，`vl[k] = min(vl[j] − w(k,j))`。汇点 vl = ve。
**e(活动最早)**：`e = ve[起点]`。
**l(活动最迟)**：`l = vl[终点] − 权`。
**关键活动**：`l − e = 0`。
:::

@ aoe({'1':(40,100),'2':(170,40),'3':(170,160),'4':(300,40),'5':(300,160),'6':(430,100)},[('1','2',3,'a'),('1','3',2,'b'),('2','4',2,'c'),('2','5',3,'d'),('3','4',4,'e'),('3','6',3,'f'),('4','6',2,'g'),('5','6',1,'h')],cap='例子：所有数字由程序按上述规则计算')

读图：`l − e` 叫活动的**余量**，表示可以拖多久。余量为 0 的就是关键活动。**先用拓扑序算 ve，再用逆拓扑序算 vl**，顺序不能错。

:::trap 缩短工期的两个陷阱
**关键路径可能有多条。** 要缩短工期，必须缩短所有关键路径共有的活动，或者同时缩短每条关键路径上的一个活动。
**关键活动缩到一定程度可能就不再关键了**（别的路径变成最长），所以不能无限缩短。
:::

:::recall 拓扑排序怎样判环？四个量怎么算？为什么是最长路径决定工期？
输出数小于 n 就有环。ve 前推取 max，vl 后推取 min，e=ve[起点]，l=vl[终点]−权。所有活动都要完成，最慢的路决定总时间。
:::

:::domain
**拓扑：**删入度 0；每轮恰好一个 ⟺ 唯一。
**关键路径：**ve 前推取 max；vl 后推取 min；l=e 的活动是关键活动。
**缩工期：**覆盖所有关键路径。
:::
