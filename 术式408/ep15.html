其之壹简单选择排序

每趟从未排序部分选出最小的，放到前面。不管数据如何，比较次数都是 n(n−1)/2，时间 O(n²)，不稳定（交换会跨过相同元素）。交换次数不超过 n−1，所以移动少。

其之貳堆

简单选择每趟都重新比一遍，之前比较的信息全扔了。堆把比较结果留下来。堆是一棵存在数组里的完全二叉树。大根堆：父 ≥ 子，所以堆顶是最大值。

下沉：某结点比孩子小时，和较大的孩子交换，一路往下。建堆：从最后一个分支结点 ⌊n/2⌋ 开始，向前逐个下沉。排序：堆顶和末尾交换，堆缩小一个，对新堆顶下沉，重复。

模板：堆的下沉（下标从 1 开始）
void HeadAdjust(int A[], int k, int len) {
    A[0] = A[k];
    for (int i = 2 * k; i <= len; i *= 2) {
        if (i < len && A[i] < A[i + 1]) i++;   // 取较大的孩子
        if (A[0] >= A[i]) break;
        A[k] = A[i];
        k = i;
    }
    A[k] = A[0];
}
void HeapSort(int A[], int len) {
    for (int i = len / 2; i > 0; i--) HeadAdjust(A, i, len);   // 建堆
    for (int i = len; i > 1; i--) {
        int t = A[1]; A[1] = A[i]; A[i] = t;                   // 堆顶换到末尾
        HeadAdjust(A, 1, i - 1);
    }
}
术式
堆的几个结论

建堆：从 ⌊n/2⌋ 向前下沉，时间 O(n)（书上界 4n，比较次数实际约 1.88n）。
下沉：比较两个孩子 1 次，较大孩子和父亲 1 次，所以每层最多 2 次比较。
插入：放到末尾向上调，每层 1 次比较。
删除：末尾补到堆顶，向下调。
堆排序：最好最坏都是 O(n log n)，O(1) 空间，不稳定。
应用：取前 k 大（维护大小为 k 的小根堆）；优先队列。

咒灵
插入比较和下沉比较次数不同

上滤一层比 1 次（和父亲比）；下滤一层比 2 次（先比两个孩子）。依次插入建堆 ≠ 整体建堆，结果常常不一样。

合上页面说一遍：建堆从哪开始？为什么是 O(n)？下沉一层比较几次？

从 ⌊n/2⌋ 向前。大部分结点在底层，下沉距离短，累计线性。2 次。

其之參归并排序

两个有序序列合成一个，这是有序合并。从每个元素自成一段开始，两两合并，段长翻倍。

▣ 二路归并
每个元素自成一段。
第 1 趟：两两归并，段长变成 2。
第 2 趟：两两归并，段长变成 4。
第 3 趟：两两归并，段长变成 8。
模板：归并
void Merge(int A[], int low, int mid, int high) {
    int i = low, j = mid + 1, k = low;
    for (int t = low; t <= high; t++) B[t] = A[t];     // B 是辅助数组
    while (i <= mid && j <= high)
        A[k++] = (B[i] <= B[j]) ? B[i++] : B[j++];     // <= 保证稳定
    while (i <= mid) A[k++] = B[i++];
    while (j <= high) A[k++] = B[j++];
}
void MergeSort(int A[], int low, int high) {
    if (low < high) {
        int mid = (low + high) / 2;
        MergeSort(A, low, mid);
        MergeSort(A, mid + 1, high);
        Merge(A, low, mid, high);
    }
}

归并

时间永远 O(n log n)，空间 O(n)，稳定。趟数 ⌈log₂n⌉。m 路归并趟数 ⌈log_m n⌉。
两个长 m、n 的有序表合并：最少比较 min(m,n) 次，最多 m+n−1 次。

其之伍外部排序

数据放不下内存，就要分段读、归并。总时间几乎全部耗在 磁盘 I/O 上，所以优化目标是减少归并趟数。

先用内部排序把每段（内存能装多少）排好，这叫初始归并段；再多路归并。

术式
外排四个工具

① 归并趟数 S = ⌈log_k r⌉（k 路、r 个初始段）。k 越大或 r 越小，趟数越少。
② 败者树：k 路归并时选最小值的比较从 k−1 次降为 ⌈log₂k⌉ 次，使总比较次数和 k 无关。这就是多路平衡归并。
③ 置换-选择排序：内存区 w 时生成更长的初始段（平均 2w），减小 r。
④ 最佳归并树：段长不等时，归并顺序按哈夫曼树（WPL 就是 I/O 次数）。严格 k 叉，要补虚段：若 (r−1) % (k−1) = u ≠ 0，补 k−1−u 个长度 0 的虚段。

败者树：k 路归并的一棵完全二叉树，叶子是各段当前元素。分支结点存的是这场比赛的败者（段号），胜者继续往上；根之上再放一个结点存冠军。取走冠军后，只要从它那一路向上重赛，⌈log₂k⌉ 次比较就决出新冠军。

置换-选择走一遍：内存放 6 个，输入 51 49 39 46 38 29 14 61 15 30 1 48 52 3 63 27 4 13 89 24 46 58 33 76。每次输出内存里最小的、且不小于刚输出值的元素，再读入一个。放不进当前段的留到下一段。得到三段：

  • 29 38 39 46 49 51 61（7 个）
  • 1 3 14 15 27 30 48 52 63 89（10 个）
  • 4 13 24 33 46 58 76（7 个）

每段都比内存的 6 个长。

最佳归并树走一遍：段长 2、3、6、9、12、17、18、24，3 路。(8−1) % 2 = 1，补 2−1 = 1 个虚段。每次取最小的 3 个：0+2+3=5；5+6+9=20；12+17+18=47；20+24+47=91。WPL = 5+20+47+91 = 163，读写块数 = 163×2。

因果

最佳归并树 = 哈夫曼树

第 07 话的哈夫曼树就是它：先合并的部分被多读写几次，所以把小的放在最下面。

咒灵
趟数和比较次数

败者树减少的是每次选最小的比较次数，不会减少归并趟数；k 变大 I/O 趟数减少，但内存要给 k+1 个缓冲区。两者不要混。

合上页面说一遍：外排的四个优化工具，各自减少什么？虚段怎么算？

增大 k：减少趟数。败者树：减少选最小的比较。置换-选择：减少段数。最佳归并树：减少 I/O。(r−1)%(k−1)=u≠0 时补 k−1−u。

2018實戰堆·自底向上建初始堆的中间过程

2013實戰归并·两个升序链表合并成降序链表
已知两个长度分别为 m 和 n 的升序链表，若将它们合并为长度为 m + n 的一个降序链表，则最坏情况下的时间复杂度是（　）。

考虑两个升序链表合并，两两比较表中元素，每比较一次，确定一个元素的链接位置（取较小元素，头插法）。当一个链表比较结束后，将另一个链表的剩余元素插入即可。
最坏的情况是两个链表中的元素依次进行比较，因为 2max(m, n) ≥ m + n，所以时间复杂度为 O(max(m, n))。
此外，每次比较把两个链表中的较小结点插入新链表的表头，直到一个链表为空，因为原链表是升序排列的，要求合并后为降序排列的，因此还要把另一个链表剩下的结点一一插入新链表的表头，不论是最好情况还是最坏情况，都需要遍历两个链表中的所有结点。
书答给的是 O(max(m,n))，这和 O(m+n) 同阶。
再深一层
选 D。★ 这题两个坑，很多人只躲过一个：
坑一：真实工作量是 m + n，不是「比较次数」
   比较次数最坏是 m+n−1（第 7 题的公式），最好只有 min(m,n)；
   但不管比不比，每个结点都得被「摘下来 + 头插」一次
   ⟹ 总操作恒为 m + n（书上最后那句话的意思）
   ⟹ 时间复杂度恒为 O(m + n)，最好情况也是 ★

坑二：选项里没有 O(m + n)，要会「同级换写法」
   设 M = max(m, n)，则  M ≤ m + n ≤ 2M
   ⟹ m + n 与 max(m,n) 相差不超过 2 倍 ⟹ 同一个数量级
   ⟹ O(m + n) = O(max(m, n)) ⟹ 选 D ✅

另三个选项为什么错
   A O(n)       ✗ 只提了一个表，若 m = 10⁶、n = 1 显然不对
   B O(mn)      ✗ 这是「对每个元素都扫一遍另一个表」的暴力做法，
                     归并根本不用回头，两个指针各走一遍就够
   C O(min(m,n)) ✗ 比 m+n 小得多，连把结果链穿起来都不够
📌 ★★ 「升序 → 降序」这个转折是送分不是加难：正因为要降序，才用头插法——每次把较小的插到表头，最后表头是最大的。而头插法不需要尾指针、不需要额外遍历，代价和尾插一样。若题目改成「合并为升序」，用尾插（或头插后再逆置），复杂度完全一样。
📌 ★ 顺手把「合并的四种搭配」记全（考过不止一次）：
   升 + 升 → 升：每次取较小的，尾插
   升 + 升 → 降：每次取较小的，头插  ← 本题
   降 + 降 → 升：每次取较大的，头插
   降 + 降 → 降：每次取较大的，尾插
   ★ 口诀：「要升就尾插，要降就头插；取大取小看原表方向」
   ★ 四种全是 O(m+n) 时间、O(1) 空间（链表不需要辅助数组！）
⚠️ ★ 链表归并的空间是 O(1)，不是 O(n)：只改指针，不复制元素。这是链式存储相对顺序存储的唯一优势，8.6 对比题常考：「归并排序用链表实现时空间复杂度是多少」答 O(1)（若指非递归的归并操作本身）。
⚠️ 本题问「最坏」，但答案与「最好」是一样的——这正是命题人想让你想通的点。凡是「每个元素都必须被处理一次」的算法（归并、基数、计数），最好与最坏往往同级。

2019實戰★★ 虚段数：(n₀−1)%(k−1)=u≠0 时补 k−u−1 个
设外存上有 120 个初始归并段，进行 12 路归并时，为实现最佳归并，需要补充的虚段个数是（　）。

在 12 路归并树中只存在度为 0 和度为 12 的结点，设度为 0 的结点数、度为 12 的结点数和要补充的结点数分别为 n₀、n₁₂ 和 n补，则有 n₀ = 120 + n补，n₀ = (12−1)n₁₂ + 1，可得 n₁₂ = (120 − 1 + n补)/(12 − 1)。因为结点数 n₁₂ 是整数，所以 n补 是使上式整除的最小整数，求得 n补 = 2。
此外，题中为实现最佳归并，应满足 12 叉哈夫曼树，n = 120，m = 12，不满足 (n−1)%(m−1) = 0 的条件，因此需要添加两个权值为 0 的叶结点，使得 n = 122，才能满足条件。故选 B。
(120−1) % 11 = 9，补 11−9 = 2 个虚段。

  u = 0          ⟹ 补 0 个（恰好构成严格 k 叉树）
  u = k − 1      ⟹ 公式给 k − (k−1) − 1 = 0 个 ——
                     但 u = (n₀−1)%(k−1) 永远 < k−1，所以这种情况不会出现，
                     不必纠结。u 的取值范围是 0 ~ k−2。
  ⟹ 补的个数范围是 1 ~ k−2（u 从 k−2 递减到 1 时，补数从 1 递增到 k−2）

  {0, 2, 3, 4, 5, 6, 7}      0 + 2 + 3    ⟹    5
  {4, 5, 5, 6, 7}           4 + 5 + 5    ⟹   14
  {6, 7, 14}               6 + 7 + 14   ⟹   27   ← 根

第 3 步：两种算 WPL 的方法（★ 强烈建议用第二种）
  法一（老实数深度）：先把树画出来，量每片叶子到根的层数
     深度 3： 2, 3      （0 也在这层，但权为 0 不贡献）
     深度 2： 4, 5
     深度 1： 6, 7
     WPL = (2+3)×3 + (4+5)×2 + (6+7)×1 = 15 + 18 + 13 = 46
  法二（★★ 内部结点权值直接相加）：
     WPL = 5 + 14 + 27 = 46   ← 建树过程中就已经把这三个数写出来了

  ⟹ 46，选 B
📌 ★★★ 法二为什么成立（懂了就再也不会用错）：某个内部结点的权 = 它子树里所有叶权之和。一片叶子每「向上穿过」一个内部结点，它的权就在那个内部结点的权里被计一次 ⟹ 叶权被计的次数 = 它的深度 ⟹ Σ内部结点权 = Σ(叶权 × 深度) = WPL。这条对任意 k 叉都成立，第 5 章的二叉哈夫曼树也能用。
📌 ★★ 「虚叶必须离根最远」不是额外规则，而是哈夫曼贪心的自然结果：权为 0 是全场最小，第一轮合并必然把它选走 ⟹ 它自动落在最深处。考场上不必单独论证，照常做贪心即可。
📌 ★ 本题与外排的对应关系（为什么它出现在 8.7）：把 6 个权看成 6 个初始归并段的长度，WPL 就是「归并过程中读取的总记录数」，总 I/O = 2×WPL = 92（读一遍写一遍）。2013 年这题以「三叉树」的纯数学面孔出现，但考的就是最佳归并树。
⚠️ A 选项 27 是「根结点的权」，是最经典的陷阱：27 = 2+3+4+5+6+7 只是所有叶权之和（= 根的权），不是 WPL。WPL 要算「权 × 深度」，必然大于叶权之和（除非树只有一层）。看到答案恰好等于叶权和，立刻警觉。
⚠️ 不补虚段会怎样——本题有个巧合要说清：若不补虚段，而把「不足 k 路的那一次归并放在最前面」（先并 2+3=5，再 4+5+5=14，再 6+7+14=27），得到的 WPL 同样是 46。这不是偶然：补一个权为 0 的虚叶，等价于让第一次归并只并 k−1 个真段。但若把降路的那次归并放在最后，WPL 就会变大——书上 8 段那个例子的 386 vs 326 正是这么来的（详见综04）。
2016實戰大文件排序 ⟹ 外部排序 ⟹ 归并排序
对 10TB 的数据文件进行排序，应使用的方法是（　）。

外部排序指的是大文件的排序，即待排序的记录存储在外存中，待排序的文件无法一次性装入内存，需要在内存和外存之间进行多次数据交换，以达到排序整个文件的目的。外部排序通常采用归并排序算法。选项 A、B、C 都是内部排序的方法。故选 D。
10 TB 放不下内存，只能外排，而外排用的是归并。
再深一层
选 D。★★ 这道 2016 真题是全章「表 8.1 之外」最容易一眼选对、也最容易被想复杂的一题：看见「10TB / 大文件 / 装不进内存」，直接走外排，外排只用归并。
两步定位
  第 1 步：10TB 远大于任何机器的内存 ⟹ 装不进内存 ⟹ 外部排序
  第 2 步：外部排序只用归并策略 ⟹ D

★★ 为什么外排非归并不可——三个理由，答简答题时用
  ① 归并是「顺序访问」的：Merge 只需从两（k）个段的头部依次取元素，
     天然契合磁盘「按块顺序读」的特性；
     而希尔 / 堆 / 快排都要「跳着访问」（随机访问），
     在磁盘上每跳一次就是一次寻道，代价爆炸。
     ★ 呼应 8.6 的结论：只能顺序存储的四个 = 折半插入、希尔、快排、堆——
       它们恰好就是本题的三个错项（加折半插入）。
  ② 归并可以「分而治之 + 分批装入」：把文件切成能装进内存的段各自排好，
     再两两（k 路）归并——每个阶段的内存需求都是可控的。
  ③ 归并的 I/O 次数可精确预测且最少：S = ⌈log_k r⌉ 趟，每趟读写各一遍，
     总 I/O = 2×(S+1)×文件块数，可通过增大 k、减小 r 系统性优化
     ——这正是 8.7.2~8.7.5 整节在做的事。

  ⟹ D
📌 ★ 三个错项为什么在外存上不可用（各一句话）：
  A 希尔排序  要按增量 d 跳着取 A[i], A[i+d], A[i+2d]…
                ⟹ 每取一个元素可能就要读一个新磁盘块，寻道次数 ≈ 元素个数
  B 堆排序    父子下标是 i 与 2i，相隔越来越远
                ⟹ 堆底一次下沉要横跨整个文件，局部性最差
  C 快速排序  Partition 的两个指针从两端相向而行
                ⟹ 每比较一次就在文件首尾之间来回跳，同样毁灭性
  三者的共同病根：都依赖「随机访问 O(1)」这个内存才有的假设。
📌 ★ 顺带记住外排的完整流程（本题若改成简答题就这么答）：① 把 10TB 文件按内存容量切成 r 个子文件，逐个读入内存用内部排序（快排/堆排都行）排好后写回外存 ⟹ 得 r 个初始归并段；② 对这 r 个段做 k 路平衡归并，共 ⌈log_k r⌉ 趟。⚠️ 注意第 ① 步里照样可以用快排——因为那一批数据已经在内存里了。「快排不能用于外排」指的是不能拿它排整个 10TB 文件，不是说它在外排里毫无位置。
⚠️ 别被「哪个最快」带偏：本题不问时间复杂度（四个选项里三个都是 O(n log₂n) 档），问的是「能不能在外存上工作」。凡题干出现具体的数据规模单位（TB / GB / 亿条记录 / 磁盘文件），就是在暗示外排，直接锁归并。

2012實戰每趟至少确定一个元素的最终位置
在内部排序过程中，对尚未确定最终位置的所有元素进行一遍处理称为一趟排序。下列排序算法中，每趟排序结束时都至少能够确定一个元素最终位置的方法是（　）。
Ⅰ. 简单选择排序　Ⅱ. 希尔排序　Ⅲ. 快速排序　Ⅳ. 堆排序　Ⅴ. 2 路归并排序

对于说法Ⅰ，简单选择排序每次选择未排序序列中的最小元素放入其最终位置。对于说法Ⅱ，希尔排序每次对划分的子表进行排序，得到局部有序的结果，所以不能保证每趟结束都能确定一个元素的最终位置。对于说法Ⅲ，快速排序每趟结束后都将枢轴元素放到最终位置。对于说法Ⅳ，堆排序属于选择排序，每次都将大根堆的根结点与表尾结点交换，确定其最终位置。对于选项Ⅴ，2 路归并排序每趟对子表进行两两归并，从而得到若干局部有序的结果，但无法确定最终位置。故选 A。
查口诀：选择、快排、堆。
再深一层
选 A。★★ 这道 2012 真题给出了本章一条分类总纲：把八种排序按「每趟定不定得下元素」劈成两类。
★ 两类算法（背这张表，第 13、14、23 题的反推全靠它）

【定得下】每趟结束必有元素归位 —— 它们都属于「选择 / 交换」家族
  简单选择  每趟选出未排段的最小值，直接放到它的最终位置
  冒泡      每趟把未排段的最大值沉到底
  堆排序    每趟把堆顶（最大值）与末尾交换 ⟹ 末尾即最终位置
  快速排序  每趟划分后枢轴落到最终位置（至少 1 个）

【定不下】每趟只造出「局部有序」—— 它们都属于「插入 / 归并」家族
  直接插入  前 i 个自己有序，但可能一个都不在全局最终位置
  折半插入  同上
  希尔排序  只保证「下标模 d 同余的元素各自有序」，全局位置无从谈起
  2 路归并  段内有序、段间无关，合并到最后一趟才全部到位
  基数排序  最后一趟做完才有序（前面各趟按低位排，看着更乱）

  ⟹ 本题五个候选里属于第一类的是 Ⅰ、Ⅲ、Ⅳ ⟹ A
📌 ★ 两类的分界线其实是一句话：这一趟做的是「全局比较」还是「局部比较」：选择 / 冒泡 / 堆都要把候选元素与整个未排段比一遍，所以能断言「它就是最值」；快排的枢轴与整段元素都比过，所以能断言「它就在这个位置」。而插入 / 希尔 / 归并每趟只在一小块里比较，凭什么断言全局位置？
📌 ★ 快排那句「至少 1 个」要连着 8.3 的两条结论看：一趟划分只保证枢轴 1 个归位；两趟后按枢轴落点分情况：落首/尾 ⟹ 至少 2 个（其中一个在端点）、落中间 ⟹ 至少 3 个（2014、2019 两道真题）。本题只问「一趟至少一个」，是最基础的那一档。
⚠️ 希尔排序的干扰性最强：它属于插入家族（每组做的就是直接插入排序），插入家族的通病就是「定不下最终位置」。反例只要 6 个数：{1, 0, 3, 2, 5, 4} 做一趟 d=3 的希尔排序，序列纹丝不动（三组各自本就有序），而正确答案是 {0,1,2,3,4,5}——一个元素都没到位。
⚠️ 题干给「一趟排序」下了定义：「对尚未确定最终位置的所有元素进行一遍处理」。这个定义是为快排量身定制的——快排的一趟只处理一个子区间，不是整个数组，所以命题人先把定义摆出来避免争议。做题时先读定义再判，别用自己习惯的口径。
2017實戰★ 只能顺序存储的算法：改链式会变慢
下列排序算法中，若将顺序存储更换为链式存储，则算法的时间效率会降低的是（　）。
Ⅰ. 插入排序　Ⅱ. 选择排序　Ⅲ. 冒泡排序　Ⅳ. 希尔排序　Ⅴ. 堆排序

在顺序存储的条件下，插入排序、选择排序、冒泡排序的时间复杂度都是 O(n²)，更换为链式存储后的时间复杂度还是 O(n²)。希尔排序和堆排序都利用了顺序存储的随机访问特性，而链式存储不支持这种性质，所以时间复杂度会增加。故选 D。
查口诀：希尔、堆。
再深一层
选 D。★★★ 这道 2017 真题直接考「只能顺序存储的四个算法」这条命根子——折半插入、希尔、快速、堆。本题选项里出现了其中两个（希尔、堆），答案就是它俩。
★★ 只能顺序存储的四个，理由各不相同但都归结为「要跳着走」
  折半插入排序  要算 mid = (low+high)/2 并直接访问 A[mid]
  希尔排序      要按增量 跳 d 步 取元素（A[i], A[i−d], A[i−2d]…）★ 本题Ⅳ
  快速排序      要两头夹（i 从左、j 从右向中间逼近）
  堆排序        要算 2i、2i+1 直接找孩子 ★ 本题Ⅴ
  ⟹ 这四个换成链表后，每次「跳」都得从头结点重新走一遍，多出一个 O(n) 因子

顺序 / 链式都能用的（本题Ⅰ、Ⅱ、Ⅲ 全在这里）
  直接插入 · 冒泡 · 简单选择 · 2 路归并 · 基数排序
  它们的访问模式都是「从头到尾顺着走」或「相邻两个比」，链表天生支持
  ⟹ 换成链表后时间复杂度不变（插入 / 冒泡 / 选择仍是 O(n²)）

  ⟹ 会变慢的 = Ⅳ 希尔 + Ⅴ 堆 ⟹ D
📌 ★ 换个角度记：问自己「这个算法访问下一个元素时，下标是 ±1 还是跳跃的？」±1 ⟹ 链表友好；跳跃（±d、/2、×2）⟹ 必须顺序存储。这一句能一次性推出全部四个答案，不用死记。
📌 ★ 链式存储对某些算法反而有好处，别以为链表只有坏处：① 直接插入排序在链表上不需要移动元素（只改指针），移动次数从 O(n²) 降到 O(1) 每次；② 归并排序在链表上的空间从 O(n) 降到 O(1)（只改指针不复制）；③ 简单选择排序在链表上也很自然（8.4 综05 就是链表版）。但注意：时间复杂度都不变，因为比较次数没减少。
⚠️ Ⅰ「插入排序」在本题里指的是直接插入排序（链表友好）。若题目写「折半插入排序」，那就要选进去了——折半查找必须能 O(1) 访问 A[mid]，链表做不到。「插入排序」三个字在本章有直接插入 / 折半插入 / 希尔三种，读题要看清定语。
⚠️ 「时间效率降低」≠「无法实现」：希尔排序和堆排序在链表上能实现，只是每次跳跃要重新遍历，代价从 O(1) 变成 O(n)。而「快速排序不能用链表」的说法在有些教材里更绝对（双向逼近在单链表上确实做不到），2011 真题考的就是那一条。

📌 ★ 归并排序「空间 O(n)」是全章八种算法里最大的，这是它最常被扣分的短板。它拿这 O(n) 换来了三样东西：① 时间最稳（最好=最坏=平均 O(n log₂n)，无退化情形）；② 稳定（平均 O(n log₂n) 里唯一稳定的）；③ 顺序 / 链式存储都能用。本题问的是「理由」，而选项里恰好没提稳定性——若加一项「Ⅳ. 归并排序是稳定的」，那也是正确理由。
⚠️ 说法Ⅰ「代码更短」是一个纯粹的常识判断，别小看：归并排序要写两个函数（MergeSort 递归 + Merge 合并），Merge 里还要处理「两段各自的下标 + 三个 while」；直接插入排序只有一个双重循环。考研代码题里，归并的模板长度大约是插入的三倍。
⚠️ 别把「链表归并空间 O(1)」拿来救说法Ⅱ：链式存储下 Merge 只改指针确实是 O(1)，但表 8.1 与本题的默认口径都是顺序存储。题干没有任何「链表」字样，就按顺序存储答。
2019實戰选取排序算法要考虑的因素
选择一个排序算法时，除算法的时空效率外，下列因素中，还需要考虑的是（　）。
Ⅰ. 数据的规模　Ⅱ. 数据的存储方式　Ⅲ. 算法的稳定性　Ⅳ. 数据的初始状态

当数据规模较小时可选择复杂度为 O(n²) 的简单排序算法，当数据规模较大时应选择复杂度为 O(n log₂n) 的排序算法，当数据规模大到内存无法放下时需选择外部排序算法，说法Ⅰ正确。数据的存储方式主要分为顺序存储和链式存储，有些排序算法（如堆排序）只能用于顺序存储方式，说法Ⅱ正确。若对数据稳定性有要求，则不能选择不稳定的排序算法，说法Ⅲ显然正确。当数据初始基本有序时，直接插入排序的效率最高，冒泡排序和直接插入排序的时间复杂度都为 O(n)，而归并排序的时间复杂度仍然为 O(n log₂n)，说法Ⅳ正确。故选 D。
