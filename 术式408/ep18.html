定点数范围太窄：32 位补码最大才 21 亿，也表示不了小数。把小数点做成能动的，就是浮点数。这一话讲它的格式、运算，再加上数据在内存里怎么摆。

其之壹浮点的结构

N = (−1)^S × M × 2^E。和科学计数法一样，只是底数是 2。阶码 E 决定范围，尾数 M 决定精度。

规格化：为了让表示唯一，也为了多存有效位，规定尾数最高位是 1，也就是写成 1.xxx × 2^E 的形式。既然总是 1，就不用存，这一位叫隐藏位，于是 23 位的尾数实际上有 24 位精度。

咒灵
偏置值不是 128

IEEE 754 的移码偏置是 127，和普通移码的 128 不同。所以阶码 e 的实际范围是 1~254，对应指数 −126~+127。全 0 和全 1 留作特殊用途。

为什么要非规格化数：规格化的最小正数是 2⁻¹²⁶，再小就是 0，中间有个断崖。阶码全 0 时规定隐藏位是 0、指数固定为 −126，用来表示接近 0 的很小的数，让小数可以平滑地趋向 0。

术式
手转三步（十进制 → 位模式）
  1. 写成二进制并规格化：−6.5 = −110.1B = −1.101 × 2²。
  2. 算三段：S=1；e = 2+127 = 129 = 1000 0001；f = 101 后面补 0。
  3. 四位一组：1100 0000 1101 0000… = C0D0 0000H。
-6.5 → C0D00000H

反过来读也一样：C1A0 0000H = 1100 0001 1010 0000…，S=1，e = 1000 0011 = 131，指数 4，f = 01，值 = −1.01B × 2⁴ = −10100B = −20。

−1.101×2²；S=1，e=129，f=101…；C0D00000H。规格化后最高位总是 1，不存，所以 23 位尾数有 24 位精度。

其之貳精度与类型转换

float 有 24 位有效数字（含隐藏位）。超过就要舍入，可能丢。而且相邻 float 的间距随数变大而变大：2²⁴ 以上连奇数都表示不出来。这里也解释了为什么 float 能表示的最大整数是 (2−2⁻²³)×2¹²⁷ = 2¹²⁸ − 2¹⁰⁴。

术式
转换谁会丢精度

int → float：可能丢（int 有 31 位有效，float 只有 24 位）。
int → double：不丢。float → double：不丢。
float/double → int：小数被截掉，可能溢出。
double → float：可能丢，可能溢出。
大数吃小数：(d+f)−d 不一定等于 f。

其之參浮点加减

术式
五步（顺序固定）

① 对阶：小阶向大阶看齐，小阶尾数右移（精度损失最小）。
② 尾数相加减。
③ 规格化：尾数溢出右规（阶码 +1），绝对值太小左规（阶码 −1）。
④ 舍入：0 舍 1 入或恒置 1，可能再触发规格化。
⑤ 判溢出：阶码上溢才是真溢出，阶码下溢当作机器零。

走一遍：计算 1.5 + 0.25，用十进制指数看，尾数用二进制。

  1. 写成 1.1B × 2⁰、1.0B × 2⁻²。
  2. 对阶：小阶看齐大阶，1.0B × 2⁻² 变成 0.01B × 2⁰（尾数右移两位，低位可能丢）。
  3. 尾数相加：1.10 + 0.01 = 1.11。
  4. 规格化：已经是 1.xx，不用动。结果 1.11B × 2⁰ = 1.75。

如果尾数相加得 10.11B，就右规一位，阶码 +1。如果相减得 0.001B，就左规三位，阶码 −3。

舍入：对阶和右规时移出的位要处理。IEEE 754 默认就近舍入。舍入后尾数可能再次溢出，要再次规格化。

为什么小阶看大阶？小阶右移，丢的是最低位，影响小。如果大阶看小阶，要把最高位移出去，整个数就错了。

咒灵
溢出的判据

尾数溢出不一定结果溢出，右规后能救回来。真正溢出看阶码。对阶不会引起阶码溢出。阶码上溢是真溢出，阶码下溢当作机器零。

其之肆对齐与大小端

大端：最高字节放低地址（书写顺序）。小端：最低字节放低地址（x86）。

术式
结构体对齐规则
  1. 每个成员的地址必须是自己大小的整数倍。
  2. 整个结构体大小必须是最大成员大小的整数倍。
  3. 成员顺序影响大小。char+int+short（1+3 空+4+2+2 空 = 12）比 int+short+char（4+2+1+1 空 = 8）费空间。

为什么要对齐：CPU 按总线宽度成块读。如果 int 跨了两个 4 字节单元，就要访存两次并拼接。对齐是用一点空间换时间。

算地址：小端、结构体同上，a = 0x00000111。则 C008 放 11，C009 放 01，C00A、C00B 放 00。

合上页面说一遍：结构体大小怎么算？小端和大端差在哪？

每个成员放在自身大小的整数倍地址，末尾补到最大成员的倍数。小端低字节放低地址，大端低字节放高地址。

领域展开

754：1.f × 2^(e−127)，手转三步。
精度：24 位，int→float 可能丢，大数吃小数。
加减五步：对阶小向大，真溢出看阶码。
对齐：成员对齐到自身大小，总大小对齐最大成员。小端：低地址放低字节。

2011實戰IEEE 754 装（值→机器数）
float 型数据通常用 IEEE 754 单精度格式表示。若编译器将 float 型变量 x 分配在一个 32 位浮点寄存器 FR1 中，且 x = −8.25，则 FR1 的内容是（　）。

先将 x 转换为二进制数，即 −1000.01 = −1.000 01 × 23，然后计算阶码 E，E − 127 = 3，因此 E = 130，转换为二进制数，即 1000 0010。最后，根据 IEEE 754 标准，最高位的 1 是被隐藏的。因此 FR1 的内容为 1; 1000 0010; 0000 1000 0000 0000 0000 000，即 C104 0000H。
📕 本题易误选选项 D，未考虑 IEEE 754 标准隐藏最高位 1 的情况，把偏置值认为是 128。
−8.25 = −1.00001B×2³，S=1，e=130，得 C104 0000H。
再深一层
选 A。Python 复算（struct.pack 直接打包 −8.25 得 C1040000）。这是「装」的标准四步，与「拆」互逆：
【第 1 步】转二进制
  8.25 = 8 + 0.25 = 1000.01₂     ⟹ x = −1000.01₂

【第 2 步】规格化成 1.f × 2^E
  −1000.01₂ = −1.00001₂ × 2³     ⟹ E = 3，f = 00001

【第 3 步】阶码 = E + 偏置 = 3 + 127 = 130 = 1000 0010₂

【第 4 步】拼装 s | e | f（f 补 0 至 23 位）
  1 | 1000 0010 | 000 0100 0000 0000 0000 0000
  重新按 4 位一组切：1100 0001 0000 0100 0000 0000 0000 0000
  ⟹ C104 0000H   ✔ 选 A

某数采用 IEEE 754 单精度浮点数格式表示为 C640 0000H，则该数的值是（　）。

C640 0000H 的二进制格式为 1100 0110 0100 0000 0000 0000 0000 0000。符号为 1 表示负数；阶码为 1000 1100 − 0111 1111 = 0000 1101 = 13；尾数为 1.5（注意含有隐藏位，要加 1）。因此，浮点数的值为 −1.5 × 213。

2012實戰float 的表示范围
float 型（IEEE 754 单精度浮点数格式）能表示的最大正整数是（　）。

规格化短浮点数的真值为 (−1)S × 1.m × 2E−127，其中 S 为符号位，阶码 E 的取值为 1~254（8 位表示），尾数 m 为 23 位，共 32 位；因此，float 型能表示的最大整数是 1.111…1 × 2254−127 = 2127 × (2 − 2−23) = 2128 − 2104。
最大的 float：1.111…1 × 2¹²⁷ = 2¹²⁸ − 2¹⁰⁴。因为 23 位小数只能精确到 2⁻²³ × 2¹²⁷ = 2¹⁰⁴。这也是最大正整数。
再深一层
选 D。Python 复算：(2-2-23)×2127 与 2128-2104 完全相等，也正是 C 语言的 FLT_MAX。
要"最大"，符号取 0、阶码取最大规格化值、尾数取全 1：

  s = 0
  e = 254（255 = 全 1 被 ∞/NaN 占用）⟹ E = 254 − 127 = 127
  f = 全 1，加上隐藏位 ⟹ 1.111…1₂（23 个 1）= 2 − 2⁻²³

  最大值 = (2 − 2⁻²³) × 2¹²⁷

展开成选项的形式：
  (2 − 2⁻²³) × 2¹²⁷ = 2 × 2¹²⁷ − 2⁻²³ × 2¹²⁷
                     = 2¹²⁸ − 2¹²⁷⁻²³
                     = 2¹²⁸ − 2¹⁰⁴          ✔ 选 D
📌 本题的难点全在"把 (2-2-23)×2127 展开成 2128-2104"这一步的指数运算上。两个指数各自的来历要说得清：
· 128 = 127 + 1（尾数的那个"2"贡献了一次乘 2）；
· 104 = 127 − 23（2-23 与 2127 相乘）。
四个选项就是围着这两个减法设的，指数少算 1 或少减 23 就掉进去了。
⚠️ 最常见的错法是选 C（2127-2103）——那是忘了尾数能取到接近 2，直接把 1.111…1 当成了 1，于是范围整整少了一倍。这与习题 09 说法 Ⅱ 的错误一模一样。
⚠️ 题干问的是"最大正整数"，但答案与"最大正数"相同。为什么？因为 2128-2104 本身就是整数（2104 是 2128 的因数级别，差值仍是整数）。float 在大数区的间隔已经远大于 1，能表示的都是整数，所以"最大正数"就是"最大正整数"。
⚠️ 顺带把四个"最"值背全（单精度）：
项值怎么来的
最大正数(2−2−23)×2127 = 2128−2104 ≈ 3.4e38e = 254、f 全 1
最小规格化正数1.0 × 2−126 ≈ 1.18e−38e = 1、f 全 0
最小非规格化正数1.0 × 2−149 ≈ 1.4e−45e = 0、f 只有最低位是 1
对称性正负完全对称符号位独立，只翻正负
「3.4e38 / 1.2e−38」这两个近似值最好也记住——考场上可以用来快速判断量级。
2018實戰最小规格化正数
IEEE 754 单精度浮点格式表示的数中，最小的规格化正数是（　）。

IEEE 754 单精度浮点数的符号位、阶码位、尾数位（省去正数位 1）所占的位数分别是 1、8、23。最小正数，符号位取 0，移码的取值范围是 1~254，取 1，得阶码 1 − 127 = −126（127 为我们规定的偏置值），尾数取全 0，最终推出最小规格化正数为 1.0 × 2−126。

  s = 0                      → 正数

      ⟹ E = 1 − 127 = −126
  f = 全 0 ⟹ 尾数含隐藏位 = 1.000…0 = 1.0

2010實戰类型转换与大数吃小数
假定变量 i、f 和 d 的数据类型分别为 int、float 和 double（int 型用补码表示，float 型和 double 型分别用 IEEE 754 单精度和双精度浮点数格式表示），已知 i = 785，f = 1.5678E3，d = 1.5E100，若在 32 位机器中执行下列关系表达式，则结果为“真”的是（　）。
Ⅰ. i == (int)(float)i　　Ⅱ. f == (float)(int)f　　Ⅲ. f == (float)(double)f　　Ⅳ. (d+f) − d == f

题中三种数据类型强制类型转换的顺序为 int → float → double。若将 float 型转换为 int 型，小数位部分会被舍去，int 型是精确到 32 位的整数，而 float 型只保存到 1 + 23 位，因此一个 32 位的 int 型整数在转换为 float 型时可能有损失，具体判断方法如下：先将 int 型整数转换为二进制真值，然后将真值写为 ±1.x…x × 2n 的形式，若小数点后的位数超过 23 位，则转换为 float 型会发生精度损失。
本题中 i = 785，转换为二进制真值为 1.100010001 × 29，小数点后只有 9 位，不会发生精度损失，说法 Ⅰ 正确。对于说法 Ⅱ，将 float 型的 f 转换为 int 型，小数点后的数位丢失，结果非真。double 型的精度和范围都比 float 型的大，float 型转换为 double 型不会有损失，说法 Ⅲ 正确。对于说法 Ⅳ，初看似乎没有问题，但浮点运算 d + f 时需要对阶，对阶后 f 的尾数有效位被舍去而变为 0，因此 d + f 仍然为 d，再减去 d 后结果为 0，结果非真。
Ⅰ：785 小，不丢，真。Ⅱ：f 有小数部分，转 int 丢了，假。Ⅲ：真。Ⅳ：d 比 f 大太多，f 被吃掉，假。
再深一层
选 B（仅 Ⅰ、Ⅲ 为真）。四条说法各考一个独立知识点，逐条拆：
说法考什么判断
Ⅰ i == (int)(float)iint → float 会不会丢精度真：785 = 1.100010001₂ × 2⁹，小数点后仅 9 位 ＜ 23 ⟹ 装得下
Ⅱ f == (float)(int)ffloat → int 丢小数假：f = 1567.8，(int)f = 1567，小数 .8 没了
Ⅲ f == (float)(double)ffloat → double 无损真：double 有效位 53 ＞ float 的 24，往返无损
Ⅳ (d+f) − d == f大数吃小数假：d = 1.5e100 与 f ≈ 1568 阶差远超 54，d+f 仍等于 d ⟹ 结果为 0
📌 Ⅳ 是全题的重头戏，也是浮点数最著名的反直觉现象。
d = 1.5 × 10¹⁰⁰ ⟹ 二进制阶约 2³³²
f = 1567.8      ⟹ 二进制阶约 2¹⁰
阶差 ≈ 322 ≫ 54（double 大数吃小数的阈值）

对阶时，f 的尾数要右移 322 位 ⟹ 24 位有效数字【全部被移光】，变成 0
⟹ d + f 的结果就是 d 本身
⟹ (d + f) − d = d − d = 0 ≠ f

⟹ 浮点加法【不满足结合律】：(d+f)−d ≠ d−d+f
⟹ 这就是数值计算里"大量小数求和要从小往大加"的原因——从大往小加，小的会被一个个吃掉。
⚠️ Ⅰ 的判断方法要背下来（书上给的三步）：
① 把整数写成二进制真值；② 规格化成 ±1.x… x × 2n；③ 看小数点后是否超过 23 位，超了才丢精度。
等价的快判：整数绝对值超过 224（约 1677 万）才可能丢。785 才三位数，稳稳装得下。
⚠️ Ⅱ 和习题 24 的选项 D 是同一件事：转成 int 必然丢小数，只要原数不是整数，往返就不相等。这是四条里最容易判的一条，先答它能快速缩小选项范围——Ⅱ 为假 ⟹ A、C 出局，只剩 B、D，再判 Ⅰ 或 Ⅳ 其一即可。
🔗 与习题 20（int 转 double 后相加，结合律成立）恰成对照：同样是浮点加法，本题因为阶差 322 ≫ 54 而"会吃"，习题 20 因为阶差 ≤ 33 ＜ 54 而"不会吃"。判据是同一个，结论相反——这说明"浮点加法不满足结合律"要加限定条件，不是绝对的。
2017實戰无符号比较·int 溢出·float 有效位与阶码上溢
已知 f(n) = Σi=0..n 2i = 2n+1 − 1 = 11…1B（n+1 位），计算 f(n) 的 C 语言函数 f1 如下所示。将 f1 中的 int 都改为 float，可得到计算 f(n) 的另一个函数 f2。假设 unsigned 型和 int 型数据都占 32 位，float 型数据采用 IEEE 754 单精度标准。请回答下列问题：
1）当 n = 0 时，f1 会出现死循环，为什么？若将 f1 中的变量 i 和 n 都定义为 int 型，则 f1 是否还会出现死循环？为什么？
2）f1(23) 和 f2(23) 的返回值是否相等？机器数各是什么（用十六进制表示）？
3）f1(24) 和 f2(24) 的返回值分别为 33 554 431 和 33 554 432.0，为什么不相等？
4）f(31) = 232 − 1，而 f1(31) 的返回值却为 −1，为什么？若使 f1(n) 的返回值与 f(n) 相等，则最大的 n 是多少？
5）f2(127) 的机器数为 7F80 0000H，对应的值是什么？若使 f2(n) 的结果不溢出，则最大的 n 是多少？若使 f2(n) 的结果精确（无舍入），则最大的 n 是多少？
int f1(unsigned n){
    int sum=1,power=1;
    for(unsigned i=0;i&lt;=n-1;i++){
        power *= 2;
        sum += power;
    }
    return sum;
}
1）i 和 n 是 unsigned 型，因此 “i <= n−1” 是无符号数比较，n = 0 时，n − 1 的机器数为全 1，值是 232 − 1，为 unsigned 型可表示的最大数，条件 “i <= n−1” 永真，因此出现死循环。
若 i 和 n 改为 int 型，则不会出现死循环。 因为 “i <= n−1” 是有符号整数比较，当 n = 0 时，n − 1 的值是 −1，当 i = 0 时，条件 “i <= n−1” 不成立，此时退出 for 循环。
2）f1(23) 与 f2(23) 的返回值相等。 f(23) = 224 − 1，其二进制形式是 24 个 1。int 型数占 32 位，没有溢出。float 型数有 1 个符号位，8 个指数位，23 个底数位，23 个底数位可以表示 24 位的底数，所以两者返回值相等。
f1(23) 的机器数是 00FF FFFFH，f2(23) 的机器数是 4B7F FFFFH。
3）当 n = 24 时，f(24) = 25 个 1，而 float 型数只有 24 位有效位，舍入后数值增大，所以 f2(24) 比 f1(24) 大 1。
4）f(31) 已超出了 int 型数的表示范围，用 f1(31) 实现时得到的机器数为 32 个 1，作为 int 型解释时其值为 −1。因为 int 型最大可表示的数是 0 后面加 31 个 1，因此使 f1(n) 的返回值与 f(n) 相等的最大 n 值是 30。
5）IEEE 754 标准使用“阶码全 1、尾数全 0”表示无穷大。机器数 7F80 0000H 对应的值是 +∞。当 n = 126 时，f(126) = 2127 − 1 = 1.1…1 × 2126，对应的阶码为 127 + 126 = 253，尾数部分舍入后阶码加 1，最终阶码为 254，是 IEEE 754 单精度格式表示的最大阶码。因此使 f2 结果不溢出的最大 n 值为 126。
当 n = 23 时，f(23) 为 24 个 1，float 型数有 24 位有效位，所以不需要舍入，结果精确。因此使 f2 获得精确结果的最大 n 值为 23。
2017 年的这道大题把本话全用上了：无符号比较导致死循环；24 位精度；f2(24) 比 f1(24) 大 1，就是精度丢失；溢出变 ∞。第 4 问是 机器级的内容，题目本身也跨了三话。这是一道非常值得细读的题。

2009實戰浮点加法全流程与溢出
浮点数加、减运算过程一般包括对阶、尾数运算、规格化、舍入和判断溢出等步骤。设浮点数的阶码和尾数均采用补码表示，且位数分别为 5 和 7（均含 2 位符号位）。若有两个数 X = 27 × 29/32 和 Y = 25 × 5/8，则用浮点加法计算 X + Y 的最终结果是（　）。

X 的浮点数格式为 00,111; 00,11101（分号前为阶码，分号后为尾数），Y 的浮点数格式为 00,101; 00,10100。然后根据浮点数的加法步骤进行运算。
① 对阶。X、Y 阶码相减，即 00,111 − 00,101 = 00,111 + 11,011 = 00,010，可知 X 的阶码比 Y 的大 2。根据小阶码向大阶码看齐的原则，将 Y 的阶码加 2，尾数右移 2 位，将 Y 变为 00,111; 00,00101。
② 尾数相加。即 00,11101 + 00,00101 = 01,00010，尾数相加结果符号位为 01，因此需要右规。
③ 规格化。将尾数右移 1 位，阶码加 1，得 X+Y 为 01,000; 00,10001。
④ 判断溢出。阶码符号位为 01，说明发生溢出。
📕 本题容易误选选项 B、C，因为选项 B、C 本身并无计算错误，只是它们不是最终结果，选项 B 少了第 3 步和第 4 步，选项 C 少了第 4 步。
对阶、相加、右规之后阶码变成 01,000，符号位不同，就是阶码上溢。

X = 2⁷ × 29/32 ⟹ 阶 00,111   尾 0.11101 = 00,11101
Y = 2⁵ × 5/8   ⟹ 阶 00,101   尾 0.101   = 00,10100

① 对阶：阶差 = 7 − 5 = 2，Y 的阶小 ⟹ Y 尾数右移 2 位
   Y 变为 00,111 ; 00,00101

② 尾数相加：00,11101 + 00,00101 = 01,00010
   ⚠️ 双符号位 = 01 ⟹ 尾数【正溢出】⟹ 必须右规

③ 右规：尾数右移 1 位、阶码加 1
   尾数 01,00010 → 00,10001；阶码 00,111 + 1 = 01,000
   得 01,000 ; 00,10001

④ 判溢出：⚠️ 【阶码】双符号位 = 01 ⟹ 阶码正溢出 ⟹ 溢出 ✔ 选 D

⚠️ 两次"符号位为 01"要分清是谁的：
· 第 ② 步的 01 是尾数的双符号位 ⟹ 尾数溢出 ⟹ 可以补救（右规）；

这正是习题 11「溢出只看阶码」的现场演示：尾数溢出把麻烦转嫁给阶码，阶码撑不住才是真溢出。
⚠️ 双符号位判溢的规则（2.2 习题 12、14 已考过）：00 = 正数无溢出 · 01 = 正溢出 · 10 = 负溢出 · 11 = 负数无溢出。2.2 和 2.3 在这里接上了头——同一套判溢规则，先用在定点加法，再用在浮点的阶码和尾数上。
⚠️ 本题的阶码只有 3 位数值位，范围是 -4 ~ +3（双符号位补码），而右规后阶码要到 8，早就超了。先估一下范围，其实不用走完四步也能预感要溢出。
2015實戰浮点加减各阶段的溢出
下列有关浮点数加减运算的叙述中，正确的是（　）。
Ⅰ. 对阶操作不会引起阶码上溢或下溢
Ⅱ. 右规和尾数舍入都可能引起阶码上溢
Ⅲ. 左规时可能引起阶码下溢
Ⅳ. 尾数溢出时结果不一定溢出

对阶是较小的阶码向较大的阶码对齐，所以对阶后的阶码是当前那个较大的阶码而不会导致阶码溢出，说法 Ⅰ 正确。右规和尾数含入过程，阶码加 1 而可能上溢，说法 Ⅱ 正确，同理说法 Ⅲ 也正确。尾数溢出时可能仅产生误差，结果不一定溢出，说法 Ⅳ 正确。
对着五步逐句判断，全部正确。
再深一层
选 D（四条全对）。这道 2015 真题把浮点加减的五个步骤逐个问了一遍"会不会造成溢出"，是本节最好的总复习题：
说法哪一步阶码怎么动会溢出吗
Ⅰ对阶小阶升到大阶，结果就是那个已存在的大阶不会 ✔（那个阶本来就合法）
Ⅱ右规 / 舍入阶码加 1可能上溢 ✔（原阶码若已是 254，加 1 变 255 = ∞ 的编码）
Ⅲ左规阶码减 1（可能连减多次）可能下溢 ✔（跌破 −126 就进非规格化区）
Ⅳ尾数运算—尾数溢出可靠右规补救 ✔，不等于结果溢出
📌 Ⅰ 是最容易被误判为"错"的一条，因为"对阶"听起来像在改阶码。但对阶只是把小阶数抬到大阶数的水平，最终阶码等于两者中较大的那个——而那个阶码本来就是合法存在的，怎么可能溢出？⟹ 对阶动的是尾数（右移），阶码只是被赋成一个已有的合法值。
⚠️ Ⅱ 里"舍入也能引起上溢"这一点最隐蔽，值得单独想一遍：
尾数 1.111…1（23 个 1），舍入时末位加 1：
  1.111…1 + 0.000…1 = 10.000…0
  ⟹ 又变成两位整数 ⟹ 还得再右规一次 ⟹ 阶码再加 1
  ⟹ 若此时阶码已是 254，就上溢了

⟹ 舍入这个"看起来无害"的动作，也能通过连锁反应把阶码顶出界
⚠️ Ⅳ 是本节核心结论「溢出只看阶码」的另一种说法（习题 11 正面考过）：尾数溢出（相加后 ≥ 2）总能靠右规化解，把问题转嫁给阶码；只有阶码撑不住时才是真溢出。
⚠️ 把 Ⅱ 和 Ⅲ 并排看，能发现一个不对称：
· 右规只需一次——两个规格化数（尾数 ∈ [1,2)）相加，和 ∈ [2,4)，最多多一位整数位；
· 左规可能多次——相减时高位可以大量抵消（如 1.0001 - 1.0000），前导零可以很多。
⟹ 这是加法与减法的不对称性，也是"右规上溢"比"左规下溢"更少见的原因。
⚠️ 做"哪几条正确"的题，四条都像好话时先怀疑答案是"全选"——本章已经出现三次了（2.1 的 2018 真题、2.2 的习题 17、本题）。但仍要逐条验，不能靠感觉。
2012實戰结构体对齐 + 小端复合题
某计算机存储器按字节编址，采用小端方式存放数据。假定编译器规定 int 型和 short 型长度分别为 32 位和 16 位，并且数据按边界对齐存储。某 C 语言程序段如下所示。若 record 变量的首地址为 0xC008，地址 0xC008 中的内容及 record.c 的地址分别为（　）。
struct{
    int    a;
    char   b;
    short  c;
}record;
record.a = 273;

尽管 record 大小为 7B（成员 a 有 4B，成员 b 有 1B，成员 c 有 2B），因为数据按边界对齐方式存储，所以 record 共占用 8B。record.a 的十六进制表示为 0x00000111，因为采用小端方式存放数据，所以地址 0xC008 中的内容应为低字节 0x11；record.b 只占 1B，后面的 1B 留空；record.c 占 2B，因此其地址为 0xC00E。
a=273=0000 0111H，小端最低字节 11H 放在低地址。
再深一层
选 D。Python 复算 —— 这是"对齐 + 小端"复合题的标准范本，两个知识点各答一空：
【第 1 空】0xC008 里存什么？—— 考小端
  record.a = 273 = 256 + 17 = 0x00000111
  四个字节（MSB→LSB）：00 00 01 11
  小端 ⟹ LSB 放低地址 ⟹ 0xC008 存 【0x11】

【第 2 空】record.c 的地址？—— 考对齐
  int a    对齐值 4，偏移 0  ⟹ 0xC008 ~ 0xC00B
  char b   对齐值 1，偏移 4  ⟹ 0xC00C
  short c  对齐值 2，偏移 5 不是 2 的倍数
           ⟹ 填充 1 字节，偏移推到 6
           ⟹ 0xC008 + 6 = 【0xC00E】

⟹ (0x11, 0xC00E)   ✔ 选 D
地址(0xC0__)08090A0B0C0D0E0F
内容11010000b填充c（2 字节）
说明a = 273，小端存放char填充short
📌 四个选项是"小端记反 × 对齐漏做"的四象限，两处各错一次就选不对：
· 第一空 0x00 vs 0x11：答 0x00 就是按大端取了 MSB；
· 第二空 0xC00D vs 0xC00E：答 0xC00D 就是没做对齐，让 c 紧跟 b 之后。
⟹ 复合题的分数是"乘法"不是"加法"，一处错就全错。
⚠️ 273 的十六进制要算对：273 = 256 + 17 = 0x100 + 0x11 = 0x111，补足 8 位十六进制是 0x00000111。四个字节从 MSB 到 LSB 是 00、00、01、11 —— LSB 是 0x11 不是 0x01。数字节时要按"两个十六进制位 = 一个字节"来切，别按单个十六进制位切。
⚠️ 为什么 c 前面要填 1 字节？b 占了偏移 4，下一个可用偏移是 5；但 short 的对齐值是 2，5 不是 2 的倍数，只能跳到 6。那个偏移 5 的字节就成了填充，谁也用不上。
⚠️ 顺带算 sizeof：c 占到偏移 8，再按规则推到最大对齐值 4 的倍数 ⟹ sizeof(record) = 8。三个成员实际只用 7 字节，填充了 1 字节。
🔗 2012 / 2020 / 2025 三年都考这个复合题型（习题 30、37、45），2025 那道还多加一层"结构体数组下标"。三题连做，这个题型就吃透了。
2016實戰小端存储·多字节数据定位
某计算机字长为 32 位，按字节编址，采用小端方式存放数据。假定有一个 double 型变量，其机器数表示为 1122 3344 5566 7788H，存放在以 0000 8040H 开始的连续存储单元中，则存储单元 0000 8046H 中存放的是（　）。

大端方式：一个字中的高位字节存放在内存中这个字区域的低地址处。小端方式：一个字中的低位字节存放在内存中这个字区域的低地址处。据此可列出存放表，从而存储单元 0000 8046H 中存放的是 22H。
小端：最低字节 88 放 8040，高字节往后，8046 放 22H。
再深一层
选 A。Python 复算，把 8 个字节按小端摊开就一目了然：
地址(0000 80__H)4041424344454647
小端（本题）88H77H66H55H44H33H22H ✔11H
大端（对照）11H22H33H44H55H66H77H88H
机器数 1122 3344 5566 7788H 的 8 个字节：
  MSB → LSB：11 22 33 44 55 66 77 88

小端 = LSB 在低地址 ⟹ 把上面这串【倒过来】放：
  8040H 起：88 77 66 55 44 33 22 11

目标地址 0000 8046H = 首地址 + 6 ⟹ 第 7 个字节（从 0 数是第 6 个）
  ⟹ 22H   ✔ 选 A
📌 秒判公式（小端）：偏移量 k 处存的是机器数从右往左数第 k+1 对十六进制位。本题 k = 6 ⟹ 从右数第 7 对 ⟹ 1122 3344 5566 7788 里从右数：88(0)、77(1)、66(2)、55(3)、44(4)、33(5)、22(6) ⟹ 22H。数完对着题干核一遍偏移量，比画整张表快。
⚠️ 选项 C 的 77H 就是"大小端记反"的结果（大端下 8046H 存 77H）。四个选项 22/33/77/66 全是那 8 个字节里的，专抓"数错位置"和"方向记反"。
⚠️ 本题的字节数是 8（double），比常见的 4 字节多一倍，更容易数错。建议老实画出 8 格表格——考场上这张表画一遍不到 20 秒，比心算数指头可靠得多。
⚠️ 题干"字长为 32 位"是干扰信息：本题按字节编址，double 占 8 字节连续存放，字长多少与字节排列顺序无关。看到题干里的无关参数别慌，先问"这个条件影响我要算的东西吗"。

2018實戰小端存储·机器代码中的立即数
某 32 位计算机按字节编址，采用小端方式。若语句 “int i = 0;” 对应指令的机器代码为 “C7 45 FC 00 00 00 00”，则语句 “int i = −64;” 对应指令的机器代码是（　）。

按字节编址，采用小端方式，低位的数据存储在低地址位、高位的数据存储在高地址位，并且按照“一字节相对不变”的顺序存储。由题意，存储 0 的位数是后 32 位，则我们只需要把 −64 的补码按字节存储在其中即可，而 −64 表示成 32 位的十六进制是 FFFFFFC0，根据小端方式的特点，低位字节存储在低地址位，就是 C0 FF FF FF。
−64 = FFFF FFC0H，小端写成 C0 FF FF FF，指令的前 3 字节不变。
再深一层
选 A。题目已经把"哪几个字节是立即数"告诉你了——对照 int i = 0; 就能看出来：
int i = 0;   ⟹ C7 45 FC | 00 00 00 00
                └操作码┘  └─立即数 4 字节─┘
  立即数是 0，四个字节全是 00，看不出字节序

int i = −64; ⟹ C7 45 FC | ?? ?? ?? ??
  前三字节（操作码 + 寻址信息）【原样不变】
  只需把 −64 的 4 字节机器数按小端填进去

【算 −64 的 32 位补码】
  64 = 0x40 ⟹ −64 = 2³² − 64 = 0xFFFFFFC0
  按 MSB→LSB 切成 4 字节：FF FF FF C0

【按小端摆放】LSB 在低地址（写在前面）
  ⟹ C0 FF FF FF

⟹ 完整机器代码 C7 45 FC C0 FF FF FF   ✔ 选 A
📌 四个选项是"字节序" × "数值算错"的四象限：
选项诊断
C0 FF FF FF✔ 小端 + −64 = 0xFFFFFFC0
FF FF FF C0数值对了，按大端摆的
0C FF FF FF字节序对了，但把 C0 写成了 0C（半字节颠倒）
FF FF FF 0C两处都错
⚠️⚠️ 「0C 还是 C0」这一对是本题最阴的设计：它在提醒一件事——小端颠倒的是字节之间的顺序，不是字节内部的两个十六进制位。一个字节 C0 永远是 C0，绝不会因为小端就变成 0C。这是大小端题最常见的深层错误，比"方向记反"更难自查。
⚠️ −64 的补码心算：64 = 0x40，-64 = 0x100 - 0x40 = 0xC0（低字节），高位全用 F 填 ⟹ 0xFFFFFFC0。负数的 32 位补码：只需算低几位，高位全是 F——这个技巧本章用过多次（习题 2.2-29）。
⚠️ 本题的另一个隐含考点：反汇编代码里的立即数要逆序读回。教材 2.3.4 给的例子 add eax, 0x08049464 对应机器码 01 05 64 94 04 08，立即数字节是 64 94 04 08，逆序拼回才是 0x08049464。⟹ 读小端机器码时，连续的几个字节要倒过来拼。这是 2019、2023 真题的考法。
🔗 大小端的两种问法务必分清：① 给数值问存放顺序（本题、习题 22/34）：大端照抄、小端倒抄；② 给内存字节问数值（反汇编型）：小端要逆序拼回去。
