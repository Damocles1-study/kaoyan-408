其之壹多维数组与特殊矩阵

二维数组在内存里是一维的。C 语言按行优先存，a[i][j] 前面有 i 行，每行 n 个，再加 j 个：

术式
行优先下标公式（数组从 0 开始）

LOC(a[i][j]) = LOC(a[0][0]) + (i·n + j)·size
列优先时 i、j 互换：(j·m + i)·size

因果

同一个公式还要用两次

这个行优先规则是 Cache 算命中率的根据：a[i][j] 按行访问时空间局部性好，按列访问 Cache 容易频繁缺失。

其之貳压缩存储：只有一个思路

对称、三角、三对角矩阵只存一部分。不用背公式，数一数这个元素前面有多少个元素，这个数就是它从 0 开始的下标。

术式
对称矩阵下三角（i≥j，均从 1 开始，按行存）

第 i 行之前有 1+2+…+(i−1) = i(i−1)/2 个，当前行前面还有 j−1 个：
k = i(i−1)/2 + j − 1（k 从 0 开始）
上三角的元素 aij（iji。

算一遍：5 阶对称矩阵，存下三角，a₄₂（i=4, j=2）：4×3/2 + 2 − 1 = 7。上三角 a₂₄ 就取 a₄₂，也是 7。

术式
三对角矩阵（|i−j|≤1 才有值）

第 1 行 2 个，中间每行 3 个，最后一行 2 个。总数 3n−2。
k = 2i + j − 3（i,j 从 1 开始，k 从 0 开始）

稀疏矩阵大部分是 0。用三元组（行，列，值）或十字链表存，压缩后失去随机存取的能力。

咒灵
注意下标约定

题目会给出矩阵从 1 开始还是从 0 开始、数组从 0 还是从 1 开始、按行还是按列、存上三角还是下三角。四个约定一变，公式全变。所以一定数元素个数，别代公式。

其之參串与暴力匹配

串是内容受限的线性表（元素是字符）。这里只讲模式匹配：在主串里找模式串。主串长 n，模式串长 m。暴力法失配时主串指针回退，最坏 O(nm)。

其之肆KMP：主串指针永不回头

比方

看到了就别白看

你比对 abaab 时，第 6 位失配。前面五位你已经看过了，知道它们是 abaab。它的结尾 ab 和开头 ab 相同，所以模式串可以直接往右滑，让开头的 ab 对准刚才结尾的 ab，主串一步都不用退。这个判断只和模式串有关，所以能预先算好。

前缀表 PM：每个位置上，前缀和后缀的最长公共长度。next[j] 就是模式串第 j 位失配时，j 该跳回的位置。

术式
手算 next（下标从 1 开始的书上写法）
  1. 写出 PM 表（子串的最长相等前后缀长度）。
  2. 整体右移一格，开头补 −1，得到 next（下标从 0 的版本）。
  3. 书上下标从 1 开始：再全体 +1。next[1]=0，next[2]=1。

选择题要看题目用哪一套，从 0 还是从 1。

KMP 关键结论

时间复杂度 O(n+m)，空间 O(m)。主串指针 i 从不回退。
失配时：j = next[j]（模式串右滑 j − next[j] 位）。
next[j]=0（下标从 1）时：i、j 都向前进一位。
nextval：若 t[j] == t[next[j]]，则 nextval[j] = nextval[next[j]]，否则等于 next[j]。

求 next 与 KMP 主体（下标从 1 开始，字符串 ch[0] 不用）
void get_next(char T[], int len, int next[]) {
    int i = 1, j = 0;
    next[1] = 0;
    while (i < len) {
        if (j == 0 || T[i] == T[j]) { i++; j++; next[i] = j; }
        else j = next[j];
    }
}
int KMP(char S[], int n, char T[], int m, int next[]) {
    int i = 1, j = 1;
    while (i <= n && j <= m) {
        if (j == 0 || S[i] == T[j]) { i++; j++; }
        else j = next[j];              // 只有 j 回退，i 不动
    }
    return j > m ? i - m : 0;
}

走一遍匹配：

▣ KMP 逐步比较
第 1 次比较：s[0]=t[0]=a，相等，i、j 都前进。
第 2 次比较：s[1]=t[1]=b，相等，i、j 都前进。
第 3 次比较：s[2]=a ≠ t[2]=c，失配。j 跳到 next[2]=0，i 不动。
第 4 次比较：s[2]=t[0]=a，相等，i、j 都前进。
第 5 次比较：s[3]=t[1]=b，相等，i、j 都前进。
第 6 次比较：s[4]=t[2]=c，相等，i、j 都前进。
第 7 次比较：s[5]=t[3]=a，相等，i、j 都前进。
第 8 次比较：s[6]=b ≠ t[4]=c，失配。j 跳到 next[4]=1，i 不动。
第 9 次比较：s[6]=t[1]=b，相等，i、j 都前进。
第 10 次比较：s[7]=t[2]=c，相等，i、j 都前进。
第 11 次比较：s[8]=t[3]=a，相等，i、j 都前进。
第 12 次比较：s[9]=t[4]=c，相等，i、j 都前进。
匹配成功，共 12 次比较

咒灵
「改用 nextval 一定更快」是错的

nextval 只在 t[j]==t[next[j]] 时才省比较。20 万组随机对拍：比较次数从不多于 next，但接近 6 成的情况完全相同。要算次数时，老老实实模拟。

合上页面说一遍：手算一个模式串的 next：PM 表 → 右移 → 看是否 +1。说出 KMP 失配时动谁。

只有 j 动，j = next[j]；next[j]=0（从 1 开始）时 i、j 都前进。

领域展开

压缩矩阵：数前面有多少个元素，比背公式靠谱。
KMP：PM 表 → 右移 → 看是否 +1；失配时只有 j 动。
比较次数：失配也算一次。

再深一层
我逐次模拟得 10 次（前 6 次到 c≠a 失配，j 退到 next=2 后再 4 次成功），匹配起点为主串 0 号位起第 3 位（1-indexed 第 4 位）。
数比较次数的通用做法（本章最常考的手工活）：
① 先把 next 写出来；② 每趟从当前 j 往后比，失配那一次也要计入；③ 失配后 i 不动、j←next[j]，继续在同一个 i 上比（这一次算新的一次）；④ 只有 j 退到 −1/0 时才 i++ 且不计比较。
