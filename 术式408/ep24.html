上一话讲完了 OS 最核心的机制。这一话是 OS 整体的「骨架」，选择题一节一题，内容不难，读一遍配题就够了。

其之壹OS 是什么

OS 管理硬件和软件资源，为用户提供接口。

术式
四个特征

并发：宏观同时，微观交替（单核）。共享：互斥共享、同时共享。虚拟：时分（虚拟 CPU）、空分（虚拟内存）。异步：走走停停，不可预知。
并发和共享互为前提，是最基本的两个特征。

咒灵
并发不是并行

并发：一段时间内多个任务都在推进。并行：同一时刻多个任务同时运行（需要多核）。单核只有并发，没有并行。

其之貳发展历程

类型特点缺点
单道批处理自动、顺序、单道CPU 闲置
多道批处理内存有多道程序，宏观并行、微观串行无交互、平均周转长
分时时间片轮转，交互、独占感不能处理紧急事件
实时截止时间内必须响应（硬/软实时）资源利用率低
网络/分布式网络 OS 资源共享；分布式透明—
术式
多道程序的优点

CPU 利用率高、吞吐量大、I/O 设备利用率高。代价：系统开销变大、单个作业周转可能变长。

其之參体系结构

结构思路优点缺点
分层每层只用下一层易调试、验证定义层难；效率低
模块化按功能分模块灵活模块间依赖乱
宏内核所有功能在内核性能高庞大、一个错全崩
微内核内核只留最基本（进程、低级 I/O、IPC），其余放用户态可靠、易扩展、适合分布式频繁切换，性能低
外核内核只负责分配硬件资源，由应用自己管理（库 OS）灵活、高效实现复杂
术式
微内核的四个基本功能

进程（线程）管理、低级存储器管理、中断和陷入处理、进程通信。服务器以用户态运行，通过消息传递通信。

其之肆引导

术式
引导要记

BIOS 放在 ROM，不易失；OS 放在硬盘；启动完成后 OS 在 RAM。
MBR 包含引导代码和分区表，位于磁盘第一个扇区。

其之伍虚拟机

术式
两类虚拟机

第一类（裸金属）：Hypervisor 直接跑在硬件上，运行在最高特权级，性能好。虚拟机里的 OS 以为自己在内核态，其实是用户态，特权指令被捕获后模拟（陷入并模拟）。
第二类（寄居）：Hypervisor 作为应用跑在宿主 OS 上（如 VMware Workstation、VirtualBox），性能差。
虚拟内核态：虚拟机内部的 OS 看到的内核态，其实硬件上是用户态。

领域展开

四特征：并发、共享、虚拟、异步。
多道：CPU 和设备利用率高，无交互。分时：有交互。实时：讲截止。
结构：宏内核性能好，微内核可靠但切换多，外核管分配。
引导：ROM→BIOS→MBR→分区引导→OS。

2017實戰多道程序系统的优点
与单道程序系统相比，多道程序系统的优点是（　）。
Ⅰ. CPU 的利用率高　　Ⅱ. 系统开销小
Ⅲ. 系统吞吐量大　　Ⅳ. I/O 设备利用率高

多道程序系统中总有一个作业在 CPU 上执行，因此提高了 CPU 的利用率、系统吞吐量和 I/O 设备利用率，说法 Ⅰ、Ⅲ、Ⅳ 正确。但是，系统要付出额外的开销来组织作业和切换作业，说法 Ⅱ 错误。
再深一层
选 D（仅 Ⅰ、Ⅲ、Ⅳ）。唯一的错项 Ⅱ 是本题全部的分值所在：
多道带来的三个「高」：CPU 利用率↑、吞吐量↑、I/O 利用率↑   ✔
多道带来的一个「代价」：
  · 要维护多道程序的 PCB、就绪队列 → 空间开销
  · 要做进程切换（保存/恢复现场）  → 时间开销
  · 要做内存分配与保护　　　　　　 → 管理开销
  ⟹ 系统开销「变大」而非变小，Ⅱ 错
📌 凡是"多道/并发"题里出现"开销小""效率无损"，几乎必错 —— 并发是拿开销换利用率的买卖。
🔗 串联：2022 真题（1.2-20）的 D"进程数越多 CPU 利用率越高"错在同一处 —— 进程一多，切换与竞争开销吃掉收益，甚至死锁。两题一起记：多道有上限。
2016實戰批处理系统的特点
下列关于批处理系统的叙述中，正确的是（　）。
Ⅰ. 批处理系统允许多个用户与计算机直接交互
Ⅱ. 批处理系统分为单道批处理系统和多道批处理系统
Ⅲ. 中断技术使得多道批处理系统的 I/O 设备可与 CPU 并行工作

批处理系统中，作业执行时用户无法干预其运行，只能通过事先编制作业控制说明书来间接干预，缺少交互能力，说法 Ⅰ 错误。批处理系统按发展历程又分为单道批处理系统、多道批处理系统，说法 Ⅱ 正确。多道程序设计技术允许把多个程序同时装入内存，并允许它们在 CPU 中交替运行，共享系统中的各种硬/软件资源，当一道程序因 I/O 请求而暂停运行时，CPU 便立即转去运行另一道程序，即多道批处理系统的 I/O 设备可与 CPU 并行工作，这是借助中断技术实现的，说法 Ⅲ 正确。
再深一层
选 A（仅 Ⅱ、Ⅲ）。三条说法各对应本节一个必背点：
Ⅰ 「直接交互」 ✘ ── 批处理的主要缺点正是无交互（1.2-02）
Ⅱ 「分单道/多道」✔ ── 1.2.2 节的两个小标题
Ⅲ 「中断 ⟹ I/O 与 CPU 并行」✔ ── 1.2-16 的因果链
📌 Ⅰ 的造法非常典型：把分时的"多个用户直接交互"安到批处理头上。2016 这道题与 1.2-08（把批处理安到分时头上）是反向的同一手。
⚠️ Ⅲ 里有个容易被略过的字眼："I/O 设备可与 CPU 并行工作"——这里用"并行"是对的，因为 CPU 与外设是两套硬件、真能同时动（1.1.3 原话："CPU 与 I/O 设备之间、多个 I/O 设备之间可实现真正的硬件并行"）。别一看到"并行"就以为必须多 CPU。
2018實戰多任务操作系统的特点
下列关于多任务操作系统的叙述中，正确的是（　）。
Ⅰ. 具有并发和并行的特点
Ⅱ. 需要实现对共享资源的保护
Ⅲ. 需要运行在多 CPU 的硬件平台上

现代操作系统都是多任务的，允许用户把程序分为若干个任务，使它们并发执行。在单 CPU 中，这些任务并发执行，即宏观上并行执行，微观上分时地交替执行；在多 CPU 中，这些任务是真正的并行执行。此外，引入中断之后才出现了多任务操作系统，而中断方式的特点是 CPU 与外设并行工作，因此说法 Ⅰ 正确。多个任务必须互斥地访问共享资源，为达到这一目标必须对共享资源进行必要的保护，说法 Ⅱ 正确。多任务操作系统并不一定需要运行在多 CPU 的硬件上，单个 CPU 通过分时使用也能满足要求，说法 Ⅲ 错误。
多任务不需要多 CPU：单核也可以并发。
再深一层
选 C（仅 Ⅰ、Ⅱ）。Ⅰ 与 Ⅲ 看似矛盾，其实是本题最精妙的设计：
Ⅰ「具有并发和并行的特点」✔
   并发：单 CPU 上任务分时交替 —— 必然具备
   并行：① 多 CPU 时任务真并行；② 即使单 CPU，
         CPU 与外设也在真并行（中断方式的特点）
Ⅲ「需要运行在多 CPU 上」✘
   「具有并行特点」≠「必须多 CPU」——
   前者陈述能力，后者陈述硬件门槛
⭐ 这就是 2018 年的题眼：很多人因为选了 Ⅰ 就不敢否 Ⅲ，或者否了 Ⅲ 就不敢选 Ⅰ。王道给的理由是"引入中断后才有多任务，而中断方式下 CPU 与外设并行工作" —— 并行性来自CPU 与外设这一层，不必等多核。
🔗 串联：与 1.2-14（进程级并行必须多处理器）合看，"并行"这个词在 408 里分两层：进程与进程的并行要多 CPU；CPU 与 I/O 的并行单机就有。ch1 全部并发/并行题都卡在这条缝上。
📌 Ⅱ 是 ch2 的引子：共享资源必须互斥访问 ⟹ 临界区 ⟹ P/V 操作。
2013實戰操作系统运行的存储器
计算机开机后，操作系统最终被加载到（　）。

系统开机后，操作系统的程序会被自动加载到内存中的系统区，这段区域是 RAM。部分未复习计组的读者对该内容可能不太熟悉，但熟悉了各类存储介质后，解答本题并不难。
OS 最终被加载到内存 RAM。
再深一层
选 D（RAM）。题眼是"最终被加载到"——问的是内核最后待在哪：
A BIOS ── 它是「程序」不是「存储器」，选项本身就不同类
B ROM ── 只读，存 BIOS；OS 内核是从硬盘读来的，不可能写进 ROM
C EPROM ── 可擦可编程只读存储器，仍是 ROM 家族
D RAM ── 内存！内核被读入主存的「系统区」并常驻 ✔
📌 把一次开机的"搬运路线"串起来（1.5 节 + 本题）：
BIOS（ROM，本来就在）→ 读 MBR（硬盘 → RAM）
  → 读 PBR（硬盘 → RAM）→ 读启动管理器（硬盘 → RAM）
  → 读内核映象（硬盘 → RAM）→ 内核在 RAM 里跑起来并常驻
所有代码最终都要进 RAM 才能被 CPU 执行（BIOS 是唯一可原地执行的例外）。
🔗 跨科：组原 ch3 存储系统的层次结构 —— ROM/EPROM/Flash 属非易失，SRAM（Cache）/DRAM（主存）属易失；本题就是那张表的直接应用。
