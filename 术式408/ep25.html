进入 OS 的主战场。程序是一本菜谱，进程是正在做菜的厨师。这一话把进程的数据结构、状态和线程讲完。

其之壹进程

比方

菜谱和做菜

程序是菜谱（静态的）；进程是照着菜谱做菜的这一次过程（动态的）：要占灶台（CPU）、食材（内存）、切到哪一步（PC）都要记住。同一本菜谱可以同时被两个厨师做，所以一个程序可以对应多个进程。

进程 = PCB + 程序段 + 数据段。PCB 是进程存在的唯一标志，里面放着 PID、状态、优先级、寄存器的保存区、内存指针、打开的文件。

术式
五态及转换

运行→阻塞是进程自己主动做的（block）。阻塞→就绪是被别人唤醒的（wakeup）。
阻塞不能直接变运行，就绪不能直接变阻塞。

2014實戰I/O 完成引起的状态转换
一个进程的读磁盘操作完成后，操作系统针对该进程必做的是（　）。

进程申请读磁盘操作时，因为要等待 I/O 操作完成，会把自身阻塞，此时进程变为阻塞态；I/O 操作完成后，进程得到了想要的资源，会从阻塞态转换到就绪态（这是操作系统的行为）。而降低进程优先级、分配用户内存空间和增加进程的时间片大小都不一定会发生。
I/O 完成，只是把它从阻塞变成就绪，等调度。
再深一层
选 A。「必做」二字是题眼：B/C/D 都是「可能做，取决于调度策略」。
读磁盘的完整状态轨迹：
  运行 --发起读磁盘（主动阻塞）--> 阻塞
  阻塞 --磁盘中断到达，中断处理程序 Wakeup--> 就绪 ← 这一步是必做的
B 降优先级 → 只有某些反馈型调度算法会做（多级反馈队列降级）⟹ 不一定
C 分配内存 → 读磁盘的缓冲区在发起 I/O 之前就备好了 ⟹ 不需要
D 增大时间片 → 时间片是调度参数，与 I/O 完成无因果 ⟹ 不一定
📌 注意落点是「就绪」不是「运行」——唤醒只给参赛资格（2.1-46），上不上 CPU 由调度程序定（2.1-40 的禁边）。
⭐ C 与 D 其实还暗含一个正向知识：某些调度算法确实会「照顾」刚做完 I/O 的进程（如把 I/O 密集型进程放进高优先级队列，因为它很快又会去等 I/O，让它先跑能提高设备利用率）——但那是「优化」不是「必做」，2.2 多级反馈队列会正面讲。
2015實戰运行态转就绪态的触发事件
下列选项中，会导致进程从运行态变为就绪态的事件是（　）。

P(wait) 操作表示进程请求某一资源，选项 A、B 和 C 都因为请求某一资源会进入阻塞态，而选项 D 只是被剥夺了 CPU 资源，进入就绪态，一旦得到 CPU 即可运行。
再深一层
选 D。四个选项分成两类，界线就是「缺的是 CPU 还是别的」：
A 执行 P(wait)  → 缺信号量代表的资源 ⟹ 阻塞
B 申请内存失败  → 缺内存             ⟹ 阻塞
C 启动 I/O 设备 → 缺 I/O 完成这个事件 ⟹ 阻塞
D 被高优先级抢占 → 只缺 CPU       ⟹ 就绪 ✓
📌 这条分界线是全章复用率最高的一条（2.1-06 / 43 / 45 / 63 / 64 / 65 / 69 都靠它）：只缺 CPU ⟹ 就绪；缺 CPU 以外的任何东西或在等事件 ⟹ 阻塞。
⚠️ A 的严谨补充：P 操作不一定阻塞——只有 S 减 1 后小于 0 才阻塞（2022 真题 2.1-69Ⅳ 的措辞就加了「若信号量的值小于或等于 0」这个前提）。本题按「会导致」的可能性判，A 属于阻塞那一类。
🔗 D 成立的前提是可剥夺（抢占式）调度，2.2 节会把这个前提正面考。
2018實戰进程阻塞的事件
下列选项中，可能导致当前进程 P 阻塞的事件是（　）。
Ⅰ. 进程 P 申请临界资源　Ⅱ. 进程 P 从磁盘读数据　Ⅲ. 系统将 CPU 分配给高优先权的进程

进程等待某资源为可用（不包括 CPU）或等待输入/输出完成均会进入阻塞态，因此说法Ⅰ、Ⅱ正确；说法Ⅲ中的情况发生时，进程进入就绪态，故说法Ⅲ错误。
Ⅲ 是抢占，让进程进入就绪，而不是阻塞。
再深一层
选 C。Ⅲ 就是「申请 CPU 得不到 ⟹ 阻塞」这个头号坑的第二次出现（2019 是第三次）。
Ⅰ 申请临界资源 → 若已被占用 ⟹ 阻塞 ✓（「可能」二字已给了余地）
Ⅱ 从磁盘读数据 → 等 I/O    ⟹ 阻塞 ✓
Ⅲ CPU 被高优先权进程拿走 → 只缺 CPU ⟹ 就绪 ✗
⭐ 连着三年的同一条刀口，值得并排看：
年份问法那个「缺 CPU」的干扰项正确落点
2015（2.1-63）哪个会「运行 → 就绪」被高优先级抢占 —— 是答案就绪
2018（本题）哪个会「阻塞」Ⅲ CPU 被拿走 —— 是干扰项就绪
2019（2.1-65）哪个会「唤醒」Ⅲ 时间片用完 —— 是干扰项就绪
📌 三年三种问法，考的是同一句话：「与 CPU 有关的等待一律落在就绪态，与 CPU 无关的等待才落在阻塞态。」
⚠️ Ⅰ 的措辞是「可能导致」，所以不必纠结「万一临界资源空着呢」——题干问可能性时，存在一种情形即可。
2019實戰进程唤醒的事件
下列选项中，可能将进程唤醒的事件是（　）。
Ⅰ. I/O 结束　Ⅱ. 某进程退出临界区　Ⅲ. 当前进程的时间片用完

当被阻塞进程等待的某资源（不包括 CPU）可用时，进程将被唤醒。I/O 结束后，等待该 I/O 结束而被阻塞的有关进程会被唤醒，说法Ⅰ正确；某进程退出临界区后，之前因需要进入该临界区而被阻塞的有关进程会被唤醒，说法Ⅱ正确；当前进程的时间片用完后进入就绪队列等待重新调度，优先级最高的进程获得 CPU 资源从就绪态变成运行态，说法Ⅲ错误。
时间片用完不会唤醒谁，是当前进程自己转为就绪。
再深一层
选 C。「唤醒」是一个有严格定义的动作：把进程从阻塞态弄成就绪态——不是「让它跑起来」。
Ⅰ I/O 结束      → 等这个 I/O 的进程从阻塞被 Wakeup ✓
Ⅱ 某进程退出临界区 → 相当于执行 V 操作，唤醒等待进入的进程 ✓
Ⅲ 时间片用完    → 当前进程 运行 → 就绪，它本来就没阻塞
                  「就绪 → 运行」不叫唤醒，叫调度 ✗
📌 Ⅲ 的陷阱在于「谁被唤醒」偷换成了「谁开始运行」：时间片到确实会让某个就绪进程上 CPU，但那个进程一直是就绪的，从未被阻塞，没有阻塞就谈不上唤醒。
⭐ Ⅱ 是本题最值钱的一条：它把「退出临界区」与「唤醒」直接挂钩——🔗 这正是 2.3 中 V 操作的语义：V(S)：S = S + 1；若 S ≤ 0，则从该信号量的等待队列中唤醒一个进程。与 2.1-14（释放一台打印机只唤醒一个等待者）是同一件事的两种说法。

其之貳进程控制与组织

原语：不可中断的一段程序，通过关中断或硬件指令实现。创建、撤销、阻塞、唤醒都用原语，在内核态执行。

术式
创建进程三件事

申请 PCB、分配资源（内存）、插入就绪队列。
引起创建：用户登录、作业调度、提供服务、用户请求（fork）。
fork 后：子进程得到父进程地址空间的一份（写时复制）；exec 替换地址空间。

2010實戰导致创建新进程的操作
下列选项中，导致创建新进程的操作是（　）。
Ⅰ. 用户登录成功　Ⅱ. 设备分配　Ⅲ. 启动程序执行

创建进程的原因主要有：① 用户登录；② 高级调度；③ 系统处理用户程序的请求；④ 用户程序的应用请求。对于说法Ⅰ，用户登录成功后，系统要为此创建一个用户管理的进程，包括用户桌面、环境等，所有用户进程都会在该进程下创建和管理。对于说法Ⅱ，设备分配是通过在系统中设置相应的数据结构实现的，不需要创建进程，这是操作系统中 I/O 核心子系统的内容。对于说法Ⅲ，启动程序执行是引起创建进程的典型事件。
再深一层
选 C。本题的全部难度集中在Ⅱ，判据是「有没有新的执行流要跑」：
Ⅰ 用户登录成功 → 要为该用户建登录进程（桌面/shell）⟹ 建 ✓
Ⅲ 启动程序执行 → 典型的「用户程序应用请求」 ⟹ 建 ✓
Ⅱ 设备分配   → 只是改几张表：设备控制表 DCT、系统设备表 SDT，
                把设备标记为「已分配给进程 P」
                干活的还是原来那个进程 P，没有新执行流 ⟹ 不建 ✗
📌 做题口诀（与 2.1-10 共用）：「有新的活要干」⟹ 建进程；「给已有的活配资源」⟹ 只改数据结构。
⭐ 与 2.1-10 对照记忆：那题四条全是「新活」所以全选；本题的Ⅱ是唯一的「配资源」，所以是唯一的否定项。两题一正一反，配套背。
🔗 设备分配的数据结构（DCT / COCT / CHCT / SDT）是 ch5 输入输出管理的内容——本题实际上是在提前给 ch5 打广告。

组织：各状态的 PCB 串成队列（第 04 话的队列就在这里用上了），或者用索引表。

其之參线程

进程切换代价大（要换页表、TLB、Cache 全部失效）。线程共享地址空间，切换只需要换寄存器和栈。

术式
进程 vs 线程

进程：资源分配的基本单位。线程：CPU 调度的基本单位（引入线程后）。
线程共享：代码段、数据段、堆、打开的文件。
线程私有：PC、寄存器、栈、线程 ID。
同一进程内线程切换不引起进程切换。

咒灵
线程的栈

技术上一个线程可以用指针访问另一个线程的栈。但是考试答「不共享」，就按「栈私有」作答。

2011實戰线程的私有资源
在支持多线程的系统中，进程 P 创建的若干线程不能共享的是（　）。

进程是资源分配的基本单位，线程是 CPU 调度的基本单位。进程的代码段、进程打开的文件、进程的全局变量等都是进程的资源，唯有进程中某线程的栈指针（包含在线程 TCB 中）是属于线程的，属于进程的资源可以共享，属于线程的栈指针是独享的，对其他线程透明。
栈指针私有。
再深一层
选 D。一句判据切开四个选项：这东西是记在 PCB 里还是 TCB 里？
A 代码段   ┐
B 打开的文件├ 属于「进程 P」的资源 ⟹ 记在 PCB ⟹ 全体线程共享
C 全局变量 ┘
D 某线程的栈指针 → 属于「线程」⟹ 记在该线程的 TCB ⟹ 独享 ✗
📌 题干的措辞本身就是答案：A/B/C 三项都写「进程 P 的…」，D 写的是「进程 P 中某线程的…」——定语一变，归属就变了。考场上读到这个定语差异，3 秒可选出。
⚠️ 与 2024 真题（2.1-73）连着看：那题问 Ta 与 Tb 能共享什么，答案是地址空间 ✓ + 文件描述符 fd ✓，线程 T 的栈 ✗——同一考点隔 13 年再考一次，连干扰项都几乎一样（都拿「某线程的栈」当否定项）。
🔗 严格说：各线程的栈都位于进程地址空间内，技术上可被别的线程访问（2.1-34 的补充），但逻辑上归该线程私有——考试答「不能共享」。
2012實戰进程与线程的比较
下列关于进程和线程的叙述中，正确的是（　）。

在引入线程后，进程依然是资源分配的基本单位，线程是调度的基本单位，同一进程中的各个线程共享进程的地址空间。在用户级线程中，有关线程管理的所有工作都由应用程序完成，无须内核的干预，内核意识不到线程的存在。
再深一层
选 A。本题四个选项就是本节四条核心结论的「一对三反」：
选项判定依据
A 进程始终是资源分配单位✓与 2.1-54 的 C 项一字不差
B 线程分配资源 / 进程调度✗把两者对调（2.1-54 的 B 项）
C 两种线程切换都要内核✗ULT 切换全在用户态（2.1-53）
D 同进程线程有各自地址空间✗共享地址空间正是线程的定义（2.1-34）
📌 D 的正确说法要精确到词：同进程的线程共享地址空间，但各有各的栈——而那些栈仍在同一个地址空间内。「有独立的栈」≠「有独立的地址空间」，这是本题最容易被绕进去的地方。
⭐ 本题与 2.1-54 是同一道题的两次出现（一道课后题、一道真题），说明王道的课后题里混着真题的近亲——刷到重复不是浪费，是提示这条必考。

线程的实现

用户级（线程库）内核级
管理用户空间的库OS 内核
切换不需要进内核，快要进内核
OS 感知看不到，只有进程有 TCB
调度单位进程线程
一个线程阻塞整个进程阻塞其他线程继续跑
多核并行不能能
术式
三种多线程模型

多对一：多个用户线程映射到一个内核线程。一个阻塞全部阻塞。
一对一：并发好，但开销大（Linux）。
多对多：折中。

2019實戰用户级线程与内核级线程的比较
下列关于线程的描述中，错误的是（　）。

应用程序没有进行内核级线程管理的代码，只有一个到内核级线程的编程接口，内核为进程及其内部的每个线程维护上下文信息，调度也是在内核中由操作系统完成的，A 正确。用户级线程的控制块是由用户空间的库函数维护的，操作系统并不知道用户级线程的存在，用户级线程的控制块一般存放在用户空间的数据结构中（如链表或数组），由用户空间的线程库来管理。操作系统只负责为每个进程建立一个进程控制块，只能看到进程，看不到用户级线程，所以不会为每个用户级线程建立一个线程控制块。但是，内核级线程的线程控制块是由操作系统创建的，当一个进程创建一个内核级线程时，操作系统会为该线程分配一个 TCB，并将其加入内核的线程管理数据结构，B 错误。用户级线程的切换可以在用户空间完成，内核级线程的切换需要操作系统帮助进行调度，因此用户级线程的切换效率更高，C 正确。用户级线程的管理工作可以只在用户空间中进行，因此可以在不支持内核级线程的操作系统上实现，D 正确。
用户级线程内核看不到，所以 OS 没有给它建 TCB。
再深一层
选 B（B 是错误叙述）。B 的造法是最典型的「张冠李戴」：把 KLT 的行为安给 ULT。
TCB 由谁建、放在哪 —— 这是 ULT 与 KLT 最硬的一条分界：
  ULT 的控制块：线程库建，放在用户空间的链表/数组里
                OS 完全不知道它存在（只为进程建了一个 PCB）
  KLT 的 TCB  ：OS 建，放在内核空间，并加入内核的线程管理结构
⟹ 「OS 为每个 ULT 建 TCB」直接违背 ULT 的定义（内核感知不到）
📌 一个自洽性检验法：若 OS 真为每个 ULT 建了 TCB，那它就知道这些线程了 ⟹ 就能单独调度它们 ⟹ 那它们就成 KLT 了。B 项自我否定。考场上用这招可以不背结论也能判。
⭐ C 与 D 是 ULT 仅有的两大优势，一并记住：C 切换快（不进内核）· D 可移植（不依赖 OS 支持）；它的两大劣势则是阻塞连坐（2.1-50）+ 不能并行（2.1-51）。两优两劣，正好凑成一张卡。

其之肆进程通信

进程之间地址空间隔离，要通信只能靠 OS。

术式
四种通信方式

共享内存：映射同一块物理内存，最快；同步要自己做（PV）。
消息传递：send/receive，直接或通过信箱（间接）；内核复制，慢。
管道：半双工，字节流，一端写一端读。满了写阻塞，空了读阻塞，所以是一个有容量限制的生产者消费者。
信号：异步通知（如 Ctrl+C）。进程从内核态返回用户态时检查，并执行信号处理函数。

2014實戰管道通信的特点
下列关于管道（Pipe）通信的叙述中，正确的是（　）。

普通管道只允许单向通信，数据只能往一个方向流动，要实现双向数据传输，就需要定义两个方向相反的管道，A 错误。管道是一种存储在内存中的、固定大小的缓冲区，管道的大小通常为内存的一页，其大小并不是受磁盘容量大小的限制，B 错误。由于管道的读/写操作都可能遇到缓冲区满或空的情况，当管道满时写操作会被阻塞，直到有数据读出；而当管道空时读操作会被阻塞，直到有数据写入，因此 C 正确。一个管道可以有多个读进程或多个写进程对其进行操作，但是这会增加数据竞争和混乱的风险，为了避免这种情况，应使用互斥锁或信号量等同步机制来保证每次只有一个进程对管道进行读或写操作，D 错误。
写满阻塞写，读空阻塞读。
