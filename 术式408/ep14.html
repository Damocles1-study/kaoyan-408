模板：直接插入
void InsertSort(int a[], int n) {
    for (int i = 1; i < n; i++) {
        int x = a[i], j;
        for (j = i - 1; j >= 0 && a[j] > x; j--)   // 严格大于才挪，保证稳定
            a[j + 1] = a[j];
        a[j + 1] = x;
    }
}
术式
直接插入与折半插入

直接插入：最好 O(n)（已有序），最坏 O(n²)，稳定，O(1) 空间。适合基本有序或 n 小。
一趟特征：前 k 个有序，但不一定是最终位置。
折半插入：比较次数减少到 O(n log n)，但移动次数不变，总时间仍 O(n²)，稳定。

2012實戰折半插入排序·与直接插入排序的对比
对同一待排序序列分别进行折半插入排序和直接插入排序，两者之间可能的不同之处是（　）。

折半插入排序与直接插入排序都将待插入元素插入前面的有序子表，区别是：确定当前记录在前面有序子表中的位置时，直接插入排序采用顺序查找法，而折半插入排序采用折半查找法。
排序的总趟数取决于元素个数 n，两者都是 n−1 趟。元素的移动次数都取决于初始序列，两者相同。使用辅助空间的数量也都是 O(1)。折半插入排序的比较次数与序列初态无关，时间复杂度为 O(n log₂n)；而直接插入排序的比较次数与序列初态有关，时间复杂度为 O(n)~O(n²)。故选 D。
折半只改变了比较次数，移动次数相同。这是这一节最容易考的一句话。
再深一层
选 D（元素之间的比较次数）。★ 四个维度逐项对照，这张表就是本题的全部：
维度              直接插入            折半插入          相同？
排序总趟数        n−1                 n−1               ✔ 相同
元素移动次数      看初态，最坏 n²/2   完全一样          ✔ 相同
辅助空间          O(1)                O(1)              ✔ 相同
元素比较次数      看初态 O(n)~O(n²)  与初态无关 O(n log₂n) ✗ 不同 ← 答案

两者唯一的算法差异：
  找插入位置时  直接插入 = 顺序查找（边比边挪）
                折半插入 = 折半查找（先定位，再统一挪）
📌 "移动次数为什么完全一样"是本题最该想通的一点：无论怎么找到插入位置 k，L[k…i−1] 这一段该挪的一个都不少。折半只省了"找"的功夫，没省"搬"的功夫——这正是第 13 题（时间复杂度仍 O(n²)）的同一个道理。
📌 "可能的不同之处"里的"可能"二字有讲究：当序列恰好有序时，直接插入比较 n−1 次，折半插入比较约 n log₂n 次——折半反而比得更多！所以两者的比较次数不是"折半一定少"，而是"两者可能不同"，题干措辞很严谨。
⚠️ 折半插入排序只能用于顺序存储（链表算不出 mid），这是它相对直接插入的倒退之处。8.1 第 3 题的解析就拿它举过例。

2014實戰希尔排序·由一趟结果反推增量
用希尔排序算法对一个数据序列进行排序时，若第一趟排序结果为 9, 1, 4, 13, 7, 8, 20, 23, 15，则该趟排序采用的增量（间隔）可能是（　）。

首先，第二个元素为 1，是整个序列中的最小元素，可知该希尔排序为从小到大排。然后考虑增量问题：
若增量为 2，则第 1+2 个元素 4 明显比第 1 个元素 9 要小，排除 A。
若增量为 3，则第 i、i+3、i+6（i=1,2,3）个元素都为有序序列，符合希尔排序的特点。
若增量为 4，则第 1 个元素 9 比第 1+4 个元素 7 要大，排除 C。
若增量为 5，则第 1 个元素 9 比第 1+5 个元素 8 要大，排除 D。故选 B。
增量 3 时，分组 9,13,20 / 1,7,23 / 4,8,15 都有序。
再深一层
选 B（增量 3）。★ 本题给的是"结果"而不是"原序列"，所以只能用验证而不能用正算——判据只有一条：一趟 d 结束后，下标模 d 同余的元素必各自递增。
结果序列（位置 1~9）：  9   1   4  13   7   8  20  23  15

d=2：{9, 4, 7, 20, 15}    9 > 4  ✗ 立刻死
d=3：{9, 13, 20} 递增 ✔
     {1,  7, 23} 递增 ✔
     {4,  8, 15} 递增 ✔     三组全过 ⟹ 可能是 3
d=4：{9, 7, 15}           9 > 7  ✗
d=5：{9, 8}               9 > 8  ✗
📌 验证时有个提速技巧：只查第一组往往就能毙掉三个选项。本题 d=2、4、5 都是栽在"第一个元素 9 比同组后面的小"上，一眼就出。只有 d=3 需要把三组都查完。
📌 题干说"可能是"，因为反推增量不唯一：不同的原序列 + 同一个 d 可以得到同样的结果，我们能做的只是"排除不可能的"。所以答案是"通过检验的那个"，不需要（也无法）还原原序列。
⚠️ 书答第一句"第二个元素为 1 是最小元素，可知是从小到大排"值得留意：它在提醒你先确认排序方向。若某年真题给的是降序希尔，判据要反过来（各组必须递减）。
⚠️ 本题与第 8 题的区别：第 8 题给了原序列和结果，可以用"看谁和谁换位"秒杀；本题只给结果，必须逐个 d 验证。拿到题先看清给了什么。

2015實戰希尔排序·组内排序采用的算法
希尔排序的组内排序采用的是（　）。

希尔排序的思想是：先将待排元素序列分割成若干子序列（由相隔某个"增量"的元素组成），分别进行直接插入排序，然后依次缩减增量再进行排序，待整个序列中的元素基本有序（增量足够小）时，再对全体元素进行一次直接插入排序。故选 A。
再深一层
选 A（直接插入排序）。送分题，但要能说出"为什么偏偏是直接插入"：
希尔排序的设计动机（书 335 原文）：
  "直接插入排序在基本有序或数据量较小时效率高（可升至 O(n)）"
   ⟹ 希尔正是基于这一特性改进的

所以组内必须用直接插入，因为：
  ① 子序列短（每组只有 n/d 个）      → 正中直接插入的长处
  ② 越到后面子序列越基本有序          → 又一次正中长处
  ③ 直接插入不需要随机访问以外的开销  → 代码就是把步长 1 换成 dk
📌 排除另外三个的理由各不相同，要分得清：折半插入——组内元素在数组里是"跳着放"的，算 mid 后还要换算回真实下标，得不偿失；快排——子序列太短，递归开销远大于收益；归并——需要 O(n) 辅助空间，而希尔的卖点之一就是 O(1)。
📌 与第 7 题（希尔属于哪一类）互为表里：那题问"归属"，本题问"内核"，答案都指向直接插入排序。
⚠️ "组内排序"四个字别读成"组间"：希尔排序组与组之间从不比较（这正是它不稳定的根源，见第 15 题）。每一趟只是把 d 个组各自排好，组间的秩序要靠下一趟更小的 d 来建立。

其之肆冒泡排序

相邻比较，大的往后换。每一趟把一个最大值送到末尾。一趟里没发生交换就提前结束。

术式
冒泡

最好 O(n)，最坏 O(n²)，稳定，O(1) 空间。
一趟特征：末尾（或开头）增加一个最终位置的元素。

2010實戰三趟中间结果反推 ⟹ 冒泡
对一组数据 (2, 12, 16, 88, 5, 10) 进行排序，若前 3 趟排序结果如下：
　第一趟排序结果：2, 12, 16, 5, 10, 88
　第二趟排序结果：2, 12, 5, 10, 16, 88
　第三趟排序结果：2, 5, 10, 12, 16, 88
则采用的排序算法可能是（　）。

题中给出的排序过程，每一趟都是从前往后依次比较使最大值沉底，符合冒泡排序的特点。分别用其他 3 种排序算法尝试：归并排序第一趟后的结果为 (2, 12, 16, 88, 5, 10)，基数排序第一趟后的结果为 (10, 2, 12, 5, 16, 88)，希尔排序显然不符合。故选 A。
每一趟末尾增加一个最大值：88，然后 16…… 这是冒泡的特征。
再深一层
选 A。★ 本题给了三趟结果，比第 13 题信息还多——最快的打法是只看「每趟末尾多定死一个最大值」这一个特征。
初始   2  12  16  88   5  10
第1趟   2  12  16   5  10  88   ← 最大的 88 沉到最后 ★
第2趟   2  12   5  10  16  88   ← 次大的 16 沉到倒数第二 ★
第3趟   2   5  10  12  16  88   ← 12 沉到倒数第三 ★
         ↑ 末尾的有序段每趟长一个，且全是「全局最大的那几个」= 冒泡的签名

逐趟手推冒泡（第一趟）
   2:12 不换 · 12:16 不换 · 16:88 不换 · 88:5 换 · 88:10 换
   ⟹ 2, 12, 16, 5, 10, 88  ✅ 与题给逐位相同

另外三个当场排除
   归并（段长 2）：(2,12)(16,88)(5,10) 各自本来就有序 ⟹ (2,12,16,88,5,10)，与第 1 趟不符 ✗
   基数（按个位）：2→2 · 12→2 · 16→6 · 88→8 · 5→5 · 10→0
                    ⟹ (10, 2, 12, 5, 16, 88)，与第 1 趟不符 ✗
   希尔（d=3）：{2,88}{12,5}{16,10} ⟹ (2, 5, 10, 88, 12, 16)，不符 ✗
📌 ★★ 冒泡的签名一句话：末尾（或开头）的有序段每趟长一个，而且那一段的元素就是全局最大（最小）的那几个。这两个条件缺一不可——只满足「末尾有序」而不满足「是全局最大的几个」，那是插入排序或归并排序的产物。
📌 ★ 本题与第 13 题（2009）连着看，就把「反推题」的两种问法都覆盖了：2009 只给一趟、问「只能是」（用排除法）；2010 给三趟、问「可能是」（用正向验证最快）。给的趟数越多，越应该直接正向手推第一趟去对——一趟对不上就出局，不用推三趟。
⚠️ 选择排序不在选项里，但它与冒泡长得很像，要能区分：简单选择排序是每趟从前面定一个最小值（有序段在开头增长），且它靠交换把最小值换到位、被换走的那个元素会被扔到远处。冒泡则是相邻交换，元素只会「挪一格」。看第 1 趟：88 从下标 3 一路挪到下标 5，而 5、10 各前移一格——这是相邻交换的痕迹，不是选择排序的长距离对换。
⚠️ 希尔排序的「显然不符合」不能只写四个字：考场上要能随手取一个增量（如 d = ⌊n/2⌋ = 3）算一趟给出反证。本题 d=3 得 (2, 5, 10, 88, 12, 16)，与题给的第 1 趟完全不同。

其之伍快速排序

比方

选一个人站中间

选一个枢轴，比它小的站左边，比它大的站右边。这一趟之后，它就站到了最终位置。然后两边各自递归。

▣ 快速排序（首元素为枢轴）
第 1 趟后：黑格是已到最终位置的枢轴。至少 1 个元素就位。
第 2 趟后：黑格是已到最终位置的枢轴。至少 3 个元素就位。
第 3 趟后：黑格是已到最终位置的枢轴。至少 5 个元素就位。
第 4 趟后：黑格是已到最终位置的枢轴。至少 8 个元素就位。
模板：快排划分（要能默写）
int Partition(int a[], int low, int high) {
    int p = a[low];                         // 枢轴
    while (low < high) {
        while (low < high && a[high] >= p) high--;
        a[low] = a[high];
        while (low < high && a[low] <= p) low++;
        a[high] = a[low];
    }
    a[low] = p;
    return low;
}
void QuickSort(int a[], int low, int high) {
    if (low < high) {
        int m = Partition(a, low, high);
        QuickSort(a, low, m - 1);
        QuickSort(a, m + 1, high);
    }
}
术式
快排

平均 O(n log n)，最坏 O(n²)（已有序或逆序），空间 O(log n)（递归栈），不稳定。
平均性能是内部排序中最好的。
第 k 小 / 第 k 大：只递归一边，平均 O(n)。
判第二趟结果：第一趟后至少 1 个元素到位；第二趟后至少 3 个（枢轴在中间时），若第一趟枢轴在端点，则至少 2 个。

2014實戰快速排序·两趟后至少确定几个元素
下列选项中，不可能是快速排序第二趟排序结果的是（　）。

★★ 快排"两趟后至少确定几个元素"的通用判据：对 n 个元素进行第一趟快速排序后，会确定一个基准元素，根据这个基准元素在数组中的位置，有两种情况：
① 基准元素在数组的首端或尾端，接下来对剩下的 n−1 个元素构成的子序列进行第二趟快速排序，再确定一个基准元素。这样，在两趟排序后就至少能确定两个元素的最终位置，其中至少有一个元素是在数组的首端或尾端。
② 基准元素不在数组的首端或尾端，第二趟快速排序对基准元素划分开的两个子序列分别进行一次划分，两个子序列各确定一个基准元素。这样，两趟排序后至少能确定三个元素的最终位置。
基于上述结论，观察题中的四个选项：选项 A 的 2, 3, 6, 7, 9 符合第一种或第二种情况；选项 B 中 2, 9 符合第一种情况；选项 D 中 5, 9 符合第一种情况；最后看选项 C，只有 9 处于最终位置，因此不可能是快速排序第二趟的结果。故选 C。
把序列和排好序的结果比较，到位的元素不够数的，就不可能。

2010實戰快速排序·递归次数的影响因素
采用递归方式对顺序表进行快速排序。下列关于递归次数的叙述中，正确的是（　）。

快速排序的递归次数与元素的初始排列有关。若每次划分后分区比较平衡，则递归次数少；若划分后分区不平衡，则递归次数多。递归次数与分区处理顺序无关。故选 D。（⇒ A 错在"无关"，B、C 错在"处理顺序能减少递归次数"。）
递归次数和先处理哪边无关，和划分是否均匀有关。
再深一层
选 D。这题考的是一个很干净的道理：递归树的形状由划分结果决定，而遍历这棵树的顺序改变不了树上有几个结点。
          递归树的"形状" ← 由每次划分的位置决定 ← 由初始排列决定
          递归的"次数" = 树上结点个数 = 只与形状有关
          处理顺序      = 先访问左子树还是右子树 = 只改变遍历次序

  A ✗ "与初始排列无关"——恰恰相反。
      正序 n=12 ⟹ 划分 11 次（退化）；随机 n=12 ⟹ 划分 8 次左右
  B ✗ 先长后短，树没变，次数没变
  C ✗ 先短后长，树也没变，次数还是没变
  D ✔ 次数与处理顺序无关
📌 ★ 处理顺序真正影响的是"栈的最大深度"，不是"递归次数"。经典优化："先递归处理较短的分区，较长的分区改用循环（尾递归消除）"，能把栈深从 O(n) 压到 O(log₂n)。C 的说法之所以像是对的，就是因为它说对了一半——它把"减少栈深"写成了"减少递归次数"。
📌 命题人在这道题上埋了一个真实的工程知识点：C 描述的优化确实存在（很多教科书叫"尾递归优化"），但它优化的是空间。看到"减少递归次数"这五个字就该警觉：次数是树的结点数，改不了。
⚠️ 与第 13 题连读：那题问的"最大递归深度 n / 最小 log₂n"就是本题里"栈深"的两个极端。本题问次数（结点数）、那题问深度（树高），是同一棵树上的两个不同量。
2011實戰快速排序·适用的存储结构
为实现快速排序算法，待排序序列宜采用的存储方式是（　）。

对于绝大部分内部排序而言，只适用于顺序存储结构。快速排序在排序的过程中，既要从后往前查找，也要从前往后查找，因此更宜采用顺序存储。故选 A。
快排要从两端向中间扫，顺序存储最合适。
再深一层
选 A（顺序存储）。快排必须顺序存储的理由只有一个词：双向随机访问。
Partition 的两条内层循环：
  while(low<high && A[high]>=pivot) --high;   ← 从后往前走
  while(low<high && A[low ]<=pivot) ++low ;   ← 从前往后走

  单链表没有前驱指针，--high 走不动；
  就算用双链表，low/high 相遇的判断与下标算术也无从谈起。
📌 ★ 只能顺序存储的四个算法（本章必背）：折半插入、希尔、快速、堆。理由各不相同但都归结为"要跳着走"：折半要算 mid、希尔要跳 dk、快排要两头夹、堆要算 2i 和 2i+1。2017 真题（8.6）直接考这一条。
📌 反过来，链表上照样能跑的有：直接插入、冒泡、简单选择、2 路归并、基数排序。其中基数排序天生就是链式的（用队列收集），归并排序在链表上甚至更优（不需要辅助数组）。
⚠️ B 散列存储、D 索引存储是"张冠李戴"型干扰项：散列是第 7 章的查找结构（元素位置由散列函数决定，谈不上"序"），索引存储是为了加速查找的附加结构。排序讨论的存储方式只有"顺序 vs 链式"这一对。
2016實戰快速排序·快速选择的应用（集合等分）
已知由 n (n≥2) 个正整数构成的集合 A = {aₖ | 0 ≤ k < n}，将其划分为两个不相交的子集 A₁ 和 A₂，元素个数分别是 n₁ 和 n₂，A₁ 和 A₂ 中的元素之和分别为 S₁ 和 S₂。设计一个尽可能高效的划分算法，满足 |n₁ − n₂| 最小且 |S₁ − S₂| 最大。要求：
1) 给出算法的基本设计思想。
2) 根据设计思想，采用 C 或 C++ 语言描述算法，关键之处给出注释。
3) 说明所设计算法的平均时间复杂度和空间复杂度。
1) 算法的基本设计思想：由题意可知，将最小的 ⌊n/2⌋ 个元素放在 A₁ 中，其余的元素放在 A₂ 中，分组结果即可满足题目要求。仿照快速排序的思想，基于枢轴将 n 个整数划分为两个子集。根据划分后枢轴所处的位置 i 分别处理：
① 若 i = ⌊n/2⌋，则分组完成，算法结束。
② 若 i < ⌊n/2⌋，则枢轴及之前的所有元素均属于 A₁，继续对 i 之后的元素进行划分。
③ 若 i > ⌊n/2⌋，则枢轴及之后的所有元素均属于 A₂，继续对 i 之前的元素进行划分。
基于该设计思想实现的算法，无须对全部元素进行全排序。
3) 本算法的平均时间复杂度是 O(n)，空间复杂度是 O(1)。
int setPartition(int a[], int n){
    int pivotkey, low=0,low0=0,high=n-1,high0=n-1,flag=1,k=n/2,i;
    int s1=0,s2=0;
    while(flag) {
        pivotkey=a[low];                              //选择枢轴
        while(low<high) {                             //基于枢轴对数据进行划分
            while(low<high && a[high]>=pivotkey) --high;
            if(low!=high) a[low]=a[high];
            while(low<high && a[low]<=pivotkey) ++low;
            if(low!=high) a[high]=a[low];
        }                                             //end of while(low<high)
        a[low]=pivotkey;
        if(low==k-1)                                  //若枢轴是第n/2小的元素，划分成功
            flag=0;
        else{                                         //是否继续划分
            if(low<k-1){
                low0=++low;
                high=high0;
            }
            else{
                high0=--high;
                low=low0;
            }
        }
    }
    for(i=0;i<k;i++) s1+=a[i];
    for(i=k;i<n;i++) s2+=a[i];
    return s2-s1;
}
这道 2016 大题就是 Partition 的直接应用：不用全排，只要把数组分成前后两半。平均 O(n)，比全排序更优，只要求划分时不要全排。
再深一层
思路与代码与书答相同。★ 这道题与上一题（综02）是同一个模板，考场上写熟一份即可两题通吃。
第一步：把题目翻译成"找第 ⌊n/2⌋ 小"（这一步是全题的分水岭）
   |n₁−n₂| 最小  ⟹ n 为偶数时 n₁=n₂=n/2；n 为奇数时差 1
   |S₁−S₂| 最大  ⟹ 个数定死后，让 A₁ 装最小的那一半、A₂ 装最大的那一半
   ⟹ 只需知道"第 ⌊n/2⌋ 小的元素是谁"，前一半自然归 A₁
   ⟹ 不需要全排序，只需 quickselect ⟹ O(n)

第二步：三分支（与综02 一模一样）
   枢轴下标 low == k−1  ⟹ 找到了，收工
   low < k−1            ⟹ 目标在右半区：low0 = ++low;  high = high0;
   low > k−1            ⟹ 目标在左半区：high0 = --high; low  = low0;

第三步：统计并返回
   S₁ = a[0..k−1] 之和（小的一半）、S₂ = a[k..n−1] 之和 ⟹ 返回 S₂ − S₁
📌 ⚠️ 三个必踩的坑，逐个说清：
① low == k-1 里的 −1 从哪来
   k = n/2 是"个数"（A₁ 要装 k 个），low 是"下标"。
   装满 k 个 ⟺ 最后一个占的是下标 k−1 ⟹ 枢轴落在 k−1 时正好切开。
   写成 low==k 就整体错位一格。

② low0 / high0 为什么必须存
   一轮划分跑完后 low 和 high 已经相遇在枢轴处，都不是本轮的边界了。
   下一轮要在"右半区"继续，左边界应是 low+1、右边界应是本轮的 high0
   （而不是被改烂的 high）。不存就会把已确定的那一半又卷进来。

③ 返回 S₂ − S₁ 而不是 S₁ − S₂
   A₁ 装的是小的一半 ⟹ S₁ < S₂ ⟹ |S₁−S₂| = S₂ − S₁ ≥ 0。
   写反了会返回负数。
📌 为什么是"迭代"而不是"递归"：书上这份用 while(flag) 循环代替递归，是尾递归消除的手写版——因为每轮只往一边走，天然是尾递归。这样空间复杂度才真正是 O(1)（递归版是 O(log₂n) 的栈）。第 3 问答"空间 O(1)"的底气就在这里，考场上最好写一句"算法为迭代实现，不使用递归栈"。
⚠️ n 为奇数时 k = n/2 是整除（⌊n/2⌋）：如 n=5 时 k=2，A₁ 装 2 个、A₂ 装 3 个，|n₁−n₂| = 1 已是最小。C 语言的整数除法自动向下取整，不用额外处理——但要在答卷上点明这一点。
⚠️ 本算法就地重排原数组，返回后 a[0..k−1] 就是 A₁、a[k..n−1] 就是 A₂。阅卷时"能指出划分结果就在原数组里"也是采分点。
