其之壹x86 速读

这里用 Intel 风格：mov dest, src，目的在前。32 位 x86 的寄存器：eax（累加，存返回值）、ebx、ecx（计数）、edx、esp（栈顶）、ebp（当前栈帧底）、esi、edi。

指令含义
mov a, ba ← b
mov eax, [ebp+8]从内存取：eax ← M[ebp+8]
lea eax, [ebx+ecx*4]取地址不访存：eax ← ebx+ecx×4，也常用来做乘加
add/sub/imul/shl/sar加/减/乘/左移/算术右移
cmp a, b test a, a只改标志位不存结果
jmp L无条件转移
je jne等于/不等于
jg jge jl jle有符号比较
ja jae jb jbe无符号比较
push x pop xesp-=4; M[esp]=x / x=M[esp]; esp+=4
call f压入返回地址，跳到 f
ret弹出返回地址到 EIP
leavemov esp,ebp; pop ebp
束缚

读汇编的三个习惯

  1. [ ] 才是访存；lea 里的 [ ] 不访存。
  2. [ebp+8] 是第一个参数，[ebp−4] 是第一个局部变量。
  3. 看到 cmp，下一条就是条件转移。两条连起来读。

条件码就是第 17 话的标志位。cmp a,b 做 a−b，只更新 ZF、SF、OF、CF，不存结果。jg 判断的是 ZF=0 且 SF=OF，ja 判断的是 CF=0 且 ZF=0。同样的二进制，看有符号还是无符号，由后面的转移指令决定。

其之貳选择与循环

机器没有 if 和 for，只有比较和跳转。

if (a>b) x=a; else x=b;
    mov eax, [ebp+8]     ; a
    cmp eax, [ebp+12]    ; a − b
    jle ELSE             ; 条件取反后跳转
    mov [ebp-4], eax     ; x = a
    jmp END
ELSE:
    mov eax, [ebp+12]
    mov [ebp-4], eax     ; x = b
END:
咒灵
条件是反着写的

C 写 if(a>b)，汇编跳走的条件是 a<=b：条件不成立才跳走，成立就顺序往下做。读的时候翻译成「否则才走 ELSE」。

for (i=0;i<n;i++) sum+=a[i];
    mov ecx, 0              ; i = 0
L1: cmp ecx, [ebp+12]       ; i − n
    jge L2                  ; i>=n 跳出
    mov edx, [ebp+8]        ; 取数组首地址 a
    mov eax, [edx+ecx*4]    ; 变址寻址 a[i]，每元素 4 字节
    add [ebp-4], eax        ; sum += a[i]
    add ecx, 1
    jmp L1
L2:

循环有三个特征：开头有比较和向外的跳转，中间有变址，末尾有向回的 jmp。向回跳的转移是后面控制冒险和分支预测的主要对象，也是时间局部性的来源。

其之參函数调用：栈帧

函数调用要解决四件事：参数怎么传、怎么回来、局部变量放哪、调用前的寄存器怎么还原。全部靠栈，这正是 第 04 话说的递归工作栈的真实形状。

▣ 一次调用的完整过程
调用前：main 把实参从右向左压栈（`push`）。
`call f`：把下一条指令的地址（返回地址）压栈，然后跳到 f。
f 的开头：保存 main 的 ebp，然后让 ebp=esp。这两句是函数开头的固定两行。
开辟局部变量空间。之后参数和局部变量都用 ebp 定位。
`leave`（恢复 esp、ebp），`ret` 弹出返回地址到 EIP。返回值放在 eax。

一个完整的小函数：

int add(int x, int y) { int s = x + y; return s; }
add:
    push ebp             ; 保存调用者的帧
    mov  ebp, esp        ; 建立本帧
    sub  esp, 16         ; 开局部变量空间
    mov  edx, [ebp+8]    ; x
    mov  eax, [ebp+12]   ; y
    add  eax, edx
    mov  [ebp-4], eax    ; s = x + y
    mov  eax, [ebp-4]    ; 返回值放 eax
    leave                ; esp=ebp，弹出旧 ebp
    ret                  ; 弹出返回地址

为什么是 [ebp+8]？ebp 指向的是旧 ebp，往上 4 字节是返回地址，再往上才是第一个参数。

寄存器谁来保存：函数都要用寄存器，被调函数改了怎么办？约定如下。调用者保存：eax、ecx、edx，调用前如果还要用，自己先压栈。被调用者保存：ebx、esi、edi，被调函数要用就先压栈，返回前恢复。

术式
函数调用五句话

① 参数从右向左压栈；第一个参数离 ebp 最近，[ebp+8]。
② call 压返回地址；ret 弹返回地址。
③ 函数开头：push ebp; mov ebp, esp。
④ 返回值放 eax。
⑤ 递归调用 n 层，就有 n 个栈帧；栈溢出就是这里用完了。

合上页面说一遍：画出栈帧，标出第一个参数、返回地址、旧 ebp、第一个局部变量的位置。

从高到低：参数 [ebp+8]、返回地址 [ebp+4]、旧 ebp [ebp]、局部变量 [ebp−4]。

从机器码读地址

call 常用相对寻址：机器码里存的偏移 = 目标地址 − 下一条指令地址。比如 call 在 00401020H，长 5 字节，目标 00401000H：偏移 = 00401000H − 00401025H = FFFFFFDBH（−37）。按小端写进机器码就是 E8 DB FF FF FF。

一段函数的长度 = 最后一条指令的地址 + 该指令长度 − 第一条地址。

其之肆从源程序到可执行文件

术式
三个工具各自干什么

编译器：C → 汇编（.s）。
汇编器：汇编 → 可重定位目标文件（.o），每个模块地址从 0 开始。
链接器：两个任务，① 符号解析（把引用和定义对应），② 重定位（合并各段，把相对地址改成运行时地址）。
静态链接：库代码直接进文件；动态链接：运行时才链接，节省内存、方便升级。

其之伍CISC 与 RISC

CISC 的思路是硬件多做事，一条指令干很多，代码短。后来发现常用的只是一小部分（80% 的时间在跑 20% 的指令），于是 RISC 把指令精简，把常用的做快。

CISC（x86）RISC（ARM/RISC-V）
指令多，长度不固定少（常用的）、定长
寻址多少
访存很多指令都能访存只有 Load/Store
周期一条多周期大多一条一周期
控制器微程序为主硬布线为主
寄存器少多
流水线实现难天生适合
领域展开

读：[]才访存，cmp 连条件转移读，C 条件反写。
栈帧：[ebp+8] 是参数，[ebp−4] 是局部变量；返回值 eax。
链接：符号解析 + 重定位。
RISC：定长、Load/Store、硬布线、适合流水线。

【第 3 问 · 本题的计算核心，三小问一条链】
① 第 17 行地址 = 第 16 行地址 + call 指令长度
   call 机器码 E8 D6 FF FF FF ⟹ 【5 字节】
   ⟹ 00401025H + 5 = 【0040102AH】✔

② 偏移量 = 目标地址 − 【下一条指令地址】
   = 00401000H − 0040102AH = −2AH
   32 位补码 = 【FFFFFFD6H】✔

③ 判端序：机器码里偏移量字段按字节写作 D6 FF FF FF
   数值是 FFFFFFD6H（高位在左），机器码是 D6 在最前（低地址）
   ⟹ 低字节存在低地址 ⟹ 【小端】✔
📌📌 三小问其实是同一条链的三段：指令长度（数机器码字节）→ 下一条地址 → 偏移量 → 端序。「+5」这一步既定了第 17 行地址，又定了偏移量的基准，一步错则两问错。

【第 5 问 · imul 的 OF 判据 + 自陷指令】
32×32 位乘法 ⟹ 完整乘积 64 位（高 32 位在 edx、低 32 位在 eax）
但 imul eax,ecx 只保留低 32 位

不溢出 ⟺ 完整的 64 位乘积能被低 32 位【无损表示】
      ⟺ 【高 33 位（高 32 位 + 低 32 位的符号位）全为 0 或全为 1】
         （正数：高位全 0；负数：高位全 1）
⟹ 高 33 位【不】全为 0 且【不】全为 1 时，OF = 1 ✔

📌📌 「高 33 位」而不是「高 32 位」，那多出的一位是低 32 位的符号位——因为要保证截断后符号不变。这一条是本问的采分点，写成"高 32 位"要扣分。
🔗 溢出自陷 ⟹ ch5 异常与中断机制 / OS 的异常处理；与 2025 真题（4.3-综07）的除法异常是同一条线：乘法溢出靠"自陷指令主动查"，除法异常则由硬件直接检测。
2019實戰分页判断是否同页 · Cache 地址划分 · VIPT：组号可从虚拟地址低位取
对于题 4.3-综02（2019 真题 f1 递归求阶乘），若计算机 M 的主存地址为 32 位，采用分页存储管理方式，页大小为 4KB，则第 1 行的 push 指令（虚拟地址 0040 1000H）和第 30 行的 ret 指令（虚拟地址 0040 104AH）是否在同一页中（说明理由）？若指令 Cache 有 64 行，采用 4 路组相联映射方式，主存块大小为 64B，则 32 位主存地址中，哪几位表示块内地址？哪几位表示 Cache 组号？哪几位表示标记（tag）信息？读取第 16 行的 call 指令（虚拟地址 0040 1025H）时，只可能在指令 Cache 的哪一组中命中（说明理由）？
因为页大小为 4KB，所以虚拟地址的高 20 位为虚拟页号。第 1 行的 push 指令和第 30 行的 ret 指令的虚拟地址的高 20 位都是 00401H，因此两条指令在同一页中。
指令 Cache 有 64 块，采用 4 路组相联映射方式，因此指令 Cache 共有 64/4 = 16 组，Cache 组号共 4 位。主存块大小为 64B，因此块内地址为低 6 位。综上所述，在 32 位主存地址中，低 6 位为块内地址，中间 4 位为组号，高 22 位为标记。
因为页大小为 4KB，所以虚拟地址和物理地址的最低 12 位完全相同，因此 call 指令虚拟地址 0040 1025H 中的 025H = 0000 0010 0101B 为物理地址的低 12 位，对应的 7～10 位为组号，因此对应的 Cache 组号为 0。
同一题的后半：页大小 4 KB，高 20 位是页号，比较两条指令是否同页；再把低 12 位拆成 Cache 的标记、组号、块内地址。这部分学完 Cache 回来就懂了。
再深一层
⭐ 本题是 ch4 与 ch3 的接缝题，三问分别对应「分页 / Cache 划分 / VIPT」。
【第 1 问 · 是否同页：只看高 20 位】
页大小 4KB = 2¹² ⟹ 页内偏移 12 位 ⟹ 虚页号 = 高 20 位

  push : 0040 1000H = 0000 0000 0100 0000 0001 | 0000 0000 0000
  ret  : 0040 104AH = 0000 0000 0100 0000 0001 | 0000 0100 1010
                      └────── 高 20 位都是 00401H ──────┘
⟹ 两条指令【在同一页】✔
📌 速判技巧：4KB 页 ⟹ 十六进制地址的后三位是页内偏移，前五位是页号。00401|000 与 00401|04A，前五位都是 00401 ⟹ 同页。一眼就能看出来，不用展开二进制。
【第 2 问 · Cache 三段划分】
Cache 有 64 行、4 路组相联 ⟹ 组数 = 64 ÷ 4 = 16 = 2⁴ ⟹ 组号 4 位
主存块大小 64B = 2⁶            ⟹ 块内地址 6 位
标记位数 = 32 − 4 − 6          ⟹ 22 位

  31                    10  9      6  5        0
 ┌────────────────────────┬─────────┬───────────┐
 │      标记 tag（22）     │ 组号（4）│ 块内（6） │
 └────────────────────────┴─────────┴───────────┘
⟹ 低 6 位块内地址、第 6~9 位组号、高 22 位标记 ✔
⚠️ 书答写「7～10 位为组号」是按从第 1 位数起的口径（第 1 位 = 最低位）；若按程序员习惯的 bit 0 起编号，就是 bit 6～bit 9。两种写法都对，答题时把位置说清楚即可。
【第 3 问 · VIPT：组号能直接从虚拟地址取】
关键前提：页大小 4KB ⟹ 虚拟地址与物理地址的【低 12 位完全相同】
         （页内偏移不参与地址转换）

而组号 + 块内地址 = 4 + 6 = 10 位 ≤ 12 位 ✔
⟹ 组号完全落在"低 12 位"之内 ⟹ 不用等地址转换就能取出来

call 虚拟地址 0040 1025H，低 12 位 = 025H = 0000 0010 0101B
  bit5~bit0 = 100101  ⟹ 块内地址
  bit9~bit6 = 0000    ⟹ 【组号 = 0】✔
📌📌 这就是 ch3 学过的 VIPT（虚拟索引 + 物理标记）技巧：只要 (Cache 组号位数 + 块内地址位数) ≤ 页内偏移位数，Cache 组号就可以直接从虚拟地址低位取，与 TLB 查表并行进行，省掉一次串行等待。（2018、2025 两年的 ch3 真题都考过这个不等式，且都恰好取等号；本题是 10 ≤ 12，留了余量。）
⚠️ 「只可能在哪一组命中」的答题要点：先说明"虚实地址低 12 位相同"这个前提，再算组号 = 0，最后点明"因为组号由地址唯一决定，所以该指令只可能落在第 0 组的 4 路中的某一路"。三段缺一不可。
2017實戰由指令长短判 CISC/RISC · 由首末指令虚拟地址算代码长度 · 减法 C
在按字节编址的计算机 M 上，f1 的部分源程序（阴影部分）如下。将 f1 中的 int 都改成 float，可得到计算 f(n) 的另一个函数 f2。
int f1(unsigned n){
    int sum=1, power=1;
    for(unsigned i=0;i<=n-1;i++){
        power *=2;
        sum += power;
    }
    return sum;
}
对应的机器级代码（包括指令的虚拟地址）如下（依次为行号、虚拟地址、机器指令、汇编指令）：
        int f1( unsigned n)
 1   00401020   55         push ebp
 …      …        …          …
        for( unsigned i=0; i<= n−1; i++)
 …      …        …          …
20   0040105E   39 4D F4   cmp dword ptr [ebp−0Ch],ecx
 …      …        …          …
        power *= 2;
23   00401066   D1 E2      shl edx,1
 …      …        …          …
        return sum;
35   0040107F   C3         ret
1）计算机 M 是 RISC 还是 CISC？为什么？
2）f1 的机器指令代码共占多少字节？要求给出计算过程。
3）第 20 条指令 cmp 通过 i 减 n−1 实现对 i 和 n−1 的比较。执行 f1(0) 的过程中，当 i = 0 时，cmp 指令执行后，进位/借位标志 CF 的内容是什么？要求给出计算过程。
4）第 23 条指令 shl 通过左移操作实现了 power *2 运算，在 f2 中能否用 shl 指令实现 power *2？为什么？
1）M 为 CISC。M 的指令长短不一，不符合 RISC 指令系统的特点。
2）f1 的机器代码占 96B。因为 f1 的第一条指令「push ebp」所在的虚拟地址为 0040 1020H，最后一条指令「ret」所在的虚拟地址为 0040 107FH，所以 f1 的机器指令代码长度为 0040107FH − 00401020H + 1 = 60H = 96B。
3）CF = 1。cmp 指令实现 i 与 n−1 的比较功能，进行的是减法运算。在执行 f1(0) 的过程中，n = 0，当 i = 0 时，i = 0000 0000H，并且 n−1 = FFFF FFFFH。因此，执行第 20 条指令时，在补码加/减运算器中执行「0 减 FFFF FFFFH」操作，即 0000 0000H + 00000000H + 1 = 0000 0001H，此时进位输出 Cout = 0，低位进位 Sub = 1，CF = Cout ⊕ Sub = 0 ⊕ 1 = 1。
4）f2 中不能用 shl 指令实现 power*2。因为 shl 指令把一个整数的所有有效数位整体左移，而 f2 中的变量 power 是 float 型，其机器数中不包含最高有效数位，但包含了阶码部分，将其作为一个整体左移时并不能实现「乘以 2」的功能，因此 f2 中不能用 shl 指令实现 power *2。浮点数运算比整型运算要复杂，耗时也较长。
这是 第18话 那道 f1 的汇编版：长度由首末地址算（0040107FH−00401020H+1 = 96B）；第 3 问用 CF=1 解释 n=0 时的死循环，把 无符号比较落到了真实的机器级。
再深一层
⭐ 这道 2017 真题四问横跨四章：4.4（CISC/RISC）· 4.3（代码长度）· ch2（标志位与浮点表示）。
【第 1 问 · 从机器码长短判 CISC】
看给出的三条指令的机器码字节数：
  push ebp  →  55           1 字节
  cmp …     →  39 4D F4     3 字节
  shl edx,1 →  D1 E2        2 字节
  ret       →  C3           1 字节
⟹ 【指令长短不一】= 变长指令字
  ⟹ 不符合 RISC「指令长度固定」⟹ 【CISC】✔
📌 答这一问只需一句话 + 一个证据：「M 为 CISC，因为其指令长度不固定（1～3 字节不等），而 RISC 要求指令定长」。别写成"因为是 x86"——题目没说这是 x86，要从给的数据里找证据。
【第 2 问 · 代码长度 = 末地址 − 首地址 + 末条指令长度】
首条指令 push ebp 在 00401020H
末条指令 ret     在 0040107FH，机器码 C3 ⟹ 长度 1 字节

总长度 = 0040107FH − 00401020H + 1 = 5FH + 1 = 60H = 96 字节 ✔
⚠️⚠️ 那个「+1」是采分点，含义是「最后一条指令自身的长度」。本题恰好 ret 只占 1 字节，所以 +1；若末条指令占 3 字节，就该 +3。——通用式：代码长度 = 末条指令地址 − 首条指令地址 + 末条指令长度。
【第 3 问 · CF = Cout ⊕ Sub 的第三次应用】
f1(0) ⟹ n = 0（unsigned）
  n − 1 = 0 − 1 = FFFF FFFFH （无符号回绕！这是本问的题眼）
  i = 0 = 0000 0000H

cmp 做的是 i − (n−1) = 0000 0000H − FFFF FFFFH
  补码减法 = 被减数 + 减数取反 + 1：
    0000 0000H + 0000 0000H + 1 = 0000 0001H
    （FFFF FFFFH 逐位取反 = 0000 0000H）

  进位输出 Cout = 0（这一加没产生进位）
  减法 Sub = 1
  CF = Cout ⊕ Sub = 0 ⊕ 1 = 【1】✔（表示"借位了"，
  即 0 < FFFFFFFFH，符合无符号语义）
📌📌 本问真正想考的是「unsigned 的 n−1 在 n=0 时会回绕成 FFFFFFFFH」——这正是源程序里 i<=n-1 用 unsigned 写出来的经典 bug：f1(0) 本该一次循环都不做，实际却会循环 2³² 次。题目用 CF = 1 把这个坑量化了出来。
【第 4 问 · float 不能靠移位 ×2】
int 的机器数：全部 32 位都是【有效数位】
   ⟹ 整体左移 1 位 = 每一位权重翻倍 = ×2 ✔

float 的机器数：[符号 1][阶码 8][尾数 23]
   · 尾数是【规格化】的，最高有效位 1 被隐含掉了（不在机器数里）
   · 阶码是【移码】，混在同一串位里
   ⟹ 整体左移会把阶码也一起移走，得到的是一个毫无意义的数 ✘

   float 的 ×2 正确做法：【阶码 +1】，尾数不动
📌 书答的两个关键词一个都不能少：「不包含最高有效数位（隐含位）」+「包含了阶码部分」。🔗 直通 ch2 浮点数的表示——移位对定点数是乘除 2，对浮点数完全不成立。
2009實戰RISC 用硬布线控制器
下列关于 RISC 的说法中，错误的是（　）。

相对于 CISC，RISC 的特点是：指令条数少；指令长度固定，指令格式和寻址种类少；只有取数/存数指令访问存储器，其余指令的操作均在寄存器之间进行；CPU 中通用寄存器多；大部分指令在一个时钟周期内完成；以硬布线逻辑为主，不用或少用微程序控制。B、C 和 D 都是 RISC 的特点。RISC 的速度快，因此普遍采用硬布线控制器，选项 A 错误。
再深一层
选 A（本题选错误项）。控制器类型是 CISC/RISC 最硬的一条分界线：
CISCRISC
控制方式绝大多数为微程序控制绝大多数为组合逻辑（硬布线）控制
为什么指令复杂、执行步骤多变，用微程序（"软件方式"写控制流程）才写得出来指令简单规整、单周期完成，硬布线电路直接译码更快
代价控存占 CPU 芯片面积 50% 以上逻辑电路仅占约 10%
📌📌 那组 50% vs 10% 的数字出自 4.4.3 节第 1 条「更高效利用芯片面积」，是本节唯一的定量结论，很好记也很好考。
📌 因果链要能串起来：
RISC 要"大多数指令单周期完成"（B 项）
  ⟹ 控制信号必须在一个周期内产生 ⟹ 只能【硬布线】
  ⟹ 微程序那种"逐条读控存微指令"的方式太慢，用不了

⟹ A 项说 RISC「普遍采用微程序控制器」与 B 项【自相矛盾】
⚠️ 本题可以用「选项间自洽性」秒杀：B 说单周期完成、A 说用微程序控制，两者不可能同时成立，而 B 是公认的 RISC 特点 ⟹ A 必错。
