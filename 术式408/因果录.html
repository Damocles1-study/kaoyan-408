第00话战场地图

因果

书上隔得最远、真题连得最紧的五组

栈 ↔ 函数调用与栈帧（第04话 ↔ 第20话）｜中断 ↔ 内核态 ↔ DMA（第23话 ↔ 第39话）｜Cache ↔ TLB ↔ 页表（第31话 ↔ 第33话）｜B⁺ 树 ↔ 多级索引 ↔ 多级页表（第13话 ↔ 第35话 ↔ 第33话）｜滑动窗口：链路层 ↔ TCP（第43话 ↔ 第49话）。

因果

因果｜跨章跨科的连接

这一点和别处是同一回事。汇总进 因果录。

第04话栈与队列

因果

这个栈是真实存在的

第 20 话讲 x86 的 call、ret、ebp、esp 时，你会看到这张图的真实形态：返回地址和旧 ebp 都在这里。2017 年组原大题就考过看汇编分析递归调用。

第05话数组、矩阵与串

因果

同一个公式还要用两次

这个行优先规则是 Cache 考命中率的根据：a[i][j] 按行访问时空间局部性好，按列访问 Cache 容易频繁缺失。真题多次考这件事。

第07话线索、森林、哈夫曼与并查集

因果

并查集的三个应用

判断无向图连通分量数；Kruskal 判断加边是否成环；判断两个元素是否等价。选择题问「Kruskal 用什么数据结构」答并查集。

第08话二叉搜索树、AVL 与红黑树

因果

工程中的使用

Linux 的 CFS 调度器和 Java 的 TreeMap 用红黑树；MySQL 索引和文件系统用 B⁺ 树，因为后者更矮，适合磁盘。

第10话最小生成树与最短路径

因果

这是网络的路由算法

OSPF 用的就是 Dijkstra；RIP 用的距离向量，是 Bellman-Ford 思想。2014 年那道标着「图」的大题，实际上要你看懂路由表。

第13话B 树与 B⁺ 树

因果

同一个思想反复出现

B⁺ 树的「多叉 + 矮 + 按块读」和 多级索引 inode、多级页表 是一回事：用一个块能装多少指针，决定树有多宽。每层多访问一次磁盘或内存。

第15话选择、归并、基数、外排与总表

因果

最佳归并树 = 哈夫曼树

第 07 话 那道 6 个有序表的大题就是它。这个道理就是：先合并的部分被多读写几次，所以把小的放在最下面。

第17话定点数：补码与运算电路

因果

移位 + 加法替代乘法

x*5 = (x<<2)+x。机器级代码里 lea、shl 出现，编译器就是这么做的。在读汇编题时要能看出来。

第20话程序的机器级表示

因果

2019 年这道大题就是把这些全考一遍

下面这道 f1 求 n!：判断递归的栈帧、看 imul 的溢出、再问字节数和页号。它把 溢出、第20话 和 分页串在了一道题里。

第23话中断、异常与内核态

因果

多重中断与屏蔽字

中断屏蔽字的计算放在 第 39 话，和 I/O 一起讲。这里只需要记住开中断是由 OS 软件做的。

第27话互斥的实现：从锁到信号量

因果

自旋锁

TSL 就是自旋锁的实现。大纲的「锁」这一条，就是说这个：单处理器开销大；多处理器且锁很快释放时，自旋比阻塞还便宜（省去一次进程切换）。这个结论是一个分界线。

第29话死锁

因果

这张图也是图论

资源分配图：资源和进程作为顶点。死锁定理：化简之后还有边 ⟺ 死锁。化简就是 拓扑排序的思路：不断去掉可以运行完的进程。

第30话主存：芯片与连接

因果

跨科第一枢纽

局部性原理 → Cache / TLB / 页面置换 LRU / 磁盘预读。题干看到「命中率为什么高」，答案就是局部性。

因果

这也是 第31话 的命中开销

Cache 块往往比总线宽。缺失时从主存读一块用的就是低位交叉，2013 年大题就这么出。

第32话内存管理基础

因果

接上之前的知识

.text、.data、.bss 就是 第 20 话 目标文件里的那些节。栈和堆之间的那一大片空着没用，这就是虚拟内存的用武之地：没有用到的地方不用占物理内存。

因果

这就是一棵树

多级页表是多叉树，根是页目录。和 B 树、多级索引 inode是同一个算法：一块能放多少指针，决定每层多宽。

第36话文件系统

因果

分区和格式化

物理格式化、分区、逻辑格式化在 下一话 讲。逻辑格式化正是在建立上面这些结构（根目录、空闲表、超级块）。

第43话链路层：可靠传输

因果

同一个窗口

TCP 用的也是滑动窗口，只是单位变成字节，累积确认 + 快重传更接近 GBN 和 SR 的混合。

第49话TCP 可靠、流控与拥塞

因果

滑动窗口的三次使用

链路层 GBN/SR、传输层 TCP、以及 LRU 工作集 的「窗口」，形状都一样。链路层是帧，TCP 是字节；链路层是确定的物理线路，TCP 还要多一个 cwnd。
