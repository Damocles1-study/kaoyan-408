先答旧题
互斥信号量和同步信号量的初值分别是？
互斥 1，同步 0，资源等于数量。
同步的 P 和 V 分别放在哪？
前操作之后 V，后操作之前 P，分在两个进程里。
TSL、Peterson 有什么共同缺陷？
忙等，不满足让权等待。

同步问题的难点不在 P、V 的语法，而在 能否把一段故事翻译成「谁等谁、谁和谁互斥」。这一话给一个固定翻译步骤，然后讲透五个模子。绝大部分同步问题都是它们的变形。

其之壹固定四步

束缚

写同步问题的四步

① 关系分析：谁和谁互斥，谁和谁同步。写成句子。 ② 定义信号量：每个互斥一个 mutex=1；每种资源一个，初值 = 数量；每个同步一个，初值 = 0。写清含义和初值。 ③ 写进程：先写出动作骨架，再插入 P、V。 ④ 检查：同步 P 在互斥 P 之前；每个 P 都有配对的 V；并发度是否最大。

咒灵
三个常见错误

① 只写 semaphore，不写初值和含义。 ② 互斥和同步的 P 次序反了，导致死锁。 ③ 把判断写在 mutex 外面：if (count==0) P(rw) 的判断和修改必须在同一个 mutex 内，否则判断时的值已经过时。

其之貳模子一：生产者-消费者

一个缓冲区，有 n 个空位。生产者放，消费者取。翻译：

  • 互斥：缓冲区一次只能一人动，mutex = 1。
  • 同步：满了生产者等消费者；空了消费者等生产者。
  • 资源：empty = n（空位数），full = 0（产品数）。
生产者消费者（缓冲区 n）
semaphore mutex = 1, empty = n, full = 0;

producer() {
    while (1) {
        生产;
        P(empty);       // 先申请空位（同步）
        P(mutex);       // 再申请缓冲区（互斥）
        放入;
        V(mutex);
        V(full);
    }
}
consumer() {
    while (1) {
        P(full);
        P(mutex);
        取走;
        V(mutex);
        V(empty);
        消费;
    }
}
如果把 producer 的 P(empty)、P(mutex) 交换，缓冲区满时会发生什么？

生产者先拿到 mutex，然后 P(empty) 阻塞。消费者要 P(mutex) 才能取走，也阻塞。两人互等，死锁。所以「同步 P 在前，互斥 P 在后」。

最容易见到的变形：

  • 多种产品：每种产品一个 full 型信号量（比如 odd、even），共用 empty 和 mutex。
  • 一次取多个：多一个信号量，让消费者之间排队，保证这一批不被别人打断。
  • 双向：两个人互相写信，就是两组生产者消费者叠在一起。

其之參模子二：读者-写者

读可以同时，写必须独占。如果读者每人都要 P(rw)，那读者之间也互斥了。怎样让读者共用？让第一个读者上锁，最后一个读者解锁，中间的读者直接进。这要有一个计数器，计数器本身也要保护。

读者优先
int count = 0;
semaphore mutex = 1;    // 保护 count
semaphore rw = 1;       // 读写互斥

writer() {
    P(rw); 写; V(rw);
}
reader() {
    P(mutex);
    if (count == 0) P(rw);     // 第一个读者负责占坑
    count++;
    V(mutex);
    读;
    P(mutex);
    count--;
    if (count == 0) V(rw);     // 最后一个读者负责放坑
    V(mutex);
}

问题：读者接连不断地来，写者永远轮不到。改法：

术式
写者优先（读写公平）的改法

多加一个 w=1，读者和写者都先 P(w)。读者拿到 count 之后就 V(w)；写者写完才 V(w)。写者一来占住 w，后面的读者就进不去了。

看到什么想到读者写者

「多个 A 可以同时，但 A 和 B 互斥」「第一个开门、最后一个关门」。比如过独木桥（同方向一起走）。

其之肆模子三：哲学家进餐

5 个人围坐，5 根筷子放在两人之间，每人要拿到左右两根才能吃。每根筷子是一个互斥信号量。

如果每人都先拿左边的，5 人同时拿，每人都等右边那根，就是死锁。

术式
三种解法

① 限制人数：最多 4 人同时拿筷子，就至少有一人能拿到两根。
② 奇偶法：奇数号先左后右，偶数号先右后左，破坏环。
③ 一次拿两根：拿筷子的动作用一个 mutex 保护。

限制上桌人数
semaphore chopstick[5] = {1,1,1,1,1};
semaphore room = 4;        // 最多 4 人同时拿筷子

philosopher(int i) {
    while (1) {
        P(room);
        P(chopstick[i]);
        P(chopstick[(i + 1) % 5]);
        吃;
        V(chopstick[(i + 1) % 5]);
        V(chopstick[i]);
        V(room);
        思考;
    }
}

吸烟者问题是另一种资源分配：一个供应者轮流放两样材料，三个吸烟者各缺一样。供应者放了哪两样，就 V 对应的吸烟者，等他抽完再放下一轮。本质上是一个缓冲区、多种产品的生产者消费者。

其之伍模子四：前驱关系

一个操作结束后，另一个才能开始。每一条边一个信号量，初值 0。

前驱图的写法
semaphore a1=0, a2=0, b1=0, b2=0, c=0, d=0, e=0;
S1() { 做; V(a1); V(a2); }
S2() { P(a1); 做; V(b1); V(b2); }
S3() { P(a2); 做; V(e); }
S4() { P(b1); 做; V(c); }
S5() { P(b2); 做; V(d); }
S6() { P(c); P(d); P(e); 做; }

这和 拓扑排序是同一张图：入度就是这个结点开头要 P 几次。

其之陸模子五：理发师（有界排队）

银行取号、博物馆、公交车都是它：有座位限制，加一个服务员。

翻译：一个计数器记录等待人数，由 mutex 保护；顾客到了要叫醒服务员（customers），然后等服务员就位（barbers）。这是一对方向相反的同步。

顾客与服务员
int waiting = 0;                 // 等待人数，受 mutex 保护
semaphore mutex = 1;
semaphore customers = 0;         // 同步：有顾客了
semaphore barbers = 0;           // 同步：服务员准备好了

customer() {
    P(mutex);
    if (waiting < N) {
        waiting++;
        V(customers);            // 叫醒服务员
        V(mutex);
        P(barbers);              // 等服务员
        接受服务;
    } else V(mutex);             // 座位满，离开
}
barber() {
    while (1) {
        P(customers);            // 没顾客就睡
        P(mutex);
        waiting--;
        V(barbers);
        V(mutex);
        服务;
    }
}

注意 else 分支也要 V(mutex)。每条路径都要放开拿到的锁，这是最常见的笔误。

有时候不用计数器：如果多出来的人只是等而不是走，直接用资源信号量（初值 = 座位数）就行。只有「人满就走」这种要判断的场景才要计数器，因为 P 操作判断不了「能不能拿到」，它只会阻塞。

合上页面说一遍：合上页面，默写生产者消费者和读者优先。

生产者：P(empty) P(mutex) 放 V(mutex) V(full)。消费者：P(full) P(mutex) 取 V(mutex) V(empty)。读者：P(mutex)，count0 时 P(rw)，count++，V(mutex)，读，P(mutex)，count--，count0 时 V(rw)，V(mutex)。

领域展开

四步：关系、定义（写初值）、骨架、检查。
五个模子：生产消费、读者写者（首尾开关门）、哲学家（限人数）、前驱（每边一信号量）、理发师（计数 + 叫号）。
顺序：同步 P 先，互斥 P 后。

2009實戰一个生产者两个挑食的消费者 · full 按类型拆分
三个进程 P₁、P₂、P₃ 互斥使用一个包含 N（N > 0）个单元的缓冲区。P₁ 每次用 produce() 生成一个正整数并用 put() 送入缓冲区某一空单元；P₂ 每次用 getodd() 从该缓冲区中取出一个奇数并用 countodd() 统计奇数个数；P₃ 每次用 geteven() 从该缓冲区中取出一个偶数并用 counteven() 统计偶数个数。请用信号量机制实现这三个进程的同步与互斥活动，并说明所定义的信号量的含义（要求用伪代码描述）。
解：
互斥资源：缓冲区只能互斥访问 ⟹ mutex。
同步问题：P₁ 与 P₂ 因奇数的放置与取用而同步 ⟹ odd；P₁ 与 P₃ 因偶数的放置与取用而同步 ⟹ even；P₁、P₂、P₃ 因共享缓冲区而同步 ⟹ empty，初值为 N。
semaphore mutex = 1;      // 缓冲区操作的互斥信号量
semaphore odd = 0;        // 缓冲区中奇数的个数
semaphore even = 0;       // 缓冲区中偶数的个数
semaphore empty = N;      // 缓冲区中空单元的个数

Process P1(){ while(True){
    x = produce();                    // 生成一个正整数
    P(empty); P(mutex); Put(); V(mutex);
    if(x % 2 == 0) V(even);           // 偶数，通知 P3
    else           V(odd);            // 奇数，通知 P2
}}

Process P2(){ while(True){
    P(odd);  P(mutex); getodd();  V(mutex);
    V(empty); countodd();
}}

Process P3(){ while(True){
    P(even); P(mutex); geteven(); V(mutex);
    V(empty); counteven();
}}
2009。缓冲区 + 两种产品：奇数信号量 odd，偶数信号量 even，一个 empty，一个 mutex。P1 生产后根据奇偶 V 不同的那个。这是模子一的直接分叉。
再深一层
一致。🐍 PV 穷举器验证（N=2，P₁ 依次产「奇偶奇」，276 个状态）：无死锁，缓冲区占用恒在 [0, N] ✓

💭 思路（动手前看）
  1. 先照标准模型下笔：N 个单元的缓冲区 + 一放两取 ⟹ empty = N、mutex = 1。写到 full 时停一下。
  2. ⭐ 核心一问：一个 full 够不够？
    若只用一个 full：
  缓冲区里全是偶数，full = 3
  P₂（只吃奇数）执行 P(full) 顺利通过
  ⟹ 它进了临界区却找不到奇数 ⟹ 逻辑崩溃
⟹ 必须让「等待」这件事本身就区分类型
    ⟹ full 拆成 odd 与 even 两个，各数各的。
  3. 谁来分流：只有 P₁ 知道自己刚放的是奇是偶 ⟹ 由 P₁ 在放完之后判断 x % 2，决定 V(odd) 还是 V(even)。
  4. empty 由谁 V：P₂、P₃ 谁取走谁归还 ⟹ 两边都要写 V(empty)。
✍️ 考场卷面（写完对照）
解：定义四个信号量： ⛳3 分
  mutex = 1   互斥使用缓冲区
  empty = N   缓冲区中的空单元数
  odd   = 0   缓冲区中已有的奇数个数
  even  = 0   缓冲区中已有的偶数个数

P₁：while(true){                       ⛳3 分
  x = produce();
  P(empty);
  P(mutex); put(x); V(mutex);
  if(x 为奇数) V(odd); else V(even);
}

P₂：while(true){                       ⛳1 分
  P(odd);
  P(mutex); getodd(); V(mutex);
  V(empty);
  countodd();
}

P₃：while(true){                       ⛳1 分
  P(even);
  P(mutex); geteven(); V(mutex);
  V(empty);
  counteven();
}

empty 保证不写满，odd/even 分别保证 P₂、P₃ 只在
有对应类型数据时才取，mutex 保证互斥访问缓冲区。
📌 批注（对照完校对）
⭐⭐ 本题的通用启示：当消费者「挑食」时，full 必须按产品类型拆开。这是本章出现频率最高的一个变形：教材的「苹果橘子」（apple/orange 两个）、综 16 吸烟者（offer1/2/3 三个）、本题（odd/even 两个）——同一个手法的三种规模。
⚠️ V(odd)/V(even) 必须写在 V(mutex) 之后吗？不必须——两个 V 都不会阻塞，顺序可换。但 if 判断本身要放在 put() 之后（此时才知道放进去的是什么），而且绝不能把 if 判断放到 P(mutex) 之前。
⚠️ empty 不能拆：空单元就是空单元，不分奇偶——拆了反而会造成「奇数格空着但偶数格满了」这种不存在的限制。判据：拆的是「产品」，不是「空位」。
⭐ 为什么 odd + even 不等于 full 就没关系：它们的和恒等于缓冲区中的数据个数，而 empty + (odd + even) = N 始终成立——🐍 穷举器验证了这个不变式在全部 276 个状态中都保持。
🔗 与综 04（两货架装配）恰成镜像：综 04 是「两个生产者、一个消费者要取两种货」，本题是「一个生产者、两个消费者各吃一种货」。
2014實戰周期性独占 · 把 P(mutex) 提到循环外
系统中有多个生产者进程和多个消费者进程，共享一个能存放 1000 件产品的环形缓冲区（初始为空）。缓冲区未满时，生产者进程可以放入其生产的一件产品，否则等待；缓冲区未空时，消费者进程可以从缓冲区取走一件产品，否则等待。要求一个消费者进程从缓冲区连续取出 10 件产品后，其他消费者进程才可以取产品。请使用信号量 P、V 操作实现进程间的互斥与同步，要求写出完整的过程，并说明所用信号量的含义和初值。
解：这是典型的生产者-消费者问题，只加了一个条件，只需在标准模型上新加一个信号量：mutex1 控制生产者之间互斥，mutex2 控制一个消费者在一个周期（10 次）内对缓冲区的访问。
semaphore empty = 1000;   // 空缓冲区数
semaphore full = 0;       // 非空缓冲区数
semaphore mutex1 = 1;     // 生产者之间的互斥
semaphore mutex2 = 1;     // 消费者之间的互斥
int in = 0, out = 0;

生产者: while(TRUE){
    produce;
    P(empty); P(mutex1);
    put an item into buf[in]; in = (in+1) % n;
    V(mutex1); V(full);
}

消费者: while(TRUE){
    P(mutex2);              // 10 次循环被一个消费者独占
    for(int i = 0; i < 10; i++){
        P(full);
        get an item from buf[out]; out = (out+1) % n;
        V(empty);
    }
    V(mutex2);
    Consume;
}
2014。消费者要连续取 10 件：多一个 mutex1 让消费者之间排队，这样一个消费者取 10 件时不会被其他消费者穿插。放在外面，它保护的是「连续 10 次」这个动作。
再深一层
一致。🐍 PV 穷举器验证（缩为 n=4、连取 2 件、2 个消费者，783 个状态）：无死锁，且不变式「同一时刻至多 1 个消费者处于连取周期内」全程保持 ✓

💭 思路（动手前看）
  1. 先把标准模型写出来：empty = 1000、full = 0、互斥锁若干。本题 90% 是模板，只有一句话是新的。
  2. ⭐ 读懂那句特殊要求：「一个消费者连续取出 10 件后，其他消费者才可以取」⟹ 这不是「取一件要互斥」，而是「取 10 件这整件事要互斥」。互斥的粒度从一次操作扩大到了一个周期。
  3. 于是唯一的技巧浮出水面：
    普通写法：for(10 次){ P(mutex); 取一件; V(mutex); }
          ⟹ 每取一件都可能被别的消费者插队 ✗

本题写法：P(mutex2); for(10 次){ 取一件; } V(mutex2);
          ⟹ 整个周期被独占 ✓
  4. P(full) 留在循环内：每取一件都要确认「有货」，所以 P(full) 必须一件一次。
✍️ 考场卷面（写完对照）
解：定义四个信号量： ⛳4 分
  empty  = 1000  缓冲区中的空闲单元数
  full   = 0     缓冲区中的产品数
  mutex1 = 1     生产者之间互斥使用缓冲区
  mutex2 = 1     消费者之间互斥（以 10 件为一个周期）

生产者：while(TRUE){                   ⛳2 分
  生产一件产品;
  P(empty); P(mutex1);
  将产品放入 buf[in]; in = (in+1) % 1000;
  V(mutex1); V(full);
}

消费者：while(TRUE){                   ⛳4 分
  P(mutex2);            // 申请连续取 10 件的独占权
  for(i = 0; i < 10; i++){
      P(full);
      从 buf[out] 取一件; out = (out+1) % 1000;
      V(empty);
  }
  V(mutex2);            // 10 件取完，释放独占权
  消费这 10 件产品;
}

P(mutex2) 置于 for 循环之外，使一个消费者一旦开始
就会连续取满 10 件，其他消费者在此期间被阻塞。
📌 批注（对照完校对）
⭐⭐ 「把 P 提到循环外」就是本题的全部技巧，也是「周期性独占」的通用写法：要让某一串操作作为整体不被打断，就把互斥锁罩在这一串的外面。凡题目出现「连续 k 次」「一批」「一次性完成」等字眼，都往这个方向想。
⚠️ P(full) 千万不能也提到循环外：提到外面就变成「只确认一件货就取 10 件」，缓冲区会被取空（full 变负 / 取到空单元）。判据：同步信号量按「每件」申请，互斥信号量按「每批」申请——两者粒度不同，这正是本题的精髓。
⭐ 为什么生产者和消费者用两把不同的锁：环形缓冲区有 in、out 两个指针，生产者只动 in、消费者只动 out⟹ 它们操作的其实是不同的临界资源，可以并发。若共用一把 mutex，生产和消费就无法同时进行，并发度减半——按 2017 真题的评分口径，这属于「降低并发度」，是要扣分的。
⚠️ 「消费」动作要放在 V(mutex2) 之后：消费（处理数据）不碰缓冲区，圈进临界区就白白拖长了独占时间。
🔗 本题是 2.3 节里最「标准 + 一处变形」的一道，适合作为背诵模板：先默写标准生产者-消费者，再练这一处提锁。
2015實戰同步信号量初值非 0 · 双向有界缓冲
有 A、B 两人通过信箱进行辩论，每个人都从自己的信箱中取得对方的问题，将答案和向对方提出的新问题组成一个邮件放入对方的邮箱中。假设 A 的信箱最多放 M 个邮件，B 的信箱最多放 N 个邮件。初始时 A 的信箱中有 x 个邮件（0 < x < M），B 的信箱中有 y 个邮件（0 < y < N）。辩论者每取出一个邮件，邮件数减 1。当信箱不为空时，辩论者才能从信箱中取邮件，否则等待；当信箱不满时，辩论者才能将新邮件放入信箱，否则等待。请添加必要的信号量和 P、V 操作，以实现上述过程的同步。要求写出完整的过程，并说明信号量的含义和初值。
CoBegin
A{                                    B{
  while(TRUE){                          while(TRUE){
    从 A 的信箱中取出一个邮件;              从 B 的信箱中取出一个邮件;
    回答问题并提出一个新问题;               回答问题并提出一个新问题;
    将新邮件放入 B 的信箱;                 将新邮件放入 A 的信箱;
  }                                     }
}                                     }
CoEnd
解：为两个信箱各设一对同步信号量与一个互斥信号量。
semaphore Full_A  = x;      // A 的信箱中的邮件数量
semaphore Empty_A = M - x;  // A 的信箱中还可存放的邮件数量
semaphore Full_B  = y;      // B 的信箱中的邮件数量
semaphore Empty_B = N - y;  // B 的信箱中还可存放的邮件数量
semaphore mutex_A = 1;      // A 的信箱的互斥信号量
semaphore mutex_B = 1;      // B 的信箱的互斥信号量

A{ while(TRUE){
    P(Full_A);  P(mutex_A);
      从 A 信箱取一个邮件;
    V(mutex_A); V(Empty_A);
    回答问题并提出一个新问题;
    P(Empty_B); P(mutex_B);
      新邮件放入 B 信箱;
    V(mutex_B); V(Full_B);
}}

B{ while(TRUE){
    P(Full_B);  P(mutex_B);
      从 B 信箱取一个邮件;
    V(mutex_B); V(Empty_B);
    回答问题并提出一个新问题;
    P(Empty_A); P(mutex_A);
      新邮件放入 A 信箱;
    V(mutex_A); V(Full_A);
}}
2015。两人互相给对方写信，就是两组「生产者-消费者」叠在一起。信箱 A：Full_A=x，Empty_A=M−x，mutex_A；信箱 B 同理。

  「期望的消息尚未产生 ⟹ 同步信号量初值 0」
  「期望的消息已存在 ⟹ 初值为非 0 正整数」  ← 本题

  A 信箱已有 x 封    ⟹ Full_A  = x
  A 信箱还能放 M−x 封 ⟹ Empty_A = M−x
  （B 信箱同理，四个初值一个 0 都没有）
  3. 看清「取自己的、放对方的」：A 从 A 信箱取（P(Full_A)），往 B 信箱放（P(Empty_B)）——下标很容易写串，写完务必逐行核一遍。

  回答问题并提出一个新问题;

  P(Empty_B); P(mutex_B);
  将新邮件放入 B 的信箱;

B：while(TRUE){ …与 A 完全对称…  }     ⛳3 分
  （取自 B 信箱：P(Full_B)/P(mutex_B)；
    放入 A 信箱：P(Empty_A)/P(mutex_A)）

Full/Empty 保证信箱不空才取、不满才放；

📌 批注（对照完校对）
⭐⭐ 四个非 0 初值是本题的全部分量所在：若把 Full_A、Full_B 写成 0，就等于宣称「一开始两个信箱都是空的」⟹ A 和 B 都会阻塞在第一个 P 上，辩论永远开不了场（死锁）。题目特意写了 0 < x < M、0 < y < N，就是在提示你「两边都已有邮件、都能立刻开始」。
⚠️ 下标写串是本题第二大失分点：记一句口诀——「取自己的、放对方的」。A 的第一段全是下标 A，第二段全是下标 B；B 反之。写完用手指着逐行核一遍下标，10 秒钟的事。
⭐ 「回答问题并提出新问题」为什么放在两段之间、且不在任何临界区里：这是纯思考动作，不碰任何信箱——圈进临界区会让对方在他思考期间也不能用信箱，白白降低并发。
⭐ 本题不会死锁的原因（值得多想一层）：A 在申请 Empty_B 时，手里已经放掉了 mutex_A⟹ 不存在「持 A 锁等 B 锁」的循环等待。若把两段合并成 P(mutex_A); P(mutex_B); …，A 与 B 反向加锁就会死锁（正是选择题 2.3-22 的场景）。

2017實戰最大限度并发 · 读读不互斥、读写与写写互斥
某进程中有 3 个并发执行的线程 thread1、thread2 和 thread3，其伪代码如下所示。请添加必要的信号量和 P、V 操作，要求确保线程互斥访问临界资源，并且最大限度地并发执行。
// 复数的结构类型定义          thread1              thread3
typedef struct               {                    {
{                              cnum w;              cnum w;
    float a;                   w = add(x, y);       w.a = 1;
    float b;                   …                    w.b = 1;
} cnum;                      }                      z = add(z, w);
cnum x, y, z;  // 全局变量                          y = add(y, w);
                             thread2                …
// 计算两个复数之和           {                    }
cnum add(cnum p, cnum q)       cnum w;
{                              w = add(y, z);
    cnum s;                    …
    s.a = p.a + q.a;         }
    s.b = p.b + q.b;
    return s;
}
解：书上的通用方法论（这段比答案本身更重要）：
1) 只有全局变量才可能需要互斥访问（局部变量不需要，即使不同进程里同名）。
2) ⭐⭐ 互斥是「进程之间对某个变量」的互斥，不能脱离具体进程谈某变量需不需要互斥。一组互斥关系需要指出是哪些进程对哪个变量的互斥。若题目给的是「只需 1 与 3、2 与 3 互斥」而你按「三者两两互斥」解，虽然满足了要求，但降低了并发度 ⟹ 扣分。「这也是 PV 互斥的最大难点：在没有准确找准互斥关系的条件下，容易导致程序的并发度降低，从而扣分。」
3) 找互斥关系的原则 = 读者-写者原则：读与读不需要互斥，读与写、写与写需要互斥。
本题分析：全局变量只有 x、y、z。thread1 涉及 x、y（只读）；thread2 涉及 y、z（只读）；thread3 涉及 y、z（读和写）。⟹ 三组互斥关系：① thread1 与 thread3 对 y；② thread2 与 thread3 对 y；③ thread2 与 thread3 对 z。⟹ 定义三个互斥信号量 mutex_y1 = mutex_y2 = mutex_z = 1：
thread1{                 thread2{
  cnum w;                  cnum w;
  wait(mutex_y1);          wait(mutex_y2);
  w = add(x, y);           wait(mutex_z);
  signal(mutex_y1);        w = add(y, z);
  …                        signal(mutex_z);
}                          signal(mutex_y2);
                           …
                         }

thread3{
  cnum w;
  w.a = 1; w.b = 1;
  wait(mutex_z);   z = add(z, w);   signal(mutex_z);
  wait(mutex_y1);  wait(mutex_y2);
  y = add(y, w);
  signal(mutex_y1); signal(mutex_y2);
  …
}
2017。三个线程，读 x、y、z，修改 y、z。要最大并发：对每一对变量按读写分别加信号量，只有都是读时才不互斥。这题对「最大并发」要求很高。

一致。🐍 PV 穷举器验证（190 个状态）：无死锁——因为 thread3 先释放 mutex_z 再申请 mutex_y，不构成循环等待；若改成「持 mz 抢 my」与 thread2 的「持 my 抢 mz」并存，23 个状态内即死锁 ✓

💭 思路（动手前看）
  1. 第一步：画一张「谁读谁写」的表（这一步做对，题就做完了一半）：
    线程xyz
    thread1读读—
    thread2—读读
    thread3—读+写读+写
  2. 第二步：用读者-写者原则逐对筛：
    t1 ↔ t2   对 y 都是读       ⟹ 不需要互斥 ⭐
t1 ↔ t3   对 y 是读 vs 写   ⟹ 需要（mutex_y1）
t2 ↔ t3   对 y 是读 vs 写   ⟹ 需要（mutex_y2）
t2 ↔ t3   对 z 是读 vs 写   ⟹ 需要（mutex_z）
t1 ↔ ?    对 x 只有它一个碰 ⟹ 不需要
    三组关系 ⟹ 三个信号量，一个不多一个不少。
  3. 第三步：为什么 y 要两个信号量而不是一个：因为 y 上的互斥关系是「t1↔t3」和「t2↔t3」两组，而t1 与 t2 之间不互斥。若只用一个 mutex_y，t1 和 t2 就被迫互斥了 ⟹ 并发度下降 ⟹ 扣分。
  4. 第四步：检查加锁顺序，避免死锁（见批注）。
✍️ 考场卷面（写完对照）
解：全局变量只有 x、y、z。 ⛳3 分
  thread1 只读 x、y；thread2 只读 y、z；
  thread3 对 z、y 既读又写。
  由「读读不互斥、读写与写写互斥」得三组互斥关系：
    ① thread1 与 thread3 对 y   ② thread2 与 thread3 对 y
    ③ thread2 与 thread3 对 z
  故设三个互斥信号量，初值均为 1：
    mutex_y1、mutex_y2、mutex_z

thread1{                             ⛳2 分
  wait(mutex_y1); w = add(x, y); signal(mutex_y1);
}

thread2{                             ⛳2 分
  wait(mutex_y2); wait(mutex_z);
  w = add(y, z);
  signal(mutex_z); signal(mutex_y2);
}

thread3{                             ⛳3 分
  w.a = 1; w.b = 1;
  wait(mutex_z);  z = add(z, w);  signal(mutex_z);
  wait(mutex_y1); wait(mutex_y2);
  y = add(y, w);
  signal(mutex_y1); signal(mutex_y2);
}

thread1 与 thread2 之间无互斥关系，可并发执行，
故在保证互斥的前提下达到了最大并发度。
📌 批注（对照完校对）
⭐⭐⭐ 「最大限度地并发执行」这句话是本题的评分关键，也是它区别于其他 PV 题的地方：用一把大 mutex 把三个线程全锁起来，互斥要求满足了，但并发度题干明确要求⟹ 照样扣分。教材原话：「这也是 PV 互斥的最大难点：在没有准确找准互斥关系的条件下，容易导致程序的并发度降低，从而扣分。」
⭐ 「互斥关系」必须说清是「哪些线程对哪个变量」：不能笼统地说「y 需要互斥」，要说「thread1 与 thread3 对 y 互斥、thread2 与 thread3 对 y 互斥，但 thread1 与 thread2 之间不互斥」。这句分析本身就值分。
⚠️ 加锁顺序：thread3 必须先放掉 mutex_z 再去申请 mutex_y：thread2 的顺序是「先 y2 后 z」，thread3 若是「先 z 后 y2」且两把锁同时持有，就是反序加锁 ⟹ 死锁（正是选择题 2.3-22 的场景）。教材答案让 thread3 把 z 的操作完整做完、释放 mutex_z 之后，再去拿两把 y 锁——🐍 穷举器实测：这样写 190 个状态无死锁；改成同时持有则 23 个状态内死锁。
⭐ x 为什么完全不需要保护：只有 thread1 碰它，且只是读——没有第二个线程参与，就不存在「互斥关系」。再次印证：互斥是一种「关系」，单个线程谈不上互斥。
🔗 本题的方法论是 2.3 全节的总纲，2016 选择题（2.3-50）是它的选择题版，2024 真题的「尽可能少的信号量」是它的延续。
2019實戰哲学家变体 · 用第三种资源限制并发人数
有 n（n ≥ 3）名哲学家围坐在一张圆桌边，每名哲学家交替地就餐和思考。在圆桌中心有 m（m ≥ 1）个碗，每两名哲学家之间有一根筷子。每名哲学家必须取到一个碗和两侧的筷子后，才能就餐，进餐完毕，将碗和筷子放回原位，并继续思考。为使尽可能多的哲学家同时就餐，且防止出现死锁现象，请使用信号量的 P、V 操作描述上述过程中的互斥与同步，并说明所用信号量及初值的含义。
解：思路：传统哲学家问题可用「限制至多允许 n−1 名哲学家同时抢筷子」避免死锁。本题可用碗这个限制资源来避免死锁：
· 当碗数 m < n 时，直接让碗的资源量等于 m，确保不会出现所有哲学家都拿一侧筷子而无限等待另一侧的情况；
· 当 m ≥ n 时，为让碗起到同样的限制效果，让碗的资源量等于 n−1。
⟹ ⭐⭐ 碗的资源量 = min{n−1, m}。碗的资源量起限制哲学家取筷子的作用，所以必须先对碗做 P 操作。
semaphore bowl;                     // 协调哲学家对碗的使用
semaphore chopsticks[n];            // 协调哲学家对筷子的使用
for(int i = 0; i < n; i++) chopsticks[i] = 1;
bowl = min(n-1, m);                 // bowl ≤ n−1，确保不死锁

while(TRUE){                        // 哲学家 i 的程序
    思考;
    P(bowl);                        // 取碗（必须放在最前）
    P(chopsticks[i]);               // 取左边筷子
    P(chopsticks[(i+1) % n]);       // 取右边筷子
    就餐;
    V(chopsticks[i]);
    V(chopsticks[(i+1) % n]);
    V(bowl);
}
2019。m 个碗，就是天然的「room」：碗数 bowl = min(n−1, m)。为什么要取 min？碗比 n−1 多时也要限制 n−1，否则还是能死锁。一眼看出才是硬本事。
再深一层
一致。🐍 PV 穷举器三组参数验证：n=3/m=5（bowl=2，242 状态）、n=4/m=2（bowl=2，928 状态）、n=5/m=9（bowl=4，14642 状态）全部无死锁 ✓；若 m ≥ n 时不封顶（n=4 取 bowl=9），2401 个状态内即死锁 ✓

💭 思路（动手前看）
  1. 先认出这是哲学家问题的变体：核心矛盾还是「每人要凑齐两根相邻筷子」⟹ 循环等待 ⟹ 死锁风险。题目还额外给了一种资源（碗）——这不是负担，是送来的限制器。
  2. 回忆 2.3-45 的结论：n 个哲学家，只要保证同时抢筷子的人不超过 n−1，就必然有人能凑齐两根（抽屉原理）。所以我们要的是一个「最多放 n−1 人进场」的门票。
  3. ⭐ 分情况把碗变成门票：
    m < n−1 或 m = n−1  ⟹ 碗本来就不够，天然限制住了 ⟹ bowl = m
m ≥ n            ⟹ 碗太多，起不到限制作用 ⟹ 人为压到 n−1

合并写成一个式子： bowl = min{n−1, m}
  4. ⭐ 位置：P(bowl) 必须在两个 P(chopsticks) 之前。门票要在进场前检查才有意义；放在筷子之后，人已经把筷子抢完了，限制形同虚设。
✍️ 考场卷面（写完对照）
解：设两类信号量： ⛳4 分
  chopsticks[i] = 1  (i = 0,1,…,n−1)
      表示第 i 根筷子是否可用，共 n 个，初值均为 1
  bowl = min{n−1, m}
      表示可用的碗数；取 min 是因为：
      · m < n 时碗数本身已限制了同时就餐的人数；
      · m ≥ n 时须人为限制至多 n−1 人同时取筷子，
        以保证至少一人能取到两根筷子，从而不死锁。

哲学家 i 的进程：while(TRUE){          ⛳6 分
  思考;
  P(bowl);                    // 先取碗，限制并发人数
  P(chopsticks[i]);            // 取左侧筷子
  P(chopsticks[(i+1) % n]);    // 取右侧筷子
  就餐;
  V(chopsticks[i]);
  V(chopsticks[(i+1) % n]);
  V(bowl);
}

由于同时取筷子的哲学家至多 min{n−1, m} 名，
必有一人能同时获得两根筷子，故不会死锁；
且该值已取到上限，故同时就餐的人数尽可能多。
📌 批注（对照完校对）
⭐⭐ 「min」是本题唯一的得分点，而且两边都要讲理由：只写 bowl = m 会在 m ≥ n 时死锁；只写 bowl = n−1 会在 m < n−1 时超发碗（碗不够用）。两种情况都要在卷面上说一句，这就是 4 分里的核心 2 分。
⭐ 题干「为使尽可能多的哲学家同时就餐」这句话在给你定上界：它是在说「别偷懒把 bowl 设成 1」。设成 1 确实不死锁，但同时只有一人吃饭，与题意相悖——这与 2017 真题「最大限度地并发执行」是同一种要求。
⚠️ P(bowl) 的位置错了就全错：若写成 P(chopsticks[i]); P(bowl); …，那么 n 个人可以先各拿一根左筷再去抢碗⟹ 筷子已经被瓜分干净，碗再怎么限制也救不回来 ⟹ 死锁。通用判据：限制器必须放在被限制的资源之前申请。
⭐ 两个 V(chopsticks) 的顺序可以换，V(bowl) 放最后：先还筷子再交碗，语义上更顺（人吃完了才离席），但由于 V 不会阻塞，三个 V 的顺序其实都不影响正确性。
🔗 与 2.3-45（seat 初值最大为 4）是同一条结论的两种问法：那道选择题问「限制器最大取多少」（答 n−1 = 4），本题问「限制器该怎么设」（答 min{n−1, m}）。先做那道选择题，本题就只剩一个 min 要写。
2011實戰座位+取号机+叫号三个节拍 · 服务型同步
某银行提供 1 个服务窗口和 10 个供顾客等待的座位。顾客到达银行时，若有空座位，则取号机上领取一个号，等待叫号。取号机每次仅允许一位顾客使用。当营业员空闲时，通过叫号选取一位顾客，并为其服务。顾客和营业员的活动过程描述如下。请添加必要的信号量和 P、V 操作，实现上述过程中的互斥与同步。要求写出完整的过程，说明信号量的含义并赋初值。
coBegin
{
    process 顾客 i
    {
        从取号机获取一个号码;
        等待叫号;
        获取服务;
    }
    process 营业员
    {
        While(TRUE)
        {
            叫号;
            为客户服务;
        }
    }
}coEnd
解：
互斥资源：取号机（一次只有一位顾客取号）⟹ mutex。
同步问题：空座位的有无会影响等待顾客的数量、顾客的有无决定营业员是否能开始服务 ⟹ empty 与 full；顾客获得空座位后需要等待叫号和被服务 ⟹ service。
semaphore empty = 10;     // 空座位的数量，初值为 10
semaphore mutex = 1;      // 互斥使用取号机
semaphore full = 0;       // 已占座位的数量，初值 0
semaphore service = 0;    // 等待叫号

Process 顾客 i{
    P(empty);             // 等空位
    P(mutex);             // 申请使用取号机
    从取号机上取号;
    V(mutex);             // 取号完毕
    V(full);              // 通知营业员有新顾客
    P(service);           // 等待营业员叫号
    接受服务;
}

Process 营业员{
    while(True){
        P(full);          // 没有顾客则休息
        V(empty);         // 顾客离开座位
        V(service);       // 叫号
        为顾客服务;
    }
}
2011。取号机 = mutex，座位 = 计数，叫号 = 上面 customers/barbers 那一对同步。
再深一层
一致。⭐ 本题是「排队服务」类的标准答案，三个节拍的顺序是全题的采分核心。

💭 思路（动手前看）
  1. 逐个名词归位（PV 大题的第一步永远是这个）：
    10 个座位   ⟹ 有多少个 ⟹ 计数信号量 empty = 10
取号机      ⟹ 一次一人 ⟹ 互斥信号量 mutex = 1
已有顾客数  ⟹ 营业员要等 ⟹ 同步信号量 full = 0
被叫到号    ⟹ 顾客要等 ⟹ 同步信号量 service = 0
  2. 把「等待叫号」翻译成双向同步：顾客通知营业员「我来了」（V(full)）；营业员通知顾客「叫到你了」（V(service)）——两个方向各一个信号量，与综 13 司机-售票员同构。
  3. ⭐ 三个节拍的顺序（本题最容易写乱的地方）：
    V(full)    顾客取完号 ⟹ 告诉营业员「有人在等」
V(empty)   营业员叫号时 ⟹ 该顾客离座，座位腾出
V(service) 营业员叫号本身 ⟹ 让那位顾客去窗口
    三者的先后不能乱，尤其 V(empty) 归营业员执行。
  4. 顺序检查：P(empty) 在 P(mutex) 之前——不能占着取号机等座位。
✍️ 考场卷面（写完对照）
解：定义四个信号量： ⛳4 分
  empty   = 10   可用的空座位数
  mutex   = 1    取号机的互斥使用权
  full    = 0    已在等待的顾客数（用于阻塞营业员）
  service = 0    已被叫到号的顾客（用于阻塞顾客）

process 顾客 i{                       ⛳4 分
  P(empty);            // 有空座位才进入
  P(mutex);
  从取号机获取一个号码;
  V(mutex);
  V(full);             // 通知营业员：有顾客在等
  P(service);          // 等待叫号
  获取服务;
}

process 营业员{                       ⛳2 分
  while(TRUE){
    P(full);           // 无顾客则等待
    V(empty);          // 被叫的顾客离座，空出一个座位
    V(service);        // 叫号
    为客户服务;
  }
}

empty 限制等待人数不超过 10，mutex 保证取号机互斥使用，
full 与 service 构成顾客与营业员之间的双向同步。
📌 批注（对照完校对）
⭐⭐ V(empty) 为什么写在营业员进程里（本题最精妙的一步）：座位是顾客被叫到号、起身去窗口时才腾出来的，而「叫号」这个动作发生在营业员进程里。若把 V(empty) 写在顾客的「获取服务」之后，就意味着顾客要坐到服务结束才让座——那么等待区的周转会白白慢一拍，与题意不符。（这与 2025 真题「V(position) 放在放树苗之后而非填土之后」是同一类推理：资源在「不再被占用的那一刻」就该释放，而不是等整件事全部做完。）
⚠️ 「1 个服务窗口」为什么不需要一个信号量：因为营业员进程只有一个，它天然是串行的——一个进程自己就是自己的互斥。若题目改成「3 个窗口」，才需要给窗口设一个计数信号量。
⚠️ P(empty) 必须在 P(mutex) 之前：否则顾客会占着取号机等座位，后面的顾客连号都取不了⟹ 违反「资源类 P 在前、互斥类 P 在后」的铁律。
🔗 同族题：综 03 面包师取号（用整型变量比较）、综 11 理发师（用 waiting 计数）——三题都是「排队 + 叫号」，本题用的是纯信号量写法，最干净。
2013實戰容量限制 + 单出入口 · 进出共用一个 mutex
某博物馆最多可容纳 500 人同时参观，有一个出入口，该出入口一次仅允许一人通过。参观者的活动描述如下。请添加必要的信号量和 P、V 操作，以实现上述过程中的互斥与同步。要求写出完整的过程，说明信号量的含义并赋初值。
coBegin
    参观者进程 i:
    {
        …
        进门;
        …
        参观;
        …
        出门;
        …
    }
coEnd
解：出入口一次仅允许一人通过 ⟹ mutex = 1；博物馆最多同时容纳 500 人 ⟹ empty = 500。
semaphore empty = 500;    // 博物馆可以容纳的最多人数
semaphore mutex = 1;      // 用于出入口资源的控制

参观者进程 i:{
    P(empty);             // 可容纳人数减 1
    P(mutex);             // 互斥使用门
    进门;
    V(mutex);
    参观;
    P(mutex);             // 互斥使用门
    出门;
    V(mutex);
    V(empty);             // 可容纳人数增 1
}
2013。两个互斥：博物馆容量 empty=500，出入口 mutex=1。进门、出门都要 P(mutex)。注意 empty 要在门外申请，否则人进不来也出不去，这正是同步 P 先于互斥 P。
再深一层
一致。🐍 PV 穷举器双向验证（容量 2、3 名参观者）：教材顺序 392 个状态无死锁、馆内人数恒 ≤ 容量；把 P(mutex) 提到 P(empty) 前面后，365 个状态内即出现死锁 ✓

💭 思路（动手前看）
  1. 两句话两个信号量，题目给得非常干净：
    「最多容纳 500 人」  ⟹ 数量限制 ⟹ empty = 500（同步/计数）
「出入口一次一人」  ⟹ 互斥     ⟹ mutex = 1
  2. ⭐ 抓住「一个出入口」这五个字：进门和出门用的是同一扇门 ⟹ 必须共用同一把 mutex。设两把锁（mutex_in / mutex_out）就与题意不符了——那样一个人进、一个人出可以同时挤在门口。
  3. empty 的一进一出：进门前 P(empty)（占一个名额）、出门后 V(empty)（还一个名额）。注意 V(empty) 要放在 V(mutex) 之后（人已经完全离开了才算数）。
  4. 顺序检查（本题唯一的坑）：P(empty) 必须在 P(mutex) 之前——理由见批注。
✍️ 考场卷面（写完对照）
解：定义两个信号量： ⛳3 分
  empty = 500   博物馆还可容纳的参观者人数
  mutex = 1     出入口的互斥使用权（进出共用同一个门）

参观者进程 i：                        ⛳7 分
{
  P(empty);          // 馆内有余量才允许进入
  P(mutex);          // 互斥通过出入口
  进门;
  V(mutex);

  参观;

  P(mutex);          // 互斥通过出入口
  出门;
  V(mutex);
  V(empty);          // 离开后归还一个名额
}

empty 保证馆内人数不超过 500；mutex 保证任一时刻
只有一人通过出入口，进门与出门共用同一信号量。
📌 批注（对照完校对）
⭐⭐ P(empty) 必须在 P(mutex) 之前——这是本题唯一会死人的地方：
若写成 P(mutex); P(empty);
  馆内已满（empty = 0）时，某人抢到了门（mutex = 0）
  他卡在 P(empty) 上等名额
  ⟹ 里面的人想出来，却过不了这扇被占住的门
  ⟹ 名额永远不会释放 ⟹ 死锁
🐍 穷举器实测：容量 2、3 人时，颠倒顺序在 365 个状态内必然死锁。这与生产者-消费者「先资源后互斥」是同一条铁律，本题是它最直观的现实版。
⚠️ 出门那段不要再写 P(empty)：出门是释放名额，不是申请名额。出门段只需 P(mutex) 保护过门这个动作。
⭐ 「参观」这一段为什么在临界区之外：参观时人在馆内，占的是「名额」（empty），但不占「门」（mutex）。把参观圈进 mutex 里是重大错误——那意味着一次只能有一个人在馆内参观，500 的容量彻底浪费。判据：临界区只包含真正使用临界资源的那一小段。
🔗 本题是「有限容量 + 互斥入口」的模板，与 2011 综 18（10 个座位 + 取号机）结构几乎一样，差别只在于本题的入口进出共用、且不需要叫号同步。

2009、2014、2015：生产者消费者的变形（多种产品、一次取多个、两组对称）。 2011、2013：计数 + 排队。 2017：多变量的读写关系，只有都是读才能并发。 2019：哲学家加碗，碗数就是天然的 room。
