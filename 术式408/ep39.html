2012实战I/O 总线数据线传输的内容 · 中断类型号 · 三类总线分工
下列选项中，在 I/O 总线的数据线上传输的信息包括（　）。
Ⅰ. I/O 接口中的命令字　Ⅱ. I/O 接口中的状态字　Ⅲ. 中断类型号

I/O 总线分为三类：数据线、控制线和地址线。数据缓冲寄存器和命令/状态寄存器的内容都是通过数据线来传送的；地址线用以传送与 CPU 交换数据的端口地址；控制线用于给 I/O 端口发送读/写信号，仅用于对端口进行读/写控制。中断类型号用于指出中断向量的地址，CPU 响应某一外部中断后，就从数据总线上获取该中断源的中断类型号，然后据此计算对应中断向量在中断向量表（存放在内存中）的位置。因此说法 Ⅰ、Ⅱ 和 Ⅲ 均正确。

  ┌ 命令字   … 控制寄存器的内容      → 数据线 ✔

  └ 读/写信号 … 一根线上的高低电平    → 控制线
总线跑什么
数据线读/写数据、状态信息、控制信息（命令字）、中断类型号（向量中断中）
地址线要访问的 I/O 接口内部寄存器的端口地址
控制线读/写控制信号、中断请求与响应信号、总线仲裁信号、设备握手信号
⚠️⚠️ 特别注意「中断」被拆成了两半，分走两条线：
「中断请求」和「中断响应」信号 → 控制线（就是一根 INTR / INTA 线）；
「中断类型号」 → 数据线（是一个数，要占好几位）。
⟹ 7.3.2 的注意框原话：「中断请求和响应信号通过 I/O 总线的控制线传输，而中断类型号则在中断响应阶段由中断控制器经数据总线提供给 CPU」。这句话考了不止一次。

02三种方式

▣ 三种 I/O 方式
程序查询：CPU 一直问。实现简单，CPU 浪费最多。分为独占查询和定时查询。
程序中断：好了通知 CPU，==一个字一个中断==。慢设备合适，块设备太频繁。
DMA：CPU 只管开始和结束，==整块传完才一个中断==。中间由 DMAC 直接在设备和主存之间传。
术式
三种方式的 CPU 占用率（核心公式）

查询（定时）：占比 = 每秒查询次数 × 单次周期数 / 主频。
中断：每秒中断次数 = 传输率 / 每次传的字节数；占比 = 每秒次数 × 每次开销周期 / 主频。
DMA：每秒中断次数 = 传输率 / 块大小；占比 同上；再问是否抢总线。

2011实战定时查询的 CPU 占用率 · 每秒查询次数已给
某计算机处理器主频为 50MHz，采用定时查询方式控制设备 A 的 I/O，查询程序运行一次所用的时钟周期数至少为 500。在设备 A 工作期间，为保证数据不丢失，每秒需对其查询至少 200 次，则 CPU 用于设备 A 的 I/O 的时间占整个 CPU 时间的百分比至少是（　）。

每秒至少查询 200 次，每次查询至少 500 个时钟周期，则每秒最少占用 200×500 = 100000 个时钟周期，因此占 CPU 时间的百分比为 100000/50M = 0.20%。
200 × 500 / 50M = 0.2%。这是公式的直接代入。

  占用率 = 每秒查询次数 × 每次查询的时钟周期数 ÷ 主频

         = 100 000 ÷ 50 000 000
         = 0.002 = 0.20%

2014实战中断方式的 CPU 占用率 · 识别无用条件
若某设备中断请求的响应和处理时间为 100ns，每 400ns 发出一次中断请求，中断响应所允许的最长延迟时间为 50ns，则在该设备持续工作过程中，CPU 用于该设备的 I/O 时间占整个 CPU 时间的百分比至少是（　）。

每 400ns 发出一次中断请求，而响应和处理时间为 100ns，其中允许的延迟为干扰信息，因为在 50ns 内，无论怎么延迟，每 400ns 仍要花费 100ns 处理中断，所以该设备的 I/O 时间占整个 CPU 时间的百分比为 100ns/400ns = 25%。
100/400 = 25%。50 ns 是干扰项。
再深一层
选 B。⭐⭐ 本题唯一的考点是「看出 50ns 是废数据」——这是 408 计算题里少见的「反向」设计。
📐 列式（两个数就够）：

  占用率 = 每次中断耗时 ÷ 中断间隔
         = 100ns ÷ 400ns = 25%  ✔ B

🔍 为什么 50ns 用不上：

  时间轴（周期 400ns，每周期必须干 100ns 的活）：
    0        400       800       1200
    ├────────┼─────────┼─────────┤
    ▓▓       ▓▓        ▓▓            ← 每段 100ns 的中断处理

  「最长延迟 50ns」的意思是：请求发出后，
  CPU 最多可以拖 50ns 再开始处理（否则数据丢失）
  ⟹ 它只影响【什么时候开始】这 100ns，
     不影响【要花 100ns】这个事实

  ⟹ 100ns 的活照干，400ns 的周期照旧 ⟹ 25% 不变
  ★ 延迟决定「来不来得及」，不决定「占多少」
⚠️⚠️ 干扰项还原（三个错项恰好都是把 50 用进去了）：

2019实战中断方式 CPU 占用率 · 速率 ÷ 缓冲寄存器字长 = 中断次数

2009实战中断占用率含 CPI · DMA 占用率 · CPI 何时用何时不用
某计算机的 CPU 主频为 500MHz，CPI 为 5（执行每条指令平均需 5 个时钟周期）。假定某外设的数据传输速率为 0.5MB/s，采用中断方式与主机进行数据传送，以 32 位为传输单位，对应的中断服务程序包含 18 条指令，中断服务的其他开销相当于 2 条指令的执行时间。回答下列问题，要求给出计算过程。
1）在中断方式下，CPU 用于该外设 I/O 的时间占整个 CPU 时间的百分比是多少？
2）当该外设的数据传输速率达到 5MB/s 时，改用 DMA 方式传送数据。假定每次 DMA 传送块大小为 5000B，且 DMA 预处理和后处理的总开销为 500 个时钟周期，则 CPU 用于该外设 I/O 的时间占整个 CPU 时间的百分比是多少（假设 DMA 与 CPU 之间没有访存冲突）？
1）按题意，外设每秒传送 0.5MB，中断时每次传送 32bit = 4B。由于 CPI 为 5，在中断方式下，CPU 每次用于数据传送的时钟周期数为 5×18+5×2 = 100（中断服务程序 + 其他开销）。为达到外设 0.5MB/s 的数据传输速率，外设每秒申请的中断次数为 0.5MB/4B = 125000。1 秒内用于中断的开销为 100×125000 = 12500000 = 12.5M 个时钟周期。CPU 用于外设 I/O 的时间占整个 CPU 时间的百分比为 12.5M/500M = 2.5%。
2）当外设数据传输速率提高到 5MB/s 时改用 DMA 方式传送，每次 DMA 传送一个数据块，大小为 5000B，则 1 秒内需产生的 DMA 次数为 5MB/5000B = 1000。CPU 用于 DMA 处理的总开销为 1000×500 = 500000 = 0.5M 个时钟周期。CPU 用于外设 I/O 的时间占整个 CPU 时间的百分比为 0.5M/500M = 0.1%。
2009。接着这个框架算中断和 DMA 各自的比例。最后得出 DMA 省得多的结论。
再深一层
⭐⭐ 本题最震撼的一点：外设速率涨了 10 倍（0.5→5MB/s），CPU 占用率反而降了 25 倍（2.5%→0.1%）。这就是 DMA 存在的全部意义。

  ① 每次中断的时钟周期数
     = (服务程序指令数 + 其他开销折合指令数) × CPI
     = (18 + 2) × 5 = 100 个周期
     ★ 「其他开销相当于 2 条指令」⟹ 直接当 2 条指令算

  ② 每秒中断次数 = 设备速率 ÷ 每次传送量

术式
响应优先级和处理优先级

响应优先级：同时请求时先理谁，硬件固定。
处理优先级：谁可以打断谁，由屏蔽字决定，OS 可改。
屏蔽字 Mi=1 表示屏蔽第 i 级。各级的屏蔽字通常也屏蔽自己和优先级低的。

下面这道是典型：响应优先级 L0→L4，要求处理优先级改成 L4→L0→L2→L1→L3。

L1 的屏蔽字（M4 M3 M2 M1 M0）怎么写？

处理 L1 时，只有 L4、L0、L2 能打断它（处理优先级比它高），所以这三位是 0，其余（L3、L1 自己）是 1。写成 M4 M3 M2 M1 M0 = 0 1 0 1 0，即 01010。

2013实战中断与 DMA 的比较 · 多路型 DMAC 可服务慢速设备

「中断 I/O 方式适用于所有外部设备」✘ 中断方式不适合高速外设——外设准备数据的时间若小于中断处理时间就会丢数据（例 7.2 / 2022 真题 7.3-49）
「DMA 方式仅适用于快速外部设备」✘ 多路型 DMA 控制器也适合同时为多个慢速外设服务
⭐ A、B、C 三项是「中断 vs DMA」最标准的三条对比，直接背：

  ┌──────────┬────────────────┬──────────────────┐
  │          │  中断 I/O      │  DMA             │
  ├──────────┼────────────────┼──────────────────┤
  │ 请求什么 │ CPU 处理时间   │ 【总线使用权】   │
  │ 何时响应 │ 一条【指令】末 │ 一个【总线事务】完成后 │
  │ 谁传数据 │ 【软件】(服务程序) │ 【硬件】(DMAC)  │
  │ 传送单位 │ 一个字/字节    │ 【数据块】       │
  │ 保存现场 │ 【要】         │ 【不要】         │
  │ 处理异常 │ 【能】         │ 【不能】         │
  └──────────┴────────────────┴──────────────────┘
  （最后两行来自 7.3.3 §5 的第 ① ⑤ 条）
📌 「多路型 DMA 控制器」是本题唯一的课外知识点：它能分时为多个设备服务，各设备轮流占用总线传一个字。⟹ 慢速设备也能挂 DMA，只是没必要（性价比低）。
⟹ 记法：DMA 对慢设备是「不划算」而非「不能用」，一字之差。
🔗 2025 真题（7.3-54）问「哪些设备适合用 DMA」（网卡、固态硬盘），用的正是「划算不划算」的口径；7.3-05 问「哪些能发 DMA 请求」（只有带 DMA 接口的），用的是「能不能」的口径。
2015实战CPU 与 I/O 端口交换的信息 · 中断 I/O 不涉及主存地址
在采用中断 I/O 方式控制打印输出的情况下，CPU 和打印控制接口中的 I/O 端口之间交换的信息不可能是（　）。

在程序中断 I/O 方式中，CPU 和打印机直接交换，打印字符直接传输到打印机的 I/O 端口，不会涉及主存地址。而 CPU 和打印机通过 I/O 端口中的状态口和控制口来实现交互。
再深一层
选 B。⭐ 一句话判据：主存地址是 DMA 才需要的东西。中断 I/O 全程「CPU 寄存器 ↔ 端口」两点直连，主存不参与。
🔍 三种方式里「主存地址」出现在哪：

  程序查询 / 中断 I/O：
    CPU 寄存器 ←→ I/O 端口
    数据先进 CPU，再由 CPU 用另一条指令写进主存
    ⟹ 主存地址是【CPU 那条访存指令】的事，
       【不会送到接口去】

  DMA：
    主存 ←→ DMAC 数据缓冲寄存器 ←→ 外设
    DMAC 必须自己知道往主存哪儿写
    ⟹ 预处理时【主存起始地址 → AR】，
       主存地址计数器每传一个字 +1
    ⟹ 【只有 DMA 的接口里才有主存地址】
📌 三个正确项对应接口的三类端口：
A 打印字符 → 数据端口（数据缓冲寄存器）；
C 设备状态 → 状态端口（联机 / 忙 / 缺纸）；
D 控制命令 → 控制端口（初始化 / 选通 / 自动走纸）。
⟹ 三类端口全用上了，唯独没有「地址端口」这种东西。
🔗 与 7.2-11 是同一条通道的两端：那题问「接口 ↔ 打印机之间不交换什么」（答：中断请求）；本题问「CPU ↔ 接口端口之间不交换什么」（答：主存地址）。⟹ 两题合起来，把打印机这条通路上「谁跟谁交换什么」问全了，是极好的一对。
⚠️ 本题的【考点追踪】被王道标在 7.2.2（I/O 端口与 CPU 交换的内容），但题却放在 7.3.4——因为它需要「中断 I/O 方式」这个前提才能判断。⟹ 单看 7.2 会觉得 2015 是个缺口，其实不是。
2019实战DMA 传送过程 · 设备驱动程序设参数 · 后处理由中断服务程序完成
下列关于 DMA 方式的叙述中，正确的是（　）。
Ⅰ. DMA 传送前由设备驱动程序设置传送参数
Ⅱ. 数据传送前由 DMA 控制器请求总线使用权
Ⅲ. 数据传送由 DMA 控制器直接控制总线完成
Ⅳ. DMA 传送结束后的处理由中断服务程序完成

每类设备都配置一个设备驱动程序，设备驱动程序向上层用户程序提供一组标准接口，负责实现对设备发出各种具体操作指令，用户程序不能直接和 DMA 打交道。DMA 的数据传送过程分为预处理、数据传送和后处理 3 个阶段。预处理阶段由 CPU 完成必要的准备工作，数据传送前由 DMA 控制器请求总线使用权；数据传送由 DMA 控制器直接控制总线完成；传送结束后，DMA 控制器向 CPU 发送中断请求，CPU 执行中断服务程序做 DMA 结束处理。
再深一层
选 D（四条全对）。⭐ 本题把 DMA 三阶段完整走了一遍，是 7.3.3 第 4 节的默写题：
📌 四条说法逐一落位到三阶段：

  【预处理】
    Ⅰ 由【设备驱动程序】设置传送参数 ✔
       （主存起始地址→AR、设备地址→DAR、数据个数→WC、启动设备）
    Ⅱ 设备准备好后发 DMA 请求 → DMAC 向 CPU 发【总线请求】✔

  【数据传送】
    Ⅲ DMAC【直接控制总线】，硬件循环自动完成，无须 CPU 干预 ✔

  【后处理】
    Ⅳ DMAC 发中断请求 → CPU 执行【中断服务程序】做结束处理 ✔
       （校验数据完整性，出错转诊断程序）
📌 Ⅰ 里「设备驱动程序」这个词是本题唯一的软件层细节，它把 7.1.1 讲的「I/O 软件」与本节接上了：
「设备驱动程序向上层用户程序提供一组标准接口，负责实现对设备发出各种具体操作指令，用户程序不能直接和 DMA 打交道。」
⟹ 🔗 这条直通 OS 的「设备管理 / I/O 软件层次」。
⚠️ 三个「驱动」别混（见 7.2-17）：磁盘驱动器（硬件，是设备本身）· 磁盘控制器（硬件，是 I/O 接口）· 设备驱动程序（软件，在 OS 里）。本题 Ⅰ 说的是第三个。
🔗 2024 真题（7.3-53）问的是同一过程的第 ② 段：「DMA 控制器控制的数据传输通路位于设备接口和主存之间」。⟹ 两题互为补充。
2017实战DMA 方式的工作流程
系统将数据从磁盘读到内存的过程包括以下操作：
① DMA 控制器发出中断请求　② 初始化 DMA 控制器并启动磁盘　③ 从磁盘传输一块数据到内存缓冲区　④ 执行"DMA 结束"中断服务程序
正确的执行顺序是（　）。

DMA 的传送过程分为预处理、数据传送和后处理三个阶段。预处理阶段由 CPU 初始化 DMA 控制器中的有关寄存器、设置传送方向、测试并启动设备等；数据传送阶段完全由 DMA 控制，DMA 控制器接管系统总线；后处理阶段 DMA 控制器向 CPU 发送中断请求，CPU 执行中断服务程序做 DMA 结束处理。
初始化、传数据、发中断、中断服务。
再深一层
选 B（②③①④）。DMA 的三段式一旦记住，这类题永远秒选。
DMA 三阶段 ⟹ 四个操作各归其位

预处理（CPU 干）  ② 初始化 DMA 控制器并启动磁盘
      ↓                填 MAR / DC / 传送方向，启动设备
数据传送（DMA 干）③ 磁盘 → 内存缓冲区（整块）
      ↓                DMA 接管总线，CPU 去干别的
后处理          ① DMA 发中断请求
                     ④ CPU 执行「DMA 结束」中断服务程序

⟹ ② ③ ① ④ ✓ B
⭐ ①④ 的先后是本题唯一的坑：先"发出中断请求"（①），后"执行中断服务程序"（④）——请求是 DMA 控制器发的，服务程序是 CPU 跑的，中间还隔着一次中断响应。C 项（②①③④）把中断请求提到数据传送之前，等于"还没传完就说传完了"。
🔵 与 5.1-11 串：那道题问的正是本题②与①④两阶段里"谁在执行、进程处于什么态"——②由请求 I/O 的进程在内核态执行，④由中断服务例程执行（不是进程），期间进程一直阻塞。

2010实战显存带宽 · 刷新带宽公式 · 按占比反求总量
假定一台计算机的显示存储器用 DRAM 芯片实现，若要求显示分辨率为 1600×1200，颜色深度为 24 位，帧频为 85Hz，显存总带宽的 50% 用来刷新屏幕，则需要的显存总带宽至少约为（　）。

刷新所需带宽 = 分辨率×颜色深度×帧频 = 1600×1200×24bit×85Hz = 3916.8Mb/s，显存总带宽的 50% 用来刷新屏幕，于是需要的显存总带宽至少为 3916.8/0.5 = 7833.6Mb/s ≈ 7834Mb/s。
1600×1200×24×85 ≈ 3917 Mb/s，只占带宽的 50%，所以总带宽 7834 Mb/s。

选 D。⭐ 公式是送分的，本题真正的考点是最后一步「50% 用来刷新 ⟹ 总带宽要除以 0.5」。
📐 列式（背式子，不背结果）：

  ① 刷新带宽 = 分辨率 × 色彩深度 × 帧频
             = 1600 × 1200 × 24 bit × 85 /s
             = 3 916 800 000 bit/s = 3916.8 Mb/s

  ② 已知「刷新只占总带宽的 50%」，求总带宽：
     刷新带宽 = 总带宽 × 50%
     ⟹ 总带宽 = 刷新带宽 ÷ 50%
              = 3916.8 ÷ 0.5 = 7833.6 ≈ 7834 Mb/s

  ★ 部分 ÷ 占比 = 整体。占比在分母，不在分子。
