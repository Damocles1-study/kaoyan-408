先答旧题
OF、SF、CF、ZF 分别表示什么？无符号数比大小看谁？
有符号溢出、符号、进位借位、结果为零。无符号看 CF 和 ZF，有符号看 SF、OF、ZF。
IEEE 754 单精度的阶码偏置是多少？
127。
小端和大端，低字节各放在哪？
小端低字节放低地址；大端低字节放高地址。

数据讲完了，现在看指令。这一话和下一话问的是同一个问题：CPU 看到的程序长什么样。指令集（ISA）是软件和硬件之间的约定，程序员和 CPU 设计者都看它。

其之壹指令格式

一条指令要说清两件事：干什么（操作码 OP），对谁干（地址码）。

按地址字段的个数分：

类型形式含义
零地址OP操作数隐含，如 nop、栈式指令
一地址OP A另一个操作数隐含在累加器 ACC 里
二地址OP A1,A2(A1) OP (A2) → A1
三地址OP A1,A2,A3(A1) OP (A2) → A3

操作码位数决定能有多少条指令，地址字段位数决定能寻址多大。指令长度有限，地址越多，每个地址的范围就越小。

定长 vs 变长：定长指令取指和译码简单，适合流水线（RISC）；变长节省空间（CISC）。

扩展操作码：指令字长固定，让地址少的指令用更长的操作码。规则只有一条：短码不能是长码的前缀，否则译码时分不清。

走一遍：16 位指令，每个地址 4 位。

指令类型编码条数
三地址（OP 4 位）0000 ~ 111015
二地址（OP 8 位）1111 0000 ~ 1111 111015
一地址（OP 12 位）1111 1111 0000 ~ 1111 1111 111015
零地址（OP 16 位）1111 1111 1111 0000 ~ …111116

每层留一个前缀 1111 给下一层。

术式
扩展操作码算术

从地址最多的开始。k 位操作码有 2ᵏ 种，分给高层 a 条，剩 2ᵏ−a 个前缀。每个前缀再扩展 m 位，得到 (2ᵏ−a)×2ᵐ 条下一层指令。

其之貳寻址方式

指令字段里写的数，不一定就是要操作的地址。它有可能要先做一些计算。为什么要这么麻烦？因为指令短，地址字段装不下完整地址；而且程序要处理数组、指针、函数调用这些情况。

形式地址 A 是指令里写的那个数。有效地址 EA 是真正去访问的地址。

方式有效地址取操作数访存用途
立即操作数就是 A0给常数
直接EA = A1简单，范围小
间接EA = (A)2扩大范围、指针
寄存器操作数在 R0快，地址短
寄存器间接EA = (R)1指针
相对EA = (PC) + A1转移，位置无关
基址EA = (BR) + A1多道程序重定位
变址EA = (IX) + A1数组下标、循环
堆栈EA = SP1（硬件栈 0）函数调用

用一组数字走一遍。设 A = 2000H，寄存器 R = 1000H（也作变址寄存器），内存 M[1000H] = 5000H，M[2000H] = 3000H，M[3000H] = 4000H。

方式EA操作数
立即寻址无2000H
直接寻址2000H3000H
间接寻址M[2000H] = 3000H4000H
寄存器寻址无1000H
寄存器间接1000H5000H
变址寻址1000H + 2000H = 3000H4000H

直接寻址范围由 A 的位数决定，太小。间接寻址用一次访存换来更大的范围，但多访存一次。

后三种（相对、基址、变址）都是「寄存器 + 形式地址」，统称偏移寻址，区别在于谁变：

比方

基址和变址只差一个思路

基址：基址寄存器 BR 固定（由 OS 设定），A 变化。程序整体搬家时只改 BR。 变址：A 固定（比如数组首地址），IX 每次循环加一个元素大小。程序员可以改 IX。 所以按下标访问数组是变址，程序重定位是基址。

举数组的例子：double a[] 首地址 2000H，用变址寄存器 IX 存偏移。访问 a[i] 时 IX = 8i，EA = 2000H + IX。如果 IX 现在是 40H（64），下标就是 8。

相对寻址：EA = (PC) + A，A 是补码。目标和当前指令的相对距离固定，所以程序搬到哪都不用改，这叫位置无关代码。

咒灵
相对寻址的 PC

取指时 PC 已经自增了，所以 EA = 当前指令地址 + 指令长度 + 位移量。指令在 3000H，长 4 字节，位移 −8：EA = 3000H + 4 − 8 = 2FFCH。

术式
位数与范围

形式地址 A 有 n 位：直接范围 2ⁿ；相对位移（补码）−2^(n−1) ~ 2^(n−1)−1。
按字节编址、字长 w 字节：地址要 ÷w 才是字号。按字编址时寻址范围单位是字。

堆栈寻址：操作数在栈顶，指令里不用写地址。硬件栈（寄存器做的）不访存，软件栈（内存里）要访存一次。

合上页面说一遍：不看表，九种寻址方式的 EA 分别怎么算？基址和变址差在哪？

立即无 EA；直接 A；间接 (A)；寄存器无 EA；寄存器间接 (R)；相对 (PC)+A；基址 (BR)+A；变址 (IX)+A；堆栈 SP。基址 BR 固定由 OS 管；变址 IX 由程序改，用于数组。

领域展开

寻址：数组 → 变址；重定位 → 基址；转移 → 相对。
相对：PC 已经加过这条指令的长度。
扩展操作码：从地址多的开始，算剩余前缀 × 2ᵐ；短码不是长码的前缀。

2017實戰扩展操作码·反推指令字长 · 按字节编址⟹字长取 8 的倍数
某计算机按字节编址，指令字长固定且只有两种指令格式，其中三地址指令 29 条、二地址指令 107 条，每个地址字段为 6 位，则指令字长至少应该是（　）。

三地址指令有 29 条，所以其操作码至少为 5 位。以 5 位进行计算，它剩余 32 − 29 = 3 种操作码给二地址。而二地址额外多了 6 位给操作码，因此其数量最大达 3×64 = 192。所以指令字长最少为 23 位（5 + 6×3 = 23），因为计算机按字节编址，需要是 8 的倍数，所以指令字长至少应该是 24 位。
29 条三地址至少要 5 位 OP，剩 32−29 = 3 个前缀；二地址多出 6 位，3×64 = 192 ≥ 107 够用。指令长 5+18 = 23 位，按字节编址要凑成 8 的倍数，所以 24 位。
再深一层
选 A。这是扩展操作码题的「反着问」版本——已知条数求字长，而且藏了两个台阶。
【台阶一：试探操作码位数 k】
设三地址指令的操作码为 k 位，则指令字长 L = k + 6×3 = k + 18
二地址指令的操作码位数 = L − 6×2 = k + 6（多了 6 位）

约束：① 2^k ≥ 29（装得下三地址）
      ② (2^k − 29) × 2⁶ ≥ 107（剩余前缀能扩出二地址）

k = 5：① 32 ≥ 29 ✔   ② (32−29)×64 = 192 ≥ 107 ✔  ⟹ 可行
k = 4：① 16 < 29 ✘   直接出局
⟹ k 最小取 5，L = 5 + 18 = 23 位
【台阶二：⚠️ 按字节编址 ⟹ 指令字长必须是 8 的倍数】
23 位不是 8 的倍数 ⟹ 向上取整到 24 位 ✔
📌📌 本题丢分几乎全在台阶二。「按字节编址」这五个字不是背景板——主存以字节为最小单位，指令必须占整数个字节，否则取指时跨不齐边界。教材 4.1.2 节原话：「由于主存通常按字节编址，指令字长通常为字节的整数倍」。
⚠️ 凡是「求指令字长至少多少位」且题干出现「按字节编址」，算完一定再做一次向上取整到 8 的倍数。
2009實戰相对寻址 · PC 增量 = 指令长度 ÷ 编址单位
某机器字长为 16 位，主存按字节编址，转移指令采用相对寻址，由 2 字节组成，第一字节为操作码字段，第二字节为相对位移量字段。假定取指令时，每取一字节，PC 自动加 1。若某转移指令所在主存地址为 2000H，相对位移量字段的内容为 06H，则该转移指令成功转移后的目标地址是（　）。

相对寻址 EA = (PC) + A，首先计算取指令后的 PC 值。转移指令由 2 字节组成，每取一字节 PC 加 1，取指令后的 PC 值为 2002H，因此 EA = (PC) + A = 2002H + 06H = 2008H。注意，本题易误选 A 或 B：选项 A 未考虑 PC 值的自动更新；选项 B 虽然考虑了 PC 值的自动更新，但未注意到该转移指令是一条 2 字节指令，PC 值应是「+2」而不是「+1」。
2000H + 2（已经取完两个字节）+ 06H = 2008H。
再深一层
选 C。⭐ 这道 2009 真题是「PC 增量」考点的原型，它的三个干扰项精确对应三种错法：
选项算式错在哪
A 2006H2000H + 06H完全忘了 PC 会自增，拿本条指令地址当基准
B 2007H2000H + 1 + 06H记得自增了，但只加了 1——没数清这是 2 字节指令
C 2008H2000H + 2 + 06H✅ 按字节编址、指令 2 字节 ⟹ PC 增量 = 2
D 2009H2000H + 3 + 06H把指令当成 3 字节
📌📌 把本题与 4.2-12 钉成一组反复看——两题题面几乎一样，只有「编址单位」不同：
本题（2009）：按【字节】编址，指令 2 字节 ⟹ PC 增量 = 2/1 = 2
  ⟹ 2008H
4.2-12    ：按【字】编址（1 字 = 2 字节），指令 2 字节
            ⟹ PC 增量 = 2/2 = 1 ⟹ 4007H

         统一公式：PC 增量 = 指令长度 ÷ 编址单位
⚠️ 题干「每取一字节，PC 自动加 1」是在明示编址单位是字节——这句话不是废话，它就是让你算出增量 = 2 的依据。
2013實戰变址寻址 EA 计算
假设变址寄存器 R 的内容为 1000H，指令中的形式地址为 2000H；地址 1000H 中的内容为 2000H，地址 2000H 中的内容为 3000H，地址 3000H 中的内容为 4000H，则变址寻址方式下访问到的操作数是（　）。

根据变址寻址的方法，变址寄存器的内容（1000H）与形式地址的内容（2000H）相加，得到操作数的实际地址（3000H），根据实际地址访问内存，获取操作数 4000H。
变址：EA = 1000H + 2000H = 3000H，内容 4000H。
再深一层
选 D。本题四个数字被故意排成一条「链」，就是要看你会不会在中途停手：
已知：(R) = 1000H ； A = 2000H
      M[1000H] = 2000H ； M[2000H] = 3000H ； M[3000H] = 4000H

变址寻址：EA = (R) + A = 1000H + 2000H = 3000H     ← 这一步是【加法】
取操作数：操作数 = M[EA] = M[3000H] = 4000H ✔      ← 这一步是【一次访存】
⚠️⚠️ 本题最阴的设计：M[1000H] 恰好也等于 2000H。若把「变址」误做成「先取 R 所指内容再加」，会算成 M[1000H] + A = 2000H + 2000H = 4000H（地址），再取内容又落到别处——题目给的这些内容全是钓鱼数据，变址寻址只需要 R 的值本身，不取 R 所指的内容。
📌 对照记忆（同一组数据，四种寻址方式的答案全不同）：
寻址方式EA操作数
变址（本题）(R) + A = 3000H4000H ✅
直接A = 2000H3000H
间接M[A] = 3000H4000H
寄存器间接(R) = 1000H2000H
⚠️ 题干问的是「操作数」不是「有效地址」——若问 EA，答案是 C（3000H）。这与 4.2-17 是一对反向陷阱：那题问 EA 你容易多走一步，这题问操作数你容易少走一步。
2017實戰变址寻址适合数组
下列寻址方式中，最适合按下标顺序访问一维数组元素的是（　）。

变址操作时，将计算机指令中的地址与变址寄存器中的地址相加，得到有效地址，指令提供数组首地址，由变址寄存器来定位数据中的各元素。所以它最适合按下标顺序访问一维数组元素。相对寻址以 PC 为基地址，以指令中的地址为偏移量确定有效地址。寄存器寻址则在指令中指出需要使用的寄存器。直接寻址在指令的地址字段直接指出操作数的有效地址。
再深一层
选 D。为什么偏偏是变址？把循环展开就看明白了：
目标：遍历 int a[N]，首地址 base

  变址寻址：EA = (IX) + A
    A  = base   ← 【形式地址当基地址】，一次写死在指令里，循环中不变
    IX = i × 4  ← 【变址寄存器当偏移量】，每轮循环自己 +4

  ⟹ 循环体里【同一条指令】反复执行，只改 IX 的值
  ⟹ 指令不用改、代码不用展开，这正是"编制循环程序"的含义
📌📌 注意变址寻址里「谁是基地址」与基址寻址是反的（4.2-08 那张表的第 3、4 行）：变址寻址中 A 是基地址（不变）、IX 是偏移量（可变，由用户改）；基址寻址中 BR 是基地址（不变，由OS定）、A 是偏移量。
⚠️ 排除项：相对寻址的基地址是 PC，只适合定位「指令」不适合定位「数据」；直接寻址的地址写死在指令里，访问 a[0]、a[1]…就要写 N 条不同的指令；寄存器寻址操作数在寄存器里，压根不访存，跟数组无关。
🔗 4.3 节的机器级代码会把这件事具体化：x86 写作 [edx + esi*4]（比例因子 = 元素字节数），RISC 写作 slli r4,r2,2 + add r4,r3,r4——本质都是变址寻址。
2011實戰偏移寻址的范畴
偏移寻址通过将某个寄存器的内容与一个形式地址相加来生成有效地址。下列寻址方式中，不属于偏移寻址方式的是（　）。

间接寻址不需要寄存器，EA = (A)。基址寻址 EA = A + 基址寄存器 BR 的内容；相对寻址 EA = A + 程序计数器（PC）的内容；变址寻址 EA = A + 变址寄存器 IX 的内容。后三者都是将某个寄存器的内容与一个形式地址相加而形成有效地址，所以统称偏移寻址。
偏移寻址包括相对、基址、变址。间接不是。
再深一层
选 A。「偏移寻址」是一个三合一的合称，定义式长得一模一样，只是寄存器不同：
偏移寻址三兄弟有效地址用哪个寄存器典型用途
相对寻址EA = (PC) + A程序计数器转移指令、程序浮动
基址寻址EA = (BR) + A基址寄存器（OS 设定）多道程序、重定位
变址寻址EA = (IX) + A变址寄存器（用户设定）数组遍历、循环
— 以下不是偏移寻址 —
间接寻址 ✅本题EA = (A)不用寄存器扩大寻址范围、子程序返回
📌📌 一句话判据：式子里有没有「寄存器内容 + 形式地址」这个加法。间接寻址是「取内容」不是「做加法」——它连寄存器都没用上。
⚠️ 别被「间接」和「变址」的相似字形骗了：变址是 (IX) + A（一次加法 + 一次访存），间接是 (A)（两次访存、零次加法）。两者访存次数也不同（变址 1 次、间接 2 次，见表 4.1）。
2016實戰复合寻址·先变址后间址
某指令格式如下所示：[ OP | M | I | D ]，其中 M 为寻址方式，I 为变址寄存器编号，D 为形式地址。若采用先变址后间址的寻址方式，则操作数的有效地址是（　）。

在变址寻址中，有效地址（EA）等于指令字中的形式地址 D 与变址寄存器 I 的内容之和，即 EA = (I) + D。间接寻址是相对于直接寻址而言的，指令的地址字段给出的形式地址不是操作数的真正地址，而是操作数地址的地址，即 EA = (D)。从而该操作数的有效地址是 ((I) + D)。
先变址后间址：先 (I)+D，再取一次内容。写成 ((I)+D)。
再深一层
选 C。复合寻址的书写规则：按执行顺序从里往外套括号。
「先变址、后间址」——名字的顺序就是执行的顺序

第 ① 步 变址：中间地址 = (I) + D
              ← I 是【寄存器编号】，(I) 才是它的内容
第 ② 步 间址：EA = M[ 中间地址 ] = ( (I) + D )
              ← 最外层这层括号，就是这一次间址

⟹ EA = ((I) + D) ✔
📌 逐项排错，每个选项都对应一种寻址方式，正好复习一遍：
选项含义是什么寻址
A I + D把寄存器编号当数值直接加无意义（I 是编号不是数）
B (I) + D只做了第 ① 步纯变址寻址
C ((I) + D)变址结果再间址✅ 先变址后间址
D ((I)) + D先把 I 的内容当地址取一次内容，再加 D先间址后变址（顺序反了）
📌📌 C 与 D 的差别就是「先后顺序」：C 是「先加再取」，D 是「先取再加」。题干说「先变址后间址」⟹ 先加（变址）再取（间址）⟹ 加法在括号里面 ⟹ C。
🔗 与 4.2-07 完全同构（那题写作 ((X) + A)），两题必须一起记：「先 X 后 Y」⟹ Y 的操作套在 X 的结果外面。
2018實戰变址寻址反求下标 · 元素大小与比例因子
按字节编址的计算机中，某 double 型数组 A 的首地址为 2000H，使用变址寻址和循环结构访问数组 A，保存数组下标的变址寄存器的初值为 0，每次循环取一个数组元素，其偏移地址为变址值乘以 sizeof(double)，取完后变址寄存器的内容自动加 1。若某次循环所取元素的地址为 2100H，则进入该次循环时变址寄存器的内容是（　）。

根据变址寻址的公式 EA = (IX) + A，有 (IX) = 2100H − 2000H = 100H = 256，sizeof(double) = 8（双精度浮点数用 8 位字节表示），因此数组的下标为 256/8 = 32。
(2100H−2000H) = 100H = 256，每个 double 占 8 字节，256/8 = 32。
再深一层

FF12H = 1111 1111 0001 0010B，最高位 = 1 ⟹ 负数

  EFFF FF12H : 12  ← MSB
  EFFF FF13H : 34
  EFFF FF14H : FF
  EFFF FF15H : 00  ← LSB ✔

  相对【本条指令】的位移 = 2 + 2×OFFSET 字节 = 1 + OFFSET 条指令
  OFFSET = −128 ⟹ 1 + (−128) = −127 ⟹ 向后最多 【127 条】✔
📌 又是那个「前 127 / 后 128」的不对称（4.2-21、4.2-综02 同款）——根源永远是「PC 已先自增了一条指令」。
【第 2 问 · 两种标志组合，一转一不转】
先切指令：00000 | 011 | 11100011
          OP    C=0,Z=1,N=1   OFFSET = E3H
⟹ 只检测 ZF 和 NF（C = 0 表示不检测 CF）
⟹ 规则是"被检测的标志中只要有一个为 1 就转移"

情形一 CF=0, ZF=0, NF=1：检测 ZF(0)、NF(1) ⟹ 有一个是 1
  ⟹ 【转移】
   OFFSET = E3H = 1110 0011B（8 位补码，最高位 1 ⟹ 负数，真值 −29）
   符号扩展到 16 位 ⟹ FFE3H
   ×2（左移一位）  ⟹ FFC6H   （= −58）
   PC = 200CH + 2 + FFC6H = 200EH − 58 = 【1FD4H】✔

情形二 CF=1, ZF=0, NF=0：检测 ZF(0)、NF(0) ⟹ 都是 0
  ⟹ 【不转移】
   （CF = 1 不算数，因为 C = 0 表示压根不检测 CF
     —— 这是本题最阴的一处）
   PC = 200CH + 2 = 【200EH】✔
⚠️⚠️ 情形二的陷阱：题目故意把 CF 置 1，但指令的检测位 C = 0，没被点名的标志再怎么变都与转移无关。先看指令要检测谁，再看那几个标志的值。
⚠️ 符号扩展必须在左移之前做：先 E3H → FFE3H，再 ×2 → FFC6H。若先 ×2 得 1C6H 再扩展，结果就错了。
【第 3 问 · 无符号「小于等于」的标志组合】
无符号 A ≤ B ⟺ A − B 【为 0】或【有借位】
  · 为 0   ⟹ ZF = 1  ⟹ 需检测 ZF ⟹ 【Z = 1】
  · 有借位 ⟹ CF = 1  ⟹ 需检测 CF ⟹ 【C = 1】
  · 无符号数不看符号标志           ⟹ 【N = 0】

⟹ C = 1, Z = 1, N = 0 ✔
  （正好契合本指令"被检测标志中有一个为 1 就转移"的语义）
📌📌 本指令的"或"语义天然适合表达 ≤（小于 或 等于）：CF = 1 表示"小于"、ZF = 1 表示"等于"，两者取或正是"小于等于"。题目设计得很巧，值得单独记。
🔗 与 4.2-25（2011）无符号「大于」= CF + ZF = 0 恰好是一对互补：「>」要求两个标志都为 0，「≤」要求至少一个为 1。
【第 4 问 · 三个部件】
部件名称职责
①指令寄存器（IR）存放当前指令，从中切出 C/Z/N 与 OFFSET
②移位寄存器（左移一位）实现 ×2，把"指令条数"换算成"字节数"
③加法器把 (PC)+2 与 2×OFFSET 相加，得到转移目标地址
📌 ②「左移一位 = 乘 2」是硬件实现乘法的最省做法（不用乘法器），这也解释了为什么指令集要把偏移量的单位定成「指令条数」——硬件只需一个移位器就能换算。
📌 答题格式建议（本题按 12 分写）：(1) 两小问分开写，第二小问要写出「1 + OFFSET」这一步；(2) 先写"该指令检测 ZF 和 NF"，再分两种情形各给完整算式；(3) 三个字母各写一行理由；(4) 逐个部件写名称 + 一句功能。
做完再翻：这些题到底在问什么

有效地址题基本都是「算 EA，再按它去取内容」，看清是取 EA 还是取操作数。先变址后间址写成 ((I)+D)，读括号就行。 相对寻址永远是 PC 已经加过这条指令的长度；位移要符号扩展。按字节还是按字编址决定位移要不要乘。 场景题：按下标访问数组答变址，重定位答基址，转移答相对。 大题常把指令格式、标志位和相对寻址放一起：画出指令字段，算范围，再说条件转移的判断。
