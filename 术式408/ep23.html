到现在为止 CPU 都在闷头执行一个程序。可是键盘要响应、时间片要轮转、程序还可能出错。这一话讲 CPU 怎么被打断，以及怎样把权力交给操作系统。这件事组原和操作系统各讲一半，合起来才完整。

其之壹为什么要有两种模式

如果任何程序都能访问磁盘、修改别人的内存、关掉中断，一个错误或恶意程序就能拖垮整台机器。所以要把危险的操作收归操作系统。

比方

银行柜台

你的程序是储户，操作系统是柜员。储户不能自己进金库（硬件、其他人的内存），要办事就按铃（系统调用），由柜员进去。CPU 里有一位专门记录现在谁在操作：PSW 的模式位。比方的局限：柜员也是在同一台 CPU 上运行的程序，并没有另一个人。

术式
用户态与内核态

内核态（管态）：所有指令都能执行。用户态（目态）：只能执行非特权指令。
特权指令：开关中断、I/O、改 PSW、改基址/界限寄存器、设置时钟、加载页表基址。
用户→内核，只有一条路：中断或异常（包括 trap）。 内核→用户：修改 PSW（iret）。

为什么不能让用户程序自己切到内核态？如果有这样的指令，保护就形同虚设。所以切换时机由硬件决定，入口由操作系统事先设好。

判断指令能不能在用户态执行

访问内存（通过 MMU）、算术运算、读时钟、trap 指令（用户态才用得上）：能。 关中断、停机、写 PSW、写时钟、I/O：不能。

其之貳中断和异常

打断当前程序的事件分两大类，按来源分。

外部中断（简称中断）：来自 CPU 之外，和当前指令没关系，什么时候来不可预测（异步）。比如 I/O 完成、时钟到点。

内部异常（简称异常）：由正在执行的指令引起（同步）。又分三种，区别是能不能恢复、回到哪。

分类来源例子返回到
外中断CPU 外部，异步I/O 完成、时钟、断电下一条指令
故障 fault指令执行中，同步缺页、除零重新执行本条
陷阱 trap主动请求，同步系统调用、断点下一条指令
终止 abort硬件致命错误奇偶校验错不返回

为什么故障回到本条？缺页时这条指令没做成，页调进来后当然要重新做。为什么陷阱回下一条？陷阱指令本身已经完成了，它就是用来请求服务的。

咒灵
三条分界线

① 缺页是异常（故障），不是中断。 处理完重新执行这条指令。 ② 除零的归属：一般归为「故障」的例子，不可恢复时终止。判断时认准它属于内部异常即可。 ③ 外中断只能在指令结束后响应；异常是指令执行过程中当场处理。

合上页面说一遍：四种事件各来自哪里、返回到哪？

外中断来自外部，回下一条。故障是指令出错，回本条。陷阱是主动请求，回下一条。终止是致命错误，不返回。

其之參硬件做什么，OS 做什么

CPU 每条指令执行完，检查有没有中断请求。

响应条件：有请求，CPU 处于开中断状态（中断允许触发器 IF=1），一条指令执行完毕。

响应后，要做的事分两部分。这条分界线非常关键。

▣ 中断处理的完整流程
硬件（中断隐指令）完成响应的三件事，全部自动。这三步不是任何一条指令。
中断服务程序（OS）开始执行。开中断之后才能响应更高优先级的中断（多重中断）。
真正的处理工作。
恢复期间不能被打断，所以要关中断；iret 恢复 PC、PSW，回到用户态。

为什么硬件必须先关中断：如果响应中又来一个中断，断点还没存好，就全乱了。

为什么 PC、PSW 由硬件存：一旦开始执行服务程序，PC 马上就变了，PSW 也要变成内核态。通用寄存器则可以由软件存，用到哪个存哪个。

断点就是被打断的返回地址，加上 PSW。现场是通用寄存器这些。

怎样找到入口：中断向量法。每种中断有一个编号，内存里一张中断向量表存放各处理程序的入口地址，硬件用编号查表。比如编号 n，每项 4 字节，入口地址放在表基址 + 4n。表由操作系统设好。

术式
分界线

硬件：关中断、保存断点（PC、PSW）、形成入口地址（中断向量）。
OS：保存通用寄存器、保存/设屏蔽字、处理、恢复、iret。
响应时机：指令周期结束时，且开中断、有请求。

中断和子程序调用的差别：子程序调用是程序自己安排的，只保存 PC。中断随时可能来，还要保存 PSW，并切到内核态。

时钟中断很有代表性。定时器到点产生中断，处理程序做的是：更新系统时间，更新当前进程已用时间，减少时间片，时间片用完就调度。这就是时间片轮转的发动机。

因果

多重中断与屏蔽字

中断屏蔽字的计算放在 第 39 话，和 I/O 一起讲。这里只需要记住开中断是由 OS 软件做的。

合上页面说一遍：不看书，说出中断处理的全过程，并分开硬件和软件。

硬件：关中断、存 PC 和 PSW、取入口。软件：存通用寄存器、设屏蔽字、开中断、处理、关中断、恢复现场和屏蔽字、开中断、iret。

其之肆系统调用

应用程序请求操作系统服务的唯一接口（程序接口）。用的正是上面的陷阱机制。

术式
系统调用三句话

发起在用户态，执行在内核态。
分类：设备管理、文件、进程控制、进程通信、内存管理。
库函数和系统调用：printf 是库函数，内部调用 write；sin() 不进内核。命令解释程序（Shell）也是用户程序。

咒灵
「发生」vs「执行」

缺页发生在用户态（用户程序访存时），处理在内核态。系统调用发起在用户态，执行在内核态。进程切换连「发生」都只能在内核态。

合上页面说一遍：哪些操作会使 CPU 从用户态进内核态？

系统调用、异常（缺页、除零）、外中断。普通算术运算不会，除非它引发了异常。

领域展开

进内核只有一条路：中断或异常。
缺页 = 异常，重新执行本条；外中断回下一条。
硬件：关中断、存 PC+PSW、形成入口。OS：存通用寄存器、处理、恢复。
发起/发生在用户态，执行/处理在内核态。进程切换例外。

2014實戰特权指令的判别
下列指令中，不能在用户态执行的是（　）。

Trap 指令、跳转指令和压栈指令均可以在用户态执行，其中 Trap 指令负责由用户态转换为内核态。关中断指令为特权指令，必须在内核态才能执行。注意，在操作系统中，关中断指令是权限非常大的指令，因为中断是现代操作系统正常运行的核心保障之一，能把它关掉，说明执行这条指令的一定是权限非常大的机构（内核态）。
再深一层
选 D。三个用户态指令 + 一个特权指令，判据用 1.3-08 那张表：
A Trap 指令 ── 敲门砖，非特权，用户态执行 ✔（1.3-09 Ⅰ 同款）
B 跳转指令 ── 普通流程控制 ✔
C 压栈指令 ── 普通数据传送 ✔
D 关中断指令 ── 特权指令族②（修改系统状态）✘ 只能内核态
⭐ 书答给的记法极好，抄下来："中断是现代 OS 正常运行的核心保障之一，能把它关掉，说明执行这条指令的一定是权限非常大的机构"。
📌 关中断为什么这么危险：关掉中断后，时钟中断进不来 ⟹ 调度器再也没机会运行 ⟹ 该进程独占 CPU 直到天荒地老（系统假死）。这也是为什么原语要用"关中断"来保证原子性（1.3.1 节）—— 同一件事，在内核手里是工具，在用户手里是灾难。
🔗 串联：与 2021 真题（1.3-28，I/O 指令只能内核态）是同族题，两题合看即"特权指令三族"的抽查。
2011實戰用户态执行的程序
下列选项中，在用户态执行的是（　）。

缺页处理和时钟中断都属于中断，在内核态执行；进程调度是操作系统内核进程，无须用户干预，在内核态执行；命令解释程序属于命令接口，是面对用户的，在用户态执行。
命令解释程序（Shell）是用户程序。
再深一层
选 A。三个错项都属"内核态名单"，只有命令解释程序（Shell）在用户态：
B 缺页处理程序 ── 异常处理，内核态
C 进程调度程序 ── 内核核心，内核态

A 命令解释程序 ── 属「命令接口」，面向用户，用户态 ✔

2015實戰内部异常的性质 · 故障不一定可恢复 · 内部异常不能屏蔽
内部异常（内中断）可分为故障（fault）、陷阱（trap）和终止（abort）三类。下列有关内部异常的叙述中，错误的是（　）。

内部异常是指来自 CPU 内部产生的中断，如非法指令、地址非法、校验错、页面失效、运算溢出和除数为零等，以上都是在指令的执行过程中产生的（A 正确）。内部异常的检测是由 CPU 自身完成的，不必通过外部的某个信号通知 CPU（B 正确）。内部异常不能被屏蔽，一旦出现应立即处理（C 正确）。对于非法指令、除数为零等异常，无法通过异常处理程序恢复故障，因此不能回到原断点执行，必须终止进程的执行（D 错误）。
不是所有内部异常都返回原指令：陷阱返回下一条，终止根本不返回。
再深一层
选 D（本题选错误项）。⭐ D 错在一个「都」字上——它把「故障类可恢复时重新执行」偷换成了「内部异常一律返回原指令」。
D 的说法要成立，必须三类内部异常全都「返回发生异常的指令」，
但实际上三类的返回方式各不相同（09 题刚排过）：

  故障 · 可恢复（缺页）      ⟹ 返回【当前指令】重做   ✔ 符合 D
  故障 · 不可恢复（除零、非法指令）⟹ 【终止进程】，根本不返回  ✘
  自陷（系统调用、断点）      ⟹ 返回【下一条】指令      ✘
  终止（校验错、总线错）      ⟹ 【终止/重启】，不返回     ✘

  ⟹ 四种情形里只有一种符合 D ⟹ D 作为对「内部异常」的一般叙述，错误
📌 ⭐ 本题给「故障 ⟹ 重新执行当前指令」这句口诀补上了必要的前提：可恢复时。缺页之所以能重做，是因为处理程序把缺的那一页调进来了，客观条件变了，重做才有意义；除零重做一万次还是除零，所以只能杀进程。⟹ 「重做的前提是环境已被修复」。
⚠️ C 项「响应发生在指令执行过程中」正确，且是异常区别于中断的核心特征（04 题 A、06 题都在考）。书答顺带给了另一条重要结论：内部异常不能被屏蔽——中断有 INTR（可屏蔽）和 NMI（不可屏蔽）之分，而异常一律不可屏蔽，因为指令已经做不下去了，屏蔽也没用。
⚠️ 书答在 A 项的举例里把「校验错」也列入内部异常——没错，校验错属于终止类，是内部异常的一种（03 题）。⟹ 别把「终止是硬件中断」误读成「终止是外中断」：它是内中断里由硬件原因引起的那一类（03 题的对照表最后一行）。
🔗 2015 与 2021（5.5-13）两道真题正好互补：2015 问「是不是都返回原指令」（答：不是），2021 问「哪一个必须返回原指令」（答：缺页）。⟹ 同一个知识点，一道从反面考、一道从正面考，两道都做过才算掌握。
2016實戰异常与中断的判定 · 缺页属于异常 · DMA 结束属于中断
异常是指令执行过程中在处理器内部发生的特殊事件，中断是来自处理器外部的请求事件。下列关于中断或异常情况的叙述中，错误的是（　）。

中断是指来自 CPU 执行指令以外的事件，如设备发出的 I/O 结束中断，表示设备输入/输出已完成，希望处理机能向设备发出下一个输入/输出请求，同时让完成输入/输出后的程序继续运行。异常也称内中断，指源自 CPU 执行指令内部的事件。（⟹ 「访存时缺页」是在执行指令过程中发生的，属于异常，不属于中断，A 错误。）
再深一层
选 A（本题选错误项）。⭐ 「缺页到底算异常还是中断」是 408 最经典的一处口径混淆，必须一次钉死。
为什么缺页是【异常】而不是【中断】：

  缺页发生在哪？ ——某条 LOAD/STORE 指令【正在访存】的途中
  谁发现的？     ——CPU 内部的 MMU 查页表时发现有效位为 0
  与当前指令有关吗？——直接相关，就是这条指令要访问的那一页
  ⟹ 三问三答全指向【内部、同步、与当前指令相关】= 异常（故障类）

  ⚠️ 干扰来自 OS 教材：OS 里普遍叫它「缺页【中断】」！
     ——那是沿用「异常与中断处理流程相同、统称中断」的旧口径。
  ⟹ 408 考组原这一节时，一律按【异常（故障）】判；
     考 OS 时看到「缺页中断」四个字也不必惊慌，指的是同一件事。
📌 ⟹ 这是 408 四科口径打架的典型现场，处理原则：看题目问的是哪一科的框架。本题题干已经把框架说死了——「异常是处理器内部发生的，中断来自外部」，按这个框架缺页只能是异常。
⚠️ 逐项验一遍（用 07 题那句自问：把 CPU 停下来它还会不会发生）：
  A 访存时缺页 → 不执行指令就不会缺页 ⟹ 异常 ⟹ 说「中断」✘ 本题答案
  B 整数除以 0 → 不执行 DIV 就不会除零 ⟹ 异常 ✔
  C DMA 传送结束 → DMA 控制器自己在搬数据，与 CPU 无关 ⟹ 中断 ✔
  D 存储保护错 → 当前指令访问了越权地址才触发 ⟹ 异常 ✔
⚠️ C 项 DMA 值得多看一眼：DMA 传输过程中不打扰 CPU（这正是 DMA 的意义），只在整批传完时发一次中断通知 CPU。⟹ 它是不折不扣的外部异步事件。（ch7 会详讲 DMA 方式。）

2015實戰中断现场谁来保存
处理外中断时，应该由操作系统保存的是（　）。

外中断处理过程中，PC 值由中断隐指令自动保存，而通用寄存器的内容由操作系统保存。快表（TLB）和 Cache 中的内容在外中断处理过程中通常无须保存，直接置有效位为 0 即可。
PC 和 PSW 由硬件保存，通用寄存器由 OS 保存。
再深一层
选 B。⭐ 这是 1.3 节的第二条大分界线：「硬件做的」 vs 「OS 做的」。
硬件（中断隐指令）自动做：
  · 保存断点 PC　· 保存/更新 PSW　· 关中断　· 找中断向量、转入 ISR
操作系统（中断服务程序）做：
  · 保存通用寄存器　· 保存中断屏蔽字　· 提供具体的中断服务
  · 初始化中断向量表（开机时）
不用保存：
  · TLB、Cache ── 直接置有效位为 0（丢了可重建，不是"现场"）
📌 为什么 TLB/Cache 不用存：它们是可再生的副本 —— 页表和主存里有权威数据，重建一次就是了；而通用寄存器里的值一丢就永远回不来。
🔗 串联：本题与 2020（1.3-27）、2022（1.3-31）是"同一刀砍三年"：
2015：外中断中 OS 保存什么　　　→ 通用寄存器
2020：中断相关操作哪些由 OS 做 → 服务 + 初始化向量表 + 存屏蔽字
2022：系统调用中哪些由 OS 做　 → 保存通用寄存器 + 执行服务例程
  三年答案一致：断点/PSW/模式位＝硬件；通用寄存器/屏蔽字/例程＝OS

2012實戰中断处理与子程序调用的比较
中断处理和子程序调用都需要压栈以便保护现场，中断处理一定会保存而子程序调用不需要保存其内容的是（　）。

子程序调用不改变程序的状态，因为子程序调用是编译器可控的流程，而中断不是。下面以程序 if(a==b) 为例加以说明。该程序通常包含一条测试指令，以及一条根据标志位决定是否需要跳转来调用子程序的指令。编译器不在这两条指令中间插入任何子程序调用代码，因此标志位不变，但中断随时可能发生，导致标志位改变。具体地说，执行 if(a==b) 时，会进行 a−b 操作，并生成相应的标志位，进而根据标志位来判断是否发生跳转。假设刚好在生成相应的标志位后发生了中断，若不保存 PSW 的内容，则后续根据标志位来进行跳转的流程就可能发生错误。但是，若进行了子程序调用，则说明已经根据 a−b 的标志位进行了跳转，此时 PSW 的内容已无意义而无须保存。综上所述，中断处理和子程序调用都有可能使 PSW 的内容发生变化，但中断处理程序执行完返回后，可能需要用到 PSW 原来的内容，子程序执行完返回后，一定不需要用到 PSW 原来的内容，因此选择选项 B。选项 A 都会保存，选项 C 和 D 不一定会保存。
子程序调用只需要保存 PC；中断还要保存 PSW。
再深一层
选 B（PSW）。四个选项按"保存与否"三分，只有一格满足题干：
A 程序计数器 PC ── 两者「都」保存（不存就回不来）✘
B 程序状态字 PSW ─ 中断「一定」存；子程序「不需要」存 ✔
C/D 通用寄存器 ── 两者都「不一定」存（看调用约定/是否被用到）✘
⭐ 书答那个 if(a==b) 例子是本题的灵魂，用一句话概括：
子程序调用发生在"标志位已经用完"的时刻（编译器安排的），中断却可能插在"标志位刚生成、还没用"的缝里。
cmp a, b        ← 这里生成标志位（PSW 中的 ZF/SF/CF…）
   ↑ 中断可能正好插在这一行与下一行之间 ⟹ 必须存 PSW
jne  L1         ← 这里用掉标志位
call func       ← 编译器安排的调用点：标志位已用完，PSW 可弃
📌 另一条更好记的理由：中断要切换特权级（PSW 里就有模式位），不存 PSW 就不知道该返回用户态还是内核态；子程序调用不跨态，PSW 的模式位根本不变。（这正是 1.3-14 选项 A 的考点。）
🔗 串联：中断处理 vs 子程序调用的六条区别（1.3.3 节）—— 独立性 / 随机性 / 硬件支持 / 入口地址来源（中断向量表 vs CALL 地址码）/ PC 谁来存 / 是否要优先级裁决。2012 这道题只考了第 5 条的延伸。
2016實戰中断和异常的分类
异常是指令执行过程中在处理器内部发生的特殊事件，中断是来自处理器外部的请求事件。下列关于中断或异常情况的叙述中，错误的是（　）。

中断是指来自 CPU 执行指令以外事件的发生，如设备发出的 I/O 结束中断，表示设备输入/输出处理已经完成，希望处理机能够向设备发出下一个输入/输出请求，同时让完成输入/输出后的程序继续运行。异常也称内中断，指源自 CPU 执行指令内部的事件。选项 A 错误。
再深一层
选 A（A 是错误叙述）。题干已经把判据写好了，只需逐个套：
判据：事件源在 CPU「内部」＝异常；在「外部」＝中断

A 访存时缺页 ── 是「这条访存指令」引发的 ⟹ 内部 ⟹ 异常 ✘题目说中断
B 整数除以零 ── 是「这条除法指令」引发的 ⟹ 异常 ✔
C DMA 传送结束 ── DMA 控制器（外部器件）发来的 ⟹ 中断 ✔
D 存储保护错 ── 访存越权，仍由指令引发 ⟹ 异常 ✔
⭐ "缺页中断"这个中文名是 408 最大的命名陷阱：它叫中断、写作中断、但分类上属于异常中的故障（Fault）。凡见"缺页"，一律归异常。
📌 再给一条自检：异常与指令同步（同一条指令必然重现同一异常），中断与指令异步（同一段程序跑两遍，中断来的时机可能不同）。缺页是同步的（同一条指令访同一页必然再缺）⟹ 异常。
🔗 串联：1.3-12 里的 Ⅲ 缺页中断也是同一考点，ch1 考了两次。
2018實戰时钟中断服务的内容
定时器产生时钟中断后，由时钟中断服务程序更新的部分内容是（　）。
Ⅰ. 内核中时钟变量的值
Ⅱ. 当前进程占用 CPU 的时间
Ⅲ. 当前进程在时间片内的剩余执行时间

时钟中断的主要工作是处理和时间有关的信息及决定是否执行调度程序。和时间有关的所有信息包括系统时间、进程的时间片、延时、使用 CPU 的时间、各种定时器。
时钟中断服务程序做的就是这些：更新时间、进程用了多久、还剩多少时间片。
再深一层
选 D（三条全更新）。时钟中断＝OS 的心跳，每一跳干两件事：
① 更新一切与时间有关的量：
   · 系统时间 / 内核时钟变量（Ⅰ）
   · 当前进程已占用 CPU 的累计时间（Ⅱ）
   · 当前进程时间片的剩余量（Ⅲ）
   · 各种延时与定时器倒计时
② 决定要不要调度：时间片耗尽 ⟹ 置调度标志 ⟹ 切换进程
⭐ 为什么三条都对：它们全都"必须在中断里改" —— 进程自己在用户态跑的时候没有能力也没有资格更新这些内核数据；只有时钟中断把 CPU 夺回内核，才有机会记账。没有时钟中断，抢占式调度就不存在。
📌 1.3.1 节原话可以直接引："系统的大量活动均依赖于时钟机制"；分时靠它轮转、实时靠它算截止期、批处理靠它衡量作业进度。
🔗 串联：1.2-16（多道需要中断支持）→ 本题（时钟中断的具体内容）→ ch2 的时间片轮转调度，是一条完整的因果链。
2012實戰用户态发生 vs 用户态执行
下列选项中，不可能在用户态发生的事件是（　）。

本题的关键是对“在用户态发生”（注意与“在用户态执行”区分）的理解。对于选项 A，系统调用是操作系统提供给用户程序的接口，系统调用发生在用户态，被调用程序在内核态下执行。对于选项 B，外中断是用户态到内核态的“门”，也发生在用户态，在内核态完成中断处理过程。对于选项 C，进程切换属于系统调用执行过程中的事件，只能发生在内核态。对于选项 D，缺页产生后，在用户态发生缺页中断，然后进入内核态执行缺页中断服务程序。
进程切换必须在内核态才能发生。
再深一层
选 C。⭐ 这是 1.3 节的"总纲题"——"发生"与"执行"必须分开：
事件　　　　发生在哪　　　　　处理/执行在哪
系统调用　　用户态（用户敲的）→ 内核态（服务例程）
外中断　　　用户态（正跑用户程序时来的）→ 内核态（ISR）
缺页　　　　用户态（用户程序访存时）→ 内核态（缺页服务程序）
进程切换　　内核态（调度器决定的）→ 内核态
  ⟹ 只有进程切换连「发生」都轮不到用户态 ✔ C
📌 怎么记住"进程切换只在内核态"：切换要保存/恢复 PCB、改页表基址寄存器、切内核栈 —— 每一步都要特权指令。用户程序连"想切"都表达不了，它只能阻塞自己（系统调用）或被时钟中断打断，切换永远由内核发起。
🔗 串联：2021 真题（1.3-29）问"通过系统调用完成的操作"，错项里正好有进程调度（OS 自己完成、不经系统调用）—— 与本题同一条线。
⚠️ 别把本题的 C 与"进程切换需要中断"混起来：时钟中断可以触发调度，但中断发生在用户态、切换动作发生在内核态。
2017實戰系统调用的处理过程
执行系统调用的过程包括如下主要操作：
① 返回用户态　　② 执行陷入（Trap）指令
③ 传递系统调用参数　　④ 执行相应的服务程序
正确的执行顺序是（　）。

执行系统调用的过程：正在运行的进程先传递系统调用参数，然后由陷入（Trap）指令负责将 CPU 模式从用户态转换为内核态，并将返回地址压入堆栈以备后用，接下来 CPU 执行相应的内核态服务程序，最后返回用户态。
传参、陷入、服务、返回。
再深一层
选 C（③→②→④→①）。四步顺序的记法：先把货备好，再敲门，人家干活，最后送客。
③ 传递系统调用参数 ── 压栈或放寄存器（还在用户态）
      ↓
② 执行陷入指令　── 用户态 → 内核态；硬件存 PC/PSW
      ↓
④ 执行服务程序　── 内核按系统调用号查系统调用表 → 跑例程
      ↓
① 返回用户态　　── IRET 恢复现场，从断点继续
📌 为什么参数必须在陷入之前传？因为陷入之后 CPU 已经在内核，内核要立刻知道"你要我干什么"（系统调用号）和"参数在哪"。这也是干扰项 A（②→③）和 B（②→④→③）被否掉的原因 —— 它们都把"传参"排到了陷入之后。
⚠️ D（③→④→②→①）更离谱：还没陷入就执行服务程序 ⟹ 用户态跑内核代码，权限模型直接崩塌。
🔗 串联：1.3.4 节的四阶段原文比选项更细（第 2 步里"硬件与内核协同保存现场，将 PC、PSW 及通用寄存器压入内核堆栈"）—— 2022 真题（1.3-31）正是把这一步再切开考"谁保存了什么"。
2013實戰用户态切换到内核态的事件
下列选项中，会导致用户进程从用户态切换到内核态的操作是（　）。
Ⅰ. 整数除以零　　Ⅱ. sin() 函数调用　　Ⅲ. read 系统调用

整数除以零是非法操作，因此 CPU 会检测到异常，并切换到内核态进行异常处理。sin() 函数是 C 语言中的普通运算类库函数，且不会引发系统调用，在用户态执行。在用户态触发 read 系统调用时，会通过 Trap 指令陷入内核态，由 CPU 执行相应的系统调用服务例程。
除零（异常）、read（系统调用）都进内核；sin() 只是普通函数。
再深一层
选 B（Ⅰ、Ⅲ）。三条恰好各代表一种"能不能进内核"的情形：
Ⅰ 整数除以零 ── 异常（故障 Fault）⟹ 硬件强制切内核态 ✔
Ⅱ sin() ────── 纯计算库函数，全程用户态，不碰内核 ✘
Ⅲ read ─────── 系统调用，Trap 指令陷入 ⟹ 内核态 ✔
⭐ Ⅱ 就是 1.1-10 那个"并非所有库函数都依赖系统调用"的实证：strlen、sqrt、sin、abs 全程不进内核；printf、malloc、fopen 才会。2013 年把这个考点从"说法判断"升级成了"具体函数"。
📌 进内核态的三条路（1.3.4 节末尾的四种情形）：
　① 系统调用（主动，Ⅲ）　② 外中断（被动，I/O 完成、时钟）　③ 异常（被动，Ⅰ 的除零、缺页）　④ 用户程序试图执行特权指令（触发异常，本质仍是 ③）。
⚠️ 易错点：sin() 若参数非法（如溢出）会不会异常？C 标准库对 sin 定义域是全体实数，不会触发浮点异常 —— 王道按"纯计算不进内核"处理即可。
2015實戰可能引发异常的指令
假定下列指令已装入指令寄存器，则执行时不可能导致 CPU 从用户态变为内核态（系统态）的是（　）。

部分指令可能出现异常，从而转到内核态。指令 A 有除零异常的可能。指令 B 为软中断指令，用于触发一个中断并跳转到相应的中断处理程序，n 表示中断向量号，使用软中断可以在用户态和内核态之间切换，以实现系统调用。指令 D 有缺页异常的可能。指令 C 不会发生异常。
NOT R0 是普通算术，既没有访存也不除，不可能出错。
再深一层
选 C。逐条问"这条指令有没有可能出事"：
A DIV R0,R1 ── 若 (R1)=0 ⟹ 除零异常（故障）⟹ 进内核 ✘可能
B INT n ──── 软中断＝自陷，本来就是用来进内核的 ✘可能
C NOT R0 ─── 寄存器内取非：不访存、不除法、不陷入
              ⟹ 无论如何都不会异常 ✔ 选 C
D MOV R0,addr ── 访存！可能缺页（故障）或越界 ⟹ 进内核 ✘可能
⭐ 本题的解法是"找那条最无害的指令"，判据两条：① 是否访存（→缺页/越界）② 是否有非法运算可能（→除零/溢出）。只在寄存器之间倒腾的指令最安全。
📌 D 是最容易漏的：一条普通的取数指令怎么会进内核？因为虚拟存储下访存随时可能缺页 —— 缺页是"故障"，处理完还要重新执行这条指令（1.3.3 节）。ch3 的请求分页就建在这个机制上。
🔗 串联：与 2013（1.3-19）的"整数除以零"、2016（1.3-23）的"缺页属异常"，三题都在同一个"哪些事件是异常"的池子里取材。
2019實戰系统调用的定义与性质
下列关于系统调用的叙述中，正确的是（　）。
Ⅰ. 在执行系统调用服务程序的过程中，CPU 处于内核态
Ⅱ. 操作系统通过提供系统调用避免用户程序直接访问外设
Ⅲ. 不同的操作系统为应用程序提供了统一的系统调用接口
Ⅳ. 系统调用是操作系统内核为应用程序提供服务的接口

用户可以在用户态调用操作系统的服务，但执行具体的系统调用服务程序是处于内核态的，说法 Ⅰ 正确；设备管理属于操作系统的职能之一，包括对输入/输出设备的分配、初始化、维护等，用户程序需要通过系统调用使用操作系统的设备管理服务，说法 Ⅱ 正确；操作系统不同，底层逻辑、实现方式均不相同，为应用程序提供的系统调用接口也不同，说法 Ⅲ 错误；系统调用是用户在程序中调用操作系统提供的子功能，说法 Ⅳ 正确。
再深一层
选 C（仅 Ⅲ 错）。Ⅲ 错在"统一"二字：
Linux：read / write / fork / execve / mmap …
Windows：ReadFile / WriteFile / CreateProcess /
           VirtualAlloc …
  ⟹ 名字、编号、参数、语义全都不同 ⟹ 系统调用「不统一」
  真正"统一"的是标准库层（POSIX / C 标准库）——
  这正是 1.1-10 说的「库函数可移植性好、系统调用与 OS 紧耦合」
📌 Ⅲ 与 Ⅳ 放在一起就是本题设计的巧妙处：Ⅳ 说"系统调用是内核为应用程序提供服务的接口"（对），Ⅲ 顺势诱你以为"既然都是接口那就统一"（错）。接口存在 ≠ 接口统一。
⭐ Ⅱ 的因果要背：不让用户程序直接碰外设 → 只能通过系统调用请内核代劳 → 系统的安全与稳定。这条也是 1.1-08、1.3-15 的同一句。
🔗 串联：Ⅰ 与 2024 真题（1.3-33）的 B/C 选项同源，"执行服务例程时一定在内核态"是历年反复确认的常量。
2010實戰操作系统提供给应用程序的接口
下列选项中，操作系统提供给应用程序的接口是（　）。

操作系统接口主要有命令接口和程序接口（也称系统调用）。库函数是高级语言中提供的与系统调用对应的函数（也有些库函数与系统调用无关），目的是隐藏“访管”指令的细节，使系统调用更为方便、抽象。但是，库函数属于用户程序而非系统调用，是系统调用的上层。
再深一层
选 A。四个选项分属四个不同层次，逐个排掉：
A 系统调用 ── OS 主动向应用程序开放的接口          ✔
B 中断 ──── 硬件/外设触发的通道，不是「提供给应用程序用」的
C 库函数 ── 属于用户程序一侧，是系统调用的上层封装
D 原语 ──── OS 内核内部的不可中断操作，对应用程序不可见
📌 B 与 D 是本题最容易忽略的两个陷阱：
　· 中断确实是"进内核的门"，但那是被动进入（外设/异常触发）；系统调用是应用程序主动敲的门。门与接口不是一回事。
　· 原语（进程切换、P/V 操作、资源分配）运行在内核态、执行不可中断，是内核实现系统调用用到的零件，不对外暴露。
🔗 串联：把这四个词按"谁能看见"排一次序 ——
应用程序看得见：系统调用（和它的封装：库函数）
应用程序看不见：原语、中断处理程序（都在内核里）
这条线在 1.3 节会被反复地考（题 09、11、16、17、28）。
做完再翻：这些题到底在问什么

这一节的题目密度极高，问的就是几条分界线：
发生 vs 执行：缺页发生在用户态，处理在内核态；只有进程切换连发生都在内核态。
硬件 vs OS 分工：PC、PSW 硬件保存；通用寄存器 OS 保存。
返回到哪：外中断和陷阱回下一条；故障回本条；终止不回。
指令属于哪一态：trap 在用户态才用得上；关中断、写 PSW、I/O 都是特权。普通 NOT R0 既不访存也不除，不可能引发态的切换。
