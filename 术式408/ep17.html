先答旧题
机器字长、存储字长、指令字长分别对应哪个部件？
通用寄存器/ALU、MDR、IR。
CPU 时间公式？
指令条数 × CPI ÷ 主频。
CPU 怎样区分指令和数据？
取指周期取到的是指令，执行周期取到的是数据。

这一话的中心是一句话：机器里只有一串位，它是什么数，由你怎么解释决定。同一个 1111 0110，看成无符号是 246，看成补码是 −10。抓住这一点，所有 C 语言类型转换题都变成同一道题。

其之壹进位计数制

机器只认二进制，人爱看十进制，十六进制是二进制的缩写（4 位一组）。

十进制转二进制：整数部分除 2 取余，倒着写；小数部分乘 2 取整，顺着写。例如 13.625：13 = 1101，0.625 → 1.25 取 1，0.5 取 0，1.0 取 1，得 .101，所以 1101.101B = D.AH。有些小数（比如 0.1）转不尽，这是浮点数精度问题的来源。

其之貳四种编码

以 8 位为例，真值范围和转换方法：

编码规则8 位范围零
原码最高位是符号，其余是绝对值−127 ~ +127+0、−0 两个
反码负数：符号外全部取反−127 ~ +127+0、−0 两个
补码负数：取反 +1−128 ~ +127只有一个
移码真值 + 偏置值（8 位偏置常取 128）−128 ~ +127只有一个
术式
补码三招

负数求补码：绝对值的二进制「取反 +1」。或者从右往左，第一个 1 及其右边不变，左边全部取反。
求 −x：不管 x 正负，连符号位一起「取反 +1」。
真值：−b₇·2⁷ + b₆·2⁶ + … + b₀。最高位是负权，这是最本质的定义。

移码就是补码把符号位取反。它的好处是比大小时可以直接按无符号比，所以浮点数的阶码用它。

比方

补码就是时钟

12 小时的钟上，往回拨 2 小时和往前拨 10 小时是一回事。n 位补码就是一个模 2ⁿ 的钟：减 x 等于加 2ⁿ−x。这就是为什么 减法可以用加法器做，补码的全部意义都在这里。

术式
边界值（必背）

n 位补码：最小 −2^(n−1)（1000…0），最大 2^(n−1)−1（0111…1），−1 是全 1。
n 位无符号：最大 2ⁿ−1（全 1）。
8 位 −128 的机器数 80H；16 位 −32768 的机器数 8000H；32 位 8000 0000H。

其之參C 语言类型转换：位不变，解释变

▣ 一串位的四次变身
char c = −10 （F6H）
同一串位。按补码解释是 −10。
(unsigned char)c = 246
转成无符号：一个位都不改，只是换了解释方式。246 = 256 − 10。
(short)c = −10 （FFF6H）
扩展到 16 位：看==原类型==。原来是有符号，高位补符号位（符号扩展）。
(unsigned short)(unsigned char)c = 246
原类型无符号：高位补 0（零扩展）。
(char)(short)0x12F6 = F6H
短转短：直接截断，只留低位。可能改变真值。
术式
转换三条规则

① 同宽度：位不变，解释变。无符号 = 补码 + 2ⁿ（补码为负时）。
② 长→短：截断高位。
③ 短→长：看原类型，无符号补 0（零扩展），有符号补符号位（符号扩展）。
混合运算：int 和 unsigned 运算时，int 转成 unsigned。

这就是 C 语言强制类型转换的全部规则。一个容易出事的例子：unsigned n = 0; for (int i = 0; i <= n - 1; i++)。n−1 是无符号，等于 2³²−1；i 也被转成无符号比较，条件永远成立，死循环。

合上页面说一遍：同一串位：转成同宽无符号、截短、加长，分别怎么变？

同宽位不变；截短留低位；加长看原类型，有符号补符号位，无符号补 0。

其之肆加法器与标志位

一位全加器有三个输入（两个加数位和低位来的进位），两个输出。为什么 n 位加法器能同时做加减？因为前面说过，减 Y 等于加 Y 的补码，即 Y 取反再加 1。

一位全加器：S = A⊕B⊕C_in，C_out = AB + (A⊕B)C_in。n 个串起来就是串行进位加法器，进位一位位传，慢；先行进位（CLA） 用并行逻辑同时算出所有进位，快。ALU 的核心就是一个带控制端的加法器。

术式
四个标志位

ZF 结果全 0。SF 结果最高位（看作有符号时的符号）。
OF 有符号溢出：OF = C_n ⊕ C_(n−1)（最高位进位 ⊕ 次高位进位）。等价：两个同号数相加，结果符号相反。
CF 无符号的进位/借位：CF = C_out ⊕ Sub。加法时 CF=C_out，减法时取反。

走一遍 8 位运算，四个标志都算：

运算机器数结果ZFSFOFCF含义
127 + 17F + 01800110有符号溢出，无符号 128 正确
255 + 1（即 −1 + 1）FF + 01001001无符号溢出，有符号 0 正确
3 − 503 − 05FE0101无符号不够减，有符号 −2 正确

判断溢出的三种等价办法：① 同号相加，结果变号；② 最高位进位和次高位进位不同；③ 双符号位（变形补码）：用两位符号，00 正、11 负是正常，01 正溢出、10 负溢出。双符号位只在运算时用，存储时只存一位，因为正常数的两位符号总是相同的。

其之伍移位

术式
三种移位

逻辑移位（无符号）：左右都补 0。
算术右移（有符号）：高位补符号位，相当于 ÷2 向下取整。
算术左移：低位补 0，相当于 ×2，符号位变化则溢出。

咒灵
−1 算术右移还是 −1

补码负数右移是向负无穷取整。−1>>1 = −1。所以 C 里 -1/2 = 0 但 -1>>1 = -1。

其之陸乘除

乘除的电路比加减复杂，但原理就是竖式，只要明白结构。

比方

就是竖式

二进制乘法就是竖式：看乘数的最低位，是 1 就把被乘数加到积的高半部分，然后积和乘数一起右移一位。除法是试减：不够减商 0，够减商 1。

术式
乘除要记的结论

n 位 × n 位 = 2n 位。 C 的 int * int 只取低 32 位，所以可能溢出。
乘法溢出判断：有符号：高 n 位不是低 n 位符号的扩展；无符号：高 n 位不全为 0。
除法溢出：只有 最小负数 ÷ (−1)，以及除以 0（产生异常）。
C 语言整数除法向 0 取整；移位是向下取整。

补码一位乘（Booth） 看乘数相邻两位：01 加被乘数，10 减被乘数，00、11 只移位。连续的 1 只在头尾各算一次，减少加法次数。

除法是试减：够减商 1，不够商 0。恢复余数法不够减时要把减掉的加回来。不恢复余数法（加减交替）不加回，下一步改成加，节省步骤。商一共 n 位时要做 n 次（加减交替的第一步另算）。

硬件：乘法器由被乘数寄存器、乘积寄存器、加法器和计数器组成。除法器类似，用左移。多位乘法也可做成阵列乘法器，用更多电路换速度。

因果

移位 + 加法替代乘法

x*5 = (x<<2)+x。机器级代码里 lea、shl 出现，编译器就是这么做的。在读汇编题时要能看出来。

领域展开

一串位：同宽转换位不变；长转短截断；短转长看原类型。
补码：最高位负权，范围多一个负数。
标志：CF 看无符号，OF 看有符号。OF=最高两位进位异或。
移位：算术右移补符号，向下取整。

2015實戰定数量0/1的极值排列
由 3 个 “1” 和 5 个 “0” 组成的 8 位二进制补码，能表示的最小整数是（　）。

原码很容易判断大小，而负数的补码很难直接判断大小，可采用如下规则快速判断：对于负数，数值位部分越小，其绝对值越大，即负得越多。采用补码整数表示时，负数的符号位为 1，因此剩下的两个 “1” 放在末位时其值最小，补码形式为 1000 0011，转换为真值为 −125。此外，考虑负数的补码转换为原码的方法，从右向左找到第一个数值为 1 的位，之后的每位进行取反操作，符号位不变，不难发现，当符号位为 1，剩下的两个 “1” 放在末位时，补码的绝对值最大。
3 个 1，要最小：符号位放 1，其余两个 1 放最低位，得 1000 0011 = −128 + 3 = −125。
再深一层
选 B。Python 穷举 C(8,3)=56 种排列，最小值确为 −125：
要"最小"（负得最多）：
  第一步 符号位必须为 1（否则是正数）—— 花掉 1 个 “1”，还剩 2 个
  第二步 数值位要尽量小 ⟹ 剩下 2 个 “1” 全部赶到最低位
  ⟹ 1 000 0011
  真值 = 131 − 256 = −125   ✔ 选 B

对照（若把 1 堆到高位）：1 110 0000 = 224 − 256 = −32
  ← 选项 C，那是最大的那一类
📌 这道 2015 真题就是习题 22、23 的原型，三题一套动作，核心那句话已经出现第五次了：「负数补码，数值位越小 → 绝对值越大 → 负得越多」。
⚠️ 四个选项刚好把四种错法钉死：
选项对应哪种想法诊断
−1261000 0010 —— 只放了 2 个 1数错了 1 的个数（题目要 3 个）
−1251000 0011✔ 3 个 1，且都在最低处
−321110 0000 —— 把 1 堆到高位方向反了，这是最大的负数之一
−3把 1111 1101 之类当答案用了 6 个 1，且把"绝对值小"当成了"最小"
−126 这个选项最阴：它离正确答案只差 1，且位模式几乎一样，专门抓"忘了符号位也占一个 1"的人。做完一定数一遍位模式里 1 的个数。
⚠️ 书上给的第二种验证法很值得学（补码转原码的快法）：从右往左找到第一个 1，该 1 及其右侧照抄，左侧到符号位为止全部取反。1000 0011 → 最右的 1 在第 0 位，照抄 1，左边 000001 取反成 111110 ⟹ 原码 1111 1101 = −125 ✔ 一步到位。
🔗 "最小 vs 最大"这类题一定要先把目标翻译成位模式的语言再动手："最小" = 符号位 1 + 数值位最小；"最大" = 符号位 0 + 数值位最大。翻译这一步做对了，后面纯粹是堆位游戏。
2016實戰C 类型转换·等长换解释
有如下 C 语言程序段，执行上述两条语句后，usi 的值为（　）。
short si = -32767;
unsigned short usi = si;

因 C 语言中的数据在内存中为补码表示形式，si 对应的补码为 1000 0000 0000 0001B，最前面的一位 “1” 为符号位，表示负数，即 −32767。由 signed 型数转换为等长的 unsigned 型数时，符号位成为数据的一部分，即负数转换为无符号数（正数）时，其数值将发生变化。usi 对应的补码与 si 的相同，但表示正数，为 32769。
位不变：−32767 = 8001H，当无符号就是 32769。
再深一层
选 D。Python 复算：
si = −32767（16 位 short）
  |−32767| = 0111 1111 1111 1111
  取反加 1 ⟹ 1000 0000 0000 0001 = 0x8001

转 unsigned short：【位模式一个字节都不动】，只换解释方式
  0x8001 按无符号读 = 32769   ✔ 选 D

自查：32769 + 32767 = 65536 = 2¹⁶ ✔
     （负数 x 转等长无符号后 = x + 2ⁿ）
📌 等长转换的黄金公式，两个方向各一条：
· 负数 → 无符号：结果 = x + 2n（本题：-32767 + 65536 = 32769）；
· 大无符号数 → 有符号：结果 = x − 2n（2019 真题：65535 - 65536 = -1）。
两条其实是同一条：位模式不变，只是"2n 这一坨"在两种解释里归不归数值管。考场上不必转二进制，直接加减 65536 即可。
⚠️ 选项 C 的 32768 是最大的陷阱，因为 32768 = 215 看着特别"整"，很多人凭感觉觉得 −32767 的对面就是它。用公式一秒排除：-32767+65536 = 32769，不是 32768。（32768 对应的机器数是 1000 0000 0000 0000，那是 si = −32768 的情形，差一位。）
⚠️ A 是"以为值不会变"（unsigned 里根本没有负数，不可能是 −32767）；B 是"以为会取绝对值"——类型转换从不做算术，只重新解释位。牢记：等长转换 = 换个眼镜看同一串位，一个 bit 都不会动。
🔗 与 2019 真题（习题 31）是同一道题的反向版：那题从 unsigned short 转 short，同样位模式不动，值从 65535 变成 −1。两题连起来记，2016 和 2019 一起拿下。
2019實戰C 类型转换·等长换解释
考虑以下 C 语言代码，执行上述程序段后，si 的值是（　）。
unsigned short usi = 65535;
short si = usi;

unsigned short 型为无符号短整型，长度为 2 字节，因此 unsigned short usi = 65535 转换为二进制代码即 1111 1111 1111 1111。short 型为短整型，长度为 2 字节，在采用补码的机器上，short si 的二进制代码为 1111 1111 1111 1111，因此 si 的值为 −1。
65535 = FFFFH，当补码就是 −1。
再深一层
选 A。Python 复算：
usi = 65535（16 位无符号最大值）
  = 1111 1111 1111 1111 = 0xFFFF

转 short（等长，16→16）：位模式不动，只换解释
  0xFFFF 按 16 位补码读 = 65535 − 65536 = −1   ✔ 选 A

或直接用特值：补码全 1 恒等于 −1（任何字长）
📌 本题的一秒解法：全 F 的机器数按补码读就是 −1，这是习题 18 已经背过的特值。考场上看到 65535 / 0xFFFF / 全 1，不用算，直接答 −1。
⚠️ 选项 D 的 −65535 是"以为加个负号就完事"——16 位 short 的范围是 -32768 ~ 32767，−65535 根本装不进去。做完先用"范围检查"过一遍：答案必须落在目标类型的范围内，否则一定错。这一招能秒杀本题的 D，也能防住很多类型转换题的低级错误。
⚠️ B、C 是"把 65535 当成接近 32768 的数"随手改的；注意 −32768 对应的是 0x8000（最小值），−32767 对应 0x8001（正好是 2016 真题的位模式），都与 0xFFFF 相去甚远。三个干扰项各自对应一个具体的位模式，认位模式比认数字可靠。

2012實戰C 类型转换·零扩展
假定编译器规定 int 型和 short 型长度分别为 32 位和 16 位，执行下列 C 语言语句后，得到 y 的机器数为（　）。
unsigned short x=65530;
unsigned int y=x;

将一个 16 位 unsigned short 型数转换为 32 位 unsigned int 型数时，因为都是无符号数，新表示形式的高位用 0 填充。16 位无符号整数所能表示的最大值为 65535，其十六进制表示为 FFFFH，因此 x 的十六进制表示为 FFFFH − 5H = FFFAH，所以 y 的十六进制表示为 0000 FFFAH。
无符号扩展补 0。
再深一层
选 B。Python 复算：
x 是 unsigned short（16 位无符号），值 65530
  65530 = 65535 − 5 = 0xFFFF − 0x5 = 0xFFFA
         = 1111 1111 1111 1010

源是【无符号】⟹ 零扩展，高 16 位补 0
  y = 0x0000FFFA = 65530  ✔ 值不变 ⟹ 选 B
📌 这道 2012 真题是「C 类型转换四象限」的第一个格子，和 2016/2019/2025 三年的真题（习题 29、31、34）合起来正好是同一道题的四个变形。把这张表背下来，四年真题一次收掉：
年份转换字长变？符号性变？动作值变吗
2012unsigned short → unsigned int变（16→32）不变零扩展不变（65530）
2016short → unsigned short不变变只换解释变（−32767→32769）
2019unsigned short → short不变变只换解释变（65535→−1）
2025short → unsigned int变也变先符号扩展，再重解释变
⚠️ 解题的固定动作，两问定生死：
① 字长变了吗？变了 → 要扩展（看源的符号性决定零扩展还是符号扩展）；
② 符号性变了吗？变了 → 位模式不动，只换解释方式。
两个都变时必须按「先扩展、后重解释」的顺序做，顺序反了答案就错（2025 真题的唯一陷阱）。
⚠️ 本题四个选项按"高位填什么 × 数据本身对不对"排开：C、D 填了 F（误用符号扩展，把无符号源当有符号了）；A、C 写成 7FFA（把 0xFFFA 的最高位错抹成 0）。只有 B 两处都对。
⚠️ 心算 65530 的十六进制：不要去除 16，用 0xFFFF − 5 = 0xFFFA。凡是靠近 65535/65536 的数都这么减，比长除法快十倍。
2018實戰CF 与 OF 的同时判断
减法指令 “sub R1, R2, R3” 的功能为 “(R1)−(R2)→R3”，该指令执行后将生成进位/借位标志 CF 和溢出标志 OF。若 (R1) = FFFF FFFFH，(R2) = FFFF FFF0H，则该减法指令执行后，CF 与 OF 分别为（　）。

[x]补 − [y]补 = [x]补 + [−y]补，[−R2]补 = 0000 0010H，很明显 [R1]补 + [−R2]补 的最高位进位和符号位进位都是 1（当最高位进位和符号位进位的值不相同时才产生溢出），可以判断溢出标志 OF 为 0。同时，减法操作只需判断借位标志，R1 大于 R2，所以借位标志为 0。
手算 (R1)−(R2)：大减小，无借位，CF=0；同号相减不会溢出，OF=0。
再深一层
选 A。CF 和 OF 要分两条线各判一次——这就是"一次减法、两种语义"的标准考法：
机器数：R1 = FFFF FFFFH，R2 = FFFF FFF0H

【当有符号数看】（判 OF）
  R1 = −1，R2 = −16
  R1 − R2 = −1 − (−16) = +15
  15 稳稳落在 [−2³¹, 2³¹−1] 内 ⟹ OF = 0
  （另一角度：只有异号相减才可能溢出；
    本题两个数都是负的 ⟹ 同号相减 ⟹ 绝不溢出）

【当无符号数看】（判 CF）
  R1 = 4294967295，R2 = 4294967280
  R1 ＞ R2 ⟹ 够减，不需要借位 ⟹ CF = 0

⟹ (CF=0, OF=0)  选 A
📌 本题的解题模板值得固化下来，凡是"求 CF 和 OF"的题都照这个走：
标志把机器数当什么读判据
OF有符号补码真值结果是否超出 [-2n-1, 2n-1-1]
（或：同号相加/异号相减且结果变号）
CF无符号数减法：被减数 ＜ 减数 ⟹ 借位 ⟹ CF=1
加法：结果 ≥ 2n ⟹ 进位 ⟹ CF=1
⟹ 硬件两个都算，你分两次读题：一次戴"有符号"眼镜，一次戴"无符号"眼镜。
⚠️ 减法的 CF 有个电路细节容易记反：CF = Sub ⊕ Cout。本题 Sub=1，加法器算 R1 + R2 + 1 会产生进位 Cout=1，所以 CF = 1 ⊕ 1 = 0 ⟹ 无借位。直接抄 Cout（写成 CF=1）是最常见错法——做减法时"有进位"恰恰意味着"没借位"，两者是反的。
⚠️ 考场提速：不必碰电路，用大小关系判 CF。无符号数减法只问一句：被减数够不够减？够 ⟹ CF=0，不够 ⟹ CF=1。本题 FFFF FFFF ＞ FFFF FFF0，一眼够减。
🔗 与 2023 真题（习题 32）是同一考点的进阶版：那题给你一组数的 CF/OF，让你推另一组数的 CF/OF。本题是基本功，那题是应用，务必先把本题的两条线分清。
2010實戰补码运算的溢出判断
假定有四个整数用 8 位补码分别表示：r1 = FEH，r2 = F2H，r3 = 90H，r4 = F8H。若将运算结果存放在一个 8 位寄存器中，则下列运算会发生溢出的是（　）。

本题的真正意图是考查补码的表示范围，采用补码乘法规则计算出四个选项是费力不讨好的做法，且极易出错。8 位补码所能表示的整数范围为 −128~+127。将四个数全部转换为十进制数：r₁ = −2，r₂ = −14，r₃ = −112，r₄ = −8，得 r₂ × r₃ = 1568，远超出了表示范围，发生溢出。
把每个看成 8 位补码：r1=−2，r2=−14，r3=−112，r4=−8。逐项乘：−14 × −112 = 1568，超 127，溢出。
再深一层
选 B。Python 复算——转真值、算乘积、比范围，三步走完：
FEH = 1111 1110 ⟹ r₁ = −2      （254 − 256）
F2H = 1111 0010 ⟹ r₂ = −14     （242 − 256）
90H = 1001 0000 ⟹ r₃ = −112    （144 − 256）
F8H = 1111 1000 ⟹ r₄ = −8      （248 − 256）

8 位补码范围 [−128, 127]：
  A. r₁×r₂ = (−2)×(−14)   =   28   ✔ 在范围内
  B. r₂×r₃ = (−14)×(−112) = 1568   ✘ 远超 127 ⟹ 溢出，选 B
  C. r₁×r₄ = (−2)×(−8)    =   16   ✔
  D. r₂×r₄ = (−14)×(−8)   =  112   ✔ 恰好卡在 127 以内
📌 书上那句话值得抄在草稿本上：「采用补码乘法规则计算出四个选项是费力不讨好的做法，且极易出错」。命题人考的是"你知不知道 8 位补码只能装到 127"，而不是 Booth 算法。看到"哪个运算会溢出"，一律走真值路线。
⚠️ 估算就够了，连乘法都可以省：四个数的绝对值是 2、14、112、8。要超过 127，两个绝对值的乘积必须够大——只有 14 × 112 这一对量级足够（≈1500），其余三对最大也才 112。先比量级，再决定要不要精算，这是选择题的正确姿势。
⚠️ D 项 112 是故意贴着上界放的（127 的 88%），专门抓"看着挺大就选它"的人。112 < 127，不溢出。凡是接近边界的，必须精算，不能靠感觉。
⚠️ 十六进制转真值的心算法：高位是 F 的，直接用 0x100 − 值 取负 —— FEH → 256−254=2 ⟹ -2；F2H → 256−242=14 ⟹ -14；F8H → -8。90H 稍麻烦：256−144=112 ⟹ -112。四个数十秒内全部转完。
🔗 与习题 10 是同一道题的两个版本（那题四则运算里挑乘法，本题四个乘法里挑一个）。两题的解法、陷阱、甚至书上的措辞都一样，一起记。
2014實戰补码运算的溢出判断
若 x = 103，y = −25，则下列表达式采用 8 位定点补码运算实现时，会发生溢出的是（　）。

8 位定点补码表示的数据范围为 −128~127，若运算结果超出这个范围，则会溢出。对选项 A，x + y = 103 − 25 = 78，符合范围。对选项 B，−x + y = −103 − 25 = −128，符合范围。对选项 D，−x − y = −103 + 25 = −78，符合范围。对选项 C，x − y = 103 + 25 = 128，超过 127。
103−(−25) = 128，超过 127。同样判断范围就行。
再深一层
选 C。Python 复算，四项一起算完再比范围：
x = 103，y = −25，8 位补码范围 [−128, 127]

  A. x + y  = 103 + (−25) = 78    ✔ 在范围内
  B. −x + y = −103 + (−25) = −128 ✔ 恰好卡在下界上！
  C. x − y  = 103 − (−25) = 128   ✘ 超过上界 127 ⟹ 溢出，选 C
  D. −x − y = −103 − (−25) = −78  ✔
📌 B 和 C 这一对是本题的全部设计，值得盯一分钟：
−128 可以表示（B 不溢出），+128 不能表示（C 溢出）。这正是补码范围不对称的直接后果——负半边多一格。命题人把两个 128 一正一负摆在一起，就是要你在这一格上做判断。
⚠️ 若换成原码或反码（范围 ±127 对称），B 也会溢出——B 之所以安全，完全是因为"补码比原码多表示一个 -2n−1"这条 2.1 的结论。2.1 和 2.2 在这里接上了头。
⚠️ 用"同号加、异号减"预筛，可以砍掉两个选项：
表达式加法器实际算符号可能溢出？
A. x + y(+103) + (−25)异号相加绝不可能
B. −x + y(−103) + (−25)同号相加有可能 → 需精算
C. x − y(+103) + (+25)同号相加有可能 → 需精算 ✔
D. −x − y(−103) + (+25)异号相加绝不可能
⟹ A、D 一秒排除，只需在 B、C 之间精算。"减法先化成加法再看同号异号"是这类题的固定第一步。
⚠️ 提醒：题干说的"8 位定点补码"包含符号位，范围是 [−27, 27−1]。若误当成"8 位数值位 + 1 位符号 = 9 位"，范围会算成 [−256, 255]，四项全不溢出，直接懵。「n 位」默认含符号位，这是 2.1-33（2022 真题）已经强调过的换算陷阱。
2018實戰补码求真值与补码减
假定有符号整数采用补码表示，若 int 型变量 x 和 y 的机器数分别是 FFFF FFDFH 和 0000 0041H，则 x、y 的值及 x−y 的机器数分别是（　）。

利用补码转换为原码的规则：负数的符号位不变，数值位取反加 1；正数补码等于原码。两个机器数对应的原码为 [x]原 = 8000 0021H，对应的数值是 −33，[y]原 = [y]补 = 0000 0041H = 65。排除选项 A、D。x − y 直接利用补码减法规则，[x]补 − [y]补 = [x]补 + [−y]补，−y 的补码是连同符号位取反加 1，最终减法变成加法，得出结果为 FFFF FF9EH。
再深一层
选 C。Python 复算：
x：FFFF FFDFH 最高位 1 ⟹ 负数
   快法：真值 = 机器数 − 2³²  ⟹ 4294967263 − 4294967296 = −33
   慢法：0xDF = 1101 1111，取反加 1 得 0010 0001 = 33 ⟹ −33 ✔

y：0000 0041H 最高位 0 ⟹ 正数，0x41 = 65 ✔

x − y = −33 − 65 = −98
  机器数 = 2³² − 98 = 0xFFFFFF9E   ✔ 选 C
  （范围检查：−98 远在 [−2³¹, 2³¹−1] 内 ⟹ 不溢出，排除 A）
📌 本题两个陷阱，分别对应两组错误选项：
陷阱正确错项
十六进制看错0xDF → 33（不是 65）
0x41 → 65（不是 41）		A、D 把 0x41 当成十进制 41 直接抄了下来
差 1−98 ⟹ FFFF FF9EHB 写 FFFF FF9DH，那是 −99（取反没加 1）
⚠️ 「0x41 = 41」是本题最狠的一刀：0x41 恰好长得像十进制 41，实际是 65（4×16+1）。命题人专门挑了这个数。凡是十六进制里出现纯数字（不带 A~F），最要警惕——它长得最像十进制，也最容易被直接抄走。
⚠️ 差 1 的错法（B）也很典型：补码求真值时"取反"和"加 1"必须成对，漏掉加 1 得到的是反码的解释。算完回代验算：98 + 0x9E 应等于 0x100（即 158 + 98 = 256）✔。
⚠️ 最快的路线全程用十进制：x = −33、y = 65 ⟹ x−y = −98 ⟹ 机器数 = 232 − 98。232 − 98 的低两位十六进制 = 0x100 − 0x62 = 0x9E，高位全 F ⟹ FFFF FF9E。负数机器数只需算低几位，高位全是 F——这个技巧在 32 位题里能省一半时间。
🔗 四个选项被拆成"x、y 的值"和"x−y 的机器数"两问，先答第一问就能砍掉一半选项（A、D 的 x=−65,y=41 一看就错）。多问合一的选择题，永远先答最容易的那一问。
2009實戰符号扩展后的补码加
一个 C 语言程序在一台 32 位机器上运行。程序中定义了三个变量 x, y, z，其中 x 和 z 为 int 型，y 为 short 型。当 x = 127，y = −9 时，执行赋值语句 z = x + y 后，x, y, z 的值分别是（　）。

C 语言中的整型数据为补码形式，int 型为 32 位，short 型为 16 位，因此 x、y 的机器数写为 0000 007FH、FFF7H。执行 z = x + y 时，x 为 int 型，y 为 short 型，因此需将 y 的类型强制转换为 int 型，在机器中通过符号位扩展实现，y 的符号位为 1，因此在 y 的前面添加 16 个 1，即可将 y 强制转换为 int 型，其十六进制形式为 FFFF FFF7H。然后执行加法，即 0000 007FH + FFFF FFF7H = 0000 0076H，其中最高位的进位 1 自然丢弃。
三个变量宽度不同：short 先符号扩展成 32 位，再相加：127 + (−9) = 118 = 76H。
再深一层
选 D。Python 复算：
x = 127（int，32 位）= 0000 007FH
y = −9（short，16 位）：|−9| = 0000 1001
  取反加 1 ⟹ 1111 1111 1111 0111 = FFF7H   ← 注意是 F7 不是 F9

相加前 y 要提升为 int ⟹【符号扩展】高 16 位补 1
  y_ext = FFFF FFF7H

  0000 007FH
+ FFFF FFF7H
------------
(1)0000 0076H   ← 进位自然丢弃
  z = 0000 0076H = 118 = 127 − 9 ✔  选 D
📌 四个选项其实只在两个地方分家，各个击破即可：
分歧点正确错误选项
y 的机器数FFF7H（−9 的补码）A、B 写成 FFF9H —— 那是把原码当补码了（9 = 0x9，直接加了负号）
z 的高 16 位0000（结果是正数 118）B、C 写成 FFFF —— 误以为"含负数的加法结果就带一堆 F"
⚠️ FFF9H 这个陷阱值得单独记：-9 的原码是 1000 0000 0000 1001，补码要"数值位取反加 1" ⟹ 1111 1111 1111 0111 = FFF7H。心算捷径：负数补码 = 216 − 9 = 65536 − 9 = 65527 = 0xFFF7。（0xFFF9 = 65529 = -7，差了 2。）
⚠️ z 的高位为什么全是 0？因为 127 + (−9) = 118 > 0，正数的高位当然是 0。算完先判结果正负，就能直接锁定高 16 位是 0000 还是 FFFF，两个选项立刻出局。
⚠️ 本题的核心动作是"类型不同必须先统一"：short 加到 int 上，先按 short 自己的符号性做扩展（有符号 ⟹ 符号扩展），再相加。这与 2025 真题（2.1-34）的"先扩展后重解释"是同一条规则的两次考查，只不过那题最后还要换符号性，本题不用。
2011實戰无符号与有符号共用加法器·溢出判断
假定在一个 8 位字长的计算机中运行如下 C 程序段。若编译器编译时将 8 个 8 位寄存器 R1~R8 分别分配给变量 x, y, m, n, z1, z2, k1 和 k2。请回答下列问题（提示：有符号整数用补码表示）。
1）执行上述程序段后，寄存器 R1、R5 和 R6 的内容分别是什么（用十六进制数表示）？
2）执行上述程序段后，变量 m 和 k1 的值分别是多少（用十进制数表示）？
3）上述程序段涉及无符号整数加减、有符号整数加减运算，这四种运算能否利用同一个加法器辅助电路实现？简述理由。
4）计算机内部如何判断有符号整数加减运算的结果是否发生溢出？上述程序段中，哪些有符号整数运算语句的执行结果会发生溢出？
unsigned int  x=134;
unsigned int  y=246;
int  m=x;
int  n=y;
unsigned int  z1=x-y;
unsigned int  z2=x+y;
int  k1=m-n;
int  k2=m+n;
1）因为 134 = 128 + 6 = 1000 0110B，所以 x 的机器数为 1000 0110B，因此 R1 的内容为 86H。
246 = 255 − 9 = 1111 0110B，所以 y 的机器数为 1111 0110B。
x − y = 1000 0110 + 0000 1010 = (0) 1001 0000，括号中为加法器的进位，因此 R5 的内容为 90H。
x + y = 1000 0110 + 1111 0110 = (1) 0111 1100，括号中为加法器的进位，因此 R6 的内容为 7CH。
2）m 的机器数与 x 的机器数相同，皆为 86H = 1000 0110B，解释为有符号整数 m（用补码表示）时，其值为 −111 1010B = −122。
m − n 的机器数与 x − y 的机器数相同，皆为 90H = 1001 0000B，解释为有符号整数 k1（用补码表示）时，其值为 −111 0000B = −112。
3）能。 n 位加法器实现的是模 2n 无符号整数加法运算。对于无符号整数 a 和 b，a + b 可以直接用加法器实现，而 a − b 可用 a 加 −b 的补数实现，即 a − b = a + [−b]补（mod 2n），所以 n 位无符号整数加减运算都可在 n 位加法器中实现。
因为有符号整数用补码表示，补码加减运算公式为 [a+b]补 = [a]补 + [b]补（mod 2n），[a−b]补 = [a]补 + [−b]补（mod 2n），所以 n 位有符号整数加减运算都可在 n 位加法器中实现。
4）有符号整数加减运算的溢出判断规则为：若加法器的两个输入端（加法）的符号相同，且不同于输出端（和）的符号，则结果溢出；或加法器完成加法操作时，若次高位（最高数位）的进位和最高位（符号位）的进位不同，则结果溢出。
最后一条语句（k2 = m + n）执行时会发生溢出。 因为 1000 0110 + 1111 0110 = (1) 0111 1100，根据上述溢出判断规则可知结果溢出。或者，因为两个有符号整数均为负数，它们相加之后，结果小于 8 位二进制所能表示的最小负数。
这题就是本话的汇总：同一个加法器能做四种运算；OF 判断溢出；无符号和补码只是解释不同。k1 = −112 的结果是通过减法得出的。多读几遍解析。
再深一层
Python 复算全部通过。这道 2011 真题是本章总纲「一套电路，两种语义」的完整演出——同一串位、同一个加法器，跑出四个变量。

⚠️ 第 3 问的答题要点是"两段式"，两种类型各说一遍，不能只答"能"：
① 无符号：n 位加法器实现的就是模 2n 加法；减法用 a + [-b]补 实现；

⚠️ 第 4 问要写"规则 + 结论"两部分，规则最好把两条判据都写上（书上答案就写了两条）：
· 符号法：两个加数同号、结果异号 ⟹ 溢出；
· 进位法：Cn ≠ Cn−1（即 Cn ⊕ Cn−1 = 1）⟹ 溢出。
只写一条通常也给分，但两条都写更稳，尤其"进位异或"是硬件真正用的那条。
⚠️ 结论部分要说清"只有 k2 = m + n 溢出"，并给出理由：
四条运算语句逐一判：
  z1 = x − y  ← unsigned，判 CF 不判 OF（134 ＜ 246，借位，CF=1）
  z2 = x + y  ← unsigned，判 CF（380 ＞ 255，进位，CF=1）
  k1 = m − n  ← int：−122 − (−10) = −112 在范围内 ⟹ 不溢出
  k2 = m + n  ← int：−122 + (−10) = −132 ＜ −128 ⟹ 【溢出】✔

  验证进位法：1000 0110 + 1111 0110
    次高位进位 C_6 = 0，符号位进位 C_7 = 1 ⟹ 不同 ⟹ OF = 1 ✔
  验证符号法：两加数符号位都是 1，结果 7CH 符号位是 0 ⟹ OF = 1 ✔
⚠️⚠️ 题目问的是"哪些有符号整数运算语句会溢出"——z1、z2 是 unsigned，它们的"溢出"由 CF 反映，不算在本问范围内。很多人把 z2 也答上去（因为它确实产生了进位），那是无符号溢出，不是本问要的。看清题干限定词是这一问的全部得分点。
2018實戰逻辑右移与算术右移
整数 x 的机器数为 1101 1000，分别对 x 进行逻辑右移 1 位和算术右移 1 位操作，得到的机器数各是（　）。

逻辑移位：左移和右移空位都补 0，且所有数字参与移动；补码算术移位：仍然是所有数字参与移动，右移空位补符号位，左移空位补 0。根据该规则，轻松选取选项 B。
再深一层
选 B。Python 复算——同一串位、同一个方向，只因为"补什么"不同，结果就分了家：
原值 1101 1000

逻辑右移 1 位：高位补 【0】
  1101 1000 → 0110 1100
  语义：当无符号数看，216 ÷ 2 = 108 ✔

算术右移 1 位：高位补【符号位 1】
  1101 1000 → 1110 1100
  语义：当补码看，−40 ÷ 2 = −20 ✔

⟹（逻辑 0110 1100，算术 1110 1100）  选 B
📌 这道 2018 真题是"右移分家"的标准考法，注意题目问的顺序是「先逻辑、后算术」。选项 C 就是把两个答案对调了——内容全对、顺序反了，同样是零分。做完务必回头对一次题干的问法顺序。
⚠️ A 和 D 是"两个都一样"的选项，对应"以为逻辑和算术右移没区别"。记牢那张四格表里唯一不同的那一格：
左移右移
逻辑补 0补 0
算术补 0补 符号位 ← 唯一分家处
⚠️ 为什么右移必须分家、左移却不用？右移是"往低位挪"，高位空出来的那一格必须填点什么，而填什么直接决定这个数是正是负——无符号数没有符号可保，填 0；补码要保住符号，填符号位。左移空出来的是低位，低位填 0 对两种语义都正确，所以不用分家。"空出来的是高位还是低位"就是全部原因。
⚠️ 题干说的是"整数 x"没说有无符号，这不影响作答——题目让你分别做两种移位，本来就是两种解释各来一次。这正是"一串位，两种语义"在移位上的最直白呈现。
🔗 与习题 05、07、17 同族。四题合起来，移位这个考点在 408 里就没有新花样了。
2013實戰移位与补码加的混合运算
某字长为 8 位的计算机中，已知整型变量 x、y 的机器数分别为 [x]补 = 1 1110100，[y]补 = 1 0110000。若整型变量 z = 2x + y/2，则 z 的机器数为（　）。

x × 2，将 x 算术左移一位为 1 1101000；y/2，将 y 算术右移一位为 1 1011000，均无溢出或丢失精度。补码相加为 1 1101000 + 1 1011000 = 1 1000000，亦无溢出。
x 左移 1、y 算术右移 1，补码相加。全部符号未变，没有溢出。
再深一层
选 A。Python 复算，仍是「逐步移位 → 每步判溢 → 最后相加」三段式：
[x]补 = 1 1110100 = −12   （116 − 128）
[y]补 = 1 0110000 = −80   （48 − 128）
8 位补码范围 [−128, 127]

① 2x ＝ 算术左移 1 位：1 1110100 → 1 1101000 = −24
   最高两位 11 相同 ⟹ 符号未变 ⟹ 不溢出 ✔

② y/2 ＝ 算术右移 1 位（高位补符号位 1）：
   1 0110000 → 1 1011000 = −40
   移出的是 0 ⟹ 无精度损失 ✔

③ 相加：1 1101000 + 1 1011000 = (1)1 1000000
   丢弃进位 ⟹ 1 1000000 = −64
   真值检验：2×(−12) + (−80)/2 = −24 − 40 = −64 ✔  选 A
📌 选项 D「溢出」是本题的核心陷阱——两个负数相加确实有可能溢出，命题人就等你在这儿慌。但 −24 + (−40) = −64，离下界 −128 还差得远。凡是"同号相加"，必须真判一次，不能因为"可能溢出"就选溢出，也不能因为"看着不大"就跳过。
⚠️ 三步各有各的判溢方式，一步都不能省：
步骤怎么判本题结论
算术左移（×2）最高两位是否相同11 相同 ⟹ 不溢出
算术右移（÷2）永不溢出，只看移出位判精度移出 0 ⟹ 无损
补码加同号相加、结果是否变号负+负=负 ⟹ 不溢出
⚠️ 本题的记号是"1 位符号 + 7 位数值"（写成 1 1110100），所以字长是 8 位、范围 [−128, 127]。看到题干把符号位用空格分开，别数错总位数。
⚠️ 提速：直接走真值。−12 和 −80 一眼可得，2×(−12) + (−80)/2 = −64，−64 的 8 位补码 = 256−64 = 192 = 1100 0000 ⟹ A。只要三步都不溢出，真值路线永远最快——但判溢仍要做，因为一旦中间某步溢出，真值路线给出的答案就是错的（对比习题 21）。
