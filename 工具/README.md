## 一、PV 交错穷举器

### 用法

```bash
cd 工具 && python3 m_classic.py && python3 m_exam.py
```

两个脚本各自打印一行一模型的结论：`状态数 · 死锁数 · 违反不变式数`，
末尾汇总「是否全部符合预期」。**期望值写在每次 `ck(...)` 调用里**
（`dl=True` 表示这个模型<u>应该</u>死锁，即它是个反例；`viol=True` 同理）。

## 原理（`pv.py`）

- **进程** = 步骤序列，`while(1)` 循环体按 `rounds` 展开成有限长
- **信号量** = 非负整数：`P` 在 `value > 0` 时才能推进，否则该进程本步不可推进（＝阻塞）
- **BFS 穷举**全部可达状态 `(信号量向量, 各进程 PC, 共享变量向量)`
- **死锁** = 存在未完成的进程，但全局无任何可推进的步骤
- **不变式** = 每到一个新状态逐条 assert（缓冲区越界 / 临界区内 &gt; 1 个进程 / 题目自定约束）

步骤构造糖：`P(s)` `V(s)` `op(名字, fn)` `CP(s, pred)` `CV(s, pred)`。
后两个是**条件 P/V**，用来表达 `if(count==0) P(rw);` 这类读者-写者的写法。

## ⚠️ 建模时最容易自己写错的四件事（都真的犯过）

1. **两把锁就必须两个临界区计数器**。用一个共享的 `incs` 去查互斥，会把
   「A 在货架 F₁、B 在货架 F₂」这种<u>合法并发</u>误报成互斥破坏。（综 04 中招）
2. **按比例消费的题，各进程的展开轮数必须配平**。一台车 = 1 车架 + 2 车轮 ⟹
   车轮工人的轮数要是装配轮数的 2 倍，否则「造轮子的先下班」这种<u>展开假象</u>会被误判成死锁。（综 09 中招）
3. **直线代码不要展开成循环**。2024 题干是「P₁ 执行一次 C₁、P₂ 执行一次 C₂」，
   展开成 2 轮等于替题目加了 `while(1)`，缓冲区自然会涨到 2 而报越界。（2024 中招）
4. **不变式别写得比题设更紧**。2025 题设是「未使用树坑 &lt; 3 时甲<u>才可挖</u>」，
   所以挖完可以<u>等于</u> 3，写 `unused < 3` 会误报。轮数少时还测不出来，轮数加到 3 才暴露。

> 归纳：**报出 ❌ 时，第一反应永远是「我的建模错了」而不是「书错了」**——
> 与项目 CLAUDE.md 的转录复核铁律一致。四次 ❌ 全部是我自己的错，书上零错误。

## 一个书上没说、这里算出来的结论

2025 植树题把 `signal(position)` 从「放树苗之后」拖到「填土之后」，
**既不死锁、也不违反「未使用树坑 &lt; 3」**——差别只在<u>并发度</u>：
统计「甲被挡在 `P(position)` 上、但此刻真实未使用树坑其实不足 3 个」的白等场面，
**书上写法 4 个 vs 拖后写法 20 个（各跑 5 轮）；跑 6 轮时 9 个 vs 45 个，稳定 5 倍。**
⟹ 写晚了不算错，但按「尽可能少 / 尽可能并发」的评分口径要丢分。

## ⚠️ 状态数会随参数变

各卡 🐍 栏里的状态数**依赖于进程数与轮数**（每处都写明了参数）。
与练习系统题目里的数字不同，是因为那边取了另一组参数，**不是结论打架**——
**死锁的有无、不变式是否被违反，才是与参数无关的结论。**

## 二、页面置换与地址复算（OS ch3 内存管理）

### 用法

```bash
cd 工具 && python3 mem_verify_ch3.py
```

打印 67 行 `✅/❌ 项目: 算得 X | 书答 Y`。**ch3 全部 67 项通过，书上 0 错**
（3 个显示为 ❌ 的只是 `112.0` 与 `112` 的字符串比较差异，数值相同）。

### `mem_repl.py` 的四个引擎

| 函数 | 签名 | 返回 |
|---|---|---|
| `opt(ref, m)` | 最佳置换 | `(缺页数, 置换数, trace)` |
| `fifo(ref, m)` | 先进先出 | `(缺页数, 置换数)` |
| `lru(ref, m)` | 最近最久未使用 | `(缺页数, 置换数, trace)` |
| `clock(ref, m)` | 简单 CLOCK | `(缺页数, 置换数, trace)`，trace 含**每步的访问位向量** |

⚠️ **「缺页数」与「置换数」必须分开返回**——**前 m 次缺页是装入空页框，不算置换**。
2019 真题（选 53）问的正是「页置换次数」而非缺页次数，答 5 不是 9；这个区分是本章头号读题陷阱。

### 用它验出来的、书上没给的两个数

1. **教材主例 `7,0,1,2,0,3,0,4,2,3,0,3,2,1,2,0,1,7,0,1` 在 m=3 下 LRU 共 12 次缺页 / 9 次置换**
   ——书上只说「前 5 次与 OPT 相同」。**12 落在 OPT 的 9 与 FIFO 的 15 之间，
   是「LRU 性能接近 OPT」这句话唯一的量化证据。**
2. **2019 选 53 的总缺页数是 9 次**——书上只给了置换 5 次。两个数并排写才讲得清那个陷阱。

### 扩展方向（建库时要补）

- **动态分区分配模拟器**（首次/最佳/最坏/邻近适应 + 回收四种合并情形 + 重排）——3.1 的 07/61/66/综01/综02 要用
