4.1　网络层的功能

网络层提供主机到主机的通信服务，任务是把分组从源主机经多个网络、多段链路送到目的主机。两大功能：分组转发与路由选择。

背景 · 考试不碰：OSI 与 TCP/IP 在网络层上的那场路线之争 书上开头讲了一段历史：OSI 曾主张网络层用面向连接的虚电路服务、由网络自身保证可靠；TCP/IP 则选了无连接的数据报服务、由用户主机保证可靠。 这段的历史部分（谁主张、争了多久、后来怎么样）从不出题，可以快速划过。 但结论那一句必须停下来：「TCP/IP 的网络层向上只提供简单灵活的、无连接的、尽最大努力交付的数据报服务」—— 这一句 2011 年直接考成了一道选择题（答案 A：无连接、不可靠的数据报服务）。
必记 · 尽最大努力交付＝允许发生四件坏事 网络层不保证可靠 ⟹ 分组可能出错、丢失、重复、失序（四个词要能一字不差地列出来）。 好处是：路由器可以做得简单、廉价，可靠性上移给传输层。 
网络层：能送就送，送不到就丢，丢了不告诉你
              ↓ 代价上移
传输层 TCP：序号 + 确认 + 重传 + 排序 + 去重 = 把四件坏事全兜住
⭐ 「四件坏事」这个清单在 ch5 讲 TCP 时会原样再用一次——TCP 的每一个机制都对应着兜住其中一件。
我的补讲 · 「简单廉价」这四个字是命题人最爱的潜台词 书上说 X：网络层不保证可靠，所以路由器做得简单、廉价。
潜台词是 Y：路由器不做的事，比它做的事更值得记——路由器不做重传、不做排序、不做去重、不做端到端确认、不看端口号 （唯一的例外是 NAT 路由器，它偏偏要看端口号，见 4.2.3）。
所以能考 Z：凡是选项里出现「路由器负责 XXX 的可靠传输 / 路由器为分组排序 / 路由器做流量控制」，一律错。 2011 真题的解析给了一条更漂亮的判据：直接翻 IP 首部——没有序号字段 ⟹ 不可能保证有序；没有建立连接的字段 ⟹ 不可能面向连接；只有首部检验和 ⟹ 连数据部分的差错都不管。 ⟹ 「用首部有没有那个字段来反推协议有没有那个能力」，是本章最好用的一把万能钥匙，后面 IPv6 那节还会再用一次。

4.1.1　异构网络互连

互联网由全球数以百万计的异构网络互连而成——拓扑、寻址方案、差错处理、路由机制都可能不同。TCP/IP 的做法是：网络层采用标准化协议 IP，而被连接的各网络本身可以是异构的。互连后的整体被视为一个虚拟互连网络（IP 网络），主机之间通信就像在单个网络上一样，看不见各网络的异构细节。

我的补讲 · 「两种服务都是由网络层提供的」——这半句常被读漏 书上说 X：分组交换网向端系统提供虚电路服务与数据报服务，这两种服务方式都是由网络层提供的。
潜台词是 Y：虚电路是网络层的面向连接，不要和传输层的 TCP 连接混为一谈—— 两者是不同层的两件事，可以任意组合： 今天的互联网就是「网络层无连接（数据报）＋ 传输层有连接（TCP）」这一种组合。
所以能考 Z：2011 真题问「TCP/IP 模型的网络层提供什么」，答案是无连接、不可靠的数据报服务—— 哪怕你正在用 TCP 下载文件，网络层依旧是无连接的。 凡选项里出现「因为使用了 TCP，所以网络层是面向连接的」，一律错。
必记 · 中继系统按层次分四种（本章第一张必背表）
层次中继系统它连出来的东西
物理层转发器（中继器）、集线器 Hub只是把一个网络扩大了，从网络层看仍是同一个网络，一般不称为网络互连
数据链路层网桥、交换机
网络层路由器网络互连通常就是指用路由器进行连接与路由选择

我的补讲 · 「虚拟互连网络」这个词是本章所有抽象的起点 书上说 X：互连后的网络可视为一个虚拟互连网络（IP 网络），主机通信就像在单个网络上一样。
潜台词是 Y：「虚拟」二字意味着这一层是被造出来的假象—— 物理上根本不存在一朵大云，存在的只是无数条链路和路由器；是 IP 协议这一层统一的编址与转发规则「装」出了一朵云。
所以能考 Z：凡是问「为什么能互连异构网络」，标准答案就是「网络层采用统一的 IP 协议」， 而不是「因为大家的物理层相同」（恰恰相反，物理层可以完全不同）。
⭐ 更值得记的是它的代价：既然是假象，IP 就必须自己重新定义一套地址（IP 地址），而不能用底层的 MAC 地址—— 这直接引出 4.2 的全部内容，也引出 4.2.5 的 ARP（在假象与真实之间做翻译）。 把 4.1.1 与 4.2 之间的这条因果链想清楚，整章的结构就立起来了。

冲突域/广播域 ⭐ 更值钱的是：这张表与 ch3 的「冲突域 / 广播域」表是同一张表的两半—— 层次越高，隔离能力越强：集线器什么都不隔离 → 交换机隔离冲突域 → 路由器连广播域也隔离。 2019 与 2022 两道综合真题的第一问都在考这句话，复习一次拿两章的分，这是全章投产比最高的一条串联。
分层 「设备在第 n 层就屏蔽 n 层及以下差异」这条规律， 和《操作系统》里「虚拟机/抽象层」的思路完全一致——每一层都在向上兜售一个「看起来更整齐的假象」： 链路层兜售「无差错的链路」，网络层兜售「一个统一的大网」，传输层兜售「一根可靠的管道」。

4.1.2　路由与转发

路由器的核心功能就是两件事：① 路由选择——运行路由协议，定期与相邻路由器交换信息，感知拓扑变化，动态生成并维护路由表，计算到目的网络的最优路径；② 分组转发——根据转发表把到达的分组从合适的输出端口送出去。

必记 · 路由表 vs 转发表（书上专门用一段话区分，就是要考）
路由表 routing table转发表 forwarding table
谁生成路由选择算法生成由路由表导出
侧重拓扑计算（哪条路最优）查找最优化（怎么查得最快）
属于哪个平面控制平面数据平面
⚠️ 书上紧接着说：讨论原理时往往不区分，笼统使用「路由表」一词——所以做题时看到「路由表」不要吹毛求疵， 只有当题目把两个词并列摆出来问区别时，才用上面这张表答。
我的补讲 · 路由表里到底存什么？这是 04 题十几年不变的考法 书上说 X：路由表的表项是「目的网络 + 下一跳」。
潜台词是 Y：这两个词各自都在排除一个错误答案—— 「目的网络」排除的是「目的主机」（用网络号可让一个表项覆盖成千上万台主机，表才不会爆）； 「下一跳」排除的是「完整路径」（路由器只管交给下一个人，不知道全程）。
所以能考 Z：04 题的四个选项正好是这两个维度的四种组合，只有「目的网络 + 下一跳的 IP 地址」是对的。 ⚠️ 还要防第四个坑：下一跳存的是 IP 地址而不是 MAC 地址—— MAC 地址是转发的那一瞬间才用 ARP 现查的（见 4.2.5），不会长期躺在路由表里。
⭐ 07 题把这条推到极致：源主机和中间路由器都不知道完整路径—— 主机只知道「本网内直接送，出网就丢给默认网关」，路由器只知道「下一跳是谁」。 这就是数据报网络与虚电路网络最本质的差别，下一节马上要用到。
知识串联 · 「只知下一跳，不知全程」是分布式系统的通用姿势 局部决策 路由器的这种工作方式，在 408 里到处都是： 《数据结构》里 Dijkstra 每一步只挑当前最近的点 · 《操作系统》里进程调度只看就绪队列当前状态 · 本章 4.4 的距离-向量算法更是纯粹的「只跟邻居打听」。

4.1.3　网络层提供的两种服务　考点追踪：虚电路的特点（2020）

分组交换网按通信子网向端系统提供的服务，分为面向连接的虚电路服务与无连接的数据报服务——注意：两种服务方式都是由网络层提供的。

1. 虚电路方式

通信前必须先在网络层建立一条逻辑连接——虚电路（VC）。连接一旦建立，端到端传输路径就被固定。整个通信过程分三阶段：虚电路建立 → 数据传输 → 虚电路释放。每次建立时系统分配一个未使用过的虚电路号 VCID，以区别于同一节点上的其他虚电路；每个中间节点维护一张虚电路表，记录 VCID 与下一跳，在连接建立过程中就确定好了。

我的补讲 · 虚电路的三阶段，和 ch1 的电路交换只差一个字 书上说 X：虚电路通信分三阶段——虚电路建立、数据传输、虚电路释放，「与电路交换类似」。
潜台词是 Y：「类似」二字要能说清像在哪、不像在哪：
电路交换（ch1）虚电路（本节）
三阶段建立连接 → 通话 → 释放连接虚电路建立 → 数据传输 → 虚电路释放　（一模一样）
建立的是什么物理通路逻辑连接
资源独占，全程预分配带宽共享，不预分配带宽
数据怎么走连续的比特流，不分组仍是分组交换，只是路径固定
所以能考 Z：「虚」字就是「逻辑而非物理、共享而非独占」这两句话的缩写—— 2020 真题的错项「需要为每条虚电路预分配带宽」，正是把第三行读成了电路交换。
必记 · 虚电路服务的五个特点（原文顺序，逐条都出过题） ① 建立与释放连接开销大——不适合交互式应用或少量数据交换，适合长时间、大量数据交换。
② 路由选择在连接建立阶段完成，建立完成后传输路径就固定了。
③ 提供可靠、有序的分组交付，并支持端到端的流量控制。
④ 对节点或链路的故障敏感——任一故障都会导致所有经过它的虚电路中断，必须重建。
⑤ 分组首部开销小——无须携带完整目的地址，只带虚电路号。
⭐ 「虚」字的含义要能一句话答出来：这条链路并非专用，而是可被多条虚电路共享。

2. 数据报方式

发送分组前无须建立连接。源主机把应用层报文分割成若干数据段，封装成携带完整源地址和目的地址的独立分组；中间节点对分组短暂缓存，独立选路后随即转发。网络层不提供服务质量保证，也不确保可靠传输，因此分组可能丢失、重复、失序或出错——这也正是路由器可以做得比较简单、造价低廉的原因。

必记 · 数据报服务的六个特点 ① 无须建立连接，随时可发、随时可收。
② 尽最大努力交付——每分组独立选路 ⟹ 路径可能不同 ⟹ 可能失序到达。
③ 分组携带完整的源地址与目的地址，以支持独立路由。
④ 存在排队时延与丢包风险，拥塞时时延显著增加，还可能被主动丢弃。
⑤ 故障适应能力强——节点/链路失效可更新转发表动态绕行。
⑥ 资源利用率高——带宽由多个会话共享；传输中分组仅占用当前链路的资源。

4.1.4　SDN 的基本概念　考点追踪：SDN 的南向接口（2022）

网络层的两大任务（转发、路由选择）在功能架构上被抽象为两个逻辑平面：数据平面（也称转发平面）负责执行分组转发，控制平面负责实现路由选择、生成并维护路由信息。SDN（软件定义网络）的核心就是：控制平面与数据平面解耦——控制平面集中化，数据平面分布式部署。

必记 · 传统网络 vs SDN，三句话说清 传统网络：每台路由器同时承担控制与转发——既运行路由协议、与邻居交换路由信息，又维护并查找转发表。
SDN：路由器仅保留数据平面功能，不再运行路由选择软件，彼此之间也不再交换路由信息； 控制功能由一个逻辑集中式的远程控制器（通常由多台服务器协同实现）统一承担。
控制器掌握全网拓扑与主机状态，为分组计算最优路径，再通过 OpenFlow 等协议把流表（SDN 中的转发表）下发到各路由器。 路由器的工作变得极简：接收分组 → 匹配流表 → 执行转发（即所谓「匹配 + 动作」）。

4.1.5　拥塞控制

拥塞：网络中出现过量分组、超出其处理能力时所引发的性能下降现象。核心是及时感知拥塞并采取措施，避免因缓冲区溢出而丢包。这是一个全局性过程，涉及所有主机、路由器以及一切影响网络传输能力的因素——仅靠增加资源无法根本解决拥塞。

知识串联 · SDN 的「集中 vs 分布」，是 408 里反复出现的一道选择题 集中 vs 分布 书上那句「网络构架又变为集中控制模式，而互联网本质上是分布式的」， 点破了 SDN 最根本的张力——把这组权衡摊开，三科都能对上号：
集中式分布式
好处全局视图 ⟹ 能算全局最优无单点故障、可无限扩展
坏处单点故障 + 性能瓶颈只能靠局部信息，可能次优、可能震荡
本章的例子SDN 控制器、OSPF 的全网拓扑传统路由器、RIP 的逐跳打听
组原的例子集中式总线仲裁分布式仲裁
OS 的例子单一就绪队列每核一个队列 + 负载均衡
⟹ 4.4 讲的「DV vs LS」其实就是这张表的又一次实例化：RIP 分布式打听，OSPF 让每个节点都拿到全图。

现象结论
负载增大，吞吐量随之增大正常，不是拥塞
负载增大，但吞吐量增长甚微可能已处于轻度拥塞

必记 · 开环控制 vs 闭环控制（认准「有没有反馈」四个字） 开环控制：设计时就把可能导致拥塞的因素考虑进去，用静态策略防止拥塞； 一旦投入运行，控制机制不再依赖实时反馈。典型手段：确定何时接收新流量、何时丢弃哪些分组、采用何种调度策略。 特点是不依赖当前网络状态。
闭环控制：监测网络运行状态 → 检测拥塞的位置与程度 → 反馈至控制节点 → 调整运行以缓解拥塞。 基于反馈机制，是一种动态方法。
⟹ 一字判据：有反馈回路的是闭环，没有的是开环；「静态/预防」＝开环，「动态/检测+反馈」＝闭环。

4.2.1　IPv4 分组

IPv4 即现在普遍使用的网际协议 IP。它定义了数据传送的基本单元——IP 分组及其确切的数据格式，也包括一套规则，指明分组如何处理、错误怎样控制；特别是它包含了非可靠投递的思想，以及与之关联的路由选择的思想。

1. IPv4 分组的格式　考点追踪：IP 首部格式及字段含义（2011、2012）

IP 分组 ＝ 首部 + 数据部分。首部的前一部分长度固定，共 20B，是所有 IP 分组必须具有的；固定部分之后是一些可选字段（提供错误检测及安全等机制），长度可变，从 1B 到 40B 不等。

我的补讲 · 首部里哪些字段「每跳都会变」？这个清单能一次答三道题 书上在讲检验和时顺带提了一句「某些字段可能发生变化」，那句话值得单拎出来做成清单：

潜台词是 Y：命题人知道你会算分片，所以他不在算法上为难你，而在单位上为难你—— 题目给你「片偏移＝185」，你要能立刻反应出「它前面已经有 185×8 ＝ 1480 字节」； 给你「首部长度字段＝5」，要反应出 5×4 ＝ 20B；给你「总长度＝1500」，那是连首部一起的 1500B。
所以能考 Z：三个典型错法各对应一个错误选项—— ① 把片偏移当字节数（少乘 8）· ② 把总长度当纯数据长度（多算 20B）· ③ 把首部长度当字节数（少乘 4）。 ⟹ 考场自查口诀：「偏移乘八、首长乘四、总长含头」。
我的补讲 · 「首部检验和只检验首部」这句话，背后是一个很值钱的推论 书上说 X：首部检验和只检验首部，不检验数据部分，可减少计算工作量；且每经过一个路由器都要重算。
潜台词是 Y：IP 层根本不保护你的数据——数据部分坏了，IP 一无所知、照样交付。 那谁来保护？上面的 TCP／UDP 检验和（它们的检验范围包含数据）与下面的链路层 CRC。 ⟹ 「IP 只自保首部、数据靠上下两层」是一条完整的跨层结论。
所以能考 Z：① 判断题「IP 提供差错检测，所以数据出错会被丢弃」——错； ② 问「为什么每跳都要重算检验和」——因为 TTL 每跳减 1，首部变了 （顺带：总长度、标志、片偏移、地址在分片或 NAT 时也可能变）。 ⚠️ 这条还解释了一个常被问的问题：为什么 IPv6 干脆取消了首部检验和—— 既然上下两层都在查，中间这一层每跳重算纯属浪费，见 4.3。

2. IP 数据报分片　考点追踪：IP 分片相关首部字段（2011）· IP 分片的原理及分析（2021）

一个链路层数据帧能承载的最大数据量称为最大传送单元 MTU。源到目的路径上各段链路的 MTU 可能不同——以太网的 MTU 通常为 1500B，而很多广域网的 MTU 不超过 576B。当 IP 数据报总长度超过某段链路的 MTU 时，就必须拆成多个较小的 IP 数据报，称为分片。

我的补讲 · 读十六进制 IP 首部的定位法（10 题、11 题的通用做法） 综合题会直接甩给你一长串十六进制，让你答「总长度多少 / 是不是分片 / 源 IP 是什么」。 硬数字节容易错位，用下面这套定位法更稳：
  1. 找起点：IP 首部通常以 45 开头（版本 4 ＋ 首部长度 5）。先在串里搜 45。
  2. 按 4B 一行数：第 1 行 = 版本/首部长度/区分服务/总长度；第 2 行 = 标识/标志+片偏移； 第 3 行 = TTL/协议/检验和；第 4 行 = 源 IP；第 5 行 = 目的 IP。
  3. 拆位：标志+片偏移那 2 字节要按位拆——高 3 位是标志（第 2 位 DF、第 3 位 MF），低 13 位是片偏移。
  4. 倒着验：用已知的目的 IP 往前数 4 字节找到源 IP，再往前 4 字节就是 TTL 那一行——正着数错了能立刻发现。
⚠️ 最阴的一种题（教材综 11）：以太网帧的类型字段是 0x8864（PPPoE），IP 首部并不在第 15 字节起—— 此时第 1 步的「搜 45」和第 4 步的「从目的 IP 倒着数」就是救命稻草。 🐍 我按这套方法复算过教材 10、11 两题的逐字段结果，与书答完全吻合。
⚠️ 另一处书上灰框专门提醒的坑：把 4 字节地址转成点分十进制时，极易因字节顺序或进制转换出错—— 写完务必回头把四段分别对一遍十六进制。
必记 · 分片的三条铁律 ① 分片可以发生在源主机或中间路由器上，但重组只在目的主机上进行。 （⟹ 中间路由器只拆不合，哪怕下一段链路的 MTU 又变大了也不合。）
② 重组靠首部里的三个字段：标识、标志、片偏移—— 标识说「谁和谁是一家的」，MF 说「后面还有没有」，片偏移说「我该放在第几个字节」。
③ 分片行为受标志字段控制：仅当 DF＝0 时才允许分片；DF＝1 则禁止分片 （此时若超过 MTU，路由器只能丢弃并回一个 ICMP 差错报文，见 4.2.7）。
我的补讲 · 分片题的五种问法，母公式只有一条 把历年出现过的问法排一遍，你会发现它们全是同一条公式的不同投影：
问法怎么答
分成几片？⌈数据总长 ÷ 每片最大数据⌉；注意「数据总长」＝ 总长度 − 20
第 k 片的片偏移是多少？(k−1) × 每片最大数据 ÷ 8

必记 · 分片三步法（本章第一条母公式，闭着眼睛也要会） 
第 1 步 每片最大数据 = ⌊(MTU − 20) / 8⌋ × 8      ← 必须是 8 的倍数
第 2 步 片数 = ⌈数据部分总长 / 每片最大数据⌉
第 3 步 片偏移 = 该片之前已装走的字节数 / 8

标志位：除最后一片外 MF 全为 1，最后一片 MF = 0
⚠️ 第 1 步那个「向下取整到 8 的倍数」是全章最容易漏的一步—— 因为片偏移以 8B 为单位，除最后一片外，每片的数据长度必须是 8 的整数倍，否则下一片的偏移就不是整数了。 ⟹ MTU＝1500 时 (1500−20)＝1480 恰好是 8 的倍数，所以这一步「看起来没做」；一旦 MTU 换成 576，(576−20)＝556，⌊556/8⌋×8 ＝ 552，这一步就露出獠牙了。

⚠️ 三处最常出错的地方： ① 556 忘了向下取到 8 的倍数（552）；② 第二片 500B 已经小于 552，不需要再分，很多人惯性地也去拆它； ③ 片偏移必须相对最原始的数据报累计，不能在第二级重新从 0 起算。
🐍 我按事件级逐片复算过这条分片链，四片长度与偏移全部落在 8 的倍数上，与书答吻合。 ⭐ 记住 552 这个数：只要题目里出现 MTU＝576（广域网的典型值），每片数据就是 552。
我的补讲 · 多级 MTU 必须「串行做两次」，这是分片题里最狠的一个变式 书上只给了一级 MTU 的例子，但真题会给你两段链路。做法是：把第一次分出来的每一片，当成一个全新的、独立的 IP 数据报，再对它做一次分片—— 因为「重组只在目的主机」，中间路由器拿到的就是一个个独立数据报，它不知道也不关心这些片原本是一家的。 唯一要留心的是片偏移必须相对于最原始的数据报，不能从 0 重新起算。 
例：2000B 数据报（数据 1980B）先过 MTU=576，再过 MTU=552

第一级 MTU=576：每片数据 ⌊(576−20)/8⌋×8 = 552
   ⟹ 552 + 552 + 552 + 324 = 1980   偏移 0 / 69 / 138 / 207

第二级 MTU=552：552B 数据 + 20B 首部 = 572 > 552，还要再分！
   每片数据 ⌊(552−20)/8⌋×8 = 528
   ⟹ 每个 552B 的片再拆成 528 + 24
🐍 这个例子我已按事件级逐片复算过：最终片长序列 552→(528,24) 各级偏移全部落在 8 的倍数上。 所以能考 Z：凡题干里出现两个不同的 MTU，一律警觉——这是在考「串行两次」而不是「取最小的 MTU 算一次」。 （取最小值算一次得到的片数往往和正确答案不同，正是命题人准备好的干扰项。）
知识串联 · MTU 与分片，是 ch3 与 ch5 之间的一道门 帧长限制 MTU 这个数字不是网络层自己定的，是 ch3 链路层给的： 以太网帧的数据字段最大 1500B（帧总长 1518B）⟹ 以太网 MTU ＝ 1500； 「网络层的分片，是被链路层的帧长上限逼出来的」——这是最典型的一处「下层约束上层」。
端到端原则 ch5 的 TCP 用 MSS 从源头避免分片： 与其让路由器辛苦地拆、让目的主机辛苦地拼，不如一开始就发小一点 ⟹ 这就是为什么实际网络里 IP 分片很罕见，也是 IPv6 干脆禁止中间路由器分片的底气（见 4.3）。
分块与映射 「大的东西装不进小容器，就切成块并编号，到目的地再拼回去」—— 这个动作在 408 里出现了至少四次：IP 分片（本节）· TCP 分段（ch5）· OS 的分页（一个进程切成页）· 组原的 Cache 行划分。 四者的「重组信息」也同构：片偏移 ≈ 序号 ≈ 页号 ≈ 块号。
陷阱 · MF 与 DF 的极性方向相反，一年至少考一次 DF＝0 才允许分片（Don't Fragment 为 0，即「不禁止」）；MF＝1 表示还有后续片（More Fragment）。 一个「0 是允许」，一个「1 是还有」，方向恰好拧着，这是纯粹的记忆坑，没有道理可讲，只能死记。
我的记法：把两个字母都读成英文原意——Don't Fragment ＝「别分片」，那当然是 1 才生效； More Fragment ＝「还有更多」，当然是 1 表示还有。 ⟹ 两个都是「1 时该字母的字面意思成立」，这样就统一了。
⚠️ 第二个附带的坑：最后一片的 MF＝0，但它的片偏移不为 0； 第一片的片偏移＝0，但它的 MF＝1。「MF＝0 且偏移＝0」只有一种情况：这个数据报根本没被分片。

4.2.2　IPv4 地址　考点追踪：0.0.0.0 的作用（2017）· 网络地址的确定（2022）· 默认网关与子网掩码的配置（2015、2016、2019、2022）· CIDR 地址块的分析（2011、2015、2016、2019、2023）· 路由聚合的原理（2009、2011、2013、2014、2018）

IP 地址是为连接到互联网上的每台主机（或路由器）的每个接口分配的一个全球唯一的 32 位标识符，由 ICANN 统一管理。通常把 32 位分成 4 段、每段 8 位，转成十进制并用小数点分隔——点分十进制记法。

1. 分类的 IP 地址

无论哪一类，IP 地址都由网络号与主机号两部分组成：IP 地址 ::= {<网络号>, <主机号>}。网络号标志接口所连接到的网络，在整个互联网范围内必须唯一；主机号标志该接口，在其所在网络内必须唯一。

知识串联 · 「按首位模式分类」＝ 一棵最朴素的前缀树 分块与映射 A/B/C/D/E 五类的划分方式，本身就是一次变长前缀编码： 
     0…            ⟹ A 类（占掉整个地址空间的 1/2）
     10…           ⟹ B 类（1/4）
     110…          ⟹ C 类（1/8）
     1110…         ⟹ D 类（1/16）
     1111…         ⟹ E 类（1/16）
⟹ 这正是《数据结构》里哈夫曼编码/前缀码的形状：没有任何一个码字是另一个的前缀，所以能唯一解码。 「看第一字节就能定类别」这件事之所以成立，全靠这个前缀码性质。
分块与映射 而 CIDR 干的事，就是把这棵固定的树换成可以任意深浅的树—— 前缀长度不再限于 1/2/3 位，而是 0～32 任选；于是「查表」也从「看头几位」升级成了 4.2.4 的最长前缀匹配。 分类编址 → CIDR 的这次演化，用一句话概括就是：从定长前缀码变成了变长前缀码。

必记 · IP 地址的四个重要特点（第 ② 条最常考） ① 分等级的地址结构——两大好处：管理机构只分配网络号，主机号由本单位自行分配； 路由器转发时只依据目的地址的网络号，从而显著减小路由表规模。
② IP 地址标识的是「网络接口」，而不是「主机」—— 一台主机连到多个网络时，每个接口都要配一个 IP，且各地址的网络号必须不同 ⟹ 路由器至少拥有两个或更多 IP 地址，每个接口对应一个不同网络号的地址。
③ 用集线器或交换机连起来的多个网段，逻辑上仍属同一个网络（同一个广播域） ⟹ 其中所有主机的 IP 必须有相同的网络号，主机号唯一。
④ IP 地址是逻辑地址，与底层物理硬件（MAC 地址）无关——正因如此，网络层才能屏蔽链路层的异构性。
⚠️ 近年随着无分类编址广泛应用，传统分类地址已逐渐退出历史舞台（但考试仍在考，因为它是理解 CIDR 的台阶）。

潜台词是 Y：做子网划分题时，路由器接口要占掉一个 IP 地址—— 这就是为什么书上的例题里「50 台主机的部门」要按 51 个地址算。

2. 划分子网

传统两级 IP 地址结构有三个缺点：地址空间利用率低（一个物理网络吃掉一整个网络号）、路由表规模过大、地址分配缺乏灵活性。从 1985 年起在 IP 地址中增加「子网号」字段，形成三级结构：

IP 地址 ::= { <网络号> , <子网号> , <主机号> }
                └── 对外可见 ──┘   └── 单位内部自己划 ──┘
我的补讲 · 「无法从 IP 地址本身判断是否划分了子网」——这句话有三个直接后果 书上说 X：划分子网只动主机号、不改网络号，因此从 IP 地址本身看不出有没有划子网。
潜台词是 Y：掩码是必须单独告诉你的信息，它不藏在地址里。
所以能考 Z（三个后果，都出过题）：
  1. 题目只给「192.168.1.100」而不给掩码 ⟹ 无法确定它的网络地址（这正是 CIDR 下「/前缀长度不可省略」的由来）。
  2. 配置主机时必须同时配掩码（三条使用原则的第 ① 条），否则主机不知道该直接交付还是间接交付。
  3. 路由器交换路由信息时必须同时通告网络地址和掩码——这一条到 4.4 会变成 RIP 与 OSPF 的一个具体差别：RIP 报文里不带掩码，所以它不支持 VLSM；OSPF 带，所以它支持。
⭐ 第 3 条是把 4.2 与 4.4 缝在一起的一针，很多人读完两节也没发现它们在说同一件事。
必记 · 划分子网的三条基本思想 ① 对外透明：单位对外仍表现为单一网络，外部路由器无须感知其内部子网结构。
② 内部灵活划分：从原主机号中借用若干位作为子网号，主机号位数相应减少。
③ 分层转发：外部路由器按网络号把数据报送到该单位的边界路由器；边界路由器再结合子网号交付到具体子网，最后送到目的主机。
⚠️ 书上灰框的两句话，句句是考点： ① 划分子网只对主机号部分再划分，不改变原网络号，因此无法从 IP 地址本身判断是否划分了子网（必须给掩码）。 ② 划分子网提升了灵活性，但也使可分配主机总数略有减少（每个子网都要各扣掉一个网络地址和一个广播地址）。

必记 · 子网掩码与三条使用原则　2022 子网掩码是一个与 IP 地址对应的 32 位二进制串，由一串 1 后跟一串 0 组成： 1 对应网络号 + 子网号，0 对应主机号。 把 IP 地址与子网掩码逐位「与」（AND），得到的就是子网地址（网络地址）。
默认子网掩码：A ＝ 255.0.0.0 · B ＝ 255.255.0.0 · C ＝ 255.255.255.0；现在的互联网标准规定每个网络都要配置子网掩码。
三条使用原则：① 配 IP 必须同时配掩码；② 同一子网内所有主机及路由器接口必须配置相同的掩码； ③ 路由表的三项核心信息 ＝ 目的网络地址 + 子网掩码 + 下一跳地址。
⭐ 路由器交换路由信息时，必须同时通告目的网络地址和子网掩码—— 这一句在 4.4 讲 RIP 与 OSPF 时会变成「RIP 的报文里带不带掩码」这个具体差别。

3. 无分类编址 CIDR　考点追踪：CIDR 地址块的分析（2011、2015、2016、2019、2023）

无分类域间路由选择 CIDR 是一种基于可变长子网掩码的地址分配与路由聚合机制，用来消除 A/B/C 类地址的限制、提升地址空间利用率。核心思想：不再区分网络类别，改用「网络前缀」标识网络部分，前缀长度（掩码中连续 1 的个数）可任意指定，不再局限于 8/16/24 位。

我的补讲 · CIDR 题的四个标准问法，答案都从同一组数推出来 拿到「a.b.c.d/n」，先算出三个数，四类问法就都能答： 
主机位 h = 32 − n        块大小 = 2^h        怪字节 = 256 − (块大小 mod 256)

  ① 网络地址（最小地址）＝ 把主机位全置 0
  ② 广播地址（最大地址）＝ 把主机位全置 1 ＝ 下一个网络地址 − 1
  ③ 地址总数 ＝ 2^h          ④ 可分配主机数 ＝ 2^h − 2
  ⑤ 可用地址范围 ＝ 【网络地址+1】～【广播地址−1】
问法答
「该地址块的最小/最大地址」① 与 ②
「能容纳多少台主机」④，别忘了减 2
「某地址是否属于该块」拿它与掩码 AND，看是否等于 ①
「两个地址在不在同一网」各自与同一个掩码 AND，比结果
⚠️ 第二问的变体最坑：「该网络还能再连多少台主机」——要在 2h−2 的基础上再减去已用的主机数和路由器接口数。 2018 真题就是这么问的：126 − 80 − 1 ＝ 45（🐍 已复算，与书答吻合）。
必记 · 斜线记法与地址块的四件事 CIDR 结构：IP 地址 ::= {<网络前缀>, <主机号>}，写作 「IP 地址/前缀长度」。 只要知道地址块中的任意一个地址及其前缀长度，就能定出：最小地址、最大地址、地址总数、可用主机数。 
以 128.14.32.5/20 为例（前 20 位是前缀）
IP 地址  = 10000000.00001110.0010|0000.00000101
掩码     = 11111111.11111111.1111|0000.00000000   = 255.255.240.0
网络前缀 = 10000000.00001110.0010|0000.00000000   = 128.14.32.0   ← 最小地址
最大地址 = 10000000.00001110.0010|1111.11111111   = 128.14.47.255 ← 广播地址
地址总数 = 2^(32-20) = 2^12 = 4096      可分配 = 4096 - 2 = 4094
🐍 已复算：网络 128.14.32.0、掩码 255.255.240.0、广播 128.14.47.255、共 4096 个地址 —— 与书吻合。
⚠️ 在 CIDR 下「/前缀长度」不可省略：只给 128.14.32.5 无法确定它的网络地址。 ⭐ CIDR 地址块的地址总数一定是 2 的整数次幂；前缀越短 ⟹ 主机位越多 ⟹ 块越大。
知识串联 · 掩码 AND 运算，是组原位操作在网络里的现场演出 位运算 「IP AND 掩码 ＝ 网络地址」这一步，在《组成原理》里叫按位与做位屏蔽： 掩码里的 1 保留原位、0 清零，正是 ch4 逻辑指令那一节讲的 AND 的标准用法； 而「求广播地址 ＝ 主机位全置 1」在组原里叫「与掩码的反码按位或」。
分块与映射 「前缀长度 n 决定块大小 232−n」，与 OS 的「页内偏移 k 位 ⟹ 页面大小 2k」是同一个公式： 都是「低位留几位，块就多大」。连「地址必须对齐到块边界」这条约束也一样—— 页框起始地址必是页面大小的整数倍，子网起始地址必是块大小的整数倍。
空间换时间 组原里判断「两个地址是否同一 Cache 行」＝ 高位相同；本章判断「两个 IP 是否同一网」＝ 网络号相同—— 做题时的动作完全一致：把地址右移 h 位后比较。
我的补讲 · 手算网络地址／广播地址的两条捷径（考场上别真去写 32 位二进制） 32 位手写一遍要 30 秒，一道题里往往要算五六次，必须提速。两条捷径：
① 只算「有零有一的那一段」。前缀是 8 的倍数时（/8、/16、/24）直接按段截断，一位二进制都不用写； 不是 8 的倍数时，只有跨界的那一个字节需要展开，其余字节照抄或清零。 例 /20 ⟹ 前两段照抄、第三段展开（前 4 位保留、后 4 位清零/置一）、第四段清零/置一。
② 用「块大小」直接跳。块大小 ＝ 256 − 掩码中那个非 0 非 255 的字节值， 网络地址就是「该字节向下取到块大小的整数倍」，广播地址 ＝ 下一个网络地址 − 1。

   下一个块从 32+16 = 48 起 ⟹ 广播 = 128.14.47.255

我的补讲 · 「借几位前缀就加几」——这条加法贯穿整个 4.2 书上说 X：/20 的地址块借 3 位划子网，每个子网变成 /23。
潜台词是 Y：前缀长度是可以做加法的，而且方向永远是「越切越长」： 
父块 /n  ──借 k 位子网号──▶  2^k 个子块，每个 /(n+k)

  /24 借 1 位 ⟹ 2 个 /25      /24 借 2 位 ⟹ 4 个 /26
  /24 借 3 位 ⟹ 8 个 /27      /20 借 3 位 ⟹ 8 个 /23
所以能考 Z（三种问法，全靠这一条加法）： ① 「要划出 m 个子网，前缀该多长」⟹ 取最小的 k 使 2k ≥ m，前缀 ＝ n+k； ② 「划成 /(n+k) 后每个子网能容纳几台」⟹ 232−n−k−2； ③ 「这样划会不会不够用」⟹ 拿 ② 的结果和需求比。
⚠️ 定长划分时这条加法就够了；变长划分时不能只用它——变长是「每块单独定前缀」，不是「统一借 k 位」。
陷阱 · 「CIDR 不使用子网」≠「用了 CIDR 就不能划子网」 书上专门用一段话强调这件事：「CIDR 不使用子网」是指它不在全局地址结构中预设固定的子网字段， 但这并不妨碍获得 CIDR 地址块的单位在其内部继续划分子网。
例：某单位拿到一个 /20 地址块后，可从主机号里再借 3 位划成 8 个子网，此时每个子网的前缀变成 /23。 （20 + 3 ＝ 23，借几位前缀就加几）
⭐ 这正是 CIDR 的最大好处，书上原话值得背下来： 「在网络外部，可通过较短前缀进行路由聚合，显著减少全局路由表项；在网络内部，可延长前缀以灵活划分子网。」 ——外部聚合、内部细分，八个字概括整个 CIDR。

4. 路由聚合　考点追踪：路由聚合的原理（2009、2011、2013、2014、2018）

一个大的 CIDR 地址块包含多个较小的地址块，于是在路由表里可以用一个较大的块代替多条较小的路由，这称为路由聚合——它使路由表中的一个项目能代表原来的多条路由，从而压缩路由表规模、提升网络性能。

知识串联 · 路由聚合、Cache 分块、多级页表：同一笔「压缩表规模」的账 分块与映射 三者要解决的问题一模一样：一张表太大了，装不下也查不动：
原始的表有多大怎么压代价
路由聚合（本节）每个网络一条 ⟹ 全球几十万条用一条 /16 代替两条 /17粒度变粗，可能连不该管的地址也吸进来
Cache 分块（组原）每字节一个标记 ⟹ 标记比数据还大一整块共用一个标记块内有用不上的字节（伪共享）
多级页表（OS）4GB/4KB ＝ 100 万个页表项分级，只为用到的部分建二级表多一次访存
⟹ 三者的收益都来自「地址空间的连续性」：相邻的东西往往去同一个地方，于是可以打包处理。 这也解释了为什么地址分配必须连续——不连续就聚合不了，ISP 分配地址块时最看重的就是这一点。

第 2 步 只把【有差异】的那一段展开成 8 位二进制
第 3 步 从高位起数出【连续相同】的位数 k
        聚合前缀长度 = (相同段的位数) + k

5. 最长前缀匹配　考点追踪：最长前缀匹配机制（2013、2015）

我的补讲 · 为什么「前缀最长 ＝ 最精确」？想通了就不用背 书上说 X：匹配多条时选前缀最长的，因为前缀越长地址块越小、信息越具体。
潜台词是 Y：把它翻译成日常语言就很自然了—— 路由表就像一份「投递指南」：「凡是寄往中国的，交给 A」和「凡是寄往北京海淀区的，交给 B」同时命中时， 当然听后者的，因为后者对这个具体地址知道得更多。 默认路由 0.0.0.0/0 就是那条「其余一律交给 A」，最笼统，所以优先级最低； 特定主机路由 /32 是「专门给张三的信交给 C」，最具体，所以优先级最高。
所以能考 Z：① 选择题问优先级顺序 ⟹ 前缀长度降序；② 综合题给一张表让你判走哪个接口 ⟹ 逐条 AND 后取最长。
⚠️ 最经典的一道设计（2013 综合真题）：表里同时有 /23 和 /25 两条能匹配同一个目的地址—— 此时必须走 /25 那条，哪怕 /23 那条看起来更「主干」。 🐍 我复算过这道题的裁决过程，与书答吻合。
必记 · 最长前缀匹配（也称最佳匹配） 使用 CIDR 时，路由表项由「网络前缀」和「下一跳地址」组成。查表时目的地址可能匹配多条路由， 此时应选择网络前缀最长的那一条——因为前缀越长，地址块越小，路由信息就越具体、越精确。
优先级从高到低：特定主机路由 /32 > 前缀长的普通路由 > … > 默认路由 0.0.0.0/0（前缀长度 0，最低）。
实现：为高效实现最长前缀匹配，路由器通常把 CIDR 路由表组织成层次式数据结构（如 Trie 树），自上而下快速定位。
我的补讲 · 一道「四合一模板题」的完整走法（教材综 06） 这类题把本节几乎所有考点串在一道里，走一遍就等于复习了半节：
问考什么怎么做
① 分组 A 走哪个接口最长前缀匹配逐条 AND，命中 /30 那条（前缀 30 位最长）
② 分组 B 走哪个接口同上命中 /28 那条
③ 若加一条特定主机路由/32 优先级最高一旦命中就走它，其余全被压过
④ 都不匹配时默认路由走 0.0.0.0/0；若连默认路由都没有 ⟹ 报「目的不可达」
🐍 我复算过这道题：分组 A 命中 30 位前缀那条、分组 B 命中 28 位那条，与书答一致。
⭐ 做这类题的两个提速习惯： ① 先把表按前缀长度从长到短重排一遍（在草稿纸上标个序号即可），然后从上往下扫，第一个命中就停； ② 只展开「有 0 有 1 的那一个字节」，其余字节直接比十进制。 这两招能把一道 5 分钟的题压到 2 分钟。
我的补讲 · 查路由表的标准动作，三行写完（综合题必考步骤） 拿到一张路由表和一个目的 IP，机械地做三件事，一步都别跳：
  1. 逐行做 目的IP AND 该行掩码，把结果与该行的「目的网络」比较，相等即为一条候选。
  2. 在所有候选中挑前缀最长的那一条（掩码里 1 最多的那行）。
  3. 按该行的下一跳转发；若该行下一跳写的是「直接交付」，就在本地网络用 ARP 找 MAC 直接送到。
⚠️ 三个高频失分点：① 忘了默认路由 0.0.0.0/0 也是候选（它匹配一切，只是前缀最短）； ② 把「候选最多的」当答案（要选前缀最长，不是匹配得最多）； ③ 忘了检查「特定主机路由」（掩码 255.255.255.255，前缀 32，一旦命中就是它，优先级最高）。
⭐ 考场提速技巧：先把路由表按前缀长度从长到短排一遍，然后从上往下扫，第一个匹配上的就是答案，扫到即停—— 这正是路由器内部真实的做法（Trie 树自上而下），也省掉了「比较谁更长」这一步。
知识串联 · 最长前缀匹配 ＝ 数据结构的 Trie 树 ＋ 组原的按块匹配 分块与映射 「前缀越长越具体」这个规则，在《数据结构》里就是 Trie（字典树）的最深匹配： 沿着树往下走，能走多深走多深，最后停下的那个节点就是答案——王道在正文里直接点了 Trie 树的名字，这是本章少见的明确跨科指路。
空间换时间 路由器把路由表组织成层次结构，与《组成原理》Cache 的组相联映射是同一笔账： 全相联查得准但慢，直接映射快但冲突多，组相联折中；路由表若逐条线性比对就是 O(n)，组织成 Trie 后是 O(前缀长度)。
分块与映射 再往回看：路由聚合 ＝ 把多个小块合成大块，与 OS 里大页（huge page）、组原里增大 Cache 行的动机一模一样—— 都是「用一条表项覆盖更多地址，来压住表规模的爆炸」。 而副作用也一模一样：粒度变粗，可能把用不着的东西也包进来。

我的补讲 · 变长划分的「二叉树模型」：判断一个方案合不合法 综合题有时不让你划，而是给你一组子网问「这样划行不行」。用二叉树模型三秒判定： 
把每个子网写成【去掉公共前缀后的二进制串 / 前缀增量】，摆成一棵二叉树：

  208.115.21.0/26   ⟹ 00
  208.115.21.64/27  ⟹ 010
  208.115.21.96/29  ⟹ 01100

  判据① 任意两串【不能互为前缀】（不能有祖先—后代关系）
        —— 若 "01" 和 "010" 同时出现就冲突了（地址重叠）
  判据② 若要求【正好用完】父块，全部串必须【刚好铺满】这棵树
⟹ 判据 ① 就是「不重叠」，判据 ② 就是「不留缝」。绝大多数题只考 ①。
这个模型还能一眼看出「最小子网有多大」：把最大的子网放树的最左边、用最短的串， 之后每个子网的串长依次 +1，最后两个子网必然等长—— 教材 64 题问「按这种分法最小的子网能容纳几台」，靠的就是这条规律（答案 254，🐍 已复算）。
⚠️ 书上也提到可以「借助二叉树模型辅助分配」，并要求各子网地址范围互不重叠，且起始地址对齐到其前缀对应的边界—— 这两句话就是判据 ① 与「对齐」的书面表述。
我的补讲 · 变长子网划分的标准解法：四步 + 一张验算表 这是本章综合题出现频率最高的一问，把动作固定下来，考场上不用思考：
  1. 算需求：每个部门 主机数 ＋ 1（路由器接口）；别忘了路由器之间的每条点对点链路各算一个「网络」，需求为 2。
  2. 定主机位 n：找最小的 n 使 2n−2 ≥ 需求；前缀 ＝ 32 − n。
  3. 从大到小、边界对齐地切块：每个块的起始地址必须是它自己块大小的整数倍（这叫「对齐」，是唯一容易错的一步）。
  4. 写出四件东西：CIDR 表示、子网掩码、地址范围（最小～最大）、可用主机范围（最小+1 ～ 最大−1）。

查什么怎么查

对不对齐每块起始地址 ÷ 块大小 是否整除？不整除就是切错了

4.2.3　网络地址转换 NAT　考点追踪：私有 IP 地址连网处理机制（2011）· NAT 的工作原理（2016、2019、2020、2023）

NAT 把专用网络中的私有 IP 地址转换为公网 IP 地址，从而实现与互联网的通信，并对外隐藏内部网络的结构。整个专用网通常只需一个全球 IP 地址即可与互联网连通；由于私有地址可在不同专用网中重复使用，NAT 有效缓解了 IP 地址短缺的问题，并在一定程度上降低了内网被攻击的风险。

我的补讲 · 三个私有块的「/12」为什么最容易记错 书上说 X：172.16.0.0/12 相当于 16 个连续的 B 类网络，范围到 172.31.255.255。
潜台词是 Y：另外两块的前缀恰好落在字节边界上（/8 和 /16），所以「看第几段」就够了； 唯独 /12 卡在第二段中间，必须真的去数位： 
172.16.0.0/12  前 12 位固定 = 10101100 . 0001____
                                └172┘   └ 16~31 ┘
  第二段的高 4 位锁死为 0001，低 4 位自由 ⟹ 0001 0000 ~ 0001 1111
                                        ＝ 16 ~ 31   ⟹ 共 16 个 B 类网
所以能考 Z：判断「172.20.5.1 是不是私有地址」——是（20 在 16~31 内）； 「172.35.5.1 呢」——不是（35 > 31）。 这两个判断题在教材 14、15、29、38、68 五道题里都出现过，🐍 我用 ipaddress 逐个复算，全部吻合。
⭐ 记忆钩子：三块的大小依次是 1 个 A 类 · 16 个 B 类 · 256 个 C 类， 三个数字 1 / 16 / 256 正好是 20 / 24 / 28，与三个前缀 /8 /12 /16 一一对应（8+0＝8、12+4＝16、16+8＝24，都补齐到各自类别的网络号长度）。

主机发送数据时，先把目的 IP 与本网络的子网掩码逐位与运算：结果等于本网络前缀就直接交付（无须路由器参与），否则发给默认网关由路由器转发（间接交付）。分组的转发始终基于「目的主机所在网络」——因为互联网中的网络数量远小于主机数量，这样能显著压缩转发表规模。

必记 · 路由器的分组转发算法四步（可直接当综合题卷面模板）
  1. 从收到的 IP 分组首部提取目的 IP 地址 D，从转发表第一项开始检查（表按前缀长度降序排列）。
  2. 若存在特定主机路由（目的网络为 D/32），按其下一跳转发；否则转步骤 3。
  3. 把当前路由项的子网掩码与 D 逐位「与」：结果等于该项的网络前缀 ⟹ 匹配成功，按「下一跳」处理 （直接交付给本网络上的目的主机，或经指定接口转发到下一跳路由器）；否则检查下一项，重复本步。
  4. 全表都不匹配时：若有默认路由 0.0.0.0/0 就发给它；否则报告 「目的不可达」 错误。
书上补了一句：特定主机路由与默认路由的匹配本质上已包含在第 3 步里，单列只是为了强调优先级与典型场景。
⚠️ 转发表不提供到目的网络的完整路径，仅指明「下一跳路由器」，分组逐跳转发直至抵达目的网络。
必记 · 书上灰框：下一跳的 IP 不会被填进分组首部（跨层串联的关键句） 从转发表得到下一跳路由器的 IP 地址后，并不会把该地址填入待转发分组的首部， 而是通过 ARP 解析出对应的 MAC 地址，填入链路层帧首部作为目的地址。 该帧发到下一跳路由器后，路由器剥离帧首部、取出 IP 分组，再交给网络层处理。 
同一个 IP 分组，走三跳的样子：

           [ IP 首部: S=H1, D=H4 ]  ← 三跳全程【一个字都不改】
链路 1 外面套：[ MAC: H1 → R1 ]
链路 2 外面套：[ MAC: R1 → R2 ]      ← 每跳【拆掉重套】
链路 3 外面套：[ MAC: R2 → H4 ]

我的补讲 · 第 ③ 条那句话，是本章分值最高的一句 书上说 X：每经过路由器转发都会解封装并重新封装，MAC 帧的源地址和目的地址都随之改变，这决定了 MAC 地址无法用于跨网络通信。
潜台词是 Y：这句话是一个因果链，不是一个孤立事实：

   ⟹ ARP（靠广播工作）跨不了网

⭐ 这条链把 ch3、4.2.5、4.7.1、4.8 四处内容串成了一根绳，是全章最值得画在草稿纸上的一张图。
必记 · 分层抽象的四条精髓（书上原话，命题人反复取材） ① 在 IP 层抽象的互联网上，只能看到 IP 数据报。
② 尽管 IP 数据报首部包含源 IP 地址，但路由器仅依据目的 IP 地址进行转发。
③ 在局域网的链路层只能看到 MAC 帧，IP 数据报被封装其中；每经过路由器转发都会被解封装并重新封装，MAC 帧的源地址和目的地址都随之改变 ⟹ 这决定了 MAC 地址无法用于跨网络通信。
④ 底层硬件地址体系各异，IP 层的抽象屏蔽了这些差异——只要在网络层讨论问题，就能用统一的 IP 地址研究主机与主机、主机与路由器的通信。
⚠️ 附带一条：路由器因互连多个网络，每个接口都配置有一个 IP 地址和一个对应的 MAC 地址。
必记 · ARP 的三步与两个「广播/单播」 每台主机和路由器都维护一个 ARP 高速缓存（ARP 表），存放本局域网内各主机与路由器接口的 IP↔MAC 映射； 动态更新，每个表项设有生存时间（例如 20 分钟），超时自动删除。
主机 A 要给本局域网的主机 B 发数据：先查自己的 ARP 缓存，有就直接用；没有则：
  1. A 构造 ARP 请求分组，封装在目的 MAC ＝ FF-FF-FF-FF-FF-FF 的帧中广播发送，本局域网内所有主机都收到。 内容：「我的 IP 是 …，MAC 是 …，我想知道 IP 为 X 的主机的 MAC」。
  2. B 发现被问的正是自己，向 A 单播发送 ARP 响应分组，含自己的 MAC。 ⚠️ 同时 B 把 A 的 IP↔MAC 写进自己的 ARP 缓存（一次问答，两边都受益）。
  3. A 收到响应后把 B 的映射写入缓存，然后用该 MAC 封装数据帧发出。
⚠️ 「ARP 请求广播、ARP 响应单播」是本节最高频的一个考点。
ARP 归为网络层协议，因为它处理的是 IP 地址——书上给了通用判据：看某协议使用或依赖哪一层的地址/端口信息，就归哪一层。
我的补讲 · ARP 缓存里到底存了些什么？看一眼就懂四种情况 把四种情况反过来看——各方的 ARP 缓存里会多出哪些条目，比死记表格直观得多：
谁的缓存里面会有什么
普通主机 H1同网内它通信过的主机（H2）＋ 默认网关 R1 的 L1 接口——只有这两类，绝不会有跨网主机的 MAC
路由器 R1它每个接口所在网络里的主机与邻居路由器接口（L1 侧有 H1、H2；L2 侧有 H3、R2 的 L3）

⚠️ 书上灰框：ARP 仅作用于同一局域网（广播域），无法跨网络工作。
知识串联 · 「地址在哪一层变、在哪一层不变」，一张表管住三层 一段 vs 端到端 把三层的地址放在一起看，本章那句核心结论就有了参照系：

自始至终： IP 分组的  源 = H1 ，目的 = H4   【一个字都没变】

4.2.6　动态主机配置协议 DHCP　考点追踪：DHCP 发现报文的作用（2022）· DHCP 报文的地址分析（2015、2022、2025）

DHCP 用于给主机动态分配 IP 地址，提供即插即用的联网机制。DHCP 是应用层协议，基于 UDP——这一句与「ARP 是网络层协议」形成对照，是最常考的层次判断。

必记 · 连网主机需要配置的四项 ① IP 地址　② 子网掩码　③ 默认路由器的 IP 地址（默认网关）　④ 域名服务器（DNS）的 IP 地址 ⟹ 这四项正是 DHCP 提供报文里要发下来的内容（再加一个租用期）。 选择题会问「DHCP 不能提供下列哪一项」，四项之外的都是错的。
我的补讲 · DHCP 四步为什么非广播不可？逐步问一遍就懂了 很多人死记「四步全广播」，其实每一步的理由都不一样，理解后根本不用背：
步为什么必须广播

4.2.7　网际控制报文协议 ICMP　考点追踪：ICMP 使用的下层协议（2012）· ICMP 差错报告报文的类型与语义（2022）

为了更有效地转发 IP 数据报、提高交付成功率，网络层使用 ICMP，使主机或路由器能向源点报告网络中的差错或异常。ICMP 报文被封装在 IP 数据报中传送，但它不是高层协议，而是网络层协议——这是最经典的一道判断题。ICMP 报文分两类：差错报告报文与询问报文。

我的补讲 · ICMP 那道十几年不变的判断题，考的是「封装」与「层次」的区别 书上说 X：ICMP 报文封装在 IP 数据报中传送，但它是网络层协议、不是高层协议。
潜台词是 Y：「被谁封装」和「属于哪一层」是两回事—— 判断层次看的是它处理什么信息、为谁服务，而不是它坐在谁的肚子里。 ICMP 报告的是 IP 转发过程中的差错、服务对象是 IP 本身，所以它是网络层的一部分。
所以能考 Z：2012 真题问「ICMP 使用的下层协议是什么」，答案是 IP； 但若问「ICMP 属于哪一层」，答案是网络层，不是传输层也不是应用层。 同一把刀的另外两面：ARP 也封装在链路层帧里，但它是网络层协议；DHCP 封装在 UDP 里，它就真的是应用层协议。
⭐ 王道给的通用判据值得抄下来：「看某协议使用或依赖哪一层的地址或端口信息，就归到哪一层」—— ARP 用 IP 地址 ⟹ 网络层；DHCP 用 UDP 端口 ⟹ 应用层；ICMP 报告 IP 转发的差错 ⟹ 网络层。

4.3.1　IPv6 的特点　考点追踪：IPv6 的特点（2023）

必记 · IPv6 的十个特点（加粗的四条几乎每次考到 IPv6 都出现） ① 更大的地址空间——这是最重要的：地址从 32 位增大到 128 位（16B）， 地址空间是 IPv4 的 2128/232 ＝ 296 倍。
② 扩展的地址层次结构（空间大了，就能划出更多层次）。
③ 灵活的首部格式：定义了许多可选的扩展首部；能提高路由器处理效率，因为路由器通常不处理扩展首部。
④ 改进的选项：IPv6 首部长度固定，选项放在有效载荷中；而 IPv4 的选项放在首部的可变部分。
⑤ 允许协议继续扩充（IPv4 的功能是固定不变的）。
⑥ 支持即插即用（自动配置地址） ⟹ 通常不需要使用 DHCP。
⑦ 支持资源的预分配（实时音视频等需要带宽与时延保证的应用）。
⑧ 只有源主机才能分片，只支持端到端分片，不允许中间路由器分片（与 IPv4 正好相反）。
⑨ 首部长度固定为 40B（IPv4 的首部长度可变，必须是 4B 的整数倍）。
⑩ 增大了安全性：身份鉴别与保密功能由扩展首部提供。
⚠️ IPv6 与 IPv4 不兼容，但与其他互联网协议（TCP、UDP、ICMP、IGMP、DNS 等）总体兼容， 仅在少数地方做了必要修改，主要是为了处理更长的地址。
陷阱 · 2023 真题的两个坑，都埋在数字上 坑一：「IPv6 地址空间是 IPv4 的 96 倍」——错，是 296 倍。 96 与 296 差了大约 2.4×1028 倍，但在选项里只差一个上标，扫读极易漏。 🐍 复算：2128/232 ＝ 296 ≈ 7.9×1028。
坑二：「IPv4 首部和 IPv6 基本首部的长度均可变」——错。 IPv4 首部可变（20–60B），IPv6 基本首部固定 40B。 「一个可变一个固定」，选项把它们捏成「均可变」，就是在赌你只记得 IPv4 那半句。
⭐ 2023 那道题的正确项是 Ⅲ（过渡用双协议栈和隧道）与 Ⅳ（Hop Limit ≡ TTL），答案 D。 把这两个「对的」也记住，比只记两个坑更保险。

4.3.2　IPv6 数据报的基本首部　考点追踪：IPv6 首部格式及字段含义（2023）

IPv6 数据报 ＝ 基本首部 + 有效载荷（净负荷）。有效载荷由零个或多个扩展首部（扩展首部不属于基本首部）及其后的数据部分构成。

必记 · IPv6 相对 IPv4 的八项调整（「IPv4 vs IPv6」对照题的全部素材）
取消 / 改动了什么为什么
取消「首部长度」基本首部固定 40B，不需要了
取消「服务类型」功能由通信量类（优先级）和流标号实现
取消「总长度」改用「有效载荷长度」
取消「标识、标志、片偏移」相关功能移到分片扩展首部
「TTL」更名为「跳数限制」作用不变，只是名称更贴合实际含义
取消「协议」改用「下一个首部」
取消「首部检验和」传输层已提供差错检测，取消可加快路由器处理速度
取消「选项」功能由灵活的扩展首部实现
⚠️ 结果很反直觉，书上专门点了一句：字段数从 IPv4 的 12 个减少到 8 个，首部长度却从 20B 增加到 40B—— 因为两个地址字段各自从 4B 涨到了 16B，光这两项就 32B。
必记 · 八个字段里只有三个要细看 版本（4 位，值为 6）· 通信量类（8 位，区分类别/优先级）· 源/目的地址（各 128 位）——这四个一看就懂。剩下三个要细看：
字段位数要点
流标号20「流」＝ 互联网上从特定源点到特定终点（单播或多播）的一系列数据报（如实时音视频）；路径上的路由器可据此提供特定的服务质量保证；同一个流的所有数据报有相同的流标号
有效载荷长度16基本首部之后的字节数，包括所有扩展首部和上层数据；最大 65535B
下一个首部8类似 IPv4 的「协议」字段：没有扩展首部就标识上层协议；有扩展首部就标识紧随其后的第一个扩展首部的类型
跳数限制8作用等同于 IPv4 的 TTL；源主机设初值（最大 255），每经一个路由器减 1，减到 0 丢弃
我的补讲 · 「取消首部检验和」这一条，是全书最好的一道分层权衡题 书上说 X：IPv6 取消首部检验和，因为传输层已提供差错检测，这样能加快路由器处理速度。
潜台词是 Y：这是一次明确的取舍，理由要能自己复述出来—— ① 下面：链路层的 CRC 已经把出错的帧丢掉了；② 上面：TCP/UDP 检验和覆盖了包括数据在内的全部内容； ③ 中间这一层每经过一跳就要重算一次（因为 TTL 变了），代价高、收益低。 三条合起来 ⟹ 中间这一层的检验属于重复劳动，砍掉换速度。
所以能考 Z：选择题「IPv6 使用首部检验和保证传输正确性」——错（05 题的 D 项）； 简答「为什么 IPv6 取消首部检验和」——答上面三条。
⭐ 把这个思路推广，就得到 408 里一条通用的判断法则： 同一个功能若在多层重复实现，就要问「哪一层做一次就够」—— 差错检测（链路层 + 传输层就够）· 流量控制（链路层与传输层各做各的，作用范围不同，都需要）· 可靠传输（端到端原则说：必须在端做，中间做了也白做）。 这三条对照着记，ch3／本章／ch5 的一大批判断题就都通了。

4.3.3　IPv6 地址

必记 · 三种目的地址类型（IPv6 没有广播地址） ① 单播：传统的点对点通信，发给唯一指定的接收方。
② 多播：一点对多点，发给所有加入该多播组的接口。
③ 任播（Anycast）——IPv6 新增的地址类型：「一址多用、就近交付」； 任播地址标识一组接口，但网络只把数据报交付给其中路由距离最近的那一个。
⚠️ IPv6 没有广播地址——广播的功能由「多播」承担了。这是一道现成的判断题。
必记 · 冒号十六进制记法与两条缩写规则（本节唯一要动手的题型） 把 128 位分成 8 组，每组 16 位（4 个十六进制数），组间用冒号分隔， 例如 4BF5:AA12:0216:FEBC:BA5F:039A:BE9A:2170。
规则内容易错点
① 省略前导零每组中前面连续的十六进制零可省略，但至少保留一个数字开头的 0 可省，结尾的 0 不可省（89A 还原成 089A，不是 89A0）
② 双冒号一个或多个连续的全零组可用 :: 替代:: 在一个地址中只能用一次，否则无法确定各段省了几组
例：4BF5:0000:0000:0000:BA5F:039A:000A:2176 ⟹ 先省前导零 4BF5:0:0:0:BA5F:39A:A:2176 ⟹ 再用双冒号 4BF5::BA5F:39A:A:2176。
我的补讲 · 缩写还原三步法（03、04 两题的标准动作） 还原（缩写 → 完整）的机械步骤，一步都别跳：
  1. 先补组数：数出现有的组数 k，:: 代表 8 − k 个全零组，把它们摊开写成 0000。
  2. 再补每组的位数：每组不足 4 位的，在前面补 0 补到 4 位。
  3. 核对：最终必须正好 8 组、每组 4 位。
04 题：8::D0:123:CDEF:89A  还原

4.4.1　路由算法

路由选择协议的核心是路由算法，即生成路由表各表项的计算方法。目的很明确：给定一组路由器及其互连链路，找到从源路由器到目的路由器的最佳路径。「最佳」通常指费用最低，而费用可根据跳数、带宽、延迟等因素定义。

必记 · 静态路由 vs 动态路由
静态路由算法动态路由算法
怎么来的网络管理员手工配置每一条路由根据网络状态变化（链路故障、新增）动态调整自身路由表
优点实现简单、开销小能较好地适应网络状态变化
缺点不能及时适应网络状态变化实现复杂、开销大
适用简单的小型网络较复杂的大型网络
常用的动态路由算法分两类：距离-向量算法（DV）与链路状态算法（LS）——这两个词是本节全部内容的骨架。
必记 · 距离-向量算法（Bellman-Ford）的核心公式与三项信息 DV 算法基于 Bellman-Ford 算法，不要求每个节点掌握完整的网络拓扑，只需知道两件事： ① 与相邻节点之间的距离；② 各邻居到目的节点的最短距离。 
d_x(y) = min { c(x,v) + d_v(y) }        v 取遍 x 的所有邻居

含义：我到 y 有多远 = 【我到某个邻居的代价 + 那个邻居到 y 的代价】里最小的一个
⭐ 所有最短路径算法都依赖同一个基本性质： 「两点之间的最短路径，必然包含路径上任意子路径的最短路径」——这就是《数据结构》里 Dijkstra／Floyd 的最优子结构性质。
每个节点 x 维护三项信息：① 到每个直连邻居 v 的链路费用 c(x,v)；② 自己的距离向量（x 到网络中其他各节点的费用）； ③ 从每个邻居收到的距离向量副本。
运行方式：每个节点定期向所有邻居发送自己的距离向量；收到邻居的新向量后更新副本、按公式重算自己的向量； 若自己的向量变了就立即再向所有邻居发送（没变就不发）。
我的补讲 · DV 迭代题的做题模板：一张 3×3 的表，逐轮填 书上说 X：图 4.16 用三节点网络 x —2— y —1— z、x —7— z 演示了两轮迭代。
潜台词是 Y：这类题永远只考三件事—— ① 初始向量是什么（只填直连邻居的链路费用，非邻居填 ∞）；② 第 k 轮后哪一格变了；③ 什么时候收敛。
所以能考 Z：把三轮摊成一张表，答案一目了然（🐍 已用 Bellman-Ford 迭代复算，与书上三张表逐格吻合）：

⚠️ 「更新报文的大小与网络节点数成正比」——这一句是 DV 的致命缺陷，也是它与 LS 对比时的第一条。 最常见的 DV 协议就是 RIP，它用跳数作为费用度量。
必记 · 链路状态算法（LS）的两项任务与三个优点 链路状态 ＝ 「本路由器与哪些邻居相连，以及对应链路的代价」。 LS 要求每个节点都掌握完整的全网拓扑图，为此每个节点做两件事： ① 主动探测所有相邻节点的状态；② 定期把自身的链路状态通过洪泛法传播给全网所有节点。 于是每个节点都能用 Dijkstra 算法独立算出到其他所有节点的最短路径；链路状态一变就立即重算。
三个主要优点：
① 所有节点基于相同的链路状态数据库独立计算，不依赖邻居的路由决策 ⟹ 避免了 DV 的无穷计数问题；
② 拓扑完整 ⟹ 本地即可算出全局最优，收敛快且无环；
③ 链路状态报文只含本节点的直连链路信息，报文大小与网络总规模无关 ⟹ 大网中扩展性更好。
典型的 LS 算法就是 OSPF。
我的补讲 · DV 与 LS 的对比，本质是「信息传得远还是传得广」 书上说 X：DV 只与直接邻居交换、发的是完整距离向量（与节点数成正比）；LS 洪泛给全网、但每条报文只含局部信息。
潜台词是 Y：两者各自省了一样、各自费了一样，是一笔对称的账：
距离-向量 DV链路状态 LS
信息传给谁只给直接邻居（传得近）洪泛给全网（传得远）
每条报文多大整个距离向量，∝ 节点数（内容多）只有自己的直连链路，与规模无关（内容少）
每个节点知道什么只知道「到各处多远」，不知道全图知道完整拓扑
算法Bellman-Ford，分布式迭代Dijkstra，本地独立计算
典型病无穷计数、慢收敛洪泛本身的开销
所以能考 Z：凡问「为什么大网用 OSPF 不用 RIP」，答两条——① 报文大小与规模无关；② 不会无穷计数、收敛快。 ⟹ 一句话记法：DV 是「跟邻居打听，消息层层转」，LS 是「大家把自己那块拼图发给所有人，各自拼出全图」。
知识串联 · 这一节其实是《数据结构》第 6 章的应用题 最短路径 ⭐ DV ＝ Bellman-Ford，LS ＝ Dijkstra，两个算法你在《数据结构》ch6 图里都手算过： 连「最优子结构」这句话都是同一句。408 复盘中心的图算法八合一模拟器里就有 Dijkstra 的逐步演示， 卡在 OSPF 算路的题上时，回去跑两遍比看文字快。 ⚠️ 2014 那道 OSPF 综合真题，王道自己在题干上标了「数据结构与计网组合题」——它真的就是一道 Dijkstra 手算题。
局部决策 DV 的「只跟邻居打听就能收敛到全局最优」，是分布式算法里最漂亮的结论之一， 与 OS 里「每个进程只看自己的局部状态、靠调度器涌现全局秩序」同构。

4.4.2　分层次的路由选择协议

互联网采用自适应的分布式路由选择协议。由于规模庞大、且许多联网单位不愿对外暴露内部网络细节，因此采用分层次的路由选择协议：把整个互联网划分为许多较小的自治系统 AS，每个 AS 对外表现为单一且一致的路由选择策略，而AS 的管理者有权自主决定内部使用什么协议（RIP 或 OSPF）。

4.4.3　路由信息协议 RIP　考点追踪：RIP 中跳数为 16 的含义（2010）· RIP 使用的下层协议（2017）· RIP 路由收敛机制（2024）· RIP 的优缺点（2024）

RIP 是一种分布式的、基于距离向量的路由选择协议，是 IGP 中最早得到广泛应用的协议之一。

必记 · RIP 的五条规定与三问三答 五条规定：
① 用跳数衡量距离：到直连网络的距离规定为 1，每经过一个路由器跳数加 1。
② 「好」路由 ＝ 所经路由器数量最少（跳数最少）。
③ 一条路径最多只能包含 15 个路由器，跳数 16 ＝ 目的网络不可达 ⟹ RIP 仅适用于小型自治系统。
④ 路由表项三字段：<目的网络 N，距离 d，下一跳路由器地址 X>，读作「我通过 X 到 N 的距离是 d」。
⑤ 每个路由器维护一个距离向量（到所有目的网络的距离记录）。
三问三答（必背）：
问答
和谁交换仅和直接相邻的路由器
交换什么本路由器当前的完整路由表（全部路由信息）
何时交换按固定时间间隔（默认 30 秒）；拓扑变化时也及时通告
⭐ RIP 是应用层协议，使用 UDP 传送（端口 520）； ⚠️ RIP 选的路径不一定时延最短，但一定跳数最少——因为它只看跳数。
必记 · RIP 的距离向量更新算法（2024 综合真题的第一问） 收到相邻路由器 X 发来的 RIP 报文后： 
第 1 步 把报文里【所有】项目改一遍：
        下一跳 ← X          距离 ← 距离 + 1

第 2 步 逐项与自己的路由表比较：
  IF   表中【没有】目的网络 N
       ⟹ 加入路由表（发现新网络）
  ELIF 表中有 N，且原下一跳【就是 X】

第 3 步 若连续 180 秒未收到某邻居的更新报文
        ⟹ 把该邻居对应的路由项距离置为 16（不可达）
⚠️ 第二条是全节最容易错的一条：下一跳相同就无条件更新，哪怕距离变大。 理由：下一跳没变，说明这条信息就是从这条路上来的最新消息，必须以最新为准；只有下一跳不同时才去比距离。

必记 · RIP 的优缺点　2024 优点：① 实现简单、开销小、收敛过程较快；② 「好消息传播得快」——发现更短的路由后，更新信息会迅速传遍所有路由器。
缺点：① 限制了网络规模（最大有效距离 15）；② 交换的是完整路由表，网络越大通信开销越大； ③ 「坏消息传播得慢」——故障时要反复多次交换才能收敛，即慢收敛 / 无穷计数问题。
我的补讲 · 「坏消息传播得慢」是怎么发生的：一步一步推给你看 书上说 X（图 4.18b）：R1 与 R2 相邻、链路开销 1；初始 R1 有 <N, 4, 直接>，R2 有 <N, 5, R1>。 某刻 R1 发现 N 不可达（距离置 16），但要等下一次周期性更新（30s）才通知 R2； 而 R2 可能抢先把自己的 <N, 5, R1> 发给了 R1。
潜台词是 Y：R1 收到后误以为「原来还能绕道 R2 到 N」—— 而 R2 那条路本来就是经 R1 的，这是一个「自己教坏自己」的回环。 于是距离开始一格一格往上爬： 
R1 <N,16,直接>  R2 <N,5,R1>
  ⟹ R1 收到 R2 的报文，改成 <N, 6, R2>      ← 第一次「教坏」
  ⟹ R2 收到 R1 的报文，改成 <N, 7, R1>      ← 此后【下一跳相同 ⟹ 无条件替换】
  ⟹ <N,8,R2> → <N,9,R1> → … → <N,16,R2> → <N,16,R1>
  共 12 轮周期性交换 × 30s ≈ 6 分钟，双方才都判定「N 不可达」
🐍 我严格按三条更新规则做过事件级模拟：确实是 12 轮 ≈ 6 分钟，与书上叙述吻合。 ⚠️ 模拟时的关键点：R1 第一次把下一跳改成 R2 之后，后续每次收到 R2 的报文都属于「下一跳相同 ⟹ 无条件替换」，所以距离才会一路爬升； 若误用「只在更短时才更新」，会卡在 6/7 反复震荡而永远到不了 16。
所以能考 Z：① 问「几轮后收敛」——按上面的爬升数；② 问「跳数上限 15 有什么用」——给无穷计数封顶，否则会无限循环； ③ 问「好消息为什么快」——更短的路由一旦出现，任何一条规则都会立刻接受它，一轮传一跳，没有回环。

4.4.4　开放最短路径优先协议 OSPF　考点追踪：OSPF 与 RIP 特性对比（2024）· OSPF 使用的下层协议（2017）

OSPF 是分布式链路状态算法的典型代表，采用 Dijkstra 最短路径算法。名字里虽有「最短路径优先」，但这不意味着其他协议不用最短路径原则——AS 内使用的所有路由协议都在找最短路径，只是「最短」的度量标准不同（RIP 量跳数，OSPF 量代价）。

必记 · OSPF vs RIP 的四个主要区别（2024 直接考这张表）
#OSPFRIP
1用洪泛法向本 AS 中所有路由器发送信息：向所有输出端口发给邻居，邻居再转给它的所有邻居（但不再回传给刚刚发来信息的那个路由器），最终全区域每台都收到一个副本仅向直接相邻的几个路由器发送
2发的是本路由器与其相邻路由器之间的链路状态（局部拓扑）发的是自己所知的全部路由信息（完整路由表）
3仅在链路状态发生变化时才触发洪泛更新，收敛快，不会出现「坏消息传得慢」不论拓扑是否变化都定期交换
4OSPF 是网络层协议，不用 UDP 也不用 TCP，直接封装在 IP 数据报中（IP 首部协议字段 ＝ 89）RIP 是应用层协议，使用 UDP（端口 520）
📌 书上灰框给了「层次判断题」的判据，原话很值钱： 「用 UDP 传送」是指把协议数据作为 UDP 报文的数据部分；「直接使用 IP 数据报传送」是指把协议数据直接作为 IP 数据报的数据部分。 RIP 报文属于前者。
必记 · OSPF 另外五项优势 ① 支持对每条路由设置不同的代价（可针对不同业务类型算差异化路径）；
② 多条等代价路径时可实现负载分担（负载均衡）；
③ 分组具备鉴别功能，确保只在可信路由器之间交换链路状态；
④ 支持可变长子网掩码和无分类编址（⚠️ 这一条正是 RIP 的短板，选择题常拿来对比）；
⑤ 每条链路状态通告都带一个 32 位序号，序号越大表示状态越新。
所有路由器最终构建出一致的链路状态数据库 LSDB，再各自用 Dijkstra 算出路由表。
📌 书上灰框，极易被忽略但很能出题：Dijkstra 虽能算出完整的最优路径，但路由表中不存整条路径，只存「下一跳」——只有到了下一跳，才能确定再下一跳怎么走。
必记 · OSPF 的区域划分（图 4.19） 为支持大规模网络，OSPF 把一个 AS 划分为若干区域（Area）。 好处：把洪泛交换链路状态的范围限制在各区域内，而不是整个 AS，从而显著减少通信开销。
  • 每个区域由一个或多个区域边界路由器负责为进出该区域的分组提供路由（图 4.19 中的 R3、R4、R7）。
  • AS 内必须有一个区域配置成主干区域（0.0.0.0），它包含 AS 内的所有区域边界路由器，用于连通其他区域。
  • 跨区域传送的路径固定为：源区域 → 本地区域边界路由器 → 主干区域 → 目的区域边界路由器 → 目的地。
  • 主干区域中还要指定一个自治系统边界路由器（图中的 R6），专门负责与本 AS 之外的其他 AS 交换路由信息。
必记 · OSPF 的五种分组（记住谁问谁答）
#分组作用
1问候（Hello）发现邻居、维持邻接关系，确认链路双向连通
2数据库描述（DD）发送自己 LSDB 中所有链路状态项目的摘要
3链路状态请求（LSR）向邻居请求某些链路状态项目的详细信息
4链路状态更新（LSU）用洪泛法发送链路状态通告 LSA，是 OSPF 最核心的部分
5链路状态确认（LSAck）对链路更新分组的确认
⭐ 五种分组正好串成一条完整的剧情：Hello 找到人 → DD 对目录 → LSR 要细节 → LSU 给细节 → LSAck 回执。 这样记比逐条背名字快得多。

我的补讲 · OSPF 的可靠性是自己做的，这一点和 BGP 形成绝妙对照 书上说 X：OSPF 用 LSU 洪泛、用 LSAck 确认；BGP 走 TCP。
潜台词是 Y：两者都需要可靠传输，但解决方式完全相反—— OSPF 直接坐在 IP 上（IP 不可靠），所以它自己实现了一套确认机制（LSAck）； BGP 干脆借用传输层的 TCP，一行确认代码都不用写。
所以能考 Z：①「OSPF 如何保证可靠传输」——靠 LSAck 确认分组，不靠传输层； ② 由此可推出「OSPF 的层次」——它自己做确认这件事本身就说明它下面没有可靠传输层，所以它是网络层协议。

协议坐在谁上面可靠性从哪来

4.4.5　边界网关协议 BGP　考点追踪：BGP 的功能（2013）· BGP 使用的下层协议（2013、2017）· BGP 会话类型（2024）· BGP 报文类型及作用（2024）· BGP 路由选择的策略（2024）

BGP 是不同自治系统的路由器之间交换路由信息的协议，是一种外部网关协议。RIP 和 OSPF 都只能在一个 AS 内工作；若没有 BGP，全世界数以万计的 AS 就都是一个个彼此孤立的「孤岛」。

必记 · BGP 为什么不追求「最佳路由」（两条理由 + 一句结论） ① 互联网规模太大——AS 之间的路由选择非常困难，每个主干网路由器表中的项目数都极其庞大，要寻找最佳路由是很不现实的。
② AS 之间的路由选择必须考虑政治、安全或经济等因素（这是 IGP 完全不需要考虑的）。
⟹ 结论：BGP 只能力求寻找一条能够到达目的网络且比较好的路由（不能兜圈子），而并非寻找一条最佳路由。
BGP 采用路径向量路由选择协议（与 DV、LS 都不同，是第三种）；BGP 是应用层协议，基于 TCP 实现（端口 179）。
必记 · BGP 路由的两个关键属性 
BGP 路由 = <前缀, BGP 属性> = <前缀, AS-PATH, NEXT-HOP>
AS-PATH（自治系统路径）：记录该路由所经过的自治系统序列；每个 AS 有全局唯一的 ASN， 路由每经过一个 AS 就把它的 ASN 加进 AS-PATH。 ⟹ BGP 路由指出经过哪些 AS，但不指明具体经过哪些路由器。
NEXT-HOP（下一跳）：接收该路由的路由器去往目的网络时应使用的下一跳地址； 通常是通告此路由的邻居 AS 的边界路由器上、与本 AS 直连的那个接口 IP，即 AS-PATH 中第一个 AS 的入口点。
必记 · eBGP 与 iBGP　2024 一个 AS 中有两类路由器：边界路由器与内部路由器。 边界路由器之间、以及 AS 内部的 BGP 路由器之间，都通过端口 179 的半永久 TCP 连接（交换完信息仍保持连接）交换 BGP 路由信息。 每对通过 TCP 交换 BGP 报文的路由器称为 BGP 对等方，该 TCP 连接称为 BGP 会话。
会话类型在哪
外部 BGP（eBGP）会话跨越两个 AS
内部 BGP（iBGP）会话位于同一个 AS 内部
⟹ BGP 不仅用于 AS 之间，还运行在 AS 内部，以确保外部路由信息在整个 AS 中正确传播。 ⚠️ 为避免路由信息丢失，BGP 要求 AS 内的任意两台 BGP 路由器之间都建立 iBGP 会话，但不要求物理直连（全连接的是「会话」不是「链路」）。
我的补讲 · 图 4.20 那个例子在讲什么：BGP 路由要「翻译」两次才能进路由表 书上说 X：AS2 的内部路由器 R4 收到一条 BGP 路由「X，AS-PATH＝AS1，NEXT-HOP＝R1」，最后在路由表里写下 <X, R3>。
潜台词是 Y：从「NEXT-HOP＝R1」到「下一跳写 R3」中间隔着两次翻译，这正是本例的全部要点：
  1. 第一次翻译（NEXT-HOP 解析）：R1 在 AS1 里，AS2 的内部路由器根本无法直接把分组发给它； R4 知道 R1 是自己的 eBGP 对等方 R2 的邻居 ⟹ 要去 R1，必须先到 R2，路径变成「R2→R1→X」。
  2. 第二次翻译（IGP 查找）：R4 再用内部网关协议（RIP/OSPF）算出「我到 R2 的最优路径」， 假设查得下一跳是 R3 ⟹ 于是在路由表里写 <X, R3>。
最终转发路径：R4 → R3 → R2 → R1 → X（同理 R3 的表里会写 <X, R2>）。
所以能考 Z：每个路由器收到新的 BGP 路由通告后，都要执行「NEXT-HOP 解析 + IGP 查找」两步，才能把路由正确写入本地路由表。 2013 与 2024 两道综合真题都在考这个「BGP 给方向、IGP 给下一跳」的分工。
⭐ 一句话记法：BGP 负责「出了本 AS 该往哪个 AS 走」，IGP 负责「在本 AS 内部怎么走到出口」——两者接力，缺一不可。

4.5.1　多播的概念

多播 ＝ 把同一份数据同时发送给多台主机，即一对多的通信；在互联网上进行的多播称为 IP 多播。与单播相比，多播在一对多通信中能显著节省网络资源：视频服务器向 90 台主机发同一段视频时，单播要发 90 份，多播只发 1 份——该分组在传输路径上仅当遇到分岔节点时才被复制并转发。多播的实现依赖路由器支持，支持多播路由协议的路由器称为多播路由器。

4.5.2　IP 多播地址

必记 · 多播地址的四条与「三个注意」 ① 多播数据报的源地址是源主机的 IP 地址，目的地址是 IP 多播地址。
② IP 多播地址就是 IPv4 的 D 类地址：前四位 1110，范围 224.0.0.0 ～ 239.255.255.255， 可支持 228 个多播组，主机可随时加入或离开。
③ 多播数据报的协议字段值由它携带的上层协议决定：携带 UDP 数据 ⟹ 17；携带 IGMP 报文 ⟹ 2。
三个注意（必背）： ❶ 多播数据报也是「尽最大努力交付」，不提供可靠交付； ❷ 多播地址只能用于目的地址，不能用于源地址； ❸ 对多播数据报不产生 ICMP 差错报文（← 与 4.2.7「四种不发 ICMP」的第 ③ 条是同一条规则的两处出现）。
⭐ 多播机制仅适用于 UDP——TCP 是面向连接的，建立的是一对一的端到端连接，无法支持一对多。

4.5.4　IGMP 与多播路由协议

必记 · IGMP 的三条限定 + 两个阶段 三条限定：
① IGMP 让连接到本地局域网的多播路由器知道：本局域网上是否有主机加入或退出了某个多播组。
② IGMP 仅作用于本地子网——它既不知道某个多播组的总成员数量，也不了解成员分布在哪些网络。
③ IGMP 报文封装在 IP 数据报（协议字段值 2）中传送；IGMP 是 IP 协议的一个组成部分，不被视为单独的协议。
两个阶段：❶ 加入时——主机向该多播组的多播 IP 地址发一个 IGMP 报文声明入组，本地多播路由器再用多播路由选择协议把组成员关系通告出去； ❷ 维持时——组成员关系是动态的，本地多播路由器周期性查询本网主机；只要有一台响应就认为该组仍活跃； 连续多次查询都无人响应，才判定本网已无该组成员并停止通告。
⭐ 多播路由选择的实质：构造一棵以源主机为根的多播转发树， 树上每个分组在每条链路上仅传送一次，参与转发的路由器不会收到重复的多播数据报。 ⚠️ 不同的多播组对应不同的转发树；同一个多播组若源主机不同，转发树也不同。

4.6　移动 IP　2 页 · 3 题 · 0 真题 · 只有「三角路由」一个硬点

必记 · 移动 IP 的定义与三种功能实体 移动 IP ＝ 允许移动主机在切换网络接入点时，仍保持其永久 IP 地址不变的网络协议机制。 目标：不论移动主机当前在哪个网络，发往它的分组都能被自动、透明地正确投递；该机制对上层应用（如 TCP 连接）完全透明。
实体定义
移动节点拥有永久 IP 地址、可在不同网络间移动的主机
归属代理（本地代理）连接在归属网络（初始接入的网络）上的路由器，负责截获并转发发往移动节点的数据
外地代理连接在被访网络（当前接入的网络）上的路由器，协助移动节点接收数据；它还负责为移动站分配转交地址并把该地址通知归属代理
陷阱 · 「换个地方上网 + DHCP 拿新 IP」不是移动 IP 书上专门用一段话否定了这个直觉：把笔记本关机、从家里搬到办公室、通过 DHCP 自动获取新 IP 重新接入—— 尽管物理位置和接入网络都变了，但由于它的 IP 地址已经改变，不属于移动 IP 的范畴。
那移动 IP 到底为了什么？为了让 TCP 连接不断。 若要在移动过程中维持 TCP 传输，就必须保证该连接在漫游期间持续有效；而 TCP 连接由「源 IP + 源端口 + 目的 IP + 目的端口」四元组标识，IP 一变连接立刻作废 ⟹ 「让 IP 地址保持不变」正是移动 IP 存在的全部理由。 ⟹ 判断题记法：IP 变了 ＝ 不是移动 IP；IP 没变而位置变了 ＝ 才是移动 IP。
必记 · 移动 IP 通信流程五步（第 ③④ 两步就是「三角路由」） 每个移动站有一个永久地址（归属地址），它最初所在的网络叫归属网络；永久地址与归属网络的关联固定不变。 离开归属网络后接入的网络叫被访网络（外地网络），在那里获得一个转交地址。
  1. 本地通信：移动站在归属网络时，按传统 TCP/IP 方式直接通信。
  2. 漫游与注册：漫游到被访网络后，先向外地代理登记、获得转交地址；外地代理再把该地址注册到归属代理。
  3. 接收数据（B → A，绕远路）：归属代理截获所有发往 A 的分组，构建一条通往转交地址的 IP 隧道， 把原始分组封装在新 IP 包里送到外地代理；外地代理解封装还原出原始分组，直接交给 A。
  4. 发送数据（A → B，走近路）：A 发分组时仍用永久地址作源地址， 直接通过被访网络的外地代理转发，无须经过归属代理。
  5. 移动与返回：再次漫游时，新外地代理把新的转交地址注册给归属代理；回到归属网络后向归属代理注销转交地址，恢复本地直连。
⚠️ 两点注意：① 转交地址仅用于移动站、归属代理、外地代理之间的通信，应用程序不会使用它； ② 外地代理向被访网络中的移动站发送分组时，直接通过 MAC 地址做链路层交付。
为支持移动 IP，网络层要增加四个新功能：① 移动站→外地代理的登记协议；② 外地代理→归属代理的注册协议； ③ 归属代理的隧道封装协议；④ 外地代理的隧道拆封协议。

4.7.1　冲突域和广播域　考点追踪：网络设备对冲突域和广播域的影响（2010、2020）

必记 · 两个「域」的定义与所属层次 冲突域 ＝ 连接到同一物理介质上的所有节点的集合，这些节点之间存在介质争用现象。 在 OSI 参考模型中，冲突域属于第 1 层（物理层）的概念。
广播域 ＝ 能够接收同一广播帧的所有节点的集合。 在 OSI 参考模型中，广播域属于第 2 层（数据链路层）的概念。
⭐ 通常所说的局域网 LAN 在逻辑上等同于一个广播域；路由器用于连接不同的 LAN，即分隔不同的广播域。
必记 · ⭐⭐ 三层设备对照表（与 ch3 3.8 同源，两章合并记一次）

潜台词是 Y：考试从来不问「能不能」，只问「有几个」——所以要把定性的表变成可操作的数法：

4.7.2　路由器的组成和功能　考点追踪：路由器的功能（2010）

路由器是一种具有多个输入/输出端口的专用计算机，任务是互连不同的（异构）网络并转发分组。在多个逻辑网络（多个广播域）互连时必须使用路由器；它可连接不同的 LAN、不同的 VLAN、不同的 WAN，或实现 LAN 与 WAN 的互连。

必记 · 路由器的两大部分（图 4.27） 从结构上看，路由器由路由选择（控制平面）与分组转发（数据平面）两部分构成。
部分核心部件做什么
路由选择（控制平面）路由选择处理机按所选路由协议（RIP／OSPF）构建路由表，并周期性与相邻路由器交换路由信息以更新维护
分组转发（数据平面）交换结构 + 一组输入端口 + 一组输出端口交换结构是路由器内部连接输入与输出端口的高速通路，按转发表把分组快速送到合适的输出端口
⭐ 书上一句很形象的话：「交换结构本身就是一个在路由器中的网络」。
⚠️ 路由器的每个端口都包含物理层、数据链路层和网络层三层的处理模块： 输入端口在物理层接收比特流，在数据链路层提取帧、剥离帧头帧尾，再把分组交给网络层模块； 若是普通数据分组 ⟹ 查转发表、经交换结构送到输出端口；若是路由协议分组（RIP／OSPF 报文）⟹ 交给路由选择处理机。
路由器端口设有缓冲区暂存分组并可做差错检测；到达速率超过处理能力时缓冲区溢出，后续分组被丢弃 （⟵ 这正是 4.1.5 说的拥塞在硬件上的样子）。

4.8　本章小结及疑难点

必记 · 疑难点 1：「尽最大努力交付」到底包含哪五条 ① 不保证 IP 数据报无差错地到达目的主机；
② 不保证在规定时间内交付；
③ 不保证按发送顺序交付；
④ 不保证不重复交付；
⑤ 不主动丢弃数据报——仅在两种情况下丢弃：首部检验和出错，或因缓存满而无法处理。
⭐ 第 ⑤ 条最容易被忽略，它其实是一句「辩护」：IP 虽然不保证什么，但它不会无缘无故地扔你的分组。 由此推出一条常考结论：凡交付给目的主机的 IP 数据报，其首部都是没有差错的（有错早被丢了） ⟹ IP 层可确保首部完整性，但不保证数据部分正确、也不保证传输可靠；若应用需要可靠传输，交给 TCP。
必记 · 疑难点 2：ARP 请求的对象不在本网时，谁来应答？（2015 真题的理论依据）
情形谁应答返回谁的 MAC
A 与 B 在同一局域网B 本人（单播 ARP 响应）B 自己的硬件地址
B 不在 A 所在局域网A 的默认网关（路由器）代理应答——A 的 ARP 请求根本到不了 B路由器在该局域网这一侧接口的硬件地址
⟹ 这就是 4.2.5 那张「ARP 四种典型情况」表的第 2 行，换了个问法。 考场判据依旧是那一句：ARP 永远只解析「我这一跳要交给谁」的 MAC。
必记 · 疑难点 3：为什么路由表里放的是 IP 而不是 MAC？（整个网络部分最核心的一句设计哲学） 问题：数据报首部只有源和目的 IP，没写下一跳，怎么转发？
答：路由器查路由表得到下一跳的 IP 地址，但不修改 IP 数据报的内容； 这个 IP 交给数据链路层，由 ARP 解析成 MAC 填进帧首部，从而在物理网络中送到下一跳。此过程对每个数据报重复执行。
追问：那能不能直接在路由表里存 MAC，省掉 ARP？ 答案是不能。 理由两条：① IP 地址的抽象性屏蔽了底层网络差异，是互联网可扩展性的基础； ② 硬件地址是平面化的，若路由表直接用它，表项数量将剧增、管理复杂，反而得不偿失。
⭐ 把这两条与 4.2.2「IP 地址是分等级的、MAC 地址是平面的」对上，整章的设计哲学就闭环了。
必记 · 疑难点 4：「路由器实现了三层」是什么意思 指路由器具备处理这三层协议的能力： 物理层——能接收和发送比特流； 数据链路层——能识别帧结构、解析 MAC 地址，完成帧的解封装与重新封装； 网络层——能读取 IP 首部，按目的 IP 查路由表做转发决策。
⟹ 转发数据时，路由器先解封装输入帧取出 IP 数据报，再按下一跳接口重新封装成适合输出链路的新帧。 正是这种能力使它能互连底层技术不同的网络（如以太网与 PPP 链路）。
