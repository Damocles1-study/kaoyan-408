4.1　网络层的功能

网络层提供主机到主机的通信服务，任务是把分组从源主机经多个网络、多段链路送到目的主机。两大功能：分组转发与路由选择。

背景 · 考试不碰：OSI 与 TCP/IP 在网络层上的那场路线之争 书上开头讲了一段历史：OSI 曾主张网络层用面向连接的虚电路服务、由网络自身保证可靠；TCP/IP 则选了无连接的数据报服务、由用户主机保证可靠。 这段的历史部分（谁主张、争了多久、后来怎么样）从不出题，可以快速划过。 但结论那一句必须停下来：「TCP/IP 的网络层向上只提供简单灵活的、无连接的、尽最大努力交付的数据报服务」—— 这一句 2011 年直接考成了一道选择题（答案 A：无连接、不可靠的数据报服务）。
必记 · 尽最大努力交付＝允许发生四件坏事 网络层不保证可靠 ⟹ 分组可能出错、丢失、重复、失序（四个词要能一字不差地列出来）。 好处是：路由器可以做得简单、廉价，可靠性上移给传输层。 
网络层：能送就送，送不到就丢，丢了不告诉你
              ↓ 代价上移
传输层 TCP：序号 + 确认 + 重传 + 排序 + 去重 = 把四件坏事全兜住
⭐ 「四件坏事」这个清单在 ch5 讲 TCP 时会原样再用一次——TCP 的每一个机制都对应着兜住其中一件。
我的补讲 · 「简单廉价」这四个字是命题人最爱的潜台词 书上说 X：网络层不保证可靠，所以路由器做得简单、廉价。
潜台词是 Y：路由器不做的事，比它做的事更值得记——路由器不做重传、不做排序、不做去重、不做端到端确认、不看端口号 （唯一的例外是 NAT 路由器，它偏偏要看端口号，见 4.2.3）。
所以能考 Z：凡是选项里出现「路由器负责 XXX 的可靠传输 / 路由器为分组排序 / 路由器做流量控制」，一律错。 2011 真题的解析给了一条更漂亮的判据：直接翻 IP 首部——没有序号字段 ⟹ 不可能保证有序；没有建立连接的字段 ⟹ 不可能面向连接；只有首部检验和 ⟹ 连数据部分的差错都不管。 ⟹ 「用首部有没有那个字段来反推协议有没有那个能力」，是本章最好用的一把万能钥匙，后面 IPv6 那节还会再用一次。

4.1.1　异构网络互连

互联网由全球数以百万计的异构网络互连而成——拓扑、寻址方案、差错处理、路由机制都可能不同。TCP/IP 的做法是：网络层采用标准化协议 IP，而被连接的各网络本身可以是异构的。互连后的整体被视为一个虚拟互连网络（IP 网络），主机之间通信就像在单个网络上一样，看不见各网络的异构细节。

必记 · 中继系统按层次分四种（本章第一张必背表）
层次中继系统它连出来的东西
物理层转发器（中继器）、集线器 Hub只是把一个网络扩大了，从网络层看仍是同一个网络，一般不称为网络互连
数据链路层网桥、交换机
网络层路由器网络互连通常就是指用路由器进行连接与路由选择
网络层以上网关连接高层协议不同的网络
⚠️ 历史遗留：许多 TCP/IP 文献把网络层的路由器也称为「网关」（「默认网关」这个日常说法就是这么来的）。
我的补讲 · 01 题与 03 题是同一把刀的两面，一起记才不会混 这两题的答案看起来打架，其实问的是两个不同问题，务必分开：
问题答案为什么
01 题「异构」是指哪几层不同？物理层 + 数据链路层（至少一个不同）异构性 ＝ 传输介质、数据编码、链路控制协议、数据单元格式、转发机制——这些全定义在下两层
03 题路由器互连时，哪几层可以不同？物理层 + 链路层 + 网络层（网络层以上必须相同）路由器是第三层设备，向传输层及以上隐藏下层实现
⚠️ 03 题的高频错项是 B（认为网络层协议必须相同）——理由听起来很合理：「现在都用 TCP/IP、网络层都是 IPv4 啊」。 王道给的反驳一针见血：用特定路由器连接 IPv4 网络与 IPv6 网络，就是「网络层协议不同而实现互连」的典型例子（这也正是 4.3 双栈/隧道那两个过渡策略在干的事）。 ⟹ 记法：设备在第 n 层，就能屏蔽第 n 层及以下的差异，第 n+1 层起必须一致。
我的补讲 · 「虚拟互连网络」这个词是本章所有抽象的起点 书上说 X：互连后的网络可视为一个虚拟互连网络（IP 网络），主机通信就像在单个网络上一样。
潜台词是 Y：「虚拟」二字意味着这一层是被造出来的假象—— 物理上根本不存在一朵大云，存在的只是无数条链路和路由器；是 IP 协议这一层统一的编址与转发规则「装」出了一朵云。
所以能考 Z：凡是问「为什么能互连异构网络」，标准答案就是「网络层采用统一的 IP 协议」， 而不是「因为大家的物理层相同」（恰恰相反，物理层可以完全不同）。
⭐ 更值得记的是它的代价：既然是假象，IP 就必须自己重新定义一套地址（IP 地址），而不能用底层的 MAC 地址—— 这直接引出 4.2 的全部内容，也引出 4.2.5 的 ARP（在假象与真实之间做翻译）。 把 4.1.1 与 4.2 之间的这条因果链想清楚，整章的结构就立起来了。
知识串联 · 中继系统四层表 ＝ ch2＋ch3＋本章三张表拼起来的那一张 设备 这张表你其实已经见过两次了，只是每次只见到一行： ch2 2.3 讲的转发器/集线器 ＝ 第一行；ch3 3.8 讲的网桥/交换机 ＝ 第二行；本章 4.7 要讲的路由器 ＝ 第三行。
冲突域/广播域 ⭐ 更值钱的是：这张表与 ch3 的「冲突域 / 广播域」表是同一张表的两半—— 层次越高，隔离能力越强：集线器什么都不隔离 → 交换机隔离冲突域 → 路由器连广播域也隔离。 2019 与 2022 两道综合真题的第一问都在考这句话，复习一次拿两章的分，这是全章投产比最高的一条串联。
分层 「设备在第 n 层就屏蔽 n 层及以下差异」这条规律， 和《操作系统》里「虚拟机/抽象层」的思路完全一致——每一层都在向上兜售一个「看起来更整齐的假象」： 链路层兜售「无差错的链路」，网络层兜售「一个统一的大网」，传输层兜售「一根可靠的管道」。

4.1.2　路由与转发

路由器的核心功能就是两件事：① 路由选择——运行路由协议，定期与相邻路由器交换信息，感知拓扑变化，动态生成并维护路由表，计算到目的网络的最优路径；② 分组转发——根据转发表把到达的分组从合适的输出端口送出去。

必记 · 路由表 vs 转发表（书上专门用一段话区分，就是要考）
路由表 routing table转发表 forwarding table
谁生成路由选择算法生成由路由表导出
侧重拓扑计算（哪条路最优）查找最优化（怎么查得最快）
属于哪个平面控制平面数据平面
⚠️ 书上紧接着说：讨论原理时往往不区分，笼统使用「路由表」一词——所以做题时看到「路由表」不要吹毛求疵， 只有当题目把两个词并列摆出来问区别时，才用上面这张表答。
我的补讲 · 路由表里到底存什么？这是 04 题十几年不变的考法 书上说 X：路由表的表项是「目的网络 + 下一跳」。
潜台词是 Y：这两个词各自都在排除一个错误答案—— 「目的网络」排除的是「目的主机」（用网络号可让一个表项覆盖成千上万台主机，表才不会爆）； 「下一跳」排除的是「完整路径」（路由器只管交给下一个人，不知道全程）。
所以能考 Z：04 题的四个选项正好是这两个维度的四种组合，只有「目的网络 + 下一跳的 IP 地址」是对的。 ⚠️ 还要防第四个坑：下一跳存的是 IP 地址而不是 MAC 地址—— MAC 地址是转发的那一瞬间才用 ARP 现查的（见 4.2.5），不会长期躺在路由表里。
⭐ 07 题把这条推到极致：源主机和中间路由器都不知道完整路径—— 主机只知道「本网内直接送，出网就丢给默认网关」，路由器只知道「下一跳是谁」。 这就是数据报网络与虚电路网络最本质的差别，下一节马上要用到。
知识串联 · 「只知下一跳，不知全程」是分布式系统的通用姿势 局部决策 路由器的这种工作方式，在 408 里到处都是： 《数据结构》里 Dijkstra 每一步只挑当前最近的点 · 《操作系统》里进程调度只看就绪队列当前状态 · 本章 4.4 的距离-向量算法更是纯粹的「只跟邻居打听」。
存储转发 06 题的「必须先收完整个分组才能开始转发 ＝ 存储转发机制」， 与 ch3 3.8 交换机的「直通式 vs 存储转发式」是同一个对照： 存储转发能查错、能变速率，代价是多一份发送时延；直通式快，但坏帧也照转。 ⚠️ 计算题里凡是出现「经过 N 个路由器」，几乎一定要按存储转发算 N 次发送时延—— 这正是 ch1 那条母公式 T ＝ (k+m−1)·r 的由来。

4.1.3　网络层提供的两种服务　考点追踪：虚电路的特点（2020）

分组交换网按通信子网向端系统提供的服务，分为面向连接的虚电路服务与无连接的数据报服务——注意：两种服务方式都是由网络层提供的。

1. 虚电路方式

通信前必须先在网络层建立一条逻辑连接——虚电路（VC）。连接一旦建立，端到端传输路径就被固定。整个通信过程分三阶段：虚电路建立 → 数据传输 → 虚电路释放。每次建立时系统分配一个未使用过的虚电路号 VCID，以区别于同一节点上的其他虚电路；每个中间节点维护一张虚电路表，记录 VCID 与下一跳，在连接建立过程中就确定好了。

必记 · 虚电路服务的五个特点（原文顺序，逐条都出过题） ① 建立与释放连接开销大——不适合交互式应用或少量数据交换，适合长时间、大量数据交换。
② 路由选择在连接建立阶段完成，建立完成后传输路径就固定了。
③ 提供可靠、有序的分组交付，并支持端到端的流量控制。
④ 对节点或链路的故障敏感——任一故障都会导致所有经过它的虚电路中断，必须重建。
⑤ 分组首部开销小——无须携带完整目的地址，只带虚电路号。
⭐ 「虚」字的含义要能一句话答出来：这条链路并非专用，而是可被多条虚电路共享。

2. 数据报方式

发送分组前无须建立连接。源主机把应用层报文分割成若干数据段，封装成携带完整源地址和目的地址的独立分组；中间节点对分组短暂缓存，独立选路后随即转发。网络层不提供服务质量保证，也不确保可靠传输，因此分组可能丢失、重复、失序或出错——这也正是路由器可以做得比较简单、造价低廉的原因。

必记 · 数据报服务的六个特点 ① 无须建立连接，随时可发、随时可收。
② 尽最大努力交付——每分组独立选路 ⟹ 路径可能不同 ⟹ 可能失序到达。
③ 分组携带完整的源地址与目的地址，以支持独立路由。
④ 存在排队时延与丢包风险，拥塞时时延显著增加，还可能被主动丢弃。
⑤ 故障适应能力强——节点/链路失效可更新转发表动态绕行。
⑥ 资源利用率高——带宽由多个会话共享；传输中分组仅占用当前链路的资源。

4.1.4　SDN 的基本概念　考点追踪：SDN 的南向接口（2022）

网络层的两大任务（转发、路由选择）在功能架构上被抽象为两个逻辑平面：数据平面（也称转发平面）负责执行分组转发，控制平面负责实现路由选择、生成并维护路由信息。SDN（软件定义网络）的核心就是：控制平面与数据平面解耦——控制平面集中化，数据平面分布式部署。

必记 · 传统网络 vs SDN，三句话说清 传统网络：每台路由器同时承担控制与转发——既运行路由协议、与邻居交换路由信息，又维护并查找转发表。
SDN：路由器仅保留数据平面功能，不再运行路由选择软件，彼此之间也不再交换路由信息； 控制功能由一个逻辑集中式的远程控制器（通常由多台服务器协同实现）统一承担。
控制器掌握全网拓扑与主机状态，为分组计算最优路径，再通过 OpenFlow 等协议把流表（SDN 中的转发表）下发到各路由器。 路由器的工作变得极简：接收分组 → 匹配流表 → 执行转发（即所谓「匹配 + 动作」）。
必记 · 三类接口谁对谁（2022 真题就考这一张表）
接口连接谁与谁典型协议 / 用途
北向接口控制器 ↔ 上层应用标准化 API，供开发者构建定制化网络应用，无须关心底层转发设备
南向接口控制器 ↔ 转发设备OpenFlow；控制器统一管理异构硬件、下发流表到数据平面
东西向接口控制器集群内部提升控制平面的可靠性与可扩展性
记法：上北下南、左右东西——把控制器画在中间，应用在上、交换机在下、别的控制器在两边，一秒定位。
我的补讲 · SDN 三道题只考三件事，其余全是包装 17、18、21 三题拆开看，考点只有三个：
① 三类接口谁对谁（21/2022 真题）——「下发流表」用南向；北向是给上层应用的。
② 谁取代了谁（17 题）——流表取代了转发表，OpenFlow 不是取代路由协议的东西，它只是控制平面与数据平面之间的接口。 真正取代路由协议的是「远程控制器集中计算」这件事本身。
③ 控制器在哪（18 题）——控制器是远程的服务器，不在 OpenFlow 交换机里； 另外 SDN 是一种新型网络体系结构（设计、构建、管理网络的新方法），不是新型「物理网络结构」——这个字眼是 18 题的 I 项。
⭐ 我的记法：SDN 的一切说法都可以用一句话验：「路由器变笨了，控制器变聪明了」。 凡是让路由器显得还很聪明的说法（还在跑路由协议、还在交换路由信息、控制器就装在它肚子里），一律错。
背景 · 考试不碰：SDN 的三大优势与两大挑战 书上列了优势三条（集中控制 + 分布转发 · 灵活可编程 · 降低成本）与挑战两条（安全风险：控制器一崩全网瘫 · 性能瓶颈：规模变大后控制器扛不住）， 以及一段「SDN 并非要把整个互联网都改造成集中控制模式」的说明（互联网本质是分布式的，全面集中不具可行性；但在大型数据中心互联的广域网等特定场景下确实能显著提效）。 这些段落至今没有出过题，理解一遍即可，不必背条目。 唯一值得留一句的是那对矛盾本身：集中化带来全局最优，也带来单点故障——这个权衡在 OS 与组原里也会反复见到。
知识串联 · 「控制与数据分离」是 408 三科共有的一条设计哲学 控制器 vs 数据通路 ⭐ 《组成原理》ch5 的 CPU 就是这么分的： 控制器（产生控制信号、决定做什么）与 数据通路（ALU、寄存器、总线，负责实际搬运和运算）—— SDN 不过是把这套结构从一块芯片放大到了一整张网。
机制与策略分离 《操作系统》里叫「机制（怎么做）与策略（做什么）分离」： 调度机制固定在内核，调度策略可以换；页面置换机制固定，FIFO/LRU/CLOCK 可以换 ⟹ 与「转发机制留在交换机、路由策略上收到控制器」是同一件事的三种说法。
分层 北向/南向接口的设计动机 ＝ ch1 讲的「分层 + 标准化接口」： 只要接口不变，上下两侧可以各自独立演进——这也是 OpenFlow 能统一管理「异构硬件」的全部原因。

4.1.5　拥塞控制

拥塞：网络中出现过量分组、超出其处理能力时所引发的性能下降现象。核心是及时感知拥塞并采取措施，避免因缓冲区溢出而丢包。这是一个全局性过程，涉及所有主机、路由器以及一切影响网络传输能力的因素——仅靠增加资源无法根本解决拥塞。

必记 · 怎么判断「已经拥塞了」：看吞吐量与负载的关系
现象结论
负载增大，吞吐量随之增大正常，不是拥塞
负载增大，但吞吐量增长甚微可能已处于轻度拥塞
负载增大，吞吐量反而下降很可能已进入拥塞状态（02 题答案）
⚠️ 02 题的两个干扰项 B、C 说的是「节点接收和发出的分组越来越少 / 越来越多」—— 「分组多少」与「吞吐量」不成正比，多发的可能全是重传和丢弃，因此不能据此判断是否拥塞。 严重时网络通信业务会陷入停顿，书上称为死锁。
必记 · 拥塞控制 vs 流量控制（一句话分界线） 拥塞控制是全局性的，流量控制是点对点的。
拥塞控制流量控制
作用范围整个网络（所有主机、路由器、链路）一对发送方与接收方
要解决什么网络中分组太多、来不及处理抑制发送方速率，使接收方来得及接收和处理
谁在喊「慢点」网络（路由器丢包、拥塞信号）接收方（通告窗口）
必记 · 开环控制 vs 闭环控制（认准「有没有反馈」四个字） 开环控制：设计时就把可能导致拥塞的因素考虑进去，用静态策略防止拥塞； 一旦投入运行，控制机制不再依赖实时反馈。典型手段：确定何时接收新流量、何时丢弃哪些分组、采用何种调度策略。 特点是不依赖当前网络状态。
闭环控制：监测网络运行状态 → 检测拥塞的位置与程度 → 反馈至控制节点 → 调整运行以缓解拥塞。 基于反馈机制，是一种动态方法。
⟹ 一字判据：有反馈回路的是闭环，没有的是开环；「静态/预防」＝开环，「动态/检测+反馈」＝闭环。
我的补讲 · 4.1.5 只有半页，却是 ch5 半章的总纲 书上说 X：这半页讲了拥塞的定义、判据、与流量控制的区别、开环与闭环两类方法。

⚠️ 最容易被忽略的一句：「仅靠增加资源无法根本解决拥塞」—— 直觉上「带宽不够就加带宽」，但加了带宽只会让更多分组涌进来、把瓶颈推到下一个路由器。 这句话本身就可以当判断题的题干。
知识串联 · 拥塞 ＝ 队列排不过来，这在三科里是同一件事 队列与调度 拥塞的物理实质就是「路由器的输出队列排满了」—— 与《操作系统》的就绪队列过长、《组成原理》I/O 的缓冲区溢出是同一种现象： 到达率 > 服务率，队列无界增长，最终只能丢弃。
流量控制 ⚠️ 流量控制这个词你已经在 ch3 见过一次了（链路层的滑动窗口）， ch5 还会再见一次（TCP 的接收窗口）——同一件事在三层各做一遍，作用范围逐层放大， 但「拥塞控制」只有网络层与传输层有，链路层没有（链路层管不到全局）。
丢弃策略 开环控制里那句「确定何时及丢弃哪些分组」， 与《操作系统》的页面置换算法（该淘汰谁）、Cache 的替换策略（LRU/随机）是同一类决策—— 资源不够时，谁被牺牲。

4.2.1　IPv4 分组

IPv4 即现在普遍使用的网际协议 IP。它定义了数据传送的基本单元——IP 分组及其确切的数据格式，也包括一套规则，指明分组如何处理、错误怎样控制；特别是它包含了非可靠投递的思想，以及与之关联的路由选择的思想。

我的补讲 · 「4B / 1B / 8B」这三个单位，是本章计算题最大的失分点 书上说 X：三个长度字段的单位分别是 4B、1B、8B。
潜台词是 Y：命题人知道你会算分片，所以他不在算法上为难你，而在单位上为难你—— 题目给你「片偏移＝185」，你要能立刻反应出「它前面已经有 185×8 ＝ 1480 字节」； 给你「首部长度字段＝5」，要反应出 5×4 ＝ 20B；给你「总长度＝1500」，那是连首部一起的 1500B。
所以能考 Z：三个典型错法各对应一个错误选项—— ① 把片偏移当字节数（少乘 8）· ② 把总长度当纯数据长度（多算 20B）· ③ 把首部长度当字节数（少乘 4）。 ⟹ 考场自查口诀：「偏移乘八、首长乘四、总长含头」。
我的补讲 · 「首部检验和只检验首部」这句话，背后是一个很值钱的推论 书上说 X：首部检验和只检验首部，不检验数据部分，可减少计算工作量；且每经过一个路由器都要重算。
潜台词是 Y：IP 层根本不保护你的数据——数据部分坏了，IP 一无所知、照样交付。 那谁来保护？上面的 TCP／UDP 检验和（它们的检验范围包含数据）与下面的链路层 CRC。 ⟹ 「IP 只自保首部、数据靠上下两层」是一条完整的跨层结论。
所以能考 Z：① 判断题「IP 提供差错检测，所以数据出错会被丢弃」——错； ② 问「为什么每跳都要重算检验和」——因为 TTL 每跳减 1，首部变了 （顺带：总长度、标志、片偏移、地址在分片或 NAT 时也可能变）。 ⚠️ 这条还解释了一个常被问的问题：为什么 IPv6 干脆取消了首部检验和—— 既然上下两层都在查，中间这一层每跳重算纯属浪费，见 4.3。

2. IP 数据报分片　考点追踪：IP 分片相关首部字段（2011）· IP 分片的原理及分析（2021）

一个链路层数据帧能承载的最大数据量称为最大传送单元 MTU。源到目的路径上各段链路的 MTU 可能不同——以太网的 MTU 通常为 1500B，而很多广域网的 MTU 不超过 576B。当 IP 数据报总长度超过某段链路的 MTU 时，就必须拆成多个较小的 IP 数据报，称为分片。

必记 · 分片的三条铁律 ① 分片可以发生在源主机或中间路由器上，但重组只在目的主机上进行。 （⟹ 中间路由器只拆不合，哪怕下一段链路的 MTU 又变大了也不合。）
② 重组靠首部里的三个字段：标识、标志、片偏移—— 标识说「谁和谁是一家的」，MF 说「后面还有没有」，片偏移说「我该放在第几个字节」。
③ 分片行为受标志字段控制：仅当 DF＝0 时才允许分片；DF＝1 则禁止分片 （此时若超过 MTU，路由器只能丢弃并回一个 ICMP 差错报文，见 4.2.7）。
必记 · 分片三步法（本章第一条母公式，闭着眼睛也要会） 
第 1 步 每片最大数据 = ⌊(MTU − 20) / 8⌋ × 8      ← 必须是 8 的倍数
第 2 步 片数 = ⌈数据部分总长 / 每片最大数据⌉
第 3 步 片偏移 = 该片之前已装走的字节数 / 8

标志位：除最后一片外 MF 全为 1，最后一片 MF = 0
⚠️ 第 1 步那个「向下取整到 8 的倍数」是全章最容易漏的一步—— 因为片偏移以 8B 为单位，除最后一片外，每片的数据长度必须是 8 的整数倍，否则下一片的偏移就不是整数了。 ⟹ MTU＝1500 时 (1500−20)＝1480 恰好是 8 的倍数，所以这一步「看起来没做」；一旦 MTU 换成 576，(576−20)＝556，⌊556/8⌋×8 ＝ 552，这一步就露出獠牙了。

我的补讲 · 多级 MTU 必须「串行做两次」，这是分片题里最狠的一个变式 书上只给了一级 MTU 的例子，但真题会给你两段链路。做法是：把第一次分出来的每一片，当成一个全新的、独立的 IP 数据报，再对它做一次分片—— 因为「重组只在目的主机」，中间路由器拿到的就是一个个独立数据报，它不知道也不关心这些片原本是一家的。 唯一要留心的是片偏移必须相对于最原始的数据报，不能从 0 重新起算。 
例：2000B 数据报（数据 1980B）先过 MTU=576，再过 MTU=552

第一级 MTU=576：每片数据 ⌊(576−20)/8⌋×8 = 552
   ⟹ 552 + 552 + 552 + 324 = 1980   偏移 0 / 69 / 138 / 207

第二级 MTU=552：552B 数据 + 20B 首部 = 572 > 552，还要再分！
   每片数据 ⌊(552−20)/8⌋×8 = 528
   ⟹ 每个 552B 的片再拆成 528 + 24
🐍 这个例子我已按事件级逐片复算过：最终片长序列 552→(528,24) 各级偏移全部落在 8 的倍数上。 所以能考 Z：凡题干里出现两个不同的 MTU，一律警觉——这是在考「串行两次」而不是「取最小的 MTU 算一次」。 （取最小值算一次得到的片数往往和正确答案不同，正是命题人准备好的干扰项。）
陷阱 · MF 与 DF 的极性方向相反，一年至少考一次 DF＝0 才允许分片（Don't Fragment 为 0，即「不禁止」）；MF＝1 表示还有后续片（More Fragment）。 一个「0 是允许」，一个「1 是还有」，方向恰好拧着，这是纯粹的记忆坑，没有道理可讲，只能死记。
我的记法：把两个字母都读成英文原意——Don't Fragment ＝「别分片」，那当然是 1 才生效； More Fragment ＝「还有更多」，当然是 1 表示还有。 ⟹ 两个都是「1 时该字母的字面意思成立」，这样就统一了。
⚠️ 第二个附带的坑：最后一片的 MF＝0，但它的片偏移不为 0； 第一片的片偏移＝0，但它的 MF＝1。「MF＝0 且偏移＝0」只有一种情况：这个数据报根本没被分片。

4.2.2　IPv4 地址　考点追踪：0.0.0.0 的作用（2017）· 网络地址的确定（2022）· 默认网关与子网掩码的配置（2015、2016、2019、2022）· CIDR 地址块的分析（2011、2015、2016、2019、2023）· 路由聚合的原理（2009、2011、2013、2014、2018）

IP 地址是为连接到互联网上的每台主机（或路由器）的每个接口分配的一个全球唯一的 32 位标识符，由 ICANN 统一管理。通常把 32 位分成 4 段、每段 8 位，转成十进制并用小数点分隔——点分十进制记法。

无论哪一类，IP 地址都由网络号与主机号两部分组成：IP 地址 ::= {<网络号>, <主机号>}。网络号标志接口所连接到的网络，在整个互联网范围内必须唯一；主机号标志该接口，在其所在网络内必须唯一。

② IP 地址标识的是「网络接口」，而不是「主机」—— 一台主机连到多个网络时，每个接口都要配一个 IP，且各地址的网络号必须不同 ⟹ 路由器至少拥有两个或更多 IP 地址，每个接口对应一个不同网络号的地址。
③ 用集线器或交换机连起来的多个网段，逻辑上仍属同一个网络（同一个广播域） ⟹ 其中所有主机的 IP 必须有相同的网络号，主机号唯一。
④ IP 地址是逻辑地址，与底层物理硬件（MAC 地址）无关——正因如此，网络层才能屏蔽链路层的异构性。
⚠️ 近年随着无分类编址广泛应用，传统分类地址已逐渐退出历史舞台（但考试仍在考，因为它是理解 CIDR 的台阶）。
我的补讲 · 「IP 标识接口而非主机」这一条，是三道大题的第一问 书上说 X：IP 地址标识的是网络接口；路由器至少有两个 IP。
潜台词是 Y：做子网划分题时，路由器接口要占掉一个 IP 地址—— 这就是为什么书上的例题里「50 台主机的部门」要按 51 个地址算。
所以能考 Z：凡题目说「某部门有 N 台主机」，你要算的需求量是 N ＋ 1（多出来的那个给路由器接口）， 再按 2n−2 ≥ N+1 反推主机位 n。 2009、2018、2019、2025 四道综合真题在这一步上一模一样。
⭐ 第二个推论同样值钱：既然路由器每个接口都在不同的网络里，那么「一台路由器连了 k 个网段」就意味着要划出 k 个子网—— 点对点链路两端也是两个接口，因此那条链路本身也算一个网络，需要一个 /30 地址块（见下文）。 很多人算子网时漏掉的正是「路由器之间那条线也要一个子网」。

2. 划分子网

传统两级 IP 地址结构有三个缺点：地址空间利用率低（一个物理网络吃掉一整个网络号）、路由表规模过大、地址分配缺乏灵活性。从 1985 年起在 IP 地址中增加「子网号」字段，形成三级结构：

IP 地址 ::= { <网络号> , <子网号> , <主机号> }
                └── 对外可见 ──┘   └── 单位内部自己划 ──┘
必记 · 划分子网的三条基本思想 ① 对外透明：单位对外仍表现为单一网络，外部路由器无须感知其内部子网结构。
② 内部灵活划分：从原主机号中借用若干位作为子网号，主机号位数相应减少。
③ 分层转发：外部路由器按网络号把数据报送到该单位的边界路由器；边界路由器再结合子网号交付到具体子网，最后送到目的主机。
⚠️ 书上灰框的两句话，句句是考点： ① 划分子网只对主机号部分再划分，不改变原网络号，因此无法从 IP 地址本身判断是否划分了子网（必须给掩码）。 ② 划分子网提升了灵活性，但也使可分配主机总数略有减少（每个子网都要各扣掉一个网络地址和一个广播地址）。
必记 · 子网掩码与三条使用原则　2022 子网掩码是一个与 IP 地址对应的 32 位二进制串，由一串 1 后跟一串 0 组成： 1 对应网络号 + 子网号，0 对应主机号。 把 IP 地址与子网掩码逐位「与」（AND），得到的就是子网地址（网络地址）。
默认子网掩码：A ＝ 255.0.0.0 · B ＝ 255.255.0.0 · C ＝ 255.255.255.0；现在的互联网标准规定每个网络都要配置子网掩码。
三条使用原则：① 配 IP 必须同时配掩码；② 同一子网内所有主机及路由器接口必须配置相同的掩码； ③ 路由表的三项核心信息 ＝ 目的网络地址 + 子网掩码 + 下一跳地址。
⭐ 路由器交换路由信息时，必须同时通告目的网络地址和子网掩码—— 这一句在 4.4 讲 RIP 与 OSPF 时会变成「RIP 的报文里带不带掩码」这个具体差别。
必记 · 默认网关与「直接交付 / 间接交付」　2015、2016、2019、2022 四年真题 默认网关 ＝ 本子网所连路由器接口的 IP 地址。 主机发数据前，先把目的 IP 与自身 IP、自身子网掩码比较，判断是否在同一子网： 
目的IP AND 我的掩码  ==  我的IP AND 我的掩码  ？
   ├─ 相等 ⟹ 同一子网 ⟹ 直接交付
   │        用 ARP 查【目的主机】的 MAC，封成帧直接发过去
   └─ 不等 ⟹ 不同子网 ⟹ 间接交付
            用 ARP 查【默认网关】的 MAC，把帧发给路由器，由它在网络层转发
⚠️ 这段话是本章跨节引用最多的一段：4.2.4 转发过程、4.2.5 ARP、4.7 路由器工作原理全都建立在它之上。
陷阱 · 判断「是否同一网络」，用的是发送方自己的掩码 这是本章 45 题与 58 题的胜负手，也是最反直觉的一处： 主机 A 判断「目的主机在不在我这个网」，用的是 A 自己的子网掩码去 AND 目的 IP——它根本不知道目的主机的掩码是多少。
后果是：如果 A 和 B 的掩码配错成不一致，会出现「A 认为 B 在同网、B 认为 A 在外网」这种单向可达的怪现象—— 而这正是很多真题题干里「为什么 ping 不通」的原因。
⚠️ 配套的第二条：路由器不会把分组从它进来的那个接口再转发回去 （否则就绕回去了）——做转发路径题时，这条能直接排掉一个选项。

3. 无分类编址 CIDR　考点追踪：CIDR 地址块的分析（2011、2015、2016、2019、2023）

无分类域间路由选择 CIDR 是一种基于可变长子网掩码的地址分配与路由聚合机制，用来消除 A/B/C 类地址的限制、提升地址空间利用率。核心思想：不再区分网络类别，改用「网络前缀」标识网络部分，前缀长度（掩码中连续 1 的个数）可任意指定，不再局限于 8/16/24 位。

必记 · 斜线记法与地址块的四件事 CIDR 结构：IP 地址 ::= {<网络前缀>, <主机号>}，写作 「IP 地址/前缀长度」。 只要知道地址块中的任意一个地址及其前缀长度，就能定出：最小地址、最大地址、地址总数、可用主机数。 
以 128.14.32.5/20 为例（前 20 位是前缀）
IP 地址  = 10000000.00001110.0010|0000.00000101
掩码     = 11111111.11111111.1111|0000.00000000   = 255.255.240.0
网络前缀 = 10000000.00001110.0010|0000.00000000   = 128.14.32.0   ← 最小地址
最大地址 = 10000000.00001110.0010|1111.11111111   = 128.14.47.255 ← 广播地址
地址总数 = 2^(32-20) = 2^12 = 4096      可分配 = 4096 - 2 = 4094
🐍 已复算：网络 128.14.32.0、掩码 255.255.240.0、广播 128.14.47.255、共 4096 个地址 —— 与书吻合。
⚠️ 在 CIDR 下「/前缀长度」不可省略：只给 128.14.32.5 无法确定它的网络地址。 ⭐ CIDR 地址块的地址总数一定是 2 的整数次幂；前缀越短 ⟹ 主机位越多 ⟹ 块越大。
我的补讲 · 手算网络地址／广播地址的两条捷径（考场上别真去写 32 位二进制） 32 位手写一遍要 30 秒，一道题里往往要算五六次，必须提速。两条捷径：
① 只算「有零有一的那一段」。前缀是 8 的倍数时（/8、/16、/24）直接按段截断，一位二进制都不用写； 不是 8 的倍数时，只有跨界的那一个字节需要展开，其余字节照抄或清零。 例 /20 ⟹ 前两段照抄、第三段展开（前 4 位保留、后 4 位清零/置一）、第四段清零/置一。
② 用「块大小」直接跳。块大小 ＝ 256 − 掩码中那个非 0 非 255 的字节值， 网络地址就是「该字节向下取到块大小的整数倍」，广播地址 ＝ 下一个网络地址 − 1。 
例 128.14.32.5/20 ⟹ 掩码 255.255.240.0，关键字节 240
   块大小 = 256 − 240 = 16
   第三段 32 是 16 的整数倍 ⟹ 网络地址第三段 = 32     ⟹ 128.14.32.0
   下一个块从 32+16 = 48 起 ⟹ 广播 = 128.14.47.255

前缀/25/26/27/28/29/30
末字节掩码128192224240248252

可用主机12662301462
这张表里的 62 / 30 / 6 / 2 四个数字，在真题里出现的频率高得离谱——因为它们对应「50 台/20 台/5 台/点对点」这四种最常见的部门规模。
陷阱 · 「CIDR 不使用子网」≠「用了 CIDR 就不能划子网」 书上专门用一段话强调这件事：「CIDR 不使用子网」是指它不在全局地址结构中预设固定的子网字段， 但这并不妨碍获得 CIDR 地址块的单位在其内部继续划分子网。
例：某单位拿到一个 /20 地址块后，可从主机号里再借 3 位划成 8 个子网，此时每个子网的前缀变成 /23。 （20 + 3 ＝ 23，借几位前缀就加几）
⭐ 这正是 CIDR 的最大好处，书上原话值得背下来： 「在网络外部，可通过较短前缀进行路由聚合，显著减少全局路由表项；在网络内部，可延长前缀以灵活划分子网。」 ——外部聚合、内部细分，八个字概括整个 CIDR。

4. 路由聚合　考点追踪：路由聚合的原理（2009、2011、2013、2014、2018）

一个大的 CIDR 地址块包含多个较小的地址块，于是在路由表里可以用一个较大的块代替多条较小的路由，这称为路由聚合——它使路由表中的一个项目能代表原来的多条路由，从而压缩路由表规模、提升网络性能。

必记 · 路由聚合三步法（本章第三条母套路） 
第 1 步 找出这些网络地址【完全相同】的前几段，原样保留
第 2 步 只把【有差异】的那一段展开成 8 位二进制
第 3 步 从高位起数出【连续相同】的位数 k
        聚合前缀长度 = (相同段的位数) + k
书上的例子（图 4.8）：R2 下挂 206.1.0.0/17 与 206.1.128.0/17，R1 到两者的下一跳都是 R2。 两者前 16 位完全相同、第 17 位分别为 0 和 1 ⟹ 聚合成 206.1.0.0/16，两条路由变一条。 🐍 已复算：collapse_addresses 结果就是 206.1.0.0/16 —— 与书吻合。
⚠️ 能聚合的前提是「下一跳相同」——下一跳不同的路由再怎么地址相邻也不能合并，这是选择题的常见错项。
我的补讲 · 聚合题的两个坑：「多聚了」与「少聚了」 书上说 X：从高位数出连续相同的位数，就是聚合前缀长度。
潜台词是 Y：这个数只能不多不少—— 多聚（前缀取太短）会把不属于自己的地址也吸进来，造成错误转发； 少聚（前缀取太长）则聚不完，还得留着多条路由。
所以能考 Z：选择题最爱给你四个前缀长度让你挑，正确答案永远是「能覆盖全部给定网络的最长前缀」。 换句话说：先算出必须多短才能全包住，然后一位都不再放宽。 
口诀：聚合取【最长的公共前缀】，一位都不能多让

反例：要聚合 192.168.4.0/24 与 192.168.7.0/24
  4 = 000001|00     7 = 000001|11
  高位连续相同 6 位 ⟹ 192.168.4.0/22
  ⚠️ /22 实际覆盖 4、5、6、7 四个网络——比要求的多包了 5 和 6，
     但这是【聚合必然的代价】，只要 5、6 也归自己管就没问题；
     若 5、6 属于别人，则【不能聚合】。
⟹ 综合题里出现「聚合后是否会影响其他网络」这一问时，考的就是上面这个副作用。

5. 最长前缀匹配　考点追踪：最长前缀匹配机制（2013、2015）

必记 · 最长前缀匹配（也称最佳匹配） 使用 CIDR 时，路由表项由「网络前缀」和「下一跳地址」组成。查表时目的地址可能匹配多条路由， 此时应选择网络前缀最长的那一条——因为前缀越长，地址块越小，路由信息就越具体、越精确。
优先级从高到低：特定主机路由 /32 > 前缀长的普通路由 > … > 默认路由 0.0.0.0/0（前缀长度 0，最低）。
实现：为高效实现最长前缀匹配，路由器通常把 CIDR 路由表组织成层次式数据结构（如 Trie 树），自上而下快速定位。
我的补讲 · 查路由表的标准动作，三行写完（综合题必考步骤） 拿到一张路由表和一个目的 IP，机械地做三件事，一步都别跳：
  1. 逐行做 目的IP AND 该行掩码，把结果与该行的「目的网络」比较，相等即为一条候选。
  2. 在所有候选中挑前缀最长的那一条（掩码里 1 最多的那行）。
  3. 按该行的下一跳转发；若该行下一跳写的是「直接交付」，就在本地网络用 ARP 找 MAC 直接送到。
⚠️ 三个高频失分点：① 忘了默认路由 0.0.0.0/0 也是候选（它匹配一切，只是前缀最短）； ② 把「候选最多的」当答案（要选前缀最长，不是匹配得最多）； ③ 忘了检查「特定主机路由」（掩码 255.255.255.255，前缀 32，一旦命中就是它，优先级最高）。
⭐ 考场提速技巧：先把路由表按前缀长度从长到短排一遍，然后从上往下扫，第一个匹配上的就是答案，扫到即停—— 这正是路由器内部真实的做法（Trie 树自上而下），也省掉了「比较谁更长」这一步。
知识串联 · 最长前缀匹配 ＝ 数据结构的 Trie 树 ＋ 组原的按块匹配 分块与映射 「前缀越长越具体」这个规则，在《数据结构》里就是 Trie（字典树）的最深匹配： 沿着树往下走，能走多深走多深，最后停下的那个节点就是答案——王道在正文里直接点了 Trie 树的名字，这是本章少见的明确跨科指路。
空间换时间 路由器把路由表组织成层次结构，与《组成原理》Cache 的组相联映射是同一笔账： 全相联查得准但慢，直接映射快但冲突多，组相联折中；路由表若逐条线性比对就是 O(n)，组织成 Trie 后是 O(前缀长度)。
分块与映射 再往回看：路由聚合 ＝ 把多个小块合成大块，与 OS 里大页（huge page）、组原里增大 Cache 行的动机一模一样—— 都是「用一条表项覆盖更多地址，来压住表规模的爆炸」。 而副作用也一模一样：粒度变粗，可能把用不着的东西也包进来。

6. 子网划分的应用举例（本章综合题的主干，逐字精读）

通常有两类划分方法：定长子网掩码与变长子网掩码。

必记 · （1）定长子网掩码　2009、2010、2017、2018 定长 ＝ 每个子网使用相同的掩码、分到相同数量的地址 ⟹ 容易造成地址浪费。

我的补讲 · 变长子网划分的标准解法：四步 + 一张验算表 这是本章综合题出现频率最高的一问，把动作固定下来，考场上不用思考：
  1. 算需求：每个部门 主机数 ＋ 1（路由器接口）；别忘了路由器之间的每条点对点链路各算一个「网络」，需求为 2。
  2. 定主机位 n：找最小的 n 使 2n−2 ≥ 需求；前缀 ＝ 32 − n。
  3. 从大到小、边界对齐地切块：每个块的起始地址必须是它自己块大小的整数倍（这叫「对齐」，是唯一容易错的一步）。
  4. 写出四件东西：CIDR 表示、子网掩码、地址范围（最小～最大）、可用主机范围（最小+1 ～ 最大−1）。
验算表（写完必查，30 秒）：
查什么怎么查
够不够每块的 2n−2 ≥ 该部门需求？（含路由器接口）
对不对齐每块起始地址 ÷ 块大小 是否整除？不整除就是切错了
重不重叠前一块的最大地址 < 后一块的最小地址？
漏没漏网络数一数路由器的接口数：每个接口所在的网段都必须有一个块
⭐ 第 3 步「对齐」失手的典型样子：需求 30 的部门想从 .70 开始切一个 /27——错，/27 的块大小是 32，起点只能是 .0/.32/.64/.96… 我按这四步复算过 2009／2018／2019／2021／2025 五道综合真题，步骤完全通用。
必记 · 点对点链路用 /30（真题口径）还是 /31（新标准） 传统做法（统考真题至今仍用这个口径）：连接两个路由器接口的点对点链路分配一个 /30 地址块—— 主机号 2 位，共 4 个地址，扣掉网络地址与广播地址后恰好剩 2 个，给链路两端各一个。 
/30 的四个地址，用途一目了然：
   x.x.x.0   网络地址   ✗ 不能用
   x.x.x.1   接口 A     ✓        ⟹ 记法：【网络地址+1】与【广播地址−1】
   x.x.x.2   接口 B     ✓
   x.x.x.3   广播地址   ✗ 不能用
新标准（谢希仁第 8 版，书上脚注特别提醒「近年统考真题仍采用旧标准」）： 这类链路两端接口可不分配 IP；若要分配，则用 /31——只有 1 位主机号、2 个地址， 无须保留网络地址与广播地址，两个地址全部可用，实现零浪费。
⟹ 考场上一律按 /30 作答；/31 只在题目明确提到「新标准」时才用。
我的补讲 · 「点对点链路也是一个网络」，这是子网题最常见的漏项 书上说 X：点对点链路分配一个 /30 地址块。
潜台词是 Y：一条只连了两个路由器接口、上面一台主机都没有的线，在 IP 的世界里也是一个完整的「网络」—— 因为路由器的每个接口必须处于不同的网络（IP 标识接口，见前文的四个特点之②）。
所以能考 Z：题目画一张拓扑，三个部门 + 两台路由器互连，要划的子网不是 3 个而是 4 个甚至 5 个 （3 个部门网段 ＋ 路由器之间的每条链路各一个）。 2016 的 201.1.3.10、2023 的 195.123.0.33、教材综合题 12 的 203.10.2.1，三处都是在考「这个地址属于哪条 /30 链路」。

4.2.3　网络地址转换 NAT　考点追踪：私有 IP 地址连网处理机制（2011）· NAT 的工作原理（2016、2019、2020、2023）

NAT 把专用网络中的私有 IP 地址转换为公网 IP 地址，从而实现与互联网的通信，并对外隐藏内部网络的结构。整个专用网通常只需一个全球 IP 地址即可与互联网连通；由于私有地址可在不同专用网中重复使用，NAT 有效缓解了 IP 地址短缺的问题，并在一定程度上降低了内网被攻击的风险。

必记 · 三个私有 IP 地址块（172 那一行是经典陷阱）
地址块范围相当于
10.0.0.0/810.0.0.0 ～ 10.255.255.2551 个 A 类网络
172.16.0.0/12172.16.0.0 ～ 172.31.255.25516 个连续的 B 类网络
192.168.0.0/16192.168.0.0 ～ 192.168.255.255256 个连续的 C 类网络
⚠️ 172 那块的上界是 172.31.255.255，不是 172.16.255.255—— 因为 /12 表示前 12 位固定，第 13～16 位可变，即第二段的低 4 位可从 0000 变到 1111，也就是 16～31，正好 16 个 B 类网络。 这个 31 我用 ipaddress 复算过，是本节最容易丢的一分。
⚠️ 私有地址只用于 LAN 内部，互联网中所有路由器对目的地址为私有地址的数据报一律不予转发； 私有地址也称可重用地址，用它组建的网络称为专用网络。
必记 · NAT 的四步（图 4.9，2020 综合真题就是把这四步做了两遍） 场景：家庭宽带获得全球 IP 138.76.29.7，内部主机 10.0.0.1／2／3，网关 LAN 侧 10.0.0.4； 主机 10.0.0.1 用源端口 3345 访问 Web 服务器 128.119.40.186:80。

必记 · 书上灰框：普通路由器 vs NAT 路由器（高频考点，原话背下来） ① 普通路由器转发 IP 分组时，不会改变其源 IP 地址和目的 IP 地址。
② NAT 路由器转发时，会修改源 IP（出站）或目的 IP（入站）。
③ 普通路由器仅工作在网络层；NAT 路由器还需查看并转换传输层的端口号，因此其功能涉及传输层。
⭐ 第 ③ 条是 408 里「网络层设备越界」的唯一例子，问「NAT 路由器工作在哪一层」时，标准答案是「网络层，但涉及传输层」。
我的补讲 · NAT 题的通用解法：画一张四列表，逐跳填地址 书上说 X：NAT 路由器出站改源、入站改目的。
潜台词是 Y：做题时不要在脑子里想，一律画表——「在哪一段链路上 / 源 IP / 源端口 / 目的 IP / 目的端口」五列，一段一行。 因为真题（2020）会串两级 NAT，脑子转两圈必错。

双 NAT（2020 真题的骨架）：内网 A --NAT1--> 中间网 --NAT2--> 公网 S

⚠️ 还有第三条容易忘的规则：NAT 只改 IP 和端口，不改数据部分； 而且目的地址在出站方向自始至终不变——很多人一紧张就把目的地址也改了。
知识串联 · NAT 是「地址空间不够」这个老问题的第二种解法 地址耗尽 IPv4 地址不够用，408 里给了三种解法，考试常放在一起对比： ① CIDR / VLSM（把地址切得更细，少浪费）· ② NAT（让多台机器共用一个地址）· ③ IPv6（直接把地址加长到 128 位，见 4.3）。 前两个是「省着用」，第三个是「彻底换」——这就是 4.2 与 4.3 之间的逻辑关系。
端口 NAT 靠端口号区分内网主机，这一点直通 ch5： 端口号本是「区分同一台主机上的不同进程」的，NAT 把它借来「区分不同主机」—— 这也解释了为什么 NAT 表里必须记端口，以及为什么 NAT 对 ICMP 这种没有端口的协议要特殊处理。
空间换时间 NAT 转换表本身就是一张缓存表：动态建立、超时清除—— 与 ARP 缓存、Cache、TLB 是同一族机制，连「表满了怎么办」「条目过期怎么办」这些问题都同构。

4.2.4　网络层转发分组的过程　考点追踪：特定主机路由的应用（2009）· 默认路由的应用（2009、2014）

主机发送数据时，先把目的 IP 与本网络的子网掩码逐位与运算：结果等于本网络前缀就直接交付（无须路由器参与），否则发给默认网关由路由器转发（间接交付）。分组的转发始终基于「目的主机所在网络」——因为互联网中的网络数量远小于主机数量，这样能显著压缩转发表规模。

必记 · 路由表中的两种特殊路由
特定主机路由默认路由
写法a.b.c.d/320.0.0.0/0
为什么这么写掩码全 1 ⟹ 只匹配这一台主机全 0 掩码与任何地址相与都是 0.0.0.0 ⟹ 必然匹配所有地址
用途网络管理员对某台主机做控制和测试目的网络不在表中就走它；常用于连接互联网（海量网络列不完）
优先级最高（前缀 32 位，最长）最低（前缀 0 位，最短）
⚠️ 书上专门说明：「/32」的掩码在子网划分里没有意义，但在转发表里可作为标识单个主机的特殊前缀。 ⭐ 两者的优先级差异不是额外规定，而是最长前缀匹配的自然结果——这一点想通了就不用背。
必记 · 路由器的分组转发算法四步（可直接当综合题卷面模板）
  1. 从收到的 IP 分组首部提取目的 IP 地址 D，从转发表第一项开始检查（表按前缀长度降序排列）。
  2. 若存在特定主机路由（目的网络为 D/32），按其下一跳转发；否则转步骤 3。
  3. 把当前路由项的子网掩码与 D 逐位「与」：结果等于该项的网络前缀 ⟹ 匹配成功，按「下一跳」处理 （直接交付给本网络上的目的主机，或经指定接口转发到下一跳路由器）；否则检查下一项，重复本步。
  4. 全表都不匹配时：若有默认路由 0.0.0.0/0 就发给它；否则报告 「目的不可达」 错误。
书上补了一句：特定主机路由与默认路由的匹配本质上已包含在第 3 步里，单列只是为了强调优先级与典型场景。
⚠️ 转发表不提供到目的网络的完整路径，仅指明「下一跳路由器」，分组逐跳转发直至抵达目的网络。
必记 · 书上灰框：下一跳的 IP 不会被填进分组首部（跨层串联的关键句） 从转发表得到下一跳路由器的 IP 地址后，并不会把该地址填入待转发分组的首部， 而是通过 ARP 解析出对应的 MAC 地址，填入链路层帧首部作为目的地址。 该帧发到下一跳路由器后，路由器剥离帧首部、取出 IP 分组，再交给网络层处理。 
同一个 IP 分组，走三跳的样子：

           [ IP 首部: S=H1, D=H4 ]  ← 三跳全程【一个字都不改】
链路 1 外面套：[ MAC: H1 → R1 ]
链路 2 外面套：[ MAC: R1 → R2 ]      ← 每跳【拆掉重套】
链路 3 外面套：[ MAC: R2 → H4 ]
⭐ 这张图就是本章与 ch3 的接缝，也是综合题最爱问的一问：「在链路 X 上，帧的源/目的 MAC 分别是什么」。

4.2.5　地址解析协议 ARP　考点追踪：ARP 的工作原理（2011、2012、2021）· ARP 的解析过程（2011、2015）· 跨局域网的 ARP 解析（2015）

必记 · 分层抽象的四条精髓（书上原话，命题人反复取材） ① 在 IP 层抽象的互联网上，只能看到 IP 数据报。
② 尽管 IP 数据报首部包含源 IP 地址，但路由器仅依据目的 IP 地址进行转发。
③ 在局域网的链路层只能看到 MAC 帧，IP 数据报被封装其中；每经过路由器转发都会被解封装并重新封装，MAC 帧的源地址和目的地址都随之改变 ⟹ 这决定了 MAC 地址无法用于跨网络通信。
④ 底层硬件地址体系各异，IP 层的抽象屏蔽了这些差异——只要在网络层讨论问题，就能用统一的 IP 地址研究主机与主机、主机与路由器的通信。
⚠️ 附带一条：路由器因互连多个网络，每个接口都配置有一个 IP 地址和一个对应的 MAC 地址。
必记 · ARP 的三步与两个「广播/单播」 每台主机和路由器都维护一个 ARP 高速缓存（ARP 表），存放本局域网内各主机与路由器接口的 IP↔MAC 映射； 动态更新，每个表项设有生存时间（例如 20 分钟），超时自动删除。
主机 A 要给本局域网的主机 B 发数据：先查自己的 ARP 缓存，有就直接用；没有则：
  1. A 构造 ARP 请求分组，封装在目的 MAC ＝ FF-FF-FF-FF-FF-FF 的帧中广播发送，本局域网内所有主机都收到。 内容：「我的 IP 是 …，MAC 是 …，我想知道 IP 为 X 的主机的 MAC」。
  2. B 发现被问的正是自己，向 A 单播发送 ARP 响应分组，含自己的 MAC。 ⚠️ 同时 B 把 A 的 IP↔MAC 写进自己的 ARP 缓存（一次问答，两边都受益）。
  3. A 收到响应后把 B 的映射写入缓存，然后用该 MAC 封装数据帧发出。
⚠️ 「ARP 请求广播、ARP 响应单播」是本节最高频的一个考点。
ARP 归为网络层协议，因为它处理的是 IP 地址——书上给了通用判据：看某协议使用或依赖哪一层的地址/端口信息，就归哪一层。
必记 · ARP 的四种典型情况（图 4.11，「解析谁的 MAC」是唯一考点） 拓扑：H1、H2 在网 1 —— L1[R1]L2 —— 网 2 上有 H3 —— L3[R2]L4 —— 网 3 上有 H4。
情况发送方目标ARP 解析出的是谁的 MAC
1主机 H1本网络上的 H2目的主机 H2 的 MAC
2主机 H1其他网络上的 H4本网络中默认网关（R1 的接口 L1）的 MAC，不是 H4 的

⟹ 四种情况其实只有一条规律：ARP 永远只解析「我这一跳要交给谁」的 MAC—— 同网就是目的主机，跨网就是下一跳路由器接口。
⚠️ 书上灰框：ARP 仅作用于同一局域网（广播域），无法跨网络工作。
必记 · 书上灰框：一路上 MAC 地址怎么变（⭐⭐ 综合题最爱考的一句） H1 → H4 这一路，MAC 帧的源/目的地址依次是： 
链路 1（网1）:  源 = H1 ，目的 = L1        ← R1 的入接口
链路 2（网2）:  源 = L2 ，目的 = L3        ← R1 的出接口 → R2 的入接口
链路 3（网3）:  源 = L4 ，目的 = H4        ← R2 的出接口

自始至终： IP 分组的  源 = H1 ，目的 = H4   【一个字都没变】
⟹ IP 分组每经过一个路由器，外层 MAC 帧的源/目的地址都会更新为当前链路两端设备的接口 MAC；而 IP 地址始终不变——除非经过 NAT 路由器。 整个 ARP 过程对用户完全透明，系统自动完成，用户无须也无法干预。

DHCP 用于给主机动态分配 IP 地址，提供即插即用的联网机制。DHCP 是应用层协议，基于 UDP——这一句与「ARP 是网络层协议」形成对照，是最常考的层次判断。

我的补讲 · DHCP 为什么用 UDP 不用 TCP？这是一道白送的简答题 书上说 X：DHCP 基于 UDP。
潜台词是 Y：这不是随便选的，而是被逼的—— ① 客户在初始阶段既没有 IP 地址、也不知道服务器地址，建不了 TCP 连接（TCP 三次握手需要双方明确的地址）； ② TCP 不支持广播，而 DHCP 的头两步必须广播。
所以能考 Z：凡问「DHCP 为何不用 TCP」，答上面两条即可； 反过来，选择题若说「DHCP 使用 TCP 保证可靠性」，直接判错。
⭐ 顺带把三个协议的层次一次钉死（这是本节与前后节的唯一混淆点）： ARP ＝ 网络层 · DHCP ＝ 应用层（走 UDP） · ICMP ＝ 网络层（封装在 IP 里但不是高层协议）· IGMP ＝ IP 的组成部分。 王道把 DHCP 放在网络层这一章讲，考的却是「它是应用层协议」——这个错位本身就是考点。

4.2.7　网际控制报文协议 ICMP　考点追踪：ICMP 使用的下层协议（2012）· ICMP 差错报告报文的类型与语义（2022）

为了更有效地转发 IP 数据报、提高交付成功率，网络层使用 ICMP，使主机或路由器能向源点报告网络中的差错或异常。ICMP 报文被封装在 IP 数据报中传送，但它不是高层协议，而是网络层协议——这是最经典的一道判断题。ICMP 报文分两类：差错报告报文与询问报文。

必记 · 五种 ICMP 差错报告报文
类型什么时候发
终点不可达路由器或主机无法交付数据报时，向源点发送
时间超过TTL 减为 0 而丢弃时发送；另外，目的主机在规定时间内未收齐某数据报的所有分片，也会丢弃已收到的分片并发送此报文
参数问题发现首部中某些字段的值不正确（⚠️ 注意并非任意字段）时，丢弃并发送

必记 · 四种「不发」ICMP 差错报告的情形（必背，考过多次） ① 对 ICMP 差错报告报文本身，不再发送（否则会无限循环）。
② 对第一个数据报片之后的所有后续分片，不发送（一个原始数据报只报一次）。
③ 对目的地址为多播或广播地址的数据报，不发送（否则会引发差错报文风暴）。
④ 对具有特殊地址（如 127.0.0.0 或 0.0.0.0）的数据报，不发送。
⟹ 四条的共同动机只有一个：防止差错报文本身把网络压垮。理解了这一点，四条就不用硬背。
必记 · 两种询问报文与 ICMP 的两个典型应用 询问报文两种：① 回送请求和回答（测试目的主机是否可达、获取状态）；② 时间戳请求和回答（估算往返时延）。
两个典型应用（必须能说出各用哪种报文）：
应用用什么原理
PING（分组网间探测）ICMP 回送请求与回答报文测试两台主机之间的连通性
Traceroute / Tracert（路由跟踪）ICMP 时间超过报文逐步增大 TTL（1, 2, 3…），让沿途每一跳路由器依次因 TTL 归零而回报，从而追踪出完整路径
⭐ Traceroute 是 TTL 字段最漂亮的一个应用，也是把 4.2.1 与 4.2.7 串起来的那根线。
我的补讲 · ICMP 那道十几年不变的判断题，考的是「封装」与「层次」的区别 书上说 X：ICMP 报文封装在 IP 数据报中传送，但它是网络层协议、不是高层协议。
潜台词是 Y：「被谁封装」和「属于哪一层」是两回事—— 判断层次看的是它处理什么信息、为谁服务，而不是它坐在谁的肚子里。 ICMP 报告的是 IP 转发过程中的差错、服务对象是 IP 本身，所以它是网络层的一部分。
所以能考 Z：2012 真题问「ICMP 使用的下层协议是什么」，答案是 IP； 但若问「ICMP 属于哪一层」，答案是网络层，不是传输层也不是应用层。 同一把刀的另外两面：ARP 也封装在链路层帧里，但它是网络层协议；DHCP 封装在 UDP 里，它就真的是应用层协议。
⭐ 王道给的通用判据值得抄下来：「看某协议使用或依赖哪一层的地址或端口信息，就归到哪一层」—— ARP 用 IP 地址 ⟹ 网络层；DHCP 用 UDP 端口 ⟹ 应用层；ICMP 报告 IP 转发的差错 ⟹ 网络层。
知识串联 · ICMP 把本章的三个零件接成了一条链 中断 ICMP 在网络层扮演的角色，正是《组成原理》与《操作系统》里「异常/中断」扮演的角色： 正常流程走不下去时，向发起者报告一个异常事件——「终点不可达」≈ 缺页异常，「时间超过」≈ 超时中断，「源点抑制」≈ 忙信号。 连「不为异常处理本身再产生异常」（第 ① 条不发规则）都和 OS 的中断嵌套限制同构。
TTL 「时间超过」把 4.2.1 的 TTL 字段变成了可考的东西： TTL 是个计数器（4.2.1）→ 减到 0 就丢弃并回报 ICMP（4.2.7）→ 逐步增大 TTL 就能画出路径（Traceroute） ⟹ 2014 与 2024 两道真题都是在这条链上出的。
拥塞控制 「源点抑制」是 4.1.5 说的闭环控制的一个具体实例： 路由器检测到拥塞 → 反馈给源点 → 源点降速；而它被新标准废弃这件事同样值得记—— 因为拥塞控制的重担后来完全交给了 ch5 的 TCP（这正是「端到端原则」的又一次胜利）。
