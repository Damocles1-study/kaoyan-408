组原和数据结构有什么不一样

①「🤖 运行核对」这一栏在组原 = Python 独立复算。数构那边是跑 C 程序对拍，组原这边是 把每道计算题（位模式、平均 CPI、命中率、周期数、带宽、时延）用 Python 不看书答先自己算一遍，再和书比对—— 不一致时第一反应是自己抄错，放大到 dpi ≥ 400 逐字符复核题面。
② 错因标签换成了组原一套。「指针代码写错」对组原毫无意义，取而代之的是 进制位数拆错 / 补码符号处理错 / 公式套错 / 单位换算错 / 时序周期数错 / 硬件部件功能记混 / 读图表错。
③ 记录与数构完全分家。两科的做题记录、错题本、统计各存各的（localStorage 键 co_* vs ds_*）， 互不覆盖；备份文件也分开导出，导错科目会被拦下。
④ 组原最大的失分源不是不会公式，是单位和位数拆错（B vs b、K 是 10³ 还是 2¹⁰、ns vs μs）。 刷题时错在这上面，请老实勾「单位换算错」标签——统计页会把它顶到最前面。

怎么用

① 第一遍闭卷刷：进某章或真题场，切「📝 考试模式」，做完点交卷→ 出正确率 + 错误知识点归因，自动记一次。

③ 消化错题：错的自动进错题本，专项重刷到做对即移出。

⭐⭐⭐ 本章最有说服力的一组数：正文例 7.1 / 7.2 / 7.4 是同一台机器（500MHz · CPI 4 · 32 位缓冲）上的三方对照， 而这三个例题正是 2018 综合真题拆开写的——定时查询 2MB/s 吃掉 4%；中断在 40MB/s 下根本不可行； DMA 在 40MB/s 下同样只吃 4%。7-综06 更完整：查询 50% → 中断 40% → DMA 0.75%。
⭐⭐ 本章三条分界线： ① 响应优先级（硬件排队器固定，决定「谁先开始」）vs 处理优先级（屏蔽字动态调，决定「谁先执行完」）—— 2024 真题就死在「屏蔽字确定响应优先级」这一字之差上； ② 断点＝硬件（中断隐指令「关、存、寻」三件事）存，现场＝软件（中断服务程序）存； ③ 中断查「指令末尾」、DMA 查「总线周期末尾」——一条指令含多个总线周期 ⟹ DMA 响应更快、访存优先级更高。
⚠️ 计算题头号分水岭：「每秒次数」除的是什么—— 中断 ÷ 数据缓冲寄存器字长（缓冲满一次中断一次）；DMA ÷ 数据块大小（整块传完才中断一次）； 第二个坑是 CPI 何时用：给「N 条指令」要乘，给「N 个时钟周期」不能乘。
