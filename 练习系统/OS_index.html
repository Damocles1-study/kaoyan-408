操作系统和前两科有什么不一样

①「🤖 核对与延伸」这一栏在 OS 干三件事。数构是跑 C 程序对拍、组原是 Python 复算位模式与周期数， 而 OS ch1 是概念题的主场，所以核对栏改成：把每个干扰项「是怎么造出来的」还原（是张冠李戴？是把优点写反？是全称量词？）、 把同一考点的跨年真题串成一条线、需要算的（甘特图、CPU 利用率、时间片）用 Python 独立排程复算。 从第 2 章起，PV 题的核对栏会变成穷举交错执行序列、自动检查死锁与缓冲区越界。
② 错因标签换成了 OS 一套。OS 的失分源不是算错，是判断错，所以标签是 概念边界混 / 态与特权级判断错 / 硬件·OS 分工记错 / 同步模型认错 / PV 顺序颠倒 / 调度算法记混 / 地址与时间算错 / 读题漏条件。
③ 记录与前两科完全分家。三科的做题记录、错题本、统计各存各的（localStorage 键 os_* vs co_* vs ds_*），互不覆盖。
④ OS 最大的失分源是「谁在什么态下做什么」。发生在用户态还是内核态、由硬件做还是由 OS 做、 是中断还是异常——第 1 章 27 道真题里有 18 道卡在这三条缝上。刷题时错在这里，请老实勾「态与特权级判断错」「硬件/OS分工记错」。

第 1 章 计算机系统概述 · 88 题 / 27 真题 · 1.3 运行环境是四科已建章里失分密度最高的一节
第 1 章已就绪：88 题（1.1 操作系统的基本概念 11 + 1.2 操作系统发展历程 22 + 1.3 操作系统的运行环境 33 + 1.4 操作系统结构 10 + 1.5 操作系统引导 5 + 1.6 虚拟机 7；86 选择 + 2 综合应用）， 含 27 道统考真题（2010–2025 共 16 个年份，仅缺 2009）。
🔥 1.3 运行环境是全章、也是目前四科所有已建章中失分密度最高的一节： 11 页正文塞进 18 道统考真题 ≈ 1.64 道/页（组原最高的 6.2 节是 1.14/页、ch5 的 5.6 是 0.90/页）， 且 2011–2024 连续 14 年每年必考，2012 / 2015 / 2021 / 2022 各考 2 道。
⭐⭐ 1.3 的四条分界线（本章全部真题都卡在这四条缝上）：
① 「在用户态发生」vs「在用户态执行」——系统调用、外中断、缺页都发生于用户态、处理在内核态； 只有进程切换连"发生"都在内核态（2012 真题）。2024 又把它细分成「中断发生时」（可能在用户态） 与「中断处理程序开始执行时」（一定在内核态）。
② 硬件做的 vs 操作系统做的——硬件：保存断点 PC/PSW、改模式位、查中断向量； OS：初始化中断向量表、保存通用寄存器、保存中断屏蔽字、执行服务例程。 2015 / 2020 / 2022 三年考的是同一把刀。
③ 中断（外，返回第 i+1 条）vs 异常（内，返回第 i 条重执行）—— 「缺页中断」名字带中断、分类却属异常（故障），2016 真题的正解就是这一条。
④ 指令属于哪一态——陷入/访管指令在用户态执行；关中断、I/O 指令、置时钟、停机、 中断屏蔽字设置在内核态。这一单点在 ch1 考了 5 次（2014、2021 + 三道书内题）。
✅ 两道甘特图综合题（1.2-21 / 1.2-22）已用 Python 独立排程复算： 单道 40/80 = 50% · 多道 40/45 = 88.9% · CPU 空闲区间 [100,150]ms、利用率 250/300 = 83.3% · 进程 B 的两段等待 [0,50] 与 [180,200]——各段与书图逐段吻合，本章未发现书上错误。
第 2 章 进程与线程 · 题库四节全部建成（277 题 / 74 真题，2009–2025 一年不落）· 全书最大章 139 页
全章题库已建成 277 题 / 74 道统考真题（2.1 74/17 · 2.2 67/22 · 2.3 86/23 · 2.4 50/12）。 ⚠️ 本章不能只看失分密度：2.3 同步与互斥仅 0.46 真题/页， 但它的 13 道综合真题覆盖 2009–2025 一年不落，每年稳定 8 分， 按分值算是全章、也是全书投入产出比最高的一节。

✅ 2.1 进程与线程简介已就绪：74 题（进程篇 40 + 线程篇 17 + 统考真题 17 = 16 选择 + 1 综合）， 含 17 道统考真题（2010–2025，缺 2013 / 2016 / 2017；2025 出的是综合题）。
🔥 第一主线：状态转换的「谁引起谁」——本节 74 题里 14 题考它， 2014 / 2015 / 2018 / 2019 / 2022 / 2023 六年真题全在这条线上。一句判据吃透： 只缺 CPU ⟹ 就绪；缺 CPU 以外的东西或在等事件 ⟹ 阻塞。
⭐ 「申请处理器得不到 ⟹ 阻塞态」是本节最大的坑，三年真题拿它当干扰项： 2015 把「被高优先级抢占」设为正解（落点就绪）、2018 把「CPU 分配给高优先权进程」设为干扰项、 2019 把「时间片用完」设为干扰项——三年三种问法，考的是同一句话。
⭐ 主动 vs 被动：运行→阻塞是进程自己调 Block（唯一一条主动边）； 阻塞→就绪由中断处理程序或合作进程 Wakeup（被动）。 推论：阻塞是主动行为 ⟹ 只有运行态进程能执行 Block；Block 与 Wakeup 必须成对，否则永久阻塞。 2023 又补了第三格：主动出让 CPU（yield）也是主动，但落点是就绪不是阻塞。
📌 第二主线：ULT vs KLT（11 题）——所有结论都能从一句话推出来： 内核感知不到 ULT，只能按进程为单位下手 ⟹ 阻塞连坐、不能多核并行（但仍能并发）、 调度以进程为单位、OS 不为 ULT 建 TCB（2019 真题正面考）。 ULT 的两优两劣：切换快 + 可移植 vs 阻塞连坐 + 不能并行。
📌 第三主线：线程私有 vs 共享——2011 与 2024 两次真题，连干扰项造法都一样（都拿「某线程的栈」当否定项）。 私有＝TCB / PC / 寄存器组 / 栈与栈指针；共享＝地址空间、代码段、全局变量、已打开文件 fd、堆、信号量机构。
📌 「分配 CPU 不是创建原语的事」在本节考了 3 次（两道课后题 + 2021 真题）： 创建原语备齐除 CPU 外的一切，终点是就绪队列——正好落进「就绪 = 只欠 CPU」的定义里。
🔗 跨科枢纽已就地点名：信号的两条位向量 ↔ 组原 ch5 的中断请求寄存器 + 中断屏蔽字（同构）； 缺页属异常而非中断 ↔ ch1 四条分界线之一；管道 = 有界缓冲区 ↔ 2.3 生产者-消费者 ↔ 数构循环队列； 栈高→低 ↔ 组原 ch4 栈帧。

✅ 2.2 CPU 调度已就绪：67 题（基础题 36 + 统考真题 21 + 综合应用题 10）， 含 22 道统考真题（2009–2025 逐年，仅缺 2015；其中 2016 是一道综合大题）。
🐍 本节是全书两大计算主场之一（另一个是 2.4 银行家算法）： 18 处排程/开销计算全部经 Python 独立复算，书上 0 错—— Q26 的 10.62/6.8 · Q27 的 14（并还原了 FCFS 19.2、优先级 20 两个干扰项）· Q28 的 27 · Q29 的 120ms · 2012 的 260ms · 2016 的 17ms · 2018 的 75μs · 2019 的 15ms · 2022 的 6 次 · 2023 的 61ms · 2024 的 250ms · 综 01/02/04/06/07/08/09 逐时间片吻合。 ⚠️ 反倒抓出本人三处转录手误（均已 dpi≥340 复核订正）：综 02 作业 B 第三段是 I/O₂ 不是 I/O₁ · Q47 的 P₃ 优先权是 20 不是 100 · 综 04「在时刻 0 以 1,2,3,4,5 的顺序到达」＝全部在 0 时刻到达（中文歧义句）。
⭐⭐ 四条分界线：
① 上下文切换到底换什么——进程私有的（通用寄存器 / PC / 栈基址 / 页表基址）要换； 全局共享的（中断向量表基址）不换；再叠一层：同进程内线程切换只换 PC 与栈基址，不换页表基址、不换打开文件表。 2024 与 2025 连着两年考同一把刀（Q55 要换 vs Q57 不换），课后题 Q09 是它的线程版镜像。
② 调度的「直接原因」是当前进程不能继续运行（Q13/14/41/51/06）——新进程进入就绪队列不是直接原因（要看是否允许抢占）； 处于临界区的进程照样能被调度（2012 真题直接考，课后题 06 重复考一遍）。 ⚠️ 但 2021 真题问的是「可能引起调度」，答案是四条全选——「直接原因」与「可能引起」是两个问法。
③ 饥饿（Q35/39/43）——FCFS 与时间片轮转绝不饥饿；SJF/SRTN（抢占与否都算）与静态优先级会饥饿； 高响应比优先不会（等待时间在分子上，天然带老化）。2011 真题问的正是「短作业优先且不饥饿」＝ HRRN 的独有位置。
④ 优先级调整方向（Q22/38/42 + 2016 综合题）——运行时间↑ ⟹ 优先级↓；等待时间↑ ⟹ 优先级↑； I/O 型 > 计算型；系统进程 > 用户进程。2010、2013、2016 三年是同一条线， 终点是那道大题的公式 priority = nice + k₁·cpuTime − k₂·waitTime。
📐 计算题五个套路：① 广义甘特图（CPU 与每种 I/O 各画一行）② 不同设备可并行、同种设备排队 ③ 周转 = 完成 − 到达、带权 = 周转 ÷ 运行、SJF 平均周转必最小（可用于自检） ④ 「两道/多道」限制 → 作业调度 → 进程调度，三层各管一件事（综 05 / 综 09，最容易漏中间那层） ⑤ 开销要计次（2018 那题 1μs 计 3 次，综 07 的中断/调度/切换）。
🔗 跨科枢纽：2025 的 Q56（有序单链表插入 O(n) / 取头 O(1)）是一道「数据结构 × 操作系统」跨科真题； 2021 的时钟中断与节拍率 ↔ 组原 ch7 程序中断方式；页表基址寄存器 ↔ ch3 与组原 ch3； 处理器亲和性 ↔ 组原 Cache 局部性；2016 的三设备流水 ↔ 组原 ch5 流水线的「瓶颈段决定吞吐率」。

✅ 2.3 同步与互斥已就绪：86 题（概念与准则 20 + 信号量数值与管程 19 + 经典同步模型 8 + 统考真题 10 + 综合应用题 16 + PV 统考大题 13；原书 85 题，其中一题两问的「就绪/阻塞队列上界」拆成两小题）， 含 23 道统考真题——10 道选择（2010–2020）+ 13 道综合大题，2009–2025 十三年一年不落。
⭐⭐ 本节按分值算是全章、也是全书投入产出比最高的一节： 真题密度只有 0.46 道/页（全章最低之一），但每年稳定一道 8 分 PV 大题。 13 道 PV 大题单独成组，每道按「💭 思路 → ✍️ 考场卷面（⛳ 采分点）→ 📌 批注」三层写—— 思路层只讲怎么想（关系分析 → 定信号量 → 摆 PV），卷面层只写考场上真要落笔的字，批注层讲「顺序为什么不能换、少一个信号量会怎样」。

⚡ 更有价值的是反例侧：每个「教材说会死锁」的写法都被精确复现—— 生产者-消费者颠倒 P 顺序（57 状态即死锁）· 博物馆颠倒（365）· 自行车去掉 N−2/N−1 上界（221，3 个车轮占满箱子）· 哲学家碗数不封顶 n−1（2401，4 人各持一根左筷）· 综 06 少写一次 V(Sy)（61）· 两把锁反序加锁（23）。 「顺序不能换」不再是背下来的口诀，而是被穷举证过的结论。

⭐⭐ 六条分界线：
① P 的顺序不能换、V 的顺序可以换——资源类（empty/full/pit/position/bowl）在前，互斥类（mutex）在后； 反了就会「占着锁等资源」。2013 博物馆真题就是它的现实版（占着门等名额，里面的人出不去）。
② 同步信号量初值不一定是 0——期望的消息尚未产生才写 0，已存在就写正整数。 2015 真题四个初值 x、M−x、y、N−y 一个 0 都没有；背死「同步就写 0」这道 8 分题全错。
③ 消费者「挑食」时 full 必须按产品类型拆开——苹果橘子拆 2 个、2009 奇偶拆 2 个、吸烟者拆 3 个； 但 empty 不能拆（空位就是空位，不分类型）。
④ 找互斥关系用读者-写者原则：读读不互斥，读写与写写才互斥—— 2017「最大限度地并发执行」的评分依据；用一把大锁虽然正确但降低并发度，教材明说要扣分。
⑤ 同一进程/线程内部的先后由程序顺序保证，不需要信号量——2022 的命门： 图上 5 条边，3 条落在线程内部 ⟹ 只需 2 个信号量；对照 2020 的 5 个独立进程 4 条边一条都不能省。
⑥ 缓冲区容量为 1 时，同步信号量兼作互斥——2024 第 2 问：只写一个 S=0 即可，再加 mutex 属多余。
⚠️⚠️ 2020 之后真题明显转向「分析 / 改错 / 最少信号量」： 2021 分析开关中断实现信号量的两种写法哪个对（方法 1 关中断后忙等 ⟹ 死循环）· 2023 改错 swap 实现互斥（if 应为 while、退出区 lock 应置 FALSE，且「不增加语句条数」）· 2024 与 2025 都明写「定义尽可能少的信号量」。 ⟹ 只会背模板不够，要能说清「每个信号量为什么必须存在、少一个会怎样」——这正是 📌 批注层的内容。
⭐ 2025 最精妙的一步：signal(position) 放在「放树苗之后」而不是「填土之后」—— 题干抠的是「未被使用的树坑数量」，苗一放下该坑就不再占配额。 🐍 穷举实测：两种写法都不死锁（各 270 状态），所以这不是正确性问题而是贴合题意的问题； 同类推理还有 2011 的 V(empty) 由营业员在叫号时执行（顾客被叫离座才腾座位）。

⭐⭐ 死锁公式 m > n(k−1) 在本节考了 9 次（2009 / 2014 / 2021 三年真题 + 教材 6 处）， 是 2.4 性价比最高的一个式子。三种问法都要会： 问不死锁的最少资源 m ≥ n(k−1)+1 · 问最多进程数 n < m/(k−1) · 反问「可能死锁的最小 n」取 m ≤ n(k−1)； 需求不等时写成 m > Σ(kᵢ−1)（2014 那道 3/4/5 台）。 ⚠️ 三道真题全在等号上设坑：不死锁要求严格大于，取等一律判「可能死锁」。
⭐ 银行家算法四步 + 两个提速技巧： ① Request ≤ Need（否则出错）② Request ≤ Available（不过就直接让它等待，不必做安全性检查） ③ 试探性分配三行同时改 ④ 安全性算法，不安全就撤销恢复。 提速一：安全性算法里 Work += Allocation（已分配那一列）——2018 真题 A/C 之争就靠它 （P₃ 归还的是 0 而不是 1）。提速二：集合推进法（综 05 原书注意框）—— 把每步能满足的进程一次全推完，Work 只增不减、最大值与顺序无关： 能满足余下任意一个 ⟹ 直接判安全；推到天花板仍谁也满足不了 ⟹ 直接判不安全。

📌 五条分界线：
① 死锁 vs 饥饿——饥饿可以只涉及一个进程、可以停在就绪态； 死锁必须 ≥2 个进程、形成循环等待、且全部阻塞。本节考 4 次（含「进程死循环＝饥饿不是死锁」）。
② 环 ≠ 死锁——只有「每类资源仅一个实例」时，环才是死锁的充要条件； 多实例时环只是潜在风险（图 2.15 的 P_K 一释放环就断）。正式判据永远是死锁定理：资源分配图不可完全简化。
③ 不可剥夺 vs 请求并保持——苹果比喻：「别人抢不走我手里的」＝不可剥夺， 「我攥着第一个去要第二个」＝请求并保持。破法也不同：前者靠强制释放（代价高、极少用），后者靠静态分配。
④ 预防 vs 避免 vs 检测（2015 真题专考这组）—— 预防＝事前立规矩破条件（只有它限制申请顺序）· 避免＝事前跑安全性算法（需预知 Max）· 检测＝事后查资源分配图（不需预知未来请求）。 ⚠️ 银行家算法的身份被真题从两头堵死：2013 考「它不是预防」、2019 考「它也不能判断是否已死锁」。
⑤ 三条单向蕴含，方向不能反——安全 ⟹ 必不死锁；死锁 ⟹ 必不安全；不安全 ⇏ 死锁 （原书同心椭圆图已裁入 2.4-17 的答案栏，2013 真题 C 项又考一次）。
