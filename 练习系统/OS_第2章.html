⭐⭐ 2.4 只有两样东西要练熟，练熟就是白拿分：
① 死锁公式 m > n(k−1)（＝ m ≥ n(k−1)+1，需求不等时写成 m > Σ(kᵢ−1)）—— 本节连同真题共考 9 次（2009 / 2014 / 2021 三年真题 + 教材 6 处）。 口诀：给每个进程都发到「差一个」，再多一个就能解锁。 ⚠️ 三次都在等号上设坑：不死锁要求严格大于，取等一律判「可能死锁」。
② 银行家算法四步：① Request ≤ Need？否则出错 → ② Request ≤ Available？否则直接让它等待，不必做安全性检查 → ③ 试探性分配（Available / Allocation / Need 三行同时改）→ ④ 安全性算法，不安全就撤销恢复。 安全性算法里 Work += Allocation（已分配那一列），不是 Max，也不是 Need—— 这是全节最高频的低级错误（2018 真题就是靠它区分 A 和 C）。
⭐ 考场提速：集合推进法（综 05 原书「注意」框）—— 把每一步能满足的进程一次性全推完，因为 Work 只增不减、涨到的最大值与顺序无关： 某步 Work 已能满足余下任意一个 ⟹ 直接判安全；推到天花板仍谁也满足不了 ⟹ 直接判不安全。 两头都能省掉半张表。
📌 2.4 的五条分界线：① 死锁 vs 饥饿（饥饿可只有一个进程、可停在就绪态；死锁必 ≥2 个进程、必全阻塞）· ② 环 ≠ 死锁（只有每类资源仅一个实例时环才是充要条件，多实例时环只是潜在风险；正式判据是「资源分配图不可完全简化」）· ③ 不可剥夺 vs 请求并保持（苹果比喻：别人抢不走我手里的 / 我攥着第一个去要第二个）· ④ 预防 vs 避免 vs 检测（事前立规矩破条件 / 事前算安全性、需预知 Max / 事后查图、不需预知——2015 真题专考这组）· ⑤ 安全 ⟹ 必不死锁；死锁 ⟹ 必不安全；不安全 ⇏ 死锁（三条单向蕴含，方向不能反）。
🐍 2.4 的「🤖 核对」＝ Python 独立复算：所有安全序列用 DFS 枚举全部条数（2012 有 66 条、2020 唯一 1 条、 2022 恰 2 条、综 03 有 6 条、综 05 的 (1,4,0) 有 24 条），死锁公式题用穷举全部分配组合验边界—— 2.4 节书上 0 错。另外还独立验了三件事：Q31 的「Σkᵢ < m+n」是紧界（能死锁的最小 Σkᵢ 恰为 m+n）； 综 03 第 3 问的状态确实不安全但确实没死锁（Available=(0,1,0)、安全序列 0 条，却无一进程阻塞）； 哲学家三方案穷举（朴素版 2163 状态出现死锁、封顶版 14642 状态与奇偶异序 2164 状态均无死锁）。

⭐⭐ 2.3 是本章、也是全书按分值算的第一重心：真题密度只有 0.46 道/页（全章最低之一）， 但 13 道 PV 综合真题覆盖 2009–2025 十三年一年不落，每年稳定一道 8 分大题——投入产出比全章第一。 「PV 统考大题」这一组单独刷，每道都按「💭 思路 → ✍️ 考场卷面（⛳ 采分点）→ 📌 批注」三层写： 看完思路就合上页面自己写，别直接翻卷面。
🐍 2.3 的「🤖 核对」升级为 Python 穷举 PV 交错执行序列：把每份参考代码翻成状态机， 穷举全部交错，自动检查 ① 死锁 ② 缓冲区越界 ③ 互斥破坏。 20 个模型全部通过，教材参考解零错误；且每个「教材说会死锁」的反例都精确复现—— 生产者-消费者颠倒 P 顺序（57 状态即死锁）· 博物馆颠倒（365 状态）· 自行车去掉 N−2/N−1 上界（221 状态）· 哲学家碗数不封顶 n−1（2401 状态）· 综 06 少写一次 V(Sy)（61 状态）· 两把锁反序加锁（23 状态）。
📌 2.3 的六条分界线：① P 的顺序不能换、V 的顺序可以换（资源类在前、互斥类在后，反了必死锁， 2013 真题就是它的现实版）· ② 同步信号量初值不一定是 0（消息已存在就写正数，2015 真题四个初值全非 0）· ③ 消费者「挑食」时 full 要按类型拆开（苹果橘子 / 2009 奇偶 / 吸烟者三档）· ④ 读读不互斥、读写与写写才互斥（2017「最大限度并发」的评分依据）· ⑤ 同一线程内部的先后不用信号量（2022 只用 2 个信号量的命门）· ⑥ 容量为 1 时同步信号量兼作互斥（2024 第 2 问「尽可能少的信号量」）。
⚠️ 2020 之后真题明显转向：从「写一遍经典模型」变成「分析 / 改错 / 最少信号量」—— 2021 分析开关中断、2023 改错 swap、2024 与 2025 都明写「定义尽可能少的信号量」。 只会背模板不够，要能说清「每个信号量为什么必须存在、少一个会怎样」，这正是三层里 📌 批注层的内容。

🐍 2.2 是本章两大计算主场之一（另一个是 2.4 银行家算法）： 18 处排程/开销计算已全部用 Python 独立复算，书上 0 错—— Q26/27/28/29 · 2012 的 260ms · 2016 的 17ms · 2018 的 75μs · 2019 的 15ms · 2022 的 6 次 · 2023 的 61ms · 2024 的 250ms · 综 01/02/04/06/07/08/09 逐段吻合。
📌 2.2 的四条分界线：① 上下文切换换什么（2024 与 2025 连考：进程私有的要换、全局共享的中断向量表基址不换； 同进程内线程切换不换页表基址）· ② 调度的「直接原因」是当前进程不能继续跑（新进程就绪不算）· ③ 饥饿（FCFS 与 RR 绝不饥饿；SJF/SRTN 与静态优先级会；HRRN 不会）· ④ 优先级调整方向（运行时间↑⟹降、等待时间↑⟹升、I/O 型 > 计算型、系统 > 用户）。
⚠️ 计算题五个套路：广义甘特图（CPU 与每种 I/O 各画一行）· 不同设备可并行、同种设备排队 · 周转 = 完成 − 到达且带权 = 周转/运行 · 「两道/多道」限制 → 作业调度 → 进程调度三层各管一件事 · 开销要计次（2018 那题 1μs 要计 3 次）。

🔥 2.1 的失分主线只有一条：状态转换的「谁引起谁」——本节 74 题里有 14 题考它， 2014／2015／2018／2019／2022／2023 六年真题全在这条线上。一句判据吃透全部： 只缺 CPU ⟹ 就绪；缺 CPU 以外的东西或在等事件 ⟹ 阻塞。 「申请处理器得不到 ⟹ 阻塞态」是本节最大的坑，三年真题拿它当干扰项。
📌 第二主线：用户级线程 vs 内核级线程（11 题）——所有结论都能从一句话推出来： 内核感知不到 ULT，所以只能按进程为单位下手 ⟹ 阻塞连坐、不能多核并行、OS 不为 ULT 建 TCB（2019 真题）。
📌 第三主线：线程私有 vs 共享（2011、2024 两次真题，干扰项造法完全相同）—— 私有＝TCB／PC／寄存器组／栈与栈指针；共享＝地址空间、代码段、全局变量、已打开文件 fd、堆。
